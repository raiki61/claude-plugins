# P1 主経路の実行観測（writer が実行）

対象差分: {{loop.diff_file}}　変更ファイルの一覧: {{loop.changed_files_file}}（1 行 1 ファイル。要る所だけ Read）　リポジトリ: {{inputs.cwd}}

対象差分が利用者から見える経路・外部との継ぎ目を変えているなら、その経路を**実際に 1 回動かし、通った値を観測しろ**。観測の対象は「テストが緑になること」ではなく本番と同じ経路を流れた実物である。動かしていない経路を「検証済み」と扱うな——他の観点は全て差分を読む役で、実行して初めて現れる欠陥（実行環境固有の挙動・中間層による値の加工・描画）はどれだけラウンドを重ねても現れない。動かせない（環境が無い・権限が無い・実機が要る）なら awaiting_human で理由を書け（台帳に載り、次の周の judge が「動かす手段が本当に無いか」を再審する）。observed に経路と観測した値。
素材（material）の書き方: status は found（見つけた。count と detail）／clean（今ラウンドに見たが無かった。checked に何を見たか）／not_applicable（条件に当たらない。reason）／awaiting_human（人の起動待ち。reason）／not_run（やるべきだったが飛ばした。reason）。前の周の判定を流用するなら carried_over（from_round と reason）。欄と値の正本は review-record.py。
