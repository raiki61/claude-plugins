# P0-5 並行 PR 衝突チェック（writer の仕事・6 段を順に。段を飛ばすな）

リポジトリ: {{inputs.cwd}}　BASE: {{record.base}}

1. 対象リポジトリを解決する: `git remote get-url <upstream の remote>`（upstream は `git rev-parse --abbrev-ref @{u}`。無ければ origin）から owner/repo を導け。以降の gh には全て `-R <owner/repo>`。**`gh repo view` の値をこの確認に使うな**（cwd の remote から解決するので検査が恒真になる）。導けないなら以降を「確認できなかった」（awaiting_human）。取り違えた一覧で「衝突なし」と書くな。
2. 自分の PR を除外する: `gh pr list -R <owner/repo> --limit 100 --json number,headRefName,headRefOid` で列挙し、`git rev-parse HEAD` と headRefOid が一致する PR を先に外せ（外さないとレビュー対象そのものをスコープ外にする自己言及的な誤判定になる。ブランチ名で照合するな——detached HEAD では空文字になる）。
3. 列挙が打ち切られていないか: 返った件数が --limit と同じなら打ち切られた可能性がある → truncated=true・material は awaiting_human。打ち切られた一覧で「衝突なし」と書くな。
4. 変更ファイル集合: 機械が取った一覧 {{loop.changed_files_file}}（BASE と周に固めた版の差。1 行 1 ファイル）。空で、判定から入る run の依頼が指す場所（{{loop.request_wheres}}）が在れば、そこに名指されたファイルを集合にせよ。**それでも集合が空なら clean と書くな**——空の集合との交差は何も確かめていない。not_run（reason に何が空だったか）で返せ。
5. 残った PR の変更ファイル: `gh pr view <n> -R <owner/repo> --json files --jq '.files[].path'`。交差するものが「同一ファイルを触る並行 PR」。
6. 交差した箇所を担当 PR に渡す: `gh pr diff <n>` で hunk を見て、衝突・重複が判明した箇所はその変更を主導している PR に申し送り、本ループのスコープから外せ（conflicts に handed_over）。

**この指示書が任せ先に届くのは、engine が 1〜5 段を済ませられなかったか、交差が在ったときだけ**（next の ready の `engine_fallback` に理由）——remote が GitHub で gh が在り交差が 0 なら、engine が同梱の scripts/parallel-pr.py で済ませてこの節は出ない。

GitHub 以外のホストでは同等コマンドに読み替えろ。読み替えられないなら awaiting_human。**未確認を clean と書くな。**
素材（material）の書き方: status は found（見つけた。count と detail）／clean（今ラウンドに見たが無かった。checked に何を見たか）／not_applicable（条件に当たらない。reason）／awaiting_human（人の起動待ち。reason）／not_run（やるべきだったが飛ばした。reason）。carried_over（前の周の流用）は走らなかった節に機械が書く——走った役は今の周の判定を書け（流用と書いても拒まれる）。欄と値の正本は review-record.py。
