{{node.skills}}

読み方: `skill` が名前、`args` は付ける引数（在るなら必ず付けろ）、`note` はその 1 本の条件と注意、`required` が false のものは条件に当たらなければ起こさなくてよい。

**宣言 1 本につき findings の行を 1 本、例外なく返せ。** 起こして所見が無いなら `items` を空にして `failed` に「起こしたが所見なし」と何を見たかを書く。起こしていない・非該当なら `failed` にその理由を書く。`required: false` の 1 本も行は要る。**行を省くな**——省ける形だと、起動しなかったことが「見たが所見なし」と同じ形で通る（実測 2026-09-15: 3 周続けて型設計のレンズが起動されず、記録のどこにも赤が出なかった）。`findings[].skill` には上の `skill` の綴りをそのまま書け——engine の post_check がこの配列と 1 対 1 で数えるので、綴りが違えば落ちる。**宣言に無い名前を足すな**（増やしたいなら graph の `skills` を直す。役が増やした名前は数えられない）。

**どの検出器にも対象を明示的に渡せ。ただし渡し方は道具で違う**——`/code-review` が受けるのはファイルパス・PR 番号・ブランチ名・ref 範囲の 4 種なので `{{record.base}}...HEAD` の ref 範囲で渡す（`{{loop.diff_file}}` は `.git` 配下の `.patch` でレビュー対象のパスではない）。agent のレンズには `{{loop.diff_file}}` をそのまま渡す。渡さないと各々が既定で自分の対象を作り直し、別物を見た空の findings が「見たが所見なし」と同じ形で記録に入る。

**findings を機械的に集めるだけで、採点・ラベル確定はするな。** `/code-review` の裏取りの verdict は**この節では受け取らない**——findings の項目は 5 鍵で固定（`additionalProperties: false`）で置き場が無く、鍵を足せば型に合わずに落ち、足さなければ P2 に届かない。欄の新設は台帳の決着待ちなので、**verdict を本文に埋める回避もするな**。誤検出を落とす工程は、この周は P2 の judge の反証が担う。

**まとめ役の `pr-review-toolkit:review-pr` は挟むな。レンズは 1 つずつ名指しで起こせ**——散文の振り分けは差分の形（try/except・型定義・テストの有無）に依るが、上のレンズが当たるクラス（黙って無力化される検査・恒真になった柵・不変条件を平坦な値で持つ設計・振る舞い網羅の穴）は差分の形に関係なく出る。`pr-review-toolkit:code-simplifier` は指摘でなく修正を当てる agent なので呼ぶな。**この節は作業ツリーを変えてはいけない**（engine が P1 の前後で突き合わせる）——修正まで行く道具は、修正を禁じた形でだけ呼べ。

各 skill を呼ぶプロンプトには次を課せ（REVIEW.md に書くだけでは skill に届かない）: 指摘の提出基準（`REVIEW.md`「指摘の提出基準」）: 機構（なぜそうなるかのコード上の因果を一文）・実測（動かせるものは動かす。動かせないなら「未実測」と明記して仮説として出す）・提出前の自己反証（規則を引くならその条件節が当たるか・近傍の実態まで読み、殺せなかった指摘だけ提出する）・誤検出の見積もり（どんな場合に誤りになるかを一行）。

skill の呼び出し自体が失敗したら（権限・実行時エラー）止めるな——その行の `failed` に書き、material を awaiting_human にして理由を書け。**無かったことを not_applicable にするな。** 直前の周から対象差分にロジック変更が無いなら /simplify の再実行は持ち越してよい（simplify_carried=true と理由。**持ち越しでも行は要る**——`failed` に持ち越しと書く）。
素材（material）の書き方: status は found（見つけた。count と detail）／clean（今ラウンドに見たが無かった。checked に何を見たか）／not_applicable（条件に当たらない。reason）／awaiting_human（人の起動待ち。reason）／not_run（やるべきだったが飛ばした。reason）。carried_over（前の周の流用）は走らなかった節に機械が書く——走った役は今の周の判定を書け（流用と書いても拒まれる）。欄と値の正本は review-record.py。
