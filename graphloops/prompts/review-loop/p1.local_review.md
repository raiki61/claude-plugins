欠陥は組み込みの `/code-review high`、品質は `/simplify`、認証・データ取扱い・外部 I/O に触れるなら `/security-review` も実行し、findings のみ取得しろ。**`/code-review` は Claude Code 本体に同梱のものを指す**（入手経路は README の依存表が正本）。**どの検出器にも対象を明示的に渡せ。ただし渡し方は道具で違う**——`/code-review` が受けるのはファイルパス・PR 番号・ブランチ名・ref 範囲の 4 種なので、`{{record.base}}...HEAD` の ref 範囲で渡す（`{{loop.diff_file}}` は `.git` 配下の `.patch` でレビュー対象のパスではない）。agent のレンズには`{{loop.diff_file}}` をそのまま渡す。渡さないと各々が既定で自分の対象を作り直し、別物を見た空の findings が『見たが所見なし』と同じ形で記録に入る。**findings を機械的に集めるだけで、採点・ラベル確定はするな。** `/code-review` の裏取りの verdict は**この節では受け取らない**——findings の項目は 5 鍵で固定（`additionalProperties: false`）で置き場が無く、鍵を足せば型に合わずに落ち、足さなければ P2 に届かない。欄の新設は台帳の決着待ちなので、**verdict を本文に埋める回避もするな**。誤検出を落とす工程は、この周は P2 の judge の反証が担う。`--comment`（PR へ投稿）も `--fix`（作業ツリーへ適用）も付けるな——投稿は R1、当てるのは P3 で、この節は作業ツリーを変えてはいけない。`/simplify` は既定で修正まで行う skill なので、指摘だけ返す形で呼べ——4 観点（再利用・単純化・効率・高度）を修正を禁じたプロンプトでそれぞれ起こす（当てるのは P3）。**まとめ役の `pr-review-toolkit:review-pr` は挟むな。レンズは 1 つずつ名指しで起こせ**（`pr-review-toolkit:code-reviewer` / `pr-review-toolkit:silent-failure-hunter` / `pr-review-toolkit:type-design-analyzer` / `pr-review-toolkit:pr-test-analyzer`。名指しの正本は graph の `skills` 配列で、ここはその写しなので本数を焼き込まない。**`code-reviewer` を落とすな**——実測 2026-09-15: この節の 1 周目で `code-reviewer` だけが『宣言済み依存から、どこにも宣言されていない裸名へ主検出器を移した』を挙げた。規約準拠の専任ではなく、準拠とバグ検出の両方を担う汎用レンズである）——散文の振り分けは差分の形（try/except・型定義・テストの有無）に依るが、これらのレンズが当たるクラス（黙って無力化される検査・恒真になった柵・不変条件を平坦な値で持つ設計・振る舞い網羅の穴）は差分の形に関係なく出る（実測: 3 周続けて型設計のレンズが起動されなかった）。`pr-review-toolkit:code-simplifier` は指摘でなく修正を当てる agent なので呼ぶな。

各 skill を呼ぶプロンプトには次を課せ（REVIEW.md に書くだけでは skill に届かない）: 指摘の提出基準（`REVIEW.md`「指摘の提出基準」）: 機構（なぜそうなるかのコード上の因果を一文）・実測（動かせるものは動かす。動かせないなら「未実測」と明記して仮説として出す）・提出前の自己反証（規則を引くならその条件節が当たるか・近傍の実態まで読み、殺せなかった指摘だけ提出する）・誤検出の見積もり（どんな場合に誤りになるかを一行）。

skill の呼び出し自体が失敗したら（権限・実行時エラー）止めるな——findings に failed を書き、material を awaiting_human にして理由を書け。**無かったことを not_applicable にするな。** 直前の周から対象差分にロジック変更が無いなら /simplify の再実行は持ち越してよい（simplify_carried=true と理由）。作業ツリーを変えるな（engine が P1 の前後で突き合わせる）。
素材（material）の書き方: status は found（見つけた。count と detail）／clean（今ラウンドに見たが無かった。checked に何を見たか）／not_applicable（条件に当たらない。reason）／awaiting_human（人の起動待ち。reason）／not_run（やるべきだったが飛ばした。reason）。carried_over（前の周の流用）は走らなかった節に機械が書く——走った役は今の周の判定を書け（流用と書いても拒まれる）。欄と値の正本は review-record.py。
