# P2-8 履歴との突合（同じ judge。1〜7 を確定した後に、いま初めて履歴と前の台帳を渡す）

前の周までの履歴（review-record.py の出力。機械は解釈しない）:
{{prev.p4.record.out}}

前の周の台帳: {{?loop.prev_questions}}
前の周のユニット: {{?loop.prev_units}}　過去の [block] キー: {{?loop.prev_blocks}}　defer 台帳: {{?loop.defer_ledger}}
前の周の writer の異議（rejudge_requested——フレーミングか disposition に同意できなかった旨。無ければ空）: {{?loop.prev_rejudge}}
人の答え（あれば）: {{?record.process.human_answers}}
凍結した目的: {{out.p0.purpose.purpose_text}}
お前が 1〜7 で確定したもの: units {{record.units}} ／ questions {{record.questions}}

**履歴を読んでラベルを下げることを禁ずる**（下げてよいのは台帳の defer 理由が今も成立する場合の維持だけ）。やるのは 5 つ:
- 台帳のルーター: 前の周までに defer と確定したキーを再び挙げるなら ①構造的理由がまだ成立 → defer 維持 ②新証拠が理由に答える → do-now / [block] に上げ reopen_evidence を一文 ③理由が無い → 台帳側の欠陥として surface。
- 同じルーターを過去の [block] キーにも: ①まだ残っている → 同じキー文字列で挙げ直す ②閉じた → closed_note に根拠を一文（記録には載せない）③確かめられない → 未確認として挙げる。機械はこの一覧を数えない——振り分けは judge の義務（実測: 振り分けなかった周に [block] 6 件のうち 3 件が未閉鎖のまま落ち、次の周に「新規」の顔で戻った）。
- 再燃の原因: 新証拠なく戻る指摘は、コード／レビュアー／規約のどれか（reburn_causes）。規約なら kind=rule で台帳へ。
- 目的の外への膨張: 露呈の回収が凍結した目的の外に出ているなら当該ユニットを defer に落とし kind=split で台帳へ（BASE 時点の実在の確かめ方と、目的の外である理由）。
- 問いの台帳の再審: 前の周の held / escalate を 1 件ずつ、今ラウンドの材料で ①答えた → resolved（resolution に答えた材料）②自明——決める規律を名指しできる → resolved（規律を resolution に。**決着したが出どころの欠陥がまだ開いているなら decided**）③まだ決まらないが次の周で決まりうる → held（何が来れば決まるかを reason に）④人でないと決められない（好み・方針・可逆性の低い合意・目的の書き換え）→ escalate。自明かの検査は独立再導出で——お前は 1〜7 で台帳を見ずに同じ欠陥を採点している。そこで岐路を立てずに処方を置けたなら前の周の目にだけ難しかった（resolved）。同じ岐路を独立に立てたなら問いは実在する。1 件ずつの後、台帳全体を並べて (a) 同じ根から出た問いは束ねる (b) 答え待ちで手を止めるユニットの key を depends に (c) resolved 同士が矛盾しないか (d) 1 つの零処方で複数の問いが同時に消えないか。**前の周の held / escalate は黙って落とすな**（機械が止める）。resolved は次の周から落としてよい。

出力は p2.diagnose と同じ形（units・questions は再審後の全量。router・reburn_causes を添える）。
