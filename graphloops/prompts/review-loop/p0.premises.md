# P0-3 前提を実測しろ（writer の仕事・目的テキストより先に）

依頼: {{inputs.request}}
リポジトリ: {{inputs.cwd}}

目的と制約に書く数値・規模・件数・「〜が来うる」の類は、**この作業ツリーで測った値か、ファイルを名指しできる事実**でなければ書くな。記憶・以前の測定・一般論を制約として渡すと、R2 はそれを所与として理想解を導くので、前提が誤っていても pass が返る（実例: 「本文は最大 4MB 級」の 4MB は同じ PR が削除した経路の実測値で、実際は 5,411 バイトだった。5 ラウンド分の作り込みがその上に乗った）。各制約に measured_how（どう測ったか）を添えろ。**kind=実測 には measured_output——実行したコマンドと、その出力そのもの——も添えろ**（貼れないほど長いなら要る行だけ）。コマンドと出力を示せないものは kind=仮説に落とせ。『実測』の札だけが検算なしで信頼値に昇格し、誤った事実がゼロベースで疑う役に所与として渡る（実測: 『CI の定義はリポジトリに無い』が実測として凍結されたが .github/workflows/test.yml は実在した。同じ run の別の節がそれを前提に書いていても、制約は訂正されない）。
