# P1 ゲートの実効性確認（writer が実行・該当 PR のみ）

対象差分が検証ゲート（CI ジョブ・assert・テスト・pre-commit）を新設・変更しているなら、そのゲートが検知すべき違反を**条件の腕ごとに 1 つずつ**作って赤くなることを確認し、確認後に戻せ。**検査をまるごと外して赤いことは、腕が守られている証拠にならない**（実測: 設計が最も強く禁じた形が、検査全体を外せば赤くなるのに当該の腕には一度も当たっていなかった）。**壊していない写しでも 1 本走らせて緑を確認しろ**（control_green）——仕掛け自体が壊れていると全部の腕が同じ色に出て逆の結論を書ける。**本物の作業ツリーを壊すな——腕ごとにリポジトリの写しを `mktemp -d` の下に作り、写しの上で壊して検査一式を走らせろ**（リポジトリの内側に作ると作業ツリー突合と記録が汚れる。共有の木を壊して戻す形は前後 2 点の突合で原理的に検出できない）。赤を一度も確認できていないゲートを「検証済み」と扱うな。
**赤が出たことは、その赤が守りたい行から出た証拠にならない**——腕ごとに「**その腕が守る行を実際に通ったこと**」も測れ（`hit_evidence`）。測り方: その柵（分岐）が書く値を一意の印に差し替えた写しをもう 1 つ作り、その印が出力か記録に現れることを見る。現れなければ、その筋書きは守る行を一度も通っていない（実測 2026-09-13: 持ち越しの可否の柵は、退行を注入しても検査が緑のままで、印も記録に出なかった）。赤・control の緑・この 3 つがそろって初めて、その腕は覆いの証拠になる。
**対象リポジトリが変異の腕の一覧と実行器を持つなら、それで撃て**（どこに在るかは対象リポジトリ側の観点——REVIEW.md——が名指しする）。実行器が撃った結果からこの返答の形を組む口を持つなら（このリポジトリの tests/mutate.py なら `python3 tests/mutate.py {{loop.gate_auto_args}} --deadline-at {{node.deadline_at}} --out <結果>` で撃った後の `--gate-efficacy <結果>`。引数は engine が組んだまま貼れ——前の周の頭の版が在る周は、前の周の修正と手直しが足した Python の分岐も自動の腕で撃つ）、その出力をそのまま返せ——手で組み直すな。回す側がその場で使い捨ての台本を書くと、置換対象の字列がコードの書き換えで消えた腕が黙って外れ、次の周も誰も同じ腕を撃てない（実測 2026-09-23: 1 周目 25 本・2 周目 18 本が外れた）。この差分が柵を足した・直したなら、その腕を一覧に足し・直すのもこの差分の仕事で、P3 の修正に含めよ。一覧を持たないリポジトリでは、上の手順を写しの上で手で行え。
**期限は `--deadline-at` で実行器に渡せ**——実行器は期限の手前で新しい腕を始めるのをやめ、撃てた腕と残りの腕（pending）を `--out` に書いて終わる（腕 1 本ごとにも書き直す）。
前の周に撃った結果のファイルが在れば `--reuse` に渡して撃つ腕を減らせ。期限で残りが出ても、期限を越えて撃ち直すな——そのまま `--gate-efficacy` の出力を返せ（残りの腕は証拠にならない行になる。続きは同じ `--out` を `--reuse` に渡せば撃てる）。
外から時間で殺す形（`timeout` 等）にするな（実測 2026-09-24: 任せ先が timeout 1800 で全腕を撃ち、結果の無いまま書いたと返した）。
arms に gate・arm・red_confirmed・control_green・hit_evidence を腕ごとに。
素材（material）の書き方: status は found（見つけた。count と detail）／clean（今ラウンドに見たが無かった。checked に何を見たか）／not_applicable（条件に当たらない。reason）／awaiting_human（人の起動待ち。reason）／not_run（やるべきだったが飛ばした。reason）。carried_over（前の周の流用）は走らなかった節に機械が書く——走った役は今の周の判定を書け（流用と書いても拒まれる）。欄と値の正本は review-record.py。
