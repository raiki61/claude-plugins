# P4 最後の関門（最終のコードで変異の検算を撃ち直す。writer が任せ先で実行）

リポジトリ: {{inputs.cwd}}　BASE: `{{record.base}}`　撃つ版: `{{loop.gates_cut.rev}}`（この周に固めた最終のコード。今の作業ツリーと同じ姿）

収束を言う前の関門。途中の版で撃った線の結果は数えない——**BASE からの変更全部を、この最終の版で撃ち直せ**。撃ち方・見逃しの定義・答えの語は並行の線（p3.delta_gates のプロンプト）と同じで、違いは 2 つ:

1. **範囲は BASE から**: 変わったファイルの腕だけを撃つ口と起点の版から機械で腕を作る口の両方に起点 `{{record.base}}` を渡して `nice -n 19` で撃ち、返答の形を組む口の出力の `arms` をそのまま返せ（実行器の在りかと呼び方: {{loop.mutation_decl.text}}）。撃ち終えるまで待て。撃てた腕が 0 本なら `arms: []` のまま返せ——0 本のまま収束してよいかは engine が人に諮る（腕を手で作り足して埋めるな）。
2. **本物の作業ツリーにも .git にも書くな・テストを足すな**（撃つのは写しの上でよい——engine が sandbox の中で起こした任せ先なら作業ディレクトリがその写し。そうでなければ `mktemp -d` の下に `git clone -q --shared {{inputs.cwd}}` して撃つ版を checkout した物）。見逃しには `equivalent`（振る舞いの変わらない変異。理由）・`needs_test`（テストが要る）・`defect`（テストでは閉じない。コードの欠陥の疑い）で答えよ。`tests_added` は使えない。`patch` は空文字。テストが要る見逃しは次の周の判定・修正・差分レビュー・CI を通って入る——関門が書いた物を誰も見ないまま収束させない。

テスト一式は回さなくてよい——同じ版の一式は、この周の p4.ci を engine が走らせた結果が正本（役の申告の `suite` は読まない）。

`rev` は撃つ版 `{{loop.gates_cut.rev}}` をそのまま。converge は、見逃しが全部 `equivalent` で、撃った版の後に作業ツリーが変わっていないときだけ収束と言う。
