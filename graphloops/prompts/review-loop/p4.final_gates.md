# P4 最後の関門（最終のコードで変異の検算を撃ち直す。writer が任せ先で実行）

リポジトリ: {{inputs.cwd}}　BASE: `{{record.base}}`　撃つ版: `{{loop.gates_cut.rev}}`（この周に固めた最終のコード。今の作業ツリーと同じ姿）

収束を言う前の関門。途中の版で撃った線の結果は数えない——**BASE からの変更全部を、この最終の版で撃ち直せ**。撃ち方・見逃しの定義・答えの語は並行の線（p3.delta_gates のプロンプト）と同じで、違いは 3 つ:

1. **範囲は BASE から**: このリポジトリなら `nice -n 19 python3 tests/mutate.py --changed-since {{record.base}} --auto {{record.base}} --deadline-at {{node.deadline_at}} --out <結果>` の後に `--gate-efficacy <結果>`。その `arms` をそのまま返せ。盤面の lanes/ に同じ版を撃った線の `--out` が残っていれば `--reuse` に渡してよい（指紋が同じ腕だけ持ち越す）。期限で残った腕は証拠にならない行になる——その腕は `needs_test`（撃ち終えていない）で答えろ。
2. **作業ツリーにも別の worktree にも書くな**（テストを足さない）。見逃しには `equivalent`（振る舞いの変わらない変異。理由）・`needs_test`（テストが要る）・`defect`（テストでは閉じない。コードの欠陥の疑い）で答えよ。`tests_added` は使えない。`patch` は空文字。テストが要る見逃しは次の周の判定・修正・差分レビュー・CI を通って入る——関門が書いた物を誰も見ないまま収束させない。
3. **テスト一式を今の作業ツリーで回し**（CI と同じもの。このリポジトリなら `bash graphloops/tests/run.sh` と `bash tests/run.sh`。`nice -n 19` で）、`suite` にコマンドと終了コードを書け。

`rev` は撃つ版 `{{loop.gates_cut.rev}}` をそのまま。converge は、見逃しが全部 `equivalent` で、テスト一式の終了コードが 0 で、撃った版の後に作業ツリーが変わっていないときだけ収束と言う。
