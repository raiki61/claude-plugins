# P3 修正差分の腕（writer が実行。柵の分岐ごとに退行を注入して赤を見る）

修正の差分: {{loop.fix_delta.file}}（周の頭に固めた版と修正後の姿の差）　変わったファイル: {{loop.fix_delta.files}}
リポジトリ: {{inputs.cwd}}（読む版: `{{inputs.review_rev}}`）——周の頭の版。撃つのは今の作業ツリー（修正後）の写し

**この修正が足した・変えた柵（検査・拒否・分岐）ごとに、腕を撃て。** 手順と証拠の要件は P1 のゲートの実効性と同じ——腕ごとに写しの上で
退行を注入して赤（red_confirmed）、壊していない写しで緑（control_green）、その腕が守る行を通ったこと（hit_evidence）。
**腕の無い分岐は、red_confirmed=false と note『腕が無い』の行で書け**（found）——手直しの節がその分岐に腕を足す。
読み役のレビューは『新しい分岐に腕が在るか』を見ない（実測 2026-09-24: 前の周の修正の 3 分岐に腕が無いまま、次の周の判定まで残った）。

対象リポジトリが変異の腕の一覧と実行器を持つなら、それで撃て。このリポジトリなら
`python3 tests/mutate.py --changed-since {{inputs.review_rev}} --auto {{inputs.review_rev}} --out <結果>` の後に `--gate-efficacy <結果>` の出力をそのまま返せ。
`--changed-since` は変わったファイルの一覧の腕を、`--auto` はこの周の修正が足した Python の文と式（if の条件・or/and の項・条件式・raise・
式の呼び出し・累算代入）から機械で作った腕を撃つ——**一覧に腕を宣言していない入口は、自動の腕の生き残り（GREEN）として出る**。
自動の腕が扱わない分岐（JSON・Markdown・台本・代入の値）で柵を足したなら、その腕を上の形の行として足せ。
**時間の上限（timeout）を付けるな**——腕の数によっては 30 分を超える。**バックグラウンドで走らせ、完了の通知で待て**（ファイルの有無をループで見張るな）。
