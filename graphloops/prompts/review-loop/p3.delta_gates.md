# P3 変異の検算と見逃しへの答え（並行の線。周の締めを止めない）

**回す側へ**: この節は背景の任せ先が読む。任せ先（sonnet）を**背景で**立てて「このファイルを Read し、その指示どおりにやれ」とだけ渡し、**待たずに**受領 `{"lane": "{{loop.gates_cut.result}}"}` を out_path に書いて done しろ。周の締め（P4・R1〜R4）も次の周も、この線を待たない。末尾の JSON Schema は受領の型で、線の結果の型ではない。

---

**任せ先へ**: あなたは変異の検算の線を 1 本、最後まで走らせる。回す側はあなたを待っていない——途中で報告せず、最後に結果のファイルを 1 つ書いて終われ。

- リポジトリ: {{inputs.cwd}}
- 撃つ版: `{{loop.gates_cut.rev}}`（この周の修正と手直しが済んだ姿）　範囲の起点: `{{loop.gates_cut.from}}`（この周の頭の版）
- 範囲で変わったファイル: {{loop.gates_cut.files}}
- 結果の置き場: `{{loop.gates_cut.result}}`　足したテストの patch の置き場: `{{loop.gates_cut.patch}}`

1. **生きた作業ツリーに触るな。** 回す側が同じ作業ツリーで次の周を進めている。撃つ版から別の worktree を作り、その上だけで作業しろ:
   `T=$(mktemp -d) && git -C {{inputs.cwd}} worktree add --detach "$T/wt" {{loop.gates_cut.rev}}`。終わったら（失敗しても）`git -C {{inputs.cwd}} worktree remove --force "$T/wt"`。
2. **撃つ。** 対象リポジトリが変異の腕の一覧と実行器を持つなら、それで撃て（どこに在り・どう呼ぶかは対象リポジトリの側——README・CONTRIBUTING・CI 定義・対象リポジトリの REVIEW.md など——が名指しする。このプロンプトは道具の名前と引数の綴りを持たない）。worktree の中で、
   変わったファイルの腕だけを撃つ口と起点の版から機械で腕を作る口の両方に起点 `{{loop.gates_cut.from}}` を渡して撃ち（結果は `$T` の下に置く）、実行器が撃った結果から返答の形を組む口の出力の `arms` をそのまま結果の `arms` にしろ——手で組み直すな。同じ機械で別の run も動いているので `nice -n 19` を外すな。期限は無い——撃ち終えるまで走らせろ。外から時間で殺す形（`timeout` 等）にするな。
3. **見逃しに 1 本ずつ答える。** 見逃し＝赤（red_confirmed）・対照の緑（control_green）・当たりの証拠（hit_evidence）のどれかが欠けた腕。腕ごとに `handled` を 1 行（key は `arm:<腕の名前>`）:
   - `tests_added` — worktree にその腕を殺すテストを足し、その腕だけを撃ち直して（実行器の撃つ腕を名指しで絞る口で）赤を見た。how に何を足してどう赤を見たか。
   - `equivalent` — 変異しても振る舞いが変わらない（等価な変異）。how にどの入力でも同じになる理由。
   - `defect` — テストを足しても閉じない（変異した方が正しい・柵がそもそも効いていない等、コードの欠陥の疑い）。how に何が欠陥に見えるか。**コードは直すな**——次の周の判定者が振り分ける。
   - `needs_test` — テストが要るが足せなかった。how に理由。
   見逃しの無い腕に行を書くな。
4. **テスト一式を回す。** テストを足したら、worktree の上でテスト一式（CI と同じもの。CI 定義が正本）を `nice -n 19` で回し、全部が緑になるまで直せ。テスト一式が自分の件数を定数で持つなら（件数の柵。どこに在るかは対象リポジトリの側が名指しする）、回すときは実測に合わせてよいが、**patch を作る前にその行だけ元に戻せ**——件数の行は合流した周の修正が実測に合わせる（遅れて届く patch が同じ行で当たらなくなるのを避ける）。`suite` に回したコマンドと、最後に回した終了コードを書け（足さなかったなら撃った版そのままで回す）。
5. **patch を作る。** テストを足したなら `git -C "$T/wt" add -A && git -C "$T/wt" diff --cached --binary {{loop.gates_cut.rev}} > {{loop.gates_cut.patch}}`（worktree の index はあなたの物で、生きた作業ツリーの index ではない）。`patch` にその置き場を、足さなかったなら空文字を書け。
6. **結果を書く。** 下の型の JSON を `{{loop.gates_cut.result}}.tmp` に書いてから `mv` で `{{loop.gates_cut.result}}` に移せ（読む側が書きかけを読まない）。`rev` は撃つ版 `{{loop.gates_cut.rev}}` をそのまま。
