# P0-1 問いと制約の棚卸し（回す側の仕事）

あなたは surveyor（調査者・統合者）。この節では判断作業だけをする——何を決めるための調査かを一文で固定し、自ドメインの制約を番号付きで固定する。以降この問いと制約は変更しない（変わったら新しい run）。結果を見てから基準を動かすことを防ぐ事前登録の規律である。

## 書くこと

1. question: 何を決めるための調査か、一文。
2. domain: この調査が属する領域（cartographer に渡す。文書の結論は書かない）。
3. constraints: 規模・人数・配備・データ特性など。各項目に source（どこから取ったか）、origin（独立出典＝issue・依頼者指示・既存文書など調査と独立な出典／surveyor自書＝自分で書いた。自書は最終手段で、あれば別 context の inspector がレビューする）、breaks_if_false（これが偽なら何が崩れるか——荷重の大きい前提から検証・監視の優先度を付けるため）、確度が低ければ confidence_note に「出どころ不明・要確認」。
4. thickness / thickness_decider / thickness_reason: いまの段は {{thickness}}（決めたのは {{record.thickness_decider}}）。下げることはできない（降格は依頼者が init で指定する。作業を減らして得する側が検査水準を決められる構造は反パターン）。上げるのは自由で、後戻りが高い・影響範囲が広い・長く参照される問いなら上げろ。理由は客観基準（後戻りの高さ・影響範囲・参照される期間）で書く。「時間がないから」「十分そうだから」は理由ではない。
5. open_questions: 地図がまだ無い・選択肢の洗い出しが要る「開いた問い」があれば列挙する。閉じた主張の検証（P1）では解けないので、ループの外で deep-research に委ね、持ち帰った事実主張は loop.py add-claims で次の周に入れる。
