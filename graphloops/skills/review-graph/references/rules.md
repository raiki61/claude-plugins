# review-graph で守ることと、大きな差分

## 置き場（グラフ・engine・rules）

- **グラフ**（このプラグインの `graphs/review-loop.json`）—— 工程（ノード）・依存・役・各ノードのプロンプトと返答の型
- **engine**（このプラグインの `scripts/loop.py`）—— グラフを読んで盤面を持つ機械。どのノードが終わったか・同時に走らせてよい組・各ノードに渡してよいもの（グラフの `reads` の宣言に無いものはプロンプトに貼らない）・作業ツリーの前後突合・走らせなかった素材のフィールド・R1/R2 の再発火・周の記録の組み立て・検証器の 3 分岐の読み取り・周の上限
- **rules**（このプラグインの `rules/review-loop.py`）—— グラフに書けない算術。記録のフィールドと語彙は検証器の定数を写さず import する

## 守ること

- **run の途中でプラグインの版を上げても、走っている run の graph は init の時の版のまま**: 盤面は init の時の graph を、その置き場（インストールされた版のディレクトリ）の絶対パスで持ち、graph・指示書・rules・検証器をそこから読み続ける。置き場のファイルそのものが書き換わる形（`--plugin-dir` などでその場から読み込んだプラグイン）では graph も変わり、変わった周は `next` の `notes` と `process.graph_changes` に出る。engine（`loop.py`）は今インストールされている版で動き、役の定義（convergence-loops の `agents/<役>.md` のツール・モデル・effort・system prompt に足す本文）はノードを描くたび（`next` がノードを出すとき）に今見つかる版から読む——どの engine が周を回したかは、替わった周の `next` の `notes` に出る。新しい版の graph や指示書の動きが要るなら、走っている run を仕上げてから新しい run を始めよ。盤面を別の版の graph へ付け替える手順は用意していない（`loop.py patch` で state を書き換えれば変わるが、それは手当ての口で、この用途には案内しない）。更新で置き換わった古い版のディレクトリは後で掃除されることがあり（公式の plugins の読み込みの文書『Cleanup of previous versions』）、消えるとその run は開けなくなる。古い版の graph が役を `--output-format text` で起動しても、engine は包みでない標準出力を本文として読むので、返答は受け付けまで届く。
- **graph はブロックの約束（プラグインの `blocks/`）を `$ref` で引く**: graph と `blocks/` は同じ版のプラグインの置き場から読む（graph からの相対だけで引き、ほかの置き場へは落ちない）。`blocks/` を引けない古い engine は新しい graph を読めない（引けない `$ref` で止まる）。ブロックのファイルだけが変わっても graph の変化に数え、変わった周は `next` の `notes` と `process.graph_changes` に出る。
- 周の記録（`rounds/round-<N>.json`）を直接編集しない。判定のフィールドは役の返答から engine だけが書く。手当ては `loop.py patch`（痕跡が残る最終手段）: `--path` は記録のフィールド（`record.` を付けても付けなくても同じ所）か `state.<盤面の欄>` か `out.<節>.<欄>`（ノードの最新の出力。書いた後の形をノードの schema で照合する）、`--file <json>` で書くか `--delete` で在る鍵を消す（無い鍵は拒む。綴りを誤って書いた鍵も消せる）。
- **engine が走らせる CI のノード（`p0.local_checks`・`p4.ci`）を人の指示で走らせない**なら `loop.py skip --node <ノード> --reason "<理由>" --dir <DIR>` で省け（`patch` で盤面を書き換えない）。素材 `local_checks` は理由つきの条件外で記録に残り、検証器が阻害なしの周に `ci_unverified` として人に聞かれる（収束するのは engine が走らせた CI が clean の周だけ）。起動中のノードは拒まれる。CI のノードを省いた run は、収束の手前で engine が「CI を自分で確かめてから続けるか（continue）、未収束のまま報告に進むか（stop）」を 1 度だけ人に聞く。答えた後は聞き直さず、残る阻害が CI 未確認だけになった周で止まる（盤面の `stop_reason` が `ci_unverified_stopped`）。
- 探す役に「ここは見るな」の線を引かない（プロンプトを書き換えない）。削るのは judge の仕事である。
- 数える問い（判定者の `class_query`・修正の `coverage` の `how`）は engine が数える——判定者の件数は周に固定した版で、修正の前後は p3.fix の done で。回す側が数える口は置いていない（置いていた数えるサブコマンドは、engine の数え方と揃わない入口として 4 回繕われ、使う側が無かったので消した）。
- **Web を読む調べ（先行例・一次情報の確かめ）は自分でやるな**——読み役（`convergence-loops:investigator`）を起動して任せ、返った結論と出典だけを受け取れ。ページの本文があなたの文脈に入ると、周を回す文脈が先に尽きる。外へ送る検索語に対象の名前を載せない規律は、役の定義（convergence-loops の `agents/investigator.md` と `agents/judge.md`）が持つ。
- 盤面の置き場は `git rev-parse --git-dir` の下（作業ツリーの外）。investigator の前後と P1 の前後で engine が作業ツリーを突き合わせる。自分の変更なら `--accept-tree-change "<理由>"` で痕跡付きで通す——investigator の instance の突合で止まったなら `done` に、P1 後の機械のノードで止まったなら `next` に付ける（そのとき pending の instance は無いので `done` では通せない）。
- **回す側の手の心得**（人の居ないターンで止まらない・取り違えない）: ①手順書が命じていない消す操作（一時の写しの片付けを含む）は、人の居ないターンで打たない——許可の問いは主の会話に出るので、答える人が居なければそこで止まり続ける（実測 2026-09-27: 最後に一時の写しを消すコマンドが許可待ちになり 50 分止まった）。写しは消さず、置き場を報告に書いて人に渡せ。②背景に回すのはハーネスの Bash の背景実行で、シェルの `&` ではない——背景実行なら作業に ID が付き、止める口と出力を引く口をハーネスが持つ。③ノードと線の結果は盤面で見る。背景の作業の出力で判断しない（別の背景の作業の出力と取り違える）。待つのは `run` の終了コードである。
- 報告は依頼者の言語で書く。この手順書が日本語なのは理由にならない。

## 大きな差分と生成データ

ツールゼロの役（`p1.hygiene`・`r2.compare`）は差分の本文を指示書に貼って受け取る。標準入力で渡すので Agent ツールの貼る上限には当たらないが、モデルの入力の上限は残る（実測 2026-09-27: 生成データ約 2 MB を足した run で、2,149,613 バイトの指示書が Prompt is too long で落ち、R2 の審査が抜けた）。graph は役の入力の上限をバイトに直した値を `launch.input_budget_bytes` に、役が Read で読む本文と返答の余白を `launch.read_room_bytes` に宣言し、rules は差分がそこから指示書の差分の外の本文の分と余白を引いた値を超えた周だけ、セクションを要約（行数・バイト数・全文の行範囲）に替えた写しをツールゼロの役に貼る。要約する順は、BASE の `.gitattributes` で `linguist-generated` が立つファイル → この差分の `.gitattributes` で新しく立ったファイル → そのほか、段の中は大きい順で、収まった所で止める。`.gitattributes` の変更のセクションは要約しない。要約したセクションの本文は、ノードの `read_file` が名指す全文の写しを Read で読ませる——engine はその写しを指示書の隣に置き、ツールゼロの役にその 1 本だけを読む Read を渡す（起動方法は graph の `launch.isolated_read`。空の一時ディレクトリで起動し、`dontAsk` と実パスの `Read(//…)` の規則で 1 本に縛る）。予算の内の周は今までどおり全文を貼る。ツールを持つ役には全文の写しの置き場を渡し続ける。差分は利用者の git の設定に依らない旗で撮り、描画の属性（`-diff`・`binary` 等）は BASE の版から引く（git 2.42 から。古い git では作業ツリーの属性で描く）。要約に替えた周・生成データの属性が引けなかった周（`git check-attr --source` は git 2.40 から）・替えても超えた周は、起動するのを止めずに記録の `process.notices` と報告に出る。
