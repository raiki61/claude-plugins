# 変更の記録（works-dispatch）

works-dispatch（`/works-dispatch:dispatch` スキルと、`dispatch/` のスクリプト）の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版の出し方（この記録を書き足す段。git の tag は作らない）は、リポジトリのルートの `docs/releasing.md` に在る。0.1.0 は出していない。作った時に付けた版の後に変更を積んだので、初めて出す版を 0.1.1 にした。

## [0.24.0] - 2026-10-17

### Added

- 頼みと納品の知らせを、相手の会話の待ち受けが会話を起こして届ける形にした（持ち主の決め、2026-10-17）。今までは相手の窓の入力欄に herdr で打ち込んでいたので、人が窓口に打っている途中に納品が届くと、人の文と納品がくっついて届いた。プラグインのフックが、部署と窓口（`--desk`）の会話の番の終わりと始まりに裏で待ち受けを起こし（Claude Code のフックの `asyncRewake`）、待ち受けは自分の会社の受付箱の台帳の、宛先が自分（「会社/名前」。前の名前も）の行だけを見て、見つけたら会話を起こす。宛先違いの行は会話に渡さない。待ち受けの居ない会話（このフックの無い古い版の会話・落ちた会話）には、今までどおり打ち込む。別のアカウントの部署からの納品でも、裏の会話（`claude --bg`）でも起きることを確かめた。
- 順番待ち: 待ち受けの居る部署への `--ask` は、前の頼みを納品していなくても止めずに積み、受付番号と何件目かを返す。部署が納品したら、待ち受けが次の 1 件を渡して起こす。同じ中身の頼みが積まれているか動いていれば、新しく積まずにその受付番号を返す。`--tree` の部署の行に順番待ちの件数を出す。
- 機械窓口: 会社の形の役に、AI を起こさずに機械で答える道具（`[[roles.tools]]`。欄は MCP の道具の定義に合わせた `name`・`title`・`description`・`inputSchema` と、`command`・`fallback_role`）を書けるようにし、呼ぶ口 `--call <会社/役> <道具>` を足した。片づかなければ外れを受付箱の台帳に残し、その入力を回す役の AI の部署への頼みに変えて順番待ちに積む（常設の部署が無ければ一度きりの部署を自動で立てる）。AI の部署を持たない役は `machine = true` と書く。`--tree` に道具と外れの回数を出す。
- 合図: 会社の形の `[[land.after]]` に書いた道具を、`--land` が本流へ push し終えた後に呼ぶ。

### Changed

- `fresh = true` の役の部署は、待ち受けが居れば、次の頼みの前ではなく、納品して止まった時点で会話を空にする（終わった会話が画面に残り、herdr に done と出続けるノイズを減らす）。

## [0.23.0] - 2026-10-17

### Added

- 会社の形の `[[roles]]` に `effort` の欄を足した（持ち主の OK 済み、2026-10-17）。部署を起こすとき（`--task` と、`--ask` で新しく立てるとき）に `--effort` で渡す。役の `effort` の欄を省けばそのアカウントの既定のまま（`--effort` を付けない）、欄に値（`low`・`medium`・`high`・`xhigh`・`max`・`ultracode`）を書けばその値、`inherit` なら頼んだ会話（上役）の今の effort（Claude Code が Bash の道具に渡す `CLAUDE_EFFORT`）で起こす。知らない値は Claude Code が注意を 1 行出すだけで既定に戻す（裏の会話の注意は誰も読まない）ので、読むときに弾いて注記を出す（役は外す）。`model` の `inherit` は作っていない（上役の会話の今のモデルを外から読む口が無い）。書けば注記を出して役を外す。`--ask` が既に立っている部署に頼みを送るときは、モデルと effort を変えない（起こしたときのまま）。`--dry-run` は起こすときの effort も出す。

## [0.22.0] - 2026-10-17

### Added

- 部署の会話が番を終えて、裏で走らせた Bash（`run_in_background`。`--land` など）の終わりを待っているとき、herdr の表示名に「・裏の処理待ち」を添える（例: `担当（常設・毎回空）・裏の処理待ち`）。herdr の状態は番が終わると done になり、待っている会話も終わったように見えて、持ち主が見誤った。Stop のフックが、番の終わりに会話のプロセスの子に残る Bash の道具のシェルを数えて付け、待ち終えた後の番の終わりに外す。待っている間は、納品していない頼みの差し戻しもしない（裏の処理が終われば会話が起きるので、待つだけの番を差し戻しの上限まで繰り返していた）。裏で走らせたサブエージェントは数えない。Windows では出さない。
- `--sync` が、会社の形の役の `fresh` を今いる部署の属性 `company.fresh` に写し直す。会社の形を変えたら、`--sync` 1 回で全部の部署の属性と herdr の表示に行き渡る（今までは `--ask` か `--reorg --role` を打つまで写らなかった）。

### Fixed

- 0.21.0 の記録の「会話の一覧に見えなければそれで打つ」が、何を打つのか読み切れなかった。部署の窓に `<アカウントのコマンド> attach <短い id>` を打って会話を戻す（頼みを打ち込むのは戻った後）と書き切った。

## [0.21.0] - 2026-10-17

### Added

- 会社の形の `[[roles]]` に `fresh` の欄を足した（持ち主の決め、2026-10-17）。`fresh = true` の役の部署は、頼みごとに空の会話で受ける（省けば今までどおり会話を持ち越すので、今の会社の形は書き足さなければ変わらない）。`--ask` は、部署が前の頼みを納品し終えていて会話が止まっていれば、新しい頼みを打つ前に `/clear` を打ち、会話の id が変わったのを見てから頼む。前の頼みの無い部署と、動いている会話は空にせず、そのまま頼みを送る（動いている会話では、頼みは今の番の後の待ちの列に入る）。`resident`（常設か都度か）とは別の軸で、常設の値打ち（受け持ちごとの席: 順番を 1 本にする・宛先の名前・決まった窓）は残したまま、前の頼みの記憶を持ち越さない（記憶は太るうえ、覚えた中身で書き直すと、ほかの部署が入れた行を消す）。`--init-company` の下書きは、担当を `fresh = true`（常設・毎回空）にし、相談（常設・持ち越し）の例をコメントで足した。部署には役の `fresh` を属性 `company.fresh` に写す。
- herdr の表示名に、常設か都度かと会話の持ち越し方を添える（例: `担当（常設・毎回空）`・`相談（常設・持ち越し）`・`作業（都度）`）。herdr の設定の行の並びは変えずに見える。`--tree` の役の欄も同じに出す。

### Changed

- 「常駐」の言葉を、会社の形と文書の言葉「常設」に揃えた（`--tree`・`--clean`・`--land` の出力と SKILL.md）。

### Fixed

- 部署の会話で `/clear`・圧縮（compact）・`--resume` をすると会話の id が変わり、部署の属性 `company.session` が古いまま残っていた。古い id のままだと、`--ask` が会話の動き出しを見られず、Stop のフックが部署の会話を別の会話と見て納品を促さなかった。SessionStart のフックが、そのときだけ属性を新しい id に書き直す（新しく起こした会話と代表の clone では書き直さない）。裏の会話の短い id（`claude attach` に渡す。`/clear` の後も変わらない）は属性 `company.job` に残し、部署の窓から会話が消えて --ask が戻すとき、会話の一覧にその会話が見えなければ、部署の窓に `<アカウントのコマンド> attach <短い id>` を打って戻す（頼みを打ち込むのは戻った後）。
- `--land` の版上げが、`plugin.json` の説明（`description`）の字だけを変えたプラグインを、記録の節が Changed なら minor に上げていた（tiers 0.5.0）。説明の字だけの変更は試験と文書と同じに数え、patch にする。

## [0.20.1] - 2026-10-17

### Fixed

- `--ask` が、動いている部署の会話に頼みを打つと「3 回打ったが、会話が動き出さない」で failed を返し、頼みを 3 回届けていた。failed なので部署に頼み元を書かず、部署の納品が前の頼み元へ届いた。原因は 2 つ。
  - 部署の会話で `/clear` を打つと会話の id が変わるのに、部署の属性 `company.session`（部署の worktree の git の設定に書く会話の id）は古い id のままで、会話の一覧から部署の会話を引けず、動き出しを見られなかった。直した後は、id で見つからなければ、一覧のうち作業フォルダが部署の作業場で、終わっていない裏の会話（`claude --bg` で起こした会話）が 1 つだけならそれで見る（0 か 2 つ以上なら見つからないとし、動き出しは見ずに画面の字だけで確かめる）。頼みを届けたとき、id が変わっていれば属性を見つけた会話の id に書き直す。
  - 送る前から動いている会話に打った字は、今の応答が終わった後に読まれる待ちの列（入力欄の上に「❯ <打った字>」と並ぶ）に回るので、動き出しでは確かめられなかった。直した後は、そういう会話には 1 回だけ打ち、入力欄に残れば Enter を足し、入力欄の上（待ちの列）に載るか入力欄から出たのを見て届いたとする。画面で見られなくても打ち直さず、届いたとする（打ち直すと同じ頼みが何度も届くため）。送る前に動いていなかった会話は、前の版と同じく、動き出しを見て確かめ、見えなければ 3 回まで打ち直す。
- 代表の clone の `.git/info/exclude` に `.claude/` を丸ごと足していた。exclude は全 worktree で共有なので、`.claude/` の下に新しく作ったファイル（フックの台本など）が未追跡に出ず、commit し忘れに気づけなかった。足すのを部署の会話が書く許可の記録 `.claude/settings.local.json` だけにした。前の版が足した `.claude/` の行は残るので、手で消す（`<代表の clone>/.git/info/exclude` の `.claude/` の 1 行）。
- `--check` が、dispatch の呼ぶ herdr の口のうち `pane.process_info`（PR を開く道）と、`pane.send_keys`・`workspace.rename`（部署の道）を確かめていなかった。`pane.process_info` は PR を開く道の集まり（`HERDR_METHODS`）に、部署の道の 2 つは部署を立てる実行の集まり（`TASK_HERDR_METHODS`。`--check` はこちらも確かめ、足りなければ注記に出す）に足し、`docs/prerequisites.md` の PR を開く道の口の数を 11 から 12 に直した（増えたのは `pane.process_info`）。
- Windows で、`limits.py herdr-config` が herdr のタブ欄（herdr がタブを並べる欄。dispatch はその右端にアカウントの使用率を出す）に書くパスが `\` 区切りを引用符で包んだ形になり、`activity.py` の settings の塊は台本のパスだけドライブ名が付かなかった。どちらも、ドライブ名の付いた `/` 区切りの形で書く。

## [0.20.0] - 2026-10-17

### Added

- `--land` に、部署どうしの書き換えの取り合いを止める関門を足した（持ち主の決め、2026-10-17）。部署が本流を最後に知った位置（属性 `company.base`。`--task` が枝を作ったときの origin の本流と、その部署の `--land` で入れた後の本流）より後に、ほかの部署が本流へ入れた行を、部署の枝が消していれば、関門に出さずに止め、部署の窓に「どの commit（件名）の、どのファイルの何行目を消すか」を打ち込む。部署が前に読んだ中身を覚えたまま書き直すと、ほかの部署が入れたばかりの行を消しても git の衝突にならず、関門の試験も通っていた（まっさらな環境での 2 回目の試し）。わざと消すなら `--land <部署> --keep-removal` で通す。`--dry-run` も止まる見立てを出す。位置の記録が無い部署（0.19.8 までに立てた部署）は見ずに注記を出し、その `--land` の後から記録する。

### Fixed

まっさらな環境での 7 回目の試し（`docs/trials/2026-10-16-clean-env-7.md`）で、未納品の頼みを持ったまま落ちた部署を `--ask` が戻せなかった形の直し。

- SKILL.md に、部署の会話を止める手順（先に部署の窓の attach を終わらせてから `claude stop <短い id>`。窓が開いたままだと attach が会話を起こし直す）を書いた。

- SKILL.md の「アカウントの書き方」と `--init` の下書きに、`CLAUDE_CONFIG_DIR` をシェルの環境でだけ入れる人も `config_dir` を書くことを足した。
- macOS で、部署の作業場に付ける信頼の印が `/tmp/…` の形で書かれ、効いていなかった。Claude Code は記号のリンクを解いた形（`/private/tmp/…`）で引く（2.1.301 で、`/tmp/…` の印では信頼の確認が出て、`/private/tmp/…` の印では出ないことを確かめた）。印は解いた形で書く。

- フォルダの信頼の判定（`--check` の注記と、部署の作業場への信頼の印）が、Claude Code の書いたフォルダの字と dispatch の持つ字の違いで外れていた（Windows の `C:/…` と `C:\…`、macOS の `/tmp` と `/private/tmp`）。記号のリンクを解き、OS の決まりで大文字小文字と区切りを揃えて比べる。新しく書く印は、Claude Code が書いた区切りに揃える。

## [0.3.0] - 2026-10-15

### Added

- `--issue N`。issue から始める作業の入口。issue に結んだ枝（`gh issue develop --list`）の作業場を開き、1 ターン目の `/catchup N` まで送って止める（2 ターン目の文は送らない）。結んだ枝が見えなければ、その issue を閉じる開いた PR の枝を使い、それも無ければ既定の枝から GitHub に枝を作って issue に結ぶ（`gh issue develop`）。報告の行は `issue #N` で始め、枝を出す。閉じた issue には枝を作らず `issue_closed` で止める。`--pr` とは一緒に使えない。
- 作業場の一生を 1 つのコマンドで回すようにした（引数なしで回すとき）。自分が作者でレビュアーの付いていない PR は開かない（`own_unreviewed`）。会話の開いている PR は、前に送った後に相手の新しい返事が有り、会話が手すきで手元の作業も無ければ、古い会話を終えて同じ場所で送り直す（`refreshed`）。閉じた PR の場所は最後に片付ける。送り直しも片付けも、終える会話は herdr が見ている会話のペインの物だけで（herdr の外の会話は終えない）、閉じる作業場はその場所の worktree の作業場だけ（ほかの作業場のペインがそのフォルダに cd していても閉じない）。その作業場にシェルでない物が居れば閉じない（`close_failed`）。片付けは、会話が 2 つ以上なら残し、会話を終えた後に一覧を取り直して居ないことを確かめてから消す。作者が force-push した枝は、場所の HEAD が前に送った時の head のままで場所がきれいなら、`git reset --keep` で origin に揃える（前に送った時の控え `dispatch-sent.json` に head も書く）。1 ターン目の終わりは、herdr の画面の見立てでなく Claude Code の会話の状態で見る。

### Changed

- 作業場を、PR ごとの clone（`<clone_root>/<名前>-pr-<番号>`）から、枝ごとの git worktree に替えた。代表の clone（設定の `source`）から、herdr（会話を走らせる端末を作業場とペインに分けて並べる道具）の `herdr worktree create` で作り、置き場は herdr の設定の `worktrees.directory`（既定 `~/.herdr/worktrees/<リポジトリ>/<枝>`）に任せる。作るときも使い直すときも、origin の今の head へ早送りしてから `/catchup` に渡す（手元にしか無い commit が有れば動かさない）。代表の clone 自身がその枝を開いていれば作らず `branch_busy` と報告する。fork の PR は作らず `provision_failed` と報告する。
- 報告の行の 3 つ目の欄を、作業場のフォルダの名前から枝の名前に替えた。
- `--check` は、設定の `source` が本体の clone か（linked worktree でないか）も確かめる。
- 片付け（`--clean`・一覧で回したときの最後）は、代表の clone の linked worktree だけを見る。枝の PR が閉じていて、会話が無く、手元の作業（未コミットの変更・git に足していないファイル・その枝の stash）も無く、手元の枝の先頭が PR の head と同じ場所だけ、worktree と手元の枝を消す。PR の無い枝は消さない。設定の `copy_files` のうち写し元と中身が違うファイルが有る場所は残して名指し、ほかの git が追わないファイル（依存・生成物）は一緒に捨てる。会話や herdr を読めなければ、traceback で止めずに、その場所を残して報告に書く。
- 1 件あたりの使用率の見積もりは、1 ターン目の終わりまで待った件だけから取る。`--no-second` と `--issue` の件は 1 ターン目を送ってすぐ測るので、`/catchup` がまだ使用率を使っていない時点の差（ほぼ 0）を 1 件あたりとして覚え、見積もりを小さくしていた。

### Removed

- 設定の `clone_root`。読まなくなった（設定に残っていても止めない。消してよい）。前の版が作った `<名前>-pr-<番号>` の clone は、この版の片付けの対象にならない。要らなければ手で消す。

## [0.2.0] - 2026-10-15

### Changed

- PR を 1 つのアカウントに全部入れず、アカウントの使用率の残りに合わせて割り振るようにした。全部の PR の `/catchup` は同時に走るので、始める前に件数を決める。各アカウントに、週と 5 時間の枠の使用率が上限（既定 95%）に届かない件数まで入れ、あふれた分を次のアカウントへ回す。1 件あたりの使用率は、dispatch が毎回、始める前と全部の `/catchup` の後に使用率を問い合わせて（出力 0 トークン）測り、`<limits_dir>/dispatch-cost.json` に覚える。まだ測っていないうちは、選べるアカウントに 1 件ずつ順に配る。報告の頭に、何をもとに割り振ったかを 1 行で出す。`--dry-run` は問い合わせない。

## [0.1.4] - 2026-10-15

### Fixed

- Windows で、`--clean --apply` が PR ごとの clone を消せなかった。Windows の git は `.git/objects/` の中を読み取り専用で作るので、そのままでは消せない。読み取り専用を外して消し直す。作業場を作りかけで失敗したときの片付けも同じ理由で作りかけを残し、次の回にそれを別のリポジトリのフォルダとみなしていた。これも直した。
- Windows で、作業場のペインのシェルを POSIX のシェル（`/bin/sh`）で起こそうとして落ちていた。POSIX のシェルが無ければ、コマンドは PATH の上で探し、ペインは既定のフォルダとみなす。
- Windows の `\` の区切りのパスで、消えたプラグインのパスの検出（`--check`）が古いパスを見落とすか、別のパスを報告していた。手元のパスの origin から OWNER/NAME を取れず、作った clone の読み戻しが落ちていた。`limits.py herdr-config` が出す行も、`\` を含むパスで herdr の TOML を壊していた。

### Changed

- `--clean --apply` は、1 件でも消せなければ終了コード 1 で終わる（前は 0）。

## [0.1.1] - 2026-10-15

### Added

- `/works-dispatch:dispatch` スキルと `dispatch/dispatch.py`。自分の番の PR（attention の whose-turn）を、PR ごとの作業場（代表の clone から作る `<名前>-pr-<番号>` の clone と、同じ名前の herdr の作業場）に開き、週の使用率のリセットが近いアカウント（95% を超えるものは外す）で Claude Code を起こして、`/<attention のプラグイン名>:catchup <番号>` と設定の 2 ターン目の文を送る。AI は使わない。開いている会話は閉じず、同じリポジトリとブランチの会話が開いていれば飛ばす。引数は `--dry-run`・`--pr N`・`--no-second`・`--clean [--apply]`・`--init`・`--check`。前提と、試しの実行で確かめた外の道具の振る舞いは README に在る。
- アカウントの書き方を 3 通りにした。`claude` をそのまま使う形、設定のフォルダを分ける形（鍵の Keychain の項目の名前を `keychain_service` で上書きできる）、使用率の枠の無い形（`limits = false`。Ollama・Foundry など）。数に決まりは無い。
- `dispatch/limits.py`（任意）。アカウントごとの使用率の控えを作り、herdr のタブ欄に 1 行ずつ出す。`herdr-config` が herdr の設定に貼る行を出す。
- `dispatch/activity.py`（任意）。Claude Code のフックから、herdr のサイドバーに会話ごとの作業内容を出す。`activity.py settings` が settings.json に足す hooks の塊を出す。
- `--check` が、アカウントごとの herdr の連携と、herdr の設定やフックが消えたプラグインのフォルダを指していないかも見る。
