# 変更の記録（works-dispatch）

works-dispatch（`/works-dispatch:dispatch` スキルと、`dispatch/` のスクリプト）の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版の出し方（この記録を書き足す段。git の tag は作らない）は、リポジトリのルートの `docs/releasing.md` に在る。0.1.0 は出していない。作った時に付けた版の後に変更を積んだので、初めて出す版を 0.1.1 にした。

## [0.14.0] - 2026-10-16

### Added

- 会社の形（`.claude/company.toml`）の頭に `default_role` を書くと、`--task` で `--role` を省いたときの役になる（省けば `作業者`）。省いたときの役が会社の形に無ければ、止めずに「役の本文と起動の設定が付かない」と注記を出す。
- 会社の形の役の項目（`[[roles]]`）に `resident = true` を書くと、その役の部署は `--resident` を付けなくても常駐の部署で立つ。部の管理者のような常設の役に書く。0.13.0 までは、役で宛てた頼み（`--ask 会社/役`）で部署がまだ無いときに `--resident` を付け忘れると都度の部署が立ち、次に同じ役で頼んでもその部署が見つからず、別の部署を立て直していた。

### Changed

- `--init-company`（会社の形〔`.claude/company.toml`〕の下書きを書く命令）の下書きを、組織の「部＋役職」の形で書くようにした。部は受け持ち（プラグインかフォルダ）ごとに会社で違うので例を 1 つだけ置き字で書き、役の名前は `<部の名前>の管理者`（部に常設で 1 人。`--task --resident` で立てる）にした。役職の作業者（一度きりの作業をする一時の人）と、社長室（持ち主と話して各部に頼む会話。前の呼び名は窓口）の役は、どの会社でも同じ型で入れる。管理者と作業者の本文には「済んだら納品の命令（`--deliver`）で返し、納品の後に判断が要ることが出たらもう一度納品の命令で返す」を、管理者と社長室の本文には「部の管理者に頼む命令（`--ask <会社>/<部の名前>の管理者`）で頼む」を入れた。組織の決まり（部＋役職の形・部署の名前は会社・部・役職が分かる日本語〔例: `<会社><部の名前>の管理者`・`<会社>の社長室`〕・枝の名前は英小文字とハイフン・部どうしは `--ask` で頼み合う・納品の後の判断はもう一度納品で返す）をコメントで書いた。
- `--task` で `--role` を省いたときの役を、`作業役` から `作業者` に替えた（役職の名前に揃えた）。会社の形に `作業役` の役を書いている人は、名前を `作業者` に替えるか、会社の形の頭に `default_role = "作業役"` を書くか、`--role 作業役` で名指す（省いた役が会社の形に無ければ、止めずに注記を出す）。下書きの役の管理者には `resident = true` を、頭には `default_role = "作業者"` を入れた。

## [0.12.1] - 2026-10-16

### Fixed

- 一時停止（Ctrl-Z）したまま `claude --resume` で開き直した会話は、Claude Code の会話の一覧（`claude agents --json`）に、同じ会話の id（`sessionId`）で古い処理（Claude Code のプロセス。古い名前のまま）と今の処理の 2 件が並ぶ。dispatch を呼んだ会話（頼み元）を探すとき、dispatch の処理から親の処理をたどり、その中に pid が在る方を選び、どちらも無ければ処理の起きた時刻（`startedAt`。開き直した今の処理の方が新しい）の新しい方を選ぶ。0.12.0 までは先頭の古い方を拾い、`--ask` と `--task` で立てた部署（作業ごとに会話を起こす枝の worktree）の上役（`company.boss`。頼み元の会話の名前）と herdr の札（ペインに添える短い印）が古い名前になっていた。納品（`--deliver`。部署が要約を頼み元へ返す命令）で頼み元の会話を引くときも同じく古い方を拾っていたので、起きた時刻の新しい方を選ぶようにした。
- `--ask`（部署に頼みを送る命令）が、`--from-name`・`--from-account`（頼み元の会話の名前と、その Claude Code のアカウントの名）を頼み元に使う。0.12.0 までは渡しても効かなかった。
- `--sync`（部署の属性から herdr の表示を付け直す命令）が、ペインに加えて herdr の作業場の名前（サイドバーの 1 行目）も、属性（場所ごとの git の設定に書く `company.*` の値）の `company.name`（部署の会話の名前）から付け直す。部署の worktree に加え、代表の clone（部署の worktree を作る元の clone）も、属性が書いてあれば、その作業場の名前を付ける。今の名前と同じなら付け直さない。属性を持つ場所（代表の clone か部署の worktree）が 2 つ以上居る作業場は、名前が 1 つに決まらないので触らず、出力にも出さない。

## [0.11.0] - 2026-10-16

### Added

- 会社の形（`.claude/company.toml`）の下書きを書く `--init-company`。名前（フォルダの名前）・説明・`gh_user`（gh の今のアカウント。読めなければコメントにする）・役 1 つ（作業役）・`[land]`（`mode = "none"`。本流へは入れない）を、欄の説明のコメント付きで書く。既定はリポジトリの中（commit するかは利用者が決める）、`--local` で dispatch の設定のフォルダ（既定は `~/.config/works-dispatch/`）の `companies/`（commit しない側）。書き出し先にもうあれば上書きしない。両方にあれば、リポジトリの中の物を読む。

### Changed

- 部署の回（`--task`・`--ask`・`--land`・`--tree`）は、dispatch の設定に `[[repos]]` が無くても動く。会社は `--repo` に渡した代表の clone のパスか、コマンドを打ったフォルダのリポジトリ（git の共通の `.git` から、代表の clone）で決まる。`[[repos]]` は PR を開く回（引数なし・`--pr`・`--issue`）と、部署の `gh_user` を会社の形と違うアカウントにするときと、`copy_files` を使うときだけ要る。設定のファイルそのものが無くても、部署の回は Claude Code のアカウント 1 つ（`claude` コマンドそのまま）で動く。前の版は、部署を立てるリポジトリごとに `[[repos]]` を、必須だった `second_prompt_file` も含めて書かないと「設定の repos に無い」で止まった。
- `--task`・`--land` を `--repo` 無しで打つと、コマンドを打ったフォルダのリポジトリの部署を扱う（git の外なら前と同じく設定の最初の `[[repos]]`、それも無ければ止まって `--repo` を求める）。前は打ったフォルダに関わらず設定の最初の `[[repos]]` だった。
- `--task` の始める前の確かめは、部署を立てるリポジトリだけを見る（設定のほかの `[[repos]]` の足りない物で止めない）。
- `--land` の gh のアカウントを `--task` と同じ決め方にした（設定の `[[repos]]` の `gh_user`、無ければ会社の形の `gh_user`）。前は会社の形の `gh_user` を見なかった。
- `second_prompt_file` を省けるようにした（部署の回では要らない。省くと 2 ターン目の文は空になり、PR を開く回は始める前の確かめで止まる）。`--check` は、`[[repos]]` が無ければ（設定のファイルが無くても）部署の回の前提だけを確かめる。

## [0.10.1] - 2026-10-16

### Fixed

- `dispatch.py --land <部署>`（部署の枝を本流に入れる命令）が `--dry-run` を見ていなかったので、空打ちのつもりで打つと版上げと本流への push まで走った。`--dry-run` を付けると、決まり（会社の形の `[land]` に書いた取り込み方・関門・版上げ）と、することの見立て（載せ直しが要るか・入れる commit・上げる版・関門・片付け）を出すだけになり、何も書かない（本流の先頭は fetch せず origin に問い合わせて読み、関門の枝への push・手元の検証・部署の窓〔herdr のペイン〕への打ち込み・片付けをしない）。
- `bump = "marketplace"` の取り込みで、中身の無い版（`## [Unreleased]` が空なのに、見出しだけ足して版を上げる回）を作らない。版を最後に上げた後に、フォルダの中のファイルを変えた（commit した）プラグインのうち 1 つでも、`CHANGELOG.md` の `## [Unreleased]` に `### Fixed` のような `#` で始まる行のほかに何も無ければ、`--land` 全体を止め（版を上げず、何も push しない。終わりの値は 1。`--dry-run` でも同じ所で止まると見立てて 1 を返す）、どのプラグインの `CHANGELOG.md` かを出す。部署が利用者に効く違いを `## [Unreleased]` に書き足して commit したら、`--land` を打ち直す。版を上げずに取り込む道は用意しない。marketplace は版が変わった時だけ中身を取り直すので、上げなければ変えた中身が利用者に届かない。

## [0.9.3] - 2026-10-16

### Fixed

- 部署を立てる `--task` と、新しく部署を立てる `--ask` は、会社の形（`.claude/company.toml`）を読む前に、origin の既定の枝（`origin/HEAD` が指す先）だけを fetch する（`--dry-run` は fetch せず、読んだ所を出す）。前は作業場を作るときの fetch より前に手元の控えで読んでいたので、別の所で本流の会社の形を変えて fetch していないと、起こすときの役の `settings`・`model` は古い形で決まり、立てた後に役を足すフックは新しい形を読んでいた。作業場を作った後に読む並びにしなかったのは、役の名前の誤りを作業場を作る前に止め、`--dry-run` でも役の起動の設定を出すため。fetch できなければ注記を出し、手元の控えで読む。
- `origin/HEAD` が無い clone では、会社の形を代表の clone の作業ツリーから読む（作業ツリーが古い枝なら役が効かない）ことを、`--check` と、会社の形を読む `--task`・`--ask`・`--deliver`・`--land` が注記に出し、直す命令 `git -C <代表の clone> remote set-head origin --auto` を添える。
- `--land` が部署を「残した（会話がまだ動いている）」で終えたとき（納品の直後は会話がまだ止まりきっていない）、後で片付ける道が `--clean --apply` しか無かった。残した都度の部署に入れた印（その部署の worktree の git の設定 `company.landed`。入れた commit）を書き、次の `--land`（どの部署を入れるときでも）が、`--clean` と同じ決まりで片付けられる形（会話が終わり、未コミットの変更も push していない commit も無く、枝が本流に入っている）になっていれば一緒に片付ける。次の `--land` が来なくても、前と同じく `--clean --apply` で片付く。`--land` の終わりの文にもそう出す。会話が止まるのを待つ形にしなかったのは、こちらから期限（timeout）を足さない決まり（README の D5）のため。

## [0.9.0] - 2026-10-16

### Added

- 部署の成果を本流に入れる `--land 部署`。会社の形（`.claude/company.toml`）の `[land]` に、取り込み方（`ff-after-ci`・`pr`・`none`）・関門（CI の枝の形〔例 `release/*`〕か手元の検証 `check`）・手元の検証のコマンド・本流の枝を書く。`ff-after-ci` は、関門の枝へ push して CI を待ち、緑で本流がまだ祖先なら本流を早送りして push し、入れた都度の部署を片付ける。本流が先に進んでいれば merge せずに部署へ載せ直しを、赤なら失敗の要点を、部署の窓に打ち込んで頼む。`[land]` が無ければ何もしない。役ごとに `[land.roles.<役>]` で替えられる。
- `[land]` の `bump = "marketplace"`: Claude Code のプラグインの marketplace で、部署は版を上げずに出し、取り込むときに、中身を変えたのに版が据え置きのプラグインの版（と marketplace の版・変更の記録の見出し）を上げる commit を足してから関門に出す。同じ版の番号を付けた部署どうしがぶつからない。

### Fixed

- 役の起こし方（`instructions`・`model`・`settings`）と納品する要約の必須項目（`deliver`）を、会社の形の同じ `[[roles]]` の項目に書けるようにした。0.8.0 は `deliver` を `[roles."役"]`（名前で引く表）で読んでいたが、TOML では同じ `roles` を `[[roles]]` と両方の形で書けないので、役の設定と役ごとの納品の項目を一緒に使えず、`[[roles]]` の中に書いた `deliver` は黙って無視されていた。`[roles."役"]` の形は読まず、`[[roles]]` に移すよう注記を出す。`deliver` を `[roles.settings]` の中に書いてしまったときも注記を出す。

## [0.8.0] - 2026-10-16

### Added

- 部署（`--task` で立てた、作業ごとの worktree と Claude Code の会話の組）に頼む `--ask <会社/役 か部署の名前> (--text <文> | --brief <ファイル>)`。宛先の部署の窓（その会話の画面を出した herdr のペイン）に 1 行を打ち込み、宛先の部署の属性に受けた頼みと頼み元を書く。役で宛てて常駐の部署が無ければ、`--task <名前> --branch <枝>` で新しい部署を立てて頼む。宛先の会社（herdr に開いているリポジトリ）は `--tree` に出る中から選ぶ。
- 部署から納品する `--deliver <要約のファイル>`。要約の項目（既定は結論〔3 行以内〕・決め手〔原典の URL〕・残った疑問・枝。会社の形 `.claude/company.toml` の `[roles.<役>]` の `deliver` で役ごとに替えられる）がそろっているかを確かめ、欠けていれば送らずに欠けた項目を返す。そろっていれば頼み元の窓に打ち込む。
- 頼みと納品の本文と台帳（`log.jsonl`）を、頼み元の会社の共通の `.git` の中の受付箱 `company/inbox/` に残す（commit されず、部署を片付けても消えない）。
- プラグインの Stop フック。部署の会話が、受けた頼みを納品しないまま止まろうとしたら、納品の命令で返すよう差し戻す（同じ会話・同じ頼みで 3 回まで。その後は止まるのを許す）。部署でない場所では何もしない。

### Fixed

- `--check` が tiers を見つけられないとき、入れる命令（`claude plugin install tiers@<マーケットプレイス>`。名は `plugin.json` の `dependencies` から読む）と、開いている会話では `/reload-plugins` を打つことを注記に出す。依存は `claude plugin update` では入らない（公式の文書のとおり。install・入れ直し・`/reload-plugins`・自動更新で入る）ので、0.7.0 へ update しただけだと tiers が無いまま works-dispatch が読み込まれない。前は「/plugin で入れ直す」とだけ出していた。

## [0.7.0] - 2026-10-16

### Added

- 役ごとの起動: 会社の形（`.claude/company.toml` か設定の置き場の `companies/`）に `[[roles]]`（`name`・`instructions`・`model`・`settings`）を書くと、`--task --role <役>` が、その役の `settings` を `--settings` に（裏の会話が自分で worktree を作らない設定は重ねたまま）、`model` を `--model` に渡して部署を起こす。利用者の全体の設定とリポジトリの設定は触らない。名指した役が会社の形に無ければ止まる。
- SessionStart のフック: 部署（属性 `company.role` の有る worktree）で会話が始まると、会社の形からその役の `instructions` を引いて会話の指示に足す。代表の clone やふつうの clone では何も足さない。
- 部署の gh のアカウント: 会社の形の頭に `gh_user` を書ける（dispatch の設定の `[[repos]]` の `gh_user` が先）。`--task` は名前だけを部署の属性 `company.gh-user` に書き、フックが会話の Bash に、コマンドごとに `gh auth token --user` で鍵を取り出して `GH_TOKEN` に入れる 1 行を足す。鍵の値はどこにも書かない。

### Changed

- `--check` が、最初に要る道具の段 2（gh が入っていてログイン済みか・herdr が動いているか・設定の各アカウントの起こすコマンドがシェルで見つかるか）を、新しい共通のプラグイン tiers（依存として入る）の `tiers --tier 2 --json` で点検する。足りなければ、OS ごとの入れ方を出して止まる。tiers が見つからなければ注記にして、今までの確かめを続ける。

## [0.6.0] - 2026-10-16

### Added

- アカウントを 1 つ選ぶ口 `python3 dispatch/nodes/accounts.py --pick` を足した。dispatch と同じ選び方で、アカウントの名前と、そのアカウントで Claude Code を起こす命令（設定の `command`）と、選んだ訳を 1 行で出す（`--json` で機械向け）。dispatch を通さずに手で会話を立てるときも、同じ選び方を通せる。
- 設定に `reset_soon_hours`（既定 24 時間）を足した。週の枠（Claude Code の使用率の上限を測る 7 日の窓）の切り替わりがこの時間以内（ちょうども含む）で、まだ使えるアカウントを先に使う。切り替わりの前に使わなかった分は捨てられるため。

### Changed

- アカウントの順を変えた（PR を開くときも、`--task` で部署を立てるときも同じ）。週の枠の切り替わりが近い（`reset_soon_hours` 以内）アカウントを先に使い、それ以外は 5 時間の枠（同じく 5 時間の窓）と週の枠のうち高い方の使用率が低い順、同じなら動いている会話（そのアカウントの `claude agents --json` で作業中か返事待ちのもの）の少ない順にする。前は週の切り替わりの近い順だけで並べたので、どのアカウントも切り替わりが何日も先でも、十数時間早いだけのアカウントに毎回寄せ、その 5 時間の枠を先に食い潰していた。

## [0.5.0] - 2026-10-16

### Added

- 作業ごとの部署を 1 回の呼び出しで立てる `--task 名前 --branch 枝 --brief 頼みのファイル`。枝の作業場を herdr に、リポジトリの作業場の子として作らせ、その中で Claude Code の裏の会話（`claude --bg`）を、名前と頼みのファイルを読ませる最初の文を付けて起こし、同じ区画で attach して画面を並べる。アカウントは PR と同じ決まりで使用率から 1 つ選ぶ。呼んだ会話と同じアカウントなら SendMessage、違えば画面に報告を書かせる。`--role <役>` で役を、`--resident` で常駐の部署（片付けで畳まない）を指せる。
- 部署の属性（役・常駐か都度か・アカウント・会話の名前と id・上役）を、部署の worktree ごとの git の設定 `company.<名前>` に書く（代表の clone に `extensions.worktreeConfig = true` を入れる。commit されない）。代表の clone の `.git/info/exclude` に `.claude/` を足す。
- 会社のツリー図 `--tree`（`--json` で JSON）。herdr の作業場と全アカウントの会話が指すリポジトリを会社として、会社ごとに受ける仕事（`.claude/company.toml`、無ければ設定の置き場の `companies/`）と、部署ごとの枝・状態・会話・役・アカウント・上役・窓の有無を出す。dispatch の設定が無くても動く。
- `--sync`: 部署の属性から、herdr の区画の名前・表示名・題名・札を付け直す（何度打っても同じ）。
- `--clean` が部署も片付ける。都度の部署で、会話が終わり、手元の作業が無く、枝が origin の既定の枝に入っていれば、`claude rm` で会話を消してから、場所と窓と手元の枝を消す。

### Removed

- 設定の `task_cwd`。部署は自分の作業場で起こす（その会社の AGENTS.md・CLAUDE.md とフックを効かせるため）。設定に残っていれば、止めずに注記を出して無視する。

## [0.3.0] - 2026-10-15

### Added

- `--issue N`。issue から始める作業の入口。issue に結んだ枝（`gh issue develop --list`）の作業場を開き、1 ターン目の `/catchup N` まで送って止める（2 ターン目の文は送らない）。結んだ枝が見えなければ、その issue を閉じる開いた PR の枝を使い、それも無ければ既定の枝から GitHub に枝を作って issue に結ぶ（`gh issue develop`）。報告の行は `issue #N` で始め、枝を出す。閉じた issue には枝を作らず `issue_closed` で止める。`--pr` とは一緒に使えない。
- 作業場の一生を 1 つのコマンドで回すようにした（引数なしで回すとき）。自分が作者でレビュアーの付いていない PR は開かない（`own_unreviewed`）。会話の開いている PR は、前に送った後に相手の新しい返事が有り、会話が手すきで手元の作業も無ければ、古い会話を終えて同じ場所で送り直す（`refreshed`）。閉じた PR の場所は最後に片付ける。送り直しも片付けも、終える会話は herdr が見ている会話のペインの物だけで（herdr の外の会話は終えない）、閉じる作業場はその場所の worktree の作業場だけ（ほかの作業場のペインがそのフォルダに cd していても閉じない）。その作業場にシェルでない物が居れば閉じない（`close_failed`）。片付けは、会話が 2 つ以上なら残し、会話を終えた後に一覧を取り直して居ないことを確かめてから消す。作者が force-push した枝は、場所の HEAD が前に送った時の head のままで場所がきれいなら、`git reset --keep` で origin に揃える（前に送った時の控え `dispatch-sent.json` に head も書く）。1 ターン目の終わりは、herdr の画面の見立てでなく Claude Code の会話の状態で見る。

### Changed

- 作業場を、PR ごとの clone（`<clone_root>/<名前>-pr-<番号>`）から、枝ごとの git worktree に替えた。代表の clone（設定の `source`）から、herdr（会話を走らせる端末を作業場とペインに分けて並べる道具）の `herdr worktree create` で作り、置き場は herdr の設定の `worktrees.directory`（既定 `~/.herdr/worktrees/<リポジトリ>/<枝>`）に任せる。作るときも使い直すときも、origin の今の head へ早送りしてから `/catchup` に渡す（手元にしか無い commit が有れば動かさない）。代表の clone 自身がその枝を開いていれば作らず `branch_busy` と報告する。fork の PR は作らず `provision_failed` と報告する。
- 報告の行の 3 つ目の欄を、作業場のフォルダの名前から枝の名前に替えた。
- `--check` は、設定の `source` が本体の clone か（linked worktree でないか）も確かめる。
- 片付け（`--clean`・一覧で回したときの最後）は、代表の clone の linked worktree だけを見る。枝の PR が閉じていて、会話が無く、手元の作業（未コミットの変更・git に足していないファイル・その枝の stash）も無く、手元の枝の先頭が PR の head と同じ場所だけ、worktree と手元の枝を消す。PR の無い枝は消さない。設定の `copy_files` のうち写し元と中身が違うファイルが有る場所は残して名指し、ほかの git が追わないファイル（依存・生成物）は一緒に捨てる。会話や herdr を読めなければ、traceback で止めずに、その場所を残して報告に書く。
- 1 件あたりの使用率の見積もりは、1 ターン目の終わりまで待った件だけから取る。`--no-second` と `--issue` の件は 1 ターン目を送ってすぐ測るので、`/catchup` がまだ使用率を使っていない時点の差（ほぼ 0）を 1 件あたりとして覚え、見積もりを小さくしていた。

### Removed

- 設定の `clone_root`。読まなくなった（設定に残っていても止めない。消してよい）。前の版が作った `<名前>-pr-<番号>` の clone は、この版の片付けの対象にならない。要らなければ手で消す。

## [0.1.4] - 2026-10-15

### Fixed

- Windows で、`--clean --apply` が PR ごとの clone を消せなかった。Windows の git は `.git/objects/` の中を読み取り専用で作るので、そのままでは消せない。読み取り専用を外して消し直す。作業場を作りかけで失敗したときの片付けも同じ理由で作りかけを残し、次の回にそれを別のリポジトリのフォルダとみなしていた。これも直した。
- Windows で、作業場のペインのシェルを POSIX のシェル（`/bin/sh`）で起こそうとして落ちていた。POSIX のシェルが無ければ、コマンドは PATH の上で探し、ペインは既定のフォルダとみなす。
- Windows の `\` の区切りのパスで、消えたプラグインのパスの検出（`--check`）が古いパスを見落とすか、別のパスを報告していた。手元のパスの origin から OWNER/NAME を取れず、作った clone の読み戻しが落ちていた。`limits.py herdr-config` が出す行も、`\` を含むパスで herdr の TOML を壊していた。

### Changed

- `--clean --apply` は、1 件でも消せなければ終了コード 1 で終わる（前は 0）。

## [0.1.1] - 2026-10-15

### Added

- `/works-dispatch:dispatch` スキルと `dispatch/dispatch.py`。自分の番の PR（attention の whose-turn）を、PR ごとの作業場（代表の clone から作る `<名前>-pr-<番号>` の clone と、同じ名前の herdr の作業場）に開き、週の使用率のリセットが近いアカウント（95% を超えるものは外す）で Claude Code を起こして、`/<attention のプラグイン名>:catchup <番号>` と設定の 2 ターン目の文を送る。AI は使わない。開いている会話は閉じず、同じリポジトリとブランチの会話が開いていれば飛ばす。引数は `--dry-run`・`--pr N`・`--no-second`・`--clean [--apply]`・`--init`・`--check`。前提と、試しの実行で確かめた外の道具の振る舞いは README に在る。

- `dispatch/activity.py`（任意）。Claude Code のフックから、herdr のサイドバーに会話ごとの作業内容を出す。`activity.py settings` が settings.json に足す hooks の塊を出す。
- `--check` が、アカウントごとの herdr の連携と、herdr の設定やフックが消えたプラグインのフォルダを指していないかも見る。
