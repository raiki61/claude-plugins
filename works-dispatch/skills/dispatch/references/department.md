# 部署を立てる・会社のツリー図: `--task`・`--tree`

## 部署を立てる: `--task`

持ち主と話す長く生きる会話（窓口）が、作業ごとに別の会話（部署）を立てて仕事を渡す形を、1 回の呼び出しでやる。部署は、リポジトリ（会社）の git worktree 1 つ（ブランチ 1 本）と、そこで働く Claude Code の裏の会話（`claude --bg`）1 つの組である。部署の画面は、herdr のリポジトリの作業場の子の作業場に、常に並べる。

- 窓口は長く生かす。部署は作業ごとに 1 つ立て、終わったら畳む（`--clean`）。部署の仕事を点検する役は、部署の文脈を持たない新しいサブエージェントを毎回立てる。
- 部署のペインと会話には、作業の中身の名前（例: `catchup作り直し`）を付ける。ペインの名前には、アカウントが 2 つ以上なら、そのアカウントの名前を添える（例: `catchup作り直し p2`）。会話の名前は SendMessage の宛先になる。
- 連絡の道は 2 つある。窓口と部署が同じアカウントなら、部署は区切りで SendMessage を窓口へ送り、窓口は SendMessage の `notify_when_idle` で手すきの知らせを 1 回受けられる（待つ間トークンを使わない）。アカウントが違うと SendMessage は両方向とも届かない（各会話の一覧に、同じアカウントの会話しか出ない）。その場合、部署は区切りごとに画面に短く報告を書いて止まり、窓口は herdr で部署のペイン（`attach` で裏の会話の画面を出したペイン）に打ち込み、画面を読む（`herdr pane read`）。dispatch は、どちらの道かを最初の文の後ろに書き足す。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --task catchup作り直し --branch feat/catchup-redo --brief <頼みのファイル> [--role <役>] [--persistent] [--repo OWNER/NAME か代表の clone]
```

`--repo` を省くと、コマンドを打ったフォルダのリポジトリに立てる（中のフォルダや worktree から打っても、その代表の clone になる）。打ったフォルダが git の外なら設定の最初の `[[repos]]`、それも無ければ止まって `--repo` を求める。`OWNER/NAME` で指せるのは設定の `[[repos]]` に書いたリポジトリだけ。

1. ブランチの作業場を、PR と同じ置き場の決まりで用意する（代表の clone の git worktree を herdr に作らせ、置き場は herdr の `worktrees.directory`。herdr はその作業場を、リポジトリの作業場の子としてまとめる）。ブランチの作業場が既に在れば開き直し、git では動かさない（PR と違い、origin の head へ fast-forward しない。部署のブランチは手元で commit を積む物のため）。無ければ作る。元は、origin にそのブランチが在れば origin のブランチ、無ければ既定のブランチ（`--base` で替えられる）。既定のブランチの名前は GitHub に問わず、代表の clone の手元の `origin/HEAD` から取り、無ければ origin に `git ls-remote --symref origin HEAD` で問う（`--land` のメインブランチと `--clean` も同じ元から取る）。部署の回（`--task`・`--ask`・`--land`・`--init-company`）は GitHub を読まないので、origin は手元の bare リポジトリでもよい。GitHub が要るのは、PR を開く回と、`[land]` の取り込み方が `pr` か CI のブランチのゲートのときだけ。
2. 使用率が上限（dispatch の設定の `limit_percent`。既定 95%）に届かないアカウント（上限は週の枠と 5 時間の枠の両方に当てる）のうち、「自分の番の PR を開く」の手順 2 と同じ順（点数（週の枠の上限までの残り ÷ 週の切り替わりまでの時間 × 5 時間の枠の上限までの残りの割合）の高い順）の頭を 1 つ選ぶ。
3. 部署の属性（役〔`--role`。省けば会社の形の `default_role`、それも無ければ `作業`〕・寿命〔`--persistent` を付けるか、役か受け持ちの寿命 `lifetime` が `always` なら always の部署（属性の値は `persistent`）、そうでなければ畳む部署（`ephemeral`）。always の部署は `--clean` で畳まず、次の頼みを同じ部署で受ける〕・アカウント・会話の名前・頼み元〔呼んだ会話〕）を、作業場の git の設定に、属性ごとに `company.role`・`company.lifecycle`・`company.account`・`company.name`・`company.boss` のような名前で書く（代表の clone に `extensions.worktreeConfig = true` を入れる。値は commit されず、worktree と一緒に消える）。代表の clone の `.git/info/exclude` に `.claude/settings.local.json`（部署の会話が書く許可の記録）を足す（`.gitignore` は触らない。`.claude/` を丸ごとは隠さない。exclude は全 worktree で共有なので、`.claude/` の下に新しく作ったファイルが未追跡に出なくなり、commit し忘れに気づけない）。
4. ペインに名前を付け、そのアカウントの起動コマンド（設定の `command`）に `--bg --name <作業の名前> --settings <設定のファイル> [--model <モデル>] [--effort <段>] "<最初の文>"` を付けて打ち込む。設定のファイルは、裏の会話が自分で別の worktree を作らないようにする（`worktree.bgIsolation = "none"`。このプラグインの templates/department-settings.json）。会社の形の役の項目に起動の設定・モデル・effort が有れば、それも渡す（「役の中身と起動方法」）。最初の文は「作業の頼みです。<頼みのファイル> を読んで進めてください。」に連絡の道を書き足したもの。
5. そのアカウントの会話の一覧に裏の会話が出たら、会話の id を属性に足し、同じペインで `<command> attach <id>`（`<command>` は手順 4 と同じ、そのアカウントの起動コマンド〔設定の `command`〕）を打ち込んで画面を出す。herdr の表示名（役）と札（ペインに添える短い印。役・アカウント・頼み元）をペインに、寿命と会話の引き継ぎ方（`always · carry`・`always · new`・`on-demand · carry`・`on-demand · new`・`per-ask`。new は頼みを納品するたびに会話を `/clear` で空にする〔役の `context = "new"`〕、carry は空にせず続ける。per-ask は次の頼みが無いので引き継ぎ方を付けない。rent-or-buy を切った部署〔役か受け持ちの `rent_or_buy = false`〕には ` · rent-or-buy off` を足す）を作業場の印 `$kind`（dispatch が部署の作業場に付ける herdr の印の名前。herdr の設定での出し方は [setup.md](setup.md)）に付ける（会話の行でなく作業場の行に出す）。作業の終わりは待たない。ペインを閉じても裏の会話は続く。

呼んだ会話の名前とアカウントは、dispatch が Claude Code の会話の一覧（`claude agents --json`）から、Bash のツールに渡る `CLAUDE_CODE_SESSION_ID` で探す。一時停止（Ctrl-Z）したまま `--resume` で開き直した会話は、一覧に同じ会話の id（`sessionId`）で古い処理（古い名前のまま）と今の処理の 2 件が並ぶので、dispatch の処理から親の処理を順にたどって pid（処理の番号）の並びを作り、2 件のうち一覧の `pid` がその並びに入っている方（dispatch を走らせている、今の処理）を、どちらも入っていなければ処理の起きた時刻（`startedAt`。開き直した今の処理の方が新しい）の新しい方を選ぶ。Claude Code の外から走らせるなど見つからないときは、画面の道にして注記を出す。SendMessage の道にしたいなら `--from-name <呼んだ会話の名前> --from-account <アカウントの名>` で渡す（`--ask` でも、渡せば頼み元の名前とアカウントになる）。`--dry-run` は、作業場を作るか使い直すか、アカウント、名前、部署の属性、連絡の道、最初の文を出すだけで、何も起動しない。同じ名前の会話が既に開いていれば、その会話がこの会社（元の clone とその worktree）の中なら止まり（「会社/名前」の宛て方でも分けられないため）、ほかの会社なら、その会話の居るアカウントを避けて振る（SendMessage の宛先はアカウントの中で 1 つに決まれば足りるため。部署の名前に会社の名前を付けずに、会社ごとに同じ名前の受け持ちを並べて立てられる）。避けると振れるアカウントが無ければ止まる。

部署の会話が起きて attach するまでで終わるので、前で走らせてよい。会話が起きなかった（`launch_failed`・`blocked` など）ときは、終了の値 1 で知らせる。裏の会話が会話の一覧に出るのを、打ち込んだ後に何度か見直す（Windows の `claude --bg` は、裏の会話を受ける仕組みを起動するのに 2〜3 秒かかる）。ペインに `backgrounded · <id>` が出ていれば、その id の会話を使う。`git worktree add` は本社（代表の clone）の `config.worktree`（`--desk` が書いた窓口の属性）を新しい部署に写すので、部署を立てるときに、本社と同じ値のまま写っていて今回書かない属性（窓口の会話の id・前の名前など）は消す。always の部署（`--persistent` か、寿命が `always` の役・受け持ち）は、同じ作業場のまま、頼みごとに部署の会話が次の頼みのブランチを切って移る（会社の形の担当の役の本文が、頼みごとに origin のメインブランチから決まりどおりの名前のブランチを切ると決めている。dispatch はブランチを切らない）。そのため、立てたときの最初のブランチの名前とその時の先頭の commit も、メインブランチに入れたブランチと同じ記録（属性 `company.landed-branches`。ブランチ → commit）に書く。最初のブランチをメインブランチに入れないまま次のブランチへ移っても、そのブランチの先頭が記録した commit のままなら、移った後に誰かが打つ `--land`（どの部署でも）か `--clean --apply` が、手元のそのブランチを消し、記録からも外す（どこかの worktree がまだそのブランチを開いていれば消さずに次に回し、記録より後に commit が有ればブランチは残して記録から外す）。

設定に前の版の `task_cwd` が残っていれば、止めずに注記を出して無視する（部署は自分の作業場で起動する。その会社の AGENTS.md・CLAUDE.md とフックを効かせるため）。

## 会社のツリー図: `--tree`

会社は、部署を置いて回す git のリポジトリ 1 つで、代表の clone を本社、そこから切った git worktree（ブランチ 1 本ずつ）を部署と呼ぶ。`--tree` は、herdr（端末の画面をペインに分けて会話を並べるツール）に開いている作業場と、全アカウントの会話（終わった裏の会話〔`claude --bg` で裏で動く会話〕も）が指すリポジトリを会社として、会社ごとに受ける仕事と部署を出す。読むだけで、何も書かない。dispatch の設定が無くても動く（有れば、そのアカウントの会話の一覧も見る）。`--tree --json` は同じ物を JSON で出す（形は `dispatch/schemas/tree.schema.json`）。

役と受ける仕事は、会社の形（会社ごとの設定のファイル `.claude/company.toml`。書き方は下）に書く。役（`[[roles]]` の 1 項目）は部署の会話の決まりと起動方法で、受け持ち（`[[skills]]` の 1 項目。受ける仕事 1 つ）はどの役が受けるかを持つ。部署の寿命は `lifetime` で決める。`always` は、受け持ちと同じ名前の部署が 1 つ立ち続けて受ける。`on-demand` は、頼まれたときに受け持ちの名前の部署を立て、手が空いたら畳む。`per-ask` は、頼みごとに部署を立て、済んだら畳む（同時に並行して進められる）。役の `lifetime` は `per-ask`（省けば）か `always` で、受け持ちの `lifetime` を省くと役の寿命を継ぐ（担当の役が always なら、受け持ちも always）。受け持ちに名指される always の役（担当）の部署は、受け持ちの名前でしか立てない。`<受け持ち>：<主題>` のような、どの受け持ちの名前でもない名前でその役の部署を立てようとすると、`--task` と `--ask` は止まり、per-ask の役（会社の形の `default_role` など）で頼むよう出す（立てると、誰の席でもない always の部署が畳まれずに残るため）。`--persistent` を名指した回は名前を問わない。

- 受ける仕事の行: 受け持ちの寿命の語（always・on-demand・per-ask）と、その仕事を頼む宛て方（`--ask` の宛先）を添える（`rent_or_buy = false` の受け持ちには `rent-or-buy off` も）。寿命が on-demand か per-ask の受け持ちと、寿命が always で部署がもう立っている受け持ちは、`--ask <会社>/<受け持ちの名前>`。always で部署がまだ立っていなければ、役で宛てて受け持ちの名前で立てる形（`--ask <会社>/<役> --task <受け持ちの名前> --branch <ブランチ>`）。外の会社の部署も中の部署も、ここから誰に頼むかを決める。
- 窓口の行: 本社で `--desk` を打って名付けた会話（持ち主と話して頼みを部署に配る会話）。受ける仕事に当たらない件・部署をまたぐ件の宛先。その会話を起動したときに効く model と effort を添える。model と effort で別々に、窓口の役の直下の `model`・`effort`（窓口を起動し直す `--move` が起動の旗 `--model`・`--effort` で渡す。名前は旗に合わせてある）を先に、無ければ同じ役の `[roles.settings]`（起動の `--settings` に渡す Claude Code の設定で、名前は Claude Code の設定のキーの `model`・`effortLevel`）を出す。どちらも無いか、役の `effort` が `inherit`（頼んだ会話と同じ effort。窓口には頼んだ会話が無いので旗を付けない）で設定にも無ければ「既定」と出し、アカウントの Claude Code の設定のまま起動する。会社の形の `desk` でほかの会社の窓口を使う会社の行には添えない（窓口を持つ会社の行に出る）。
- 部署の行: ブランチ・状態（作業中・止まっている・終わった・待機中・会話なし など）・会話の名前・役・アカウント・頼み元（納品を返す先。直前に頼んだ会話で、上下ではない。上下は本社〔窓口〕の下に部署が並ぶ木の形で出す）・herdr の窓の有無。裏の処理を待ってターンを終えたまま、納品していない同じ頼みで 1 時間を超えて会話が動いていない部署には「! 裏の処理を待ってターンを終えたまま、<時刻> から同じ頼みで会話が動いていない」を足す（待つ処理が終わらない形かを窓で確かめる。仕組みは受付の設計の 3.4 の「長い待ちの注記」）。

会社の情報（名前と受ける仕事）は、リポジトリの中の `.claude/company.toml` を先に読み、無ければ設定の置き場（設定のファイルの隣）の `companies/<代表の clone の場所を符号にした名前>.toml` を読む。リポジトリの中の物は、origin の既定のブランチ（main など。手元の ref `origin/HEAD` が指すブランチ。部署を立てる `--task` と `--ask` は、読む前にそのブランチだけを fetch する〔`--dry-run` を除く〕。ほかのコマンドは fetch しない）に commit された物を先に読み、既定のブランチに無いときだけ代表の clone の作業ツリーの物を読む。既定のブランチに在れば、代表の clone がたまたま開いているブランチや部署の worktree で書き換えた物は読まないので、変えた会社の形は既定のブランチに入れてから効く。手元の `origin/<既定のブランチ>` が古ければ古い物を読む（`git fetch` や `--land` の push で新しくなる）。`origin/HEAD` が無い clone（作った後に origin の既定のブランチを替えた、など）では既定のブランチを決められないので代表の clone の作業ツリーから読み、`--check` と会社の形を読むコマンドが、直すコマンド `git -C <代表の clone> remote set-head origin --auto` を注記に出す。`--tree`・`--task`・`--ask`・`--deliver`・`--land`・役の本文を足す SessionStart のフック（「役の中身と起動方法」）は同じ読み方をする。書き方は同じ TOML で、フィールドの名前は A2A（Agent2Agent。エージェント同士がやり取りする公開の仕様）の Agent Card（エージェントが自分の名前と受ける仕事を載せる JSON）に合わせた。次の例は `.claude/company.toml` の一部で、`[[skills]]` の 1 項目が受け持ち 1 つ:

```toml
name = "my_notes"
description = "持ち主のノート"
[[skills]]
id = "research"
name = "調べもの"
description = "結論と原典の一句を返す"
role = "調べ役"   # 受ける役（A2A に無い、ここだけのフィールド）
lifetime = "on-demand" # 受け持ちの寿命: always（立ち続ける）・on-demand（頼まれたときだけ立て、手が空いたら畳む）・per-ask（頼みごとに部署を立て、済んだら畳む。同時に並行して進める。下の段の 5）。省けば役の寿命
```

寿命が on-demand か per-ask の受け持ち（頼まれたときに部署を立てる。`lifetime = "on-demand"`・`"per-ask"`）の流れ。下の 1〜5 は、会社の形にこの受け持ちを書いた後に、dispatch と部署の会話がたどる振る舞いで、頼む会話が打つのは 1 の `--ask` だけ（`lifetime` を会社の形に書くのは、会社の形を直す会話）。部署は、作業場（git worktree）ごとに立つ裏の Claude Code の会話。always の部署は頼みが無くても立ったまま残り、畳む部署は頼みを済ませたら畳まれる。

1. 頼む会話が `--ask <会社>/<受け持ち>` を打つ。その受け持ちの名前の部署が無ければ、dispatch がその名前（寿命が per-ask なら 5 の名前）の畳む部署（頼みを済ませたら畳まれる、一度きりの部署）を立てる（`--task`・`--branch` は要らない。ブランチは `work/ask-<受付番号の終わり 6 字>`。受付番号は、`--ask` が頼みごとに振って出す番号〔例: `20261018-120448-b6778d`〕で、その終わりの 6 字が `b6778d`）。役の寿命が always でも、受け持ちの `lifetime` が on-demand か per-ask なら、この受け持ちは畳む部署で立つ。
2. 立った部署の会話の始まりの文（部署の会話が最初に読む文）に「この受け持ちの寿命は on-demand（頼まれたときに立て、手が空いたら畳む）。」（per-ask の部署には「この受け持ちの寿命は per-ask（頼みごとに部署を立て、済んだら畳む）。」）と足される。役の本文には、頼みを納品してメインブランチに入れたら `--done`（ターンを終えて部署を畳ませるコマンド）を打つよう書く。
3. 部署が立っている間に同じ受け持ちへ来た次の頼みは、その部署の順番待ちに積まれる（同じ受け持ちの会話は 1 度に 1 つ）。
4. `--tree` は、受ける仕事の行に受け持ちの寿命の語（on-demand・per-ask）を出す。
5. 寿命が per-ask の受け持ちは（受け持ちに書くか、役の寿命が per-ask で受け持ちが省いて継ぐか。後者は役の下の受け持ちを `--ask <会社>/<受け持ち>` で直に宛てられる）、3 の順番待ちに積まず、頼みごとに別の部署を立てて同時に並行して進める。部署の名前は「<受け持ち>：<受付番号の終わり 6 字>」（全角のコロン）、ブランチは 1 と同じ `work/ask-<同じ 6 字>`。頼む側は 1 と同じ `--ask <会社>/<受け持ち>` で頼む。1・2 の効き（役が always でも畳む部署で立つ・2 の会話の始まりの文）と、受け持ちの `model`・`effort`・`settings`・`account`・`rent_or_buy` は、この名前の部署にも効く。`--tree` の行には「per-ask」と出る。受け持ちの名前そのものの部署が立っている間（per-ask にする前から動いている always の部署や、下の `[skills.start]` で立った部署）は、頼みはその部署に届き、3 のとおり積まれる。`[skills.start]` の起動（`--start`・`--due`）は、今までどおり受け持ちの名前の部署を立てる。頼みごとの部署も、1 つの頼みを済ませたら 2 のとおり畳まれる。頼みごとの部署は別々なので、同じ中身の頼みを 2 回打つと 2 つ立つ（立っている部署への同じ中身の頼みを積まない決まりは効かない）。`--nudge`・`--move` などで部署を名指すときは、受け持ちの名前でなく部署の名前（「<受け持ち>：<6 字>」）で打つ。
