# 部署を立てる・会社のツリー図: `--task`・`--tree`

## 部署を立てる: `--task`

持ち主と話す長く生きる会話（窓口）が、作業ごとに別の会話（部署）を立てて仕事を渡す形を、1 回の呼び出しでやる。部署は、リポジトリ（会社）の git worktree 1 つ（枝 1 本）と、そこで働く Claude Code の裏の会話（`claude --bg`）1 つの組である。部署の画面は、herdr のリポジトリの作業場の子の作業場に、常に並べる。

- 窓口は長く生かす。部署は作業ごとに 1 つ立て、終わったら畳む（`--clean`）。部署の仕事を点検する役は、部署の文脈を持たない新しいサブエージェントを毎回立てる。
- 部署のペインと会話には、作業の中身の名前（例: `catchup作り直し`）を付ける。ペインの名前には、アカウントが 2 つ以上なら、そのアカウントの名前を添える（例: `catchup作り直し p2`）。会話の名前は SendMessage の宛先になる。
- 連絡の道は 2 つある。窓口と部署が同じアカウントなら、部署は区切りで SendMessage を窓口へ送り、窓口は SendMessage の `notify_when_idle` で手すきの知らせを 1 回受けられる（待つ間トークンを使わない）。アカウントが違うと SendMessage は両方向とも届かない（各会話の一覧に、同じアカウントの会話しか出ない）。その場合、部署は区切りごとに画面に短く報告を書いて止まり、窓口は herdr で部署のペイン（`attach` で裏の会話の画面を出したペイン）に打ち込み、画面を読む（`herdr pane read`）。dispatch は、どちらの道かを最初の文の後ろに書き足す。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --task catchup作り直し --branch feat/catchup-redo --brief <頼みのファイル> [--role <役>] [--resident] [--repo OWNER/NAME か代表の clone]
```

`--repo` を省くと、コマンドを打ったフォルダのリポジトリに立てる（中のフォルダや worktree から打っても、その代表の clone になる）。打ったフォルダが git の外なら設定の最初の `[[repos]]`、それも無ければ止まって `--repo` を求める。`OWNER/NAME` で指せるのは設定の `[[repos]]` に書いたリポジトリだけ。

1. 枝の作業場を、PR と同じ置き場の決まりで用意する（代表の clone の git worktree を herdr に作らせ、置き場は herdr の `worktrees.directory`。herdr はその作業場を、リポジトリの作業場の子としてまとめる）。枝の作業場が既に在れば開き直し、git では動かさない（PR と違い、origin の head へ早送りしない。部署の枝は手元で commit を積む物のため）。無ければ作る。元は、origin にその枝が在れば origin の枝、無ければ既定の枝（`--base` で替えられる）。既定の枝の名前は GitHub に問わず、代表の clone の手元の `origin/HEAD` から取り、無ければ origin に `git ls-remote --symref origin HEAD` で問う（`--land` の本流と `--clean` も同じ元から取る）。部署の回（`--task`・`--ask`・`--land`・`--init-company`）は GitHub を読まないので、origin は手元の bare リポジトリでもよい。GitHub が要るのは、PR を開く回と、`[land]` の取り込み方が `pr` か CI の枝の関門のときだけ。
2. 使用率が上限（dispatch の設定の `limit_percent`。既定 95%）に届かないアカウント（上限は週の枠と 5 時間の枠の両方に当てる）のうち、「自分の番の PR を開く」の手順 2 と同じ順（週の枠の切り替わりが近い物を先に、ほかは使用率の低い順）の頭を 1 つ選ぶ。
3. 部署の属性（役〔`--role`。省けば会社の形の `default_role`、それも無ければ `作業`〕・常設か都度か〔`--resident` を付けるか、役の項目に `resident = true` が有れば常設（`resident`）、省けば都度（`per-task`）。常設の部署は `--clean` で畳まず、次の頼みを同じ部署で受ける〕・アカウント・会話の名前・頼み元〔呼んだ会話〕）を、作業場の git の設定に、属性ごとに `company.role`・`company.residency`・`company.account`・`company.name`・`company.boss` のような名前で書く（代表の clone に `extensions.worktreeConfig = true` を入れる。値は commit されず、worktree と一緒に消える）。代表の clone の `.git/info/exclude` に `.claude/settings.local.json`（部署の会話が書く許可の記録）を足す（`.gitignore` は触らない。`.claude/` を丸ごとは隠さない。exclude は全 worktree で共有なので、`.claude/` の下に新しく作ったファイルが未追跡に出なくなり、commit し忘れに気づけない）。
4. ペインに名前を付け、そのアカウントの起こし方（設定の `command`）に `--bg --name <作業の名前> --settings <設定のファイル> [--model <モデル>] [--effort <段>] "<最初の文>"` を付けて打ち込む。設定のファイルは、裏の会話が自分で別の worktree を作らないようにする（`worktree.bgIsolation = "none"`。このプラグインの templates/department-settings.json）。会社の形の役の項目に起動の設定・モデル・effort が有れば、それも渡す（「役の中身と起こし方」）。最初の文は「作業の頼みです。<頼みのファイル> を読んで進めてください。」に連絡の道を書き足したもの。
5. そのアカウントの会話の一覧に裏の会話が出たら、会話の id を属性に足し、同じペインで `<command> attach <id>` を打ち込んで画面を出す。herdr の表示名（役）と札（ペインに添える短い印。役・アカウント・頼み元）をペインに、常設か都度かと会話の持ち越し方（`常設・毎回空`・`常設・持ち越し`・`都度`）を作業場の印 `$kind` に付ける（会話の行でなく作業場の行に出す）。作業の終わりは待たない。ペインを閉じても裏の会話は続く。

呼んだ会話の名前とアカウントは、dispatch が Claude Code の会話の一覧（`claude agents --json`）から、Bash の道具に渡る `CLAUDE_CODE_SESSION_ID` で探す。一時停止（Ctrl-Z）したまま `--resume` で開き直した会話は、一覧に同じ会話の id（`sessionId`）で古い処理（古い名前のまま）と今の処理の 2 件が並ぶので、dispatch の処理から親の処理を順にたどって pid（処理の番号）の並びを作り、2 件のうち一覧の `pid` がその並びに入っている方（dispatch を走らせている、今の処理）を、どちらも入っていなければ処理の起きた時刻（`startedAt`。開き直した今の処理の方が新しい）の新しい方を選ぶ。Claude Code の外から走らせるなど見つからないときは、画面の道にして注記を出す。SendMessage の道にしたいなら `--from-name <呼んだ会話の名前> --from-account <アカウントの名>` で渡す（`--ask` でも、渡せば頼み元の名前とアカウントになる）。`--dry-run` は、作業場を作るか使い直すか、アカウント、名前、部署の属性、連絡の道、最初の文を出すだけで、何も起こさない。同じ名前の会話が既に開いていれば、その会話がこの会社（元の clone とその worktree）の中なら止まり（「会社/名前」の宛て方でも分けられないため）、ほかの会社なら、その会話の居るアカウントを避けて振る（SendMessage の宛先はアカウントの中で 1 つに決まれば足りるため。部署の名前に会社の名前を付けずに、会社ごとに同じ名前の受け持ちを並べて立てられる）。避けると振れるアカウントが無ければ止まる。

部署の会話が起きて attach するまでで終わるので、前で走らせてよい。会話が起きなかった（`launch_failed`・`blocked` など）ときは、終了の値 1 で知らせる。裏の会話が会話の一覧に出るのを、打ち込んだ後に何度か見直す（Windows の `claude --bg` は、裏の会話を受ける仕組みを起こすのに 2〜3 秒かかる）。ペインに `backgrounded · <id>` が出ていれば、その id の会話を使う。`git worktree add` は本社の `config.worktree`（`--desk` が書いた窓口の属性）を新しい部署に写すので、部署を立てるときに、本社と同じ値のまま写っていて今回書かない属性（窓口の会話の id・前の名前など）は消す。常設の部署（`--resident` か `resident = true` の役）は、同じ作業場のまま、頼みごとに部署の会話が次の頼みの枝を切って移る（会社の形の担当の役の本文が、頼みごとに origin の本流から決まりどおりの名前の枝を切ると決めている。dispatch は枝を切らない）。そのため、立てたときの最初の枝の名前とその時の先頭の commit も、本流に入れた枝と同じ記録（属性 `company.landed-branches`。枝 → commit）に書く。最初の枝を本流に入れないまま次の枝へ移っても、その枝の先頭が記録した commit のままなら、移った後に誰かが打つ `--land`（どの部署でも）か `--clean --apply` が、手元のその枝を消し、記録からも外す（どこかの worktree がまだその枝を開いていれば消さずに次に回し、記録より後に commit が有れば枝は残して記録から外す）。

設定に前の版の `task_cwd` が残っていれば、止めずに注記を出して無視する（部署は自分の作業場で起こす。その会社の AGENTS.md・CLAUDE.md とフックを効かせるため）。

## 会社のツリー図: `--tree`

会社は、部署を置いて回す git のリポジトリ 1 つで、代表の clone を本社、そこから切った git worktree（枝 1 本ずつ）を部署と呼ぶ。`--tree` は、herdr（端末の画面をペインに分けて会話を並べる道具）に開いている作業場と、全アカウントの会話（終わった裏の会話〔`claude --bg` で裏で動く会話〕も）が指すリポジトリを会社として、会社ごとに受ける仕事と部署を出す。読むだけで、何も書かない。dispatch の設定が無くても動く（有れば、そのアカウントの会話の一覧も見る）。`--tree --json` は同じ物を JSON で出す（形は `dispatch/schemas/tree.schema.json`）。

役と受ける仕事は、会社の形（会社ごとの設定のファイル `.claude/company.toml`。書き方は下）に書く。役（`[[roles]]` の 1 項目）は部署の会話の決まりと起こし方で、受け持ち（`[[skills]]` の 1 項目。受ける仕事 1 つ）はどの役が受けるかを持つ。常設の役（`resident = true`）の受け持ちは、受け持ちと同じ名前の部署が 1 つ立ち続けて受ける。都度の役は、頼みごとに部署を立てる。

- 受ける仕事の行: その仕事を頼む宛て方（`--ask` の宛先）を添える。常設の役の受け持ちで部署がもう立っていれば部署の名前、まだ立っていなければ役と `--task <受け持ちの名前>`、都度の役なら役と `--task <部署の名前>`。外の会社の部署も中の部署も、ここから誰に頼むかを決める。
- 窓口の行: 本社で `--desk` を打って名付けた会話（持ち主と話して頼みを部署に配る会話）。受ける仕事に当たらない件・部署をまたぐ件の宛先。その会話を起動したときに効く model と effort を添える。model と effort で別々に、窓口の役の直下の `model`・`effort`（窓口を起こし直す `--move` が起動の旗 `--model`・`--effort` で渡す。名前は旗に合わせてある）を先に、無ければ同じ役の `[roles.settings]`（起動の `--settings` に渡す Claude Code の設定で、名前は Claude Code の設定のキーの `model`・`effortLevel`）を出す。どちらも無いか、役の `effort` が `inherit`（頼んだ会話と同じ effort。窓口には頼んだ会話が無いので旗を付けない）で設定にも無ければ「既定」と出し、アカウントの Claude Code の設定のまま起動する。会社の形の `desk` でほかの会社の窓口を使う会社の行には添えない（窓口を持つ会社の行に出る）。
- 部署の行: 枝・状態（作業中・止まっている・終わった・待機中・会話なし など）・会話の名前・役・アカウント・頼み元（納品を返す先。直前に頼んだ会話で、上下ではない。上下は本社〔窓口〕の下に部署が並ぶ木の形で出す）・herdr の窓の有無。

会社の情報（名前と受ける仕事）は、リポジトリの中の `.claude/company.toml` を先に読み、無ければ設定の置き場（設定のファイルの隣）の `companies/<代表の clone の場所を符号にした名前>.toml` を読む。リポジトリの中の物は、origin の既定の枝（main など。手元の ref `origin/HEAD` が指す枝。部署を立てる `--task` と `--ask` は、読む前にその枝だけを fetch する〔`--dry-run` を除く〕。ほかの命令は fetch しない）に commit された物を先に読み、既定の枝に無いときだけ代表の clone の作業ツリーの物を読む。既定の枝に在れば、代表の clone がたまたま開いている枝や部署の worktree で書き換えた物は読まないので、変えた会社の形は既定の枝に入れてから効く。手元の `origin/<既定の枝>` が古ければ古い物を読む（`git fetch` や `--land` の push で新しくなる）。`origin/HEAD` が無い clone（作った後に origin の既定の枝を替えた、など）では既定の枝を決められないので代表の clone の作業ツリーから読み、`--check` と会社の形を読む命令が、直す命令 `git -C <代表の clone> remote set-head origin --auto` を注記に出す。`--tree`・`--task`・`--ask`・`--deliver`・`--land`・役の本文を足す SessionStart のフック（「役の中身と起こし方」）は同じ読み方をする。書き方は同じ TOML で、欄の名前は A2A の Agent Card に合わせた:

```toml
name = "my_notes"
description = "持ち主のノート"
[[skills]]
id = "research"
name = "調べもの"
description = "結論と原典の一句を返す"
role = "調べ役"   # 受ける役（A2A に無い、ここだけの欄）
standing = false # 常設の部署を置かず、頼まれたときだけ立てる（省けば常設。下の段）
```

頼まれたときだけ立てる受け持ち（`standing = false`）の流れ。部署は、作業場（git worktree）ごとに立つ裏の Claude Code の会話。常設の部署は頼みが無くても立ったまま残り、都度の部署は頼みを済ませたら畳まれる。

1. 頼む会話が `--ask <会社>/<受け持ち>` を打つ。その受け持ちの名前の部署が無ければ、dispatch がその名前の都度の部署を立てる（`--task`・`--branch` は要らない。枝は `work/ask-<受付番号の終わり 6 字>`）。役の項目が `resident = true`（常設で立てる役）でも、この受け持ちは都度で立つ。
2. 立った部署の会話の始まりに「この受け持ちは頼まれたときだけ立てる物で、この部署は都度の部署」と足される。役の本文には、頼みを納品して本流に入れたら `--done`（番を終えて部署を畳ませる命令）を打つよう書く。
3. 部署が立っている間に同じ受け持ちへ来た次の頼みは、その部署の順番待ちに積まれる（同じ受け持ちの会話は 1 度に 1 つ）。
4. `--tree` は、受ける仕事の行に「頼まれたときだけ立てる」と出す。
