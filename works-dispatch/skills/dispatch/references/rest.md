# 待つ・区切る: `--wait`・`--rest`・`--compact` と止める前の差し戻し

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）や窓口の会話が、人の答えを待つ・会話を空にする区切りや compact の区切りを印すときに、読んでから下のコマンドを打つ。止まる前のフックに差し戻されたときの訳も、ここに在る。言葉（herdr・受付箱・属性・ターン・待ち受け）と納品の決まりは「納品する: `--deliver`」に在る。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --wait <訳> [--park]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --rest
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --compact [焦点]
```

- **答え待ち（`--wait <訳>`）**: 部署の場所から走らせる。今の頼みが人の答えを要って止まっている（持ち主に聞いて、答えが数時間後になる など）と、部署の属性 `company.waiting`（受付番号）と `company.waiting-why`（訳）に書く。その頼みの間、止まる前のフックは納品を促さない（促しはターンの終わりごとに同じ頼みにつき 3 回まで出るので、答えを待つ部署が無駄にターンを回していた）。その会話に文が打たれると（人の答えのほか、窓に打ち込まれた知らせも）、文を受けたフックが印を外し、また納品を促す。納品でも外れる。A2A の頼みの状態 `input-required`（人の入力が要って止まっている）に当たる。役の名前は見ないので、どの役の部署でも使える。
- **答え待ちのまま次の頼みを受ける（`--wait <訳> --park`）**: 人の答えに時間がかかり、その間にほかの頼みを受けて閉じたい部署（社長室のように、持ち主への問いを取りまとめつつ振り分けも持つ部署）が打つ。訳は `--wait` と同じく、何の答えを誰から待つか。今の頼みの受付番号（属性 `company.ask`）と頼み元（この部署に頼んだ会話。属性 `company.boss` など 5 つ）を、属性 `company.parked`（JSON の並び）に移し、今の頼みを空ける。受付箱の台帳 `log.jsonl`（この部署の会社と頼み元の会社の両方）には `kind` が `waiting` の行を `parked: true` 付きで足し、その頼みは答え待ちのまま閉じない（`--todo` にも残る）。順番待ちの次の頼みは、そのターンの終わりに待ち受けが会話に渡す。保留の頼みが在る間、待ち受けは会話を空にしない（頼みのたびに `/clear` で空にする役〔会社の形の役の `fresh`〕でも）し、起動し直しもしない（会社の形の起動の設定が替わったときも、使用上限の前にほかのアカウントへ早めに移すときも。空にすると、保留の答えを返す会話の中身が消える）。会話の始まりのフック（役の本文を足す `dispatch/role_hook.py`）が、役の本文の後に、保留の頼みの一覧（受付番号・頼み元・訳）と返し方を足す（`/clear` の後の会話も保留の頼みを知る）。答えが出たら `--deliver <要約> --for <保留の頼みの受付番号>`（`--park` を打ったときの出力と、会話の始まりに足される一覧に出る番号）で、保留の件の頼み元へ返し、その頼みを閉じる（今受けている頼みは閉じない）。保留の頼みだけが在り、今受けている頼みが無いのに、`--for` を付けずに `--deliver` を打つと止まる。答え待ちを納品済みに見せかけて消さない・自分宛ての `--ask` で逃がさないための口。
- **区切り（`--rest`）**（この項は、会話が区切りを印した後に機械がすることの説明。いつ打つかは役の本文が決める）: 会話を引き継ぐ部署と窓口（`--desk` で名付けた本社の会話）が、文脈がたまり続けないよう、今は会話を空にしてよい区切りだと自分で印す（部署の属性 `company.rest` に、その場所の会話の id を書く）。そのターンの終わりに待ち受けが、窓の入力フィールドが空で会話が止まっていれば、窓に `/clear` を打って空にし、印を外す（会社の形の起動の設定が、会話を起動したときの設定と違えば、`/clear` の代わりにその設定で起動し直す。「ほかのアカウントで起動し直す」）。入力フィールドの薄字（Claude Code が出す次の文の候補と、空の入力フィールドの例の字。打てば消える）は、打ちかけの字と数えない。空にできないまま次の頼みか納品を渡すときは、空にできなかった訳（会話が動いている・人の打ちかけの字が在る、など）を、会話に渡す文の頭に添え、受付箱の台帳 `log.jsonl` の、渡したことを書く `handed` の行にもフィールド `unrested` で残す（黙って前の会話のまま渡し続けない）。空にした後の会話の始まりに役の本文が足され、本社の窓口は会話の id の付け直し（`company.pid` の追従）で頼みと納品をそのまま受ける。どこを区切りにするか（例: 受けた頼みを全部納品で閉じ、会話の中にしか無いことをファイルに書き終えたとき）は、各会社の形の役の本文に書き、このプラグインでは決めない。納品していない頼みが在る間は印せず、空にもしない。人がその会話に打つと印が外れる（持ち主と話している途中の会話は空にしない）。持ち主が手で compact する道はそのまま。本社では、待ち受けは、herdr がペインごとに持つ会話の印（`agent_session`）がその窓口の会話の id と同じペインにだけ `/clear` を打つ（本社に会話の居るペインがほかにも在っても、持ち主のほかの会話には打たない）。
- **compact の区切り（`--compact [焦点]`）**（いつ打つかは役の本文が決める）: 部署か窓口の会話が、同じ仕事の前の部分が済み、続きは要約で足りる区切りで、ここで compact してよいと自分で印す（`--compact` を打った作業場〔部署の worktree か、窓口の居る本社の clone〕の属性〔作業場の git の設定値。`git config --worktree company.*`〕`company.compact` に、その会話の id、`company.compact-focus` に焦点）。属性に会話の id（`company.session`）の無い場所では印せない（印がその会話の物かを見分けられない）。`--rest` と違い、納品していない頼みが在っても印せる。印したターンの終わりは、止まる前のフックが納品を促さない。そのターンの終わりに、待ち受けはまず compact の費用の元が取れるかを判定する。借りるか買うかの判断の部品〔rent-or-buy の `bin/rent-or-buy compact`。[roles.md](roles.md) の「仕事が終わるまでの keepalive」〕の答えは `buy`（元が取れる。compact する）か `rent`（取れない。しない）で、部品が入っていない・答えないときだけ、会話の記録の最後の応答の文脈が 10 万トークン〔`nodes/wake.py` の `COMPACT_FLOOR`〕以上か、強制の線（下の「keepalive の時刻の compact」）に着いていれば元が取れると見る。元が取れて、窓の入力フィールドが空で会話が止まっていれば、窓に `/compact <焦点>` を打つ（ターンの終わりの直後に会話がまだ動いていると見えたら、30 秒まで手が空くのを待つ。打った字が入力フィールドに残れば Enter を 1 回足す）。compact が済んで会話が始まり直した時（SessionStart のフック）に、同じ待ち受けが印を外し、「compact した。続ける」の 1 行で会話を起動する。compact の費用の元が取れない（部品が `rent` と答えた、部品が無ければ文脈が 10 万トークンより小さい）・会話の記録から文脈の大きさを読めない・30 秒待っても会話が動いている・入力フィールドに字が在る・打ったが 10 分で済んだのを見られない、のどれかなら、compact せずに印を外し、訳を添えて会話を起動する。裏の処理（会話が `run_in_background` で走らせた Bash や、裏で動くサブエージェント。終わると知らせで会話が再開する）が残っていても打つ（compact の後も裏の処理は動き続け、終わりの知らせは縮めた後の会話に届く）。そのときは、herdr の窓が「作業中」と出たままなので窓の会話の状態は見ず、ターンの終わりから会話の記録にターンの行が足されていなければ手が空いていると見る。足されていたら（知らせでターンが始まった）打たずに印を残し、そのターンの終わりにまた試す。焦点に書けない長いもの（次の手の細部など）は、ターンを終える前にファイルに書いておく（要約は細部を落とす）。区切り（`--rest`）か終わり（`--done`）の印が同じターンに在れば、compact しない。人がその会話に打つと印が外れる（待ち受けが打った `/compact` では外れない）。
- **keepalive の時刻の compact**: keepalive（キャッシュの寿命が切れる前に、待ち受けが止まった会話へ送る短い文。[roles.md](roles.md) の「仕事が終わるまでの keepalive」）を書いた部署と窓口で、仕事が終わらないまま（出した頼みの納品・持ち主の答え・裏の処理の終わりを待って）ターンを終えた会話には、待ち受けが keepalive を送る時刻に、先に compact するかを部品に聞く（`--compact` の印が無くても。部品は、長い文脈を持ち続けるキャッシュ読みの余分な費用と、compact する費用を比べて答える。詳しくは設計書 docs/specs/2026-10-24-rent-or-buy-design.md〔リポジトリのルート〕の 6）。keepalive の時刻を待たずに、そのような会話のターンの終わり（待ち受けが待ち始めた時）にも同じく聞く（寿命より短い待ちが続く会話や、待たずに働き続ける会話では、keepalive の時刻が来ないため。持ち主 2026-10-25。待ち受けが送った keepalive の文か下の問いで始まったターンの終わりは除く）。部品が `rent` と答えるか答えないなら、そのまま keepalive の判断に進む（ターンの終わりなら keepalive の時刻を待つ。訳は、受付箱の台帳〔`.git/company/inbox/log.jsonl`。1 行が 1 件の出来事で、keepalive の行は `kind` が `keepalive`〕の keepalive の行の `compact`）。`buy` に `consult`（会話に聞け）が付いていたら、keepalive の文の代わりに（ターンの終わりならその場で）、残す焦点を 1 行で返すか、今は困るなら `skip:` と訳を返すよう頼む問いを送る（ツールは使わせない。モデルへの要求は keepalive と同じ 1 回で済む）。ターンの終わりの問いは、人がすぐ次の文を打ちそうなら `skip:` を返すよう添える（持ち主と話している最中の会話に compact を割り込ませない）。そのターンの終わりに、そのターンを始めた文がこの問いなら、待ち受けが会話の記録の最後の答えを読んで部品にもう一度聞く。焦点が返れば、その焦点で `--compact` と同じく `/compact <焦点>` を打つ。`skip:` なら延期と数え（同じ会話で 2 回まで。`dispatch/wake_hook.py` の `DEFER_LIMIT`）、上限を超えたら問わずに焦点なしで打つ（ターンの終わりには打たず、keepalive の時刻に打つ）。ターンの終わりの問いへの `skip:` は keepalive の時刻の延期と別に数え、2 回に着いたらターンの終わりには問わない（keepalive の時刻の問いは残る）。順番待ちに頼みが在るときもターンの終わりには聞かず、ターンの終わりの問いは keepalive の 1 本と数える。打てなかったら印を外し、keepalive を送る（ターンの終わりなら keepalive の時刻を待つ）。compact が済んだら、待ち受けが「待ちの間に費用の判断で compact した」と添えて会話を起動する。会話の文脈が強制の線（その部署の起動の設定の `autoCompactWindow` の 8 割。[roles.md](roles.md) の「起動の設定」）に着いていれば、部品に `forced` を真にして聞く。部品は会話に聞かずに `buy` と答える（`reason` は `forced`）ので、問いを送らず、延期も受けずに焦点なしで打つ（ターンの終わりにも打つ）。部品が入っていない・答えない・`buy` 以外を答える（`forced` を知らない古い版）ときも、強制の線に着いていれば打つ（自動の compact の線を上げた後に、会話が伸び続けないため）。keepalive を止めた後（送った本数が上限に着いた、部品が止め時と答えたなど）の待ちでは、keepalive の時刻も、同じ物を待つ間のターンの終わりの判断も無いので、強制の線も見ない（キャッシュは冷えていて、次のターンの途中で伸びれば自動の compact が打つ）。延期の数と、判断で打ったかは、受付箱の `wake/<場所の鍵>.compact.json`〔場所の鍵は、場所の git のフォルダの実のパスの SHA-1 の頭 16 字〕に控え、会話が `--compact` を打つか、compact が済むと消す。

- **止める前の差し戻し**: このプラグインの Stop フックが、部署（`company.role` の在る場所）の会話で、受けた頼みを納品しないまま止まろうとしたら、納品のコマンドで返すよう差し戻す。同じ会話・同じ頼みで 3 回まで差し戻し、その後は止まるのを許す。部署でない場所と、`--ask` で頼まれていない部署（`--task` だけで立てた部署）では何もしない。納品し終えた後も、部署（窓口でない）が次のどちらかのまま止まろうとしたら差し戻す（数えるのは納品の前と別に、同じ会話・同じ頼みで 3 回まで）。
  - ブランチの先頭がメインブランチ（origin の既定のブランチの手元の控え）に入っていない: `--land <部署>` で入れるか、`--land` が自動の権限の判定に止められたなら、入れてほしいと窓口に `--ask <会社の名前>` で頼むよう差し戻す。この差し戻しを出すのは、会社の形（その会社のリポジトリの `.claude/company.toml`）の `[land]`（メインブランチへの入れ方を書くセクション）の `mode` が `ff-after-ci`（ゲート〔CI か手元の検証〕が緑なら、PR を通さずに fast-forward でメインブランチに入れる取り込み方）の会社だけ（PR で入れる会社では、ブランチがメインブランチに入るのは人の見直しの後なので出さない）。2026-10-17 に my_notes で、`--land` が止まった部署が残った疑問に「持ち手: 段取り」（「持ち手」はその疑問を最後まで追う部署、段取りは my_notes の会社で部署への頼みを配る窓口の役の名前）と書いただけで段取りに `--ask` で頼まず、誰も追わないまま 1 日残った。
  - エフェメラルの部署（一度の頼みのために立てて終われば畳む部署。頼みごとにブランチを移って残り続けるのは永続の部署）で、ブランチもメインブランチに入っている（commit の無い部署も）のに終わりの印（エフェメラルの部署が自分で `--done` を打って部署の属性 `company.finished` に書く、畳んでよいという印）が無い: `--done` を打つよう差し戻す。

  この部署が頼んで返事（納品）の来ていない頼みが在る間（この部署の納品の残った疑問の担当者に書いた頼みは数えない）・順番待ちに頼みが在る間・終わりの印が在る間は差し戻さない。永続の部署は、ブランチがメインブランチに入っていないときだけ差し戻す。部署の会話は、差し戻されたら、その文に書かれた手（`--land`・窓口への `--ask`・`--done` のどれか）を打ってから止まる。
