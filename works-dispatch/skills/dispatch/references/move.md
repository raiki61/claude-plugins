# ほかのアカウントで起こし直す: `--move`

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --move <部署か窓口の名前> [--account <アカウントの名>] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --move <部署の名前> --if-changed [--dry-run]
```

立っている部署か本社の窓口（`--desk` で名付けた会話）の会話を、ほかのアカウントで起こし直す。`--account` を省けば、使用率の順で、今のアカウントのほかに上限に届いていない物を選ぶ。同じ役の会話が同時に 2 つ動かないよう、前の会話を止めてから起こす。会話の記憶は引き継がない（自動の覚え書きにも頼らない）ので、起こした会話への最初の文で、受けている頼み（属性 `company.ask` と頼みのファイル）と作業場の枝から続きへ戻らせる。移したことは会社の受付箱の台帳に `moved` で残す。`--account` に今のアカウントを名指すと、同じアカウントのまま、会社の形の今の起動の設定（下の「替わったとき」）で起こし直す（区切り〔`--rest`〕を印さない会話を、持ち主が起こし直してよいと答えたとき）。

- **部署（裏の会話）**: 部署の窓に会話が見えていて、番の途中か入力欄に字が在るときは、会話を止めず起こし直しもせずに終わる（終了の値 75。使用上限で移す `--if-limited` はこの守りを飛ばす）。会話の外から打った `--move` なら、起こし直さなかった訳をその会話に台帳の知らせで渡す（待ち受けが入力欄に打たずに会話へ渡すので、持ち主はその窓で訳を見る。同じアカウントのまま起こし直すときは、区切りで `--rest` を打てば番の終わりに待ち受けが起こし直すことも添える）。そうでなければ、窓の attach の画面をシェルに戻し、前の会話を `claude stop` で止め、`--task` と同じ道で、同じ名前・枝・役の会話を移る先のアカウントで起こす。頼み元の属性はそのまま残すので、納品は元の頼み元へ返る。
- **本社の窓口（持ち主の前の会話）**: 窓口の窓に `/exit` を打って前の会話を終え、同じペインで `<移る先のコマンド> --name <窓口の名前> [--model <モデル>] [--effort <段>] [--settings <ファイル>] <最初の文>` を打つ（窓口の役に `[roles.settings]` が有れば、`--desk` と同じファイルに書いて渡す。model・effort は役の値で、effort の `inherit` は旗を付けない）。起こした値は属性 `company.launched` に書く。窓口の会話が番の途中（herdr の状態が working か blocked）か、窓の入力欄に字が在るときは `/exit` を打たずに止まる（番の途中に打った `/exit` は番の終わりまで待ちの列に回り、起こし直さずに止まった後で効いて、窓口が消えたままになりうる。窓口が自分の番の中で `--move` を打った場合）。会話の外から打った `--move` なら、部署と同じく訳を知らせで渡す。起きた会話は窓口の席に座り（前の会話が終わっていて、名前が窓口の名前なので、役の本文が足される）、最初の文のとおり `--desk` を打って席を自分に付け替える。
- **使用上限で止まったとき（自動）**: 常設の部署と本社の窓口の会話が使用上限で番を止める（Claude Code の StopFailure のフック。誤りの種類が `rate_limit`）と、このプラグインのフックが `--move <その名前> --if-limited` を会話から切り離して裏で走らせる。`--if-limited` は、今のアカウントの使用率の控えが上限（設定の `limit_percent`）に達していなければ移さない（一時の混み合い）。同じ場所では 10 分の間に 2 度は走らせない。走らせた出力は受付箱の `moves/` に残る。`--move` は会話から切り離して走らせる（前の会話を止めると、Claude Code はその会話のフックから起こした処理も止めるので、切り離さないと新しい会話を立てずに消える）。前の会話を止めた後に新しい会話が立たなければ、窓口は前の会話を `--resume` で、部署は前の裏の会話を `attach` で戻し、台帳の `moved` の行に訳を書く。区切りの印は打った会話の id で、待ち受けは今の会話の印のときだけ区切りと見る。前の会話へ戻した窓口は、同じ値では区切りのたびに起こし直さない。都度の部署（作業）は移さない。
- **会社の形の起動の設定が替わったとき（自動）**: 起動の設定は、役（と受け持ち）の model・effort と、役の `[roles.settings]`。待ち受けは `--move <部署か窓口> --if-changed` を走らせ、走り終えるまで頼みを渡さずに待つ。走らせる時は 2 つ。毎回空にする部署では、次の頼みを渡す前。会話を持ち越す部署と本社の窓口では、区切り（`--rest`）を印した番の終わりに、`/clear` の代わりに。`--if-changed` は、origin の既定の枝を取り直してから会社の形の今の値を読み、起こしたときの値（属性 `company.launched`）と違うときだけ起こし直す。アカウントは、今のアカウントが使用率の上限に届いていなければ同じアカウント、届いていれば空いているほかの物。前の会話を止めずに終わったとき（同じ値だった・会社の形を読めない・空いたアカウントが無い・起こせない）は、毎回空にする部署はその頼みを前の会話に渡し（前の設定で受ける）、区切りの会話は前と同じく `/clear` で空にする。今の値は属性 `company.restart-kept` に残して、同じ値では試し直さない。ただし窓口か部署の会話が番の途中か、窓の入力欄に人の打ちかけの字が在って起こし直さなかったときは、訳がすぐ替わるので残さず、次の区切りでまた試す。会話を持ち越す部署と本社の窓口は、区切りの番の終わりのほかには起こし直さない（持ち主と話している途中の会話を切らない。区切りの印は、人がその会話に打つと外れる）。区切りでは会話を空にするので、起こし直しても失う物は同じ。区切りを印さない窓口（持ち主が自分で空にする社長室など）には、設定は自動では届かない。走らせた出力は受付箱の `moves/` に残る。
