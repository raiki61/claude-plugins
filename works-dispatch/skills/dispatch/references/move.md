# ほかのアカウントで起動し直す: `--move`

dispatch のスキル（works-dispatch のプラグインの、Claude Code の会話を部署ごとに立てて仕事を頼むスキル）の別ファイル。部署か窓口の会話を別のアカウントや新しい設定で起動し直すと頼まれたとき、または使用上限などで自動の起動し直しが起きた訳を調べるときに、会話が読む。急ぎの操作は無い。

言葉: dispatch は works-dispatch のプラグインのスクリプト。会社は部署を置いて回す git のリポジトリで、会社の形はその設定ファイル `.claude/company.toml`（役ごとの model・effort などを書く）。部署は作業ごとの git worktree と、そこで働く Claude Code の裏の会話の組。窓口は本社（代表の clone）で持ち主（このスキルを使う人）と話し、部署に頼みを配る会話。役は部署と窓口の会話の決まりで、受け持ちは部署ごとの仕事の範囲。受付箱は会社ごとに頼みと知らせを置くフォルダ（代表の clone の `.git/company/inbox/`）で、台帳はその中の記録のファイル（`log.jsonl`）。待ち受けは、会話のターンの終わりにこのプラグインのフックが裏で起動し、受付箱の台帳を見て会話を再開させる処理。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --move <部署か窓口の名前> [--account <アカウントの名>] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --move <部署の名前> --if-changed [--dry-run]
```

立っている部署か本社の窓口（`--desk` で名付けた会話）の会話を、ほかのアカウントで起動し直す。`--account` を省けば、使用率の低い順（週の枠がすぐ切り替わる物は先。下の「使用上限に当たる前の区切りで移すとき」と同じ順）で、今のアカウントのほかに上限に届いていない物を選ぶ。同じ役の会話が同時に 2 つ動かないよう、前の会話を止めてから起動する。会話の記憶は引き継がない（自動の覚え書きにも頼らない）ので、起動した会話への最初の文で、受けている頼み（属性 `company.ask` と頼みのファイル）と作業場のブランチから続きへ戻らせる（属性は、部署の worktree か代表の clone の git の設定に `git config --worktree` で書いた `company.*` の値で、`git config --worktree --get <名前>` で読める。下の `company.launched`・`company.restart-kept` も同じ）。前の会話が作業場の worktree の git ディレクトリ（`git rev-parse --git-dir`。窓口は代表の clone の `.git`）に引継ぎ `handoff.md`（済んだこと・次の手の覚え書き。下の「使用上限に当たる前の区切りで移すとき」の 1 のとおり `--rest` を納品の前に打つと、書くよう案内が出る）を書いていれば、最初の文がそのパスと、ファイルを最後に書いた時刻を添えて読むよう指し、そのファイルを `handoff-<書いた時刻>.md` に名前を替えて退ける（後の頼みの `--move` が前の頼みの引継ぎを指さない）。移したことは会社の受付箱の台帳に `moved` で残す。`--account` に今のアカウントを名指すと、同じアカウントのまま、会社の形（`.claude/company.toml`。役ごとの model・effort などを書く会社の設定ファイルで、今の値は origin の既定のブランチに在る物を読む）の今の起動の設定（下の「替わったとき」）で起動し直す。この使い方は、区切り〔`--rest`。会話が自分で、ここで会話を空にしてよいと印すコマンド〕を印さない会話について、起動し直してよいかを持ち主に問い、よいと答えたときにする（区切りを印す会話は、下の「替わったとき」のとおり自動で起動し直す）。

- **部署を移すとき**: 部署の会話は裏の会話（`claude --bg` で起動した、画面を持たない会話）で、部署の窓（その部署の herdr のペイン）では、attach の画面（裏の会話を `claude attach` で映している画面）を通して見える。
  - 移さずに終わる場合: 部署の窓に会話が見えていて、その会話がターンの途中か、入力フィールドに字が在るときは、`--move` は会話を止めず、起動し直しもせずに終わる（終了の値 75。使用上限で移す `--if-limited` だけは、この守りを飛ばして移す）。`--move` を部署の会話の外から打ったなら、起動し直さなかった訳を、台帳の知らせとして部署の会話に渡す（待ち受けが入力フィールドに打たずに会話へ渡すので、持ち主はその窓で訳を見る。知らせには、同じアカウントのまま起動し直す方法〔その会話が区切りで `--rest` を打てば、ターンの終わりに待ち受けが起動し直す〕も書いてある）。
  - 移す場合（上に当たらないとき）: 1. 部署の窓の attach の画面を抜けてシェルに戻す。2. 前の会話を `claude stop` で止める。3. `--task`（部署を立てるコマンド。[department.md](department.md)）が会話を起動するのと同じ手順（部署の worktree のペインで、移る先のアカウントの起動コマンドに `--bg --name <部署の名前>` と役の model・effort・`--settings` を付けて裏の会話を起動し、窓に attach する）で、前の会話と同じ部署の名前・ブランチ・役の新しい会話を、移る先のアカウントで起動する。部署の属性の頼み元はそのまま残すので、新しい会話の納品は元の頼み元へ返る。
- **本社の窓口（持ち主の前の会話）**: 窓口の窓に `/exit` を打って前の会話を終え、同じペインで `<移る先のコマンド> --name <窓口の名前> [--model <モデル>] [--effort <段>] [--settings <ファイル>] <最初の文>` を打つ（`<移る先のコマンド>` は移る先のアカウントの起動コマンドで、dispatch の設定の `accounts` のそのアカウントの `command`。`<最初の文>` は上で述べた、続きへ戻らせる文で、`--desk` を打つことも書いてある。窓口の役に `[roles.settings]` が有れば、`--desk` と同じファイル〔代表の clone の `.git/company-settings.json`〕に書いて `--settings` で渡す。model・effort は役の値で、effort の `inherit` は旗を付けない）。起動した値は属性 `company.launched` に書く。窓口の会話がターンの途中（herdr〔端末を作業場とペインに分けて Claude Code の会話を並べるツール〕がペインの会話に付ける状態が working〔応答中〕か blocked〔許可待ちなど〕）か、窓の入力フィールドに字が在るときは `/exit` を打たずに止まる（窓口が自分のターンの中で `--move` を打ったときがこれに当たる。ターンの途中に打った `/exit` はターンの終わりまで待ちの列に回り、起動し直さずに止まった後で効いて、窓口が消えたままになりうる）。会話の外から打った `--move` なら、部署と同じく訳を知らせで渡す。起きた会話は窓口の席に座り（前の会話が終わっていて、名前が窓口の名前なので、役の本文が足される）、その `<最初の文>` のとおり `--desk` を打って席を自分に付け替える。
- **使用上限で止まったとき（自動）**: 永続の部署と本社の窓口の会話が使用上限でターンを止める（Claude Code の StopFailure のフック。誤りの種類が `rate_limit`）と、このプラグインのフックが `--move <その名前> --if-limited` を会話から切り離して裏で走らせる。`--if-limited` は、今のアカウントの使用率の控えが上限（設定の `limit_percent`）に達していなければ移さない（一時の混み合い）。同じ場所では 10 分の間に 2 度は走らせない。走らせた出力は受付箱の `moves/` に残る。`--move` は会話から切り離して走らせる（前の会話を止めると、Claude Code はその会話のフックから起動した処理も止めるので、切り離さないと新しい会話を立てずに消える）。前の会話を止めた後に新しい会話が立たなければ、窓口は前の会話を `--resume` で、部署は前の裏の会話を `attach` で戻し、台帳の `moved` の行に訳を書く。区切りの印（会話が `--rest` を打って属性 `company.rest` に書く、ここで会話を空にしてよいという印）の値は打った会話の id で、待ち受け（ターンの終わりに動くこのプラグインのフック）は、その値が今の会話の id のときだけ区切りと見る（前の会話が打った印は、新しい会話では効かない）。窓口を前の会話へ戻したときは、`--move` が今の起動の設定の値を属性 `company.restart-kept` に残す。会社の形（`.claude/company.toml`）の起動の設定（役の model・effort・`[roles.settings]`）がその値から替わるまでは、待ち受けは区切りのたびに起動し直しと戻しを繰り返さない。エフェメラルの部署（作業）は移さない。
- **会社の形の起動の設定が替わったとき（自動）**: 起動の設定は、役（と受け持ち〔会社の形の `[[skills]]` に書く、部署ごとの仕事の範囲。部署の名前と同じ名前の物がその部署に効く〕）の model・effort と、役の `[roles.settings]`。待ち受けは `--move <部署か窓口> --if-changed` を走らせ、走り終えるまで頼みを渡さずに待つ。待ち受けが `--if-changed` を走らせる時は、部署の種類で 2 つに分かれる。毎回クリアする部署（役が `fresh = true`）では、次の頼みを渡す前に走らせる。会話を引き継ぐ部署と本社の窓口では、区切り（`--rest`）を印したターンの終わりに、会話を空にする `/clear` を打つ代わりに走らせる。`--if-changed` は、origin の既定のブランチを取り直してから会社の形の今の値を読み、起動したときの値（属性 `company.launched`）と違うときだけ起動し直す。アカウントは、今のアカウントが使用率の上限に届いていなければ同じアカウント、届いていれば空いているほかの物。前の会話を止めずに終わったとき（同じ値だった・会社の形を読めない・空いたアカウントが無い・起動できない）は、毎回クリアする部署はその頼みを前の会話に渡し（前の設定で受ける）、区切りの会話は前と同じく `/clear` で空にする。今の値は属性 `company.restart-kept` に残して、同じ値では試し直さない。ただし窓口か部署の会話がターンの途中か、窓の入力フィールドに人の打ちかけの字が在って起動し直さなかったときは、訳がすぐ替わるので残さず、次の区切りでまた試す。会話を引き継ぐ部署と本社の窓口は、区切りのターンの終わりのほかには起動し直さない（持ち主と話している途中の会話を切らない。区切りの印は、人がその会話に打つと外れる）。区切りでは会話を空にするので、起動し直しても失う物は同じ。区切りを印さない窓口（持ち主が自分で空にする社長室など）には、設定は自動では届かない。走らせた出力は受付箱の `moves/` に残る。
- **使用上限に当たる前の区切りで移すとき（自動）**: 上の「会社の形の起動の設定が替わったとき」と同じ区切り（毎回クリアする部署は次の頼みを渡す前、会話を引き継ぐ部署と本社の窓口は `--rest` を印したターンの終わり）で待ち受けが走らせる `--move <名前> --if-changed` は、起動の設定が同じでも、次の 2 つのどちらかに当たれば、ほかのアカウントで起動し直す。使用上限に当たってから移る `--if-limited` はターンの途中で切られ、そのターンの作業が消えるので、その手前で移す。1. 持ち主か窓口が `--move <名前> --account <アカウント>` を打ったが、移す会話がターンの途中だったか、その窓の入力フィールドに打ちかけの字が在ったので、`--move` が移さずに終わった（上の「移さずに終わる場合」。`--move` の終了の値は 75。このとき `--move` が移す先のアカウントの名を、その部署か窓口の属性 `company.move-to` に書き、区切りの `--if-changed` がそれを読む。この印の在る会話は、受けた頼みを納品する前でも `--rest` を打てる。そのターンの終わりに、待ち受けが会話をほかのアカウントへ移し、新しい会話への最初の文が受けている頼みを渡す。移せなかったときは、頼みの途中なので `/clear` で会話を空にはせず、待ち受けが区切りの印 `company.rest` を外して、前の会話がそのまま頼みを続ける。`company.move-to` は残るので、その会話が次に `--rest` を打ったときにまた移すのを試す）。2. 今のアカウントの 5 時間か週の枠が、dispatch の設定（`~/.config/works-dispatch/dispatch.toml`）の `move_early_percent`（既定 90%）に達し、達した枠のうち 1 つでも `move_early_reset_hours`（既定 1 時間）より先まで戻らない。移る先は、1 なら名指したアカウント、2 なら、5 時間と週の枠の使用率の高い方が `move_early_percent` に届かないほかのアカウントのうち、`--account` を省いたときと同じ選び方の順（週の枠がすぐ切り替わる物が先で、ほかは使用率の低い順）の先頭。移る先が無い（名指した先が上限に達した・目安に届かないアカウントが無い）・達した枠がどれもすぐ戻るときは移さず、訳を台帳の `moved` の行（`status` が `skipped`）に残す。同じアカウントの同じ訳は 1 度だけ残す（属性 `company.move-skipped`）。早めに移そうとして移る先で起動できず前の会話へ戻したときは、その先を属性 `company.move-kept` に書き、次からは早めに移す先に選ばない（区切りのたびに止めて戻すのを繰り返さない。どちらの属性も、起動し直すと外れる）。移ると会話の記憶を引き継がず、移る先の週の枠も使う。区切りの印の無い、会話を引き継ぐ部署と窓口は、この早めの移し替えでも起動し直さない（持ち主と話している途中の会話を切らない）。
- **使える時間帯が終わるとき（自動）**: 設定のアカウントに `hours`（使える時間帯。[setup.md](setup.md) の「アカウントの書き方」）を書いたアカウントは、時間帯の終わりまで `hours_margin_minutes`（既定 30 分）を切ると、新しい部署の起動にも移し先にも選ばれなくなる。そのアカウントで動いている会話は、次の 2 つで移る。1. 上の「使用上限に当たる前の区切りで移すとき」と同じ区切りで、`--if-changed` がほかのアカウントへ移す（移る先は、選べるほかのアカウントのうち `--account` を省いたときと同じ順の先頭。使用率の分からないアカウントも選べる）。選べるほかのアカウントが無ければ移さず、訳を台帳の `moved` の行（`status` が `skipped`）に残す。2. 区切りが来ないまま時間帯が終わって要求が断られ、ターンが誤りで止まったときは、「使用上限で止まったとき」と同じフックが、誤りの種類を問わずに（時間帯の外の要求をどの誤りで断るかは提供元ごとに違う）、その会話のアカウントが時間帯の外か終わる手前なら `--move <名前> --if-limited` を走らせる。台帳の `moved` の行の訳は「使える時間帯の外か終わる手前で止まった」。区切りの印の無い、会話を引き継ぐ部署と窓口は、1 では移さず、2 で移る。`--move <名前> --account <アカウント>` で時間帯の外のアカウントを名指すと止まる。
