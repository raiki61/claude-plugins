# 役の中身と起動方法: 会社の形の `[[roles]]` と `gh_user`

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。会社の形（`.claude/company.toml`、無ければ設定の置き場の `companies/` の物）に役を足す・直すとき（下の見本から書くフィールドを選ぶ）と、部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）の役・model・effort・設定がどう効くかを確かめたいときに読む。会社の形のファイルにはフィールドの説明を書かなくてよい（説明はここに置く）。

語:

- ターンは会話の 1 回の応答。注記は、dispatch のコマンドやフックが出す、止めずに知らせる 1 行。
- 本社は会社（部署を置いて回す git のリポジトリ）の代表の clone で、窓口は本社で持ち主と話し、部署に頼みを配る会話（`--desk` で名付ける）。
- 部署の窓は、部署の会話を映した herdr（端末の画面を作業場とペインに分けて会話を並べるツール）のペイン。永続の部署は頼みが無くても立ったまま残り、エフェメラルの部署は頼みを済ませたら畳む。
- 受け持ちは、会社の形の `[[skills]]` に 1 つずつ書く仕事の範囲（例 `割り振り`）で、名前が同じ部署に効く。
- 属性は `git config --worktree` で書く `company.*` の値。属性を持つフォルダ（部署の worktree か代表の clone の作業ツリー）を場所と呼び、「場所の属性の会話」は、その場所の属性 `company.session` に書いた会話。
- 待ち受けは、ターンの終わりにこのプラグインのフックが裏で起動し、受付箱（頼みと納品を置く、代表の clone の `.git/company/inbox/`）の台帳を見て会話を再開させる処理（ask.md の「待ち受け」）。

## 見本

```toml
gh_user = "<gh のログイン名>"   # 部署の会話の gh が使うアカウント（省けば、その人の今の gh の設定のまま。下の「gh のアカウント」）
default_role = "作業"            # --role を省いたときの役（[[roles]] のどれか。省けば 作業）
desk_role = "窓口"               # 本社（会社の代表の clone。上の「本社」）で持ち主と話す会話の役（--desk で --role を省いたときの役。省けば本社の会話に今付いている役、無ければ 窓口）
shared_instructions = """
試験は触った所だけ回す。
"""                                 # 任意。どの役の部署の会話にも、役の本文の前に足す会社の共通の本文（本社の窓口の会話には足さない）
desk = "<会社>/<窓口の名前>"    # 任意。この会社に窓口を置かず、ほかの会社の窓口に兼ねさせるとき、その窓口（--tree が窓口と宛て方に出す。この会社の本社に --desk で名付けた窓口が立つか、本社の窓口を --handover で継いだ部署が在れば、そちらが先）

[[roles]]
name = "調べ役"                                  # --role に渡す名前（部署の属性 company.role）
former_names = ["下調べ"]                        # 任意。役の前の名前（下の「役の名前と既定の役」）
instructions = "結論と原典の一句を返す。"          # 部署の会話に足す役の本文。短く、AGENTS.md（どの会話も読む、リポジトリのエージェント向けの指示）と同じことは書かない
model = "haiku"                                  # 部署を起動するときの --model（省けばアカウントの既定）
effort = "low"                                   # 部署を起動するときの --effort（inherit なら頼んだ会話と同じ。省けばアカウントの既定）
account = "cheapest"                             # 部署を新しく立てるときに先に使うアカウント（dispatch の設定の accounts の name。"cheapest" は名前の例で、予約の値ではない）
deliver = ["結論", "決め手", "残った疑問", "ブランチ"]   # 納品する要約の必須項目（省けば既定。「納品する」の「要約の項目」）
deliver_check = "python3 scripts/check_deliver.py"   # 納品の検査のシェルのコマンド（省けば検査しない。「納品する」の「納品の検査」）
holders = []                                     # 任意。true か名前の並びなら、納品の要約の残った疑問ごとに、それを追う担当者が書いてあるかを確かめる（空の [] は true と同じ。並びには、担当者にさせない持ち主への中継の会話の名前を書く。例 ["社長室"]。false か省けば確かめない。「納品する」の「要約の書き方」）
ask_check = "python3 scripts/check_ask.py"       # 任意。この役へ宛てた頼みを受ける会社の検査（「頼む」の「受ける会社の検査」）
ask_holders = []                                 # 任意。holders と同じ値で、この役へ宛てた頼みの残った疑問の担当者を確かめる（「頼む」の「本文の書き方」）
persistent = true                                # この役の部署は永続（--persistent を付けたのと同じ。前の版のキー resident = true も同じ意味）
fresh = true                                     # 頼みごとに空の会話で受ける（省けば会話を引き継ぐ）
keepalive = true                                 # 任意。仕事が終わらないままターンを終えた間、待ち受けがプロンプトキャッシュの寿命の前に短い文を送る（間と文は「仕事が終わるまでの keepalive」）
[roles.settings]                                 # 部署を起動するときの --settings（その会話にだけ効く Claude Code の設定）。この行より後のフィールドは settings に入る
permissions = { deny = ["Artifact", "Workflow", "ScheduleWakeup", "SendFeedback", "ReportFindings"] }
enabledPlugins = { "pr-review-toolkit@claude-plugins-official" = false }
skillOverrides = { dataviz = "off" }

[[skills]]
name = "割り振り"                     # 部署の名前と同じ（「割り振り：…」の名前の部署にも効く）
role = "担当"
model = "sonnet"                      # この部署だけ、役の model より先に効く
effort = "low"                        # この部署だけ、役の effort より先に効く
account = "cheapest"                  # この部署だけ、役の account より先に効く
settings = { promptCacheTtl = "5m" }  # この部署だけ、役の [roles.settings] に重ねる（例はプロンプトキャッシュの寿命を 5 分にする）
keepalive = { every = "240s" }        # この部署だけ、役の keepalive より先に効く（表どうしは鍵ごとに重ねる。false で切る）
```

`machine = true` の役は、AI の部署を持たない役（AI を起動せずに機械で答えるツール `[[roles.tools]]` だけを持つ「機械窓口」。書き方は call.md）で、`--ask` で宛てられない。

見本に無いフィールド: 頭の `name`（会社の名前。`--ask <会社>` の宛先）・`description` と、`[[skills]]` の `description`・`on_demand`・前の版の `standing` は department.md の「会社のツリー図: `--tree`」。`[[skills]]` の `id` は `--tree --json` に出るだけの識別子。`[skills.start]` は start.md、`[land]` は land.md。

## TOML の書き方の決まり

- 役は `[[roles]]` の形だけで書く。`[roles."調べ役"]` のように名前で引く表の形は読まず、`[[roles]]` に移すよう注記を出す（TOML では同じ `roles` を両方の形で書けず、混ぜると片方が黙って効かない）。
- `[roles.settings]` の行より後に書いたフィールドは `settings` の中に入る。`deliver` などの役のフィールドは `[roles.settings]` より前に書く（`settings` の中に `deliver` が有れば注記を出す）。
- TOML には共通の表を引く書き方が無く、works-dispatch も役の間で `settings` を継がない。いくつかの役に同じ起動の設定を効かせるなら、役ごとの `[roles.settings]` に同じ値を書く（受け持ちごとに足す分は受け持ちの `settings`）。本文の共通の決まりは `shared_instructions` に 1 度だけ書く（下の「役の本文」）。
- 会社の形の表（頭・`[[roles]]`・`[[roles.tools]]`・`[[skills]]`・`[skills.start]`・`[land]`・`[land.roles.<役>]`・`[[land.after]]`）に、この版が読まない鍵（書き間違い・新しい版の鍵・外した鍵）が有れば、その鍵だけを読まずに、会社の形を読むコマンド（`--tree`・`--task`・`--ask`・`--deliver`・`--land`）の出力に鍵の名前を挙げた注記を出す（`--tree` では会社の行の下の `!` の行。読む鍵の一覧は `dispatch/known_keys.py`）。`[roles.settings]`・受け持ちの `settings`・ツールの `inputSchema`・`[[land.after]]` の `input` の中は見ない（Claude Code・JSON Schema・ツールに渡す値のため）。
- 注記だけで止めないのが基本で、止めるのは 2 つ。`[[roles]]` の項目に読まない鍵が 1 つでも有れば、その役の部署からの `--deliver` とその役へ宛てた `--ask` は、何も送らず受付箱にも置かずに鍵の名前を出して終わる（`deliver_check`・`ask_check`・`holders`・`ask_holders` を書き間違えると、ゲートが黙って外れるため）。`[land]`・その役の `[land.roles.<役>]`・`[[land.after]]` の読まない鍵は `--land` を止める。直すには、鍵を直して origin の既定のブランチ（会社の形はここから読む）に入れるか、その鍵を知る版の works-dispatch を使って打ち直す。
- 前の版のキー（役の `resident = true`、受け持ちの `standing = false`）は、今の版が今のキー（`persistent = true`・`on_demand = true`）と同じ意味で読む（両方有れば今のキー）。0.78.0 までの works-dispatch は今のキーを読まないので、その版でこの会社の形を読む PC が残る間だけ前のキーも並べて書き、残らなくなったら消す。

## 役の本文

- 役の本文は、このプラグインの SessionStart のフックが、会話の始まり（やり直し・圧縮の後も）に足す。毎回の起動の量に入るので短く書く。
- 足す先は、部署（属性 `company.role` の有る worktree）の会話と、`--desk` で窓口を名付けた代表の clone の、窓口の席に座る会話だけ。窓口の席に座るのは次のどれか:
  - 属性の会話（`company.session`）。
  - `--desk` を打った会話と同じ Claude Code の処理の会話（`/clear` の後）。
  - 窓口の会話が動いていないときに、窓口の名前で起動した会話（`claude --name <窓口の名前>`）。
- 名前の無い試しの `claude -p` や、窓口が動いている間に起きたほかの会話には足さない。
- 部署の名前（属性 `company.name`）と同じ `name` の受け持ちが有れば、その受け持ちの `description` も「受け持ちは「<name>」（<description>）」の形で足す（役を 1 つ〔担当〕にし、受け持ちごとの中身を部署の名前で引くため）。
- 会社の場所で役の本文を足さない会話（属性の無い作業場の会話・代表の clone の窓口でない会話）には、ほかの会社への頼み方の 1 行（SendMessage でなく `--ask <会社の名前>` を打つ）だけを足す（SendMessage の頼みは受付の台帳に頼み元が残らない）。会社になる前から動いている会話には、会社になった後の最初のターン（UserPromptSubmit）で足す（まだ何も足していないときだけ）。会社でないリポジトリの会話には何も足さない。
- 役をまたいで同じ決まり（試験の回し方・手元のパスを書かないなど）は、役ごとの `instructions` に写さず `shared_instructions` に 1 度だけ書く（写すと、直すときに全部の役を同時に直すことになる）。フックが会社と役の 1 行の後・役の本文の前に足す。本社の窓口には足さない（窓口は部署を立てて頼む側で、窓口に要る決まりは窓口の役の本文に書く）。
- 会社の形の役の名前・役の本文・`shared_instructions`・受け持ちの `description` を替えたら、会話を引き継いでいる部署と窓口にも、次のターンの頭（UserPromptSubmit のフック。待ち受けが知らせで会話を再開させるときは知らせの文の前）に今の文を足す。前に足した文（控えは TMPDIR の `works-dispatch-role-<会話の id>`）と違うときだけ足し、会話は空にしない。足すのは場所の属性の会話だけ。
- エフェメラルの部署の役の本文には畳み方（納品し、ブランチがメインブランチに入ったら `--done`。commit の無い頼みなら納品の後に `--done`）まで書く（書かないと、納品した部署が会話を残したまま並び続ける）。`--done` はメインブランチに入っていない部署を断るので、入れるのが人の会社（`[land]` が `none`）なら、断られた部署は止まり、入った後に窓口が `--retire` で畳む、と書く（`--init-company` の下書きの `作業` と `窓口` の本文はそう書いてある）。
- `--compact <焦点>`（ここで compact してよいと印すコマンド。「待つ・区切る」の「compact の区切り」）を、どの役がいつ打つかは役の本文に書く（会社の形に役ごとの値は無い）。新しい仕事に移る所は `/clear`（`fresh` か `--rest`）が安い（読み直しは約 3 万トークンで、compact の要約の費用が要らない）。
- 効きは、`claude plugin details` の見積もりでなく、起動した会話の最初の API 要求のトークン（入力とキャッシュの書き・読みの和）で確かめる（見積もりは、フックが足す文やサブエージェントの説明を数えない）。

## model・effort・account

- どの値を書くかの材料（世代ごとの、仕事ごとの格・effort の成績と費用）は models.md のいちばん上の世代の見出し。
- `model` と `effort` は、部署を起動するとき（`--task` と、`--ask` で新しく立てるとき）だけ渡す。省けばそのアカウントの既定（そのアカウントの Claude Code の設定、無ければモデルの既定。Opus 5.5 の effort は medium）。`--effort` はその会話にだけ効き、設定の `effortLevel`・`modelSettings` より強い。
- `effort` は `low`・`medium`・`high`・`xhigh`・`max`・`ultracode` か `inherit`。`inherit` は、dispatch を打った会話の今の effort（Bash のツールに渡る `CLAUDE_EFFORT`）で起動する（読めなければ既定で起動して注記）。知らない値は Claude Code が注意を 1 行出すだけで既定に戻す（裏の会話の注意は誰も読まない）ので、dispatch が読むときに弾き、注記を出して役を外す。`model` の `inherit` は無い（頼んだ会話の今のモデルは、Bash のツールの環境変数にも `claude agents --json` にも出ない）。書けば注記を出して役を外す。
- 立っている部署に `--ask` で頼むときは、モデルと effort を渡さない。会話を引き継ぐ部署は起動したときのまま変わらない（落ちた会話を `--ask` が `attach` で戻すときも）。`fresh` の部署は次の頼みの前に起動し直すことがある（下の「永続と毎回クリア」）。
- 受け持ちに書いた `model`・`effort`・`account` は、次の名前の部署にだけ効く。
  - 名前が受け持ちの名前と字が同じ部署。
  - 「<受け持ち>：<何をするか>」（全角のコロン）の名前の部署。「：」より前を、長い方から受け持ちの名前と比べる。
- 決める順はフィールドごとに、受け持ちの値・部署の役（`--role` か `--ask 会社/役` で決まる。受け持ちの `role` フィールドではない）の値・アカウントの既定。永続の部署はどれも役「担当」で起動するので、部署ごとに替えるには受け持ちに書く。
- 形の違う値（`model` の `inherit` を含む）はそのフィールドだけ外し、注記を出して次の順の値で起動する（止めない）。`--tree` の受ける仕事の行に、受け持ちに書いた値が出る（形の違う値は `!` の行に注記）。
- 受け持ちの名前の部署は 1 つしか立たないので、その部署への頼みは 1 件ずつ順に受ける。並べて走らせたい一度きりの仕事は「<受け持ち>：<何をするか>」の名前で、永続でない役（`作業` など）で立てる（受け持ちに名指される永続の役〔担当〕で立てると、`--task`・`--ask` は止まる）。受け持ちに当たらない部署で仕事の種類（レビュー・直し・下調べなど）ごとにモデルを替えるなら、種類ごとに `[[roles]]` を足して `--role <役>`（か `--ask 会社/役 --task <名前>`）で選ぶ（部署の名前は自由で、`--init-company` の下書きのコメントに例が有る）。
- `account` は、部署を新しく立てるとき（`--task`・宛先の部署が無い `--ask`・`--call` で呼んだ機械窓口のツールが片づかず〔0 以外で終わり〕、仕事を回す役の部署を立てるとき）に先に使うアカウント（dispatch の設定 `~/.config/works-dispatch/dispatch.toml` の `accounts` の `name`）。省けば使用率の順（アカウントごとの使用率の控え `~/.cache/claude-limits/<アカウント>.json` の低い順で、控えの無いアカウントは後。取り方は setup.md の「任意: herdr の見た目を整える」の 2）。立っている部署の起動し直し（`--move`・`fresh` の起動し直し）には効かない。
- 名指したアカウントが使えないと見るのは、次のどれか。
  - 使用率の上限に達した（控えの有るアカウント）。
  - 使える時間帯（`hours`）の外か、終わりの `hours_margin_minutes`（既定 30 分）前を切った。
  - そのアカウントに終わっていない会話が `max_open`（`accounts` の 1 行に書く 1 以上の整数。既定 1）件以上在る。`claude agents --json` に出る会話を、会社や部署を問わず、待機中の裏の会話も数える（既定の 1 は、同時に 1 件しか走らないアカウントがあるため）。
  - `accounts` に無い。
  - 立てる部署と同じ名前の会話が、ほかの会社でそのアカウントに開いている（department.md の `--dry-run` の後の段落）。
- 使えないときは止めずに使用率の順で選び、名指しを使わなかった訳を注記に出す。ただし名指したアカウントが `named_only = true`（名指しのときだけ使うアカウント）なら、ほかのアカウントで立てずに止める（「止めた」で始まる行を出して 1 で終わる。`--ask` なら台帳に failed と残す）。
- モデルの別名（`opus`・`sonnet` など）が何に読み替わるかはアカウントごとの設定で決まる（setup.md の「アカウントの書き方」の `named_only` の項。`--tree` の終わりのアカウントの一覧に読み替え先が出る）。名指したアカウントでしか動かないモデルを別名で書くと、名指しが使えずにほかのアカウントで立ったとき、黙って別名どおりのモデル（Anthropic の Sonnet など）で動く。そのアカウントを `named_only = true` にして止めるか、`model` に実名（例 `gpt-6.1-sol`）を書いて、ほかのアカウントでは起動の誤り（api_error）で止まって見えるようにする（実名なら部署の画面にも実名が出る）。
- 待ち受けが起動し直すかを比べる値（属性 `company.launched`。起動したときの `model`・`effort` など）に、名指しのアカウントは入れない（名指しが使えずに別のアカウントで立った部署が、頼みのたびに起動し直されないため）。`--tree` の受ける仕事の行と機械窓口のツールの行（`[[roles.tools]]`）に「先に使うアカウント」が、`--task --dry-run` に名指したアカウントの名前とそれを使うかが出る。

## 起動の設定（settings）

- `settings` は、その会話の間だけ、利用者の全体の設定とリポジトリの設定の同じ鍵より先に効く（全体の設定とリポジトリの設定は触らない）。ツールの名前だけを `permissions.deny` に書くと、そのツールは会話の文脈から消える。`skillOverrides` は Claude Code に同梱のスキルにだけ効き、プラグインのスキルには効かない（プラグインごと切るのは `enabledPlugins`）。`enabledPlugins` で works-dispatch 自身を切ると役の本文が足されないので、dispatch が注記を出す。
- 受け持ちの `settings`（表）は、その受け持ちの部署（受け持ちの名前と「<受け持ち>：<何をするか>」）を起動するとき、役の `[roles.settings]` の上に重ねる（表は鍵ごとに深く重ね、表でない値〔並びを含む〕は受け持ちの値で置き換える。部署の worktree を作業場から出さない `worktree.bgIsolation` は最後に上から重ねる）。表でなければ注記を出して外す。効く時は `model`・`effort` と同じで、`company.launched` にも重ねた設定が入る。`--task --dry-run` の「役の起動の設定」の行に、重ねた後の鍵の名前が出る。
- 部署が打つ `--land` が auto mode の判定に止められないための `autoMode.allow` の書き方と訳は land.md。並びの頭に `"$defaults"` を置く（無いと、組み込みの例外の並びを丸ごと置き換える。https://code.claude.com/docs/en/auto-mode-config ）。`autoMode` はプロジェクトの `.claude/settings.json` からは読まれないので、役の `settings` に書く。
- `autoCompactWindow`（Claude Code が自動で compact する文脈の量。トークンの数で 100000〜1000000。https://code.claude.com/docs/en/settings-reference ）は、待ち受けの強制の線の元にもなる。強制の線は、その値の 8 割（`dispatch/nodes/role.py` の `FORCED_SHARE`）。keepalive を送る時刻（「仕事が終わるまでの keepalive」）と、keepalive を送る会話のターンの終わりと、`--compact` の印のターンの終わりに、会話の文脈が強制の線に着いていれば、待ち受けは借りるか買うかの判断の部品に `forced` を真にして聞き、会話に焦点を問わずに compact を打つ（部品が入っていない・答えないときも打つ。書き方は [rest.md](rest.md) の「keepalive の時刻の compact」）。会話の環境変数 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` が設定より先に効く（Claude Code と同じ順）。どちらも書いていない・幅の外の値なら、強制の線は無い。上げる値は次の順で決める。
  1. 上げるのは keepalive を書いた役か受け持ちだけ。待ち受けが compact を判断するのは keepalive を送る会話（keepalive の時刻とターンの終わり）と `--compact` の印のときだけなので、keepalive の無い部署で上げると、自動の compact のほかに歯止めが無くなる。
  2. 値は、その役のモデルの文脈の上限を超えない（今の Claude 5 系は全部 1M。https://platform.claude.com/docs/en/about-claude/models/overview ）。超えて書くと、Claude Code はモデルの上限で打つ（https://code.claude.com/docs/en/model-config の「Set the auto-compact window」）が、強制の線は書いた値から出すので、自動の compact より後ろになって働かない（例: 200K のモデルに `500000` と書くと、線は 40 万トークン）。`1000000` を超える値は幅の外なので、強制の線は無い。
  3. 上限の近くまで上げる（設計書 docs/specs/2026-10-24-rent-or-buy-design.md〔リポジトリのルート〕の 6。自動の compact はターンの途中でも焦点なしで打つので、歯止めにだけ残す）。1M のモデルで `1000000` なら、強制の線は 80 万トークンで、自動の compact は約 967K（https://code.claude.com/docs/en/model-config ）。
  4. 上げた後は、待ち受けが compact を判断しない会話（1 つのターンが長く続く会話と、仕事を終えたままターンを重ねる会話）が自動の compact の線まで伸びる。その費用を、会話の記録で、自動の compact（compact の境目の `trigger` が `auto`）の数と、20 万トークンを超えた会話の数で見る。20 万は、長い会話の読み直しの費用を抑えるために入れた前の値（ルートの docs/reform/ledger.md の「長い会話を 20 万トークンで縮める」）。待ちの間に自動の compact が打たれていたら、`FORCED_SHARE` を下げる（8 割は実測の前の仮の値）。

## 仕事が終わるまでの keepalive（keepalive）

- 部署が頼みの途中でターンを終える（裏の処理〔Bash の `run_in_background` など〕を待つ・出した頼みの納品を待つ・持ち主の答えを待つなど）か、窓口が出した頼みの納品を待ってターンを終えると、会話は手が空いたまま知らせを待つ。プロンプトキャッシュの寿命（5 分か 1 時間。キャッシュに当たるたびに伸びる）を過ぎてから知らせでターンが始まると、会話の中身を全部キャッシュに書き直す。書く単価は入力の 1.25 倍（5 分）か 2 倍（1 時間）、当たって読む単価はモデルで違い、Opus 5.5・Sonnet 5.5 は 0.05 倍、Fable 5.1・Mythos 5.1 は 0.025 倍、ほかは 0.1 倍（https://platform.claude.com/docs/en/about-claude/pricing 。2026-10-23 に読んだ）。`keepalive` を書いた役と受け持ちの部署と窓口では、待ち受けが寿命の切れる前に短い文を会話に送り、そのターンの要求でキャッシュを伸ばす。
- 書き方は 3 つ。`keepalive = true`（間も文も既定）・`keepalive = { every = "240s", text = "…" }`（`every` は正の整数の秒か `"<数>s"`・`"<数>m"`・`"<数>h"`、`text` は空でない文字列。どちらも省ける）・`keepalive = false`（切る）。書かなければ送らない。受け持ちの値は役の値より先に効き、両方が表なら鍵ごとに受け持ちの値で重ねる。窓口は部署でないので受け持ちを引かず、役の値だけで決める（寿命も、`--move` が窓口を起動するときに渡す役の `[roles.settings]` から読む。持ち主が自分で起動した窓口の寿命が違うなら、環境変数か役の `promptCacheTtl` で合わせる）。形が違えば注記を出して、書かなかったのと同じに扱う。
- 送る時刻と止め時は、借りるか買うかの判断の部品（このリポジトリの rent-or-buy プラグインの `bin/rent-or-buy`。つなぎ方は設計書 docs/specs/2026-10-24-rent-or-buy-design.md〔リポジトリのルート〕の 6）に聞く。部品は会話の記録から最後の要求の時刻・モデル・文脈の量を読み、送る時刻（`next_at`。最後の要求の始まり + 寿命 − 余裕 60 秒）と、もう 1 本送るか（`action` が `rent`）止めるか（`buy`）を返す。止めるのは、この待ちで送った費用の合計と次の 1 本の費用が、キャッシュの書き直し 1 回分に着く所（部品の判断の決まりは rent-or-buy の README）。余裕の正は部品の `prices.toml` の `margin_s` で、works-dispatch の `dispatch/nodes/role.py` の `KEEPALIVE_MARGIN`（60）は部品が無いときの控え。60 秒は持ち主の判断（2026-10-24「90だと3分半で送るのでさすがにはやいのでは」）で、外の keepalive のプラグインの既定の間隔 240 秒（https://github.com/yujiachen-y/claude-code-cache-keepalive ）と同じ。部品の時刻は最後の要求の始まりから数えるので、ターンの終わりの応答を作る時間を含まない（2026-10-24 に手元の 4 アカウントの直近 4 日の会話の記録 4,921 本・ターンの終わり 5,470 回で、最後の要求の始まりからターンの終わりまでは中央 7.8 秒・99% 42 秒・99.9% 81 秒だった）。部品が入っていない・答えない（訳は台帳の行の `fixed`）か、役か受け持ちに `every` を書いた部署では、ターンの終わりから `every` 秒で送る。`every` の既定は寿命から 60 秒を引いた値（5 分なら 240 秒、1 時間なら 3600 − 60 = 3540 秒）。ターンの終わりから数えるので、応答を作るのが 60 秒を超えたターンでは寿命の後に届く。`every` を書いても、部品が答えれば止め時は部品の `action` で決める。寿命は、Claude Code が先に効かせる順（https://code.claude.com/docs/en/prompt-caching の「Choose the TTL yourself」）に、会話の環境変数 `FORCE_PROMPT_CACHING_5M=1`（5 分）・`CLAUDE_CODE_PROMPT_CACHE_TTL`、その部署の起動の設定（役の `[roles.settings]` に受け持ちの `settings` を重ねた物）の `promptCacheTtl`、環境変数 `ENABLE_PROMPT_CACHING_1H=1`（1 時間）を見て決め、どれも無ければ 1 時間と見る（サブスクリプションの使用枠の中では、Claude Code の会話の既定が 1 時間）。環境変数 `DISABLE_PROMPT_CACHING=1` でキャッシュを切っている・寿命の値が `5m`・`1h` のどちらでもない・`every` が寿命より短くない部署には送らない（伸ばすキャッシュが無いか、寿命が分からないか、送っても寿命の切れた後に届く）。利用者の設定（`~/.claude/settings.json` など）の `promptCacheTtl` は読まないので、そこで寿命を変えている部署では、会社の形の `settings` に同じ `promptCacheTtl` を書く（起動の `--settings` は利用者の設定より先に効くので、会話の寿命とも合う。`every` だけを書くと、間は合っても続けて送る本数の上限を 1 時間の寿命で数える）。
- 文の既定は、keepalive だと名乗り、することは無いと断って、ツールを使わずに `waiting` とだけ返すよう頼む英語の 1 行（約 15 トークン。英語で短いのは、keepalive の要求ごとに書く分を減らすため。文面は `dispatch/nodes/role.py` の `KEEPALIVE_TEXT`。返事を空にすると、Claude Code が見える返事を促す文を足して要求が 1 回増える）。役の本文に keepalive の扱いを書くなら、`text` で文を合わせる。
- 送るのは、ターンの終わりに区切り（`--rest`・`--compact`）・終わり（`--done`）の印が無く、仕事が終わっていないときだけ。裏の処理が動いているかでは決めない（持ち主 2026-10-24「その裏作業があればじゃなくて。ずっとのほうがいいんじゃないの」）。仕事が終わっていないのは、次のどれかが在る間。
  - 受けた頼みがまだ閉じていない（納品〔`--deliver`〕の前）。
  - その会話が出した頼み（`--ask`）のうち、納品・取り下げ・回して閉じる、のどれもまだ無い物。頼みを受けない窓口も、今の頼みを納品した部署も、これを待つ間は送る。
  - 答え待ちのまま保留にした頼み（`--wait <訳> --park`。[rest.md](rest.md)）。
  - 数える出した頼みは、毎回クリアの部署（`fresh`）が子の返事を待つ間は会話を空にしない、の判定と同じ見分け（その会話が出した物と、今の頼みを受けた後に出した物。頼みを受けない窓口は、前の会話が出して閉じていない物も数える）。保留の頼みを数えるのは、答えをその会話で返すので、保留の間は会話を空にしないから。
- 会話を空にした・止めた・ほかのアカウントへ移した（`--move`）ときは、待ち受けが替わるか止まるので送らない。送る時刻（部品の `next_at` か、ターンの終わりから `every` 秒）まで、会話の記録（transcript）にターンの行（人の文・知らせ・ツールの結果か答え）が足されなければ 1 本送る。足されたら会話が動いたので、その待ちでは送らない。herdr の窓の会話の状態は見ない（裏の処理が動く間は、ターンを終えていても「作業中」と出るため）。頼みと納品の知らせが来ればそちらを先に渡す。部品が答えれば、送るか止めるかは部品の `action` で決める（上の項）。部品が答えないときは、同じ会話が同じ物（動いている裏の処理と、上の頼みの並び。台帳の行の `tasks` に、裏の処理は id、受けた頼みは `ask:<受付>`、出した頼みは `child:<受付>`、保留の頼みは `parked:<受付>` で出る。どれかが替われば数え直す）を待つ間に続けて送るのは、送る費用の合計がキャッシュの書き直し 1 回分に着くまで（`ceil(書く倍率 / 読む倍率)`。読む倍率は会話の記録の最後に答えたモデルで決める。Opus 5.5・Sonnet 5.5 なら 5 分で 25 本・1 時間で 40 本、0.1 倍のモデルなら 13 本・20 本）で、その先は送らない（待ちがどれだけ続くか分からないので、書き直しを恐れて送り続けて損を広げない。持ち主が寝ていて答えが朝になる保留の頼みも、この上限で止まる。1 時間の寿命の Opus 5.5 なら 40 本で約 39 時間）。送るたびと止めた時に、受付箱の台帳に `kind` が `keepalive` の行を残す（部品が答えた行は、送った費用の合計 `spent` と部品の訳 `reason`、答えない行は上限 `limit` と答えない訳 `fixed` を持つ）。送らなかった時も、訳（「今の頼みを納品し、閉じていない出した頼みも保留の頼みも無い」「頼みを受けておらず、閉じていない出した頼みも保留の頼みも無い」「区切りの印（--rest）が在る」「会社の形の役にも受け持ちにも keepalive が無い」など）を `status` が `skipped` の行の `detail` に残す。残すのは、keepalive を書いた部署か窓口が、裏の処理か、閉じていない受けた頼み・出した頼み・保留の頼みを残してターンを終えた（印などで送らなかった）時と、keepalive を書いていない部署が、納品していない頼みを受けて裏の処理を待ってターンを終えた時。裏の処理の知らせなどで会話が動いて送らなかった時は、送らなくてよい形なので残さない。送る時刻には、裏の処理の有無によらず、先に compact するかを部品に聞き、compact するなら keepalive の代わりにする（compact の要求がキャッシュを読むので。送る時刻を待たずに、ターンの終わりにも聞く。書き方は [rest.md](rest.md) の「compact の区切り」の後の「keepalive の時刻の compact」）。仕組みと、keepalive のターンが知らせのターンと重ならない訳は受付の設計（docs/specs/2026-10-17-reception-design.md）の 3.4。

## 永続と毎回クリア（persistent・fresh）

- `persistent = true` の役は、`--persistent` を付けなくても永続の部署で立つ（役で宛てた `--ask 会社/役` で付け忘れても、次に同じ役で頼めば同じ部署に届く）。
- `fresh = true` の役は、頼みごとに空の会話で受ける。`persistent` とは別の軸で、永続の席（順番を 1 本にする・宛先の名前・決まった窓）は残したまま、前の頼みの記憶を引き継がない（記憶は太るうえ、覚えた中身でファイルを書き直すと、ほかの部署がメインブランチに入れたばかりの行を消す）。
- 会話を空にするのは待ち受けで、納品して止まった時点で部署の窓に `/clear` を打つ。空にできないときは、訳で扱いが分かれる。
  - 会話が動いている・入力フィールドに字が在る・その会話の窓を herdr で確かめられない、のどれかなら、前の会話のまま次の頼みを渡さず、5 秒ごとに試し直す（訳は台帳に `held` の行で残る）。
  - この会話が `--ask` でほかへ出した頼み（子の頼み）の返事を待っている・会話が裏で走らせた処理が残っている、のどちらかなら、順番待ちを止めずに前の会話のまま次の頼みを渡す（訳は渡す字の頭と、台帳の `handed` の行の `kept` に残る）。
- 待ち受けの居ない部署（このフックの無い古い版の会話）は、前の頼みを納品し終えて会話が止まっているときだけ、`--ask` が頼みの前に `/clear` を打って空にする（細部は下の「部署の属性」の終わりの文書）。
- 会話を引き継ぐ部署と本社の窓口も、会話が区切りで `--rest` を打てば、そのターンの終わりに同じく空にする（「待つ・区切る」の「区切り」）。
- `fresh` の部署の model・effort:
  - `/clear` は、起動したときの `--model`・`--effort` を残す。
  - そこで待ち受けは、次の頼みを渡す前に、会社の形の今の値を `company.launched` と比べ、違えば `--move <部署> --if-changed` で起動し直す（`company.launched` の無い前の版の部署は `--model`・`--effort` なしで起動したと見る。`inherit` は字のまま比べる。move.md の「会社の形の起動の設定が替わったとき（自動）」）。持ち主が打つコマンドは無い。会社の形がリポジトリの `.claude/company.toml` なら origin の既定のブランチに入れた後、設定の置き場の `companies/` の物なら書き替えた後の、次の頼みから効く。
  - 会話の中で `/model` を打つ形は採らない。引数で打つ `/model` は、そのアカウントの新しい会話の既定として保存され、持ち主の会話の既定まで替わるため。
- 部署には役の `fresh` を属性 `company.fresh` に写す（`--task`・`--ask`・`--reorg --role`・`--sync` のとき）。会社の形の `fresh` を変えたら、ターンの終わりのフックが全部の部署の属性と herdr の表示に行き渡らせる（reorg.md の「herdr の表示を付け直す」）。
- `--init-company` の下書きの既定は、担当が永続・毎回クリア、作業がエフェメラル、相談が永続・引き継ぎ。

## 役の名前と既定の役

- 役の名前を替えるときは、今の名前の項目に `former_names = ["<前の名前>"]` と書く（Terraform の `moved` と同じく、替え方を会社の形に書いて属性を手で直さない）。前の名前で宛てた `--ask 会社/前の名前` と `--call` は今の役に当たり、属性 `company.role` に前の名前を持つ場所は今の役の本文を受け、会話の始まりとターンの頭のフックと `--sync` が属性を今の名前に書き直す。今の役の名前や、2 つ以上の役の前の名前と重なる前の名前は、注記に出して引かない。部署の受け持ちを別の部署へ移すのは reorg.md の `--handover`。
- `--role` で名指した役が会社の形に無ければ、部署を立てずに止まる（書き損じで設定が黙って効かないのを防ぐ）。`--role` を省いたときは `default_role`、無ければ `作業`。`default_role` が `[[roles]]` に無い名前なら注記を出して `作業` に代え、それも会社の形に無ければ止まる（役を英語で書いた会社で、どの役でもない `作業` の部署を立てない）。会社の形を読めない（TOML が壊れているなど）ときも、`--role` を省いた頼みは止まる。

## 部署の属性

- 部署の会話が `/clear`・compact・`--resume` で会話の id を替えても、フックが属性 `company.session` を書き直す（窓口は `/clear` の後に `--desk` を打ち直さなくてよい）。
- 部署の会話が裏の処理（`run_in_background` の Bash・裏のサブエージェント・Monitor。`--land` など）の終わりを待つ間、herdr の状態は done になる。待っている印（会話の画面の下の「⧖ バックグラウンド作業中 N 本」と、herdr に作業中と見分けさせる印）は tiers の statusline（`tiers-statusline setup` でアカウントごとに入れる。tiers の README の「Status line」）が出す。待っている間、このプラグインの Stop のフックは、納品していない頼みを差し戻さない（処理が終わると Claude Code が会話を再開させる）。
- 部署が自分の作業場から `git worktree add` で切った一時の worktree には、git が部署の属性を写す。今の版の属性は書いた worktree の id（`company.worktree-id`）を持つので、id の違う worktree では属性を無いと読み、部署に見えない。
- `--task` で立てずに手で開いた worktree を部署にするときは、その worktree で次を打つ（値は commit されず、worktree と一緒に消える。代表の clone の窓口は手で書かず `--desk` を打つ）。属性の無い場所は `--reorg` を受けないので、手で書く。

  ```sh
  git config --worktree company.role <役>
  git config --worktree company.name <部署の名前>          # 待ち受けは role と name の在る場所にだけ張る。受け持ちもこの名前で引く
  git config --worktree company.lifecycle persistent       # エフェメラルなら ephemeral
  git config --worktree company.worktree-id "$(basename "$(git rev-parse --absolute-git-dir)")"   # 写しと見分ける
  ```

  代表の clone に `extensions.worktreeConfig = true` が要る（dispatch が一度でも部署を立てた clone には在る）。0.78.0 までの works-dispatch と混ざって動く間は、前の版の属性 `company.residency`（`resident` か `per-task`）も同じ値で書く。`company.residency` が在れば `company.lifecycle` より先に読むので、後で寿命を替えるときは `company.residency` も一緒に書き替える。書いた後に `--sync` を打つと herdr の表示が付く。
- 属性の書き直し・写しの見分け・裏の処理の数え方・フォルダの信頼の見方・`company.job`・`company.config` の細部は works-dispatch の `docs/internals.md`〔直す人向けの文書〕の「部署の属性と会話の見分け」（会社の形の書き手には要らない）。

## gh のアカウント

- gh のアカウントは、dispatch の設定の `[[repos]]` の `gh_user` を先に、無ければ会社の形の `gh_user` を使う（commit した会社の形のアカウントは、ほかの人のものでありうる）。
- dispatch は名前だけを属性 `company.gh-user` に書く。フックがそれを読み、会話の Bash がコマンドごとに `gh auth token --user <名前>` で鍵を取り出して `GH_TOKEN` に入れる（鍵の値はファイルにも画面にも履歴にも残らない）。そのアカウントで gh にログインしていなければ、`GH_TOKEN` に使えない字を入れる（gh はほかのアカウントに落ちずに認証の誤りで止まる）。
- 設定の場所や gh のアカウントを替えて同じブランチの部署を立て直すと、前の回の属性は消してから書く。
- PowerShell のツールには `GH_TOKEN` が入らず、そこで打つ gh はその人の今の gh の設定のアカウントで動く（フックが足す `export GH_TOKEN="$(gh auth token …)"` は `$(…)` で gh を走らせる形で、Claude Code が PowerShell に写すのは値をそのまま読める `export 名前=値` の行だけのため）。
- 鍵を `GH_TOKEN` で gh に渡している人（コンテナや CI の形）は `gh_user` を書かない（`gh auth token --user` は `GH_TOKEN` の鍵を取り出せず、部署を立てるときの確かめで止まる。`--init-company` の下書きは、取り出せないアカウントを書かない）。
