# 自分の番の PR を開く: 引数なし・`--pr`・`--issue`

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。「自分の番を全部開いて」「#1234 を開いて catchup して」「issue #1300 を始めて」と頼まれたときに、会話が読んで、下の「引数」から当たる物を選んで打つ。下の 1〜6 は打った後にスクリプトがすること、「しないこと」はスクリプトが飛ばす場合で、結果は出力に出るのでそのまま見せる。

自分の番の PR を、ブランチごとの作業場で開くところまでを機械でやる。「自分の番の PR」は、attention プラグインの `/whose-turn` が「自分の番」のセクションに並べる PR（直す側に回っている自分の PR と、レビューを待たれている PR）である。

1. PR のブランチごとに作業場を用意する。代表の clone から、そのブランチの git worktree を herdr に作らせ（置き場は herdr の設定の `worktrees.directory`）、herdr の作業場を開く。そのブランチの worktree が既にあれば開き直す。どちらでも、origin の今の head へ fast-forward してから渡す（手元にしか無い commit が有れば動かさない）。代表の clone 自身がそのブランチを開いていれば作らない（`branch_busy`）。
2. アカウントを並べ、順の頭から、使用率が上限（設定の `limit_percent`。既定 95%）に届かない件数まで PR を割り振り、Claude Code を起動する。上限は、週の枠と 5 時間の枠の両方に当てる（どちらかが上限に届いたアカウントは選ばない）。順は、点数（週の枠の上限までの残り ÷ 週の切り替わりまでの時間 × 5 時間の枠の上限までの残りの割合）の高い順、同じなら動いている会話の少ない順。件数は、1 件あたりの使用率（dispatch が毎回の前後で測って覚える）から決める（今の使用率に 1 件ぶんずつ足して、両方の枠で上限に届かない数）。まだ測っていなければ、選べるアカウントに 1 件ずつ順に配る。
3. attention の `/catchup <番号>` を送る。これは、その PR で前回自分が触ってから何が起きたかを出すコマンドである。それが終わったら、dispatch の設定（`dispatch.toml`）の `second_prompt_file` が指すファイルに書いた 2 ターン目の文を送る。2 ターン目の文の後ろには、「前のターン（`/catchup`）で調べた物は引き継いでよい。取り直すのは、その後に変わった物と調べていない物だけ。問う事が違えば調べ直す」という大意の決まった一言を、改行を挟まずに足す。前からある場所で開き直すとき（前の会話を終えて立て直す・持ち主が閉じた後に開く）は、新しい会話を起動する前に、その場所で前に開いた会話のうち報告の在るいちばん新しい物（`/catchup` だけで終えた会話は飛ばす）の報告（`/catchup` の外のターンの最後の答え。GitHub に出していない下書きや発見を含む）を、場所の git の置き場（`<worktree の git の置き場>/works-dispatch/reports/<会話の id>.md`。作業ツリーの外で、worktree を消すと一緒に消える）に残し、その場所を渡す一言も同じく足す。どの会話にも報告が無ければ足さない。
4. 会話が開いている PR は、dispatch が前に送った時（dispatch の控えに残る）の後に相手の新しい返事（コメント・レビュー・commit。Bot は数えない）が有り、会話が手すき（Claude Code の会話の状態が idle）で手元の作業も無ければ、古い会話を終えて herdr の作業場を閉じ（worktree は残す）、同じ worktree に herdr の作業場を開き直し、新しい会話を起動して 3 から送り直す。送り直した会話にも、前の会話の中身を持たない新しい目で PR を見させるためである。
5. 自分の番でなくなった（`/whose-turn` の自分の番から外れた）開いている PR は、引数なしの dispatch が `/catchup` を送って起動した会話が手すき（会話の状態が idle）で手元の作業（未コミットの変更・手元にしか無い commit・stash）も無ければ、会話のペインに `/exit` を打って終え、herdr の作業場を閉じる（worktree とブランチは残す）。自分の番に戻ったときは、4 と同じく新しい会話を起動して上の 3（`/catchup` から）を送り直すので、古い会話は使わない。持ち主が自分で開いた会話・`--pr` か `--issue` で開いた会話・印を書く前の版で開いた会話（dispatch の控え〔`/catchup` を送った PR ごとに、送った時刻と送り方を覚えておく記録 `dispatch-sent.json`〕に、引数なしの回で送った印 `via: listing` が無い会話）には触らない。部署の作業場（`--task` が立てた worktree。worktree の git 設定 `company.role` を持つ。`git config --worktree company.role` で読める）は、引数なしの回の送り直し・閉じた PR の片付けのどれにも使わず、部署の会話は終えない。自分の番の部署のブランチの PR は開かずに報告に 1 行出す（レビューの返しは `--ask <部署> --text <頼み>` で部署へ回す。部署は `--clean`・`--retire` が畳む）。部署のブランチの開いている PR が自分の番から外れたら、部署の会話がどれも手すきか止まっていて、受けた頼みを納品し終え（頼み元へ `--deliver` で結果を返し終え）、順番待ち（部署に届いたがまだ受けていない頼みの列。[ask.md](ask.md) の冒頭の言葉）に頼みが無く、未コミットの変更・手元にしか無い commit・stash も無ければ、部署の herdr の作業場（窓）だけを閉じ、閉じたことを報告に 1 行出す。窓の前の `claude attach` の画面（裏の会話を窓に映している画面）は、先に Ctrl+Z でシェルに戻してから閉じる（attach の画面が前に居るまま閉じない訳は [clean.md](clean.md) の「部署の会話を止める」）。部署の裏の会話・worktree・ブランチは残し、次の `--ask` が作業場を開き直して会話を窓に戻す。窓に attach の画面でない物（エディタ・別の会話など）が居れば閉じない。同じ PR の worktree（ブランチの checkout）の中で会話が 2 つ以上開いているときは、どれにも触らない。whose-turn がその PR の判定の材料を取り切れなかった（whose-turn の `--json` の出力の `limited`〔判定の材料が走査の上限に当たって取り切れなかった PR の番号の並び〕に入った）ときも、自分の番でないという判定が取りこぼしの上に立つので閉じず、報告に残した訳を出す。自分の番の一覧を取れなかったときは dispatch ごと止まるので、何も閉じない。
6. 閉じた（merge・close した）PR のブランチの場所は片付ける（worktree と手元のブランチを消す）。会話が手すきで手元の作業も無ければ、会話を終えてから消す。見るのは代表の clone の worktree だけで、ほかのリポジトリには触らない。PR の無いブランチ（issue から始めてまだ PR を作っていないもの）は消さない。

## 引数

- 引数なし: 自分の番の PR を全部開き（部署のブランチの PR は開かず、報告に 1 行出す。上の 5）、返事の有った PR（dispatch が前に送った後に相手のコメント・レビュー・commit が付いた PR）を送り直し（上の 4）、自分の番でなくなった PR の会話と部署の窓を閉じ（どちらも worktree とブランチは残す。上の 5）、閉じた（merge・close した）PR の作業場を片付ける（worktree と手元のブランチを消す。上の 6）。自分が作者でレビュアーの付いていない PR も開くが、`/catchup` だけを送り、2 ターン目の文は送らない（`--pr` で指したときも同じ）。
- `--dry-run`: 何も起動せず、どの PR をどのアカウント・どの作業場で開くか、どれを送り直すか（`refresh`）、どの会話を閉じるか、どれを片付けるかだけを出す。
- `--pr N`: 指した番号の PR だけを開く。複数なら `--pr` を重ねる。止めている実装や、見に行くだけの PR に使う。レビュアーの有無では外さず、送り直しも片付けもしない。`--pr` で開いた会話は、後の引数なしの回で自分の番でなくても閉じない。
- `--issue N`: issue から始める。issue に結んだブランチ（GitHub の issue の Development のフィールドに出るブランチ。GitHub の GraphQL API で issue の `linkedBranches` を `gh api graphql` で読む）の作業場（ブランチごとの git worktree）を開き、1 ターン目の `/catchup N`（N は issue の番号。`/catchup` は issue の番号も受ける）まで送って止める（2 ターン目のレビューの文は送らない）。ブランチが見えなければ、issue の Development のフィールドに出る開いた PR（merge するとその issue が閉じる PR）のブランチを使い、それも無ければ既定のブランチから GitHub にブランチを作って issue に結ぶ（ブランチを作って issue に結ぶ gh のコマンド `gh issue develop` を使う。GitHub に書く）。閉じた issue ならブランチを作らずに止め、出力に止めた訳 `issue_closed` を出す。`--pr` とは一緒に使えない。送り直しも片付けもしない。
- `--no-second`: `/catchup` だけで止め、2 ターン目の文を送らない。

## しないこと

- 作業中の会話・未コミットの変更や push していない commit の有る会話は、送り直しにも、自分の番でない PR の会話を閉じるのにも、片付けにも使わない（送り直しでは `busy`・`dirty`・`unpushed`、ほかは報告の頭の注記に出る）。相手の新しい返事が無い会話もそのまま（`no_news`）。前に送った後に相手の動き（コメント・レビュー・commit・head の変化）が無い PR は、会話を閉じてあっても開き直さない（`no_news`。`--pr N` で名指せば開く）。PR の作業場の外で同じブランチの会話が開いていれば、その PR は飛ばす（`already_open`）。
- シェルではない物（エディタ・dev server・別の会話）が前に居るペインには打ち込まない（`pane_busy`）。起動した Claude Code が信頼やログインの確認の画面で止まったら、`/catchup` を送らずに `blocked` と報告する。
- 依存（`.venv`・`node_modules`）は入れない。試験を走らせる段になってから、その会話の中で入れる。
- 起動した会話の `/catchup` のページ（`/catchup` が書く HTML のファイル）を、会話ごとには VS Code の窓に開かない（起動するコマンドの前に `ATTENTION_CATCHUP_OPEN=0` を置く）。全件を送り終えた後に、送った PR のページをまとめて、生きている VS Code の窓にタブで開く（`ATTENTION_CATCHUP_OPEN=0` で dispatch を走らせれば開かない。窓が無ければページの path を報告に出す）。
