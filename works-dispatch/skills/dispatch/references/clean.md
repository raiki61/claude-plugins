# 片付ける・止める・畳む: `--clean`・`--done`・`--retire`

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。部署や作業場を片付ける・部署の会話を止める・エフェメラルの部署を終える・畳むと頼まれたときに、頼まれた会話（このファイルを読んでいる自分。窓口でも部署でもよい）が読んでから下のコマンドを打つ。急ぎの操作ではなく、読んで手順に従えばよい。ここでの言葉:

- 会社: 部署を立てる元のリポジトリ。代表の clone は、その会社の元の clone（本社とも呼ぶ）で、部署の worktree はここから作る。
- 部署: 作業ごとの git worktree 1 つと、そこで働く Claude Code の裏の会話 1 つの組。エフェメラルの部署は一度の頼みのために立てて終われば畳む部署、永続の部署（`--persistent` で立てる）は頼みごとにブランチを移って残り続ける部署。
- herdr: 端末の画面を作業場とペインに分けて Claude Code の会話を並べるツール。部署の窓は、部署の会話を映した herdr のペイン（窓には `claude attach` の画面が開く）。
- 窓口: 本社で持ち主と話し、部署に仕事を配る会話。受付箱は、頼みと納品の記録を置く代表の clone の `.git/company/inbox/`。
- ターン: 会話の 1 回の応答。待ち受けは、ターンの終わりにこのプラグインのフックが裏で起動し、受付箱の台帳を見て会話を再開させる処理。
- コマンド: `--clean` などは dispatch のスクリプトの引数。ここに出るほかの引数の `--ask`（部署に頼みを送る）・`--task`（部署を立てる）・`--tree`（会社と部署の一覧を出す）・`--land`（部署のブランチをメインブランチに入れる）・`--rest`（会話を空にしてよい区切りを印す）は、それぞれの別ファイルで説明する。

- `--clean`: 代表の clone の worktree のうち、消してよい場所を並べる。部署や一時の worktree が残っていると思ったら、まず `--clean` を打って並びと訳を読み、「消せる」と出た物は `--clean --apply` で消し、「残す」と出た物は訳に添えた手（`--land`・`--retire`・手で消す手順など）を打つ。会社（代表の clone）は部署を立てるコマンド（`--task` など）と同じに、`--repo`（設定の `[[repos]]` の名前か代表の clone のパス）か打った場所で決まる。下の箇条は、何を「消せる」「残す」と並べるかの決まりと、消すときにすること。
  - `--clean --apply` で本当に消す（worktree と手元のブランチを消す。herdr に `--force` を付けずに消させるので、並べた後に変更が出来ていれば herdr が断り、何も消えない）。
  - PR の作業場: 消してよいのは、ブランチの PR が閉じていて、会話が無く、未コミットの変更・git に足していない新しいファイル（`git status` に出るもの）・そのブランチの stash が無く、手元のブランチの先頭が PR の head と同じか、その祖先（origin のブランチより遅れているだけで、手元にしか無い commit が無い）のものだけ。設定の `copy_files`（git が追わない手元だけのファイルの一覧。新しく作った worktree へ、`copy_from`〔省けば代表の clone〕から写す）のうち写し元と中身が違うファイルが有る場所も残し、そのファイルを出す。`.gitignore` に当たるファイル（依存・生成物など）は数えず、場所と一緒に捨てる。設定のファイルが無くても動き、設定の `[[repos]]`（PR を開く回に使うリポジトリの一覧）に無い会社では、部署だけを並べて片付け、部署でない worktree（PR を開く回が PR ごとに開いた作業場など）は並べも消しもしない（PR が閉じたかを GitHub に問うのは、`[[repos]]` のリポジトリだけのため）。
  - エフェメラルの部署: 部署（`--task` が立てた worktree）は PR を見ずに別に並べ、エフェメラルの部署で、会話が終わり（または会話がもう無く）、未コミットの変更・手元にしか無い commit・stash が無く、ブランチの先頭が origin の既定のブランチに入っているものだけを「消せる」と並べる。会話がまだ動いているエフェメラルの部署は消さずに残し、残す訳を一緒に出す。前に終わりの印（`--done`）をきっかけに畳もうとして畳めなかった部署には、その時に畳めなかった訳を出す。
  - 頼みを納品済みの部署の形: 今の形を次の 4 つのうち、前から見て最初に当たる物で出す。
    1. この部署が頼んだ返事（頼んだ先の納品）がまだ来ていない（受付番号を出す。この部署の納品の残った疑問の担当者に書いた受付は数えない）。
    2. ブランチがメインブランチに入っておらず、入れる手を預けた先の答えがまだ出ていない（受付番号を出す）。入れるのを預けた物（`--land` が止められて入れるのを頼んだ・メインブランチの CI の赤の直しを頼んだなど）なら、その答えを待つ。そうでなければ、答えを待たずに `--land <部署>` で入れてよい。出た受付番号を `--todo <受付番号>` に渡し、出た頼みの題で用件を確かめる（預けた先は、入れる件と関係の無い頼みでも数える。台帳の行には用件が無く、機械では見分けられないからである。見分けるのは読む人）。
    3. ブランチがメインブランチに入っていない（上の 2 つに当たらない、つまり待っている返事も答えも無いのに入っていない。入れ損ねたか、預けた先の答えは出たのにまだ誰も入れていない。消すと成果を失うので `--land <部署>` で入れる）。
    4. どれでもなく終わりの印が無い（止めて畳むなら `--retire <部署>`）。
    - 2 の「預けた先」と「答えがまだ出ていない」の決め方: 預けた先とは、この部署が今の頼みを受けてから `--ask` で出した頼みのこと。答えがまだ出ていないかは、預けた先の頼みから始めて、頼みを 1 件ずつ見て決める。見ている頼みがまだ納品も取り下げもされていなければ、答えはまだ出ていない。納品されたか、ほかの部署へ回して閉じられていれば、次の 2 種類の頼みを両方とも、同じ決まりで続けて見る。1 つ目は、見ている頼みの納品の要約の残った疑問（要約の頭書き〔1 行目と閉じの行が `+++` の TOML〕の `[[open]]` に 1 件ずつ書く）の担当者（`holder`。その疑問を最後まで追う者）に受付番号で書かれた頼み（担当者がまだ閉じていないリマインダー〔`--remind`〕の受付番号なら、答えはまだ出ていない）。2 つ目は、見ている頼みを受けた部署が、それをほかの部署へ回した頼み。見ている頼みを受けた部署が途中で出した別の頼み（子の頼み）は見ない。見る頼みが尽きるまで、まだ納品も取り下げもされていない頼みに当たらなければ、答えは出ている。例: 入れるのをほかの部署に頼み、その納品の残った疑問の担当者に持ち主の答え待ちの頼みが書かれて返ってきたら、その持ち主の答え待ちの頼みが閉じるまで、部署はこの形で出る。`--todo` で追える。
  - 永続の部署（`--persistent`）は消さない。永続の部署は頼みごとにブランチを移るので、前の頼みでメインブランチに入れ終えたブランチが手元に残る。`--land` は入れたブランチの名前と入れた時の先頭の commit を属性 `company.landed-branches` に書いておき、`--clean` はそのブランチを、どの worktree も開いていなくなり、先頭がまだ入れた時と同じなら消す（入れた後に commit を積んだブランチは消さず、記録から外す）。
  - ツールの一時の場所: 機械のツール（AI の会話を起動せずに決まった台本で頼みを片づける `--call` のツール。これを走らせる役を「機械窓口」と呼ぶ）を走らせた一時の worktree も「ツールの一時の場所」の行で並べ、作った処理がもう居ない物を `--apply` で消す。
  - 消す順と一時の置き場の写し: 部署を消すときは、先に `claude rm` で会話を消してから場所と窓と手元のブランチを消す。`claude rm` は会話の一時の置き場（`<設定のフォルダ>/jobs/<短い id>/tmp`。設定のフォルダはその会話のアカウントの Claude Code の設定のフォルダで、`CLAUDE_CONFIG_DIR` の値。既定は `~/.claude`）も消すので、中に物が在れば先に代表の clone の `.git/company/kept-tmp/<短い id>/` に写す（写せなければ消さない）。
  - graphloops の盤面を写す: 部署でも PR の作業場でも、worktree の git の置き場（`.git/worktrees/<名前>/`。`<名前>` は git が worktree ごとに作る管理用のフォルダの名前）に graphloops（このリポジトリの別のプラグイン）の run の記録（費用・読んだ記録・判定。盤面と呼ぶ。`graphloops/`）が在れば、消す前に代表の clone の `.git/graphloops/boards-archive/<名前>/graphloops/` に写し、`--apply` を付けない `--clean` は「消せる」の行に写す先を添える（graphloops の `init`・`status` が出す先と同じで、graphloops の `tests/replay_boards.py` と `scripts/quality-ledger.py` が読む。写せなければ何も消さず、部署は `claude rm` より前に写すので会話も残る）。写しの量には上限を置く。works-dispatch は自分が作った写しの `<名前>/` に印のファイル `.works-dispatch-archived`（写しの大きさを書く）を置き、写すたびに、印の有る写しの合計が 2 GiB 以下になるまで、古く写した物から消す。上限を超えた分のほかは消さない（日数では消さない）。同じ名前の写しが印無しで既に在れば（手で写した物）、その中に写すが印は付けず、自動では消さない。消し終えても合計が上限を超えたままなら `--tree` が注記に出す。
- **部署の会話を止める**: 先に部署の窓で Ctrl+Z を押して attach の画面を終わらせ（Ctrl+C では終わらない。Ctrl+Z の後にシェルでなく会話の一覧の画面〔`claude agents`〕が出たら、そこで Esc を押すとシェルに戻る）、それから `claude stop <短い id>` を打つ。短い id は `--tree` の部署の行か `claude agents` に出る。止めたままにしたいなら、`claude stop` の 1 分ほど後に `claude agents` で `stopped` のままかを見る。片付けるなら `--clean --apply`（エフェメラルの部署）。
  - ペインを閉じても attach は終わるが、そのときは部署の作業場も herdr から閉じてしまう（次の `--ask` が作業場を開き直してから戻す）。
  - 経緯: 部署の窓に attach の画面が開いていると、`claude stop <短い id>` で止めても、窓の attach が会話を再開させる（「Waking session …」。macOS で見た）。Ctrl+Z で終わるのは `claude attach --help` の「Ctrl+Z drops back to your shell」。Claude Code 2.1.302 では、Ctrl+Z の後にシェルでなく会話の一覧の画面が出る。dispatch が窓をシェルに戻すときも、シェルが戻らなければ Esc を足す（macOS と Linux で確かめた）。`claude stop` で止めた会話は、手元で確かめた限り（Claude Code 2.1.301 の macOS と Linux。Linux では裏の処理を起動し直した後も）止まったままだった。まっさらな環境での試しでは約 1 分後に起き直って頼みを済ませた例があり、何が会話を再開させたかは分かっていない（dispatch の止まる前のフックは `claude stop` では走らないことを確かめた）。
- **終わり（`--done`）と畳む（`--retire <部署>`）**: エフェメラルの部署は、納品してメインブランチに入れ終えたら、自分で `--done` を打って終わりを印す。そのターンの終わりに待ち受けが部署を畳む。印を打たずに残った部屋は、本社の窓口の会話が `--retire <部署>`（部署の名前か `<会社/部署>`）で畳む。
  - `--done` がすること: 部署の属性 `company.finished` に、その場所の会話の id〔部署の属性 `company.session` の値〕を書く。断るのは、部署でない・窓口・永続の部署（区切りなら `--rest`）・部署の属性 `company.session`（会話の id。部署の会話を起動したときに書く）が無い・納品していない頼みか順番待ちの頼みが在る・この部署が頼んで返事（頼んだ先の納品）の来ていない頼みが在る（この部署の納品〔前の頼みの納品と `--again` で返し直した分も〕で、残った疑問〔要約の頭書きの `[[open]]`〕の担当者〔`holder`〕に受付番号で書いた頼みは数えない。返事は部署が畳まれても受付箱に届き、`--todo` がその受付で追う。書き忘れたなら `--deliver --again` で担当者に書いて返し直してから打ち直す）・未コミットの変更か git に足していないファイルが在る・手元にしか無い commit か stash が在る・ブランチがメインブランチ（origin の既定のブランチの手元の控え）に入っていない（commit の無い部署は入っているとみなす。ほかの会話が入れたなら `git fetch` してから打ち直す）とき。人がその会話の入力フィールドに文を打って送ると、終わりの印が外れる（人と話している途中の会話を畳まないため）。
  - 印の後に起きること: エフェメラルの部署の会話が `--done` を打ったそのターンの終わりに、待ち受け（このプラグインのフック `dispatch/wake_hook.py`。部署の会話のターンの終わりに裏で動き、頼みと納品の知らせを待つ処理）が終わりの印（`company.finished`）を外し、`--retire <会社/部署>` を会話から切り離して裏で走らせる（出力は受付箱の `retires/`）。その部署の順番待ちに頼みが在れば、待ち受けは部署を畳まずにその頼みを部署に渡し、終わりの印を外す（部署はその頼みを済ませてから `--done` を打ち直す）。
  - `--retire` がすること: 止める前に `--clean` の部署の決まりで会話のほかに残す訳が無いか（と、納品していない頼みも順番待ちの頼みも無いか）を確かめ、窓の attach の画面をシェルに戻してから `claude stop` で会話を止め、`--clean --apply` と同じ部品で部屋（作業場・worktree・会話・手元のブランチ）を消す。止められなかった・消せなかったときは部屋を残し、訳を属性 `company.retire-kept` に書く（`--clean` の一覧の「残す」の訳に出る。次の `--done` で消える）。`--retire` を自動で打ち直しはしない。片付けたか残したかは受付箱の台帳に `retired` の行で残す。
  - 印を打たずに残った部屋: 印を打たずに残らないよう、止まる前のフックが、納品し終えてブランチもメインブランチに入ったエフェメラルの部署に `--done` を打つよう差し戻す（`references/rest.md`〔待つ・区切る〕の「止める前の差し戻し」。部署の会話が止まろうとしたとき、このプラグインの Stop のフックが、止まらずに `--done` を打つよう会話に返す）。それでも印を打たずに残った部屋は、`--clean` の一覧が「頼みは納品済みで、終わりの印が無い」などと訳を添えて並べるので、止めるかは本社の窓口の会話（会社の形〔`.claude/company.toml`〕で窓口に当てた役の会話。my_notes の会社では、この役の名前が「段取り」）が決めて `--retire <部署>` を打つ。
  - 経緯: エフェメラルの部署は、納品してメインブランチに入れ終えた後も会話が生きたまま残り、`--clean` は「会話がまだ動いている」と見て残す。終わったかを機械は推し量らず、部署が自分で印す。いつ `--done` を打つか（例: 納品してメインブランチに入れ終えたら）は、各会社の形のエフェメラルの部署の役の本文に書き、このプラグインでは決めない。
