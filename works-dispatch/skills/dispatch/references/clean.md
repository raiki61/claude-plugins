# 片付ける・止める・畳む: `--clean`・`--done`・`--retire`

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。部署や作業場を片付ける・部署の会話を止める・都度の部署を終える・畳むと頼まれたときに、会話が読んでから下の命令を打つ。急ぎの操作ではなく、読んで手順に従えばよい。ここでの言葉:

- 会社: 部署を立てる元のリポジトリ。代表の clone は、その会社の元の clone（本社とも呼ぶ）で、部署の worktree はここから作る。
- 部署: 作業ごとの git worktree 1 つと、そこで働く Claude Code の裏の会話 1 つの組。都度の部署は一度の頼みのために立てて終われば畳む部署、常設の部署（`--resident` で立てる）は頼みごとに枝を移って残り続ける部署。
- herdr: 端末の画面を作業場とペインに分けて Claude Code の会話を並べる道具。部署の窓は、部署の会話を映した herdr のペイン（窓には `claude attach` の画面が開く）。
- 窓口: 本社で持ち主と話し、部署に仕事を配る会話。受付箱は、頼みと納品の記録を置く代表の clone の `.git/company/inbox/`。
- 番: 会話の 1 回の応答。待ち受けは、番の終わりにこのプラグインのフックが裏で起こし、受付箱の台帳を見て会話を起こす処理。
- 命令: `--clean` などは dispatch のスクリプトの引数。ここに出るほかの引数の `--ask`（部署に頼みを送る）・`--task`（部署を立てる）・`--tree`（会社と部署の一覧を出す）・`--land`（部署の枝を本流に入れる）・`--rest`（会話を空にしてよい区切りを印す）は、それぞれの別ファイルで説明する。

- `--clean`: 代表の clone の worktree のうち、消してよい場所を並べる。部署や一時の worktree が残っていると思ったら、まず `--clean` を打って並びと訳を読み、「消せる」と出た物は `--clean --apply` で消し、「残す」と出た物は訳に添えた手（`--land`・`--retire`・手で消す手順など）を打つ。消してよいのは、枝の PR が閉じていて、会話が無く、未コミットの変更・git に足していない新しいファイル（`git status` に出るもの）・その枝の stash が無く、手元の枝の先頭が PR の head と同じものだけ。設定の `copy_files`（git が追わない手元だけのファイルの一覧。新しく作った worktree へ、`copy_from`〔省けば代表の clone〕から写す）のうち写し元と中身が違うファイルが有る場所も残し、そのファイルを出す。`.gitignore` に当たるファイル（依存・生成物など）は数えず、場所と一緒に捨てる。`--clean --apply` で本当に消す（worktree と手元の枝を消す。herdr に `--force` を付けずに消させるので、並べた後に変更が出来ていれば herdr が断り、何も消えない）。部署（`--task` が立てた worktree）は PR を見ずに別に並べ、都度の部署で、会話が終わり（または会話がもう無く）、未コミットの変更・手元にしか無い commit・stash が無く、枝の先頭が origin の既定の枝に入っているものだけを「消せる」と並べる。消すときは、先に `claude rm` で会話を消してから場所と窓と手元の枝を消す。`claude rm` は会話の一時の置き場（`<設定のフォルダ>/jobs/<短い id>/tmp`）も消すので、中に物が在れば先に代表の clone の `.git/company/kept-tmp/<短い id>/` に写す（写せなければ消さない）。会話がまだ動いている都度の部署は消さずに残し、残す訳を一緒に出す。前に終わりの印（`--done`）をきっかけに畳もうとして畳めなかった部署には、その時に畳めなかった訳を出す。頼みを納品済みの部署には、今の形を次の 3 つのどれかで出す: この部署が頼んだ返事を待っている（受付番号を出す）・枝が本流に入っていない（入れ損ねか、入れる手を待っている。消すと成果を失うので `--land <部署>` で入れる）・どちらでもなく終わりの印が無い（止めて畳むなら `--retire <部署>`）。機械の道具を走らせた一時の worktree（「機械窓口」）も「道具の一時の場所」の行で並べ、作った処理がもう居ない物を `--apply` で消す。常設の部署（`--resident`）は消さない。常設の部署は頼みごとに枝を移るので、前の頼みで本流に入れ終えた枝が手元に残る。`--land` は入れた枝の名前と入れた時の先頭の commit を属性 `company.landed-branches` に書いておき、`--clean` はその枝を、どの worktree も開いていなくなり、先頭がまだ入れた時と同じなら消す（入れた後に commit を積んだ枝は消さず、記録から外す）。会社（代表の clone）は部署を立てる命令（`--task` など）と同じに、`--repo`（設定の `[[repos]]` の名前か代表の clone のパス）か打った場所で決まる。設定のファイルが無くても動き、設定の `[[repos]]` に無い会社では、PR の作業場は見ずに（GitHub に問わずに）部署だけを片付ける。
- **部署の会話を止める**: 部署の窓に attach の画面が開いていると、`claude stop <短い id>` で止めても、窓の attach が会話を起こし直す（「Waking session …」。macOS で見た）。止めるなら、先に部署の窓で Ctrl+Z を押して attach の画面を終わらせ（`claude attach --help` の「Ctrl+Z drops back to your shell」。Ctrl-C では終わらない。Claude Code 2.1.302 では、Ctrl+Z の後にシェルでなく会話の一覧の画面〔`claude agents`〕が出るので、そこで Esc を押すとシェルに戻る。dispatch が窓をシェルに戻すときも、シェルが戻らなければ Esc を足す。macOS と Linux で確かめた）、それから `claude stop <短い id>` を打つ。ペインを閉じても attach は終わるが、部署の作業場も herdr から閉じる（次の `--ask` が作業場を開き直してから戻す）。短い id は `--tree` の部署の行か `claude agents` に出る。片付けるなら `--clean --apply`（都度の部署）。`claude stop` で止めた会話は、手元で確かめた限り（Claude Code 2.1.301 の macOS と Linux。Linux では裏の処理を起こし直した後も）止まったままだった。まっさらな環境での試しでは約 1 分後に起き直って頼みを済ませた例があり、何が起こしたかは分かっていない（dispatch の止まる前のフックは `claude stop` では走らないことを確かめた）。止めたままにしたいなら、`claude stop` の 1 分ほど後に `claude agents` で `stopped` のままかを見る。
- **終わり（`--done`）と畳む（`--retire <部署>`）**: 都度の部署は、納品して本流に入れ終えた後も会話が生きたまま残り、`--clean` は「会話がまだ動いている」と見て残す。終わったかを機械は推し量らず、都度の部署が自分で `--done` を打って印す（部署の属性 `company.finished` に、その場所の会話の id を書く）。断るのは、部署でない・窓口・常設の部署（区切りなら `--rest`）・属性に会話の id が無い・納品していない頼みか順番待ちの頼みが在る・未コミットの変更か git に足していないファイルが在る・手元にしか無い commit か stash が在る・枝が本流（origin の既定の枝の手元の控え）に入っていない（commit の無い部署は入っているとみなす。ほかの会話が入れたなら `git fetch` してから打ち直す）とき。その番の終わりに待ち受け（このプラグインのフック `dispatch/wake_hook.py`。部署の会話の番の終わりに裏で動き、頼みと納品の知らせを待つ処理）が印を外し、`--retire <会社/部署>` を会話から切り離して裏で走らせる（出力は受付箱の `retires/`）。その部署の順番待ちに頼みが在れば、待ち受けは部署を畳まずにその頼みを部署に渡し、印を外す（部署はその頼みを済ませてから印し直す）。`--retire` は、止める前に `--clean` の部署の決まりで会話のほかに残す訳が無いか（と、納品していない頼みも順番待ちの頼みも無いか）を確かめ、窓の attach の画面をシェルに戻してから `claude stop` で会話を止め、`--clean --apply` と同じ部品で部屋（作業場・worktree・会話・手元の枝）を消す。止められなかった・消せなかったときは部屋を残し、訳を属性 `company.retire-kept` に書く（`--clean` の一覧の「残す」の訳に出る。次の `--done` で消える）。打ち直しはしない。片付けたか残したかは受付箱の台帳に `retired` の行で残す。印を打たずに残らないよう、止まる前のフックが、納品し終えて枝も本流に入った都度の部署に `--done` を打つよう差し戻す（`references/deliver.md`〔納品する〕の「止める前の差し戻し」。部署の会話が止まろうとしたとき、このプラグインの Stop のフックが、止まらずに `--done` を打つよう会話に返す）。それでも印を打たずに残った部屋は、`--clean` の一覧が「頼みは納品済みで、終わりの印が無い」などと訳を添えて並べるので、止めるかは段取り（会社の形〔`.claude/company.toml`〕の役で、本社の窓口の会話。my_notes の会社の窓口の名前）が決めて `--retire <部署>` を打つ。いつ `--done` を打つか（例: 納品して本流に入れ終えたら）は、各会社の形の都度の部署の役の本文に書き、このプラグインでは決めない。人がその会話に打つと印が外れる。
