# 機械窓口: `--call` と合図

dispatch のスキル（works-dispatch のプラグイン）の別ファイルで、スキルを動かす Claude Code の会話が、書く前・打つ前に読む。急ぎの操作ではない。機械窓口は、頼みを AI の会話でなくスクリプト（ここでのツール）が受けて、成功か失敗かを返す仕組み。合図は、メインブランチに入れた後などの出来事をきっかけにツールを呼ぶこと。ツールは、会社（部署を立てる元のリポジトリ）の設定ファイルである会社の形（`.claude/company.toml`）に下の TOML の形で書いて足す。そのツールを呼ぶよう頼まれたら、下の `--call` のコマンドを打つ。下に出る `--ask` は、部署に頼みを送るコマンド（[ask.md](ask.md)）。

役ごとに、AI を起動せずに機械で答えるツールを会社の形に書ける。どの会社にどんなツールを置くか（ツールの台本そのものも）は会社の形とそのリポジトリが決め、works-dispatch は呼ぶ仕組みだけを持つ。機械窓口を付けてよいのは、**成功と失敗を機械で決められる仕事だけ**（ツールは片づいたら終了の値 0、片づかなかったら 0 以外を返す）。

```toml
[[roles]]
name = "配布"
machine = true                       # AI の部署を持たない役（--ask で宛てられない）

[[roles.tools]]
name = "spread-plugins"              # 以下 4 つは MCP のツールの定義（Tool）のフィールドに合わせる
title = "全アカウントに配る"
description = "…"
inputSchema = { type = "object", properties = { dry_run = { type = "boolean" } }, additionalProperties = false }
command = "python3 scripts/spread-plugins.py"   # origin の既定のブランチの中身（一時の worktree）のルートで走らせる。入力の JSON を標準入力に渡す
fallback_role = "作業"               # 片づかなかったときに回す役か受け持ちの名前（--ask 会社/<名前> と同じ宛て方。省けばそのツールを持つ役。machine の役では要る）
```

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --call <会社/役> <ツールの名前> [--input <JSON の字か @ファイル>] [--dry-run]
```

- **呼ばれて動くツール**（`--call`）: 頼まれた会話は上のコマンドを打ち、終わったときの値（0・3・1）を見て次の手を決める。ツールが片づけば答えを出して 0 で終わる。片づかなければ、外れ（`kind: "miss"`）を受付箱の台帳に残し、その入力を AI への頼みに変えて、回す役（上の TOML のツールの `fallback_role` に書いた役か受け持ち。省けばツールを持つ役）に回し、受付番号を出して 3 で終わる（この頼みの頼み元は、`--call` を打った会話。待つか、自分で進めるかはその会話が選ぶ）。回す先の部署の選び方は `--ask` と同じで、回す役の always の部署（頼みを終えても畳まず、次の頼みも受ける部署）が在ればその順番待ちに積み、無ければ一度きりの部署を自動で立てる（名前は「<ツールを持つ役>：<ツールの title>」、ブランチは `work/<ツールの name>-<受付番号の末尾 6 字>`）。外れの行には、回した頼みの受付番号を `ask` として書いておく。ただし、`--call` を打った部署がいま受けていて、まだ納品していない頼みが、同じツールの同じ入力（JSON の値で比べ、鍵の順は見ない）の外れの行の `ask` なら、それはその頼みの中での打ち直しなので、同じ頼みをもう 1 つ積まないよう回さない。このときは外れの行に `rerun_of`（受けている頼みの受付番号）を書き、ツールの標準出力と標準エラーの終わりの 20 行を出して、終了の値 1 で終わる。打ち直しのときに限り、片づかなかった仕事はほかの部署へ回らず、その頼みを受けている、打った部署がそのまま続けて進める（打ち直しでない外れは、上のとおり回す役の部署へ回る）。ツールを走らせる一時の worktree を作れない（残ったパス・index.lock など）ときは、ツールは走っていないので外れとは数えず、ほかの部署へも回さない。台帳に `kind: "call"`・`status: "failed"` の行（`why` に訳）を残し、終了の値 1 で終わる。入力の `dry_run` が `true` の呼び（空打ち）も、片づかなければ回さず、外れとも数えずに、ツールの出力を出して 1 で終わる。入力は、物であること・`required`・`additionalProperties = false`・各鍵の `type` だけを確かめる。
- **合図で動くツール**: 出来事のフィールドに書いておくと、その出来事の後に呼ぶ。最初の出来事はメインブランチに入れた後（`[[land.after]]`。「メインブランチに入れる」）。2 つ目は部署を新しく立てた後（`[[task.after]]`。形は `[[land.after]]` と同じ）で、`--task`（`--ask` が立てる部署も）が `dispatch.py --after-task <部署の場所>` を裏で打ち、終わりを待たない。合図には呼んだ会話が居ないので、合図で呼んだツールが片づかなかったときは、`--call` と同じに外れの行を残し、その入力を `fallback_role` の役への頼みとして回す。この頼みの頼み元は、その会社の窓口（持ち主と話す会話）。開き直した部署（`--task` の打ち直しや `--move` で開いた、新しく立てていない部署）では呼ばない。出力は受付箱の `task-after.log` に残る。
- MCP のサーバーは立てない（各会話の文脈にツールの定義を載せないため）。ツールの一覧と外れの回数は `--tree` の会社の行に出る。
- ツールは会社の形を origin の既定のブランチから読む（`--ask` と同じ）ので、会社の形に足したツールはメインブランチに入ってから呼べる。
- ツールを走らせる場所は、代表の clone から一時のフォルダ（`<一時のフォルダ>/works-dispatch-tool-<字>/tree`）に作る worktree で、走らせ終えたら消す。作るときに、作った処理の番号（pid）を訳にした鍵（`git worktree lock` の訳 `works-dispatch-tool pid <番号>`）を掛ける。処理が殺される（Bash の持ち時間切れなど）と消す所まで行かずに残るので、次にツールを走らせるときと `--clean --apply` が、作った処理がもう居ない物を消す。場所がもう無いのに git の記録だけ残った物も消す。鍵の無い物（この直しより前の版が作った）は、アカウントごとに入っている版が違う間、前の版のツールが今走っている場所かもしれないので消さず、`--clean` が訳と消し方を添えて並べる。ツールがその場所で作った commit（例: my_notes の会社には、ほかのリポジトリの中身を写して、その来歴を commit して push するツールが在る）が push されないまま殺されたときに失わないよう、先頭の commit がどのブランチにも無ければ `refs/company/kept-tools/<commit の id>` に残してから消す（中を見るなら `git log refs/company/kept-tools/<id>`、要らなければ `git update-ref -d` で消す）。未コミットの変更か git に足していないファイルが在る場所は消さず、`--clean` が訳と消し方を添えて並べる。Windows では処理が居るかを確かめない（`os.kill` が処理を止めるため）ので、番号の鍵の物は消さない。`--tree` は「（ツールの一時の場所）」、`--clean` は「ツールの一時の場所」の行で出す。`--clean` に「残す」と出たツールの一時の場所は、ツールが走っていないのを確かめてから、その行に添えた手順（commit を残す `git update-ref` と、`git worktree remove -f -f`）で消す。
