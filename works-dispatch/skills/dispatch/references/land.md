# メインブランチに入れる: `--land 部署`

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）の成果をメインブランチ（origin の既定のブランチ）に入れると頼まれたときに、読んでから `--land` を打つ。

部署（名前かブランチの名前で指す。名前が無ければ、`--reorg` が覚えた前の名前でも引く）のブランチを、会社の形（`.claude/company.toml`、無ければ dispatch の設定のフォルダ〔既定は `~/.config/works-dispatch/`〕の `companies/`）の `[land]` の決まりでメインブランチに入れる。フィールドと例は、このプラグインの `docs/land.md`。

- 決まりが無い（`[land]` が無いか `mode = "none"`）なら何もしない。`mode = "pr"` なら、部署のブランチを origin に出して PR を出し、止める。
- `mode = "ff-after-ci"` なら、ゲート（`gate`。CI のブランチの形〔例 `release/*`〕か、手元の検証の `check`）を通し、緑でメインブランチがまだ部署のブランチの祖先なら、メインブランチを fast-forward して push する。`bump = "marketplace"` なら、部署は版を上げずに出し、取り込むときに版を上げる commit を足してからゲートに出す。
- メインブランチが先に進んでいれば、自分では merge せず、部署の窓（部署の会話の画面を出した herdr のペイン。打ち込むと部署の会話への入力になる）に「メインブランチの上にリベースして push し直す」と打ち込んで止める。赤なら、失敗の要点を部署の窓に打ち込んで止める。部署が直したら、もう一度 `--land` を打つ。
- 部署が永続かエフェメラルかは、部署を立てたときに決まり、属性 `company.lifecycle` に残る（`--persistent` を付けたか、役の項目に `persistent = true` が有れば永続で、頼みごとにブランチを移って残り続ける。それ以外はエフェメラルで、一度の頼みのために立てて終われば畳む）。
- 入れたら、エフェメラルの部署は `--clean` と同じ決まりで片付ける。片付けは部署の作業場・worktree・会話・手元のブランチを消すことで、消すのは、会話が終わり、未コミットの変更・手元にしか無い commit・stash が無く、ブランチがメインブランチに入っているときだけ（永続の部署と、会話がまだ動いている部署は残す）。会話がまだ動いているなどで残したエフェメラルの部署には入れた印（`company.landed`）を書き、次の `--land`（どの部署でも）が、会話が止まった後なら一緒に片付ける（`--clean --apply` でも片付く）。永続の部署は、入れたブランチと入れた時の先頭を属性 `company.landed-branches` に書き、部署が次の頼みでブランチを移った後の `--land`（どの部署でも）か `--clean --apply` が、その前のブランチを手元から消す。部署の会話に「ブランチを移るときに前のブランチを消す」を任せず機械で消すのは、会話は消し忘れても止まらず、消してよいか（入れた時の先頭のままか）を機械が確かに見られるため。
- `mode = "ff-after-ci"` と `bump = "marketplace"` で、版を最後に上げた後にフォルダの中のファイルを変えた（commit した）プラグインの `CHANGELOG.md` の `## [Unreleased]` が、版を上げる commit を足す前の時点で空（`### Fixed` のような `#` で始まる行だけ）なら、中身の無い版を作らずに `--land` 全体を止める（何も push しない。終わりの値は 1）。版を上げずに入れる道は無い（marketplace は版が変わった時だけ中身を取り直すので、上げなければ利用者に届かない）。部署が利用者に効く違いを書き足して commit したら、もう一度 `--land` を打つ。
- 書き換えの取り合いのゲート: 部署がメインブランチを最後に知った位置（属性 `company.base`。`--task` がブランチを作ったときの origin のメインブランチと、その部署の `--land` で入れた後のメインブランチ）より後に、ほかの部署がメインブランチへ入れた行を、部署のブランチが消して（書き換えて）いれば、ゲートに出さずに止め、部署の窓に「どの commit（件名）の、どのファイルの何行目を消すか」を打ち込む。部署が前に読んだ中身を覚えたまま書き直すと、ほかの部署が入れたばかりの行を消しても git の衝突にならず、ゲートの試験も通る（まっさらな環境での 2 回目の試しの 5）ため。部署はその行を残す形に取り込み直して push し、`--land` を打ち直す。わざと消すなら `--land <部署> --keep-removal` で通す。位置の記録が無い部署（0.19.8 までに立てた部署）は見ずに注記を出す（今のメインブランチとの merge-base は、リベースした後のブランチではメインブランチの先頭になり、何も見つけないため）。入れた後は、その部署の位置を入れた後のメインブランチに進める。
- 会社の形の `[land]` に `queue`（メインブランチへ入れる列）が有れば、`--land` は申し出た順に 1 本ずつ通る。判断役（頼みを部署に配る会話）は、引数なしの `--land-order` で待っている札（列に申し出た 1 本ごとの印）を見て、`--land-order <部署> [<部署> ...]` で先に入れる順を書ける。書いた順は、引数に `-` だけを渡す `--land-order -` で全部消え、申し出た順に戻る（何もしなければ申し出た順）。何を先にするかの決め手は、このプラグインの `docs/land.md` の「入れる順を決める」。
- works-dispatch の外で、同じ clone からメインブランチへ自分で push するツール（my_notes〔持ち主のノートのリポジトリ〕の collect など）は、ツールの側が `dispatch.py --queue-run -- <コマンド>` を打ち、`--land` と同じ列（会社の形の `[land]` の `queue`）に並んでからコマンドを走らせる。終了の値は、コマンドが走ればコマンドの物。列に入れずコマンドを走らせなかったとき（`[land]` に `queue` が無いなど）は、`--queue-run` 自身が 125 を返す。ツールが `--call` か `[[land.after]]` で走るときは、`dispatch.py` のパスが環境変数 `WORKS_DISPATCH` に、それを走らせる Python が `WORKS_DISPATCH_PYTHON` に入るので、`"$WORKS_DISPATCH_PYTHON" "$WORKS_DISPATCH" --queue-run -- <コマンド>` で打つ。それ以外の道で走るツールや、この会話から打つときは、上のスキルの本文と同じ `bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --queue-run -- <コマンド>` の形で打つ。詳しくはこのプラグインの `docs/land.md`（この文書とは別の、詳しい説明）の「外のツールが列に並ぶ」。
- `--dry-run` を付けると、決まりと見立て（リベースが要るか・入れる commit・上げる版・ゲート・片付け）を出すだけで、何も書かない・push しない・部署の窓に打ち込まない。打つ前の確かめに使う。終わりの値は、本当に打てば途中で止まる見立て（リベースが要る・中身の無い版など）か、見立てそのものの失敗（origin を読めないなど）なら 1、通る見立てなら 0。
- 会社の形の `[land]` の下に `[[land.after]]`（`role`・`tool`・省けば空の `input`）を書くと、メインブランチへ push し終えた後に、そのツール（機械窓口。AI を起動せずに機械で答えるツールで、役の `[[roles.tools]]` に書く。`references/call.md` の「機械窓口」）を順に呼ぶ（出来事の後に呼ぶこの形を合図と呼ぶ）。ツールが片づかなければ（0 以外で終われば）、`--call` と同じに、その入力を AI への頼み（部署に仕事を頼むこと）に変えてツールの `fallback_role` の役へ回し、回した頼みの頼み元（納品を返す先の会話）は、メインブランチに入れた部署の頼み元（その部署の `company.boss`）にする。合図が片づかなくてもメインブランチに入れたことは取り消さず、`--land` の終了の値も変えない。`mode = "pr"` ではメインブランチへ push しないので呼ばない。
- 部署の会話が打つ `--land` は、Claude Code の自動の権限の判定（auto mode の classifier）に「Merge Without Review」として止められることがある。役の `settings` の `autoMode.allow` に、`--land` が会社の形のゲートを通してからメインブランチに入れる決まりであることを文で書くと、組み込みの拒否の例外になる（[Configure auto mode](https://code.claude.com/docs/en/auto-mode-config)。`autoMode` はプロジェクトの `.claude/settings.json` からは読まれず、`--settings` で渡す役の設定からは読まれる）。`--init-company` が書く会社の形の下書きでは、役「担当」と役「作業」の `settings` が、この `autoMode.allow` の文を持つ。`--land` は部署の場所の `__pycache__/` を、未コミットの変更・git に足していないファイルに数えない（部署を立てるときと `--land` のときに、代表の clone（部署の worktree を作る元の、その会社の clone）の `.git/info/exclude` に `.claude/settings.local.json` と一緒に足す）。
