# 表示を付け直す・組み直す・アカウントを選ぶ: `--sync`・`--reorg`・`--desk`・`--pick`

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。会話が読んでから打つ。herdr（端末の画面を作業場とペインに分けて Claude Code の会話を並べるツール）の表示がずれたとき（herdr を立ち上げ直した後など）は `--sync`、部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）の名前・役・頼み元を替えるときは `--reorg`、本社（代表の clone）で持ち主と話す会話を窓口に名付けるときは `--desk`、dispatch を通さずに会話を立てるときは `--pick` を打つ。

## herdr の表示を付け直す: `--sync`

部署の属性（正本）から、部署のペインの名前・表示名（役）・題名・札と、作業場の名前（herdr のサイドバーの 1 行目）と印 `$kind`（常設・毎回空／常設・持ち越し／都度。「前提」の作業場の行に出る）を付け直す。付け直す前に、会社の形の役を部署と本社の属性に写し直す（属性 `company.role` が役の前の名前〔`former_names`〕なら今の名前に、`company.fresh` は役の `fresh` に。会社の形に無い役の場所は触らない。`--dry-run` は写す物を出すだけ）。作業場の名前は、部署の worktree なら属性の `company.name`（部署の会話の名前と同じ値）、代表の clone（`--desk` で窓口の属性を書く）なら会社の名前（herdr の木の親の作業場なので、会社の名前は親にだけ出す）。代表の clone の作業場は、その git の設定に属性が書いてあるときだけ付ける。ペインは、属性の会話（`company.session`）の居るペインが分かればそのペインだけに付け、代表の clone で会話の居るペインが 2 つ以上あって結べなければ付けない（持ち主のほかの会話の名前を替えない）。今の名前・印と同じなら付け直さない。属性を持つ場所（代表の clone か部署の worktree）が 2 つ以上居る作業場は、名前が 1 つに決まらないので触らない。何度打っても同じ結果になる。属性の無い部署（手で開いた場所）は触らない。Stop のフックが表示名に添えた「・裏の処理待ち」（部署の会話が裏で走らせた Bash の終わりを待っている印。「役の中身と起動方法」のセクション）は残す。会社の形が替わったときは打たなくてよい（会話のターンの終わり〔1 回の応答を終えたとき〕に裏で走る Stop のフック `dispatch/shape_hook.py` が、会社の形の中身を、前に揃えた時の控え〔代表の clone の `.git/company/shape-synced`〕と比べ、替わっていればその会社の全部の部署と本社に付け直す。会社の形は origin の既定のブランチから読むので、この PC の `origin/<既定のブランチ>` に届いた後〔この PC からの push か `git fetch` の後〕に効く）。herdr を立ち上げ直した後などに打つ。`--sync --dry-run` は付ける物を出すだけ。

部署の作業場（会社のまとまりの中の、元の clone でない作業場）は、仕事の流れの順に並べ直す。常設で会話を持ち越す部署（相談の社長室など）、常設で毎回空にする部署（担当。この中は会社の形の `[[skills]]` の書き順）、都度の部署（作業。この中は今の並び。herdr は新しい作業場を後ろに足すので、起動した順）、属性の無い作業場（手で開いた場所）の順。順は部署の属性と会社の形から毎回出すので、順の表は持たず、部署が増えても手で並べ直さない。本社（元の clone。窓口の段取りなど）の作業場は、herdr が会社のまとまりの頭に置くので動かさない（社長室を本社より上には置けない）。ほかの会社の作業場と、会社のまとまりに入らない作業場の位置は変えない。`--task`（と `--ask` が部署を新しく立てるとき）も、立てた後にその会社の分だけ並べ直す。herdr 0.9.3 の CLI に作業場を並べ替えるコマンドが無いので、herdr のソケットの API の `workspace.move` を使う（herdr のペインの中は環境変数 `HERDR_SOCKET_PATH`、外は `herdr status server` の socket の行で場所を引く）。動かせなければ残りは動かさず、訳を出す。`--sync --dry-run` は動かす作業場と行き先の位置を出す。`--tree` の部署の並びも同じ順（本社を頭に、その後は上と同じ 4 つの区分〔常設で持ち越し・常設で毎回空・都度・属性の無い作業場〕の順。同じ区分の中はブランチの名前の順）。

## 組み直す: `--reorg`・`--desk`

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --reorg [--name <新しい名前>] [--role <役>] [--resident | --per-task] [--boss <頼み元の名前> [--boss-account <アカウントの名>]] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --desk [<名前>] [--role <役>] [--dry-run]
```

- `--reorg` は、部署（属性 `company.role` の在る worktree）の中から打ち、その部署の属性を付け替える。`--role` は会社の形に無ければ止まり、`--resident`・`--per-task` を省いて `resident = true` の役に替えると常設にする。`--boss` は頼み元（納品を返す会話）の名前を替え、前の頼み元の会話の id とペイン（`company.boss-session`・`company.boss-pane`）を消す（納品は新しい頼み元を名前で引く）。`--name` の新しい名前を、ほかの部署がもう持っていれば止まる（宛先が 1 つに決まらなくなるため）。
- `--desk` は、代表の clone で持ち主と話す会話の中から打ち、その場所の属性に窓口（役・常設・名前・その会話のアカウントと会話の id と会話の処理の番号）を書く。役は `--role`、会社の形の `desk_role`、本社が今持つ役、`窓口` の順に決め、名前を省けば本社が今持つ名前、無ければ役の名前。手で `git config --worktree company.role …` と書いていた物の正式な口。部署の worktree で打つと止まる（部署は `--reorg`）。窓口の席は 1 つで、前に `--desk` を打った会話の処理（属性 `company.pid`）が動いている Claude Code の間は、ほかの会話から打つと止まる（試しの `claude -p` などが席を取ると、納品がそちらに届き、同じ役の会話が 2 つ動く）。席を移すとき（アカウントを替えるなど）は、前の窓口の会話を `/exit` で終えてから、新しい会話で打つ。窓口の役に起動の設定（`[roles.settings]`）が有れば、`--desk` はそれを代表の clone の `.git/company-settings.json` に書き（部署だけの鍵 `worktree.bgIsolation` は重ねない）、その設定で窓口を起動するコマンド（`<アカウントのコマンド> --name <窓口の名前> --settings <ファイル>`）を出す。`--settings` はその会話を起動するときにだけ読まれる。起動し直しは持ち主の手順にしない: `--desk` は、`--move` が起動した会話（属性 `company.launching`）から打たれたら、`--move` が書いた起動した値（`company.launched`）を残し、ほかの新しい会話（持ち主が手で起動した物）なら消す（起動した値を知らないので旗なしで起動したと見る）。会社の形の起動の設定がその値と違えば、窓口が区切り（`--rest`）を印したターンの終わりに、待ち受けがその設定で起動し直す（「ほかのアカウントで起動し直す」の「会社の形の起動の設定が替わったとき」）。`--move` は起動するたびにファイルを書き直す。
- どちらも、名前を替えたら前の名前を属性 `company.former-names` に覚える。`--land` と `--ask` の宛先は、今の名前が無ければ前の名前でも部署を引く（`--land` はブランチの名前でも引ける）。
- 属性を書いた後に、その場所の分だけ `--sync` と同じ物（ペインの名前・表示名・題名・札と作業場の名前）を付け直す。
- 会話の名前（Claude Code の `/rename`）は替えない。Claude Code に、外から会話の名前を替える口が無いため。替えたら、揃える `/rename <名前>` を出すので、その会話の中で打つ。
- `--dry-run` は、付け替える属性を出すだけで、何も書かない。

## アカウントを 1 つ選ぶ（手で会話を立てるとき）

dispatch を通さずに会話を立てるときも、同じ選び方でアカウントを選ぶ。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/nodes/accounts.py" --pick
```

`main: claude — 5 時間 3%・週 1% で、高い方 3% が選べるものの中で最も低い。動いている会話 5 件` のような 1 行を出す。頭が選んだアカウントの名前、`:` の後がそのアカウントの起動コマンド（設定の `command`）。`--json` を付けると、選んだ 1 件（`pick`）と全部の順（`accounts`）と注記（`notes`）を JSON で出す。選べるアカウントが無ければ、終了の値は 1。古い使用率の控えだけを取り直す（`--no-probe` で取り直さない）。
