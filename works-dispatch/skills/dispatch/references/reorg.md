# 表示を付け直す・組み直す・受け持ちを移す・アカウントを選ぶ: `--sync`・`--reorg`・`--desk`・`--handover`・`--pick`

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。会話が読んでから打つ。herdr（端末の画面を作業場とペインに分けて Claude Code の会話を並べるツール）の表示がずれたとき（herdr を立ち上げ直した後など）は `--sync`、部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）の名前・役・頼み元を替えるときは `--reorg`、本社（代表の clone）で持ち主と話す会話を窓口に名付けるときは `--desk`、部署か窓口の受け持ちを同じ会社のほかの部署へ移して畳むときは `--handover`、dispatch を通さずに会話を立てるときは `--pick` を打つ。

## herdr の表示を付け直す: `--sync`

部署の属性（正本）から、部署のペインの名前・表示名（役）・題名・札と、作業場の名前（herdr のサイドバーの 1 行目）と印 `$kind`（keep・clear／keep・continue／tmp。「前提」の作業場の行に出る）を付け直す。付け直す前に、会社の形の役を部署と本社の属性に写し直す（属性 `company.role` が役の前の名前〔`former_names`〕なら今の名前に、`company.fresh` は役の `fresh` に。会社の形に無い役の場所は触らない。`--dry-run` は写す物を出すだけ）。作業場の名前は、部署の worktree なら属性の `company.name`（部署の会話の名前と同じ値）、代表の clone（`--desk` で窓口の属性を書く）なら会社の名前（herdr の木の親の作業場なので、会社の名前は親にだけ出す）。代表の clone の作業場は、その git の設定に属性が書いてあるときだけ付ける。ペインは、属性の会話（`company.session`）の居るペインが分かればそのペインだけに付け、代表の clone で会話の居るペインが 2 つ以上あって結べなければ付けない（持ち主のほかの会話の名前を替えない）。今の名前・印と同じなら付け直さない（印は、見せる語の `$kind` でなく、言語に依らない席のキー `seat`〔`persistent-carry`・`persistent-fresh`・`ephemeral`〕で比べる。`seat` の無い前の版の作業場には一度だけ付け直す）。属性を持つ場所（代表の clone か部署の worktree）が 2 つ以上居る作業場は、名前が 1 つに決まらないので触らない。何度打っても同じ結果になる。属性の無い部署（手で開いた場所）は触らない。前の版の Stop のフックが表示名に添えた「・裏の処理待ち」が残っていれば、付け直しで外れる（待っている印は tiers の statusline に移した。「役の中身と起動方法」のセクション）。会社の形が替わったときは打たなくてよい（会話のターンの終わり〔1 回の応答を終えたとき〕に裏で走る Stop のフック `dispatch/shape_hook.py` が、会社の形の中身を、前に揃えた時の控え〔代表の clone の `.git/company/shape-synced`〕と比べ、替わっていればその会社の全部の部署と本社に付け直す。会社の形は origin の既定のブランチから読むので、この PC の `origin/<既定のブランチ>` に届いた後〔この PC からの push か `git fetch` の後〕に効く）。herdr を立ち上げ直した後などに打つ。`--sync --dry-run` は付ける物を出すだけ。

部署の作業場（会社のまとまりの中の、元の clone でない作業場）は、仕事の流れの順に並べ直す。keep・continue の部署（会話を引き継ぐ。相談の社長室など）、keep・clear の部署（担当。この中は会社の形の `[[skills]]` の書き順）、tmp の部署（作業。この中は今の並び。herdr は新しい作業場を後ろに足すので、起動した順）、属性の無い作業場（手で開いた場所）の順。順は部署の属性と会社の形から毎回出すので、順の表は持たず、部署が増えても手で並べ直さない。本社（元の clone。窓口の段取りなど）の作業場は、herdr が会社のまとまりの頭に置くので動かさない（社長室を本社より上には置けない）。ほかの会社の作業場と、会社のまとまりに入らない作業場の位置は変えない。`--task`（と `--ask` が部署を新しく立てるとき）も、立てた後にその会社の分だけ並べ直す。herdr 0.9.3 の CLI に作業場を並べ替えるコマンドが無いので、herdr のソケットの API の `workspace.move` を使う（herdr のペインの中は環境変数 `HERDR_SOCKET_PATH`、外は `herdr status server` の socket の行で場所を引く）。動かせなければ残りは動かさず、訳を出す。`--sync --dry-run` は動かす作業場と行き先の位置を出す。`--tree` の部署の並びも同じ順（本社を頭に、その後は上と同じ 4 つの区分〔keep で引き継ぎ・keep で clear・ tmp ・属性の無い作業場〕の順。同じ区分の中はブランチの名前の順）。

## 組み直す: `--reorg`・`--desk`

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --reorg [--name <新しい名前>] [--role <役>] [--persistent | --ephemeral] [--boss <頼み元の名前> [--boss-account <アカウントの名>]] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --desk [<名前>] [--role <役>] [--dry-run]
```

- `--reorg` は、部署（属性 `company.role` の在る worktree）の中から打ち、その部署の属性を付け替える。`--role` は会社の形に無ければ止まり、`--persistent`・`--ephemeral` を省いて `persistent = true` の役に替えると keep にする。`--boss` は頼み元（納品を返す会話）の名前を替え、前の頼み元の会話の id とペイン（`company.boss-session`・`company.boss-pane`）を消す（納品は新しい頼み元を名前で引く）。`--name` の新しい名前を、ほかの部署がもう持っていれば止まる（宛先が 1 つに決まらなくなるため）。
- `--desk` は、代表の clone で持ち主と話す会話の中から打ち、その場所の属性に窓口（役・keep〔属性 `company.lifecycle` の `persistent`。頼みを終えても畳まず、次の頼みも同じ作業場で受ける印。窓口はいつも keep〕・名前・その会話のアカウントと会話の id と会話の処理の番号）を書く。役は `--role`、会社の形の `desk_role`、本社が今持つ役、`窓口` の順に決め、名前を省けば本社が今持つ名前、無ければ役の名前。手で `git config --worktree company.role …` と書いていた物の正式な口。部署の worktree で打つと止まる（部署は `--reorg`）。窓口の席は 1 つで、前に `--desk` を打った会話の処理（属性 `company.pid`）が動いている Claude Code の間は、ほかの会話から打つと止まる（試しの `claude -p` などが席を取ると、納品がそちらに届き、同じ役の会話が 2 つ動く）。席を移すとき（アカウントを替えるなど）は、前の窓口の会話を `/exit` で終えてから、新しい会話で打つ。前の会話が一時停止（ps の状態 T。端末の Ctrl+Z などで止まった物）なら `/exit` を受けないので、`--desk` はそう出し、その端末の名前と終え方（その端末で `fg` を打って会話を戻し、`/exit`）を添える。前の窓口の会話を開き直さずに、新しい会話（`claude --name <窓口の名前>` で起動する）で継いだとき（会話が抜けたなど）は、その新しい会話がまだ席を持たないので、works-dispatch のフックが、会話の始まりに文脈へ足す文（ほかの会社への頼み方の 1 行）の次の行として、「前の窓口の会話を継ぐなら `--desk` で席を取り直す」という 1 行を足す（会話の画面に出る文ではなく、会話が読む文脈に入る）。足すのは、本社で窓口の名前を付けて起動した、席を持たない会話だけで、名前を付けない試しの `claude -p` やほかの名前の会話には足さない（その 1 行を読んだ試しが `--desk` を打って席を取る恐れがあるため）。席を取り直さない会話には待ち受けが張られず、納品は予備の道として窓に打ち込まれる。窓口の役に起動の設定（`[roles.settings]`）が有れば、`--desk` はそれを代表の clone の `.git/company-settings.json` に書き（部署だけの鍵 `worktree.bgIsolation` は重ねない）、その設定で窓口を起動するコマンド（`<アカウントのコマンド> --name <窓口の名前> --settings <ファイル>`）を出す。`--settings` はその会話を起動するときにだけ読まれる。起動し直しは持ち主の手順にしない: `--desk` は、`--move` が起動した会話（属性 `company.launching`）から打たれたら、`--move` が書いた起動した値（`company.launched`）を残し、ほかの新しい会話（持ち主が手で起動した物）なら消す（起動した値を知らないので旗なしで起動したと見る）。会社の形の起動の設定がその値と違えば、窓口が区切り（`--rest`）を印したターンの終わりに、待ち受けがその設定で起動し直す（「ほかのアカウントで起動し直す」の「会社の形の起動の設定が替わったとき」）。`--move` は起動するたびに、この `.git/company-settings.json` を書き直す。
- `--desk` は、PR などのブランチを開いた worktree（代表の clone でない worktree）で打っても止まる。窓口の会話がブランチの worktree に居ると、窓口がそのブランチに部署を立てられないため。`--desk` は代表の clone で打つ。
- どちらも、名前を替えたら前の名前を属性 `company.former-names` に覚える。`--land` と `--ask` の宛先は、今の名前が無ければ前の名前でも部署を引く（`--land` はブランチの名前でも引ける）。
- 属性を書いた後に、その場所の分だけ `--sync` と同じ物（ペインの名前・表示名・題名・札と作業場の名前）を付け直す。
- 会話の名前（Claude Code の `/rename`）は替えない。Claude Code に、外から会話の名前を替える口が無いため。替えたら、揃える `/rename <名前>` を出すので、その会話の中で打つ。
- `--dry-run` は、付け替える属性を出すだけで、何も書かない。
- **窓口の席を確かめる（`--desk --dry-run` の出力の読み方）**: 窓口の会話が `/clear`・compact・resume で会話を空にした後に、頼みと納品がまだこの会話に届くかを確かめる手順。頼みと納品は、本社の属性 `company.session`（窓口の会話の id）の会話に届き、空にすると会話の id が替わる。
  1. 空にした後の会話の始まりに「窓口 <名前> の席はこの会話に引き継いだ: …」の一行が在れば、フック（`dispatch/role_hook.py`）が属性の会話の id を新しい id に書き直し済み。空打ちは要らない。ここで終わる。
  2. 一行が無ければ、代表の clone で `--desk --dry-run` を打ち、出た字に下の a〜d を上から当て、最初に当たったものをする。
     - a. 「このコマンドを打った会話が会話の一覧に見えない」の注記が出た: dispatch はこの会話の id を本社の属性と比べられていない（`--dry-run` を外して打っても会話の id を書かない）。頼みと納品がこの会話に届くかを確かめられないので、今壊れている works-dispatch の直しとして、works-dispatch を受け持つ部署に `--ask` で頼む。「止めた:」が出たら、その訳に従う（前の窓口の会話がまだ動いていると出たら、上の `--desk` の箇条のとおり、その会話を `/exit` で終えてから打ち直す。一時停止のまま残っていると出たら、添えた端末で `fg` を打って戻してから `/exit` で終える。代表の clone でない場所で打った・役が会社の形に無い・名前がほかの部署とぶつかった、も訳の字のとおりに直して打ち直す）。
     - b. `- company.session: <前の値> → <今の値>` か `- company.pid: …` の行が出た（片方だけでも）: `--dry-run` を外して `--desk` を打ち直し、同じ形の行が出たのを見る。付け直さないと頼みと納品がこの会話に届かない。
     - c. 「付け替える物は無い（今の属性と同じ）」が出た: 書き直し済み。何もしない。
     - d. どれにも当たらない（ほかの `company.` の行だけが出たなど）: `--dry-run` を外して `--desk` を打ち直す。
  - 経緯: 一行はフックが書き直しを済ませたときだけ出す（同じ Claude Code の処理の中の `/clear`・compact・resume なら、`company.pid` の処理がフックの親に在るので書き直せる）。b の行が出るのは、Claude Code を落として新しい処理で起動したとき（別のアカウントで起動し直したときも含む）か、フックの書き直しが効かなかったとき。前は空にするたびに空打ちしていた。

## 受け持ちを移す: `--handover`

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --handover <前の名前> [--dry-run]
```

ここでの言葉（このセクションで使う語）:

- ターン: 会話のターン。会話が人の文か知らせの 1 通を受けてから、応答を終えるまでの 1 回。
- 場所: 部署なら、その部署の worktree。本社の窓口なら、代表の clone。
- 属性: 場所の git の設定 `company.*` に書く値（役・名前・頼み元など）。
- 台帳: 会社ごとに 1 つ、その会社の代表の clone の `.git/company/inbox/log.jsonl`（受付箱の台帳）で、頼み・納品・知らせを 1 行ずつ足していく記録。前の行は書き換えない。
- 知らせ: 台帳の、ある宛先に宛てた行。その宛先の待ち受けが読んで、頼みや納品を会話に渡す。
- 待ち受け: 部署と窓口の会話のターンの終わりと会話の起動のときに、このプラグインのフックが裏で起動する処理。台帳を読み、自分宛ての知らせが在れば会話を再開させる。人の文（窓に打ち込まれた知らせも同じに数える）でターンが始まると、ターンの始まりに走る別のフックがその場所の待ち受けを止め、ターンが終わると新しい待ち受けが起動する。そのため、会話のターンの中では、その会話の待ち受けは動いていない。会話を `/exit` で終えると、待ち受けも終わる。
- 役の `ask_check`: その役が頼みを受ける前に回す検査のコマンド（[ask.md](ask.md) の「受ける会社の検査」）。
- `<受付>`: 頼みの受付番号（頼み 1 件ずつに付く番号。例 `20261018-014838-3cd0d2`）。
- `--forward`: `--ask` に添えて、受けている頼みをほかの部署へ回し、自分の受けている頼みとしては閉じるコマンド。回した先の答えは、回した側が `--deliver <要約> --for <受付>` で頼み元へ返す（[ask.md](ask.md) の「回したことで閉じる」）。
- 台帳の `handover` の行: `--handover` が後継の会社の台帳に書く 2 行。始めるときに `status` が `started` の行（前の部署と後継の名前・移す前の属性など）を、全部の手順を済ませたときに `status` が `done` の行を書く。

同じ会社の部署か窓口（前の部署）の受け持ちを、打った部署（後継）へ移し、前の部署を畳む（畳むのは前の場所の属性を消すところまでで、worktree・ブランチ・会話は消さない）。部署を増やさずに窓口を既存の部署へまとめるときなどに使う。`--handover` は、後継の部署の会話が、自分のターンの中で打つ。後継の待ち受けが動いている間（後継の会話のターンの外。別の処理から打ったときなど）は、`--handover` のコマンドが何も書かずに止まる。`--handover` はほかのコマンドの引数（`--deliver`・`--for`・`--move` など）と一緒には打てない（`--dry-run` は付けてよい）。移したのを戻すコマンドは無いので、先に `--dry-run` で移す物を確かめる。

- 移す物:
  - 宛先: 前の名前と、前の部署の前の名前を、後継の属性 `company.former-names`（部署の前の名前を覚える属性。会社の形の役の `former_names`〔役の前の名前〕とは別）に足す。これで、`--ask <会社>/<前の名前>`・`--land <前の名前>`・会社の名前だけの `--ask <会社>`（前の部署が本社の窓口だったとき）は後継に届く。ほかの会社の会社の形の頭に `desk = "<会社>/<前の名前>"`（その会社の窓口を前の部署に兼ねさせる書き方。[roles.md](roles.md)）と書いてあれば、その会社の名前だけの宛先も後継に届く（ほかの会社の会社の形は書き換えない）。後継に届いた頼みには、後継の役の `ask_check` が効く。
  - 前の部署の待ち受けがまだ読んでいない知らせ: 後継の宛先宛てに台帳へ写し直す。
  - 順番待ち（部署に届いたが、まだ受けていない頼みの列）: 全部の件を移す。後継の役の `ask_check` を 1 件でも通らなければ、どの件も移さずに止まる。1 件ずつ後継の順番待ちへファイルの rename で移すので、途中で落ちても、同じ頼みが 2 か所に残ったり 2 度渡ったりしない。
  - 保留の頼み（`--wait <訳> --park` で答え待ちのまま保留にした頼み。[rest.md](rest.md)）: 後継の属性 `company.parked` へ移す。答えは後継が `--deliver <要約> --for <受付>` で返す。
  - 前の場所の属性 `company.*` は全部消す。前の部署が本社の窓口なら、代表の clone の窓口の属性（役・名前・会話の id など）が消え、本社の会話は窓口でなくなる（頼みと納品はその会話に届かず、会社の名前だけの宛先は後継に届く）。
- 替えない物: 受付番号・頼みの親子（`cause`・`forwarded` の行）・ほかの部署の属性に書いた頼み元。頼み元が前の部署（名前で見る。前の部署の前の名前も含む）で、移す前に頼んだ頼み（頼みの受付番号と `handover` の行の受付番号〔`--handover` を始めた時に付く〕の、頭の時刻〔UTC の `YYYYMMDD-HHMMSS`〕で比べる）は、納品の時に、前の部署と後継の会社（同じ 1 つの会社）の台帳に `--handover` が書いた `handover` の行を見て、返し先を後継に読み替える（後継へ返す）。移した後に同じ名前で頼んだ頼みは読み替えない。残った疑問の担当者の検査（役の `holders`）と納品の検査（役の `deliver_check`）も、読み替えた後の頼み元で見る。担当者には後継の名前を書き、前の部署の名前は書けない。後継の名前が役の `holders`（持ち主への中継の会話の名前の並びで、ここに在る名前はふつう担当者に書けない）に在っても、読み替えた頼みでは、後継の名前を頼み元の名前として担当者に書ける。読み替えない頼みでは、今までどおり書けない。`--deliver --for` で返す頼み（`--forward` で回した頼み・`cause` 付きの `--ask` で回した子の頼み・保留の頼み）も同じ。読み替えた先の頼み元が後継自身（後継の今の名前・`--handover` で継いだ名前・後継の会話の id のどれか。`--reorg --name` で替える前の名前は数えない）なら、要約を受付箱に置き、だれにも知らせずに閉じる（台帳の納品の行の `status` を `self` にして済にする）。例: 後継が前の部署から受けた頼みを納品したとき。前の部署が `--forward` で回して閉じた頼みの答えは、後継が `--deliver <要約> --for <受付>` で返す。
- 止まるとき（初めて打つときは、書き始める前に確かめて止まり、何も書かない。打ち直しで止まったときと、書き始めた後に書けなかったときは、下の「途中で落ちたら」）:
  - 前の部署が受けた頼みをまだ納品していない: 前の部署が納品するか、`--wait <訳> --park`（訳は、何の答えを誰から待つか）で保留にしてから打つ。
  - 前の部署の待ち受けが動いている: 前の会話を `/exit` で終えてから（待ち受けも終わる）、後継の会話が自分のターンの中で `--handover` を打ち直すのが簡単で安全（ターンの終わる時を気にしなくてよい）。前の会話を終えたくないときは、次の順に打つ。
    1. 前の会話に文を打ってターンを始めさせる（人の文でターンが始まると、前の会話の待ち受けは止まる）。
    2. その前の会話のターンがまだ続いている間に、後継の会話が自分のターンの中で `--handover` を打つ（前の会話のターンが終わると、前の待ち受けがまた起動する）。
  - `<前の名前>` の場所が会社に無いか 2 つ以上ある・ほかの場所がその名前を前の名前に持つ・属性が読めない。
  - 移す物を読んだ後に、前の部署の待ち受けが台帳を読み進めたか、順番待ちに頼みが積まれた（前の待ち受けを止めて打ち直す）。
- `--dry-run` は何も書かずに、次を出す。止まる訳が在れば、`--dry-run` でも止まる訳を出す。
  - 移す宛先・写し直す知らせの件数・移す順番待ちと保留の頼み。
  - 前の部署を頼み元に持ち、まだ納品していない部署（その納品の返し先は後継に読み替わる）。
  - 前の部署が `--forward` で回し、まだ `--for` で返していない頼み（後継が `--deliver --for` で返す）。
  - 後継が今受けている頼みのうち、頼み元が前の部署の物（納品すると頼み元が後継自身になり、送らずに閉じる）。
- 途中で落ちたら（書けずに「途中で書けなかった」で止まったときも）、同じコマンドを打ち直すと続きから済ませる（台帳の `done` の無い `handover` の行から。どの手順も 2 度打って同じ）。打ち直しは、前の場所の今の属性を読み直して止まる訳を確かめ直す（前の場所に別の名前が付いた・前の部署が新しく頼みを受けた・始めた後に積まれた頼みを後継の役が受けない、なら止まる）。落ちてから打ち直すまでの間も、前の部署宛ての納品の返し先は後継に読み替わる（台帳の `started` の行で読み替えるため）。打ち直しが止まり続けても（始めた後に積まれた頼みを後継の役が受けないなど）、引き継ぎを取り消すコマンドは無い。止まる訳を除いて（その頼みを頼み元が取り下げるか、後継の役の `ask_check` が受ける形にして）打ち直し、済ませる。済んだ後に打つと「もう移してある」で何もしない。
- 引き継ぎと同時に打った `--ask <前の名前>` は、頼みを積む直前に宛先の属性を読み直し、宛先が畳まれたか名前が替わっていれば積まずに止まる（打ち直すと後継に届く）。`--task` は、後継が `--handover` で継いだ名前で新しい部署を立てない。
- 移した後、本社の会話が `--desk <継いだ名前>` でその名前を窓口の名前にしようとすると止まる（前の名前で宛てた頼みが、後継でなく本社に届くようになるため）。ほかの名前なら `--desk` で窓口を名付けられ、名付いた窓口が在れば、会社の名前だけの宛先は後継よりその窓口に先に届く。
- 台帳の行の形は [docs/ledger.md](../../../docs/ledger.md) の `handover`。

## アカウントを 1 つ選ぶ（手で会話を立てるとき）

dispatch を通さずに会話を立てるときも、同じ選び方でアカウントを選ぶ。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/nodes/accounts.py" --pick
```

`main: claude — 5 時間 3%・週 1% で、高い方 3% が選べるものの中で最も低い。動いている会話 5 件` のような 1 行を出す。頭が選んだアカウントの名前、`:` の後がそのアカウントの起動コマンド（設定の `command`）。`--json` を付けると、選んだ 1 件（`pick`）と全部の順（`accounts`）と注記（`notes`）を JSON で出す。選べるアカウントが無ければ、終了の値は 1。古い使用率の控えだけを取り直す（`--no-probe` で取り直さない）。
