# 順番待ちを動かす: `--take`・`--withdraw`・`--first`・`--nudge` と落ちた部署の会話

dispatch のスキル（works-dispatch のプラグインの、Claude Code の会話を部署ごとに立てて仕事を頼むスキル。本体は [../SKILL.md](../SKILL.md)）の別ファイル。急ぎの操作は無い。窓口や部署の会話が、宛先の会社の受付箱の `queue/` に積んだ頼み（「順番待ち」）を今受ける・ほかへ回す・取り除く・先頭へ回す・止まった順番待ちを動かすとき、頼みごとに会話を空にする部署どうしの返事待ちを知りたいとき、部署の会話が落ちた（窓に会話が居ない）ときに、読んでから下のコマンドを打つ。言葉（窓口・部署・待ち受け・受付箱・属性・窓）と、頼む `--ask`・順番待ちそのものの決まりは「頼む: `--ask` と順番待ち」に在る。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --take <受付> [--ask <宛先> [--task <名前> --branch <ブランチ>] [--text <添え書き>]] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --withdraw <受付> [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --first <受付> [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --nudge <部署> [--dry-run]
```

- **順番待ちから取り出す（`--take`・`--withdraw`）**: 受付番号を `--take <受付>`（今受ける・ほかの部署へ回す）か `--withdraw <受付>`（取り下げる）に渡して打つ。順番待ちは積んだ順に渡る。急ぎの頼みを先に受けるときと、担当が長い頼みで埋まっている間に次の頼みをほかの部署へ回すときは、受付番号で 1 件を取り出す。順番の中で先頭へ動かすだけなら、下の `--first`。
  - `--take <受付>` を部署の場所から打つと、その部署の順番待ちの件を今受ける（待ち受けが渡すときと同じに頼み元の属性を書き、頼みの 1 行を出す。今の頼みを納品していなければ止まる）。
  - `--take <受付> --ask <宛先>`（新しく立てるなら `--task`・`--branch` も）は、どこからでも、受付番号と頼み元をそのままにほかの部署へ頼み直す。`--text` を添えると、回す側の添え書き（担当が回したこと・触らないファイルなど）を元の本文の前に置く。納品は元の頼み元に返る。頼み直せなければ、元の順番待ちの同じ場所に戻す。担当の部署が自分の仕事を並べて進めたいときもこの形で回す。担当の部署は、受け持ち（会社の形の `[[skills]]` に 1 つずつ書く仕事の範囲。例 `割り振り`）を永続で預かる部署で、その受け持ちの名前で立つ。担当の部署が仕事を回す先は、担当の部署とは別に新しく立てる役「作業」の一度きり（エフェメラル）の部署で、名前は `<受け持ちの名前>：<何をするか>`（例: `割り振り：スキルの説明`）にする。
  - `--withdraw <受付>` は渡さずに取り下げる（頼み元が取り下げを頼んだときなど）。順番待ちに無い受付を渡すと、台帳（`log.jsonl`）がまだ開いている（順番待ち・動いている・答え待ち）と出す頼みに限り、取り下げの行を足して閉じる。そうなる頼みは 2 つ。1 つは、順番待ちのファイルが台帳に行を残さずに手で消された頼み。もう 1 つは、受けた部署が納品しないまま、その作業場が消されたか、部署の属性 `company.ask`（部署が今受けている頼みの受付番号）がほかの頼みに替わった頼み。`--todo` は、このうち順番待ちのファイルが消された物と作業場が消された物を、頼みの木（頼みの親子を字下げで並べた一覧）の前に「!」で始まる注記の行（`! 受付 <番号> は…（--withdraw <番号> で閉じる）`）で出す。作業場が在るまま `company.ask` が替わった物は注記に出ないが、`--withdraw` で閉じられる。この 2 つに当たらない頼み、つまり受けた部署の作業場が在り、その `company.ask` がまだこの受付番号のまま（部署がふつうに作業していて、まだ納品していない）の頼みは、閉じずに止まる。その頼みの取り下げは、その旨を `--note` で足す。
  - 台帳: どれも、順番待ちの在る受付箱と頼み元の受付箱の台帳（`log.jsonl`）に 1 行を残す。`--take` は `taken` の行で、取り出した件より先に積まれていて追い越された件と、受けた先（その場で受けたならその部署、`--ask` で頼み直したならその宛先）を書く。`--withdraw` は `withdrawn` の行（順番待ちに無い頼みを閉じたときは、前の状態 `was` と理由 `why` を添える）。
  - 自動では回さない（同じ受け持ちのファイルを 2 つの部署が書くのを避けられるかは、受け持ちを知る担当か窓口が決める）。例外は下の「返事待ちの輪」の項だけで、待ち受けが回す（回すのはまだ誰も手を付けていない順番待ちの頼みで、受ける作業の部署は自分の作業場とブランチで作る。回すときは輪の部署の作業場を見ないので、輪の部署の作業場に有る書きかけの変更とぶつかるかは、受けた作業の部署がメインブランチに入れる〔`--land`〕ときに初めて分かる）。
- **順番待ちの先頭へ回す（`--first`）**: `--first <受付>` は、その頼みを積まれた順番待ちの先頭に回す（急ぐ物を先にする）。渡すのは、宛先の部署が今の頼みを納品した後。後から回した物ほど前に来る。順番待ちの在る受付箱と頼み元の受付箱の台帳（`log.jsonl`）に `reordered` の行を残し、先頭に回した件が追い越した件を書く。上の `--take`・`--withdraw` と同じく、自動では回さない。
- **渡らずに止まった順番待ちを動かす（`--nudge`）**: `--tree` の部署の行に「渡す待ち受けが居ない」か「渡さずに待っている（訳）」が出ていたら、`--nudge <部署>` を打つ。終了の値 1 で終わったら、部署の窓を見て `--nudge <部署>` を打ち直す。持ち主に部署の窓へ打たせない。
  - 止まり方は 2 つ。ターンを終えたのに渡す待ち受けが居ない（`--tree` に「渡す待ち受けが居ない」）と、待ち受けは居るが渡さずに待っている（受付箱の台帳〔`.git/company/inbox/log.jsonl`〕で、その部署の作業場について書いた最後の行が `held`。`--tree` に「渡さずに待っている（訳）」）。
  - 打つと起きること: 部署の窓に会話が居なければ attach で戻し（戻った会話の始まり〔SessionStart〕に張られる待ち受けが渡す）、居て手が空いていて（herdr の状態が idle か done）入力フィールドが空なら、`/reload-plugins`（会話にプラグインを読み直させる打ち込み）を打ってから、「ターンを 1 つ回す。受けている頼みが途中ならそれを続け、無ければ何もせずにターンを終える」の 1 行を打つ。ターンの初めにそれまで待っていた待ち受けが止まり、ターンの終わりに今の版の待ち受けが張り直して渡す。1 行を打つのは、`/reload-plugins` を打った後に、窓の画面を読んで、入力フィールドに `/reload-plugins` の字が残っていないこと・会話の手が空いていること・入力フィールドが空なことの 3 つを全部見られたときだけである。1 つでも見られなければ（待つ間に人が打ち始めたなど）、1 行は打たず、台帳の `nudged` の行を `failed` にし、部署の窓を見て `--nudge <部署>` を打ち直すよう出して、終了の値 1 で終わる（`--ask` から打ったときは 0 で終わる）。区切り（`--rest`）・答え待ち（`--wait`）・終わり（`--done`）の印は部署の属性に書く値で、会話に打つと外れるので、`--nudge` は打った後に（1 行を打たずに終えたときも）元の値を書き戻す。打ったか戻したかは台帳に `nudged` で残し、動かせなかったら終了の値 1。待ち受けの居る部署へ積む `--ask`（同じ中身が積まれていたときも）は、止まっていれば同じことを自分でする。
  - 窓に何も打たないとき: 次の 2 つのとき。1 つは、部署の会話が動いているか入力フィールドに字が在るとき。もう 1 つは、`--tree` に出る待ち受けの訳が、会話が動いている・入力フィールドに字が在る、のどちらかのとき。これらの訳はすぐ替わり、待ち受けが 5 秒ごとに試し直して渡す。打てば、人の打ちかけの字と、待ち受けが納品して止まった会話を空にするために打つ `/clear` を壊す。
  - 経緯: 先に読み直させるのは、会話が前の版のプラグインのままだと、ターンの終わりに張り直すのも前の版の待ち受けになるため。前の版の待ち受けは、今の版の待ち受けなら渡す場面（納品し終えた部署が、自分の出した頼み〔子の頼み〕の返事を待っているときと、裏の処理〔会話が裏で走らせた Bash やサブエージェント〕が残るとき）でも、また渡さずに待つ。読み直しはターンを始めず会話の中身も消さないので、前の版かは外から確かには分からない会話にも毎回打つ。
- **返事待ちの輪（待ち受けがほどく）**: 頼みごとに会話を空にする部署（役が `fresh = true` の部署。受けた頼みを納品するたびに会話を `/clear` で空にし、空の会話で次の頼みを受ける）は、自分が出した頼み（子の頼み）の返事が来るまで、納品し終えても会話を空にしない（返事を、その頼みを出した会話で受けるため）。順番待ちに次が在れば、空にしないまま渡すので、納品し終えた部署は子の頼みの返事待ちでは止まらない。輪になるのは、納品していない頼みを受けたままターンを終えた部署どうしである。部署 A の子の頼みが B の順番待ちに積まれたまま、B も納品していない頼みを受けたままターンを終え、B の子の頼みが A の順番待ちに積まれていると、どちらも動かない。部署が 3 つ以上でも同じである。待ち受け（部署の会話のターンの終わりに裏で走り、受付箱の台帳〔`.git/company/inbox/log.jsonl`〕を読んで頼みを渡す台本）は、この輪を台帳からたどって見つける。見つけたら、輪の頼みのうち受付番号の一番小さい物（一番古く出された物。輪が重なっていても、どの部署の待ち受けが見つけても同じ物を選ぶ）を、その頼みが積まれていた部署の会社で `--take <受付> --ask <会社>/<既定の役> --task <積まれていた宛先の部署の名前>：<受付の末尾 6 字> --branch work/ask-<受付の末尾 6 字>` で回す。回す先は、新しく立てる一度きりの部署で、役は既定の役（会社の形 `.claude/company.toml` の `default_role`、無ければ「作業」）。`--task` の名前の `：` の前は、その頼みが積まれていた順番待ちの部署（宛先）の名前。受付番号と頼み元はそのままで、納品は元の頼み元に返る。台帳には輪をほどいた印の `knot` の行が残り、`--take` の出力は受付箱の `takes/` に残る。`--take` が 0 以外で終わった（ほかの待ち受けと取り合って負けた・頼み直せずに順番待ちへ戻した）ときだけ、最初の回を含めて 3 回まで回す。終わりの値は、`--take` を会話から切り離して（会話が止まっても止まらない別のプロセスとして）走らせる包みの `/bin/sh` が、出力の置き場（受付箱の `takes/`）の終わりのファイルに書き、待ち受けがそれを読む。Windows ではこの包みで走らせないので、最初の 1 回だけ回し、回し直さない。回し切れなかった輪は、台帳の `knot` の行と `takes/` の出力に訳が残り、`--tree` に「渡さずに待っている」と出続けるので、今までどおり人か段取り（部署への頼みを配る部署）が `--take` で回す。輪が重なっていれば、1 件回して残った輪を、回した頼みが渡って部署が動いた後に、待ち受けが次に輪を探す時（次のターンの終わりか、空にしない間の 5 秒ごとの見直し）に順にほどく。人が `--take` で回さなくてよい。
- **落ちた部署の会話**: `--ask` が頼みを送る前に毎回自動でする確かめ。PC やサーバーの再起動で部署の窓（attach の画面）が消えると、部署の窓に会話が居なくなるので、`--ask` が会話を戻してから頼む。手ですることは次の 2 つだけ。
  - 戻せないとき（ペインの前にシェルが居ない・作業場が開いていない）は、`--ask` は打つコマンドを出して止まるので、そのコマンドを手で部署の作業場のペインで打つ。
  - 窓の端末に貼り付けの印（端末の貼り付けの切り替え〔bracketed paste〕が入ったままの状態）が残っていて打ったコマンドが崩れた（打った字の前後に `00~`・`01~` のような字が出る）ときは、`--ask` はその旨を出して止まるので、部署の窓で `reset` を打ってから `--ask` を打ち直す。
  - 戻し方: 部署の会話は裏の会話（`claude --bg` で起動した、画面を持たない会話。窓の attach の画面はそれを映しているだけ）で、その記録は残っているので、`--ask` は部署の窓のペインに `<部署のアカウントの起動コマンド（設定の command）> attach <短い id>` を打って前の続きから戻し、窓に会話が戻るのを見てから頼む。1 つの会話に id が 2 つ有る。短い id は会話の一覧（`claude agents --json` が出す、そのアカウントの会話の一覧）の `id`（8 字）で、attach に渡す。長い id は会話の記録の id で、部署の属性 `company.session`（部署の worktree の git の設定に書いた値）に残す。attach に長い id を渡すと Claude Code が「No job matching」と断る。ペインを閉じて部署の作業場（herdr の作業場。worktree のフォルダは残る）が herdr から閉じていれば、作業場を開き直してから、その新しいペインで打つ。開き直したペインにも、`--sync`（herdr の表示を部署の属性から付け直すコマンド。[reorg.md](reorg.md)）と同じく、部署の属性から読んだペインの名前・表示名（役）・題名・札を付ける。落ちる前の頼みをまだ納品していなければ、戻した会話にその納品を促す 1 行を打ち、新しい頼みは送らずに止まる（納品が届いてから頼み直す）。
  - 落ちたと見る決まり: 窓に会話が居ない（会話が落ちた）と見るのは、次の 4 つのうち 1 つでも当たるとき。1 つ目は、ペインに会話の印（herdr がペインの情報に載せる、そこで動く会話の id `agent_session`）が無いとき。herdr は attach の画面が終わった後も会話の印を残すことがあるので、印が在っても 2 つ目から 4 つ目を見る。2 つ目は、ペインの前に居るプロセスがシェルのとき（この見分けは macOS・Linux だけでする。Windows は前のプロセスを見る口が当てにならないので見ない）。3 つ目は、どの OS でも、画面の終わりに「Session … has exited.」（attach の画面が終わった表示）が出ているとき。4 つ目は、会話の一覧がその会話を止まった（`stopped`・`failed`）と言うとき（裏の処理が止まると、窓の attach が「Waking session …」（裏の会話を再開させようとしている表示）のまま前に残り、窓の前のプロセスだけでは見分けられない）。そのときは、`--ask` が残った attach を Ctrl+Z でシェルに戻してから打ち直す。会話は、部署の属性の会話の id（`company.session`）で一覧から引き、見つからなければ、一覧のうち作業フォルダが部署の作業場で、終わっていない（`done`・`failed`・`stopped` でない）裏の会話（`claude --bg` の会話）が 1 つだけならそれで見る（0 か 2 つ以上なら見つからないとする。部署の会話で `/clear` を打つと id が変わる）。頼みを届けたとき、id が変わっていれば属性を書き直す。
  - 届いたかの確かめ: 頼みと促しの 1 行は、会話の画面に入力フィールドが出てから送り、会話が動き出した（会話の一覧の status が busy）かを見て確かめる。入力フィールドに残っていれば Enter を足し、入力フィールドの外の画面に送った字が見えていれば、届いたと見て打ち直さない（二重に送らない）。入力フィールドにも画面にも見えず動き出してもいなければ打ち直す（3 回まで。3 回でも確かめられなければ failed を返し、部署の窓を見て入力フィールドに残っていれば Enter を押すよう出す）。送る前から動いている会話には 1 回だけ打つ。入力フィールドに残れば Enter を足し、入力フィールドの上（待ちの列）に載るか入力フィールドから出たのを見て届いたとし、見えなくても打ち直さない。
  - 経緯: 打ち直し（3 回まで）はどの OS でも同じ決まりで、入れた訳は、Windows で戻した直後の会話に送った文が、届かないか入力フィールドに残ったこと。送る前から動いている会話に 1 回だけ打つのは、打った字が、今の応答が終わった後に読まれる待ちの列〔入力フィールドの上に「❯ <打った字>」と並ぶ〕に回るので動き出しでは確かめられず、打ち直すと同じ頼みが何度も届いたため。
