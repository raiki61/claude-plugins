# 頼む: `--ask` と順番待ち

dispatch のスキル（works-dispatch のプラグインの、Claude Code の会話を部署ごとに立てて仕事を頼むスキル。本体は [../SKILL.md](../SKILL.md)）の別ファイル。急ぎの操作は無い。窓口（本社で持ち主と話し、仕事を配る会話）や部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）の会話が、ほかの部署や会社に頼む・積んだ頼みを並べ替える・今の頼みに足すときに、読んでから下のコマンドを打つ。

言葉: dispatch は works-dispatch のプラグインのスクリプト。herdr は端末を作業場とペインに分け、中の Claude Code の会話を外から操作するツール。会社は部署を置いて回す git のリポジトリで、会社の形はその設定ファイル `.claude/company.toml`。本社は会社の代表の clone。部署は作業ごとの git worktree と、そこで働く裏の会話（`claude --bg` で起動した、画面を持たない会話）の組で、その会話を映す herdr のペインが窓。窓口は本社で持ち主（このスキルを使う人）と話し、部署に仕事を配る会話。役は部署と窓口の会話の決まり、受け持ちは部署ごとの仕事の範囲（会社の形の `[[skills]]`。`--tree`〔会社ごとに部署を並べる一覧。中身は [department.md](department.md)〕の「受ける仕事」の行に出る）。属性は部署の worktree や代表の clone の git の設定に書く `company.*` の値（`company.role` は役、`company.name` は部署の名前、`company.session` は会話の id）。頼みは部署に渡す仕事の文、納品は部署が結果の要約を頼み元へ返すこと。受付番号は頼み 1 件ずつに付く番号（例 `20261018-014838-3cd0d2`。コマンドの `<受付>` に書く）。順番待ちは、前の頼みをまだ納品していない部署への頼みを積んでおく列。受付箱・待ち受け・返事待ちの輪は下の同じ名前の項。

コマンドの選び方: 新しく頼む → `--ask`。順番待ちの 1 件を今受けるか、ほかの部署へ回す → `--take`。順番待ちから取り除く（か、台帳で開いていると出るのに順番待ちにも受けた部署にも無い頼みを閉じる） → `--withdraw`。順番待ちの先頭へ動かす → `--first`。順番待ちが渡らずに止まった部署を動かす → `--nudge`。今受けている頼みに足す → `--note`。頼みの一覧を見る → `--todo`。後で見ること（「この日に見る」「この頼みが閉じたら見る」）を残す → `--remind`。詳しい決まりは、下の、見出しにそのコマンドの名前を書いた項に在る（`--take`・`--withdraw`・`--first`・`--nudge` と、「返事待ちの輪」「落ちた部署の会話」は「順番待ちを動かす」に在る）。

部署への頼みと、部署からの納品（要約を返すこと）は、相手の会話の**待ち受け**（会話のターン〔1 回の応答〕の終わりに、このプラグインのフックが裏で起動し、受付箱〔頼みと納品を置く代表の clone の `.git/company/inbox/`〕の台帳を見て会話を再開させる処理）が会話を再開させて届ける。人の打つ入力フィールドに字を打ち込まないので、人が窓口に打っている途中に納品が届いても混ざらない。待ち受けの動いている印が無くても、相手の会話の場所（会話の git の worktree）に待ち受けの居た跡（台帳をどこまで読んだかを、受付箱の `wake/` に worktree ごとに残す `.pos` のファイル）が在れば、送る側は知らせを台帳に置き、ターンの終わりに張り直した待ち受けがその知らせを会話に渡す。台帳に置く条件はコマンドごとに違う。`--ask` は相手の部署が前の頼みをまだ納品していないか、clear の部署（役が `fresh = true` で、頼みを納品するたびに会話を `/clear` で空にする部署）が納品の後のターンの途中か、読んでから打つまでの間に待ち受けがほかの頼みを渡していたとき。`--note` は跡が在ればいつも。`--deliver` は頼み元の会話がターンの途中（会話の一覧の status が busy）で、その worktree に `git config --worktree` で書いた会話の id（`company.session`。その場所で待ち受けを張る会話）が頼み元の会話の id のとき。そのほかの、待ち受けの居ない会話（このフックの無い古い版の会話・落ちた会話）には、今までどおり herdr の窓（相手の会話の画面を出したペイン）に 1 行を打ち込む（`--deliver` で頼み元の会話が終わっていれば、窓が無いので台帳に知らせを置いて納品済みにする）。アカウントが違っても届く（SendMessage は同じアカウントの会話にしか届かないので使わない）。仕組みと決めた訳は、このプラグインの受付の設計 `docs/specs/2026-10-17-reception-design.md`。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --ask <会社/役 か部署の名前か会社の名前> (--text <文> | --brief <ファイル>) [--task <名前> --branch <ブランチ>] [--forward] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --note <受付> (--text <文> | --brief <ファイル>) [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --todo [<受付>] [--all] [--state <状態>[,<状態>...]] [--to <宛先>] [--json | --html <ファイル>]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --remind <何を見るか> [--on <日時>] [--after <受付>]... [--dry-run]   # --on か --after の少なくとも 1 つ
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --remind-done <受付> [--dry-run]
```

`--ask` の宛先に会社の名前だけを書くと、その会社の窓口（代表の clone で `--desk` を打って名付けた会話。`--tree` の「窓口」の行）に届く。部署でない会話（窓口など）がほかの会社に頼むときに、宛先の会社の窓口の役の名前を知らなくてよい。窓口を名付けていない会社では止まり、`--tree` の「受ける仕事」の宛て方で仕事ごとの部署に宛てるよう言う。宛先に「会社/」を付けずに 1 語だけ書いたときは、その語を次の順で当てる。1 番目は部署の名前（同じ名前の部署が在れば、そちらに届く）。2 番目は会社の名前（その会社の窓口に届く）。3 番目は頼む側の会社の中の役の名前（`--ask 作業` のように、自分の会社の役で宛てる書き方）。同じ名前の会社が 2 つ以上開いていれば止まる。部署でも窓口でもない会話（部署や窓口の属性の無い場所で動く会話）の納品は、待ち受けが居ないので、その会話の herdr の窓に 1 行を打ち込んで返す（herdr の外の会話には返らず、受付の台帳にだけ残る）。

- **待ち受け**: このプラグインのフックが、部署と窓口（属性 `company.role` と `company.name` の在る場所。窓口は `--desk` が書く）の会話のターンの終わり（Stop）と始まり（SessionStart。`/clear`・compact・resume を含む）に、裏で待ち受けを起動する（Claude Code のフックの `asyncRewake`。終了の値 2 で手の空いた会話を再開させる）。待ち受けは、その会社の受付箱の台帳 `log.jsonl` の、宛先が自分（「会社/名前」。前の名前も）の行だけを読み、宛先違いの行は会話に渡さない（会話の費用は 0）。待ち受けは会話ごとに 1 つで、印は受付箱の `wake/` に置く。窓口の待ち受けは、`--desk` が書いた会話の id の会話だけが張る（代表の clone で開いたほかの会話に知らせを横取りさせない。その会話が `/clear` で会話を空にして id が替わったときは、属性の id を新しい id に書き直して張る）。人の文でターンが始まると、その場所の待ち受けを止める（ターンの終わりに張り直す）。フックの持ち時間は 7 日で、それより長く手の空いた会話は、次のターンまで待ち受けの居ない会話として扱う。

- **宛先**: 部署の名前（属性 `company.name`。無ければ `--reorg`・`--desk` が覚えた前の名前）か「会社/役」か会社の名前。役は、会社の形 `.claude/company.toml` の `[[roles]]` に書いた部署の役の名前（例「作業」）。会社は herdr に開いているリポジトリ（`--tree` に出る会社の名前）で、省けば頼む側の会社。部署の名前、会社の名前（会社の形の在るリポジトリだけ。その会社の窓口へ届く）、頼む側の会社の役の順に当たる。役で宛てたときは、その役の keep の部署へ届け、無ければ新しい部署を `--task` と同じ道で立てる（新しく立てるときは、部署の名前を `--task`、ブランチの名前を `--branch` で渡す。省けば止まる）。役で宛てて部署の名前（`--task`）も渡したときは、その名前の部署へ届け、無ければ新しく立てる（同じ役の keep の部署が別の名前で居ても、その keep の部署へは届けない。ブランチの名前は `--branch` で渡す）。宛先の会社は、頼む会話が `--tree`（会社ごとに部署を並べる一覧）の「受ける仕事」（その会社が受ける仕事ごとの、頼むコマンドの宛先を並べたフィールド）を読んで選ぶ。
- **頼んだ会話と同じブランチ**: `--ask` で部署を新しく立てるとき、`--branch` に渡したブランチを、頼んだ会話の居る作業場（git の worktree）がもう開いていれば、`--ask` は部署を立てずに止まる。部署は、そのブランチを開いた worktree で起動するからで、止めたときの文は「部署を立てずにこの会話で進める」。そのまま頼んだ会話で作業を続ける（別の仕事なら別のブランチを `--branch` に渡す）。
- **部署が起動しなかった訳**: 部署を新しく立てる処理が会話を起動できなかったとき（そのブランチの worktree で会話がもう開いている、使えるアカウントが無い、など）は、受付箱の台帳 `log.jsonl` のその頼みの行の `detail` に、起動しなかった訳を 1 行で書く。`--ask` は 0 以外の終了コードで終わる。
- **頼み（`--ask`）**: `--ask <宛先>` に、本文を `--text <文>` か `--brief <ファイル>` で渡して打つ（宛先の書き方は上の「宛先」）。
  - 本文の書き方: 本文が 2 行以上なら、頭に頭書き（1 行目と閉じの行が `+++` の TOML）を置き、`title`（`--todo` に出す 1 行の題）を書く（題の無い 2 行以上の本文は、書き方の例を出して止まる）。頼みの種類は頭書きの `type` に書く。`task`（仕事を頼む。省けばこれ）か `question`（答えか判断を求める問い）のどちらかで、ほかの値なら `--ask` は送らずに止まる。1 行で済む問いを `question` にするときも頭書きを置く（頭書きを置けば本文は 2 行以上になるので、`title` も書く）。宛先の役が `ask_holders` を持つなら、残った疑問は頭書きの `[[open]]` に書く（書き方は [deliver.md](deliver.md) の「要約の書き方」と同じ）。
  - 打つと起きること: 本文を頼む側の受付箱に置き、宛先の部署の窓に「頼みです（受付 <番号>、<頼む会話> から）: <本文>」と、返し方の 1 文（要約を項目で書いたファイルにして `--deliver` で返す、という指示）を打ち込む（待ち受けの居る部署へは、窓に打ち込まず、下の「順番待ち」のとおりに積んで待ち受けが渡す）。改行を含むか長い本文は、受付箱のファイルを指す。題は台帳の頼みの行のフィールド `title` に残り、`--todo` は本文の行から題を拾わない。宛先の部署の属性に、受けた頼み（`company.ask`）と頼み元（会話の名前・アカウント・会話の id・ペイン・受付箱。`company.boss`・`company.boss-account`・`company.boss-session`・`company.boss-pane`・`company.boss-inbox`）を書く。新しく立てた部署には、最初の文で頼みを渡す。属性は毎回すべて書き直し、分からない値は消す（前の頼み元の値を残さない）。
  - 受ける会社の検査: 宛先の役が `ask_check`（受ける会社の検査のコマンド）を持てば、works-dispatch はそのコマンドを起動するときに標準入力へ JSON を渡し、その JSON のいちばん上のキー `type` に、頭書きの `type` と同じ値を入れる（頭書きで省いた頼みは `"task"`）。問いだけを受ける役（my_notes〔持ち主のメモのリポジトリ〕の社長室〔持ち主への中継の部署〕の役「相談」など）の検査は、本文の語を見ずにこの値で見分けられる。
- **順番待ち**: 待ち受けの居る部署への頼みは、宛先の会社の受付箱の `queue/` に積み、受付番号と何件目かを返す（前の頼みを納品していない部署にも止めずに積む）。部署が前の頼みを納品したら、待ち受けが次の 1 件を渡し（部署の属性に頼みと頼み元を書いてから）、会話を再開させる。`fresh = true` の部署は、納品して止まった時点で空にし、空にした会話に次を渡す。同じ中身の頼みが積まれているか動いているなら、新しく積まずにその受付番号を返す。部署は頼みを 1 つずつ受け、頼み元の属性は渡すときに書く。待ち受けの居ない部署は今までどおり、前の頼みをまだ納品していなければ何もせずに止まる。先頭が詰まったら（部署が納品しないまま止まった）、`--tree` の部署の行に順番待ちの件数と置き場が出る。積んだファイルを消せば取り消せる。
- **今受けている頼みへの足し（`--note`）**（頼む側の会話か段取り〔部署への頼みを配る部署〕が打つ。言葉の意味は受付の設計 `docs/specs/2026-10-17-reception-design.md` の頭と 4.5）: 頼んだ後で、頼みを変える・足す・取り下げるときは、部署の窓に直に打たず、受付番号（頼み 1 件ずつに付く番号。例 `20261018-014838-3cd0d2`。`<受付>` にはこの番号を書く）に `--note <受付>` で足す（`--text` か `--brief`）。部署がその頼みを受けてターン（部署の会話の 1 回の応答）の途中でも、宛先の会社の台帳に足しの知らせ（`note`）を足し、部署の待ち受けがその応答の終わりに会話を再開させて渡す（入力フィールドには打たない）。頼みがまだ順番待ちに在れば、待ち受けが頼みを部署に渡すときに部署の会話へ送る 1 行（頼みの本文のファイルを指す文）に、足しを添える。待ち受け（応答の終わりにこのプラグインのフックが裏で走らせ、台帳の知らせを読んで会話を再開させる処理）が一度も走ったことの無い部署の会話（そのフックの無い前の版の works-dispatch で起動した物。台帳の知らせを読む者が居ない。待ち受けは、台帳をどこまで読んだかを、受付箱の `wake/` に、部署の worktree ごとに 1 つの `.pos` のファイル〔名前は worktree のパスから機械が作る〕で残す。`--note` がそのファイルの有無で見分けるので、打つ側は見分けなくてよい）には、今までどおり部署の窓に打ち込む。もう納品した頼みには足さずに止まる（新しい頼みで `--ask`）。ただし `--forward` で回して閉じた頼みなら、受付箱の台帳に `--forward` が残した、回した元と回した先をつなぐ行を、回した先がさらに回した先までたどり、まだ終わっていない（`--todo` の状態で、済〔納品された〕・取り下げ・届かず〔宛先に渡せなかった〕のどれでもない）頼みが 1 つならそちらに足す（その旨を出す）。回した先もみな閉じていれば止まり、2 つ以上なら並べて止まる（どれかの受付で打ち直す）。受けた部署は足しに別の納品をせず、今の頼みの納品にまとめる（取り下げなら、そこで止めて、どこまで済んだかを納品で返す）。打った場所・宛先・頼み元の受付箱の台帳に `note` の行が残る。
- **回したことで閉じる（`--ask … --forward`）**: 受けた頼みを自分で済ませず、ほかの部署へ頼んで回すとき（窓口が持ち主の頼みを部署へ配るときなど）は、回す `--ask` に `--forward` を添える。頼みが宛先に届いたら（送った・順番待ちに積んだ・同じ中身が動いている）、自分の受付箱と頼み元の受付箱の台帳に、受けた頼みの受付番号（`id`）と回した先の頼みの受付番号（`child`）と宛先（`to`）を結んだ行（`forwarded`）を書き、受けた頼みを納品済みにする。頼み元には知らせない（「どこへ回したか」だけの納品で頼み元の会話を再開させない）。頼み元は、結果か問いの納品で起きたときに、台帳の `forwarded` の行で、どの頼みがどこへ回ったかを追う。回した先の部署の納品は今までどおり回した側に届き、結果と問いは回した側が `--deliver <要約のファイル> --for <受付>` で頼み元へ返す（頼み元の会話を再開させる）。`--for` には回した元の受付か回した先の受付を渡す。自分の会社の受付箱の台帳の `forwarded` の行から元の受付と頼み元（会話の名前・会話の id・アカウント・ペイン・受付箱）を引き、その頼み元へ元の受付番号で返す。今受けている頼み（`company.ask`）は閉じない（`--for` を付けずに返すと、回した後に受けた別の頼みを納品済みにしてしまう）。台帳にその行が無ければ止まる。受けた頼みをまだ納品していない部署か窓口の場所から打たなければ止まる。`--take --ask`（受付番号と頼み元をそのまま回す）には要らない。
- **受けた頼みを閉じずに回した子の頼みの答えを返す（`--deliver --for`）**: 受けている頼みをまだ納品していない部署が `--forward` を付けずに `--ask` で頼むと、その頼み（子の頼み）の台帳の行に、受けている頼みの受付番号（`cause`）と、その頼みの頼み元（`cause_boss`）が残る。元の頼みを納品した後で子の頼みの答えが届いたら（残った疑問の担当者に子の受付番号を書いたときなど）、`--deliver <要約のファイル> --for <子の受付か元の受付>` で、元の頼み元へ元の受付番号で返す。頼み元が部署でない会話でも、別の会社の会話でも届く（頼み元の会話へ `--ask` で頼み直すと、部署でない宛先には部署を新しく立てようとして止まる）。`cause_boss` の無い前の版の行では、`cause` に書いた受付番号の頼みの行（台帳の `ask` の行）を探し、その行から頼み元を引く。探すのは受付箱の台帳（受付箱の `log.jsonl`）で、`--todo` と同じく、打った作業場の会社の受付箱から始め、台帳の行が指すほかの会社の受付箱へたどって読む（たどり方は `docs/ledger.md` の「会社をまたぐ読み方」）。打った部署がそのとき受けている頼み（`company.ask`。元の頼みを納品した後に受けた別の頼みなど）は閉じない。元の頼みがまだ納品されていなければ止まる（答えは元の頼みの納品に含めて返す）。`--for` で引き当てた台帳の行（`forwarded` の行か、子の頼みの行）は、この部署が書いた物でなければならない（行の `from.name`〔打った部署の名前〕が部署の属性 `company.name` と同じか、`from.place`〔打った作業場のパス〕がこの作業場のフォルダかその下）。ほかの部署が回した頼みの受付（子の受付でも元の受付でも）を渡すと、送らずに終了の値 2 で止まり、誰が回したかと、その頼みがもう納品で閉じていれば誰がどの納品で閉じたかを出す。この部署が受けた頼みの答えは、受けている間に `--for` を付けずに返す。前は、ほかの部署（仮に A）から受けた子の頼みの受付を渡すと、この部署の要約が、A がその子の頼みを出したときに受けていた頼み（`cause`）の納品として、その頼みの頼み元（`cause_boss`）へ届いた（A が受けていた頼みが、この部署から A への頼みなら、頼み元はこの部署なので、この部署自身へ）。
- **部署から窓口への頼み**: 窓口（`--desk` で名付けた本社の会話）も `--ask <窓口の名前>` で宛てられ、部署と同じに受付番号と頼み元の属性が付く。窓口は受けた頼みを、回した先か結果を `--deliver` で返して閉じる（閉じるまで止まる前のフックが促し、次の頼みは順番待ちに積まれる）。持ち主の答えを待つなら `--wait` で印す。
- **頼みの一覧（`--todo`）**: 受付箱の台帳から、頼みごとの今の状態（順番待ち・動いている・答え待ち・済・取り下げ・届かず）と、頼みの木（打った頼みの下に、その頼みを受けた部署が出した頼みと、回した先と、続きを付けた物）を、開いているブランチだけ字下げで出す。続きは、頼み A の納品の要約の「残った疑問」に、その疑問を最後まで追う者（担当者）として受付番号 B が書かれていたときの、頼み B である（A の下に `→ 続き: B` と出る。B がリマインダーなら `→ 続き（リマインダー）: B` と出て、閉じるまで A を開いている物と見る）。台帳の行が指すほかの会社の受付箱もたどって読む。`--todo <受付>`（末尾の 6 桁でもよい）でその頼みから下だけ（リマインダーの受付なら、そのリマインダーと、それを担当者に書いた頼み）、`--all` で済んだブランチも、`--json` で機械向けに、`--html <ファイル>` で 1 枚の HTML のページに出す。`--state <状態>`（順番待ち・動いている・答え待ち・済・取り下げ・届かず か英語の名前。カンマで区切って幾つでも）か `--to <宛先>`（部署の名前・会社の名前・「会社/名前」）を付けると、木にせず当たった頼みを更新の古い順に、宛先と古さ（その頼みの最後の台帳の行から打った時刻までの間）を添えて 1 行ずつ平らに並べる（`--state` を省けば開いている物だけ、`--all` で全部の状態）。「!」の注記とリマインダーの後、木か並びの前に、状態ごとの件数・済の割合（済 ÷ 届かずを除いた全件）・いちばん更新の古い開いた頼みを数えた 1 行を出す（`--json` は `summary`）。どの部署が次に動くターンかは出さない（部署の様子は `--tree`）。すぐ終わるので前景で打ってよい。行の形と状態の決め方は `docs/ledger.md`。
- **リマインダー（`--remind`）**: 部署か窓口（名前の有る会話）が、後で見ることを台帳（受付箱の `log.jsonl`。下の「受付箱」の項）に残す。メモの文に「次に X が起きたら見る」と書くだけだと、メモを読み直すまで思い出されず、条件が来ても流れる。見る時は、見る日（`--on`。打った機械の現地時刻の `YYYY-MM-DD` か `YYYY-MM-DDTHH:MM`。日付だけならその日の 0 時）と、閉じるのを待つ頼み（`--after <頼みの受付番号>`。何度でも付けられ、どれか 1 つが閉じれば見る時が来る。閉じたと見るのは、上の `--todo` の項の状態の済・取り下げ・届かずになったときで、ほかの部署へ回した頼みも済に当たる）のどちらかか両方を付け、両方付ければ先に来た方で見る時が来る。`--after` だけを付けたリマインダーは、その頼みが閉じるまで見る時が来ない。立てると、リマインダーの受付番号を出す（`--remind-done` に渡す番号。`--todo` にも出る）。条件を文でしか書けない待ち（「次に X が起きたら」「数が 25 件になったら」）は、機械が見分けられないので、見直す日を `--on` に付ける。見る時が来たら、`--ask` と `--deliver` のたびに works-dispatch が裏で打つ `--due`（[start.md](start.md)）が、打った会話の待ち受けへ「リマインダーです（受付 …）」の 1 行を 1 度だけ渡し、台帳に `reminded` の行を残す。打った部署がもう畳まれていれば（頼みを済ませて畳まれた tmp の部署〔頼まれたときだけ立てて、納品の後に畳む部署〕など。1 行を拾う待ち受けが無い）、同じ 1 行を頼みとして出す。部署の名前が、会社の形で `on_demand = true` と書いた受け持ち（on-demand）の名前なら、その受け持ちに頼み（部署が立つ）、ほかは会社の窓口に頼む。頼み元は会社の窓口で、通らなければ次の `--due` で頼み直す（頼みも納品も無い間は、`--due` を OS の予定に打たせていなければ〔[start.md](start.md)〕`--due` が走らず、知らせも出ない。その間に見る時の来た物を見るには `--todo` を打つ。`--todo` は打ったその時刻で見る時が来たかを判じる）。見たら `--remind-done <リマインダーの受付番号>` で閉じる。まだ早ければ閉じて、見る日を替えて `--remind` で立て直す。`--todo` は、受付番号を渡さないとき、見る時の来たリマインダーを、頼みの木（上の `--todo` の項）より前に「リマインダー:」の見出しを付けて出す（`--all` でまだ来ていない物と閉じた物も。`--json` は `reminders`）。行の形は `docs/ledger.md` の「リマインダー」。
- **受付箱**: 頼み元の会社の共通の `.git` の中の `company/inbox/`。頼みと納品の本文を 1 件 1 ファイルで置き、`log.jsonl` に誰が誰に何を頼み何が返ったかを 1 行ずつ足す。`.git` の中なので commit されず、勤め先のリポジトリの `.gitignore` も触らない。部署ごとの `.git/worktrees/<部署>/` ではなく共通の `.git` に置くのは、部署を片付けても（`git worktree remove`）記録を残すため。
