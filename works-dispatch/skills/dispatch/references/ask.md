# 頼む: `--ask` と順番待ち

dispatch のスキル（works-dispatch のプラグインの、Claude Code の会話を部署ごとに立てて仕事を頼むスキル。本体は [../SKILL.md](../SKILL.md)）の別ファイル。急ぎの操作は無い。窓口（本社で持ち主と話し、仕事を配る会話）や部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）の会話が、ほかの部署や会社に頼む・積んだ頼みを並べ替える・今の頼みに足すときに、読んでから下のコマンドを打つ。

言葉: dispatch は works-dispatch のプラグインのスクリプト。herdr は端末を作業場とペインに分け、中の Claude Code の会話を外から操作するツール。会社は部署を置いて回す git のリポジトリで、会社の形はその設定ファイル `.claude/company.toml`。本社は会社の代表の clone。部署は作業ごとの git worktree と、そこで働く裏の会話（`claude --bg` で起動した、画面を持たない会話）の組で、その会話を映す herdr のペインが窓。窓口は本社で持ち主（このスキルを使う人）と話し、部署に仕事を配る会話。役は部署と窓口の会話の決まり、受け持ちは部署ごとの仕事の範囲（会社の形の `[[skills]]`。`--tree`〔会社ごとに部署を並べる一覧。中身は [department.md](department.md)〕の「受ける仕事」の行に出る）。属性は部署の worktree や代表の clone の git の設定に書く `company.*` の値（`company.role` は役、`company.name` は部署の名前、`company.session` は会話の id）。頼みは部署に渡す仕事の文、納品は部署が結果の要約を頼み元へ返すこと。受付番号は頼み 1 件ずつに付く番号（例 `20261018-014838-3cd0d2`。コマンドの `<受付>` に書く）。順番待ちは、前の頼みをまだ納品していない部署への頼みを積んでおく列。受付箱・待ち受け・返事待ちの輪は下の同じ名前の項。

コマンドの選び方: 新しく頼む → `--ask`。順番待ちの 1 件を今受けるか、ほかの部署へ回す → `--take`。順番待ちから取り除く（か、台帳で開いていると出るのに順番待ちにも受けた部署にも無い頼みを閉じる） → `--withdraw`。順番待ちの先頭へ動かす → `--first`。順番待ちが渡らずに止まった部署を動かす → `--nudge`。今受けている頼みに足す → `--note`。頼みの一覧を見る → `--todo`。詳しい決まりは、下の、見出しにそのコマンドの名前を書いた項に在る（`--first` は「順番待ちから取り出す」の項）。

部署への頼みと、部署からの納品（要約を返すこと）は、相手の会話の**待ち受け**（会話のターン〔1 回の応答〕の終わりに、このプラグインのフックが裏で起動し、受付箱〔頼みと納品を置く代表の clone の `.git/company/inbox/`〕の台帳を見て会話を再開させる処理）が会話を再開させて届ける。人の打つ入力フィールドに字を打ち込まないので、人が窓口に打っている途中に納品が届いても混ざらない。待ち受けの居ない会話（このフックの無い古い版の会話・落ちた会話）には、今までどおり herdr の窓（相手の会話の画面を出したペイン）に 1 行を打ち込む。アカウントが違っても届く（SendMessage は同じアカウントの会話にしか届かないので使わない）。仕組みと決めた訳は、このプラグインの受付の設計 `docs/specs/2026-10-17-reception-design.md`。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --ask <会社/役 か部署の名前か会社の名前> (--text <文> | --brief <ファイル>) [--task <名前> --branch <ブランチ>] [--forward] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --take <受付> [--ask <宛先> [--task <名前> --branch <ブランチ>] [--text <添え書き>]] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --withdraw <受付> [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --first <受付> [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --nudge <部署> [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --note <受付> (--text <文> | --brief <ファイル>) [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --todo [<受付>] [--all] [--json | --html <ファイル>]
```

`--ask` の宛先に会社の名前だけを書くと、その会社の窓口（代表の clone で `--desk` を打って名付けた会話。`--tree` の「窓口」の行）に届く。部署でない会話（窓口など）がほかの会社に頼むときに、宛先の会社の窓口の役の名前を知らなくてよい。窓口を名付けていない会社では止まり、`--tree` の「受ける仕事」の宛て方で仕事ごとの部署に宛てるよう言う。宛先に「会社/」を付けずに 1 語だけ書いたときは、その語を次の順で当てる。1 番目は部署の名前（同じ名前の部署が在れば、そちらに届く）。2 番目は会社の名前（その会社の窓口に届く）。3 番目は頼む側の会社の中の役の名前（`--ask 作業` のように、自分の会社の役で宛てる書き方）。同じ名前の会社が 2 つ以上開いていれば止まる。部署でも窓口でもない会話（部署や窓口の属性の無い場所で動く会話）の納品は、待ち受けが居ないので、その会話の herdr の窓に 1 行を打ち込んで返す（herdr の外の会話には返らず、受付の台帳にだけ残る）。

- **待ち受け**: このプラグインのフックが、部署と窓口（属性 `company.role` と `company.name` の在る場所。窓口は `--desk` が書く）の会話のターンの終わり（Stop）と始まり（SessionStart。`/clear`・compact・resume を含む）に、裏で待ち受けを起動する（Claude Code のフックの `asyncRewake`。終了の値 2 で手の空いた会話を再開させる）。待ち受けは、その会社の受付箱の台帳 `log.jsonl` の、宛先が自分（「会社/名前」。前の名前も）の行だけを読み、宛先違いの行は会話に渡さない（会話の費用は 0）。待ち受けは会話ごとに 1 つで、印は受付箱の `wake/` に置く。窓口の待ち受けは、`--desk` が書いた会話の id の会話だけが張る（代表の clone で開いたほかの会話に知らせを横取りさせない。その会話が `/clear` で会話を空にして id が替わったときは、属性の id を新しい id に書き直して張る）。人の文でターンが始まると、その場所の待ち受けを止める（ターンの終わりに張り直す）。フックの持ち時間は 7 日で、それより長く手の空いた会話は、次のターンまで待ち受けの居ない会話として扱う。

- **宛先**: 部署の名前（属性 `company.name`。無ければ `--reorg`・`--desk` が覚えた前の名前）か「会社/役」か会社の名前。役は、会社の形 `.claude/company.toml` の `[[roles]]` に書いた部署の役の名前（例「作業」）。会社は herdr に開いているリポジトリ（`--tree` に出る会社の名前）で、省けば頼む側の会社。部署の名前、会社の名前（会社の形の在るリポジトリだけ。その会社の窓口へ届く）、頼む側の会社の役の順に当たる。役で宛てたときは、その役の永続の部署へ届け、無ければ新しい部署を `--task` と同じ道で立てる（新しく立てるときは、部署の名前を `--task`、ブランチの名前を `--branch` で渡す。省けば止まる）。役で宛てて部署の名前（`--task`）も渡したときは、その名前の部署へ届け、無ければ新しく立てる（同じ役の永続の部署が別の名前で居ても、その永続の部署へは届けない。ブランチの名前は `--branch` で渡す）。宛先の会社は、頼む会話が `--tree`（会社ごとに部署を並べる一覧）の「受ける仕事」（その会社が受ける仕事ごとの、頼むコマンドの宛先を並べたフィールド）を読んで選ぶ。
- **頼んだ会話と同じブランチ**: `--ask` で部署を新しく立てるとき、`--branch` に渡したブランチを、頼んだ会話の居る作業場（git の worktree）がもう開いていれば、`--ask` は部署を立てずに止まる。部署は、そのブランチを開いた worktree で起動するからで、止めたときの文は「部署を立てずにこの会話で進める」。そのまま頼んだ会話で作業を続ける（別の仕事なら別のブランチを `--branch` に渡す）。
- **部署が起動しなかった訳**: 部署を新しく立てる処理が会話を起動できなかったとき（そのブランチの worktree で会話がもう開いている、使えるアカウントが無い、など）は、受付箱の台帳 `log.jsonl` のその頼みの行の `detail` に、起動しなかった訳を 1 行で書く。`--ask` は 0 以外の終了コードで終わる。
- **頼み（`--ask`）**: 本文を頼む側の受付箱に置き、宛先の部署の窓に「頼みです（受付 <番号>、<頼む会話> から）: <本文>」と、返し方の 1 文（要約を項目で書いたファイルにして `--deliver` で返す、という指示）を打ち込む。改行を含むか長い本文は、受付箱のファイルを指す。本文が 2 行以上なら、頭に頭書き（1 行目と閉じの行が `+++` の TOML）を置き、`title`（`--todo` に出す 1 行の題）を書く（題の無い 2 行以上の本文は、書き方の例を出して止まる）。宛先の役が `ask_holders` を持つなら、残った疑問は頭書きの `[[open]]` に書く（書き方は [deliver.md](deliver.md) の「要約の書き方」と同じ）。題は台帳の頼みの行のフィールド `title` に残り、`--todo` は本文の行から題を拾わない。宛先の部署の属性に、受けた頼み（`company.ask`）と頼み元（会話の名前・アカウント・会話の id・ペイン・受付箱。`company.boss`・`company.boss-account`・`company.boss-session`・`company.boss-pane`・`company.boss-inbox`）を書く。新しく立てた部署には、最初の文で頼みを渡す。属性は毎回すべて書き直し、分からない値は消す（前の頼み元の値を残さない）。
- **順番待ち**: 待ち受けの居る部署への頼みは、宛先の会社の受付箱の `queue/` に積み、受付番号と何件目かを返す（前の頼みを納品していない部署にも止めずに積む）。部署が前の頼みを納品したら、待ち受けが次の 1 件を渡し（部署の属性に頼みと頼み元を書いてから）、会話を再開させる。`fresh = true` の部署は、納品して止まった時点で空にし、空にした会話に次を渡す。同じ中身の頼みが積まれているか動いているなら、新しく積まずにその受付番号を返す。部署は頼みを 1 つずつ受け、頼み元の属性は渡すときに書く。待ち受けの居ない部署は今までどおり、前の頼みをまだ納品していなければ何もせずに止まる。先頭が詰まったら（部署が納品しないまま止まった）、`--tree` の部署の行に順番待ちの件数と置き場が出る。積んだファイルを消せば取り消せる。
- **順番待ちから取り出す（`--take`・`--withdraw`）**: 順番待ちは積んだ順に渡る。急ぎの頼みを先に受けるときと、担当が長い頼みで埋まっている間に次の頼みをほかの部署へ回すときは、受付番号で 1 件を取り出す。`--take <受付>` を部署の場所から打つと、その部署の順番待ちの件を今受ける（待ち受けが渡すときと同じに頼み元の属性を書き、頼みの 1 行を出す。今の頼みを納品していなければ止まる）。`--ask <宛先>`（新しく立てるなら `--task`・`--branch` も）を添えると、どこからでも、受付番号と頼み元をそのままにほかの部署へ頼み直す。`--text` を添えると、回す側の添え書き（担当が回したこと・触らないファイルなど）を元の本文の前に置く。納品は元の頼み元に返る。頼み直せなければ、元の順番待ちの同じ場所に戻す。担当の部署が自分の仕事を並べて進めたいときもこの形で回す。担当の部署は、受け持ち（会社の形の `[[skills]]` に 1 つずつ書く仕事の範囲。例 `割り振り`）を永続で預かる部署で、その受け持ちの名前で立つ。担当の部署が仕事を回す先は、担当の部署とは別に新しく立てる役「作業」の一度きり（エフェメラル）の部署で、名前は `<受け持ちの名前>：<何をするか>`（例: `割り振り：スキルの説明`）にする。`--withdraw <受付>` は渡さずに取り下げる（頼み元が取り下げを頼んだときなど）。順番待ちに無い受付を渡すと、台帳（`log.jsonl`）がまだ開いている（順番待ち・動いている・答え待ち）と出す頼みに限り、取り下げの行を足して閉じる。順番待ちの件が台帳に行を残さずに消えた頼みと、受けた作業場が納品せずに消えたか、受けた部署がもうその頼みを受けていない頼みで、`--todo` の頭の「!」の注記がこれを指す。受けた部署がまだその頼みを受けている（納品していない）なら閉じずに止まるので、取り下げはその旨を `--note` で足す。`--first <受付>` はその順番待ちの先頭に回す（急ぐ物を先にする。渡すのは今の頼みの納品の後。後から回した物ほど前）。どれも、順番待ちの在る受付箱と頼み元の受付箱の台帳（`log.jsonl`）に 1 行を残す。`--take` は `taken` の行で、取り出した件より先に積まれていて追い越された件と、受けた先（その場で受けたならその部署、`--ask` で頼み直したならその宛先）を書く。`--withdraw` は `withdrawn` の行（順番待ちに無い頼みを閉じたときは、前の状態 `was` と訳 `why` を添える）。`--first` は `reordered` の行で、先頭に回した件が追い越した件を書く。自動では回さない（同じ受け持ちのファイルを 2 つの部署が書くのを避けられるかは、受け持ちを知る担当か窓口が決める）。例外は次の「返事待ちの輪」だけで、待ち受けが回す（回すのはまだ誰も手を付けていない順番待ちの頼みで、受ける作業の部署は自分の作業場とブランチで作る。回すときは輪の部署の作業場を見ないので、輪の部署の作業場に有る書きかけの変更とぶつかるかは、受けた作業の部署がメインブランチに入れる〔`--land`〕ときに初めて分かる）。
- **渡らずに止まった順番待ちを動かす（`--nudge`）**: 順番待ちが在るのに渡らない止まり方は 2 つ。ターンを終えたのに渡す待ち受けが居ない（`--tree` に「渡す待ち受けが居ない」）と、待ち受けは居るが渡さずに待っている（台帳のその場所の最後の行が `held`。`--tree` に「渡さずに待っている（訳）」）。`--nudge <部署>` は、部署の窓に会話が居なければ attach で戻し（戻った会話の始まりの待ち受けが渡す）、居て手が空いていて（herdr の状態が idle か done）入力フィールドが空なら、「ターンを 1 つ回す。受けている頼みが途中ならそれを続け、無ければ何もせずにターンを終える」の 1 行を打つ。ターンの初めに前の待ち受けが止まり、ターンの終わりに今の版の待ち受けが張り直して渡す。`--nudge` が 1 行を打たないのは、次の 2 つのときである。1 つは、部署の会話が動いているか入力フィールドに字が在るとき。もう 1 つは、`--tree` に出る待ち受けの訳が、裏の処理が残る・会話が動いている・入力フィールドに字が在る、のどれかのとき。これらの訳はすぐ替わり、待ち受けが 5 秒ごとに試し直して渡す。打てば、人の打ちかけの字と、待ち受けが会話を空にするために打つ `/clear` を壊す。区切り（`--rest`）・答え待ち（`--wait`）・終わり（`--done`）の印は部署の属性に書く値で、会話に 1 行打つと外れるので、`--nudge` は打った後に元の値を書き戻す。打ったか戻したかは台帳に `nudged` で残し、動かせなかったら終了の値 1。待ち受けの居る部署へ積む `--ask`（同じ中身が積まれていたときも）は、止まっていれば同じことを自分でする。持ち主に部署の窓へ打たせない。
- **返事待ちの輪（待ち受けがほどく）**: 頼みごとに会話を空にする部署（役が `fresh = true` の部署。受けた頼みを納品するたびに会話を `/clear` で空にし、空の会話で次の頼みを受ける）は、自分が出した頼み（子の頼み）の返事が来るまで、納品し終えても会話を空にせず、順番待ちの次も渡さずに待つ（返事を、その頼みを出した会話で受けるため。`--tree` に「渡さずに待っている（子の頼みの返事を待っている…）」）。出した頼みが相手の順番待ちに積まれたままで、相手も同じようにこちらへの頼みの返事を待っていると、どちらも動かない。部署が 3 つ以上でも、頼みを納品せずに返事を待つ部署が間に入っても同じである。待ち受け（部署の会話のターンの終わりに裏で走り、受付箱の台帳〔`.git/company/inbox/log.jsonl`〕を読んで頼みを渡す台本）は、この輪を台帳からたどって見つける。見つけたら、輪の頼みのうち受付番号の一番小さい物（一番古く出された物。輪が重なっていても、どの部署の待ち受けが見つけても同じ物を選ぶ）を、その頼みが積まれていた部署の会社で `--take <受付> --ask <会社>/<既定の役> --task <積まれていた宛先の部署の名前>：<受付の末尾 6 字> --branch work/ask-<受付の末尾 6 字>` で回す。回す先は、新しく立てる一度きりの部署で、役は既定の役（会社の形 `.claude/company.toml` の `default_role`、無ければ「作業」）。`--task` の名前の `：` の前は、その頼みが積まれていた順番待ちの部署（宛先）の名前。受付番号と頼み元はそのままで、納品は元の頼み元に返る。台帳には輪をほどいた印の `knot` の行が残り、`--take` の出力は受付箱の `takes/` に残る。`--take` が 0 以外で終わった（ほかの待ち受けと取り合って負けた・頼み直せずに順番待ちへ戻した）ときだけ、最初の回を含めて 3 回まで回す（終わりの値は、`--take` を会話から切り離して〔会話が止まっても止まらない別のプロセスとして〕走らせる包みの `/bin/sh` が、出力の置き場〔受付箱の `takes/`〕の終わりのファイルに書き、待ち受けがそれを読む。Windows ではそう走らせないので、最初の 1 回だけ回し、回し直さない）。回し切れなかった輪は、台帳の `knot` の行と `takes/` の出力に訳が残り、`--tree` に「渡さずに待っている」と出続けるので、今までどおり人か段取りが `--take` で回す。輪が重なっていれば、1 件回して残った輪を、回した頼みが渡って部署が動いた後に、待ち受けが次に輪を探す時（次のターンの終わりか、空にしない間の 5 秒ごとの見直し）に順にほどく。人が `--take` で回さなくてよい。
- **落ちた部署の会話**: `--ask` が頼みを送る前に毎回自動でする確かめ。PC やサーバーの再起動で部署の窓（attach の画面）が消えると、部署の窓に会話が居なくなる。部署の会話は裏の会話（`claude --bg` で起動した、画面を持たない会話。窓の attach の画面はそれを映しているだけ）で、その記録は残っているので、`--ask` は部署の窓のペインに `<部署のアカウントの起動コマンド（設定の command）> attach <短い id>` を打って前の続きから戻し、窓に会話が戻るのを見てから頼む。1 つの会話に id が 2 つ有る。短い id は会話の一覧（`claude agents --json` が出す、そのアカウントの会話の一覧）の `id`（8 字）で、attach に渡す。長い id は会話の記録の id で、部署の属性 `company.session`（部署の worktree の git の設定に書いた値）に残す。attach に長い id を渡すと Claude Code が「No job matching」と断る。窓に会話が居ない（会話が落ちた）と見るのは、次の 4 つのうち 1 つでも当たるとき。1 つ目は、ペインに会話の印（herdr がペインの情報に載せる、そこで動く会話の id `agent_session`）が無いとき。herdr は attach の画面が終わった後も会話の印を残すことがあるので、印が在っても 2 つ目から 4 つ目を見る。2 つ目は、ペインの前に居るプロセスがシェルのとき（この見分けは macOS・Linux だけでする。Windows は前のプロセスを見る口が当てにならないので見ない）。3 つ目は、どの OS でも、画面の終わりに「Session … has exited.」（attach の画面が終わった表示）が出ているとき。4 つ目は、会話の一覧がその会話を止まった（`stopped`・`failed`）と言うとき（裏の処理が止まると、窓の attach が「Waking session …」（裏の会話を再開させようとしている表示）のまま前に残り、窓の前のプロセスだけでは見分けられない）。そのときは、残った attach を Ctrl+Z でシェルに戻してから打ち直す。ペインを閉じて部署の作業場（herdr の作業場。worktree のフォルダは残る）が herdr から閉じていれば、作業場を開き直してから、その新しいペインで打つ。頼みと促しの 1 行は、会話の画面に入力フィールドが出てから送り、会話が動き出した（会話の一覧の status が busy）かを見て確かめる。入力フィールドに残っていれば Enter を足し、入力フィールドの外の画面に送った字が見えていれば、届いたと見て打ち直さない（二重に送らない）。入力フィールドにも画面にも見えず動き出してもいなければ打ち直す（3 回まで。どの OS でも同じ決まりで、打ち直しを入れた訳は、Windows で戻した直後の会話に送った文が、届かないか入力フィールドに残ったこと。3 回でも確かめられなければ failed を返し、部署の窓を見て入力フィールドに残っていれば Enter を押すよう出す）。送る前から動いている会話には 1 回だけ打つ（打った字は、今の応答が終わった後に読まれる待ちの列〔入力フィールドの上に「❯ <打った字>」と並ぶ〕に回るので動き出しでは確かめられず、打ち直すと同じ頼みが何度も届いた）。入力フィールドに残れば Enter を足し、入力フィールドの上（待ちの列）に載るか入力フィールドから出たのを見て届いたとし、見えなくても打ち直さない。会話は、部署の属性の会話の id（`company.session`）で一覧から引き、見つからなければ、一覧のうち作業フォルダが部署の作業場で、終わっていない（`done`・`failed`・`stopped` でない）裏の会話（`claude --bg` の会話）が 1 つだけならそれで見る（0 か 2 つ以上なら見つからないとする。部署の会話で `/clear` を打つと id が変わる）。頼みを届けたとき、id が変わっていれば属性を書き直す。開き直したペインにも、`--sync`（herdr の表示を部署の属性から付け直すコマンド。[reorg.md](reorg.md)）と同じく、部署の属性から読んだペインの名前・表示名（役）・題名・札を付ける。窓の端末に貼り付けの印（端末の貼り付けの切り替え〔bracketed paste〕が入ったままの状態）が残っていて打ったコマンドが崩れた（打った字の前後に `00~`・`01~` のような字が出る）ときは、部署の窓で `reset` を打ってから打ち直すよう、`--ask` の出力で知らせて止まる。落ちる前の頼みをまだ納品していなければ、戻した会話にその納品を促す 1 行を打ち、新しい頼みは送らずに止まる（納品が届いてから頼み直す）。ここまでは `--ask` が自動でする。戻せないとき（ペインの前にシェルが居ない・作業場が開いていない）は、`--ask` は打つコマンドを出して止まるので、そのコマンドを手で部署の作業場のペインで打つ。
- **今受けている頼みへの足し（`--note`）**（頼む側の会話か段取り〔部署への頼みを配る部署〕が打つ。言葉の意味は受付の設計 `docs/specs/2026-10-17-reception-design.md` の頭と 4.5）: 頼んだ後で、頼みを変える・足す・取り下げるときは、部署の窓に直に打たず、受付番号（頼み 1 件ずつに付く番号。例 `20261018-014838-3cd0d2`。`<受付>` にはこの番号を書く）に `--note <受付>` で足す（`--text` か `--brief`）。部署がその頼みを受けてターン（部署の会話の 1 回の応答）の途中でも、宛先の会社の台帳に足しの知らせ（`note`）を足し、部署の待ち受けがその応答の終わりに会話を再開させて渡す（入力フィールドには打たない）。頼みがまだ順番待ちに在れば、待ち受けが頼みを部署に渡すときに部署の会話へ送る 1 行（頼みの本文のファイルを指す文）に、足しを添える。待ち受け（応答の終わりにこのプラグインのフックが裏で走らせ、台帳の知らせを読んで会話を再開させる処理）が一度も走ったことの無い部署の会話（そのフックの無い前の版の works-dispatch で起動した物。台帳の知らせを読む者が居ない。待ち受けは、台帳をどこまで読んだかを受付箱の `wake/` に部署の場所ごとの `.pos` のファイルで残すので、そのファイルが無いかで見分ける）には、今までどおり部署の窓に打ち込む。もう納品した頼みには足さずに止まる（新しい頼みで `--ask`）。ただし `--forward` で回して閉じた頼みなら、台帳の回した線を回した先の先までたどり、まだ終わっていない（済・取り下げ・届かずでない）頼みが 1 つならそちらに足す（その旨を出す）。回した先もみな閉じていれば止まり、2 つ以上なら並べて止まる（どれかの受付で打ち直す）。受けた部署は足しに別の納品をせず、今の頼みの納品にまとめる（取り下げなら、そこで止めて、どこまで済んだかを納品で返す）。打った場所・宛先・頼み元の受付箱の台帳に `note` の行が残る。
- **回したことで閉じる（`--ask … --forward`）**: 受けた頼みを自分で済ませず、ほかの部署へ頼んで回すとき（窓口が持ち主の頼みを部署へ配るときなど）は、回す `--ask` に `--forward` を添える。頼みが宛先に届いたら（送った・順番待ちに積んだ・同じ中身が動いている）、自分の受付箱と頼み元の受付箱の台帳に、受けた頼みの受付番号（`id`）と回した先の頼みの受付番号（`child`）と宛先（`to`）を結んだ行（`forwarded`）を書き、受けた頼みを納品済みにする。頼み元には知らせない（「どこへ回したか」だけの納品で頼み元の会話を再開させない）。頼み元は、結果か問いの納品で起きたときに、台帳の `forwarded` の行で、どの頼みがどこへ回ったかを追う。回した先の部署の納品は今までどおり回した側に届き、結果と問いは回した側が `--deliver <要約のファイル> --for <受付>` で頼み元へ返す（頼み元の会話を再開させる）。`--for` には回した元の受付か回した先の受付を渡す。自分の会社の受付箱の台帳の `forwarded` の行から元の受付と頼み元（会話の名前・会話の id・アカウント・ペイン・受付箱）を引き、その頼み元へ元の受付番号で返す。今受けている頼み（`company.ask`）は閉じない（`--for` を付けずに返すと、回した後に受けた別の頼みを納品済みにしてしまう）。台帳にその行が無ければ止まる。受けた頼みをまだ納品していない部署か窓口の場所から打たなければ止まる。`--take --ask`（受付番号と頼み元をそのまま回す）には要らない。
- **部署から窓口への頼み**: 窓口（`--desk` で名付けた本社の会話）も `--ask <窓口の名前>` で宛てられ、部署と同じに受付番号と頼み元の属性が付く。窓口は受けた頼みを、回した先か結果を `--deliver` で返して閉じる（閉じるまで止まる前のフックが促し、次の頼みは順番待ちに積まれる）。持ち主の答えを待つなら `--wait` で印す。
- **頼みの一覧（`--todo`）**: 受付箱の台帳から、頼みごとの今の状態（順番待ち・動いている・答え待ち・済・取り下げ・届かず）と、頼みの木（打った頼みの下に、その頼みを受けた部署が出した頼みと、回した先と、続きを付けた物）を、開いているブランチだけ字下げで出す。続きは、頼み A の納品の要約の「残った疑問」に、その疑問を最後まで追う者（担当者）として受付番号 B が書かれていたときの、頼み B である（A の下に `→ 続き: B` と出る）。台帳の行が指すほかの会社の受付箱もたどって読む。`--todo <受付>`（末尾の 6 桁でもよい）でその頼みから下だけ、`--all` で済んだブランチも、`--json` で機械向けに、`--html <ファイル>` で 1 枚の HTML のページに出す。どの部署が次に動くターンかは出さない（部署の様子は `--tree`）。すぐ終わるので前景で打ってよい。行の形と状態の決め方は `docs/ledger.md`。
- **受付箱**: 頼み元の会社の共通の `.git` の中の `company/inbox/`。頼みと納品の本文を 1 件 1 ファイルで置き、`log.jsonl` に誰が誰に何を頼み何が返ったかを 1 行ずつ足す。`.git` の中なので commit されず、勤め先のリポジトリの `.gitignore` も触らない。部署ごとの `.git/worktrees/<部署>/` ではなく共通の `.git` に置くのは、部署を片付けても（`git worktree remove`）記録を残すため。
