# 頼む: `--ask` と順番待ち

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。窓口（本社で持ち主と話し、仕事を配る会話）や部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）の会話が、ほかの部署や会社に頼む・積んだ頼みを並べ替える・今の頼みに足すときに、読んでから下の命令を打つ。

部署への頼みと、部署からの納品（要約を返すこと）は、相手の会話の**待ち受け**（会話の番〔1 回の応答〕の終わりに、このプラグインのフックが裏で起こし、受付箱〔頼みと納品を置く代表の clone の `.git/company/inbox/`〕の台帳を見て会話を起こす処理）が会話を起こして届ける。人の打つ入力欄に字を打ち込まないので、人が窓口に打っている途中に納品が届いても混ざらない。待ち受けの居ない会話（このフックの無い古い版の会話・落ちた会話）には、今までどおり herdr の窓（相手の会話の画面を出したペイン）に 1 行を打ち込む。アカウントが違っても届く（SendMessage は同じアカウントの会話にしか届かないので使わない）。仕組みと決めた訳は、このプラグインの受付の設計 `docs/specs/2026-10-17-reception-design.md`。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --ask <会社/役 か部署の名前か会社の名前> (--text <文> | --brief <ファイル>) [--task <名前> --branch <枝>] [--forward] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --take <受付> [--ask <宛先> [--task <名前> --branch <枝>] [--text <添え書き>]] [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --withdraw <受付> [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --first <受付> [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --nudge <部署> [--dry-run]
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --note <受付> (--text <文> | --brief <ファイル>) [--dry-run]
```

`--ask` の宛先に会社の名前だけを書くと、その会社の窓口（代表の clone で `--desk` を打って名付けた会話。`--tree` の「窓口」の行）に届く。部署でない会話がほかの会社に頼むときに、宛先の会社の窓口の役の名前を知らなくてよい。窓口を名付けていない会社では止まり、`--tree` の「受ける仕事」の宛て方で仕事ごとの部署に宛てるよう言う。部署の名前が先に当たり（同じ名前の部署が在れば、そちらに届く）、会社の名前は頼む側の会社の役の名前より先に当たる。同じ名前の会社が 2 つ以上開いていれば止まる。部署でない会話の納品は、待ち受けが居ないので、その会話の herdr の窓に 1 行を打ち込んで返す（herdr の外の会話には返らず、受付の台帳にだけ残る）。

- **待ち受け**: このプラグインのフックが、部署と窓口（属性 `company.role` と `company.name` の在る場所。窓口は `--desk` が書く）の会話の番の終わり（Stop）と始まり（SessionStart。`/clear`・compact・resume を含む）に、裏で待ち受けを起こす（Claude Code のフックの `asyncRewake`。終了の値 2 で手の空いた会話を起こす）。待ち受けは、その会社の受付箱の台帳 `log.jsonl` の、宛先が自分（「会社/名前」。前の名前も）の行だけを読み、宛先違いの行は会話に渡さない（会話の費用は 0）。待ち受けは会話ごとに 1 つで、印は受付箱の `wake/` に置く。窓口の待ち受けは、`--desk` が書いた会話の id の会話だけが張る（代表の clone で開いたほかの会話に知らせを横取りさせない。その会話が `/clear` で会話を空にして id が替わったときは、属性の id を新しい id に書き直して張る）。人の文で番が始まると、その場所の待ち受けを止める（番の終わりに張り直す）。フックの持ち時間は 7 日で、それより長く手の空いた会話は、次の番まで待ち受けの居ない会話として扱う。

- **宛先**: 部署の名前（属性 `company.name`。無ければ `--reorg`・`--desk` が覚えた前の名前）か「会社/役」か会社の名前。会社は herdr に開いているリポジトリ（`--tree` に出る会社の名前）で、省けば頼む側の会社。部署の名前、会社の名前（会社の形の在るリポジトリだけ。その会社の窓口へ届く）、頼む側の会社の役の順に当たる。役で宛てたときは、その役の常設の部署へ届け、無ければ新しい部署を `--task` と同じ道で立てる（新しく立てるときは、部署の名前を `--task`、枝を `--branch` で渡す。省けば止まる）。役で宛てて部署の名前（`--task`）も渡したときは、その名前の部署へ届け、無ければ新しく立てる（同じ役の常設の部署が名前違いで居ても、そこへは届けない。枝は `--branch` で渡す）。宛先の会社は、頼む会話が `--tree` の「受ける仕事」を読んで選ぶ。
- **頼み（`--ask`）**: 本文を頼む側の受付箱に置き、宛先の部署の窓に「頼みです（受付 <番号>、<頼む会話> から）: <本文>」と、返し方の 1 文（要約を項目の見出しで書いたファイルにして `--deliver` で返す、という指示）を打ち込む。改行を含むか長い本文は、受付箱のファイルを指す。宛先の部署の属性に、受けた頼み（`company.ask`）と頼み元（会話の名前・アカウント・会話の id・ペイン・受付箱。`company.boss`・`company.boss-account`・`company.boss-session`・`company.boss-pane`・`company.boss-inbox`）を書く。新しく立てた部署には、最初の文で頼みを渡す。属性は毎回すべて書き直し、分からない値は消す（前の頼み元の値を残さない）。
- **順番待ち**: 待ち受けの居る部署への頼みは、宛先の会社の受付箱の `queue/` に積み、受付番号と何件目かを返す（前の頼みを納品していない部署にも止めずに積む）。部署が前の頼みを納品したら、待ち受けが次の 1 件を渡し（部署の属性に頼みと頼み元を書いてから）、会話を起こす。`fresh = true` の部署は、納品して止まった時点で空にし、空にした会話に次を渡す。同じ中身の頼みが積まれているか動いているなら、新しく積まずにその受付番号を返す。部署は頼みを 1 つずつ受け、頼み元の属性は渡すときに書く。待ち受けの居ない部署は今までどおり、前の頼みをまだ納品していなければ何もせずに止まる。先頭が詰まったら（部署が納品しないまま止まった）、`--tree` の部署の行に順番待ちの件数と置き場が出る。積んだファイルを消せば取り消せる。
- **順番待ちから取り出す（`--take`・`--withdraw`）**: 順番待ちは積んだ順に渡る。急ぎの頼みを先に受けるときと、担当が長い頼みで埋まっている間に次の頼みをほかの部署へ回すときは、受付番号で 1 件を取り出す。`--take <受付>` を部署の場所から打つと、その部署の順番待ちの件を今受ける（待ち受けが渡すときと同じに頼み元の属性を書き、頼みの 1 行を出す。今の頼みを納品していなければ止まる）。`--ask <宛先>`（新しく立てるなら `--task`・`--branch` も）を添えると、どこからでも、受付番号と頼み元をそのままにほかの部署へ頼み直す。`--text` を添えると、回す側の添え書き（担当が回したこと・触らないファイルなど）を元の本文の前に置く。納品は元の頼み元に返る。頼み直せなければ、元の順番待ちの同じ場所に戻す。担当の部署が自分の仕事を並べて進めたいときもこの形で回す。担当の部署は、受け持ち（会社の形の `[[skills]]` に 1 つずつ書く仕事の範囲。例 `割り振り`）を常設で預かり、その受け持ちの名前で立つ。回す先は役「作業」の一度きりの部署で、名前は `<受け持ちの名前>：<何をするか>`（例: `割り振り：スキルの説明`）にする。`--withdraw <受付>` は渡さずに取り下げる（頼み元が取り下げを頼んだときなど）。`--first <受付>` はその順番待ちの先頭に回す（急ぐ物を先にする。渡すのは今の頼みの納品の後。後から回した物ほど前）。どれも順番待ちの在る受付箱と頼み元の受付箱の台帳に、取り出した件（`taken`。飛ばした件と回した先）か取り下げ（`withdrawn`）か回した件（`reordered`。追い越した件）を残す。自動では回さない（同じ受け持ちのファイルを 2 つの部署が書くのを避けられるかは、受け持ちを知る担当か窓口が決める）。
- **渡らずに止まった順番待ちを動かす（`--nudge`）**: 順番待ちが在るのに渡らない止まり方は 2 つ。番を終えたのに渡す待ち受けが居ない（`--tree` に「渡す待ち受けが居ない」）と、待ち受けは居るが渡さずに待っている（台帳のその場所の最後の行が `held`。`--tree` に「渡さずに待っている（訳）」）。`--nudge <部署>` は、部署の窓に会話が居なければ attach で戻し（戻った会話の始まりの待ち受けが渡す）、居て手が空いていて（herdr の状態が idle か done）入力欄が空なら、「番を 1 つ回す。受けている頼みが途中ならそれを続け、無ければ何もせずに番を終える」の 1 行を打つ。番の初めに前の待ち受けが止まり、番の終わりに今の版の待ち受けが張り直して渡す。`--nudge` が 1 行を打たないのは、次の 2 つのときである。1 つは、部署の会話が動いているか入力欄に字が在るとき。もう 1 つは、`--tree` に出る待ち受けの訳が、裏の処理が残る・会話が動いている・入力欄に字が在る、のどれかのとき。これらの訳はすぐ替わり、待ち受けが 5 秒ごとに試し直して渡す。打てば、人の打ちかけの字と待ち受けの `/clear` を壊す。打った 1 行で外れる区切り・答え待ち・終わりの印は書き戻す。打ったか戻したかは台帳に `nudged` で残し、動かせなかったら終了の値 1。待ち受けの居る部署へ積む `--ask`（同じ中身が積まれていたときも）は、止まっていれば同じことを自分でする。持ち主に部署の窓へ打たせない。
- **落ちた部署の会話**: PC やサーバーの再起動で部署の窓（attach の画面）が消えると、部署の窓に会話が居なくなる。裏の会話の記録は残っているので、`--ask` は部署の窓のペインに `<部署のアカウントの起こし方（設定の command）> attach <短い id>` を打って前の続きから戻し、窓に会話が戻るのを見てから頼む。短い id は会話の一覧（`claude agents --json`）の `id`（8 字）で、部署の属性の長い id（`company.session`）では Claude Code が「No job matching」と断る。窓に会話が居ないと見るのは、ペインに会話の印が無いとき、前に居るのがシェルのとき（macOS・Linux。herdr は attach の画面が終わった後も会話の印を残すことがある）、画面の終わりに「Session … has exited.」が出ているとき。会話の一覧がその会話を止まった（`stopped`・`failed`）と言うときも落ちたと見る（裏の処理が止まると、窓の attach が「Waking session …」のまま前に残り、窓の前のプロセスだけでは見分けられない）。そのときは、残った attach を Ctrl+Z でシェルに戻してから打ち直す。ペインを閉じて部署の作業場が herdr から閉じていれば、作業場を開き直してから、その新しいペインで打つ。頼みと促しの 1 行は、会話の画面に入力欄が出てから送り、会話が動き出した（会話の一覧の status が busy）かを見て確かめる。入力欄に残っていれば Enter を足し、入力欄にも画面にも見えず動き出してもいなければ打ち直す（3 回まで。Windows で、戻した直後の会話に送った文が、届かないか入力欄に残った。3 回でも確かめられなければ failed を返し、部署の窓を見て入力欄に残っていれば Enter を押すよう出す）。送る前から動いている会話には 1 回だけ打つ（打った字は、今の応答が終わった後に読まれる待ちの列〔入力欄の上に「❯ <打った字>」と並ぶ〕に回るので動き出しでは確かめられず、打ち直すと同じ頼みが何度も届いた）。入力欄に残れば Enter を足し、入力欄の上（待ちの列）に載るか入力欄から出たのを見て届いたとし、見えなくても打ち直さない。会話は、部署の属性の会話の id（`company.session`）で一覧から引き、見つからなければ、一覧のうち作業フォルダが部署の作業場で、終わっていない（`done`・`failed`・`stopped` でない）裏の会話（`claude --bg` の会話）が 1 つだけならそれで見る（0 か 2 つ以上なら見つからないとする。部署の会話で `/clear` を打つと id が変わる）。頼みを届けたとき、id が変わっていれば属性を書き直す。開き直したペインにも、`--sync` と同じ名前・表示名・札を付ける。窓の端末に貼り付けの印が残っていて打った命令が崩れた（画面に `00~` が出る）ときは、部署の窓で `reset` を打ってから打ち直すよう、`--ask` の出力で知らせて止まる。落ちる前の頼みをまだ納品していなければ、戻した会話にその納品を促す 1 行を打ち、新しい頼みは送らずに止まる（納品が届いてから頼み直す）。戻せないとき（ペインの前にシェルが居ない・作業場が開いていない）は、打つ命令を出して止まる。手で戻すときも、部署の作業場のペインで同じ命令を打つ。
- **今受けている頼みへの足し（`--note`）**（頼む側の会話か段取りが打つ。言葉の意味は受付の設計 `docs/specs/2026-10-17-reception-design.md` の頭と 4.5）: 頼んだ後で、頼みを変える・足す・取り下げるときは、部署の窓に直に打たず、受付番号に `--note <受付>` で足す（`--text` か `--brief`）。部署がその頼みを受けて番の途中でも、宛先の会社の台帳に足しの知らせ（`note`）を足し、部署の待ち受けが番の終わりに会話を起こして渡す（入力欄には打たない）。頼みがまだ順番待ちに在れば、渡すときの 1 行に足しを添える。待ち受けを一度も張ったことの無い部署の会話（待ち受けのフックの無い前の版の works-dispatch で起こした物。台帳の知らせを読む者が居ない）には、今までどおり部署の窓に打ち込む。もう納品した頼みには足さずに止まる（新しい頼みで `--ask`）。受けた部署は足しに別の納品をせず、今の頼みの納品にまとめる（取り下げなら、そこで止めて、どこまで済んだかを納品で返す）。打った場所・宛先・頼み元の受付箱の台帳に `note` の行が残る。
- **回したことで閉じる（`--ask … --forward`）**: 受けた頼みを自分で済ませず、ほかの部署へ頼んで回すとき（窓口が持ち主の頼みを部署へ配るときなど）は、回す `--ask` に `--forward` を添える。頼みが宛先に届いたら（送った・順番待ちに積んだ・同じ中身が動いている）、自分の受付箱と頼み元の受付箱の台帳に、受けた頼みの受付番号（`id`）と回した先の頼みの受付番号（`child`）と宛先（`to`）を結んだ行（`forwarded`）を書き、受けた頼みを納品済みにする。頼み元には知らせない（「どこへ回したか」だけの納品で頼み元の会話を起こさない）。頼み元は、結果か問いの納品で起きたときに、台帳の `forwarded` の行で、どの頼みがどこへ回ったかを追う。回した先の部署の納品は今までどおり回した側に届き、結果と問いは回した側が `--deliver <要約のファイル> --for <受付>` で頼み元へ返す（頼み元の会話を起こす）。`--for` には回した元の受付か回した先の受付を渡す。自分の会社の受付箱の台帳の `forwarded` の行から元の受付と頼み元（会話の名前・会話の id・アカウント・ペイン・受付箱）を引き、その頼み元へ元の受付番号で返す。今受けている頼み（`company.ask`）は閉じない（`--for` を付けずに返すと、回した後に受けた別の頼みを納品済みにしてしまう）。台帳にその行が無ければ止まる。受けた頼みをまだ納品していない部署か窓口の場所から打たなければ止まる。`--take --ask`（受付番号と頼み元をそのまま回す）には要らない。
- **部署から窓口への頼み**: 窓口（`--desk` で名付けた本社の会話）も `--ask <窓口の名前>` で宛てられ、部署と同じに受付番号と頼み元の属性が付く。窓口は受けた頼みを、回した先か結果を `--deliver` で返して閉じる（閉じるまで止まる前のフックが促し、次の頼みは順番待ちに積まれる）。持ち主の答えを待つなら `--wait` で印す。
- **受付箱**: 頼み元の会社の共通の `.git` の中の `company/inbox/`。頼みと納品の本文を 1 件 1 ファイルで置き、`log.jsonl` に誰が誰に何を頼み何が返ったかを 1 行ずつ足す。`.git` の中なので commit されず、勤め先のリポジトリの `.gitignore` も触らない。部署ごとの `.git/worktrees/<部署>/` ではなく共通の `.git` に置くのは、部署を片付けても（`git worktree remove`）記録を残すため。
