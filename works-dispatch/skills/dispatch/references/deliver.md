# 納品する: `--deliver`

dispatch のスキル（works-dispatch のプラグイン）の別ファイル。部署（作業ごとの worktree と、そこで働く Claude Code の会話の組）の会話が、頼まれた仕事の要約を頼み元へ返す（納品する）・人の答えを待つ・会話を空にする区切りを印すときに、読んでから下のコマンドを打つ。ここでの言葉:

- herdr: 端末の画面を作業場とペインに分けて Claude Code の会話を並べるツール。窓は、ある会話を映した herdr のペイン。
- 受付箱: 頼みと納品の本文と台帳 `log.jsonl` を置く、会社の代表の clone（部署を作る元の clone）の `.git/company/inbox/`。
- ターン: 会話の 1 回の応答。待ち受けは、ターンの終わりにこのプラグインのフックが裏で起動し、受付箱の台帳の自分宛ての行を見て会話を再開させる処理。「待ち受けが居る」は、その会話に待ち受けが張られていること。

```
bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/dispatch/dispatch.py" --deliver <要約のファイル> [--for <受付> | --again] [--dry-run]
```

- **納品（`--deliver`）**: 部署の場所から走らせる。要約の項目がそろっているかを確かめ、欠けていれば送らずに欠けた項目を出して終了の値 2 で止まる。そろっていれば頼み元（この部署に頼んだ会話）の会社の受付箱に置き、頼み元（宛先の名前は、頼み元の会社の名前と、部署の属性 `company.boss` に書いた頼み元の名前を `/` でつないだ物）の待ち受けが居ればその台帳に知らせの 1 行を足し、居なければ頼み元の窓に「納品です（受付 <番号>、<部署>・ブランチ <ブランチ> から）: 【結論】…【決め手】…（全文: <パス>）」を打ち込み、属性に納品済み（`company.delivered`）を書く。部署の会社の形（`.claude/company.toml`）のメインブランチへの入れ方（`[land]` の `mode`。部署の役ごとの上書きが在ればそれ。「メインブランチに入れる」）が `ff-after-ci` なら、納品の後に、その会社の代表の clone の手元のメインブランチを origin のメインブランチの先頭へ fast-forward する（`git merge --ff-only`。`--land` も push の後に同じ fast-forward をする。部署が `--land` を通さずに手で push した成果も代表の clone に届ける。ほかの入れ方の会社の代表の clone は動かさない。進められなければ、その会社の窓口〔`--desk` で名付けた会話〕へ、受付箱の台帳に知らせの 1 行を足して渡す）。頼み元の会話が終わった（窓が無く、会話の一覧〔`claude agents --json` が出す、そのアカウントの会話の一覧〕にも生きた頼み元の会話が無い）ときは、要約を受付箱に置き、頼み元の名前（「頼み元の会社/`company.boss`」）に宛てた知らせの 1 行を台帳に足して、納品済みにする（台帳の status は `posted`。頼み元の名前の待ち受けが後で張られれば、その知らせで起きる。待たずに納品済みにするのは、前は頼み元の窓が開くのを待って納品済みにしなかったが、終わった会話の窓はいつまでも開かないので、部署が納品待ちのまま次の頼みを受けられなくなっていたため）。頼み元の会話は生きているのに窓を 1 つに決められない・頼み元が誰か分からない・窓は在るのに打てなかった（herdr の誤り）ときは、終了の値 1 で知らせ、納品済みにはしない（打ち直す）。要約のファイルは納品ごとに別にする（打ち直しで前の要約を消さない）。部署に渡す返し方のコマンドは、今動いている Python と dispatch.py のパスを `/` 区切りで引用符に包んだ形にする（Windows の Git Bash でも崩れない）。そのパスはプラグインの版の置き場の中なので、プラグインを上げた後は前の版を指す（Claude Code は前の版の置き場を 14 日残す）。dispatch.py は、版の置き場の中で動いていて、Claude Code の入れた物の控え（`installed_plugins.json`）が今の版を別の置き場と言えば、そちらの dispatch.py を同じ引数で起動し直す（前の版が、後の版で足した決まり〔会社の形の `[[land.after]]` など〕を黙って飛ばさないため）。
- **同じ頼みへの 2 通目（`--again`）**: 今受けている頼み（部署の属性 `company.ask`）を納品した後（`company.delivered` が同じ受付）に、`--for` も `--again` も付けずに `--deliver` を打つと、送らずに終了の値 2 で止まり、頼み元の受付箱（部署の属性 `company.boss-inbox`）が読めれば、その頼みの本文と送った要約のパスを出す。今受けている頼み（`company.ask`）が、この部署が `--forward` でほかの部署へ回して閉じた物なら、頼みの本文と要約のパスは出さず、`--for` に `company.ask` の受付番号を付けて打ち直すよう出す（回した先の部署から届いた結果か問いを、頼み元へ返す打ち方）。出た頼みの本文と送った要約を、今送ろうとした要約と見比べる。今の要約が同じ頼みの続き（この部署がその頼みを納品した後に気づいた、頼み元に判断してほしいことや、送った要約の直し）なら、`--again` を付けて打ち直す。ほかの頼みの答えは、その受付を `--for` に渡す（[ask.md](ask.md) の「受けた頼みを閉じずに回した子の頼みの答えを返す」）。前は黙って同じ受付へ 2 通目を送り、前に受けた別の頼みの要約が、済んだ頼みの納品として頼み元に届いた（2026-10-18 の割り振り。my_notes の段取りの受付 20261018-233916-b54685）。
- **答え待ち（`--wait <訳>`）**: 部署の場所から走らせる。今の頼みが人の答えを要って止まっている（持ち主に聞いて、答えが数時間後になる など）と、部署の属性 `company.waiting`（受付番号）と `company.waiting-why`（訳）に書く。その頼みの間、止まる前のフックは納品を促さない（促しはターンの終わりごとに同じ頼みにつき 3 回まで出るので、答えを待つ部署が無駄にターンを回していた）。その会話に文が打たれると（人の答えのほか、窓に打ち込まれた知らせも）、文を受けたフックが印を外し、また納品を促す。納品でも外れる。A2A の頼みの状態 `input-required`（人の入力が要って止まっている）に当たる。役の名前は見ないので、どの役の部署でも使える。
- **区切り（`--rest`）**（この項は、会話が区切りを印した後に機械がすることの説明。いつ打つかは役の本文が決める）: 会話を引き継ぐ部署と窓口（`--desk` で名付けた本社の会話）が、文脈がたまり続けないよう、今は会話を空にしてよい区切りだと自分で印す（部署の属性 `company.rest` に、その場所の会話の id を書く）。そのターンの終わりに待ち受けが、窓の入力フィールドが空で会話が止まっていれば、窓に `/clear` を打って空にし、印を外す（会社の形の起動の設定が、会話を起動したときの設定と違えば、`/clear` の代わりにその設定で起動し直す。「ほかのアカウントで起動し直す」）。入力フィールドの薄字（Claude Code が出す次の文の候補と、空の入力フィールドの例の字。打てば消える）は、打ちかけの字と数えない。空にできないまま次の頼みか納品を渡すときは、空にできなかった訳（会話が動いている・人の打ちかけの字が在る、など）を、会話に渡す文の頭に添え、受付箱の台帳 `log.jsonl` の、渡したことを書く `handed` の行にもフィールド `unrested` で残す（黙って前の会話のまま渡し続けない）。空にした後の会話の始まりに役の本文が足され、本社の窓口は会話の id の付け直し（`company.pid` の追従）で頼みと納品をそのまま受ける。どこを区切りにするか（例: 受けた頼みを全部納品で閉じ、会話の中にしか無いことをファイルに書き終えたとき）は、各会社の形の役の本文に書き、このプラグインでは決めない。納品していない頼みが在る間は印せず、空にもしない。人がその会話に打つと印が外れる（持ち主と話している途中の会話は空にしない）。持ち主が手で compact する道はそのまま。本社では、待ち受けは、herdr がペインごとに持つ会話の印（`agent_session`）がその窓口の会話の id と同じペインにだけ `/clear` を打つ（本社に会話の居るペインがほかにも在っても、持ち主のほかの会話には打たない）。
- **compact の区切り（`--compact [焦点]`）**（いつ打つかは役の本文が決める）: 部署か窓口の会話が、同じ仕事の前の部分が済み、続きは要約で足りる区切りで、ここで compact してよいと自分で印す（`--compact` を打った作業場〔部署の worktree か、窓口の居る本社の clone〕の属性 `company.compact` に、その会話の id、`company.compact-focus` に焦点）。属性に会話の id（`company.session`）の無い場所では印せない（印がその会話の物かを見分けられない）。`--rest` と違い、納品していない頼みが在っても印せる。印したターンの終わりは、止まる前のフックが納品を促さない。そのターンの終わりに待ち受けが、会話の記録の最後の応答の文脈が 10 万トークン（`nodes/wake.py` の `COMPACT_FLOOR`）以上で、窓の入力フィールドが空で会話が止まっていれば、窓に `/compact <焦点>` を打つ（ターンの終わりの直後に会話がまだ動いていると見えたら、30 秒まで手が空くのを待つ。打った字が入力フィールドに残れば Enter を 1 回足す）。compact が済んで会話が始まり直した時（SessionStart のフック）に、同じ待ち受けが印を外し、「compact した。続ける」の 1 行で会話を起動する。文脈が 10 万トークンより小さい（compact の費用の元が取れない）・会話の記録から文脈の大きさを読めない・30 秒待っても会話が動いている・入力フィールドに字が在る・打ったが 10 分で済んだのを見られない、のどれかなら、compact せずに印を外し、訳を添えて会話を起動する。裏の処理（会話が `run_in_background` で走らせた Bash や、裏で動くサブエージェント。終わると知らせで会話が再開する）が残る間は印を残し、それが終わった後のターンの終わりにまた試す。焦点に書けない長いもの（次の手の細部など）は、ターンを終える前にファイルに書いておく（要約は細部を落とす）。区切り（`--rest`）か終わり（`--done`）の印が同じターンに在れば、compact しない。人がその会話に打つと印が外れる（待ち受けが打った `/compact` では外れない）。
- **要約の書き方**: 機械が読むフィールド（残った疑問）は、要約の頭の頭書き（1 行目と閉じの行が `+++` の TOML。Hugo の front matter と同じ形）に書き、ほかの項目は見出し（`## 結論`。英語の `## Conclusion`・`## Evidence`・`## Branch` も同じ項目に当たる）か行の頭の札（`結論: …`）で書く。残った疑問は `[[open]]` に 1 件ずつ `question`（疑問）と `holder`（最後まで追う担当者）で書き、無ければ `open = []` と書く。本文に「残った疑問」の見出しを書く・頭書きに知らないフィールドが在る・最初の見出しの前に字が在る、のどれかなら送らずに書き方の例を出して止まる。決まった項目の外の見出し（`## 参考になりうる点` など）は落とさずにそのまま送る。送る要約の「残った疑問」の項目は、頭書きから機械が書く（`- <疑問> 担当者: <担当者>`、無ければ「なし」）。部署の役が会社の形の `holders` を持てば、担当者が下の例のコメントの 4 つ（受付番号・`owner:choose`・`owner:confirm`・頼み元の名前）のどれかかを確かめる。担当者が受付番号（`--ask` が頼みを出したときに出す番号）なら、その番号が、届いた（status が `failed` でない）頼みか、まだ閉じていないリマインダー（`--remind` が出す受付番号。後でしか起きない事を追う疑問の担当者に書く。`--todo` は閉じるまで続きとして追う）として、受付箱の台帳（`.git/company/inbox/log.jsonl`）に在るかも確かめる。閉じたリマインダーは止める。探す台帳は、`--deliver` を打った場所の会社の受付箱と頼み元の受付箱の台帳から始め、台帳の行がほかの会社の受付箱を指していれば、そこの台帳もたどる（`--todo` と同じたどり方）。違えば送らずに止まる。受付番号で止まったら、`--ask` の出力の受付番号を `holder` に写して打ち直す（`--ask` の出力を待たずに書いた番号は、どの台帳にも無く、`--todo` がその疑問を誰にも追わせられない。届かなかった頼みは `--todo` が閉じた物と見て追わない。my_notes の受付 20261019-022419-b50f85）。

```toml
+++
[[open]]
question = "…を決める"
holder = "20261018-120448-b6778d"   # 受付番号（頼みか、閉じていないリマインダー）・owner:choose（持ち主が価値で選ぶ）・owner:confirm（持ち主が確認してからやる）・頼み元の名前
+++
## 結論
…
```

- **要約の項目**: 既定は「結論」（3 行以内）・「決め手」（原文の一句と原典の URL）・「残った疑問」・「ブランチ」（書かなければ部署のブランチを機械が足す）。役ごとに会社の形（その会社の代表の clone の `.claude/company.toml`、無ければ設定の置き場の同じ書き方のファイル）の `[[roles]]` の `deliver` で替えられる（[roles.md](roles.md) の「役の中身と起動方法」で述べる、その役の `[[roles]]` の項目に書く）。`--ask` が打ち込む返し方の 1 文には、その役の要る項目と、項目に付く決まり（結論は 3 行以内・決め手には原典の URL が要る など）を書く。決め手の URL の決まりは、決め手の項目を持つ役すべてに掛かる（既定の項目に残しているのは調べものの役のため。要らない役は `deliver` から決め手を外す）。コードを書く部署なら、たとえば次のように書く:

```toml
[[roles]]
name = "作業"
deliver = ["結論", "差分", "試験", "残った疑問", "ブランチ"]
```

- **納品の検査（`deliver_check`）**: 会社の中身の決まり（調べものの URL の原典を全部 `reference/` に残す、など）を、文で頼むだけでなく納品の時に機械で確かめる口。役の `deliver_check` にシェルのコマンドを書くと、`--deliver` が項目を確かめた後（`--dry-run` でも）に、部署の作業場（worktree）のルートで走らせる。何を確かめるかは会社の側のスクリプトが持ち、dispatch は決め打ちしない。
  - 渡す物: 標準入力に JSON の物を 1 つ。`role`（役の名前）・`ask`（受付番号。`--task` だけで立てた部署は `null`）・`branch`（部署のブランチ）・`place`（走らせた作業場のルートの絶対パス）・`items`（項目の名前 → 本文。ブランチは機械が足した後）・`open`（頭書きの残った疑問の並び `[{"question", "holder"}]`。無ければ空の並び）・`summary`（頼み元の受付箱に置く要約の本文と同じ字）・`version`（走らせた works-dispatch の版。読めなければ `null`。会社の側の台本が版の下限を確かめるのに使う。会社の形に下限のフィールドは置かない〔古い版は知らないフィールドを読み飛ばすので、フィールドでは止まらない〕。このフィールドの無い入力は、このフィールドを足した版〔`CHANGELOG.md` の Added に書いた版〕より前の版から来ている）。
  - 終わりの値: 0 なら通り、そのまま送る。0 以外（スクリプトが見つからない 127 や、動かないときも）なら頼み元に送らず、`--deliver` は終了の値 2 で止まり、検査の標準出力と標準エラーを合わせた終わりの 20 行を `--deliver` の出力に出す（打った部署が読む）。訳（どの URL が `reference/` に無いか など）は検査が出力に書く。部署はそれを直して打ち直す。納品済みにしないので、止まる前のフックも差し戻し続ける（同じ頼みで 3 回まで。下の「止める前の差し戻し」）。
  - 時間の上限は付けない。検査を飛ばす旗も作らない（部署が自分で飛ばせるゲートはゲートにならない）。検査が壊れて誰も納品できないときは、会社の形の `deliver_check` を直してメインブランチに入れる。
- **止める前の差し戻し**: このプラグインの Stop フックが、部署（`company.role` の在る場所）の会話で、受けた頼みを納品しないまま止まろうとしたら、納品のコマンドで返すよう差し戻す。同じ会話・同じ頼みで 3 回まで差し戻し、その後は止まるのを許す。部署でない場所と、`--ask` で頼まれていない部署（`--task` だけで立てた部署）では何もしない。納品し終えた後も、部署（窓口でない）が次のどちらかのまま止まろうとしたら差し戻す（数えるのは納品の前と別に、同じ会話・同じ頼みで 3 回まで）。
  - ブランチの先頭がメインブランチ（origin の既定のブランチの手元の控え）に入っていない: `--land <部署>` で入れるか、`--land` が自動の権限の判定に止められたなら、入れてほしいと窓口に `--ask <会社の名前>` で頼むよう差し戻す。この差し戻しを出すのは、会社の形（その会社のリポジトリの `.claude/company.toml`）の `[land]`（メインブランチへの入れ方を書くセクション）の `mode` が `ff-after-ci`（ゲート〔CI か手元の検証〕が緑なら、PR を通さずに fast-forward でメインブランチに入れる取り込み方）の会社だけ（PR で入れる会社では、ブランチがメインブランチに入るのは人の見直しの後なので出さない）。2026-10-17 に my_notes で、`--land` が止まった部署が残った疑問に「持ち手: 段取り」（「持ち手」はその疑問を最後まで追う部署、段取りは my_notes の会社で部署への頼みを配る窓口の役の名前）と書いただけで段取りに `--ask` で頼まず、誰も追わないまま 1 日残った。
  - エフェメラルの部署（一度の頼みのために立てて終われば畳む部署。頼みごとにブランチを移って残り続けるのは永続の部署）で、ブランチもメインブランチに入っている（commit の無い部署も）のに終わりの印（エフェメラルの部署が自分で `--done` を打って部署の属性 `company.finished` に書く、畳んでよいという印）が無い: `--done` を打つよう差し戻す。

  この部署が頼んで返事（納品）の来ていない頼みが在る間（この部署の納品の残った疑問の担当者に書いた頼みは数えない）・順番待ちに頼みが在る間・終わりの印が在る間は差し戻さない。永続の部署は、ブランチがメインブランチに入っていないときだけ差し戻す。部署の会話は、差し戻されたら、その文に書かれた手（`--land`・窓口への `--ask`・`--done` のどれか）を打ってから止まる。
