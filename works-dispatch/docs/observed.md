# 試しの実行で確かめた外の振る舞い（2026-10-14〜2026-10-16）

dispatch が頼る herdr・Claude Code・git・gh の振る舞いのうち、文書に無く、手元で打って確かめた物の記録。使い始め方は [README](../README.md)、使う人向けの手順の全部は [SKILL.md](../skills/dispatch/SKILL.md) と、そこから主題ごとに指す別ファイル（`skills/dispatch/references/`）。下の記録の部署は、dispatch が作業ごとに立てる git worktree 1 つと、そこで動く Claude Code の会話 1 つの組で、役は部署の会話に持たせる役割（会社の形 `.claude/company.toml` に書き、役ごとに設定とモデルを決める）。

確かめた版は、herdr 0.9.3、Claude Code 2.1.299、git 2.50.1（Apple Git-155）、gh 2.102.0。項の頭に別の版を書いた物は、その版で確かめた。版が変わったら、ここを確かめ直す。

- herdr の `agent wait` は、まだ会話を見つけていないペインでは待たずに `agent_not_found` を返す。`herdr.wait_ready` は、ペインで前面に動いているプロセス（`pane process-info`）を見て待ち直す。
- herdr の `pane run` は、成功しても何も出力しない。`workspace close` は 2026-10-14 には何も出さず、2026-10-15 には `{"result": {"type": "ok"}}` を返した（どちらも受ける）。
- `herdr agent prompt` で送った `/exit` は、文字は入るが送信されなかった（Enter をもう 1 回押す必要があった）。`/attention:catchup 1737` は 1 回で送信された。違いの理由は調べていない。
- 新しいフォルダで Claude Code を起動すると、信頼の確認が出る。2.1.301 では、この画面の Esc は「取り消し」で、既定の選び（No, exit）と同じく会話を始めずに終わり、そのフォルダは信頼済みとして記録されない（`~/.claude.json` の `projects` に、そのフォルダの項目が増えない）。2026-10-16 に、使い捨てのフォルダで起動して Esc を送り、確かめた（まっさらな環境での 2 回目の試し `docs/trials/2026-10-16-clean-env-2.md` の「1 回目の 14 件の今」の 12 と同じ）。前の版のこの行は「Esc で会話が進み、信頼済みになる」と書いていたが、今の版とは逆。信頼するには「Yes, I trust this folder」を選んで Enter を押す。
- herdr の worktree の口（2026-10-15 に、一時の git リポジトリに打って確かめた。出力の写しは `dispatch/tests/test_ports.py`）:
  - `worktree list --cwd <元の clone>` は、herdr で開いていないリポジトリに打っても作業場を開かない。`worktree create` は、その元の clone の作業場も開く。
  - 自分の持ち物のリポジトリでは、`worktree create` に `--trust-repository` は要らなかった。
  - `worktree open --path <場所>` だけでは `worktree_not_found` が返り、`--cwd <元の clone>` を足すと開いた。開いている場所に打つと、`already_open: true` でその作業場を返す。
  - `worktree remove --workspace <ID>` は、未追跡のファイルが有ると `dirty_worktree_requires_force` で断る。消すと作業場も閉じ、手元のブランチは残る。
  - 元の clone が開いているブランチで `worktree create` を打つと、git の「already used by worktree」で `worktree_create_failed` になる。dispatch はその前に `branch_busy` で止める。
- 2026-10-16（Claude Code 2.1.301、herdr 0.9.3）: `herdr pane rename <ペイン> <名前>` は `{"result": {"type": "pane_info", "pane": {…, "label": "<名前>"}}}` を返した。`claude --help` に `-n, --name <name>` が有り、`claude agents --json` の 1 件の `name` に、その名前（付けなければ自動の名前）が出た。持ち主の手元で、別のアカウント（別の `CLAUDE_CONFIG_DIR`）の会話どうしでは SendMessage が両方向とも「No agent named … is reachable」で届かず、各会話の一覧にも同じアカウントの会話しか出なかった（Claude Code の文書は、設定のフォルダの違う会話に届くかを書いていない）。
- 2026-10-17（Claude Code 2.1.302、持ち主の手元のアカウントの 1 つ、信頼済みの作業場で裏の会話を 2 つ起動して消した）: `--bg --name … --settings <部署の設定のファイル> --model haiku --effort low <最初の文>` で起動した会話の記録の最初の要求は、モデル `claude-haiku-5-5`・effort `low` だった。`--effort` を外すと `medium`（Haiku 5.5 の既定）だった。知らない値（`--effort bogus`）は「Unknown --effort value 'bogus' — ignoring it and using the default effort」の注意だけで既定に戻った。Claude Code の会話の Bash のツールには、今の effort が環境変数 `CLAUDE_EFFORT` で渡っていた（hooks の文書の記述どおり）。モデルの環境変数は無く、`claude agents --json` の 1 件のフィールド（pid・cwd・kind・startedAt・sessionId・name・status・id・state）にも無かった。
