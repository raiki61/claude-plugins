# doctor-loop の役と道具、実行の効率（始める前に 1 度読む）

## 依存

実行時のハード依存は無い——追加プラグイン・pip 依存を使わず、git / python3 / bash は在れば使い、無ければ代替を「試せなかった計器」として報告する。サブエージェントはプラグイン同梱の役割 agent で起動する——以降 `inspector` / `investigator` / `cold-reader` / `judge` / `blind-judge` と書いたものは `subagent_type: convergence-loops:<役割>` を指し、モデル・effort・持てる道具は `${CLAUDE_PLUGIN_ROOT}/agents/<役割>.md` が正本である（**この手順書にモデル名を書くな**）。遮断系（`cold-reader` / `blind-judge`）は道具を一切持たないので、読ませたい本文はプロンプトに貼って渡せ。**ただし「道具を持たない」ことは遮断の保証ではない**——ハーネスは Agent ツールで起こした subagent に CLAUDE.md 階層を注入し、それを止める設定が公式に存在しない（code.claude.com/docs/en/sub-agents、2026-09-12 取得: 『Explore and Plan are the only subagents that omit CLAUDE.md and git status. There is no frontmatter field or per-agent setting to change which agents skip them.』）。実測 2026-09-12: 道具ゼロの `cold-reader` が利用者の CLAUDE.md の 1 項目を逐語で引用した。設定ごと外せるのは CLI（`claude -p --setting-sources ""`）だけなので、**判定の独立と CLAUDE.md の非流出が要る場面では、このコマンドの遮断は『道具の不在ぶんだけ』と読め**（機械が外す形は graphloops の cli モード＝`/review-graph`・`/research-graph` に在る）。**Read を持つ役（`inspector` / `investigator` / `judge`）には貼るな——本文をファイルに落として path を渡せ**（`git diff` や `cat` の出力を自分の文脈に出さず `> file` に落とす）。回す側の文脈を通る本文は読む・貼るで 2 回数え、圧縮で失われる。自分が既に受け取った返答を次の役や次の手順に貼り直すのも同じ——置き場の path と 1 行の要約で指し、要る所だけ読み直せ。決定的な検査は同梱の scripts/（`${CLAUDE_PLUGIN_ROOT}/scripts/`）に置いてよい——正本は script・手順書は列挙を持たない（review-loop の記録検証と同じ流儀。本ループ用の記録検証はまだ無く、導入するなら書き先と「変更禁止の機械確認」の関係を先に決めること）。同一プラグイン内の正本参照は 1 箇所だけ: ライブラリ級判定の**出典の格の全階層**は `research-loop` P1 を参照する（ただし判定に効く規則——公式一次まで——は本文に書いてあるので、参照が切れても走る）。`/research-loop` への「委譲」は呼び出しではなく提案文であり、委譲するか決めるのは依頼者である。計器は在れば使い、無ければ「試せなかった計器」として報告する——導入を手順に含めるな。**欠陥（バグ）探しは本ループの守備範囲外**——欠陥は既存の欠陥レビューの領分で、ここで再実装するな。走査中に偶然見つけた欠陥は、判定せず「守備範囲外の所見」として報告だけしろ（最終報告参照）。

## 実行の効率（漏斗と並走）

原理は「**安い網を先に、高い針を後に・反証で早く刈る・差分だけ再検証・依存の無いものは同時に走らせる**」。直列を許すのは依存があるときだけ。並走・先行起動は**前景の並列呼び出し**で行え（有人・無人を問わない——背景起動して自分のターンを閉じて待つ形は、入れ子実行で応答経路が壊れて結果が迷子になる）。

- **役の漏斗**: 広い所に安く、狭い所に高く。scout・事実照合（P2a）・P2b の一次反証は安い役（`inspector`）、P2b の二次反証・P3-5 の 3 票は高い役（`judge`）、収束ゲート（cartographer・rederiver・比較係）は `blind-judge`、報告ゲートは `cold-reader`。**全候補に一律で高い役を当てるな**——`judge` は例外駆動である（出動条件は P2b）。
- **P0-4（先行議論の突合と死んだ試みの探索）は検索作業**なので `investigator` に切り出し、P0 の他項目と並走させてよい。
- **P1 第 1 層（計器）は面積の確定だけに依存する**——計器は面積にだけ当たるので、レンズが未定でも回し始めてよい（P0-1 のレンズ選定が計器の出力量を使う場合は、この先行が前提である）。P0-2〜5 の完了も待たなくてよい。
- **scout はレンズ×面積の単位で並行起動**。返ってきた候補から順に P2a へ流せ——全 scout の返答を待ち合わせるな。待ち合わせが要るのは P3 の木の構築だけである。
- **cartographer は入力が P0 だけ**なので起動は序盤に先行してよい。突合だけを収束ゲート時に行え。
- 重厚の **rederiver と模範照合も P1 と並走できる**——隔離がそもそも要件なので、並走しても壊れない。
- **抜き取り検査と cartographer の突合は互いに独立**——収束確認の時点（P4）で同時に走らせろ。
