# doctor-loop の根本の木と提案の重さ（節の欄・高さ・展開・刈り込み・重さの 4 段）

## データ構造: 根本の木

このループの中心の成果物は候補の一覧ではなく**根本の木**である。全工程はこの木を組み立て・注釈し・測る操作として行え。

**節（ノード）の欄**: 安定キー（ファイルパス＋シンボル名＋一文要約。位置が特定できない上位の節は「領域＋一文要約」）／**高さ**（初期値は 1＝症状。上位の節は P3 で prospector が生やして付ける）／親キー（仮説でよい。無根拠の親付けは禁止——「なぜ在るか」への答えとして書けるものだけ）／レンズ／確度（確実・有力・仮説）／**重さ**（4 段。**scout が根拠付きで付ける**——prospector は上げてよいが下げるのは禁止。増し掛けを発火させる欄を、検証の費用を払う側の裁量で下げさせるな。事実根拠は P2a-⑤ の checker が裏取りする）／判定（P2 の「判定の語彙」。欄の初期値は「未検証」＝判定の不在であって、判定語彙ではない）。

**高さ（固定 4 段・増やすな）**:

1. **症状**: 個別の違反・欠落（この行が規約に反する、この検査が無い）
2. **機構**: 症状を許している仕組みの欠落・故障（この種の検査を置く場所が無い、逃げ道が塞がれていない）
3. **体制**: 機構が整わない運用上の理由（検査を必須化する手段が無い、実装待ち行列が流れない、担当が不在）
4. **方針**: 体制を形づくっている暗黙の前提（成文化した時点で完了扱いになっている等）

**展開の 3 方向**:

- **下（具体化）**: この節は実際にどこに何件現れるか。子を生やす
- **上（なぜ）**: この節はなぜ存在するか。親を生やす。**1 節につき遡り 3 段まで、かつ高さ 4（方針）を超えない**——それ以上遡ると「文化が悪い」に着地して実行不能になる
- **横（兄弟）**: 同じ親を持つ別の症状。束ねは「共通の親を発見して橋を架ける」操作である

**刈り込み**: 反証（P2）が刈り込みの演算子。**刈るとは、下と横を閉じて上だけ開けておくことである**——木から外すのではなく、下（具体化）と横（束ね）の展開とその節への以後の検証を止め、上（なぜ）の展開は刈った節にこそ課す。棄却の理由文はしばしば親を名指ししている（「既に決着済み」なら決着させた機構が、「やったが壊れた」なら壊した構造が、その上の節である）——**棄却理由から親候補を抽出して木に足せ。刈った枝の断面に、次の節が見える。** 検証不能の節は保留枝——上のみ展開し、下は止める。どの判定の節も木からは外さない（外すと安定キーの突合から漏れ、同じ候補が毎ラウンド再燃して飽和しない）。

**手詰まりの手筋**: 断面が凡庸・木が伸びないときは、次を順に当てろ——**不在の逆算**（これだけ整備されているのに、なぜこれだけ無いのか。不在の理由が親を指す）／**逆転**（いま在る検査を全部消したら何が最初に壊れるか。効いている縛りと飾りが分かれる）／**極端化**（開発者が 1 人なら・50 人ならこの規律は持つか。適用条件の境界が出る）／**抽象度の上下**（どの高さまで上がるとこの問題は自分たち固有でなくなるか。標準問題になった瞬間、世界の解が使える）。手筋は P3 の中で当てろ。生成した節は確度「仮説」で木に足し、**同じラウンドの P2 に掛けろ**——根拠（パス:行）を持つ節は P2a から、持たない節は P2b（親の節への入力仕様）へ。prospector 生成節の重さ欄は空＝増し掛けの対象外である（一撃に選ばれれば P3-5 の 3 票が掛かる）。生成は安く、濾すのは検証の仕事。

## 提案の重さ（4 段）

重さは**採用コストと後戻りの高さ**の尺度であって、木の中での効き具合（一撃性）ではない——後者は P3-4/5 が扱う。

| 重さ | 例 | 報告に必ず添えるもの |
|---|---|---|
| **機械検証可能・小** | 未使用依存の削除、既依存の機能での自前実装置換 | 機械の根拠（計器の出力） |
| **振る舞いに触れる・中** | 内部実装の是正・境界の引き直し（依存追加なし） | 影響範囲の列挙・検証計画 |
| **ライブラリ級** | 新しい依存の追加・置換 | 一次情報の確認結果・移行の当たり |
| **構成変更級** | 構成・方式の変更 | 摩擦の証拠・research-loop への委譲提案（P3-6 の 4 点。**段に依らず添える**——一撃としての宣言とは別である） |
