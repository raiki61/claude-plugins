# doctor-loop の最終報告と型への還流

## 最終報告（欠けたら未完成）

**報告は利用者の言語で書け。** この手順書が日本語であることは、報告を日本語にする理由にならない——判断を下すのは人で、読めない言語の報告では下せない。サブエージェントの出力が報告の言語と違っても揃えろ（固有名詞はそのままでよい）。**軽量・標準の減免は「厚みの三段」の表に従う——減免された欄は無言で落とさず「この段では走らせていない」と明示しろ。**

**記録が先、散文が後。** 最終報告を出す前に実行記録の JSON を**作業ツリーの外**（一時ディレクトリ等）に書き、`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/doctor-record.py <記録.json>` が exit 0 になるまで直せ。**記録の欄の正本は script 側で、手順書は列挙を持たない**（二重管理を避けるため。実例は `templates/doctor-record.example.json`）。書き先を作業ツリーの外に限るのは変更禁止の規律のため——変更禁止の機械確認（git 突合）は作業ツリーを対象とし、外への記録はこれに映らない。プラグインの実体ディレクトリにも書くな（更新でパスが変わる）。**飽和に至らず停止した走査**（軽量の打ち切り・上限・stuck・thrash）は記録の convergence を stopped にして理由を書けばそのまま出せる——検証器が塞ぐのは飽和の偽装だけである。数値・判定は記録が正本——散文に足したくなったら先に記録へ足せ。同梱 script を実行できない環境では、script 本文（欄の正本）を Read して目視で照合し、その旨を報告に書け。

散文の側にだけ残る義務: ①**根本の木を字下げの木で描け**（記録の nodes は親子の表であり、読み手は形で見る。棄却・保留枝も含めろ——読み手は生き残りだけでなく、何が刈られてなぜかを見る）②refuter・checker・3 票・ゲートの**生の判定と理由の転記**（記録は verdict と件数しか持たない——要約で丸めるな）③平易版と凡例（prospector・scout・checker・refuter・レンズ・段・高さ・判定語彙の 2 系統・保留枝など、本文で使う役割語の一言定義）④棄却された節と理由の付録 ⑤段の選択で省略した機構の明示 ⑥消化の三分類の順序は**情報の価値順**（その検証の結果で採否が最も多く変わるものから。何を確かめても採否が変わらない候補は削除候補）——順は提案であって決定ではない ⑦新設する検査の提案には「違反例を 1 つ作って赤くなることを確認してから信じる」を採用時の条件として一言添えろ——何にもマッチしない検査は緑のまま居座る ⑧決定記録への転記候補は **P0-4 で特定したそのリポジトリの流儀**の書式に整形しろ（器が無ければ P0-4 で立てた「文書の欠落」候補への参照——この欄で新しい候補を起こすな。転記するか・どこへ書くかは依頼者が決める）⑨件数を成果として書くな。

**執筆前の自己検査（cold-reader の往復を減らす——実走で指摘が集中した点）**: 出す前に、下の cold-reader の問いを自分に当てろ。加えて ①数値に測定出所（計器・コマンド・対象・時点）が添えてあるか——数値は記録した瞬間に出所を添えろ、報告時に遡って探すから漏れる ②工程の記録が専用の欄に隔離されているか ③内部語彙（凡例に無い役割語・説明なしの安定キー略記）を未定義のまま使っていないか。

**報告の初見検査（`cold-reader`・文脈遮断）**: **報告ゲートである——収束の判定には関与しない**（3 語彙を共有するだけ）。報告を出す前に、本文をプロンプトに貼って（道具を持たないので自分では開けない）、経緯を一切知らない読み手に通読させろ——「本文だけから各候補の採否を判断できるか。判断に要る前提が省かれていないか。内部語彙が未定義のまま使われていないか。確度『仮説』の節が断定調で書かれていないか」。`redesign-needed` なら直してから出せ（再検査は 2 回まで——上限後は指摘を報告冒頭に転記して出せ）。`unverifiable` は依頼者に諮れ（無人実行では要人間判断へ）。**この報告は人に判断させるための物であり、読めない報告は成果物として失格である。**

## 型への還流（ループの後に一度）

前回までの実行で依頼者が却下した候補の理由が渡されている場合に限り、**この skill 本文への追記案（却下基準・レンズ・反パターンの修正）を差分の形で報告に含めろ**。渡されていなければ「該当なし」と書け（無人実行でも同じ）。 本ループは自分の改善も提案止まり——適用するのは依頼者である。本ループが依頼者から引き受けるのは走査までで、判断は引き受けない。
