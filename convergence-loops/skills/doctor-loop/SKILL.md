# doctor-loop

## 位置づけ（一家の分業）

変更を待たずに、リポジトリの現状そのものから候補を掘るのが本ループ。掘った候補の採用と実装は人がやる。構成変更級候補の見立てを一次情報で校正するのは `/research-loop`。1 回の実行の中でもラウンドを回す——**1 ラウンド＝P1→P3 を 1 周**で、新しい目（新規コンテキストの scout）で掘り直し、木のどの節からも新しい節が生えなくなるまで続ける（理論的飽和——厳密な収束条件は P4）。回数を数えて「N 回やったから網羅した」と言うな——飽和だけが掘り尽くしの証拠である。

このループを回すセッションが **prospector**（統合者）。prospector はセッションのモデルをそのまま使え——木の構築・一撃の選定は判断作業であり、コスト削減で下位モデルに落とすな（ここが濁ると全下流の判断が濁る）。

**このループは提案のみを行い、リポジトリへの変更を一切適用しない。** Bash は読み取り専用の計器（lint・型検査・未使用検出・テスト実行・git 履歴）としてのみ使え——**例外は「変更禁止の機械確認」が命じる、自分の汚しの復旧だけである**。本ループが起動するサブエージェントは役割 agent（[references/tools.md](references/tools.md) の「依存」）で立てる。どの役も書く道具を持たないが、`investigator` だけは Bash を持つ——起動する `investigator` のプロンプトには一人称の自己禁止を書け——「お前はこのサブエージェント。ファイルの作成・編集・削除を自らに禁じる」。保証を与えるのは定義でも自制でもなく、下の「変更禁止の機械確認」の前後突合である。提案の採否・実装・固定化・記録はすべて依頼者が行う。issue 起票も本ループはしない。成果物は最終報告だけである。

## 変更禁止の機械確認

走査を始める前に `git status --porcelain` と `git stash list` を記録し、報告の直前に再取得して突合しろ。差があれば自分が汚した分を元に戻し、何をどう戻したかを報告に書け。計器の実行が生成物（キャッシュ・カバレッジファイル・lock の書き換え等）を作った場合の削除・復旧も同じ扱い。追跡対象ファイルの内容を意図して変える操作は、依頼者の指示なしに行うな。**無変化（または復旧済み）の確認結果は最終報告の必須欄**——確認せずに「変更していない」と書くな。git が使えないリポジトリでは、確認手段が無い旨と代替（走査前後のファイル一覧・更新時刻の突合）を報告に書け。

## 段ごとに読むファイル

この本文は段の順と読むファイルだけを持ち、手順の中身は持たない。**段に入るたびに、その段のファイルを読んでから手を動かせ。** 会話が圧縮されて前に読んだ手順が見えなくなったら、今いる段のファイルを読み直せ。

このプラグインの置き場は `${CLAUDE_PLUGIN_ROOT}` である。別ファイルの命令やパスに書いた `CLAUDE_PLUGIN_ROOT`（`$` と波括弧で囲んだ形）は Bash の環境変数には無いので、この置き場に読み替えて使え。

1. 始める前に 1 度: [references/tools.md](references/tools.md)（役の起こし方と渡し方・計器の扱い・守備範囲の外・漏斗と並走の原理）と [references/tree.md](references/tree.md)（根本の木の節の欄・高さ・展開・刈り込み・手詰まりの手筋・提案の重さの 4 段）
2. P0 範囲と厚みの固定: [references/p0-scope.md](references/p0-scope.md)（厚みの三段と昇格・降格、面積×レンズ、面積の分割、ドメイン地図、先行議論と死んだ試み、ホットスポット）
3. P1 発見: [references/p1-discovery.md](references/p1-discovery.md)（計器、レンズ別の scout と指示、返答の突合、読解の盲点）
4. P2 検証と刈り込み: [references/p2-verify.md](references/p2-verify.md)（判定の語彙、P2a 事実照合、P2b 敵対検証と `judge` の出動条件、増し掛け、回し直しの禁止）
5. P3 木と一撃: [references/p3-tree.md](references/p3-tree.md)（節を張る・領域診断の突き合わせ・上への展開・一撃の計算・3 票・構成変更級）
6. P4 ラウンドと飽和: [references/p4-saturation.md](references/p4-saturation.md)（2 ラウンド目以降の規律、飽和の三条件、抜き取り検査、cartographer、止める条件と暴走ガード）
7. 重厚の段のとき（P1 と並走）: [references/heavy.md](references/heavy.md)（独立再導出と模範照合）
8. 無人で走るとき: [references/unattended.md](references/unattended.md)（諮る事態の読み替え）
9. 最終報告: [references/report.md](references/report.md)（記録の検証、散文だけの義務、自己検査、cold-reader の報告ゲート、型への還流）
10. 型の由来や限界を確かめたいとき: [references/origins.md](references/origins.md)

1 ラウンド＝P1→P3 の 1 周。P4 の判定で次のラウンドか最終報告へ進む。

## 反パターン（自分の走査に見つけたら、走査のやり方をその場で正せ）

- **変更を適用する**（1 行でも）。→ 提案に差分例を含めるのは可。当てるのは依頼者。
- **平坦化**（標準・重厚のみ。軽量は表の定義どおり一覧でよい）: 木を組まず候補の一覧で報告する。一撃を印象で選ぶ。個別判定を束ねの材料からの除外に使う。
- **一覧の水増し**: 弱い候補で件数を稼ぐ。検証を通らないものを「参考」として滑り込ませる。
- **権威の数え上げ**: 「有名」「一線級も使っている」を根拠にする。→ メカニズム＋適用条件。
- **系譜の二重計上**: 複数 scout の同一指摘を独立の証拠として数える。
- **決着済みの蒸し返し**（P0-4 を飛ばした走査は必ずこれをやる）。
- **さぼり降格**: 走査を減らすために実行者が自分で軽量を選ぶ、または候補の重さを下げて増し掛けを回避する。→ 降格は依頼者指定のみ・重さの引き下げは禁止。
- **検証の相乗り**: 費用を下げるために複数の節を 1 体の checker・refuter に束ねる。→ 隔離が検証の本体。費用を下げる正しい手段は、面積を絞ることと `judge` の例外駆動（P2b）だけである。
- **温度の誤用**: 誰も触らない場所の判断系候補を上位に並べる。逆に、機械的に安全な候補を温度を理由に見送る。
- **被覆の外を語る**: 「見ていない範囲は健全」。
