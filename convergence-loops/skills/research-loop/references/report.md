# research-loop の成果物の型・最終報告・型への還流

## 成果物の型（必須セクション ── 欠けたら未完成）

成果物は今日の答えであると同時に、**次のループの期待モデル（地図）への預金**である ── 違和感センサーの感度は校正済みの地図の濃さの関数なので、ここを省くと次回の発見力が下がる。重厚の統合文書には最低限これを備えろ（軽量・標準の減免は「厚みの三段」の表に従う）:

- **平易版**（冒頭に。専門語なしで何の話か・どう解いたか・なぜ正しいと言えるか）
- **役割・記法の凡例**（本文で使う役割語・番号参照・確定/仮説マークの定義を成果物の先頭で。文脈を持たない読み手が本文だけで読めるように ── cold-reader の形式往復をここで予防する）
- **前提の棚卸し**（P0-1。確度注記付き）
- **根拠**（メカニズム＋適用条件。出現例は傍証と明記）
- **2層マップ**（左＝業界の位置づけ・確度付き｜右＝我々の適用・仮説マーク付き。左右を混ぜるな）
- **白地図**（観点として立っていない盲点。「調べたが空白だった」も価値）
- **出典の格付け表**（各主張がどの格の出典に立つか辿れるように）
- **社内語→標準語 対応表**（社内造語と確定した語はその旨明記）
- **訂正の記録**（append-only・番号付き・理由付き）
- **残る決定事項**（P5-3）と **PoC 行き**（P5-2）

## 最終報告

**報告は利用者の言語で書け。** この手順書が日本語であることは、報告を日本語にする理由にならない——判断を下すのは人で、読めない言語の報告では下せない。

**記録が先、散文が後。** 最終報告を出す前に実行記録の JSON を書き、`bash "${CLAUDE_PLUGIN_ROOT}/scripts/run-python.sh" "${CLAUDE_PLUGIN_ROOT}/scripts/research-record.py" <記録.json>` が exit 0 になるまで直せ。**記録のフィールドの正本は script 側で、手順書は列挙を持たない**（二重管理を避けるため。実例は `templates/research-record.example.json`）。散文の最終報告は検証済みの記録を人が読める形に展開したものであり、数値・判定は記録が正本——散文に足したくなったら先に記録へ足せ（numbers フィールドが数値と出所を対で要求する。報告時に遡って探すから漏れる）。同梱 script を実行できない環境では、script 本文（フィールドの正本）を Read して目視で照合し、その旨を報告に書け。**収束せずに停止した実行もそのまま出せる**——記録の convergence を stopped にして理由を書けば、ゲートの未 pass や覆りは「未収束の申告」であって阻害にならない（検証器が塞ぐのは、収束を名乗りながらゲートが通っていない記録だけ）。その段で必須なのに一度も走らなかったゲートは「飛ばした」（not_run と理由）として書き、「この段では走らせない」（not_applicable）と混ぜない。

散文の側にだけ残る義務: ①ゲート・refuter の**生の判定と理由の転記**（記録は verdict と件数しか持たない——要約で丸めるな）②段の選択で省略した機構と、停止で飛ばしたゲート（not_run）の明示 ③平易版・凡例・2層マップ等の構成（「成果物の型」が正本）④P0-6 を洗えなかった場合の「確認できなかった」の明記 ⑤停止した実行・無人実行では、諮りたかった内容を冒頭に「要人間判断」として列挙 ⑥記録の process・convergence の展開は結論のセクションに混ぜず専用のセクションに隔離。

**執筆前の自己検査**: 記録の検証が緑であることに加え、散文側にしか現れないものを P3-3（cold-reader）の問いで自分に当てろ——仮説の断定調・経緯の混入・未定義語（用語の定義は記録の terms フィールドに集約しろ。凡例を省いた段では報告冒頭で一言定義しろ）。

## 型への還流（ループの後に一度）

最終報告を出したら、型自体を短く振り返れ ── 今回のループで型が外した点・手で補った点・要らなかった段はどれか。あれば本 skill を更新しろ（AAR＝事後検証の規律。型は完成品でなく運用で育てる資産で、更新の理由は commit message に残す）。
