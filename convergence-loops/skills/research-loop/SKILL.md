# research-loop

設計・手法・技術選定の見立てを、一次情報で校正してから自分のドメインに最適化する調査ループ。系統的レビュー・ファクトチェック・敵対検証の合成で、由来は [references/origins.md](references/origins.md)。

## 役割分担（最重要）

このループを回す session が **surveyor（調査者・統合者）**。surveyor はセッションのモデルをそのまま使え（主張の棚卸し・統合・ドメイン適応は判断作業＝上位モデルの仕事。コスト削減で安い役に落とすな ── ここが濁ると全下流の判断が濁る）。surveyor は主張の棚卸し・訂正の統合・ドメイン適応という**判断作業だけ**を行い、**自分の主張を自分で検証しない**。検証は全て別 context の subagent が行う。

subagent はプラグイン同梱の役割 agent で起動する ── 以降 `inspector` / `investigator` / `cold-reader` / `judge` / `blind-judge` と書いたものは `subagent_type: convergence-loops:<役割>` を指し、モデル・effort・持てる道具は `${CLAUDE_PLUGIN_ROOT}/agents/<役割>.md` が正本である（**この手順書にモデル名を書くな**）。遮断系（`cold-reader` / `blind-judge`）は道具を一切持たないので、読ませたい本文はプロンプトに貼って渡せ。**ただし「道具を持たない」ことは遮断の保証ではない**——ハーネスは Agent ツールで起こした subagent に CLAUDE.md 階層を注入し、それを止める設定が公式に存在しない（code.claude.com/docs/en/sub-agents、2026-09-12 取得: 『Explore and Plan are the only subagents that omit CLAUDE.md and git status. There is no frontmatter field or per-agent setting to change which agents skip them.』）。実測 2026-09-12: 道具ゼロの `cold-reader` が利用者の CLAUDE.md の 1 項目を逐語で引用した。設定ごと外せるのは CLI（`claude -p --setting-sources ""`）だけなので、**判定の独立と CLAUDE.md の非流出が要る場面では、このコマンドの遮断は『道具の不在ぶんだけ』と読め**（機械が外す形は graphloops の cli モード＝`/review-graph`・`/research-graph` に在る）。**Read を持つ役（`inspector` / `investigator` / `judge`）には貼るな——本文をファイルに落として path を渡せ**（`git diff` や `cat` の出力を自分の文脈に出さず `> file` に落とす）。回す側の文脈を通る本文は読む・貼るで 2 回数え、圧縮で失われる。自分が既に受け取った返答を次の役や次の手順に貼り直すのも同じ——置き場の path と 1 行の要約で指し、要る所だけ読み直せ。どの役も書く道具を持たないが、`investigator` だけは Bash を持つ——起動するプロンプトには一人称の自己禁止（「ファイルの作成・編集・削除を自らに禁じる」）を書き、立てる前後で `git status --porcelain` を突き合わせろ（差があれば戻して最終報告に書け。書き換えを塞ぐのは定義でも自制でもなく、この突合である）。役の配分は**漏斗**で考える ── 広い所に安く、狭い所に高く:

- **checker（`investigator`）**: 一次情報への突合。全主張に走る扇の広い部分＝コストの大半を占めるので安い役。判定はするが、統合はしない。
- **refuter（`judge`）**: checker の「相違」判定そのものを疑う敵対検証 ── **悪魔の代弁人**の席（確認でなく反証を試みる。情報分析の **ACH＝競合仮説分析**と同じ流儀）。誤検出（読み違い・古い情報・版の混同・主張側に既にある留保の見落とし）を潰す。相違と【荷重】確証だけに走る狭い部分なので高い役を払える ── 誤った相違が本文を書き換える損害の方が高い。
- **rederiver（`blind-judge`・調査結果を遮断）**: 統合後の見立てを、前提だけから独立に再導出して突合する。収束ゲートでのみ走る（P3）。
- **cartographer（`blind-judge`・文書を遮断）**: 領域と問いだけから「完全な地図に要る観点」を独立に列挙し、文書との差分＝白地図（盲点）を作る。収束ゲートでのみ走る（P3）。
- **cold-reader（`cold-reader`・文脈を遮断）**: 経緯を知らない初見の読み手として成果物を通読し、導出の再現性を判定する。収束ゲートでのみ走る（P3）。

surveyor は refuter が確定した相違を反映するだけで、判定を自分で上げ下げできない。判定に異議があるなら自分で覆さず、別 context の refuter に再判定させろ。**一度確定した結論は社会的圧力でなく新証拠でのみ覆す。**

**判定を都合よく使うな**: 同一ラウンドで checker / refuter / ゲートを回し直して有利な判定を採るな（やり直しは次ラウンドのみ）。各判定者の生の verdict と理由は最終報告にそのまま転記しろ ── 要約で丸めるな。

## 目的関数の規律（このループの一撃）

①の目的は「**合ってるかの確認**」ではない。「**座標系の校正＋適用条件の抽出**」である。確認を求めて回すと一致する証拠ばかり集まり、見せかけのロバストネス（同じ系譜を複数回数える）に落ちる。だから:

- checker への指示に「主張を好意的に読み替えるな。書かれた文言がそのまま正しいかを判定しろ」を必ず入れろ。
- **確証にも必ず適用条件を添えさせろ**（「正しい。ただし成立するのは〜の条件下」）。適用条件を持ち帰らない確証は②で使えない。
- 一致の**数**を根拠にするな。一致を数える前に**系譜図を書け**（誰が誰から借りたか）。独立性を壊すのは思想の伝播（借用）だけで、共通の動機・共通の選択圧は反証にならない ── むしろメカニズム実在の証拠側に働く。独立でない一致を数えるのは Wimsatt の言う *illusory robustness*（見せかけのロバストネス）である。
- 証拠語（三角測量・consilience・構造的に正しい・最強・定石だから正しい）を結論に使うな。根拠はメカニズム（なぜその形が優位になるか）と適用条件で語れ。

## 段ごとに読むファイル

この本文は段の順と読むファイルだけを持ち、手順の中身は持たない。**段に入るたびに、その段のファイルを読んでから手を動かせ。** 会話が圧縮されて前に読んだ手順が見えなくなったら、今いる段のファイルを読み直せ。

このプラグインの置き場は `${CLAUDE_PLUGIN_ROOT}` である。別ファイルの命令やパスに書いた `CLAUDE_PLUGIN_ROOT`（`$` と波括弧で囲んだ形）は Bash の環境変数には無いので、この置き場に読み替えて使え。

1. P0 厚みと断面の固定: [references/p0-scope.md](references/p0-scope.md)（厚みの三段、問いと制約、主張の棚卸しとクラスタ、社内語、出典の独立性、先行議論、断面の生成の手筋）
2. P1 校正: [references/p1-calibrate.md](references/p1-calibrate.md)（Workflow に渡す script の全文、判定の語彙、出典の格、件数突合、再ラウンドの経済、増し掛け、負荷確証の反証）
3. P2 統合: [references/p2-integrate.md](references/p2-integrate.md)
4. P3 収束ゲートと P4 収束判定: [references/p3-p4-converge.md](references/p3-p4-converge.md)（rederiver・cartographer・cold-reader、収束の条件、抜き取り検査、諮る事態、無人実行の読み替え）
5. P5 ドメイン適応: [references/p5-domain.md](references/p5-domain.md)（内部の突合、3 分類）
6. 最終報告: [references/report.md](references/report.md)（成果物の型、記録の検証、散文だけの義務、型への還流）
7. 型の由来や限界を確かめたいとき: [references/origins.md](references/origins.md)

1 ラウンド＝P1→P2 の 1 周。P3 は新規の相違がゼロだったラウンドの後にだけ回す。

## 反パターン（見つけたらその場で直せ）

- **確認モードで回す**: 一致する証拠を集めて安心する。→ 反証を試みる指示に変えろ。
- **一致の数を看板にする**: 「N分野が一致」「Nソース確認」。作業量は証拠強度ではない。→ 出典の格で語れ。
- **系譜を数える**: 同根の流れ（借用・派生）を独立の脚として複数回数える。→ 先に系譜図。
- **自賛を根拠にする**: 「構造を正しく見た結果」等の反証不能な自己評価。→ 検証済みの反証・実測に置換。
- **経緯を本文に混ぜる**: 「以前は〜だったが」が本文に散在。→ 訂正の記録へ集約、本文は現在形。
- **断定調の仮説**: 物理選択・数値を確定のように書く。→ 仮説マーク＋「実測で確定」を明記。
- **「要検証」の放置**: 検証方法を添えない要検証はただの先送り。→ 測定量まで書け。
- **文脈剥ぎ取り引用（quote mining）**: 一次情報から都合のよい断片だけ切り出して根拠にする。原文には問い・対象・条件・限定があり、引用の効力はその**射程**の中だけ。→ 前後と限定節まで読み、原文の射程を conditions に書け。
- **さぼり降格**: 実行者が作業を減らすために自分で軽量を選ぶ。→ 降格は依頼者指定のみ・既定は標準・芯に刺さる相違では昇格が義務（「厚みの三段」）。
