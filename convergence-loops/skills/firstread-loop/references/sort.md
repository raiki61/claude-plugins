# firstread-loop の手順 4（前半）: 詰まりを吟味して仕分ける

目次:

## まず、報告を吟味する

**読み役が「止まった」と言ったことは疑いません。** それは起きた事実です。

**疑うのは、読み役が付けた解釈と評価です。** 報告には 3 つが混ざって届きます。

| | 例 | どう扱うか |
|---|---|---|
| 事実 | 「『参照先』が何のことか分からず止まった」 | **そのまま受け取ります** |
| 解釈 | 「用語の定義が無いのが原因だ」 | 本当にそこが原因か確かめます |
| 評価 | 「これがいちばん重い問題だ」 | **重さを決めるのはあなたです** |

**解釈をそのまま直し一覧に写さないでください。** 詰まりの本当の原因ではないところを直すことに
なります。**直したのに次の周でまた同じ場所で詰まるのは、たいていこれです。**

確かめ方は 4 つです。**上から順に試します。**下へ行くほど読み役の記憶に頼るので、精度が落ちます。

- **原文に戻る** ── 読み役が引用した箇所を自分で読み直します。解釈を外して、そこに何が書いて
  あるかだけを見ます。**書いてあったのに読み役が見落としただけ、ということもあります**
- **記録に戻る** ── 何を開き、何を検索し、どの順で辿ったかは読み役の記録に残っています。
  **「開いたか」「使ったか」は、聞くより見るほうが正確です。**聞けば申告しか返りません。
  **記録の全文は読まないこと**（読み役の記録は長く、あなたの文脈を潰します）── **道具の呼び出しの
  名前と引数だけを抜き出します。**実測では、申告された経路と実際の呼び出しはおおむね一致しましたが、
  **ブランチ名を検索語にして目的のファイルへ直行した 2 人のうち 1 人は、それを申告していませんでした。**
  申告だけを見ていたら、その周は「入口を自分で探せた」と記録されていたはずです
- **他の読み役と突き合わせる** ── 同じ場所で他の人も止まったか。1 人だけなら、その人が通った
  経路に固有の事情かもしれません
- **読み役に聞く** ── 上の 3 つで分けられなかったときだけ。手順 3 と同じ相手に続きを聞きます

聞くときの形。**仮説を 2 つ以上立ててから、それを分ける行動を 1 つだけ聞きます。**「用語が原因か、
順番が原因か」は読み役に診断させる問いで、それはあなたの仕事です。「その節を読んでいる間に他の
ファイルを開いたか」なら、読み役に判定させずにこちらの仮説が分かれます。**報告された詰まりは
掘ってよく、何も無い所は掘ってはいけません。**後者は捻り出しになります。

**分からなかったと言った読み役は、こちらが探していたものを渡してくれた側です。**「本当に分から
なかったのか」を確かめに行くと、次から出てこなくなります。**聞くのは、言われたことを崩すためでは
なく、まだ言われていないことを出すためです。**ここで一番大きいものが出ることがあります。

**吟味は詰まりを値引きするためではありません。** 解釈が違っていても、**止まった事実は残ります。**
変わるのは原因の見立てだけです。「解釈が的外れだったから、詰まりも無かった」にはなりません。

## 型に当てはめる

集まったもののうち、**詰まり**（止まった場所・推測で埋めた場所・誤解・辿り着けなかった先）をあなたが分類します。疑問と着想はこの後で別に扱います。

**当てはめる前に、出自で束ねます。**別々に見える詰まりが、同じ節の作り・同じ前提・同じ欠けた宣言という
1 つの根から出ていないか。同根なら 1 件ずつ直さず、**根の側を 1 回直します**。実測: 「前提の宣言で
止まった」「宣言が約束した説明が本文に無い」「宣言の列挙に語が欠けている」は 3 人から別々に出た
3 件に見えて、根は前の周に足された宣言の作り 1 つでした。

**分類は直し方を決めるためで、詰まりを値引きするためではありません。**「これは読み役が悪い」に振り分ける置き場を作らないでください。

よくある型は次の 7 つです。**これは事後にあなたが当てるものです。読み役には渡しません**（渡すと、それだけを探すようになって網が縮みます）。この 7 つに当てはまらない詰まりも、同じ重さで扱ってください。

| 型 | どういうことか | 直し方 |
|---|---|---|
| 説明が無い | その言葉・概念を知っている前提で書かれている | 説明を先に置くか、説明のある場所へリンクする |
| 言葉が定義されていない | 文書の中で説明せずに使っている語。書いた人には当たり前でも読む人には分からない | 最初に出てきたところで、それが何を指すか書く |
| 呼び方が変わる | 同じものを、節ごとに違う言葉で呼んでいる | 言葉を繋ぐ。片方を消すのではなく、同じものだと書く |
| まとめと中身が違う | 冒頭のまとめが、本文と数や内容で合っていない | **まとめを後から足したら、必ず本文と突き合わせる。** この型は後付けのまとめから生まれます |
| リンク先に行けない | 「〜を見ろ」の先が無い。索引から引けない。入口から辿り着けない | 索引に入口を作る。リンク先を実在させる |
| 順番が逆 | 後で説明することを前提にして、前の方が書かれている | 節の順を入れ替えるか、先に短い前置きを置く |
| **書き手の事情が書いてある** | 読む人には要らない、書き手側の文脈が書かれている。他の成果物との関係、調べた順番、何を書かないと決めたか、なぜこれを書いたか | 落とす。**「これは読む人に必要か」を一度ずつ問い直す** |

**この表に載るのは、文章の欠陥だけです。** 構造の欠陥 ── 正本がどこにも無い、存在しないものを
前提にして書かれている、文書と issue が食い違っている ── は、ここには載りません。**表に
当てはまらない詰まりのほうが重いことがあります。** 型に当てはめて安心する使い方に倒れないで
ください。当てはまらなかったものは、当てはまらなかったまま同じ重さで扱います。

最後の型は見落としやすいので注意してください。**書いた本人には、書いた理由が一番はっきり見えています。だから一番書きたくなります。** でも読む人には要りません。読み役はここで止まらず読み進めてしまう（要らないだけで、分からないわけではないから）ので、「推測で埋めた場所」の申告から拾うか、あなたが事後に探すことになります。

## 範囲の内か外かを分ける

詰まりを 1 つずつ、範囲の内か外かに割り振ります。判定は「**今回の変更が作った詰まりか**」です。

| | どうするか |
|---|---|
| 今回の変更が作った | **範囲内。必ず直します** |
| 今回の変更が無くても在った、かつ触っているファイルの中 | 直すかどうかを判断します。直さないなら理由を書きます |
| 今回の変更が無くても在った、かつ触っていないファイル | **範囲外。直しません** |

**範囲外は捨て場ではありません。** 直さないと決めたものには、**行き先**を書きます ── issue に
するのか、既知の制約として台帳に載せるのか、次のブランチでやるのか。行き先の無い「範囲外」は、
**消したのと同じ**です。

範囲外の詰まりは、次の周でもまた出ます。直していないのだから当然で、**これは直し方が効いて
いない証拠ではありません。** 収束を判定するのは範囲内の詰まりだけです。

**直したことで、新しい場所に到達できるようになることがあります。** 導線を張ったら、その先が
未整備だと分かった、という形です。周を重ねるたびに次の層が露出して、終わらないように見えます。
**そう見えても慌てないでください。**判定はひとつだけです ── **前の版で、そこへ本当に届かなかったか。**

- **届かなかった** ── その先は元からそうだった詰まりです。到達できるようにしたのが今回の成果で、
  その先の欠陥は今回の変更が作ったものではありません。行き先を書いて次のブランチへ回します
- **届いていた** ── 範囲内です。**見えやすくなっただけで、元から在って元から辿り着けた**のだから、
  今回直します

**確かめずに前者だと言わないでください。** 実測では、周を重ねて出続けた詰まりに「直したから新しく
到達できるようになった」ものは 1 件も無く、確かめられた分はすべて後者でした。**確かめずに前者を選ぶと、
範囲内で直すべきものを外へ逃がす言い分になります。**逆に後者ばかりに寄せると、直すほど範囲が
広がって収束しません。**両方向に外れます。**

## 足す以外の直し方を、先に見る

上の表の直し方で、**「減らす」方向は 7 つのうち 1 つだけ**です。放っておくと足す側にしか倒れません。詰まるたびに説明を積むと文書は膨らみ、次の読み役は、その膨らみのせいで別のところで詰まります。**これはこのループが構造として抱えている癖で、気をつけていないと必ず出ます。**

だから、説明を書き足す前に次の 3 つを見ます。

- **消す** ── そこに触れる必要が、そもそもあったか
- **場所を変える** ── 要る人には要るが、全員が通り道で読む必要はない。後ろへ回す、まとめて別の節にする
- **並べ替える・見出しを付ける** ── 量は同じでも、順番と区切りで読めるようになることがあります

節を入れ子にして深くするより、**同じ高さに並べて数を増やすほうが見つけやすくなります。**深い階層は、どこに何があるかを覚えていないと辿れません。

## 読み飛ばされた場所をどう読むか

**読み飛ばされた＝要らない、ではありません。** 4 つに分かれます。

| どういう状態か | どうするか |
|---|---|
| 誰にも要らなかった | 消す |
| 要る人には要るが、全員の通り道にある | 場所を変える |
| 全員に要るのに、量に埋もれて届いていない | 順番を変えるか、見出しを付けて目立たせる |
| もう本文で読んだから飛ばした（まとめ・禁止事項・限界の宣言） | **正常です。そのまま。** まとめは飛ばされる形で機能しています |

**読まれなかった文は、無いのと同じではありません。**探すときの邪魔になる分、無いより悪いです。だからどれに当たるかを決めて、必ず何かをします。「読み飛ばされたが、そのままにした」で終えるなら、理由を書いてください。
**ただし 1 周だけの読み飛ばしは、その読み役が通った経路に固有の雑音でありえます。別の読み役が
同じ場所をまた読まずに済ませて初めて信号です**（記録の道具が周をまたいで突き合わせます）。

## 回収されなかった疑問を仕分ける

読み役が書いた疑問のうち、**文書のどこにも答えが無かったもの**を取り出します。1 つずつ、どちらかに割り振ります。

| | どういうことか | どうするか |
|---|---|---|
| 書き落とし | 設計には答えがある。文書に書いていないだけ | 書き足す |
| **設計の穴** | 設計の側にも答えが無い。誰も考えていなかった | **書き足して済ませてはいけません。** そのまま報告に残します |

見分け方は単純です。**その疑問の答えが、どこかに存在しますか。** あなたが知っている、あるいは調べれば分かるなら書き落としです。**調べても答えが無い、決めた人がいない**なら、それは設計の穴です。

かかる手間で決めないでください。調べるのに半日かかっても、答えがあるなら書き落としです。逆に一瞬で「これは誰も決めていない」と分かるなら、それは穴です。

**設計の穴を直すのは、このコマンドの仕事ではありません。** でも握り潰してもいけません。誰も気づいていなかったことが、知らない人に読ませたから出てきた ── この順序でしか出てこないものです。文章を直して見えなくすると、穴だけが残ります。

**拾うのは報告を受け取った人です。** あなたは、何が出てきたかと、なぜ設計の穴だと判断したかを書いて渡すところまでをやります。

着想の方も同じように見ます。読み役が「これはこう使えるのでは」と思ったのに文書がそれに触れていないなら、**触れていない理由が要ります。** 検討して見送ったなら、見送ったと書けます。検討していなかったなら、それも設計の穴です。
