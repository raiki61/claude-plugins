# firstread-loop で集めるもの・集めないもの

## 集める

| | 中身 | 例 |
|---|---|---|
| 止まった場所 | どの文で止まったか。何が分からなかったか | 「『参照先』が何のことか書いていないので止まった」 |
| 推測で埋めた場所 | 文書に書いていないことを、勘・他のファイル・一般知識で補った箇所 | 「たぶん設定ファイルのことだろうと思って読み進めた」 |
| 読んだ後の誤解 | 読み終えてから説明させたとき、原文とずれていた箇所 | 「手順が逆に理解されていた」 |
| 辿り着けなかった先 | 「〜を見ろ」と書いてあるのに行けなかった | 「索引から探したが見つからなかった」 |
| 湧いた疑問 | 読めた上で「では、この場合はどうなるのか」と思ったこと。後で答えが出たかどうかも書かせる | 「2 つ目のテナントが来たらどうなるのか、と思ったが最後まで書いていなかった」 |
| 湧いた着想 | 読んでいて思いついたこと | 「この形なら検証環境も同じにできるのでは、と思った」 |
| 読み飛ばした場所 | 読まなくても進めた。前と同じことが書いてあった。無くても分かったと思った | 「この段落は前の節と同じことを言っていたので飛ばした」 |

**推測で埋めた場所は、止まった場所と同じくらい大事です。** 読み役が賢いと、書いていないことを勝手に補って最後まで読めてしまいます。すると詰まりがゼロに見える。だから「補ったら必ず申告しろ」と読み役に言い渡します。

**上の 4 つは「読めなかった」側ですが、下の 3 つは違います。** 読めた上で、頭に浮かんだこと・読まずに済んだことです。ここを捨てると、読み役を「詰まる役」に閉じ込めることになります。読む人は詰まるだけでなく、考えますし、飛ばします。

**読み飛ばした場所は、これだけが「減らす」材料です。** 読み役は、説明が足りないときには止まりますが、**多すぎるときには止まりません。**要らないだけで、分からないわけではないからです。黙って飛ばして読み終えます。だから聞かないと出てきません。

集めた疑問のうち、**文書が答えていないものの扱いが一番大事です。** 原因は 2 つのどちらかで、意味がまったく違います。

- 設計には答えがあるのに、**文書が書き落としている**
- **設計そのものが答えを持っていない** ── 誰も考えていなかった

後者は、文書の欠陥ではありません。書き足して埋まるものでもありません。仕分け方は手順 4 に書きます。

## 集めない

次のものを成果物に混ぜてはいけません。混ぜると、詰まった事実がぼやけます。

- 文の長さ・むずかしい単語の数・読みやすさスコア（別のツールの仕事。**このコマンドの結論をこれで代用しない**）
- 誤字・表記ゆれ・言葉づかいの統一
- 書いてある内容が正しいかどうか（**このコマンドは内容の正しさを見ません**）
- 読み役が考えた**文書の直し方**（「この節をこう書き換えろ」。直し方を決めるのはあなたです）

最後のものは、**上の表の「湧いた疑問」「湧いた着想」とは違います。** 線はここです ── 文書について語り出したら集めません。読んでいて頭に浮かんだことなら集めます。「この説明は分かりにくいので書き直すべき」は前者。「では 2 つ目が来たらどうなるのか」は後者です。
