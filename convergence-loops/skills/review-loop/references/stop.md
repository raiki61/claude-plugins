# review-loop の停止条件（いつ止めて人に聞くか）

## 停止条件

**収束（不動点）で止めるのが正常終了。** 収束 ＝ `review-record.py` が阻害要因を返さず（ツールが**連続 2 ラウンド**——採点のゆらぎを吸収するため——と、記録の `reviews` に載った R1〜R4 の verdict まで数える。初回ラウンドに阻害が無ければ 2 ラウンド目で成立しうる）・CI 緑。**このツールが出す「阻害要因は無い」は収束の宣言ではない**——機械で見つかる範囲に何も無いという意味で、記録に載らない懸念の有無と、持ち越しが古すぎないか（ツールは何ラウンド前の判定かを見せるだけで中身を見ない）は人が見る。**機械に合格を宣言させるな。不合格を宣言させろ。**「ラウンド」は P4 の定義（P1→P4 を1周）を使い、連続2ラウンドと下記の暴走ガードは**同一カウンタ**を参照する。残った指摘は「意図的に受容した設計判断」として理由を明示して終わる。**連鎖は `[nit]` を受容して再修正を止めることで断つ——検証を止めることではない（コスト感での検証スキップは `REVIEW.md`「対応の判断」で禁止）。**

**機械が「立った周には聞かない」を持つのは帰属の条件 1 つだけ**で、中身と実測は `review-record.py` の `blockers()` の docstring が正本。実行者が知っておくのは 1 つ——**問いを立てた周に機械が「聞け」と言わなくても不具合ではない**（その阻害要因には「（今ラウンドに立った問い——再審は次の周）」の印が付く）。

**収束以外で止まるのは 3 つだけ**——①**答え無しに進める仕事が尽きた**（`review-record.py` が「残る阻害要因は保留の問いに帰属するものだけ」と出したとき。writer が数えるな）②**前提不成立が確定した**（下の `premise` の項。件数に依らず先に出る。機械も同じ文言で先に出す）——**この 1 つだけは立った周に聞く**（`premise` は立った周に別 context の judge が根拠を検算する種類なので、再審を 1 周待たない。「立った周には聞かない」の唯一の例外）③**暴走ガード（具体上限）**: 総ラウンドが **5** を超えたら「収束せず」として必ず停止し報告しろ（収束前の打ち切りでなく、非収束を検知する上限）。止まったら最終報告で、台帳の `held` / `escalate` をまとめて聞く。

**人に聞く候補は、立った周に止めて聞くな。** 問いの台帳に載せ、次の周の judge に再審させろ（P2「履歴との突合」）——立った周の目にだけ難しかった問いは、次の周の材料と独立再導出で消える（**実測はこのセクションが正本**: 前回のレビューで岐路として立ったのは 3 件——「読み手に渡す写しの範囲を絞るか」「引用符を認識するか」「記録検証の入口をどちらを正本にするか」。3 件とも後の周で、並べた選択肢の**外**にある零処方で消えた。前の 2 件は同じ仕掛けの上に在り、その仕掛けごと削除した 1 つの処方で同時に消えた。3 件目は 2 つある入口の片方を消して決着した。立った周に人へ返していたら、その選択肢からは選ばれなかったはずだ——ここまでが実測で、最後の一文は反実仮想の推論である）。

**種類の正本は `review-record.py` の `QUESTION_KINDS`、状態は `QUESTION_STATUS` で、ここに写しは持たない。** 状態は 2 軸（決着したか × 出どころが残っているか）で、決着済みのうち出どころが開いているものが `decided`、閉じたものが `resolved` である。 下に挙げるのは、**0.27 まで「停止条件」として別々に並んでいたもの**が今どう扱われるかと、その再審の問いである（`split` / `rule` は単独では周を止めないので、ここでなく P2「履歴との突合」が扱う）:

- **stuck**（`stuck`）: 同じ `[block]` キーが 2 ラウンド連続で残る（3 ラウンドの記録に続けて在る。機械が台帳への記載を要求する）。再審の問い: 処方が誤りか（別の零処方が在るか）・設計の問題か（`fork` に変える）・本当に残っているか。
- **thrash**（`thrash`）: 新規 `[block]` キーが出続け収束に向かわない（履歴の要対応の件数で見える）。**出どころを持たない種類なので `origin` も `depends` も書けない**（書くと記録の不正。特定のユニットに紐づけると、帰属と stuck の縛りをそこから外せる）。再審の問い: 新規に見えるものが言い換えでないか・アプローチの誤りか（R1 / R2 を回し直せ）。件数が落ちれば `resolved`。
- **設計の岐路**（`fork`）: 処方が機構の新設・共有面の拡大に及び候補が複数（P2「処方の列挙」）。再審の問い: 独立再導出で同じ岐路が立つか・候補の 1 つが実測で優越しないか・零処方（取り下げ）が本当に落ちるか。R2 が `redesign-needed` を再設計ラウンド 1 回で解消しない**ゼロベース乖離**もここに載せる（機械では決められない設計の岐路）。**このとき `origin` に R の名前を書くな——乖離が現れている根本ユニットの key を書け。** `fork` の `origin` の域は units の key で、R 名を書いた記録は `exit 2` になる（R2 の `redesign-needed` の理由は P2 で根本ユニットに変換されているので、指す先は必ず在る）。**この問いは周を止めない**——台帳に溜まり、止まったときに他の未決とまとめて人に届く。機械の「聞く時」に到達しないのは欠陥ではなく、即止めるのを前提不成立 1 つに絞った設計である。
- **前提不成立**（`premise`）: R2 が `premise-invalid` を返した。**立った周に、別 context の `judge` に根拠を検算させろ**——`blind-judge` はツールを持たないので、「既存機構で自明に満たされている」「1 デプロイ＝1 リポジトリ」の類は目的テキストの外の**仮定**である。judge がリポジトリの実態で仮定を偽と示せたら `resolved`（実測した事実を制約に**足し**——目的は動かすな。前提のドリフトと同じ事前登録の例外——次の周で R2 を回し直せ。この周の R2 は `premise-invalid` のまま書け）。仮定が真か、根拠が目的テキストの内側で閉じていて実測で反証できないなら `escalate`——**このときだけは残る仕事が全てその答えに従属するので、他の阻害要因の帰属を問わず止めて聞け**（機械もそう出す）。
- **独立検証不能**（`unverifiable`）: R2 が `unverifiable`（元の目的を独立に取れない）。再審の問い: 出典①②③の外（issue・コミットメッセージ・設計文書）に目的の記述が無いか。
- **未観測**（`awaiting`）: 主経路を動かせない（環境が無い・権限が無い・実機が要る）。素材を `awaiting_human` にして台帳に載せろ。再審の問い: 動かす手段が本当に無いか（テスト用の設定・写し・fixture）。**「静的レビューを何ラウンド重ねたか」で観測の欠落を埋めるな**——読む役をいくら増やしても、実行して初めて現れる欠陥は現れない。誰がどこで動かすかは人の判断で、ループ内で `pass` に丸めるな。他の `awaiting_human` の素材（並行 PR の一覧が打ち切られた・決定記録を洗えなかった・CI を手元で走らせられない）も同じ形で載せろ——「打ち切られた」は上限を上げれば済むことが多く、人に聞く前に再審で消える。

- **実地の確かめ**（`field`）: 人が実地で確かめるまで決まらない（実機・外部の環境・権限の要る操作）が、どの素材も `awaiting_human` でない——判定の途中で気づいた「Windows の実機で試していない」の類。**出どころを持たない種類で、素材のフィールドを借りるな**——`awaiting` の出どころは今 `awaiting_human` の素材だけで、CI のフィールドを借りると CI を再実行する P4 の工程が毎周そのフィールドを上書きする（実走の申し送り: 5 周で 8 回の手の書き戻し）。周を止めず、最終報告の冒頭に載る。再審の問い: ループの中で確かめる手段が本当に無いか（`awaiting` と同じ）。

**問いではないもの（台帳に載せない）。** 次の 1 つは同じセクションに置くが、人に聞く候補ではなくループ内の手当てである:

- **前提のドリフト**: 差分が P0-3 の制約の根拠を壊した（制約を測った対象をこの PR 自身が削除・置換した）→ **事前登録の例外**（P0-4 の「以降変更しない」は目的テキストを凍結し、そこに書いた制約＝P0-3 で測った値も一緒に凍る。ここで解くのはその制約の部分だけで、目的そのものは動かすな）。制約を測り直し、R1 と R2 を回し直せ。事前登録の規律はゴールポストを動かさないためのもので、**作業自身が前提を反証した場合まで凍結する意味は無い**（凍結すると、消えた前提の上に作り込みが積み上がる）。測り直した制約と、前の制約が偽になった理由を最終報告に書け。
