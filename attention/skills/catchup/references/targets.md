# /catchup の対象の読み方と移り方（呼ぶ前に、対象が素直に決まらないときに読む）

/catchup（1 件の PR などについて、前回から何が起きたかを 1 枚の HTML のページに描くコマンド）を動かす AI が、何を描くか（**対象**。`/catchup` の最初の引数で、番号・URL・ブランチ名・commit・会話の話題。無ければ今のブランチ）が素直に決まらないときに読む。読むのは、対象が会話の話題・数字だけ・commit の範囲・引数なしで今のブランチに PR も番号も無いとき、焦点の語を付けるとき、機械が移らなかったとき。対象ごとの素直な呼び方は /catchup の本文（SKILL.md）の「受け口」のセクションにあり、この文書はその続き。

前提: **機械**は `catchup.py`（`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/catchup.py`）。呼ぶと材料（AI が読む文字の報告）を出し、それを元にページが描かれる。`--out` は材料をファイルに書かせる旗、`--switch` は手元を対象のブランチへ移させる旗、`--frame <path>` はその 1 file の変更を上限なしで出す旗。`this` は今のブランチ。**焦点の語**（`指摘`・`地図`・`CI`）は対象の後ろに付ける語で、材料の末尾のセクションをその語のセクションに絞る。**地図**は材料の「変更の地図」のセクション（変更ファイルの木・名前の言及・新規ファイルの骨組み）。`what-am-i-doing.py` は同じプラグインの、このセッション（会話）の記録を読む機械（`/what-am-i-doing` の中身）。

## 会話の話題

- **会話の話題**（`新しく出たもの`・`今の修正`・`さっきの 4 件` など、番号でも commit でもブランチでもない語）→ **先に、会話の中で何に結び付いているかを解く。** 番号・ブランチ・commit に結び付いていれば対象はそれで、話題の形では書かない——番号なら `catchup.py <番号>`（`--switch` は付けない。この件の作業に戻るための呼び方ではない）、直前に commit した話なら `catchup.py HEAD`、このセッションで入れた commit が複数なら `what-am-i-doing.py` の「このセッションの間に入ったコミット」の一番古い sha に `^` を付けた範囲 `catchup.py <古い sha>^..<新しい sha>`。ページは、その対象を直接呼ばれたときと同じ形（説明・変更まで全部）。会話にしか無い話題（レビューで見つけた指摘の束・検討中の案）だけ、`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/what-am-i-doing.py --topic "<語句>" --out` でその語句が出た往復を取り、話題の形で書く（話題の形は、描く材料を持たずに、AI が書くフィールド〔ページに描く文の JSON〕に話題の名前を足して描く形。フィールドの書き方はこの文書の範囲の外で、/catchup の本文〔SKILL.md〕の手順 4 が、書く前に読む物を指す）——語句は 1 つ（引用符で括る。複数の語は続けた 1 句として当たる。0 件なら肝の 1 語か言い換えでもう 1 回）。実測: 「今の修正」を話題の形で書いたら、commit 4 件は push 済みで手元は空、フィールドの枠だけで中身の無い返答になり「何も出ない」と言われた

## commit と焦点の語

- **commit** → `catchup.py <それ> --out`。GitHub には何も聞かず、手元の git の commit として出る（題と本文、木、変更の中身。範囲は親との差 1 つ、merge は第 1 親との差）。PR を立てずに既定ブランチへ直接 commit する運用で、後から変更を読み直す口。commit の範囲 `A..B`（`2971ea2..b27cb3d`・`HEAD~4..HEAD`・`e824033^..HEAD`）も同じ形で、差は A の版と B の版の間、本文は各 commit の題（全文は `git show <sha>`）。`--frame` も効く
- **焦点の語** → 対象の後ろにそのまま（`catchup.py --switch 1569 指摘 --out`）。材料の後ろの側に並ぶ指摘・CI が落ちた理由・変更の地図のセクションを、付けた語の物（複数可）だけにする、急ぐときの口で既定ではない。無ければ機械が「無い」と 1 行出す。指摘・CI を PR でない対象に付けると「その材料は PR / issue のもの」と出る。地図は commit にも効く

## 対象の読み方

- 数字だけの語は番号が先。7 桁以上で手元の commit に解ければ commit（迷うなら `HEAD~n` か 8 桁以上）。同じ語がブランチの名前にも当たるならブランチが勝つ（移る）。焦点の語と同じ名前のブランチ・タグは対象にできない（先に焦点として読む）
- 引数なし・`this`・ブランチ名で移った後は、今のブランチから意図を汲む。順に: ブランチの PR → 無ければブランチ名の番号（`chore/1513-…` → #1513。PR か issue かは GitHub が返した種類のとおりで、機械が「（… だった。違えば番号を渡す）」と 1 行断る。issue と決めつけない）→ それも無ければ手元だけ（機械は GitHub に聞かず、手元のブランチと未コミットの変更の中身、既定ブランチより先の commit が有ればその差を出す。止めない——止めると書きかけの人に何も返らない）→ 手元に未コミットも、push していない commit も、既定ブランチより先の commit も無ければ、**会話から対象を推定する** → 推定もできなければ聞き返す。ブランチ名で呼ばれたときは推定しない（ブランチそのものが対象。差が無ければその旨をフィールドで）
- **会話からの推定**: 直近に出たものを 1 つ（番号・ブランチ・commit・話題。直前に commit した話なら HEAD の commit）。同じ往復に複数あれば 番号 → ブランチ → commit → 話題 の順。会話が要約で前半が消えていれば `what-am-i-doing.py` で往復を取ってから決める。2 つ以上が同じ強さなら推定しない（聞き返す）。番号は、会話に URL か owner/repo が無ければいま居るリポジトリの番号と見る（URL が出ていればそれで呼ぶ）。推定した対象で機械を呼び直す——番号は `catchup.py <番号>`、commit は `catchup.py <sha>`、話題は `what-am-i-doing.py --topic "<会話でその話題を指した、読む人の語>"`（0 件なら肝の 1 語で 1 回）。`--switch` は付けない（引数なしは移らない。移りたければ番号で呼び直してもらう）。ページは、その対象を直接呼ばれたときと同じ形（セクションも全部）
- **聞き返す**（**質問で返してよいのはここだけ**）: ページを描かない。手元の事実（ブランチの名前・PR も番号も無い・未コミットも push していない commit も無い）を 1〜2 文で言い切ってから、渡せるもの（番号・URL・ブランチ名・commit・話題の語）を 1 文で聞く。末尾に、引数なしで呼んだときの材料の末尾に機械が出す「見ていないもの」の 3 項目（GitHub の PR / issue・他のブランチと worktree の状態・このセッションで何をしたか）を写す（script 名は `/what-am-i-doing` の呼び名に置き換える）

## 移る（`--switch`。並行の作業からこの件に戻る人は、話がどこまで進んだかと一緒に、手元のブランチも別のブランチに替わっている）

- 移る先: PR は head のブランチ（手元に無ければ origin からその 1 本だけ `git fetch` して作って移る。名前と追跡先は `gh pr checkout` と同じ）。issue は名前にその番号を持つ手元のブランチが 1 本のときだけ（origin からは探さない）。ブランチ名はそのブランチ（origin にだけ有れば origin/<名前> を追跡するブランチを作って移る）
- 移らない条件（理由と今どこに居るかが、見出しの URL の直下の「ブランチ」の行に出る）: 追跡 file に未コミット（未追跡だけなら移る）／merge・rebase・cherry-pick の途中／別の worktree に checkout 済み／origin にももう無い（merge 済みで削除）／fetch が失敗／fork の PR で手元の同名のブランチが head の commit を含まない／`index.lock` が有る。ブランチ名で移れなかったときは、機械がそのブランチに PR が有れば PR として、無ければブランチの tip の commit として出す（ブランチ全体の差は移ってから）
- 機械が手元を変えるのは `git switch` とその 1 本の fetch だけ。pull・merge・stash・commit・`gh pr checkout` はしない。戻すのは `git switch -`。移った・既に居たときは末尾に「手元のブランチ」のセクションが付く（push していない commit・PR の head より後ろの数・未コミットの木）。移らなかったときは「ブランチ」の行だけ
