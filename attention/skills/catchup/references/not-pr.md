# /catchup の PR でないときと会話の話題（欄の言い切りの形）

/catchup（1 件の PR などについて、前回から何が起きたかを 1 枚の HTML のページに描く命令）を動かす AI が、欄（ページに描く文を AI が書く JSON。`headline`＝いまの番〔今この件で誰が動く番か〕を言う 1 文・`where`＝前回からの動き・`turn`＝止めているもの・`next`＝次の一手、など）を書く前に読む。読むのは、対象が枝に PR 無し・commit・会話から推定した番号のとき、または会話の話題を描くとき。

前提: **機械**は `catchup.py`（`--out` を付けると材料〔AI が読む文字の報告〕をファイルに書き、`--render` でページを描く）。**私**は gh の認証ユーザ＝この道具を使ってページを読む人。`this` は今のブランチで、引数なしで呼ぶと機械は `catchup.py this --out` で呼ばれる。材料の**手元の節**は、今のブランチを言う「ブランチ」の行と「手元のブランチ」の節。`what-am-i-doing.py` は同じプラグインの、このセッション（会話）の記録を読む機械（`/what-am-i-doing` の中身）。

## PR でないとき


- **枝に PR 無し**（未コミット・push していない commit・既定ブランチより先の commit のどれかが有るとき。どれも無ければ会話からの推定か聞き返し）: `headline` は「今のブランチ main に PR は無く、名前にも番号が無い」。`turn` は「GitHub 側は見ていない」と断って、手元の事実（未コミット・push していない commit・PR が無いこと）。`next` は手元から決まる一手（push する・PR を立てる・書きかけを続ける）
- **commit**: 作者が私かは、材料に機械が出す作者の名前でなく `git show -s --format=%ae <sha>` と `git config user.email` の一致で決める（違えば作者の名前で）。枝は `HEAD~n` なら今の枝、sha なら `git branch --contains <sha>` を 1 回。`headline` は「2971ea2 は 9/6 に私が作った commit で、いま居る枝 main に入っている（PR を経たかは見ていない）。動かすものは無い」——「済み」とは言わない。`where` に手元の 1 文は書かない（枝の名前が無い）。`turn` は「GitHub 側も手元の未コミットも見ていない」と断り、止めているものは無いと書く。`next` は「PR が有るなら番号で呼び直す」「前後を読むなら HEAD / HEAD~n で呼ぶ」「手元は引数なしで呼ぶ」。範囲 `A..B` は、範囲に含まれる最初と最後の commit で言い切る。その 2 つは、範囲で呼んだときの材料の 1 行目の見出し（`# A..B commit N 件（最初 → 最後。A は範囲の外）`）の括弧にある。A は範囲の外なので、N 件の 1 つとして書かない。例（`e824033^..b27cb3d` で呼んだとき。sha・件数・日付は材料の値に替える）: 「e824033 から b27cb3d までの commit 4 件は 9/6 に私が main に入れた」
- **会話から推定した番号**: `headline` の直後に「今のブランチ main には PR も名前の番号も無く、会話に出ていた #N を出している」を 1 文。手元の 1 文は、番号を推定する前に引数なしで呼んだとき（`catchup.py this`）の材料の手元の節から書く。ブランチは絶対名（「今のブランチ」でなく `main` のような名前そのもの）で書き、推定した番号の枝に移していないことも書く

## 会話の話題

呼ぶ前に番号・枝・commit に解けた話題はここではない（その対象の形で全部出す）。会話の中にしか無い話題（レビューで見つけた指摘の束・検討中の案）は、材料を `-` にして描く: `catchup.py --render - <欄の JSON>`（ページの置き場は `~/.cache/attention/catchup/topics/` で、`title` ごとに 1 枚）。欄は同じで、`title` に話題の名前（読む人の語）を足す。`headline` は「「新しく出たもの」は #1505 の再レビューで私が見つけた suggest（提案の指摘）4 件で、まだ PR には書いていない」のように**話題が何かを言い切る**。材料は会話そのもので、要約で前半が消えていれば、`what-am-i-doing.py --topic "<話題の語句>"` でその語句が出た会話の往復（依頼と返答の組）を取り出して補う。結び付いた番号があれば、その番号の機械の出力で「PR に書いたか・相手（その PR の作者やレビュアーなど、私以外の人）が動いたか」を確かめる。会話に無いことは書かず、会話の中で確かめていないことは「（未確認）」。引数なしから会話で番号を推定したときは、話題の形ではなく、番号で呼ばれたときと同じ形。
