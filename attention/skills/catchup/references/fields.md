# /catchup のフィールドの書き方（フィールドの JSON を書く前に、どの件でも毎回読む）

/catchup（1 件の PR などについて、前回から何が起きたかを 1 枚の HTML のページに描くコマンド）を動かす AI が、ページに描く文（フィールド）を JSON で書く前に読む。中身は JSON の形・ページの上のフィールドの書き方・PR でないときの形・言葉。

目次:

- ページの並び
- JSON の形
- 文体
- `headline`（いまのターンの 1 文）
- `where`（前回からの動き）
- `turn`（止めているもの）
- `next`（次にやること）
- `unseen`（見ていないもの）
- PR でないとき
- 言葉

前提:

- **機械**は `catchup.py`。`--out` を付けて呼ぶと、AI が読む文字の報告（**材料**）と、ページの構造の JSON（**描く材料**）を書く。`--render` が描く材料とフィールドからページを描き、VS Code で開く（`ATTENTION_CATCHUP_OPEN=0` なら開かない）。
- **私**は gh の認証ユーザで、ページを読む人。フィールドは全部その人の立場で書く。「私の指摘」はその人が出した指摘、「私の番」はその人が動くターン。手元の `git config user.email` と一致する commit は私の push と数える。
- **痕跡**は、私がこの件に残した発言・レビュー・push。材料の「私が最後にしたこと」が最後の痕跡で、「前回から」はその時点より後。
- **止めているものの行**は、ページのいまのターンのセクションに機械が出す状態の行（承認・CI・取り込み・返事待ちの指摘の件数など）。

## ページの並び

上から、見出し → いまのターン → 前回から → この PR がすること → 指摘 → CI → 変更 → 手元 → 見ていないもの。読む人は上から 5 秒（いまのターン）・1 分（前回から・この PR がすること）・5 分（指摘・変更）の順に読む。上のフィールドほど短く書く。

- 見出し・ターンの札（誰のターンかの印）・立場・止めているものの行・ターンの受け渡しの流れ・指摘・CI のログ・差分・手元は、機械が描く。AI は写さない。
- いまのターンに `headline` と `next`、前回からに `where` と `turn`、この PR がすることに `lead`・`figure`・`terms`・`explain`・`points`、見ていないものに `unseen` が出る。

## JSON の形

```json
{
  "headline": "誰が何をしたので、いま誰が何をするターンか（1 文）",
  "where": ["最後にしたこと", "その後の動き（1 項 1 事実）"],
  "turn": ["止めているものの原因と、誰が外せるか"],
  "next": ["一手", "その次"],
  "unseen": ["機械の申告に足す、見ていないもの"],
  "lead": "…", "figure": {"kind": "…"}, "terms": [], "explain": [], "points": {}
}
```

- `headline`・`where`・`turn`・`next` は必ず書く。
- `lead`・`figure`・`terms`・`explain`・`points` は「この PR がすること」のフィールド。書かないなら省く（`figure` は `null` でもよい）。
- `unseen` は無ければ省く。
- 最上位の `title` は、会話の話題のときだけ足す（材料が無いので件名をここに書く）。
- 知らないキー・空の文字列・字数や個数の上限の越えは、機械が止めて 1 件 1 行で言う。

## 文体

- 常体の短い文で書く（「〜した」「〜の番」）。1 文に 1 つの情報。
- `where` と `turn` は 1 項に 1 つの事実を並べる。ページは箇条で描く。
- 状態の値（CI の本数・承認・取り込み・返事待ちの件数）は文に書かない。止めているものの行に機械が出しているので、書くと 1 枚に同じことが並ぶ。
- 文中の `` `…` `` はコードの札になる。`#番号`・commit の sha・`@名前` は機械がリンクか札にする。
- この文書の例は書き方の一つで、写す文言でも許可の一覧でもない。例に無い場面も、規則に当たれば書く。

```json
{
  "headline": "私の指摘 3 件に作者が今日の夕方まとめて返信した。読んで返す私の番。",
  "where": ["昨日（10/15）、テストが例外の包み方を手で写していると指摘した", "作者が 15:32 に push し、15:44 に 3 件へ返信した"],
  "turn": ["止めているのは私の返事だけ", "3 件のうちコードで直したのは 1 件（4cf1df3aa）", "残る 2 件は、作者が #2010 と #2076 に分けた"],
  "next": ["4cf1df3aa を読み、失敗した日付のデータが解放されるかを確かめる", "#2010・#2076 への分割を受けるかを決める", "3 件に返信して解決にする", "承認するか、追加の指摘を出す"]
}
```

## `headline`（いまのターンの 1 文）

ここだけ読めば用が足りる 1 文にする。誰が何をしたので、いま誰が何をするターンか（どこで止まっているか）を、確かめた結果で書く。

- 番号・件名・立場は書かない（ページの頭とセクションの見出しに機械が出す）。進める一手は `next` の先頭に書く。
- 止まり方は 3 つ: 私が動かせる・別の番号を動かすと進む・誰かを待っている。
- 別の番号が私の物なら、私の物だと先に言う（言わないと他人の PR 待ちに読まれる）。
- 材料の `取り込み先` が既定ブランチでなく、そのブランチの PR が open なら、その番号と誰の物かを入れる（その PR が入るまで、この PR は既定ブランチに届かない）。
- 私の一手で終わるのが私の側だけ（返信しても、PR は下書きのまま・依頼が未送・別の番号待ち）なら、「進む」と書かず「私の側は終わり、その後は X さんの番」と書く。
- 機械の理由ごとに、次のように書く:
  - 「レビュー依頼が誰にも出ていない（依頼先を決めるのは私）」→ 渡す先を決めるのが私だと分かるように書く。作者から担当として受けた PR にも出て、そのときも決めるのは受けた私。
  - 「作者以外の人のレビューが付き、依頼は残っていない」→ 私の一手は、付いたレビューに応えて依頼を出し直すこと。
  - 「作者以外の人のレビューが付いた。人宛のレビュー依頼を出した記録は無い」→ 私の一手は、依頼先を決めるか、付いたレビューに応えること。
  - 札が「待ち」で「担当 X 待ち」→ X に渡してあり、X を待っている（渡す先を決める一手は書かない）。
  - 「CI 赤は担当（私）しか外せない」「衝突の解消は担当（私）」→ 作者から担当として受けた PR で、外すのは私。
- 私が入っていない他人の PR で、GitHub にも会話にも依頼が無いなら「作者 X を待っている」と書く。
- 閉じた件（merged・closed）は、同じ 1 文で済んでいて動く物が無いと言い切る（「merge 済みで、私が動くものは無い。」）。
- 書けたら問う: この 1 文だけを見た人が、何の話で、自分が動くのか、急ぐのかを言えるか。

## `where`（前回からの動き）

- 先頭の項は、私が `N 日前（M/D）` に何をしたか。N は機械の行に有ればそれを使い、無ければ（作成や渡された時点の行は日付だけ）機械の日付から今日までを数える（年は今年と見る）。同じ日は「今日（M/D）」、前日は「昨日（M/D）」。
- 機械が「この件で私はまだ何もしていない」と言うなら、その旨から始め、起点を私に渡された時点（誰の何で）か作成（誰が立てたか）にする。
- 後ろの項に、その後の動きを書く。誰も動いていなければその旨を、動いたなら誰が何をしたかを書く。人は名前で書く（「相手」と書くと誰かで止まる）。発言を「」に入れるのは、その人の語そのままのときだけ。
- 私宛の依頼があれば、いつ誰から何が来て、済んでいるか未対応かを書く（未対応なら `next` の先頭にする）。
- その後に push があれば、材料の `私の痕跡以降に変わった file` の件数を書く。
- 末尾の項に、手元の 1 文を書く。書くのは、材料に見出しの「ブランチ」の行か「手元のブランチ」のセクションが有るときだけ。ブランチは「今のブランチ」と書かず、名前そのもので書く。例:
  - 「手元は main から feat/123-x に移した」
  - 「手元に feat/123-x は無かったので origin から取り、main から移した」
  - 「手元は feat/123-x に居る」
  - 「手元は main のまま（手元に未コミット 3 件があるので feat/123-x へ移していない）」
  - 「手元に feat/123-x は無く、origin にももう無い（PR は merge 済み）。手元は main のまま」
- 移らなかったときの今のブランチは、機械の「ブランチ」の行の末尾の括弧から写す。推測で main と書かない。

## `turn`（止めているもの）

- 何が止めていて、原因は何で、誰が外せるかだけを書く。関係する別の番号の紹介や、推測の経緯は書かない。
- 止めているものが無いなら、無いことが分かるように書く。
- `headline` に出した別の番号は、ここで 1 回だけ説明する（何の PR か・誰の物か・状態）。番号そのものは何度出てもよい。
- 材料に `上に積む` があれば、この PR を base にしている PR の番号と誰の物かを 1 文で書く（この PR が止まると一緒に止まる）。
- 止めているものの行のうち、どれが効いていて原因は何かを書く。CI は、落ちたチェックの原因がいくつあるかを書き、複数本で原因が 1 つなら 1 つだと言い切る。

## `next`（次にやること）

- 1 項に 1 つの動作を書く（理由は `turn` へ）。ページは先頭の項を大きく描き、先頭の 3 手を出して残りを畳む。
- 空にしない。待ちなら、何を待ち、動いたら何をするかを書く。
- 閉じた件は、先頭を「この件で私が動くものは無い」にする。任意の後片付け（残った会話を解決にする・後から読み直す）があれば、後ろに「（任意）」を付けて並べる。
- 私が入っていない PR で待ちなら、「依頼が来たら本文と変更を読む」「レビューを返す」を並べ、最後の項を「来なければこの PR で私が動くことは無い」にする。
- 機械がブランチに移らなかったときは、その一手を先頭に書く。機械の行が `→` の後ろに一手を書いていれば、その後ろをそのまま写す（文言は機械が状況で変えるので、自分で組み立てない）。書いていなければ、移らなかった訳を外す一手を書く。別の worktree に checkout 済みなら「<path> で続ける」。手元に無いだけなら機械が origin から取って移るので、`gh pr checkout` は書き足さない。
- 一手が「依頼先を決める」で、材料に `依頼先の候補` が出ていれば、候補の名前と機械の付けた理由をそのまま括弧で添えてよい。「X に依頼を出す」とは書かない（決めるのは私）。
- ページは、先頭の項が「前回から」の commit の sha を含めば「差分へ」、返信・会話・指摘の語を含む最初の項に「指摘へ」、CI・赤の語を含む最初の項に「CI へ」の飛び先を付ける。

## `unseen`（見ていないもの）

機械の申告（上限で切れた分・GitHub の外・結び付いていない commit・痕跡の基準が近似）は、ページの末尾に機械が並べる。AI が足すのは、機械が言っていない穴だけ: 確かめようとして確かめられなかったこと（読めなかった CI のログ・引けなかった別の番号）と、会話の要約で消えた分。機械が数で出している物（未解決の件数・CI の本数・承認の数）は見ているので書かない。

## PR でないとき

- **ブランチに PR が無い**（未コミットの変更・push していない commit・既定ブランチより先の commit のどれかが有る）:
  - `headline` は「今のブランチ main に PR は無く、名前にも番号が無い」の形。
  - `turn` は「GitHub 側は見ていない」と断り、手元の事実（未コミットの変更・push していない commit・PR が無いこと）を書く。
  - `next` は手元から決まる一手（push する・PR を立てる・書きかけを続ける）。
- **commit**:
  - 作者が私かは、材料の作者の名前でなく、`git show -s --format=%ae <sha>` と `git config user.email` が一致するかで決める（違えば作者の名前で書く）。
  - どのブランチに入っているかは、`HEAD~n` なら今のブランチ、sha なら `git branch --contains <sha>` を 1 回打って決める。
  - `headline` は「2971ea2 は 9/6 に私が作った commit で、いま居るブランチ main に入っている（PR を経たかは見ていない）。動かすものは無い」の形。「済み」とは言わない。
  - `where` に手元の 1 文は書かない。
  - `turn` は「GitHub 側も手元の未コミットの変更も見ていない」と断り、止めているものは無いと書く。
  - `next` は「PR が有るなら番号で呼び直す」「前後を読むなら HEAD / HEAD~n で呼ぶ」「手元は引数なしで呼ぶ」。
  - 範囲 `A..B` は、範囲に含まれる最初と最後の commit で言い切る。その 2 つは、材料の 1 行目の見出し（`# A..B commit N 件（最初 → 最後。A は範囲の外）`）の括弧にある。A は範囲の外なので、N 件の 1 つに数えない。例（`e824033^..b27cb3d` で呼んだとき）: 「e824033 から b27cb3d までの commit 4 件は 9/6 に私が main に入れた」。
- **会話から推定した番号**: `headline` の直後に「今のブランチ main には PR も名前の番号も無く、会話に出ていた #N を出している」を 1 文書く。手元の 1 文は、推定する前に引数なしで呼んだときの材料の「ブランチ」の行から書き、推定した番号のブランチに移していないことも書く。そのほかは番号で呼ばれたときと同じ形。
- **会話の話題**（番号・ブランチ・commit に結び付かない話題）:
  - 最上位の `title` に、話題の名前を読む人の語で書く。
  - `headline` は話題が何かを言い切る（「「新しく出たもの」は #1505 の再レビューで私が見つけた提案の指摘 4 件で、まだ PR には書いていない」）。
  - 材料は会話そのもの。会話に無いことは書かず、会話の中で確かめていないことには「（未確認）」と付ける。

## 言葉

この件を知らない同僚に口で説明するときの言葉で書く。1 文 1 情報、能動態、肯定形。

- 使わない: GitHub と CI の語（reviewDecision・スレッド・rollup・CHANGES_REQUESTED）・コンサル英語・直訳の横文字・この件の中でしか通じない略号・「〜と思われる」「〜のようだ」（確かめていないことは「（未確認）」と付けて書く）。
- 機械の理由文（「私の件に相手の発言があり…」）を丸写ししない。確かめた結果を書く。材料の語と印（`取り込み先`・`上に積む`・`依頼先の候補`・`← 私が返すターン`・`← 私が最後に発言している（相手のターン）` など）は、材料を探す手掛かりで、フィールドには写さず中身を書く。
- この文書の語（材料・機械・フィールド・焦点・スクリプト）をフィールドに持ち込まない。ページのセクションの名前（指摘・CI・変更・手元）は指してよい（「下の指摘 3 件」）。機械がスクリプトの名前（what-am-i-doing.py・catchup.py）で書いた口は、`/what-am-i-doing`・`/catchup` の呼び名に替える。
- 使ってよい: 製品名・標準の仕様の名前（Helm・pgvector など）・IT で定着した英語（API・CI など）。
- どうしても要る記号は、初めて出す所で中身を先に書き、記号を後ろの括弧に入れる（「まだ承認されていない（REVIEW_REQUIRED）」）。
- 同じ物は同じ語で呼ぶ。状態の語・立場・動作は、/whose-turn・/what-am-i-doing と揃える。
