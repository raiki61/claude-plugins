# /catchup の一覧（対象・旗・ページのセクション・材料の上限と続きの口）

/catchup（1 件の PR などについて、前回から何が起きたかを 1 枚の HTML のページに描くコマンド）を動かす AI が、旗や続きの口を使うとき、ページのセクションの描かれ方を確かめるときだけ読む。数値の正本は `attention/docs/catchup-spec.md`。

前提（語は SKILL.md と同じ）: **私の痕跡**は、この件に私（gh の認証ユーザ）が残した最も新しい跡（本文コメント・レビュー・レビューのスレッドの発言・push のどれか）で、「前回から」の起点になる。**機械**は `catchup.py`。**材料**は、機械を `--out` 付きで呼ぶと書く文字の報告で、AI が読む。**描く材料**は同時に書くページの構造の JSON。**フィールド**は AI が書く JSON——`headline`（いまのターンの 1 文）・`next`（次の一手）・`where`（前回からの動き）・`turn`（止めているもの）・`lead`・`figure`・`terms`・`explain`・`points`（この PR がすることのひとこと・図・語の一覧・説明・変更点）・`unseen`（見ていないもの）。**私**は gh の認証ユーザ＝このツールを使ってページを読む人（`--me` で替えられる）。`this` は今のブランチ。**焦点**は対象の後ろに付ける語（`指摘`・`地図`・`CI`）で、材料の後ろの側に並ぶ指摘・CI が落ちた理由・変更の地図の 3 つのセクションを、付けた語のセクションだけにする。`地図` は材料の「変更の地図」のセクション（変更ファイル・名前の言及・新規ファイルの骨組み）。

## 一覧（仕様 `catchup-spec.md` の写し。数値の正本はそちら）

`/catchup [対象] [焦点]`。対象は 1 つ、焦点は 0〜3 語（`指摘`・`地図`・`CI`）。`/catchup setup` は準備の口（機械の `--setup` を走らせる）。

| 対象 | 例 | 移る | GitHub | 主な材料 |
|---|---|---|---|---|
| 番号 | `1505` `#1505` | PR の head へ | 見る | PR / issue |
| URL | `https://…/pull/1505` | 同上 | 見る | PR / issue |
| ブランチ名 | `feat/123-x` | そこへ | ブランチの PR が有れば | PR、無ければ手元 |
| 引数なし・`this`・焦点だけ | `/catchup` `/catchup 指摘` | 移らない | 今のブランチの PR が有れば | PR、無ければ手元 |
| commit | `2971ea2` `HEAD~2` `v1.2` `2971ea2..HEAD` | 移らない | 見ない | その commit（範囲なら全部） |
| 会話の話題 | `新しく出たもの` `今の修正` | 移らない | 結び付いた番号だけ | 結び付く対象か、会話 |

| 旗 | 効き | 効く対象 |
|---|---|---|
| `--switch` | 該当のブランチへ移る | 番号・URL・ブランチ名 |
| `--full` | 本文・発言の上限を外す | 全部 |
| `--out` | 材料と描く材料をファイルに書き、その path を返す（付け方は SKILL.md の「守ること」） | 全部 |
| `--frame <path>` | その 1 file の変更を上限なしで | PR・commit（手元の未コミットは、`/what-am-i-doing` の機械 what-am-i-doing.py の `--frame`） |
| `--limit N` | その後の出来事の件数（既定 12） | PR・issue |
| `-R owner/repo` | リポジトリを指す | 番号 |
| `--me <login>` | 「私」を差し替える | PR・issue |
| `--render <描く材料> <欄>` | ページを描き、一覧（`index.html`）を組み直し、VS Code で開く。描く材料は `--out` が書いた JSON の path、フィールドは AI が書いた JSON の path | 全部（会話の話題は描く材料が `-`） |
| `--setup [--check]` | VS Code で見る準備（`--check` は確かめるだけ） | なし |

ページは `~/.cache/attention/catchup/<owner>-<repo>/<番号>.html`（下の「機械が書くもの」）。セクションはこの順で、機械が材料の有るセクションだけを描く。焦点の語で絞ったときも見出し・いまのターン・前回からは描き、後ろは絞った材料のセクションだけ（説明と図は `地図` のときだけ書く）:

| # | セクション | 中身 | 書くのは |
|---|---|---|---|
| 1 | 見出し | 件名・番号・状態・作者・規模・閉じる issue | 機械 |
| 2 | いまのターン | ターンの札（誰のターンかの印）と立場（この件で私は作者かレビュアーかなど）、`headline`、`next`、止めているものの行 | 札と行は機械、文は AI |
| 3 | 前回から | ターンの受け渡しの流れ（GitHub の PR の会話の流れの形）、`where`、`turn` | 流れは機械、文は AI |
| 4 | この PR がすること | `lead`、`figure`、`terms`（このセクションの語）、`explain`、`points`（変更点ごとに差分を開ける） | AI（差分は機械） |
| 5 | 指摘 | 人が入っている未解決スレッド（差分の抜粋・私と相手の最後の発言・前回から変わったか） | 機械 |
| 6 | CI | 赤ごとに、落ちた step のログの末尾 | 機械 |
| 7 | 変更 | 前回から（私の痕跡以降）と全体の差分 | 機械 |
| 8 | 手元 | 「ブランチ」の行と「手元のブランチ」のセクション | 機械 |
| 9 | 見ていないもの | `unseen` と機械の申告 | 両方 |

対象ごとに描かれるセクション（○ 描く／△ 材料が有れば／– 描かない）:

| 対象 | いまのターン | 前回から | がすること | 指摘 | CI | 変更 | 手元 |
|---|---|---|---|---|---|---|---|
| PR | ○ | ○ | ○ | △ | △ | ○ | △ |
| issue | ○ | ○ | △ | – | – | – | △ |
| ブランチに PR 無し | ○ | ○ | △ | – | – | △ | ○ |
| commit | ○ | ○ | △ | – | – | ○ | – |
| 会話の話題 | ○ | ○ | – | – | – | – | – |

会話の話題が番号・ブランチ・commit に結び付いていれば、この表の**その対象の行**を見る（どれに結び付くかは、呼ぶ前に AI が会話から解く。解き方は SKILL.md の「受け口」のセクションが指す）。話題の行は、会話にしか無いものだけ。

上限と、続きを出す口（材料の上限。ページの差分は全部載る）。「切れた」は機械が数で言う——「N 行で切った」「上限 N 件」「古い方 N 件」「本文の残り N 行」。切れていればその口で取ってから書き、取ったものは見ていないものに書かない（もう見ている）:

| 何 | 上限 | 続き |
|---|---|---|
| 作者の本文 | 60 行 | `--full` / `gh pr view` |
| 閉じる issue・参照先の冒頭 | 12 行 | `--full` / `gh issue view` |
| 閉じる issue・参照先の件数 | 3 件ずつ | `--full` |
| 相手の発言（スレッド） | 40 行 | `--full` |
| その後の出来事 | 12 件 | `--limit` |
| 指摘（スレッド）の件数 | 10 件 | `--full` |
| CI の赤の件数 | 3 件 | `--full` |
| 取った commit | 100 本 | 見ていないものに書く |

## 機械が書くもの

**機械（catchup.py）**: 事実だけを出し、判断しない。`--out` で 2 つを書く——AI が読む文字の材料（見出し・私の最後の痕跡・私に求められていること・その後の出来事・私の痕跡以降に変わった file・いまの状態・つながっている先・見ていないもの、続いて 本文（材料）→ 指摘（材料）→ CI が落ちた理由（材料）→ 変更の地図（材料）→ 手元のブランチ）と、ページの雛形が描く構造の JSON（描く材料）。`--render` が、その JSON と AI のフィールドを雛形（`attention/templates/catchup.html`）に流し込み、`~/.cache/attention/catchup/<owner>-<repo>/<番号>.html` を書く（同じ件は上書き）。同じ置き場の `index.html` は、ページごとに 1 行（件・件名・誰のターン・次の一手・更新）を並べる一覧で、描くたびに組み直す。描いた後、生きている VS Code の窓のすべてでページを開く（`ATTENTION_CATCHUP_OPEN=0` なら開かない。開けなくても失敗にしない）

実測 2026-09-16: #1720 の材料は 2,168 行のうち骨組み 158 行・指摘 812 行・地図 1,199 行。
