# /what-am-i-doing の変更の中身の貼り方（中身を求められたときに読む）

このファイルでやらせたいことは 1 つ——機械が出した変更のコードを、読む人が読める形で返答に貼ること。下の前提で語を決め、その後に貼り方の決まりを並べる。

前提（このファイルで使う語。定義の元は、このフォルダの 1 つ上にある /what-am-i-doing の本文 SKILL.md）:
- /what-am-i-doing は、いま居るセッションで何が起きたかを、戻ってきた人に説明するコマンド。このファイルは、その返答を読んだ人に「変更したコードを見せて」と求められたときに開く
- 「機械」＝同梱のスクリプト `what-am-i-doing.py` とその出力（SKILL.md の手順 1 で `--out` を付けて走らせ、Read で読んだ物。このファイルを開く時には読み終えている）。`--frame <path>` は、その file の枠を省かずに出させる指定
- 「変更の中身」＝機械の出力の中で、変更を file ごと・関数ごとの「枠」で見せる部分。枠は、1 つの関数（散文・設定なら変わった所の周り）のコードを行頭 `| ` 付きで並べた行のかたまりで、各枠の前に機械が見出しと「飛び先 path:行」（その枠が手元の file の何行目から始まるか）を出す
- 「帯」＝機械が枠の中に入れてある、変わった所の印（実線の枠・`#│`・点線。読み方は下）

- **中身を求められたら、機械の「変更の中身」の枠を関数ごとに、言語名の枠（```python 等）へ `| ` の後ろをそのまま貼る**。
  言語名は機械が枠の見出しの末尾に置く `（言語名 X）` を写し、無ければ拡張子から必ず付ける
- 帯の読み方: 実線の枠 `┏ … ┗` の中が変わった所。その中で行頭が `#│`（コメント記号に `│`）の行は変更前
  （コメントなので貼ると薄く出る）、`#│` の付かない行は今（構文の色が付いて出る）。点線 `┅` は畳んで省いた区間
- 散文・設定も枠で出る（関数の切れ目が無いので、機械が変わった所の前後 10 行で切る）
- 新規 file は先頭（先頭のコメント・docstring）と骨組み（def・step 名・上位の key など、構造の行）だけが出る。
  `--frame <path>` で全文が出るのは `git add` 済みのものだけ——未追跡の新規は `--frame` でも先頭と骨組みなので、
  全文は file を開く
- 枠の行数をすべての file で足した合計が 800 行を超えると、超えた先の file は名前だけになる（`--frame` で出る）
- unified diff は貼らない（`@@` は人に意味が無く、`+`/`-` は構文の色を消す——実測）
- 順は呼ぶ側 → 本体 → helper
- 関数ごとの見出しは `n/N`（N はこの返答で貼る枠の数、n はその何番目か）と backtick の `path:行`——行は機械が各枠の前に出す「飛び先 path:行」（手元の
  行番号）から写す（対応する端末ではクリックで開ける。新規 file の飛び先は `path:1`）
- 同じ file に枠が複数あれば、2 つ目以降の枠の上に `# path:行（役割）` の注釈を置く。行は同じく飛び先から
  写し、役割はその枠が上の順の呼ぶ側・本体・helper のどれかを書く
- 1 file の枠が 300 行（1 file の上限）を超えると、機械は関数の切れ目で止めてその旨を断る。そう断って
  あれば `what-am-i-doing.py --frame <path>` で全部出る
