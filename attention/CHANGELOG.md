# 変更の記録（attention）

attention の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版を名指しする git の tag（例: `attention--v0.25.1`）の名前の決まり・付け方・付ける commit の一覧への案内と、この記録を書き足す段は、リポジトリのルートの `docs/releasing.md` に在る（プラグインとして入れた実体には無いので、clone か GitHub で見る: https://github.com/raiki61/claude-plugins/blob/main/docs/releasing.md）。

## [0.26.0] - 2026-10-03

### Changed

- /whose-turn: 作者以外の人だけが assignee の PR は、作者の番（draft・CI 赤・指摘対応・マージ・再依頼・レビュー依頼・未依頼・レビュー待ち）を作者から外し、その人たち全員の番に移す。draft も移す。作者は、別の役（自分の指摘への返答待ちなど）が無い限り、その PR を自分の一覧で見なくなる。待ちの日数は、その人が assignee になった日より前へは戻さない。作者も assignee に入っている PR は、今までどおり作者が持つ。
- /whose-turn: 人に数えるのは返答できるアカウント（User）だけで、Copilot 等の Bot・Mannequin・退会済みのアカウントは数えない。Bot・退会済みだけが assignee の PR は作者が持ち、人と Bot が混ざっていれば人だけに移す。Bot・退会済みの assignee には「担当」の行を立てず、作者の未依頼の PR を「まだ誰にも渡していない」から外す相手にも数えない。ただし assignedActors を返さない GitHub（GHES など）では assignee の種別が取れないので、作者の番を assignee へ移さず作者が持ち、作者以外の assignee には今までどおり担当の行だけを立てる。見ていないものにそう書く。
- /whose-turn: 移した PR の未解決スレッドは、作者と assignee のどちらが返しても返答済みとして数える。作者と assignee の間（assignee が 2 人以上なら assignee どうしも）のやり取りは、聞かれた側に返す番、聞いた側に再確認が立つ。聞いた側が作者なら、返事を待つ間は返答待ちも立つ。作者が渡す前に自分だけで書いたスレッドは、assignee が答える番になる。スレッドを立てた人のほかに、作者と assignee の中に返答できる人がいなければ（作者が退会済み・Bot・Mannequin で、ただ 1 人の assignee が立てたスレッドなど）番を立てず、未解決の内訳には書いた人の名で「人は X だけ」と数える。作者が持つ PR でも、作者の自注に人が加わったスレッドは「人は X, Y だけ」と出す（今までは未解決の総数にだけ入っていた）。退会済みの書き手は、作者が実在すれば作者の名でなく「退会済み」と数える。
- /whose-turn: 受けた assignee の draft・未依頼は、最後に誰が発言しても、自分が作者に問うて返事を待っている間も「自分の番」に置く。自分で立てた問いの返事を待っていることは、マージなどほかの行も相手の番へ下げず、その行の日数も問いの日へ戻さない。assignee が 2 人以上なら、CI 赤・指摘対応・マージなどの行は「動ける人はほかにもいる」に並ぶ。自分だけの行（自分の問いの再確認など）と、draft・未依頼だけの行は、assignee が何人でもその人の段に並ぶ。
- /whose-turn: 受けた assignee の行には `作者:` の代わりに `担当として受けた PR（起票は X）` を出し、作者の本文の 1 文と規模も付ける。渡し終えた作者の行には `担当に渡した PR（担当は X）` を出し、/whose-turn はレビュアーとして書く。障害の持ち主は「外せるのは担当の X だけ」と出す。`assignee:` の行は、この役割の行で名指した人を繰り返さない。
- /whose-turn: 返す番を負う人がその PR で一度も発言していなくても、「X は MM-DD HH:MM 以降 発言なし（この PR で発言が無い）」を出す。起点は、受けた assignee なら assignee になった日（履歴に無ければ PR の作成日）、作者なら PR の作成日。作者には括弧書きを付けない（作成日に本文を書いている）。本文の無いレビュー（承認だけなど）を出した人は、そのレビューの日から数えて括弧書きを付けない。コメント・レビュー・スレッドのどれかが取得の上限に当たった PR と、assign の日が取得した履歴（新しい 100 件）の外にありうる PR では、括弧書きを「（見た範囲で発言が無い）」にする。履歴の窓が切れた PR と issue は、走査の上限に当たったものにも出す。
- /whose-turn: 返していない呼びかけの PR の行と、見ていないものの「本文コメントの噛み合い」の該当にも、役割の行（`作者:`・`担当に渡した PR`・`担当として受けた PR`）を添える。噛み合いの該当は番号ごとの行にして、URL も添える（`--all` では `#N → X` で誰の該当かを書く）。Team 宛のレビュー依頼の該当も、件数だけでなく `#N → org/team` の番号ごとの行に URL と役割の行を添えて出す（`--all` では、Team が自分の節に同じ行を持つ分は件数だけ。draft の PR の依頼は Team の節に行が無いので、`--all` でも番号の行で出す）。/whose-turn は、機械に行が無かった番号の役割と URL を自分で引かなくなった。

作者以外の人だけを assignee にする PR を、assignee をレビュアーの意味で使うリポジトリで使うと、作者の直す番がレビュアーに移って見える。GitHub の assignee の定義（その PR で作業している人）に合わせた割り切りで、/whose-turn の手順書の守ることに書いた。
- /whose-turn: 作者も assignee に入っていてレビュー依頼を一度も出していない PR は、作者の「まだ誰にも渡していない」に置く。今までは、ほかの assignee へ渡した扱いにしてこの段から外していた。そのため、作者が最後に発言していれば「相手が動くまで進まない」、そうでなければ誰も待っていないのに「あなたを待っている人がいる」に出ていた。/catchup の「依頼先を決めるのは私」と揃う。作者を入れずに assignee を付けた PR は今までどおり。
- /whose-turn: レビューを依頼されている人の段は、その人への最新の依頼より後の発言だけで決め、依頼の後に本人が解決済みスレッドに書いた発言（「確認しました」など）も数えない。依頼より前の本人の発言（変更要求の本文など）やその相槌が最後でも、「相手が動くまで進まない」に下げない。その人の行の「X は … 以降 発言なし」も、依頼の後に本人が話したときだけ出す。次のときは今までどおり相手の番: 依頼より後に本人が問いを出して答えを待っているとき、未解決スレッドで本人が出した問いに作者の側がまだ返していないとき（問いが依頼より前でも。作者にはスレッド返答の行が立つ）。
- /catchup: PR の番の持ち主の述語と、依頼が残っていない PR の分け方（部品 lib/turn.py）を /whose-turn と共用する。作者以外の返答できる人（User）だけが assignee の PR では、下書き・CI 赤・衝突・要修正・マージの番を担当の人の /catchup に出し（「CI 赤は担当（私）しか外せない」など）、作者と第三者には「○ 待ち — 担当 X 待ち」と出す（並べるのは人だけ）。受けた担当の人には、レビュー依頼が出ている間は「○ 待ち — レビュー待ち: X」と出し、依頼の記録もレビューも無い未依頼の PR では「レビュー依頼が誰にも出ていない（依頼先を決めるのは私）」と依頼先の候補を出す。どちらも「私が担当（assignee）」は出さない。依頼の記録か作者以外の人のレビューがある渡した PR では、作者に出す理由は再依頼・レビュー依頼の 1 つだけで、CI 赤などは添えない（受けた担当の人には今までどおり「私が担当」、第三者には今までどおり「作者 X 待ち」。CI 赤・衝突が残っていれば、それを外す担当の人の「担当 X 待ち」）。Copilot などの Bot・Mannequin・退会済みだけが assignee の未依頼の自分の PR は、担当待ちではなく「レビュー依頼が誰にも出ていない（依頼先を決めるのは私）」と依頼先の候補を出す。assignedActors を返さない GitHub（GHES など）では種別なしで取り直し、番は作者が持ったまま、作者が assignee に入っていない未依頼の PR は今までどおり作者に担当待ちと出し、第三者にも作者待ちでなく担当待ちと出す。そのことは、作者以外の assignee がいる PR の「見ていないもの」に書く。issue の待ち先（起票者 X 待ち）は今までどおり。
- /catchup と /whose-turn でまだ揃っていない形: (a) 人の assignee に渡した PR で依頼の記録か作者以外の人（担当を含む）のレビューがあると、/catchup は作者に再依頼・レビュー依頼と依頼先の候補を出し、担当の人には「私が担当」と出す。/whose-turn はその番を担当へ移す（持ち主に確認中）。(b) 依頼の出来事と人のレビューを読む窓: /catchup は依頼の出来事だけの窓と人ごとの最新レビューを、/whose-turn は 4 種の出来事が取り合う窓と最新 100 件のレビューを読む。窓が埋まった PR では分け方が割れうる。(c) 衝突: /catchup は持ち主の番の理由に数え、/whose-turn は持ち主の行に数えない。
- /whose-turn: assignedActors を返さない GitHub で、作者が自分を入れずに assignee を付けた未依頼の PR は、作者の「相手が動くまで進まない」に置く。今までは作者が最後に発言していないと、誰も待っていないのに「あなたを待っている人がいる」に出ていた。未解決スレッドで作者に返す番が残っていれば今までどおり自分の番。/catchup の「担当 X 待ち」と揃う。
- /catchup: レビュー依頼の出来事の窓が切れたかは、/whose-turn の履歴の窓と同じく GitHub の hasPreviousPage だけで決め、「見ていないもの」に出す。今までは窓（新しい 100 件）が埋まっていなければ、hasPreviousPage が真でも切れていないと読んでいた。hasPreviousPage は種別で絞った後の数で決まるので（実測 2026-10-02）、出力が変わるのは GitHub の答えが件数と食い違うときだけ。窓が切れた PR を担当として受けた人の未依頼にも、前に作者が人へ依頼していれば分け方が変わる読み違い（依頼先を決めるのは作者で、出している依頼先の候補は要らない）を添える。
- /catchup: 担当（assignee）・人ごとの意見・人ごとの最新レビューが取得の上限で切れたときも「見ていないもの」に出し、それぞれで何を読み違えうるかを添える。/whose-turn は、人ごとの意見の上限を「走査の上限に当たったもの」に出す。

### Fixed

- /catchup が、作者以外の人のレビューが付いて依頼が消えた自分の PR を「レビュー依頼が誰にも出ていない」と出し、依頼先の候補まで添えていたのを直した。GitHub はレビューを送った人を依頼の一覧から外すので、今の依頼だけでは見分けられなかった。この場合は「再依頼か指摘対応は私」と出す。依頼を一度も出していない PR に依頼していない人（担当で渡した相手も含む）のレビューだけが付いたときも同じ番と出すが、理由は「人宛のレビュー依頼を出した記録は無い（依頼先を決めるか指摘対応は私）」と言い分け、候補は今どおり添える。レビューの有無は人ごとの最新レビューから、依頼を出したかは依頼の出来事だけの窓（新しい 100 件。Copilot などの Bot 宛の依頼もこの数に入る）から読む。窓が埋まり、それより前が無いと GitHub が言わないときは「見ていないもの」に出し、自分の PR で前に人へ依頼していれば分け方が変わるときは、その読み違い（候補は要らない・担当に渡したと分けたのは誤り）を添える。
- 承認の行の reviewDecision が null のときの文言を「レビューがまだ 1 件も無い」から「承認・要修正の判定なし」に改め、承認の規則が無い base では承認しても付かないことを添えた（その base では承認しても null のまま返るので、旧文言は偽になっていた）。
- 依頼を出したことが無く作者以外の人だけが担当（assignee）の PR は、レビューがまだ付いていない間は /catchup で担当待ちと出す。作者も担当に残っている PR は今どおり作者が持っている扱い。どちらも持ち主の決定（人の関所 2026-10-02。会話はリポジトリの外なので、この行を出どころの記録にする）。
- Copilot などの Bot だけへの依頼は依頼に数えない（/whose-turn と同じ）。時系列の Bot 宛の依頼は「→ Bot（依頼に数えない）」と出す。Bot 宛の依頼が残る PR を待ちとして出すときに落ちていたのも直った。
- /whose-turn・/catchup: 変更要求を出した人全員にレビューを依頼し直した PR で、作者に指摘対応（/catchup では「要修正が付いている（指摘対応は私）」）を立てていたのを直した。reviewDecision は変更要求を出した人が承認するまで残るので、人ごとの最新の意見（latestOpinionatedReviews）と今の依頼を見る。作者はレビュー待ち、レビュアーはレビューの番になる。次のときは今までどおり指摘対応を立てる。依頼し直していない人が 1 人でもいるとき、Team 宛の依頼しか無いとき（所属を展開していない）、人ごとの意見が取得の上限で切れているとき。
- /whose-turn: PR の持ち主が自分で立てた問いのスレッドにほかの人が書いた発言を、最後の発言者を決める材料から外していたのを直した。本文に書いた発言と同じに数える。今までは、相手がそのスレッドで答えても、それより古い持ち主の発言が最後に繰り上がり、マージなどの行が「相手が動くまで進まない」に沈んでいた。持ち主自身の問いの発言は今までどおり数えない。
