# 変更の記録（attention）

attention の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版の出し方（この記録を書き足す段。git の tag は作らない）は、リポジトリのルートの `docs/releasing.md` に在る（プラグインとして入れた実体には無いので、clone か GitHub で見る: https://github.com/raiki61/claude-plugins/blob/main/docs/releasing.md）。

## [Unreleased]

### Fixed

- `/reflect` の GitHub の動きは、既定の 1 週間を見るはずが、直近の 1〜3 日ほどしか取れていなかった。GitHub の出来事の API は新しい 300 件までしか返さず、部署の push で埋まるため。取れた一番古い時刻を材料の `github` の `from` に出し、ページの頭の「見た範囲が欠けている」の箱に書く。そのアカウントは、期間に更新のあった、そのアカウントが関わる PR・issue を検索の API で 300 件まで補う（`search`。何をしたかまでは分からない）。前はモデルが見ていないものに書くのに任せていた。
- `/reflect` と `/what-am-i-doing` が、人の発言を `promptSource` の `typed`・`queued` だけで見分けていた。そのため、Claude Code が足した `suggestion_accepted`（出された次の発言の候補を、人が受けて送った物）が落ちていた（2026-10-19 に直近 3 日の記録で 8 件）。これも人の発言に数える。見分け方は 2 本が共用する `lib/transcript.py` の 1 か所に置いた。

### Added

- `/reflect` のページの頭に、見た範囲の欠けを出す（材料の `coverage.notes`）。出すのは次の 4 つ。
  - GitHub の出来事が期間の頭に届かなかったアカウント。
  - 会話の記録が期間の始まりより後からしか無い設定のフォルダ。Claude Code は、最後の動きから `cleanupPeriodDays`（既定 30 日）を過ぎた記録を消す。そのため `month` では、それより前に終わった会話が数えられない。
  - 読むと言われたのに無い設定のフォルダと、ホームの `.claude*` のうち会話の記録を持つのに読んでいないフォルダ。前はどちらも黙って飛ばしていた。
  - 人の発言の見分けが崩れた見込み。知らない `promptSource` の値（人の発言に数えず、値ごとの件数を出す）。返答が有るのに `promptSource` の付いた行が 1 つも無いとき。手で開いた会話に返答が有るのに、人の発言が 0 件のとき。
- `/what-am-i-doing` も、知らない `promptSource` の値と、返答が有るのに打った発言が 0 件のことを「注意:」の行に出す。

## [0.39.1] - 2026-10-19

### Fixed

- `/catchup` が、作者以外の人のレビューが付いて依頼が消えた自分の PR を「レビュー依頼が誰にも出ていない」と出し、依頼先の候補まで添えていたのを直した（#1901）。GitHub はレビューを送った人を依頼の一覧から外すので、今の依頼だけでは見分けられなかった。この場合は「作者以外の人のレビューが付き、依頼は残っていない（再依頼か指摘対応は私）」と出し、候補は出さない。
  - 依頼を一度も出していない PR に、依頼していない人（担当で渡した相手も含む）のレビューだけが付いたときも私のターンと出すが、理由は「人宛のレビュー依頼を出した記録は無い（依頼先を決めるか指摘対応は私）」と言い分け、候補は今どおり添える。依頼がレビュー無しで外れた PR も今どおり候補を出す。
  - 依頼を出したことが無く、作者以外の人だけが担当（assignee）でレビューがまだ付いていない PR は、「担当 X 待ち」と出す（候補は出さない）。作者も担当に残っている PR は今どおり作者が持っている扱い。
  - レビューの有無は人ごとの最新のレビューから、依頼を出したかはレビュー依頼の出来事だけの窓（新しい 100 件。Copilot などの Bot 宛の依頼もこの数に入る）から読む。窓が埋まり、それより前が無いと GitHub が言わないときは「見ていないもの」に出し、前に人へ依頼していれば分け方が変わるときは、その読み違いも添える。
- Copilot などの Bot だけへの依頼は依頼に数えない（`/whose-turn` と同じ）。時系列には「→ Bot（依頼に数えない）」と出す。
- 承認の行の、reviewDecision が null のときの文言を「レビューがまだ 1 件も無い」から「承認・要修正の判定なし（reviewDecision なし——まだ誰もレビューしていないか、承認の規則が無い base。後者では承認しても付かない）」に改めた。承認の規則が無い base では承認しても null のまま返るので、前の文言は誤りになっていた。
- `/whose-turn`: 作者以外の人だけが assignee の PR で、作者のターンが作者に残り、受けた人の報告（/whose-turn の出力）には「担当」の行しか出なかったのを直した。**assignee の扱いが変わる**: 作者が assignee に入っておらず、人（User）が assignee にいる PR は、作者のターン（draft・CI 赤・指摘対応・マージ・再依頼・レビュー依頼・未依頼・レビュー待ち・分類なし〔reviewDecision が知らない値〕）をその人たち全員へ移す。draft も移す。作者は、別の役（自分の指摘への返答待ちなど）が無い限り、その PR を自分の報告で見なくなる。今までは、作者以外の assignee がいる未依頼の PR を作者の「相手の番」に置き、draft は作者の「自分の番」に残していた。作者も assignee に入っている PR は今どおり作者が持つ。
  - 待ちの日数は、その人が assignee になった日より前へは戻さない。assignee が 2 人以上なら、CI 赤・指摘対応・マージなどの行は「動ける人はほかにもいる」に並ぶ（draft・未依頼だけの行は、受けた assignee それぞれの「まだ誰にも渡していない」に並ぶ）。
  - 人に数えるのは返答できるアカウント（User）だけで、Copilot などの Bot・Mannequin（他のサービスから移した履歴の、実在しない名義）・退会済みは数えない。人に数えないアカウントだけが assignee の PR は作者が持ち、人と混ざれば人だけへ移す。assignee の種別を取るため、問い合わせを `assignees` から `assignedActors` に替えた。`assignedActors` を返さない GitHub（GitHub Enterprise Server など）では種別が取れないので、今どおり作者が持ち、報告の末尾の「見ていないもの」にそう書く。
  - 移した PR の未解決スレッドは、作者と assignee のどちらが返しても返答済みとして数える。作者と assignee の間（assignee が 2 人以上なら assignee どうしも）のやり取りは、聞かれた側に返すターン、聞いた側に再確認が立つ。作者が渡す前に自分だけで書いたスレッドは、assignee が答えるターンになる。受けた人が自分で立てた問いの返事待ちは、マージなどほかの行を相手の番へ下げない。
  - 行の事実: 受けた人には `作者:` の代わりに `担当として受けた PR（起票は X）` を出し、PR の説明文の最初の 1 文と規模（変更したファイルの数と、足した行・消した行の数）も付ける。渡し終えた作者には `担当に渡した PR（担当は X）` を出す。マージを止めている物（CI 赤・main 未追従）に添える「外せるのは作者の X だけ」は、移した PR では「外せるのは担当の X だけ」と出す。返すターンを負う人がその PR で一度も発言していなくても「X は（日時） 以降 発言なし（この PR で発言が無い）」を出す。返していない呼びかけ（@login で呼ばれてまだ返していないもの）の PR の行にも、役割の行（`作者:`・`担当として受けた PR`・`担当に渡した PR`）を添える。
  - `--json`: `role` は、その人が持ち主（作者か、担当として受けた人）なら `implementer`、ほかは `reviewer`（渡し終えた作者も `reviewer`）。`waits` の PR の項に `role` を足した（issue は `null`）。今ある JSON のキーは消していない。
- 変更要求（CHANGES_REQUESTED）を出したレビュアーに直して依頼し直した PR で、`/whose-turn` と `/catchup` が作者（持ち主）の「指摘対応」を出し続けていたのを直した（#1843）。変更要求を出した人の全員（人ごとの最新の意見で見る。後で承認に変えた人は数えない）に、人として依頼が出ていれば、ターンはレビュアーにある。1 人でも依頼が出ていない人がいれば今どおり指摘対応。Team 宛の依頼はその所属の人への依頼に数えない。人ごとの意見は新しい 30 件まで取り、切れていれば今どおり指摘対応を出して「見ていないもの」に書く。
  - `/whose-turn`: レビューを依頼されている人の「最後に発言したのが自分か」（相手の番に下げる判定と、「X は（日時） 以降 発言なし」の行）は、依頼より後の発言だけで見る。依頼の後に本人が解決済みのスレッドに書いた発言（「確認しました」など）も数えない。今までは、変更要求の本文や依頼前の返事が最後の発言に数えられ、再依頼された人の行が相手の番に下がって、誰の「自分の番」にも出なかった。
  - `/whose-turn`: 持ち主が自分で立てた問いのスレッドで、最後の発言者の判定から外すのを持ち主本人の発言だけにした。今まではスレッドごと外していて、相手がそこに書いた答えまで消え、持ち主のマージなどの行が相手の番に下がっていた。
- `/whose-turn`: 作者も assignee に入っている未依頼の PR を、作者が渡した扱いにして「相手の番」に置いていたのを直した。作者が持っていて、まだ誰にも渡していない（「自分の番」の「まだ誰にも渡していない」）。assignee の種別が取れない GitHub で作者が自分を入れずに assignee を付けた未依頼の PR は、誰も発言していなくても作者の「相手の番」に置く（`/catchup` の「担当 X 待ち」と同じ読み）。
- `/catchup`: PR の持ち主を `/whose-turn` と同じ規則（共用の部品 `scripts/lib/turn.py`）で決めるようにした。今までは作者を持ち主と決め打ちしていて、作者が自分を入れずに人を assignee に付けた PR でも、CI 赤・衝突・要修正・マージ・下書きを作者のターンと出していた。
  - 担当として受けた PR では、これらは担当（私）のターンで、「CI 赤は担当（私）しか外せない」「衝突の解消は担当（私）」のように出す。依頼も他人のレビューも無ければ「レビュー依頼が誰にも出ていない（依頼先を決めるのは私）」と依頼先の候補も受けた私に出し、渡した作者には「担当 X 待ち」と出す。
  - 渡す前に人へ依頼したか、作者以外の人（担当も含む）のレビューが付いていれば、依頼先を決めるターンは今どおり作者に残り、受けた担当には「私が担当（assignee）」と出す。
  - 人に数えるのは返答できるアカウント（User）だけで、Copilot などの Bot や Mannequin だけが assignee なら作者が持つ（今までは Bot の assignee にも「担当 X 待ち」と出していた）。assignee の種別を取るため、問い合わせを `assignedActors` に替えた。返さない GitHub（GitHub Enterprise Server など）では種別なしで取り直して作者が持つ形で出し、「見ていないもの」にそう書く。

## [0.39.0] - 2026-10-19

### Added

- 共有の認証の部品 `scripts/lib/claude_auth.py`（ルートの scripts/claude_auth.py の写し。プラグインが別の claude を `claude -p` で起動するときに、その claude に認証を足す部品）に、関数を 2 つ足した。足したのは、トークンが切れたときに、起動した claude が黙って失敗し、起動した側がそれを「済んだ」と数えるのを防ぐため。この版では呼ぶ所が無く、利用者から見た動きは変わらない。呼ぶ所は、claude を起動する処理を持つプラグインの担当が後の版で足す。
  - `expiry_note(項目の名前)`: 利用者が Keychain（macOS の資格情報の保管庫）に自分で入れたトークンが、入れた日から 335 日を過ぎていれば、作り直しを促す 1 行を返す。過ぎていなければ None。このトークンは `claude setup-token`（CI などで使う長持ちのトークンを作る Claude Code のコマンド）で作る物で、寿命は 1 年。
  - `auth_failed(出力)`: 起動した claude の標準出力が認証の失敗の形なら真を返す。真になるのは 2 つ: 300 バイト以下の 1 行で JSON として読めない文と、JSON の結果のうち `is_error`（失敗の印）が真で `result`（返答の文）に authenticate か /login を含む物。複数行の文・300 バイトを超える文・失敗でない JSON は偽。認証の切れた claude は、この形の文を出して終了の値 0 で終わり、終了の値では見分けられないため。
