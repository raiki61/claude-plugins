# 変更の記録（attention）

attention の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版の出し方（この記録を書き足す段。git の tag は作らない）は、リポジトリのルートの `docs/releasing.md` に在る（プラグインとして入れた実体には無いので、clone か GitHub で見る: https://github.com/raiki61/claude-plugins/blob/main/docs/releasing.md）。

## [0.34.0] - 2026-10-19

### Changed

- `/catchup`（1 件の PR などに戻り、どこで止まっていたか・次に何をするかを出す）・`/whose-turn`（open な PR・issue の全件で、誰の番かを棚卸しする）・`/what-am-i-doing`（いま居るセッションの経緯を出す）の命令書（AI が実行時に読む指示のファイル）を、`commands/<名前>.md` から `skills/<名前>/SKILL.md` に移し、本文を 5,000 字以下に縮めた（4,990 字・4,130 字・4,732 字。移す前は 18,615 字・7,532 字・6,230 字）。詳しい手順は主題ごとの別ファイル（`skills/<名前>/references/`）に分け、本文が「いつ読むか」を添えて指す。打つ呼び名（`/attention:catchup` など。補完で `/catchup` と打っても同じ）と振る舞いは変わらない。長い会話で Claude Code が自動で文脈を縮める（圧縮する）と、各スキルの頭の 5,000 トークンしか付け直さない（https://code.claude.com/docs/en/skills 。日本語の 5,000 字はおよそ 4,400 トークンで、その内に収まる）ので、移す前は本文の後ろの手順を失ったまま動くことがあった。リポジトリのスキルの書き方の標準（`docs/standards/skill-authoring.md`）に合わせた直し。
- `/catchup` が場面でだけ読む別ファイル（`docs/catchup-ref.md`・`docs/catchup-figures.md`）も `skills/catchup/references/` に移し、主題ごとに分けた（対象の読み方・欄の書き方・一覧・PR でないとき・準備・図）。

## [0.30.0] - 2026-10-16

### Added

- `/catchup` のページの「この PR がすること」を、初めて見るエンジニア向けに組み直した。ひとこと（`lead`）・語の一覧（`terms`。文の中の同じ語に点線を引き、乗せると意味が出る）・4〜6 段落の説明（`explain`）・図（`figure`）・変えたこと（`points`。1 点ずつ題・前・後とコード）を AI が書き、機械が描く。
- 変えたことを図の凡例として並べる。項に乗せると図の箱と線が光り、箱や線を押すと、その横に前と後の札が出る（ページは動かない）。コードは札や項のボタンを押したときだけ、画面の 9 割の窓で開く（Esc で閉じる）。
- 図の線（データの流れ）も、変えたことの番号（`points`）とコード（`code`）を持てる。線のコードは、流れるデータの形を決めている所（受け先の API の型、キューのメッセージ、Secret のキー、通信を許す規則）を指す。
- コードは、この PR で変えていないファイルも `find` で指せる。`--render` が PR の先頭の版（手元に同じ commit があれば `git show`、無ければ GitHub）から読み、指した行の塊を「この PR では変えていない」と断って出す。材料に PR の先頭の commit（`head.oid`）を書くようにした。
- 窓が 1200px 以上なら、左に節の目次（いま読んでいる節が光る）を置き、説明の右に語の一覧を並べる。

### Changed

- いまの番の節を、一言（60 字まで）・状態の札・「前回から」と「止めているもの」の 2 列（1 項 60 字までの事実を 4 つまで）・次の一手（上の 3 つを出し、残りは畳む）の形にした。
- 図は、向き（横・縦）と前と後の 2 枚の並べ方（上下・左右）を機械が全部組んでみて、字が等倍以上で窓に収まる形のうち一番低いものを選ぶ。窓が 1400px 以上なら、凡例を図の右に置く。ページの幅は 1600px まで広げ、読む文の 1 行は 46 字前後にそろえる。
- 図の自動の再生は、図を押すと止まる（乗せただけでは止めない）。
- 命令の本文から、仕様の一覧と図の書き方を `docs/catchup-ref.md` と `docs/catchup-figures.md` に分け、要るときだけ読ませる。
- 欄の検査を足した: 増える・消える・変わる箱と線には変えたことの番号が要る（差分の外の物は `[]`）、線の字は 18 字まで、変えたことの題は 30 字・前と後は 80 字まで、説明は 6 段落まで、語は 16 個まで。

## [0.29.0] - 2026-10-16

### Added

- `/reflect [期間]`（today・yesterday・week（既定）・month・YYYY-MM-DD・YYYY-MM-DD..YYYY-MM-DD）。その期間の会話・裏で起こされた会話（`claude -p` やフックが起こしたもの）・commit・GitHub の動き・`/insights` の控え・入っているプラグインと指示ファイル・提案の台帳を機械（`scripts/reflect.py`）が集め、AI が改善の提案（回数 × 手間の大きい順。自動にする前に、やめられないかを先に見る）と、仕事の仕方についての気づきとヒントを書き、機械が 1 枚の HTML（`~/.cache/attention/reflect/<始まり>_<終わり>.html`）に描く。仕様は `docs/reflect-spec.md`。
- 読む設定のフォルダを足す `ATTENTION_REFLECT_CONFIG_DIRS` と、日記の置き場 `ATTENTION_REFLECT_DIARY_DIR`。日記の置き場を決めていれば、1 日の期間のとき、その日の日記の末尾の節（`<!-- reflect:start -->` から `<!-- reflect:end -->`）だけを書き直す。
- 提案の台帳（`${XDG_STATE_HOME:-~/.local/state}/attention/reflect-ledger.json`）と `reflect.py --decide <id> <adopted|dismissed|held|open>`。却下した提案は次から機械が落とす。壊れた台帳は上書きせずに止まる。
- 非公開のリポジトリの PR・issue の番号とリポジトリ名を、AI の文に書かせない。`--render` が見つけたら終了コード 2 で止める（何の作業か・量・言いたいことで書く）。
- `/my-turn` の手順 0。掘る前に、PR の今の状態（merge 済みか・head・CI）、この PR の会話とレビューと行のコメントの全部（自分の前の指摘の一覧）、名指しされた PR・issue・ADR を取り直す。

### Changed

- VS Code でページを拡張のプレビューで開く関連付けを、`/catchup` と `/reflect` の両方に効く `**/.cache/attention/**/*.html` に広げた。前の版で準備した人は `/catchup setup` を打ち直すと足される。

- `/catchup` のページを読みやすくした。指摘のスレッドの発言を、GitHub と同じく Markdown として描く（太字・コードの囲み・箇条・リンク。生の HTML は描かずに文字にし、リンクは http(s)・mailto・ページ内・相対だけ、画像は読み込まない）。部品は marked 15.0.12（MIT）を雛形に埋め込んだ。
- 「前回から」の番の受け渡しを、横の帯の図から、GitHub の PR の会話の流れと同じ縦の並び（印・誰が・何を・いつ、最後に「いま」）にした。帯の図は字が小さく、点の名前が重なっていた。
- 状態（CI の本数・承認・取り込み・未解決の件数）は「いまの番」の止めているものの行にだけ出し、AI の文（`headline`・`turn`）では繰り返さないようにした。`headline` は 1 文で太字にしない。文の段落は 3 文までにし、説明の横幅を枠に揃えた。

## [0.28.0] - 2026-10-15

### Added

- `catchup.py --render <描く材料> <欄>`（どちらも JSON の file の path）。`--out` が書く描く材料と、AI が書く小さな欄の JSON（headline・where・turn・next・unseen・explain・figure）を雛形 `templates/catchup.html` に流し込み、`~/.cache/attention/catchup/<owner>-<repo>/<番号>.html` を書く（同じ件は上書き）。同じ置き場の `index.html` に、ページごとに 1 行（件・件名・誰の番・次の一手・更新）を並べる。欄に直す所があれば、日本語で 1 件 1 行を出して終了コード 2 で止まる。

- `/catchup setup`（`catchup.py --setup`、確かめるだけなら `--setup --check`）。VS Code で見る準備をする: 拡張 Simple HTML Viewer を入れ、Remote の Machine の設定に 2 つ（catchup のページをこの拡張で開く関連付けと、描き直したら表示も変わる自動の再読み込み）を足し（他の設定は消さず、書く前に控えを置く）、見本のページを描いて開く。

### Changed

- `/catchup` の返事を、端末の長い散文から 1 枚の HTML のページにした。端末に返るのはページの path と 1 行の要約だけ。差分・指摘・CI のログ・番の受け渡しの図は機械が描き、AI は欄だけを書く。前提（VS Code の Remote-SSH・Simple HTML Viewer・設定 2 つ）と見え方の落ち方は README の「前提（HTML で見る）」に在る。
- `/catchup` の図を、罫線の絵（60 桁・14 行）から、変更前と変更後の箱と矢印の鎖にした。`figure-check.py` は `/what-am-i-doing` の絵にだけ使う。
- `/catchup` の欄の文体を常体の短文にした（旧の返事は です・ます）。
- `/catchup` の命令書の `allowed-tools` に Write を足した（欄の JSON を一時の階層に書く）。
