# 変更の記録（attention）

attention の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版の出し方（この記録を書き足す段。git の tag は作らない）は、リポジトリのルートの `docs/releasing.md` に在る（プラグインとして入れた実体には無いので、clone か GitHub で見る: https://github.com/raiki61/claude-plugins/blob/main/docs/releasing.md）。

## [0.49.0] - 2026-10-27

### Changed

- `/my-turn` は、報告を見せる前に、確かめるために作った・入れた・変えた物を片付ける（`commands/my-turn.md` の手順 19）。一時の置き場・写し・ファイルは消し、PR のブランチの作業ツリーは始めたときの状態に戻す（`git status` が始めと同じ・stash を残さない・ブランチを変えない）。確かめるために入れたツールの版は、作業ツリーの設定（`mise.toml` など）を書き換えたなら戻す。手元に入っただけの物は残し、何を入れたかを報告の「確かめた前提」に書く。裏で起動したサーバや定期の仕事は止め、片付けられなかった物はその場所と訳を報告に書く。今までは、確かめに使った chart の写しを一時の置き場に残したまま終わることがあった。
- `/my-turn` は、前の回の報告が渡されていれば、GitHub に出した指摘だけでなく、その報告の発見（指摘・下書き・前提を消す案・相乗り〔1 つの直しで一緒に片づく別の問題や、同じ物を作る予定の別の issue・PR〕・未確認として残した物）も 1 件ずつ読み、今どうなったか（片づいた・取り下げた・残っている・未確認のまま）を報告に書く（`commands/my-turn.md` の手順 4）。残っている物は、PR を掘る問い（前提から末端まで、問いを細かく分けて確かめる手順 11 の問い）の 1 つにするか、持ち主に上げる議題にし、黙って落とさない。前の回に実物で確かめた答えは、確かめた物（PR の head・触ったファイル・ツールの版）が今も同じなら同じ実験をやり直さずに使い、報告の「確かめた前提」にそう書く。今までは、前の回の報告にしか無い発見が次の回で調べられずに落ちることがあった。
- `/my-turn` は、一般の構造から外れてよい理由を、外の基準（書かれた意図・一般の構造・業界の定石）と、PR の外の動かせない事実（外のツールの仕様・法や契約など、原典で示せる物）だけに限る（`commands/my-turn.md` の守ること）。リポジトリの今の状態（設定・CI・コード・置き方・慣習・既に在る検査や物）は、言い方を変えても理由にせず、それしか理由が無ければ寄せる。見せる前に、外れてよいとした違いの 1 件ずつ、理由が今の状態でないかを確かめる。今までは「今そうなっているから」を禁じていても、「今の CI の設定では検査が起動しない」のような言い換えで外れてよいとしてしまうことがあった。
- `/my-turn` は、問いの末端をまずコード・設定・原典を読んで決める（`commands/my-turn.md` の手順 11）。実際に動かす（描く・試験を回す・写しで試す・ツールを入れる）のは、読むだけでは答えが 1 つに決まらず、その答えで推奨や下書きが変わるときに限る。動かさずに決めた末端は何を読んで決めたかを書き、読むだけで決まらず推奨にも効かない物は「未確認」と書いて止める。「消える」「要らなくなる」「穴が塞がる」を末端まで確かめてから書く決まりは変えない。
- `/my-turn` は、下書きの本文（GitHub に出す文）に報告用の番号（`[1]` など）を書かない（`commands/my-turn.md` の手順 17・18・20）。番号は持ち主への報告から指すために見出しの行にだけ付け、本文はそのまま貼れる形にする。1 つの指摘が何か所にも効くとき、2 件目からの本文は最初の件を番号でなく `ファイル:行` か中身の短い言い方で指す。作者の側の返信の下書きも同じ。見せる前に、本文に番号が残っていないかを確かめる。0.47.0 からは、GitHub に出たインラインコメントの頭に `**[1]**` などが付き、本文どうしが番号で指し合って、作者には指す先が分からなかった。
- `/my-turn` の手順 15（自作をゼロベースで疑う段）に、0.42.1 に在った 1 文「OSS があるかもしれないし、世界がやっていない自作には何かしらの理由があるはずである。」を戻した。0.47.0 で組み直したときに落ちていた。手順のほかの文は変えない。

- 変更要求（CHANGES_REQUESTED）を出したレビュアーに直して依頼し直した PR で、`/whose-turn` と `/catchup` が作者（持ち主）の「指摘対応」を出し続けていたのを直した（#1843）。変更要求を出した人の全員（人ごとの最新の意見で見る。後で承認に変えた人は数えない）に、人として依頼が出ていれば、ターンはレビュアーにある。1 人でも依頼が出ていない人がいれば今どおり指摘対応。Team 宛の依頼はその所属の人への依頼に数えない。人ごとの意見は新しい 30 件まで取り、切れていれば今どおり指摘対応を出して「見ていないもの」に書く。
  - `/whose-turn`: レビューを依頼されている人の「最後に発言したのが自分か」（相手の番に下げる判定と、「X は（日時） 以降 発言なし」の行）は、依頼より後の発言だけで見る。依頼の後に本人が解決済みのスレッドに書いた発言（「確認しました」など）も数えない。今までは、変更要求の本文や依頼前の返事が最後の発言に数えられ、再依頼された人の行が相手の番に下がって、誰の「自分の番」にも出なかった。
  - `/whose-turn`: 持ち主が自分で立てた問いのスレッドで、最後の発言者の判定から外すのを持ち主本人の発言だけにした。今まではスレッドごと外していて、相手がそこに書いた答えまで消え、持ち主のマージなどの行が相手の番に下がっていた。
- `/whose-turn`: 作者も assignee に入っている未依頼の PR を、作者が渡した扱いにして「相手の番」に置いていたのを直した。作者が持っていて、まだ誰にも渡していない（「自分の番」の「まだ誰にも渡していない」）。assignee の種別が取れない GitHub で作者が自分を入れずに assignee を付けた未依頼の PR は、誰も発言していなくても作者の「相手の番」に置く（`/catchup` の「担当 X 待ち」と同じ読み）。
- `/catchup`: PR の持ち主を `/whose-turn` と同じ規則（共用の部品 `scripts/lib/turn.py`）で決めるようにした。今までは作者を持ち主と決め打ちしていて、作者が自分を入れずに人を assignee に付けた PR でも、CI 赤・衝突・要修正・マージ・下書きを作者のターンと出していた。
  - 担当として受けた PR では、これらは担当（私）のターンで、「CI 赤は担当（私）しか外せない」「衝突の解消は担当（私）」のように出す。依頼も他人のレビューも無ければ「レビュー依頼が誰にも出ていない（依頼先を決めるのは私）」と依頼先の候補も受けた私に出し、渡した作者には「担当 X 待ち」と出す。
  - 渡す前に人へ依頼したか、作者以外の人（担当も含む）のレビューが付いていれば、依頼先を決めるターンは今どおり作者に残り、受けた担当には「私が担当（assignee）」と出す。
  - 人に数えるのは返答できるアカウント（User）だけで、Copilot などの Bot や Mannequin だけが assignee なら作者が持つ（今までは Bot の assignee にも「担当 X 待ち」と出していた）。assignee の種別を取るため、問い合わせを `assignedActors` に替えた。返さない GitHub（GitHub Enterprise Server など）では種別なしで取り直して作者が持つ形で出し、「見ていないもの」にそう書く。
