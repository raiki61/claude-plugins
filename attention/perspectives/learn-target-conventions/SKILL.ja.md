# 対象固有の規約を、その一次情報から掴む

**芯の決まり: 対象の規約を審査の決まりに書き写さない。書いた途端に正本の写しになり、リポジトリが変わっても古いまま残る。観点を当てる前に、対象の一次情報から掴む。**

## 落とし穴（先に読む）

- **黙りは「無い」と読まれる。** 掴めなかった項目は「特定できなかった（探した先: …）」とはっきり書き、推し量りで埋めた項目は推し量りと書く。
- **差分の近くのコードが実際に使っている物が標準**であって、文書に書かれた理想ではない。両方が食い違うなら、それ自体が指摘。
- **規約を破れば lint・整形・型の検査が落ちる（赤くなる）所は、その検査が今通っている（緑である）事を確かめるだけにする。** その規約を人や言語モデルの手でもう一度確かめない。見つかる物は増えない。
- **持ち越した事実は参照に留める。** この種の申し送りの壊れ方は、持ち越した途端に確定した事実の顔をする事。
  - 縛りとして凍らせない。「前の審査でそう読んだ」は訳にならない。設定・パッケージの宣言・CI の定義が変わったら読み直す。
  - 白紙から疑う役には渡さない。文脈を断った採点役や、目的から理想の解を独立に導く役に掴んだ物を渡すと隔てが壊れ、「このリポジトリの流儀」を所与にした判断に落ちる。疑う役の入力に、前の審査で得た事実を混ぜない。

## 手順

### 読む先（在る物だけ使い、無い物は「無い」と扱う）

- **README・貢献の手引き・文書**: アーキテクチャの境・依存の方針・開発の流れ。
- **lint・整形・型の検査の設定**: 機械で守らせている規約。
- **パッケージの宣言**: 言語・フレームワーク・試験の既定（書かなくてよい約束が何か）。
- **CI の定義**: 何が関門にされているか。
- **差分の近くのコード**: 標準の仕組み（国際化・設定の読み込み・エラーの分類・依存の注入・ログ）の実体。

### 掴んだ物を持ち越す

掴んだ事実は後の審査へ持ち越してよい（審査のたびに読み直す要は無い。一次情報のファイルが変わっていない時は、前の掴みを持ち越す）。

## 済んだと言える時

- 上の読む先を全部読んだか、「無い」と書いた。
- 特定できなかった物には探した先を書き、推し量った物は推し量りと書いた。
- 掴んだ事実を、白紙から疑う役に渡していない。

## 返し方

読む先ごとに: そこから掴んだ事か、「特定できなかった（探した先: …）」。推し量った物は推し量りと書く。文書と、差分の近くのコードが実際に使う物との食い違いは、指摘として名指す。

## 例

入力: 知らないリポジトリの審査を始める。README と lint の設定が在り、CI の定義は無い。

返し: README: 処理の層は保存の層を直に import しない。lint の設定: import の順を守らせているので、緑を確かめるだけにする。CI の定義: 特定できなかった（探した先: リポジトリの根と、その隠しフォルダ）。差分の近くのコード: エラーは共通の助けで分けている。README は別の物を名指す——指摘。

## 一緒に使うと良いもの

- 対象の規約を掴んだ後に、変更の実装と設計を審査する見方。
