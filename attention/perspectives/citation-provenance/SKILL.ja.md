# 変更が引く根拠の出どころを確かめる

**芯の決まり: 変更が自分で足した根拠は根拠ではない。「正本・慣習・合意は X」の形の主張ごとに、X が変更の前から在ったかを確かめる。**

## 落とし穴（先に読む）

- **主張は 3 つの所で探す**: 差分の本文・PR の説明・docstring。
- **今の版でなく、変更の前の版と照らす。** たとえば根の版の履歴から、X を決める字列を探す。
- **循環は証拠で、判定ではない。** 差分が自分で足す物を根拠に引いていたら、証を書く: 差分の中で X を足す所と、打ったコマンドの結果。
- **外との合意**（ほかのチーム・ほかのシステム・上流の出どころ）で、変更の前に跡が無い物は、事実でなく確かめていない前提。
- **本物の作業ツリーを壊さない。** 写しは外の新しい一時のフォルダに作る。

## 手順

1. 差分の本文・PR の説明・docstring から、「正本・慣習・合意は X」の形の主張を全部抜き出す。
2. 主張ごとに、X が変更の前の版に在ったかを確かめる。
3. 循環ごとに、証を書く: 差分の中で X を足す所と、打ったコマンドの結果。
4. 変更の前に跡が無い外との合意の主張は、確かめていない前提と印を付ける。

## 済んだと言える時

- 3 つの所の主張のどれにも、X が変更の前から在ったかと、どう確かめたかの行が在る。
- 循環のどれにも証が付いている。
- 確かめられなかったなら、何も見つからなかったと返さず、そう訳と一緒に書いてある。

## 返し方

抜き出した主張ごとに 1 行: 主張の文・X が変更の前から在ったか（はい・いいえ）・どう確かめ何が見つかったか。循環が見つかったかと、その数を書く。何も見つからなかったなら、何を見たかを書く。確かめられなかったなら、そう書き、訳を書く。

ファイルの中の場所を名指す時は、差分の中の行でなく、今のファイルの行の番号を書く。差分の行はファイルの行ではなく、人がその場所を開けない。書く前にファイルを開いて行を確かめる。確かめられなければ、行の番号の代わりに、パスと関数の名などを書く。

## 例

入力: PR の説明に「設定のキーは小文字にするのが慣習（書き方の手引きを参照）」と在る。同じ差分が、その 1 行を書き方の手引きに足している。

返し: 主張「設定のキーは小文字にするのが慣習」——変更の前から在ったか: いいえ。根の版の履歴から書き方の手引きの「小文字」を探した: 当たり無し。その行は、この差分が書き方の手引きに足した所で初めて出る。循環: 1 つ。

## 一緒に使うと良いもの

- 外のサービスへの問い合わせ（Web の検索・取りに行く URL）に、見ているリポジトリ自身の名や字を入れない決まり。
