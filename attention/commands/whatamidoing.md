## 到達点

**読む人は過去のやり取りを遡らない。** この 1 つの返答だけで、その場に居た人と
**同じ所まで追いつける**必要がある。要約ではなく、追いつくための説明を書く。

判定は両向きに 1 つ——**読んだ人が、次の一手を自分で実行できるか。** 出来ないなら
足りない情報がある。逆に、**消しても次の一手が変わらない要素は、落とす。** 節・絵・
抜き書きは全部この秤にかけ、入れる量はセッションごとに変わってよい。長さの上限は
無いが、長さは目的ではない——「これが無いと、読んだ人はどこで止まるか」に答えられない
要素を足すな。

## やること

1. `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/whatamidoing.py` を実行する。往復が多くて省かれたら
   `--full` で取り直せ。出るのは**依頼と、それに対して何をしたかの対**、区切りになった操作
   （コミット・push・テスト実行）、道具の使用、このセッションの間に入ったコミット、
   未コミットの残り。**あなたが読むための材料で、そのまま貼るものではない。**

2. **会話が手元に残っていれば、そちらを主な材料にしろ。** スクリプトは、要約で前半が消えた
   ときに背骨を補うためのものだ。補って書いたなら、そう 1 行添えろ。

3. 次の形で書く。**長さの上限は無い。**

   - **冒頭に平易版 3 行**（何の作業か / どこまで進んだか / いま何で止まっているか）。
     専門語を使わず、急いでいる人がここだけで用を足せるようにする
   - **その下に、追いつくための説明。** 節はこの 5 つが目安で、無い節は落とす:
     - **何の件か** — 扱っている PR / issue の**中身**を、その件を知らない人に分かるように。
       番号と題名だけ書くな——何が問題で、何をしようとしているのか。**系のどこを触る話か**が
       言葉で遠いなら、部品の並びと触っている場所を絵にする——いまどういう状態で、
       変更が入ると何がどう変わるのか
     - **私の立場** — **実装者か、レビュワーか、どちらでもないか。** 戻ったとき真っ先に
       要るのがこれで、会話からは読み取りにくい（どちらの側でもレビューの話をするため）
     - **何をやってきたか** — 決まったことと、**選ばなかった案とその理由**。作ったものは
       位置と数まで（「テストを足した」ではなく「検査を 12 件足した（`tests/run.sh`）」）。
       **変更の中身が次の一手に効くなら、勘所を「変更前 → 変更後」の数行で抜き書きする**
       ——差分の全文ではない。コードでも文章でも同じで、動きが変わるなら入力と出力の
       変わり方まで
     - **残っている判断** — **いま何の判断で止まっているのか。** 選択肢が複数あるなら、
       それぞれの利害まで。「進行中」で済ませるな
     - **次の一手** — 読んだ人がそのまま実行できる具体度で

## 書き方

- **人称を固定しろ。**「私」＝このセッション。あなたの代理で動いているので、GitHub 上の
  立場（PR の作者・レビュー依頼の宛先）も「私」で書く。「あなた」を使うのは、読んだ人に
  判断や実行を求める文だけ。**同じ事実を「私」と「あなた」で言い換えるな**——
  「私がレビュワーに指名された」と書いたなら、図でも「→ 私」だ
- **初出の語を説明せずに使うな。** この会話の中で決めた呼び名（道具の名前・略号・「例の件」）は、
  そこで一度説明する
- **数と場所を省くな。** 追いつくとは、次に自分で触れる状態になることだ
- **却下した案を落とすな。** 何を選んだかだけでは、次の人が同じ案をもう一度持ち出す
- **削ってよいのは、読む人が要らない話だけ**——経緯の実況、自分の作業の narration、
  どのファイルを何回読んだか
- **言葉づかい**は、この作業を知らない同僚に説明するときのもの。断りなしの GitHub / CI の語・
  コンサル英語・直訳横文字を使うな。どうしても要る語は、初出で「中身 → 記号」の順に書く

### 図と表

関係が言葉より図で早いなら使え。**基準は 1 つ——言葉で書くより読む人が早く分かるか。**
飾りで足すな。効くのは、誰が誰を待っているかの関係・前と後の比較・どこまで進んで
どこで止まっているか・ファイルどうしの参照関係。

```
  依頼者 ──[レビュー依頼]──▶ 私 ──[block 1 件]──▶ 作者
                                            ▲
                              いまここ ─────┘  作者の直しを待っている
```

**表のセルに説明の文を入れるな。** 端末の表は列ごとに幅を割るので、セルの長文は
数文字ずつの細切れに折り返されて読めなくなる。セルに入れてよいのは数語まで——
「状態」「件数」「日付」のような短い値だ。文で説明したいことがあるなら、
表をやめて箇条書きか散文にする。

## 内部の事情は書くな

自分がどうやって思い出したかは、読む人の用ではない。

- **この命令書の語（「材料」「スクリプト」「道具」）を出力に持ち込むな**
- **スクリプトの立場判定は、いま居るブランチから引くので、本題と別の PR を拾うことがある。**
  会話と食い違ったら会話の側を信じて書き、**食い違ったこと自体は書くな**
- **題（`aiTitle`）は序盤で決まったまま更新されない。** 会話と食い違っていたらそちらを信じる。
  題は読む人にも見えているので、古い旨だけは書いてよい
- **スクリプトの出力は貼らない。** 往復の並びそのものを見せる用があるときだけ、
  `<details>` に畳んで末尾に添える
- スクリプトにも会話にも無いことを断定するな。推測なら推測と書け
