## 何を出すか

**求められているのは短さではなく、通じることだ。** 読む人は他のセッションから切り替えてきて、
このスレッドの文脈を持っていない。3 行に押し込めて分からない説明を出すくらいなら、
節を立てて説明しろ——ただし**冒頭の 3 行だけで用が足りる**形にする。

## やること

1. `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/whatamidoing.py` を実行する。

   **これはあなたが読むための材料で、そのまま貼るものではない。** 中身は依頼者の発言の並びで、
   問いであって状態ではない（「hi」「◯◯を教えて」）。貼っても読む人には何も分からず、
   本題の説明が下へ押し出される。

2. **会話が手元に残っていれば、それを主な材料にしろ。** あなたはこのスレッドで何をしたかを
   知っている。スクリプトは、要約で前半が消えたときに背骨を補うためのものだ。
   補って書いたなら、そう 1 行添えろ（何を根拠に書いたかが変わる）。

3. 次の形で書く。

   - **冒頭に平易版 3 行**（何の作業か / どこまで進んだか / いま何で止まっているか）。
     専門語を使わず、これだけで用が足りるようにする
   - **その下に説明**。節を立ててよい。目安はこの 4 つで、無い節は落とす:
     **何の作業か** ／ **これまでに決まったこと・作ったもの** ／
     **いま止まっている理由** ／ **次の一手**
   - 長さの上限は無い。**ただし読む人が要らない話は書くな**——経緯の実況、
     自分の作業の narration、どのファイルを何回読んだか

4. スクリプトの出力は貼らない。依頼の並びそのものを見せる用があるときだけ、
   `<details>` に畳んで末尾に添える。

## 言葉づかい

この作業を知らない同僚に口で説明するときの言葉で書く。

- **使うな**: この会話の中でしか通じない略号、断りなしの GitHub / CI の語、コンサル英語
- **使ってよい**: 製品名・標準仕様名、IT で定着した英語（API・CI 等）
- **どうしても要る語**は、初出で「中身 → 記号」の順に書く

書けたら自分に問え——**冒頭 3 行だけを見た人が、何の話で・どこまで進んでいて・次に何をするかを
言えるか。** 言えないなら、まだ自分にしか通じない書き方をしている。

## 守ること

- **題（`aiTitle`）は序盤で決まったまま更新されない。** 依頼の並びや会話と食い違っていたら、
  題ではなくそちらを信じ、題が古い旨を書け
- **止まっている理由と次の一手は、はっきり書け。** 「進行中」で済ませるな。
  何を待っているのか、誰が動けば進むのかまで書く
- 材料にも会話にも無いことを断定するな。推測なら推測と書け
