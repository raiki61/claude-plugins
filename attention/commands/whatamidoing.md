## 到達点

**読む人は過去のやり取りを遡らない。** だから、この 1 つの返答だけで、その場に居た人と
**同じ所まで追いつける**必要がある。要約ではなく、追いつくための説明を書く。

出来たかどうかの判定はこれ——**読んだ人が、次の一手を自分で実行できるか。** 出来ないなら、
まだ足りない情報がある。

## やること

1. `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/whatamidoing.py` を実行する。往復が多くて省かれたら
   `--full` で取り直せ。

   出るのは**依頼と、それに対して何をしたかの対**、区切りになった操作（コミット・push・
   テスト実行）、道具の使用、このセッションの間に入ったコミット、未コミットの残り。
   **これはあなたが読むための材料で、そのまま貼るものではない。**

2. **会話が手元に残っていれば、それを主な材料にしろ。** スクリプトは、要約で前半が消えた
   ときに背骨を補うためのものだ。補って書いたなら、そう 1 行添えろ。

3. 次の形で書く。**長さの上限は無い。**

   - **冒頭に平易版 3 行**（何の作業か / どこまで進んだか / いま何で止まっているか）。
     専門語を使わず、急いでいる人がここだけで用を足せるようにする
   - **その下に、追いつくための説明。** 節を立ててよい。目安はこの 5 つで、無い節は落とす:

     | 節 | 書くこと |
     |---|---|
     | **何の件か** | 扱っている PR / issue の**中身**を、その件を知らない人に分かるように。番号と題名だけ書くな——何が問題で、何をしようとしているのか |
     | **私の立場** | **実装者か、レビュワーか、どちらでもないか。** 材料の「私の立場」をそのまま使う。戻ったとき真っ先に要るのがこれで、会話からは読み取りにくい（どちらの側でもレビューの話をするため） |
     | **何をやってきたか** | 決まったことと、**選ばなかった案とその理由**。作ったものは位置と数まで（「テストを足した」ではなく「検査を 12 件足した（`tests/run.sh`）」） |
     | **残っている判断** | **いま何の判断で止まっているのか。** 選択肢が複数あるなら、それぞれの利害まで書く。「進行中」で済ませるな |
     | **次の一手** | 読んだ人がそのまま実行できる具体度で |

## 図を使ってよい

関係が言葉より図で早いなら、表・箇条書き・ASCII 図を使え。**基準は 1 つ——言葉で書くより
読む人が早く分かるか。** 飾りで足すな。

効くのはたとえばこういう所だ。

- **誰が誰を待っているか**の関係（矢印で書くと 1 行で済む）
- **前と後の比較**（変更前 / 変更後を並べる）
- **状態の移り変わり**（どこまで進んで、どこで止まっているか）
- **場所の関係**（どのファイルがどれを参照しているか）

```
  依頼者 ──[レビュー依頼]──▶ 私 ──[block 1 件]──▶ 作者
                                            ▲
                              いまここ ─────┘  作者の直しを待っている
```

## 追いつけるかどうかを分けるもの

- **初出の語を説明せずに使うな。** 読む人はログを遡らないので、この会話の中で決めた呼び名
  （道具の名前・略号・「例の件」）は、そこで一度説明する
- **数と場所を省くな。** 「テストを足した」ではなく「検査を 12 件足した（`tests/run.sh`）」。
  追いつくとは、次に自分で触れる状態になることだ
- **却下した案を落とすな。** 何を選んだかだけでは、次の人が同じ案をもう一度持ち出す
- **削ってよいのは、読む人が要らない話だけ**——経緯の実況、自分の作業の narration、
  どのファイルを何回読んだか

## 言葉づかい

この作業を知らない同僚に説明するときの言葉で書く。

- **使うな**: 断りなしの GitHub / CI の語、コンサル英語・直訳横文字
- **使ってよい**: 製品名・標準仕様名、IT で定着した英語（API・CI 等）
- **どうしても要る語**は、初出で「中身 → 記号」の順に書く

## 守ること

- **題（`aiTitle`）は序盤で決まったまま更新されない。** 記録や会話と食い違っていたら、
  題ではなくそちらを信じ、題が古い旨を書け
- 材料にも会話にも無いことを断定するな。推測なら推測と書け
- スクリプトの出力は貼らない。往復の並びそのものを見せる用があるときだけ、
  `<details>` に畳んで末尾に添える
