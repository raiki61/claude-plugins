description: 持ち主（このプラグインを使う人）のターンの PR を進める。/catchup でその PR に戻った後に打つ。指摘やレビューの観点を木のように掘り、世の中の解と突き合わせ、既存の OSS で足りるのに自作していないかをゼロベースで疑う。持ち主がレビュアーなら、最後に出す指摘をインラインコメントの下書きにして見せて止まる（投稿はしない）。works-dispatch プラグインが、/catchup に続けて会話の 2 ターン目に送る。
---

持ち主は、このプラグインを使う人（この会話の相手）である。「自分の番」は持ち主が次に動くターンを指す。

対象は、この会話で `/catchup` した PR である。会話にその返答が無ければ、先に `/catchup <PR 番号>` を打てと返して止まれ。

立場は、`/catchup` がページに書いた `headline`（いまのターンの太字。この会話で書いたフィールドの JSON に在る）が言ったもの（持ち主がその PR の作者か、レビュアーか）を使う。

0. 掘る前に、前提を取り直す（修正の工場 works-factory の判定役が、判断の前に集める材料と同じ考え方）。
   - PR の今の状態を `gh pr view <番号> --json state,mergedAt,headRefOid,statusCheckRollup` で取り直す。merge 済み・閉じている・head が手元と違うなら、先にそれを持ち主に言って止まる。
   - この PR の会話とレビュー（`gh pr view <番号> --json comments,reviews`）と行のコメント（`gh api --paginate repos/<owner>/<repo>/pulls/<番号>/comments`）を全部読み、自分が前に出した指摘・決着した指摘・許した指摘を一覧にする。同じ指摘を重ねて出さず、前の自分の言ったことと食い違うことを書かない。
   - 本文・コメント・触っているコードが名指す PR・issue・設計の判断の記録（ADR）を読み、後から設計を変えた PR や閉じた issue で前提が古くなっていないかを確かめる。読めなかったものは「無い」と書かずに「未確認」と書く。
1. 木を探索するように深掘りする。起点は指摘やレビューの観点で、掘って出てきた問いを子の問いに分け、子の問いごとに末端まで掘る。作者の側なら、受けた指摘を 1 件ずつ起点にして掘る。最後に、掘った問いどうしの相乗り（一つの直しで複数が片づく・一つの直しが別の問いの答えを壊す）を見て、戦略的に確かめる（どの直しをどう組めばよいかを考え、その相乗りが本当に成り立つかを確かめる）。
2. 世の中が同じ問題をどう解いているかを当たる。当てる先は 3 つ。PR が作る部品、見つけた指摘 1 件ずつ、こちらが出す直し方の案。指摘ごとに「世の中の解」と「こちらの案と同じか・違うならどちらを採るか」を返答に書く。見つからなければ、探した場所を書いて「見つからない」と書く。それでもわからなければ、持ち主に聞く。
3. 汚い自作の領域（既存の OSS や世の中の定番で足りるのに、手で作っている部分）に踏み込んでいないかを疑う。OSS があるかもしれないし、世界がやっていない自作には何かしらの理由があるはずである。今まで進んできた前提は気にせず、ゼロベースで疑う。
4. 持ち主がレビュアーなら、最後に、出す指摘をインラインコメントで出す想定の下書きにして見せ、そこで止まる。GitHub へは投稿しない。別の issue にするかは作者が決めることなので、こちらからは提案しない。作者の側なら、この項目は飛ばす。

全体を通して、確かめていない領域を残さない。
