allowed-tools: Bash

## やること

1. `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/catchup.py <番号または URL>` を実行する。番号だけならカレントのリポジトリを見る。全文が要ると言われたときだけ `--full` を足す。

2. 出力を **1 つのコードブロックでそのまま貼る。1 行も削るな。** 読む人はこれを見て思い出す。要約で置き換えるな。

3. その下に **3 行**足す。それぞれ 1 行:
   - **これは何か** — この件を知らない人に通じる言い方。題名を言い換えただけのものを書くな
   - **なぜ要るか** — これが無いと何が困るか
   - **次の一手** — 「私の番」なら何をすればよいか。「待ち」なら誰の何を待っているか

4. **3 行は入口であって上限ではない。** 読む人がこの件を知らない、あるいは変更の中身の説明を
   求めているなら、3 行の下に節を立てて説明しろ。**分かることが目的で、短さは手段にすぎない**
   ——短く書いて通じないなら、手段が目的を潰している。削ってよいのは読む人が要らない話
   （経緯の実況・自分の作業の narration）だけで、理解に要る説明ではない。

## 3 行は専門語なしで書く

読む人は並行作業から戻ってきたところで、この件の文脈を持っていない。**3 行は、この PR を
知らない同僚に口で説明するときの言葉で書く。**

- **使うな**: GitHub と CI の語（reviewDecision・スレッド・gate・rollup・CHANGES_REQUESTED）、
  コンサル英語・直訳横文字、この件の中でしか通じない略号
- **使ってよい**: 製品名・標準仕様名（Helm・pgvector 等）、IT で定着した英語（API・CI 等）
- **どうしても要る語**は、初出で「中身 → 記号」の順に書く——「まだ承認されていない
  （REVIEW_REQUIRED）」であって、その逆にするな

書けたら自分に問え——**この 3 行だけを見た人が、何の話で・自分に関係あるか・急ぐかを
言えるか。** 言えないなら、まだ題名の言い換えになっている。

## 守ること

- **求められていないのに欠陥探しへ広げるな。** 説明は長くてよいが、それは読む人の理解のためで、レビューを始める合図ではない
- **出力に無いことを断定するな。** 本文や差分が要るなら `gh pr view` / `gh pr diff` を自分で叩き、叩いたことを書く。推測で埋めるな
- 出力の「見ていないもの」を削るな。読む人はそこで、この報告が答えていない範囲を確かめる
- open 全件の棚卸しはこの道具の仕事ではない。ここで一覧を作るな
