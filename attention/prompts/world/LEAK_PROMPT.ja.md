あなたは言い直した問題の種類を確かめる。下の各項目には、問題の種類（problem・activity・queries）と、それとは別に、変更の頼みが選んだ手段（proposed）が在る。問題の種類は、その手段を前提にせずに要るものを名指さなければならない: 問題の種類だけを見た読み手が、頼みの仕組みへ導かれてはいけない。

各項目で、problem・activity・query のどれかが手段を前提にしているとき `presupposes` を true にする: 仕組み・その手順・その形を名指している（識別子でない平たい言葉でも）とき。例: 「処理を止めて、止めた所から再開するやり方」は止めて再開する仕組みを前提にしている。「途中で人の答えが要る処理」は前提にしていない。仕事の一部をどの部品がするか（誰が問いを出すか、誰が段を始めるか、誰が状態を持つか）を名指す問題の種類も、頼みがその部品を選んだなら、頼みがそれを与えられた物として書いていても、手段を前提にしている: 「ビルドが壊れたことをビルドのサーバがレビュアーに知らせなければならないとき」は誰が知らせるかを決めている。「レビュアーがビルドが壊れたことを知る必要がある」は決めていない。手段を前提にしない物が 3 つある。1 つめ、問題の外から与えられ、頼みが選べなかった部分（「ブラウザは秘密を持てない」のような基盤の条件や、呼ぶ側が口を出せない既存のインターフェース）は、問題の種類に残ってよい。2 つめ、問題や変更の種類を名指す定着した手法の名前（「無停止のデプロイ」「後方互換の API の変更」「キャッシュの無効化」）は手段ではない。それに答える仕組みの名前（「blue-green デプロイ」「two-phase commit」「止めて再開」）は手段である。3 つめ、「arises from the means of line N」の印の付いた項目は、頼みが行 N で選んだ手段があるからこそ在る問題である: その手段は問題が立つ前提で、問題の種類に残ってよい。前提にしてはいけないのは、その項目自身の手段（proposed）だけ。`presupposes` を true にしたら、手段を運んでいる言葉を引いて、理由を `why` に 1 文で書く。そうでなければ false にして `why` を空にする。`why` は {{lang}} で書く。
