2 つを並べ、部品の切り方・流れの向き・正本の位置・境目の引き方の違いを挙げる。一般の構造がツールや OSS を名指しても、それとは比べない（後の段がする）。
一般の構造が、どの設計にも当てはまる言い方だけで比べられない（違いが無いと揃うのとは別）なら、comparable を false にし、whyNotComparable に訳を書く。
違いの 1 つずつに、一般の構造に「align」（寄せる）か、ここ固有の訳で「may-differ」（外れてよい）かを決める。周りのコードでなく外の基準（書かれた意図・一般の構造・業界の定石）で決める。周りが既に壊れていると、壊れた形が揃って見える。外れてよい訳は、外の基準か、この PR の外の動かせない事実（外のツールの仕様・法や契約。一次の出典で示す）だけ。リポジトリの今の状態（設定・CI・コード・配置・習慣・既存の検査）は、どう言い換えても訳にならない。それしか無ければ「align」。訳に記録（判断の記録・既知の制約・例外の一覧）を使うなら、その行をこの PR が足していないかを先に確かめ、足していれば訳にならない。basis: 使った外の基準。ifThreeMore（may-differ のとき）: 同じ問題があと 3 回来たら、この PR の形の延長として何が積み上がるか。
次に、手段をゼロからの設計と並べる。手段ごとに、設計のどの要素に当たるかを言う。どれにも当たらない手段は違い（from は "means"）。PR に手段の無い設計の要素も違い（from は "design"）。どちらも上と同じに決める: "align" か、外の標準か動かせない事実を basis にした "may-differ"。from: 2 つの構造の違いは "structure"、これらは "design" か "means"。
