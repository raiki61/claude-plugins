差分のファイルの全部と、その周りのコードを読む。

1. structure: PR が触る物を含むシステムを、このリポジトリの言葉を使わずに描く。部品・部品の間を流れる物（値・事実・呼び出し）・どの部品が正本でどれが読むだけか・依存の向き・境目。PR が触る部品がその中のどこかを示す。文書だけの PR では、文書が説明する仕組みと、文書の置き場（誰が読み、どこが正本か）のどちらを描くかを先に決める。この PR の解き方（作る仕組み・検査・名前の組み立て方）は書かない。ただし、この PR が足す検査・試験・CI の仕組みは、見張る物と一緒に部品として描く。
2. kind: どんな種類のシステムで、触る部品がそこで何を揃えたいかを 1 文で。決まった分類は無い。このリポジトリの語も、この PR の選択を名指す語も使わない（この文は PR を見てはいけない読み手に渡る）。
3. mechanisms: この PR が作る仕組みの 1 つずつを 1 文で、それが補う前提（それが無いと何が壊れるか: 人の手・よそで守る約束・外のツールの振る舞い）と一緒に。「X を作る。Y が Z を持たないので要る」の形。PR が足す検査と試験の仕組みも全部入れる。
4. selfMade（手順 15 の入口）: 自作の部品（世の中の標準で足りる所を手で作った物）。差分のファイルの --stat で足した行がどこに集まるかを見て、主目的でない所（検査・試験・つなぎ）に多ければ、それを先に挙げる。手で書いた一覧（数・型・特例の表）も自作に数える。ファイルはカンマで区切って挙げる。
5. extraSmells: 下の固定の 5 問では捕まらない、この PR のコードの臭いか危険の問いを {{extraSmells}} 問まで。1 問ずつ、5 問のどれも捕まえない訳を 1 行添える。空でよい。

6. hiddenChoices: この PR の構造が選択をしている所の問いを、選んだ答えを伏せて（例: 正本はどちらの側が持つか、境目はどこに引くか）。一般の構造が一般的すぎて比べられなかったときだけ問う。このリポジトリの語は使わない。
7. noParts: 部品を言えない（版の番号を上げるだけなど）なら true にし、noPartsReason を書く。そのとき structure・kind・mechanisms は空でよい。
