# /my-turn の掘る段: 実装で設計から変えた所

[設計書](my-turn-workflow-design.md)のセクション 13 から移した一覧。実装の中で、設計の文のままでは動かない・形が決まっていなかった所を、どう決めたかを書く。中身は移す前の文のまま（2026-11-18 に移した。字は変えていない）。

実装の中で、設計の文のままでは動かない・形が決まっていなかった所を、次のとおりに決めた。どれもセクション 12 の点を変えない。

- ヘッドレスの形の起動は、会話が `claude -p` の引数を毎回組むのでなく、台本 `scripts/my-turn-headless.py <args のファイル>` に持たせた（引数と環境変数をセクション 2 のとおりに組み、`roles` を足した args を `<記録のフォルダ>/<PR番号>-args-headless.json` に書き、出力を `<PR番号>-headless.json`、Workflow の返した値を `<PR番号>-materials.json` に書き、`modelUsage` の照合も出す）。引数の組み方を試験（`tests/my-turn-prep-case.py headless`）で毎回同じに見るため。`--max-budget-usd` の既定は 30（1 対の試しの費用で決め直す）。`--dry-run` で起動の引数だけを出す。
- 記録のフォルダは `git rev-parse --git-common-dir` の下の `attention/my-turn/`。PR の作業ツリーが worktree でも、同じ clone の回どうしで記録を共有する。
- ハッシュは、prep の中ではファイルごとに `then`（前の回の head の版）と `now`（今の head の版）の組で比べ、Workflow には短い印（`same`: 同じ中身・`moved`: 違う・`gone`: 今の head に無い・`absent`: どちらにも無い）で渡す。会話が prep の答えを `args` に写すので、ファイルごとに 40 字の sha を 2 つ写させない（写し違いが使い回しの判定を黙って変える）。記録のフォルダの中のファイルの扱いは、下の「使い回しの判定で」の項に書く。
- 既定の形では args を会話が Workflow のツールへ直に渡すので、前の回の記録を丸ごと渡すと会話の出力が膨らむ。prep が前の回の記録から使い回しに要る物だけ（PR の種類の 1 文・一般の構造・使い回せるノード）を抜いた `priorReuse` を出す。script は `prep` の中の `priorReuse` を読むので、会話は同じ物を `priorRecord` に写さない（`priorRecord` は在れば `priorReuse` より先に使う、試しの差し替え口）。抜く条件は script の使い回しの条件と同じ。前の回の head が手元に無いときは null。
- 出力スキーマに足したフィールド: W1 の `hiddenChoices`（W2 の伏せた問いの元。この PR が選んだ所を、答えを伏せた問いの文で）、W3 の `comparable` と `whyNotComparable`（一般論で比べる相手にならないかを W3 が言い、script が W2 に 1 回だけ問い直す）、W7 のクラスタごとの `question`（クラスタの問いの文）、W9 の `leaves`（案が乗るリーフ）と `searched`（PR の外を探した語）。W10 の `evidence` は「確かめられない」のとき空でよい。
- W11 は書いたファイルの中身を丸ごと返さず、`wrote`・`nodeCount`（読み直した記録のノードの数）・`head` を返し、script が組んだ記録と照合する。中身を丸ごと返させると、大きい PR で W11 のモデル（haiku）の出力の上限に当たるため。
- 記録のノードは入れ子にせず、1 段の項目で持つ（`resultStatus`・`answer`・`checked`・`evidence`・`parts`・`premises`・`children`・`verdict` など）。prep が前の回の記録の `nodes[*].checked.files` を読むので、その形に揃えた。
- prep の止まる理由に `git-failed`（git のコマンドが失敗した）を足した。prep は打たれた所が作業ツリーの下位のディレクトリでも、ルートに移ってから差分を取る（本文の pathspec が打った所に絞られ、`--stat` と食い違うのを防ぐ）。
- 記録の `general` に、一般の構造が無い訳 `why`（`notFound`: 問い直しても出なかった・`notComparable`: 一般的すぎて比べられなかった・`noAnswer`: ブラインドの判定役が返らなかった・`noParts`: 部品の言えない PR で問わなかった・`failed`: この段がまるごと回らなかった。出たときは null）を持たせた。問い直しても出なかったときは、1 回目の答えの文を記録と後の段の両方に残す。
- ヘッドレスの形では、記録が書けた回の出力を `{"recordPath", "recordWritten"}` の短い印にし、材料は台本が記録のファイルから組む（返り値の全体を `claude -p` の出力に写させると、大きい PR で出力の上限に当たる）。記録が書けなかった回だけ、返り値の全体を出力させる。
- 決まりの文書に、CLAUDE.md と同じ場所の AGENTS.md と、ルートの `.claude/` の下の CLAUDE.md・AGENTS.md を足した（セクション 6）。CLAUDE.md を持たず AGENTS.md に決まりを書くリポジトリが在り、ヘッドレスの形の役は `omitClaudeMd` で CLAUDE.md を入れないので、prep の一覧に載らない決まりはどの段にも届かない。Code Review の読む範囲（CLAUDE.md と REVIEW.md）を含み、それより広い。
- 差分が変わっていないかの `git patch-id` は `--verbatim`（空白も比べる。git 2.39 から）で取り、無い git では `--stable` に落とす。`--stable` は空白を無視するので、字下げだけの直し（Python では意味が変わる）を「変わっていない」にしていた。前の回に結果を返さなかったエージェントが 1 エージェントでも在る記録（`counts.stages` のどれかの段の `null` が空でない。段の全部が返らなかった `counts.allNull` も含む）は、patch-id が同じでも `unchanged` にしない。ノードの一部だけが落ちた回も、記録は欠けているため。W11 は記録を写すだけなので見ない（落ちた回は会話が `counts` ごと同じ中身を書く）。前の回の head が今の head と同じなら、2 本目の差分（空になる）は作らない。使い回したノードの反証は、前の回の判定が `stands` か `falls` のときだけ持ち越し、`unverifiable` はもう一度問う。会話は、前の回の後に来た指摘が在れば `unchanged` でも Workflow を回す（`commands/my-turn.md` の手順 6）。
- 使い回しの判定で、記録のフォルダの差分のファイル（`*.diff`）はファイルごとには数えず、差分を読んだノードは、前の回の差分の本文（前の回の base から head まで。lock file を除く）と今の本文の patch-id が同じとき（prep の `diffSame`）だけ使い回す（差分には、ノードが `checked.files` に挙げていないファイルの所も載っているため）。変えたファイルのハッシュで比べる形は、消したファイル・名前を変えたファイル（ハッシュが無い）で毎回掘り直し、変更を取り消したファイル（今の変えたファイルの一覧に無い）を見落としていた。差分のファイルの commit の件名の一覧と `--stat` の行（lock file も載る）も比べに入れ、件名を直した・lock file だけを直した回も使い回さない。patch-id は行の番号を数えないが、本文は前後 10 行を載せる（`-U10`）ので、base の側の直しが PR の所から 10 行より遠いときだけ、rebase の後でも使い回せる。差分だけを読んだノードと、`parts` に差分のファイルを挙げたノードも同じ条件にする。ほかの記録のフォルダのファイル（毎回書き直す thread・justifications）は同じとみなさない。前は記録のフォルダのファイルを全部「同じ」とみなし、thread だけを読んだノードを、新しいコメントの後も使い回していた。記録のフォルダの path は、リポジトリの相対の形（main の clone では `.git/attention/my-turn/…`）でも記録のフォルダに数える。git dir の中の path と、改行を含む path はハッシュに入れない。
- prep は、`gh pr view` の URL のリポジトリを指す remote を `git remote -v` の fetch の行で探し（push の URL だけが合う remote は選ばない）、その remote の base で範囲を取る（fork の作業ツリーでは `origin` が自分の fork を指すため）。見つからなければ `origin` で取り、`remoteMatched` を偽にして報告に出す。fetch は refspec（`+refs/heads/<base>:refs/remotes/<remote>/<base>`）を明示する。single-branch の clone や、狭い `remote.<名>.fetch` の設定でも `<remote>/<base>` を今の版にするため。差分の本文・`--stat`・patch-id の元の差分は、/what-am-i-doing と同じ `changemap.DIFF_SANE`（`--no-ext-diff --no-textconv --no-color` と、接頭辞を a/ b/ に決める 2 つ）で取り（lock file の除外は `:(exclude,literal)` で、名前を glob として読まない）、使う人の git の設定（外の diff のツール・textconv・色・接頭辞）で中身を変えない。前の回の記録が指す path のうち repo の外（`../` で始まる物）はハッシュに入れない（`git cat-file` が fatal で止まるため）。`--quotes` も、在り処が作業ツリーの絶対の path なら repo の相対に直して読む（Workflow の照合と同じ）。
- ヘッドレスの形の台本は、子の出力が認証の失敗の形（`claude_auth.auth_failed`。終了の値 0 の 1 行）なら、上限の額のせいにせず、認証か使用枠で止まった形だと出力の頭を添えて返す（出力の `authFailed` が真）。記録のフォルダも `--add-dir` で足す（worktree では作業ツリーの外の clone の `.git` の下に在り、W11 が書き、段が差分を読む）。`modelUsage` のモデルの照合は前方一致でなく含むかで見る（Bedrock・Vertex のモデルの名は `us.anthropic.claude-opus-…` などの形）。
- ヘッドレスの形の子の環境に、Bedrock・Vertex・Foundry の経路の付き物（名前が ANTHROPIC_VERTEX_ などで始まる物と、独自のヘッダーの変数）を残す。経路の旗だけ残して付き物を落とすと、子が認証かリクエストで落ちる。モデルの読み替えの変数（`ANTHROPIC_DEFAULT_OPUS_MODEL` など）は今までどおり落とす。
- ヘッドレスの形の材料の `counts` は、記録の `counts`（W11 の前に数えた物）に、W11 の分（記録が書けたので、返った 1 エージェント）を台本が足した物にする。子の会話に `counts` を写させると、入れ子の大きい物の写し違いが手順 20 の照合に入るため、写させない。Workflow の呼び出しが失敗した回は、子が `{"workflowError": <訳>}` を出し、台本がその訳を `message` に写す。
- ヘッドレスの形の起動に `--add-dir <script のフォルダ>` を足した。1 回目の試し（2026-11-17）で、子の会話の Workflow のツールが、作業ツリーの外に在る `scriptPath` を「ツールが返した path か、作業ツリーか足したフォルダの下の読めるファイルでない」と断り、Workflow が 1 段も回らなかった（セクション 2 の確かめていない点の 1 つ目）。
- ヘッドレスの形の台本は、子の会話の答えが Workflow の返り値（`stopped`・`version`・`recordWritten` のどれかを持つ JSON）でなければ `ok` を偽にし、`message` に訳を書く。1 回目の試しでは、Workflow が断られた訳を子の会話が文で返したのに `ok` が真のまま返っていた。
- ヘッドレスの形の段の役（W2 と W11 を除く）に WebFetch と WebSearch を持たせた。W6・W9・W10 が公式の一次の文書の URL を根拠にし確かめるのに要り、既定の形の段も持っている。
- ヘッドレスの形の W2 の役は、convergence-loops の `agents/blind-judge.md` の本文を英訳した物で、ツールを全部外す（`tools` を空にし、`disallowedTools` に全部のツールを挙げる）。
- W11 には、共通の決まりの「読むだけ」の行を、記録のファイルだけを書く行に替えて渡す。前は全部の段に同じ決まりを渡していて、W11 には「ファイルを書くな」と「記録を書け」の両方が届いていた。
- `--quotes` は、記録のフォルダのファイル（差分・会話・正当化）を指す引用を git でなくファイルから読み（commit に無いため）、`<base7>:` の形の印が今の base でなくても commit として解ければその版を読む（前の回から使い回したノードは、前の回の base の印を持つ）。行は `\n` だけで切る（Python の `splitlines` は改ページの字なども行の区切りにし、エージェントの数える行とずれる）。git の出力もバイトで読む。
- patch-id の元の差分はバイトのまま `git patch-id` に渡す。テキストで読むと `\r\n` が `\n` になり、改行の字だけの直しを「変わっていない」にしていた。
- 2 本目の差分（前の回の head から今の head まで）は、前の回の head が今の head の祖先で、その間に merge の commit が無いときだけ作る。rebase の後や、作者が base を PR のブランチに merge した後に作ると、base の側の動きが全部「前の回の後に足された物」に載る。そのときは 1 本目だけで掘り、使い回しはハッシュで決める。
- 差分のファイルを読んだノードを使い回すのは、読んだ差分のファイルが前の回の 1 本目（prep の `priorRunDiff`。`<前の回の base7>..<前の回の head7>.diff`）だけのとき。前の回の 2 本目は、前の回の 1 つ前の回の head から前の回の head までの差分（前の回で新しく足された物だけ）なので、それを読んで出した答えは、今の回の PR 全体には当てはまらない。
- ヘッドレスの形の子の環境に、Windows の Git Bash の在り処（`CLAUDE_CODE_GIT_BASH_PATH`）を残す。Git Bash が既定の所に無い利用者では、無いと子が Bash のツールを持てない。
- Workflow の path の畳み（`foldDots`）は、頭の `//` を Python の `posixpath.normpath` と同じく 2 つのまま残し、作業ツリーと記録のフォルダの path も同じく畳む。Windows の共有フォルダ（`//server/share/repo`）の作業ツリーで、ハッシュを引けなかった。
- PR が消したファイル（head に無い。prep のハッシュの `now` が null）は、W8 に渡す「どのノードも読んでいない、変えたファイル」に入れない。head に無いので読めず、差分でしか見えない。入れていた間は、W8 が回ごとに同じファイルを挙げ続けた。
- 使い回したノードが読んだ差分のファイルは、今の回の 1 本目（本文が同じ）の path に指し直して記録に書く。前の回の path のままだと、次の回に `priorRunDiff` と名前が合わず、本文が同じでも掘り直していた（rebase のたびに、使い回しが 1 回おきに切れた）。
- 記録のフォルダの path は、リンクを解いた実パス（`git rev-parse --show-toplevel` の作業ツリーの path と、`--quotes` が比べる path と同じ綴り）にする。
- 2 回目の回で変わったファイルに触れるルートを先にするとき、path の語は、両端の印（`**`・`[`・`(` など）を外した形と外さない形の両方で照合する（`[id].tsx` は `[` から始まるファイルの名前）。語は日本語の読点（、。）と全角のかっこ（「」『』（）【】）でも切り、末の `?`・`!` も外す。日本語の文にじかに続けた path（`lib/x.pyの`）は、両端の ASCII でない字の並びも外した形でも照合する。
- ヘッドレスの形の子の環境に、mTLS のクライアント証明書の変数（`CLAUDE_CODE_CLIENT_CERT`・`CLAUDE_CODE_CLIENT_KEY`・`CLAUDE_CODE_CLIENT_KEY_PASSPHRASE`）を残す。無いと、代理を通る利用者の子が接続で落ちる。
- prep は、前の回の記録を読めない（切れた・壊れた JSON）とき止まらず、前の回が無いものとして全部を掘る形で返し、`priorUnreadable` に訳を書く。記録は W11 のモデルが写して書くので、1 度壊れると、止める形では次の回から毎回止まり、手で消すまで直らない。
- 変えたファイルの一覧は `--no-renames` で取る。名前を変えたファイルの古い path も一覧に載り、lock file を移したときに古い側の全部の削除が本文に残らない。
- 記録の JSON は 1 行に詰めず、値ごとに改行して W11 に渡す。読み直しのツールは行で区切って読むので、1 行の大きいファイルは読み直せない。
- 近道（prep の `unchanged`）は、PR の差分の patch-id が同じことに加え、前の回の記録が読んだ・根拠にしたファイル（PR の外の呼ぶ先を含む）と決まりの文書のハッシュが全部同じときだけ取る。rebase だけの push では patch-id が同じでも、PR の外のファイルが main の側で変わりうる。前の回の head が無いときはハッシュを比べられないので取らない。
- 根拠の在り処（`at`）の頭の `<commit の印>:` は、今の base の印（`<base7>:`）だけでなく、16 進の 7〜64 字の印ならどれでも外し、残りをファイルの path として読んで「読んだファイル」に数える（使い回したノードは前の回の base の印を持つので、今の base の印だけを外すと path が合わない）。差分のファイルの `--stat` は幅を決めて取る（`--stat=1000`。端末の幅で行が変わらない）。
- 使い回しの照合（prep の `priorReuse` と、Workflow の使い回し）とハッシュは、ノードの `checked.files` に加え、根拠（`evidence`）の在り処の path も「読んだファイル」に数える。根拠の行が載るファイルを `checked.files` に挙げないノードがあり、そのファイルが変わっても使い回していた。使い回したノードの根拠が差分のファイルを指すときは、`checked.files` と同じく今の回の 1 本目の path に指し直す（行の番号は残す）。段に渡す共通の決まりにも、`<commit の印>:path:行` はその commit の版を指すと書いた。
- 使い回すリーフの前の回の反証の判定（`stands`・`falls`）は、反証が根拠にしたファイル（判定の `evidence` の在り処）も前の回と同じときだけ持ち越す。違えばリーフは使い回すが、判定は捨ててもう一度反証する。反証がリーフの読まなかったファイルを根拠にし、そのファイルだけが変わったとき、古い判定が残っていた。prep のハッシュにも、判定の根拠の path を入れる。
- 差分のファイルの本文と stat は `core.quotepath=off` で取る（変えたファイルの一覧と同じ）。無いと日本語などの path が `\350…` の形で載り、段がその綴りを根拠に書いて、ハッシュも `--quotes` も引けない。
- 段が打つ `git show <base7>:path` と根拠の頭の `<base7>:` の印は、`git rev-parse --short=7` の長さ（大きいリポジトリでは 7 字より長くなり、曖昧にならない）にする。差分のファイルの名前の印は、前の回の名前（`priorRunDiff`）と合わせるため 7 字のまま。
- `--quotes` は、引用とファイルの行の両方から、Workflow が段の返した字から外す字（制御文字と、並びを変える見えない字。prep の `CTRL_RE` に、my-turn-dig.js と同じ並びで持つ）を外して比べる。引用は外された形で記録に載るので、`\f` などを含む行の正しい引用を「合わない」にしていた。
- 数え（`counts.stages`）に、段ごとに渡したモデル（`models`）を残し、記録には W11 のモデル（`recordModel`）を書く。ヘッドレスの形の `expectedMissing` は、回った段（`started` が 1 以上）のモデルのうち使われなかった物だけにする。前は段の表のモデルを全部数え、W1 で止まった回や `models` で段のモデルを替えた回にも「来なかった」と出ていた。数えの無い答えは null。
