# /my-turn の掘る段: 実装で設計から変えた所

[設計書](my-turn-workflow-design.md)のセクション 13 から移した一覧。
実装の中で、設計の文のままでは動かない・形が決まっていなかった所を、次のとおりに決めた。
どれも、設計書のセクション 12（「承認で見てほしい点」。承認された設計の要点 16 項目）の点を変えない。

- **移した経緯**: 2026-11-18 に移した。移した時は字を変えず、そのあと読みやすさのために項目を分けて並べ替えた（意味は変えていない）。
- **並び**: 話の種類ごとにまとめた。各項目の頭の太字は、何についての決めかを示す。
- **語と番号**: 「セクション N」「手順 N」「W1」〜「W11」は設計書の番号。語は設計書の「語」とセクション 3 に在る。
  - 一般の構造: W2 のブラインドの判定役が描く、同じ種類のシステムの一般の構造。
  - ルート: 問いの木のいちばん上の問い。W5 が区分の順に組む（W8 の漏れからも作る）。
  - 1 本目は base から head までの差分、2 本目は前の回の head から今の head までの差分（設計書のセクション 5）。

## ヘッドレスの形の台本と子の環境

- **台本に持たせる**: ヘッドレスの形の起動は、会話が `claude -p` の引数を毎回組むのでなく、台本 `scripts/my-turn-headless.py <args のファイル>` に持たせた。
  - 台本がすること:
    - 引数と環境変数をセクション 2 のとおりに組む。
    - `roles` を足した args を `<記録のフォルダ>/<PR番号>-args-headless.json` に書く。
    - 出力を `<PR番号>-headless.json`、Workflow の返した値を `<PR番号>-materials.json` に書く。
    - `modelUsage` の照合も出す。
  - 引数の組み方を試験（`tests/my-turn-prep-case.py headless`）で毎回同じに見るため。
  - `--max-budget-usd` の既定は 30（1 対の試しの費用で決め直す）。
  - `--dry-run` で起動の引数だけを出す。
- **`--add-dir <script のフォルダ>`**: ヘッドレスの形の起動に足した。
  - 1 回目の試し（2026-11-17）で、子の会話の Workflow のツールが、作業ツリーの外に在る `scriptPath` を断り、Workflow が 1 段も回らなかった（セクション 2 の確かめていない点の 1 つ目）。
  - 断った訳は「ツールが返した path か、作業ツリーか足したフォルダの下の読めるファイルでない」。
- **記録のフォルダも `--add-dir`**: worktree では、記録のフォルダは作業ツリーの外の clone の `.git` の下に在り、W11 が書き、段が差分を読む。
- **認証の失敗の形**: 子の出力が認証の失敗の形（`claude_auth.auth_failed`。終了の値 0 の 1 行）なら、上限の額のせいにしない。
  - 認証か使用枠で止まった形だと、出力の頭を添えて返す（出力の `authFailed` が真）。
- **`modelUsage` の照合**: 前方一致でなく、含むかで見る（Bedrock・Vertex のモデルの名は `us.anthropic.claude-opus-…` などの形）。
- **Workflow の返り値でない答え**: 子の会話の答えが Workflow の返り値（`stopped`・`version`・`recordWritten` のどれかを持つ JSON）でなければ、`ok` を偽にし、`message` に訳を書く。
  - 1 回目の試しでは、Workflow が断られた訳を子の会話が文で返したのに、`ok` が真のまま返っていた。
- **記録が書けた回の出力**: `{"recordPath", "recordWritten"}` の短い印にし、材料は台本が記録のファイルから組む。
  - 返り値の全体を `claude -p` の出力に写させると、大きい PR で出力の上限に当たる。
  - 記録が書けなかった回だけ、返り値の全体を出力させる。
- **材料の `counts`**: 記録の `counts`（W11 の前に数えた物）に、W11 の分（記録が書けたので、返った 1 エージェント）を台本が足した物にする。
  - 子の会話に `counts` を写させると、入れ子の大きい物の写し違いが手順 20 の照合に入るため、写させない。
  - Workflow の呼び出しが失敗した回は、子が `{"workflowError": <訳>}` を出し、台本がその訳を `message` に写す。
- **段の役のツール**: ヘッドレスの形の段の役（W2 と W11 を除く）に、WebFetch と WebSearch を持たせた。
  - W6・W9・W10 が公式の一次の文書の URL を根拠にし確かめるのに要り、既定の形の段も持っている。
- **W2 の役**: convergence-loops の `agents/blind-judge.md` の本文を英訳した物で、ツールを全部外す。
  - `tools` を空にし、`disallowedTools` に全部のツールを挙げる。
- **記録のフォルダの path に危ない字**: 権限の規則で意味を持つ字が在れば、台本は子を起動する前に止まり、既定の形で回すように返す。
  - 字は、空白・かっこ・カンマ・`*` など（graphloops の `engine/role_run.py` の `RULE_UNSAFE` と同じ並び）。
  - 書き込みの許可 `Edit(//<記録のフォルダ>/**)` がその字で切れ、W11 が記録を書けずに黙って拒まれるため。
- **子の環境に残す物**:
  - **Bedrock・Vertex・Foundry の経路の付き物**: 名前が ANTHROPIC_VERTEX_ などで始まる物と、独自のヘッダーの変数。
    - 経路の旗だけ残して付き物を落とすと、子が認証かリクエストで落ちる。
    - モデルの読み替えの変数（`ANTHROPIC_DEFAULT_OPUS_MODEL` など）は、今までどおり落とす。
  - **Windows の Git Bash の在り処**（`CLAUDE_CODE_GIT_BASH_PATH`）: Git Bash が既定の所に無い利用者では、無いと子が Bash のツールを持てない。
  - **mTLS のクライアント証明書の変数**（`CLAUDE_CODE_CLIENT_CERT`・`CLAUDE_CODE_CLIENT_KEY`・`CLAUDE_CODE_CLIENT_KEY_PASSPHRASE`）: 無いと、代理を通る利用者の子が接続で落ちる。
- **Foundry の経路**: 親の環境が Foundry の経路（`CLAUDE_CODE_USE_FOUNDRY`）でも、ほかの経路と同じく `claude_auth.auth_env` を通す。
  - `claude_auth` の継ぐ経路の一覧に Foundry が入った（main の 6f407021）ので、旗が立っていれば Keychain の鍵を重ねず親の経路を継ぐ。
  - 台本の側に Foundry だけの分岐は持たない。

## 前処理（prep）の範囲と差分のファイル

- **記録のフォルダ**: `git rev-parse --git-common-dir` の下の `attention/my-turn/`。
  - PR の作業ツリーが worktree でも、同じ clone の回どうしで記録を共有する。
- **記録のフォルダの path**: リンクを解いた実パスにする。
  - `git rev-parse --show-toplevel` の作業ツリーの path と、`--quotes` が比べる path と同じ綴り。
- **止まる理由 `git-failed`**: prep の止まる理由に、`git-failed`（git のコマンドが失敗した）を足した。
- **ルートに移ってから差分を取る**: prep は、打たれた所が作業ツリーの下位のディレクトリでも、ルートに移ってから差分を取る。
  - 本文の pathspec が打った所に絞られ、`--stat` と食い違うのを防ぐ。
- **remote の選び方**: `gh pr view` の URL のリポジトリを指す remote を、`git remote -v` の fetch の行で探す（push の URL だけが合う remote は選ばない）。
  - その remote の base で範囲を取る（fork の作業ツリーでは `origin` が自分の fork を指すため）。
  - 見つからなければ `origin` で取り、`remoteMatched` を偽にして報告に出す。
- **fetch の refspec**: `+refs/heads/<base>:refs/remotes/<remote>/<base>` を明示する。
  - single-branch の clone や、狭い `remote.<名>.fetch` の設定でも、`<remote>/<base>` を今の版にするため。
- **使う人の git の設定で中身を変えない**: 差分の本文・`--stat`・patch-id の元の差分は、/what-am-i-doing と同じ `changemap.DIFF_SANE` で取る。
  - `changemap.DIFF_SANE` は、`--no-ext-diff --no-textconv --no-color` と、接頭辞を a/ b/ に決める 2 つ。
  - lock file の除外は `:(exclude,literal)` で、名前を glob として読まない。
  - 使う人の git の設定（外の diff のツール・textconv・色・接頭辞）で中身を変えない。
- **決まりの文書を足した**: CLAUDE.md と同じ場所の AGENTS.md と、ルートの `.claude/` の下の CLAUDE.md・AGENTS.md（セクション 6）。
  - CLAUDE.md を持たず AGENTS.md に決まりを書くリポジトリが在る。
  - ヘッドレスの形の役は `omitClaudeMd` で CLAUDE.md を入れないので、prep の一覧に載らない決まりはどの段にも届かない。
  - Code Review の読む範囲（CLAUDE.md と REVIEW.md）を含み、それより広い。
- **変えたファイルの一覧は `--no-renames`**: 名前を変えたファイルの古い path も一覧に載る。
  - lock file を移したときに、古い側の全部の削除が本文に残らない。
- **`core.quotepath=off`**: 差分のファイルの本文と stat は `core.quotepath=off` で取る（変えたファイルの一覧と同じ）。
  - 無いと日本語などの path が `\350…` の形で載り、段がその綴りを根拠に書いて、ハッシュも `--quotes` も引けない。
- **`--stat` の幅**: 差分のファイルの `--stat` は幅を決めて取る（`--stat=1000`。端末の幅で行が変わらない）。
- **commit の一覧**: 差分のファイルの commit の一覧は、`log.showSignature` を切って取る（gpg の検証の行が混ざらない）。
- **本文はバイトで取る**: テキストの読みは `\r\n` と単独の `\r` を `\n` に変える。
  - 改行の字だけの直し（CRLF→LF）が、本文で `-` と `+` の同じ行に見えていた（patch-id はもとからバイトで取っていた）。
- **`<base7>:` の印の長さ**: 段が打つ `git show <base7>:path` と根拠の頭の `<base7>:` の印は、`git rev-parse --short=7` の長さにする。
  - 大きいリポジトリでは 7 字より長くなり、曖昧にならない。
  - 差分のファイルの名前の印は、前の回の名前（`priorRunDiff`）と合わせるため 7 字のまま。
- **PR が消したファイル**（head に無い。prep のハッシュの `now` が null）: W8 に渡す「どのノードも読んでいない、変えたファイル」に入れない。
  - head に無いので読めず、差分でしか見えない。
  - 入れていた間は、W8 が回ごとに同じファイルを挙げ続けた。
- **前の回の記録が読めない**（切れた・壊れた JSON）: prep は止まらず、前の回が無いものとして全部を掘る形で返し、`priorUnreadable` に訳を書く。
  - 記録は W11 のモデルが写して書くので、1 度壊れると、止める形では次の回から毎回止まり、手で消すまで直らない。

## 近道（unchanged）と 2 本目の差分

- **`git patch-id` の取り方**: `--verbatim`（空白も比べる。git 2.39 から）で取り、無い git では `--stable` に落とす。
  - `--stable` は空白を無視するので、字下げだけの直し（Python では意味が変わる）を「変わっていない」にしていた。
- **patch-id の元の差分はバイトのまま**: `git patch-id` にバイトのまま渡す。
  - テキストで読むと `\r\n` が `\n` になり、改行の字だけの直しを「変わっていない」にしていた。
- **欠けの在る記録は近道にしない**: 前の回に結果を返さなかったエージェントが 1 エージェントでも在る記録は、patch-id が同じでも `unchanged` にしない。
  - 「在る」は、`counts.stages` のどれかの段の `null` が空でないこと。段の全部が返らなかった `counts.allNull` も含む。
  - ノードの一部だけが落ちた回も、記録は欠けているため。
  - W11 は記録を写すだけなので見ない（落ちた回は、会話が `counts` ごと同じ中身を書く）。
- **近道を取る条件**: 近道（prep の `unchanged`）は、次が全部同じときだけ取る。
  - PR の差分の patch-id
  - 前の回の記録が読んだ・根拠にしたファイル（PR の外の呼ぶ先を含む）と、決まりの文書のハッシュ
  - rebase だけの push では patch-id が同じでも、PR の外のファイルが main の側で変わりうる。
  - 前の回の head が無いときは、ハッシュを比べられないので取らない。
- **近道（`unchanged`）のハッシュに入れる物**: 段が従う決まりの文書（`rules`）と、記録のどこかの根拠（ノード・反証・スメルの問い・直しの案の `at`）の path も入れる。
  - 前はノードの読んだファイルだけで、次の回にも古い答えをそのまま出していた。
    - base の側で REVIEW.md が変わった回
    - スメルの答えが根拠にした PR の外のファイルが変わった回
  - 次の記録も、近道を取らない（ノードの使い回しが同じファイルで使い回さないのと揃える）。
    - ハッシュを取れないファイル（repo の外・git dir の中・改行を含む path）を読んだ記録
    - 変えていないのに、前の回も今も無いファイル（untracked・ignored）を読んだ記録
- **前の指摘が来たとき**: 会話は、前の回の後に来た指摘が在れば、`unchanged` でも Workflow を回す（`commands/my-turn.md` の手順 6）。
- **2 本目の差分を作る条件**（前の回の head から今の head まで）:
  - 前の回の head が今の head と同じなら、2 本目の差分（空になる）は作らない。
  - 前の回の head が今の head の祖先で、その間に merge の commit が無いときだけ作る。
  - rebase の後や、作者が base を PR のブランチに merge した後に作ると、base の側の動きが全部「前の回の後に足された物」に載る。
  - そのときは 1 本目だけで掘り、使い回しはハッシュで決める。

## 使い回しとハッシュ

- **ハッシュの渡し方**: prep の中では、ファイルごとに `then`（前の回の head の版）と `now`（今の head の版）の組で比べる。
  - Workflow には短い印で渡す: `same`（同じ中身）・`moved`（違う）・`gone`（今の head に無い）・`absent`（どちらにも無い）。
  - 会話が prep の答えを `args` に写すので、ファイルごとに 40 字の sha を 2 つ写させない（写し違いが、使い回しの判定を黙って変える）。
  - 記録のフォルダの中のファイルの扱いは、下の「使い回しの判定で」の項に書く。
- **`priorReuse`**: 既定の形では args を会話が Workflow のツールへ直に渡すので、前の回の記録を丸ごと渡すと会話の出力が膨らむ。
  - prep が、前の回の記録から使い回しに要る物だけを抜いた `priorReuse` を出す。
    - 抜く物: PR の種類の 1 文・一般の構造・使い回せるノード。
  - script は `prep` の中の `priorReuse` を読むので、会話は同じ物を `priorRecord` に写さない。
    - `priorRecord` は、在れば `priorReuse` より先に使う、試しの差し替え口。
  - 抜く条件は、script の使い回しの条件と同じ。
  - 前の回の head が手元に無いときは null。
- **使い回しの判定で**、記録のフォルダの差分のファイル（`*.diff`）はファイルごとには数えない。
  - 差分を読んだノードは、前の回の差分の本文と今の本文の patch-id が同じとき（prep の `diffSame`）だけ使い回す。
    - 前の回の差分の本文は、前の回の base から head まで。lock file を除く。
    - 差分には、ノードが `checked.files` に挙げていないファイルの所も載っているため。
  - 変えたファイルのハッシュで比べる形は、次の失敗をしていた。
    - 消したファイル・名前を変えたファイル（ハッシュが無い）で、毎回掘り直した。
    - 変更を取り消したファイル（今の変えたファイルの一覧に無い）を見落とした。
  - 差分のファイルの commit の件名の一覧と `--stat` の行（lock file も載る）も比べに入れる。件名を直した・lock file だけを直した回も使い回さない。
  - patch-id は行の番号を数えないが、本文は前後 10 行を載せる（`-U10`）。
    - そのため、base の側の直しが PR の所から 10 行より遠いときだけ、rebase の後でも使い回せる。
  - 差分だけを読んだノードと、`parts` に差分のファイルを挙げたノードも、同じ条件にする。
  - ほかの記録のフォルダのファイル（毎回書き直す thread・justifications）は、同じとみなさない。
    - 前は記録のフォルダのファイルを全部「同じ」とみなし、thread だけを読んだノードを、新しいコメントの後も使い回していた。
  - 記録のフォルダの path は、リポジトリの相対の形（main の clone では `.git/attention/my-turn/…`）でも記録のフォルダに数える。
  - git dir の中の path と、改行を含む path は、ハッシュに入れない。
- **読んだ差分のファイルが前の回の 1 本目だけのとき**に使い回す（prep の `priorRunDiff`。`<前の回の base7>..<前の回の head7>.diff`）。
  - 前の回の 2 本目は、前の回の 1 つ前の回の head から、前の回の head までの差分（前の回で新しく足された物だけ）。
  - それを読んで出した答えは、今の回の PR 全体には当てはまらない。
- **差分のファイルの path を指し直す**: 使い回したノードが読んだ差分のファイルは、今の回の 1 本目（本文が同じ）の path に指し直して記録に書く。
  - 前の回の path のままだと、次の回に `priorRunDiff` と名前が合わず、本文が同じでも掘り直していた。
  - rebase のたびに、使い回しが 1 回おきに切れた。
- **repo の外の path**: 前の回の記録が指す path のうち repo の外（`../` で始まる物）は、ハッシュに入れない（`git cat-file` が fatal で止まるため）。
- **根拠の在り処も「読んだファイル」**: 使い回しの照合（prep の `priorReuse` と、Workflow の使い回し）とハッシュは、ノードの `checked.files` に加え、根拠（`evidence`）の在り処の path も「読んだファイル」に数える。
  - 根拠の行が載るファイルを `checked.files` に挙げないノードがあり、そのファイルが変わっても使い回していた。
  - 使い回したノードの根拠が差分のファイルを指すときは、`checked.files` と同じく今の回の 1 本目の path に指し直す（行の番号は残す）。
  - 段に渡す共通の決まりにも、`<commit の印>:path:行` はその commit の版を指すと書いた。
- **在り処の頭の印を外す**: 根拠の在り処（`at`）の頭の `<commit の印>:` は、16 進の 7〜64 字の印ならどれでも外す。
  - 今の base の印（`<base7>:`）だけではない。
  - 残りをファイルの path として読み、「読んだファイル」に数える。
  - 使い回したノードは前の回の base の印を持つので、今の base の印だけを外すと path が合わない。
- **反証の判定の持ち越し**:
  - 使い回したノードの反証は、前の回の判定が `stands` か `falls` のときだけ持ち越し、`unverifiable` はもう一度問う。
  - 判定（`stands`・`falls`）は、反証が根拠にしたファイル（判定の `evidence` の在り処）も前の回と同じときだけ持ち越す。
    - 違えば、リーフは使い回すが、判定は捨ててもう一度反証する。
    - 反証がリーフの読まなかったファイルを根拠にし、そのファイルだけが変わったとき、古い判定が残っていた。
    - prep のハッシュにも、判定の根拠の path を入れる。
  - 判定の根拠が差分のファイルを指していれば、今の回の 1 本目の差分のファイルの path に指し直す。
    - 1 本目は、base から今の head までの全体の差分。前の回の head からの差分の 2 本目ではない。
    - 指し直さないと、次の回にその判定を捨てて反証をやり直していた。
    - 行の番号の無い在り処（差分のファイルの path だけ）も、`checked.files` と同じく指し直す。
- **一般の構造の持ち越し**: 使い回した一般の構造は、それを出した問い（`general.questions`。2 問目の答えなら 2 問とも）と問い直しの印（`askedAgain`）も持ち越す。
  - 前は 1 問目だけを書き、報告の「確かめた前提」が、どの問いで出た構造かを取り違えていた。
- **path の畳み**（`foldDots`）: Workflow の path の畳みは、頭の `//` を Python の `posixpath.normpath` と同じく 2 つのまま残す。
  - 作業ツリーと記録のフォルダの path も、同じく畳む。
  - Windows の共有フォルダ（`//server/share/repo`）の作業ツリーで、ハッシュを引けなかった。
- **2 回目の回のルートの並び**: 変わったファイルに触れるルートを先にするとき、path の語を次の形でも照合する。
  - 両端の印（`**`・`[`・`(` など）を外した形と、外さない形の両方（`[id].tsx` は `[` から始まるファイルの名前）。
  - 語は、日本語の読点（、。）と全角のかっこ（「」『』（）【】）でも切り、末の `?`・`!` も外す。
  - 日本語の文にじかに続けた path（`lib/x.pyの`）は、両端の ASCII でない字の並びも外した形でも照合する。

## 引用の照合（`--quotes`）

- **記録のフォルダのファイル**: `--quotes` は、記録のフォルダのファイル（差分・会話・正当化）を指す引用を、git でなくファイルから読む（commit に無いため）。
- **今の base でない印**: `<base7>:` の形の印が今の base でなくても、commit として解ければその版を読む。
  - 前の回から使い回したノードは、前の回の base の印を持つ。
- **行の切り方**: 行は `\n` だけで切る。
  - Python の `splitlines` は改ページの字なども行の区切りにし、エージェントの数える行とずれる。
  - git の出力もバイトで読む。
- **絶対の path**: `--quotes` も、在り処が作業ツリーの絶対の path なら、repo の相対に直して読む（Workflow の照合と同じ）。
- **見えない字を外して比べる**: 引用とファイルの行の両方から、Workflow が段の返した字から外す字を外して比べる。
  - 外す字は、制御文字と、並びを変える見えない字。prep の `CTRL_RE` に、my-turn-dig.js と同じ並びで持つ。
  - 引用は外された形で記録に載るので、`\f` などを含む行の正しい引用を「合わない」にしていた。
- **印が commit に解けないとき**（引用の在り処の `<commit の印>:path:行` の印。短い印が曖昧・force-push の後に消えた）: 名前が 16 進の字だけのファイルかもしれないので、head の版の path として読む。
  - それでも読めなければ、印が commit に解けないことを訳に書き添える。
  - 印の後ろが `path:行` の形でない（`cafebabe:1`）ときは、印が commit に解けても、名前が 16 進の字だけのファイルの行として head の版で読む。

## 出力スキーマ・記録・数え

- **出力スキーマに足したフィールド**:
  - W1 の `hiddenChoices`: W2 の伏せた問いの元。この PR が選んだ所を、答えを伏せた問いの文で。
  - W3 の `comparable` と `whyNotComparable`: 一般論で比べる相手にならないかを W3 が言い、script が W2 に 1 回だけ問い直す。
  - W7 のクラスタごとの `question`: クラスタの問いの文。
  - W9 の `leaves`（案が乗るリーフ）と `searched`（PR の外を探した語）。
  - W10 の `evidence` は、「確かめられない」のとき空でよい。
- **W11 の返す物**: 書いたファイルの中身を丸ごと返さず、`wrote`・`nodeCount`（読み直した記録のノードの数）・`head` を返す。script が組んだ記録と照合する。
  - 中身を丸ごと返させると、大きい PR で W11 のモデル（haiku）の出力の上限に当たるため。
- **W11 の共通の決まり**: W11 には、共通の決まりの「読むだけ」の行を、記録のファイルだけを書く行に替えて渡す。
  - 前は全部の段に同じ決まりを渡していて、W11 には「ファイルを書くな」と「記録を書け」の両方が届いていた。
- **記録のノードは 1 段**: 入れ子にせず、1 段の項目で持つ（`resultStatus`・`answer`・`checked`・`evidence`・`parts`・`premises`・`children`・`verdict` など）。
  - prep が前の回の記録の `nodes[*].checked.files` を読むので、その形に揃えた。
- **記録の JSON は値ごとに改行**: 1 行に詰めず、値ごとに改行して W11 に渡す。
  - 読み直しのツールは行で区切って読むので、1 行の大きいファイルは読み直せない。
- **一般の構造が無い訳 `why`**: 記録の `general` に持たせた。出たときは null。
  - `notFound`: 問い直しても出なかった
  - `notComparable`: 一般的すぎて比べられなかった
  - `noAnswer`: ブラインドの判定役が返らなかった
  - `noParts`: 部品の言えない PR で問わなかった
  - `failed`: この段がまるごと回らなかった
  - 問い直しても出なかったときは、1 回目の答えの文を、記録と後の段の両方に残す。
- **数えにモデルを残す**: 数え（`counts.stages`）に、段ごとに渡したモデル（`models`）を残し、記録には W11 のモデル（`recordModel`）を書く。
  - ヘッドレスの形の `expectedMissing` は、回った段（`started` が 1 以上）のモデルのうち、使われなかった物だけにする。
  - 前は段の表のモデルを全部数え、W1 で止まった回や `models` で段のモデルを替えた回にも「来なかった」と出ていた。
  - 数えの無い答えは null。

## W7 の束ねと「確かめていない物に乗る」印

- **畳んだ問いの親にも伝える**: W7 が既に在るノードに畳んだ問いの親（`alsoFrom`）も親に数え、「確かめていない物に乗る」（`dependsOnUnverified`）を伝える。
  - 畳んだ先のノードが既に確かめていないなら、畳んだときに新しい親へ伝える。
  - 前は `parents` だけをたどり、畳まれた問いの親の答えを「決まった」として報告に出しえた。
- **子が 1 つも掘られない split**: 分けた（`split`。答えが子の問いしだいのとき）のに、子の問いが 1 つも掘られなかったノードは、次のようにする。
  - 確かめていない物（`unverified`）にする。
  - 祖先に「確かめていない物に乗る」と伝える。
  - `counts.seenUndecided.unverifiedNodes` にも載せる。
  - 掘られないのは、次のどれか。
    - 使える子が無い（`howParentChanges`〔子の答えで親の答えがどう変わるか。セクション 3〕が空・問いが空）
    - W7（違う親が出した同じ問いを束ねる段）が子を全部落とした
    - 子が自分か祖先の問いを繰り返した
  - 判定は W7 が束ねた後の 1 か所で、子が新しいノードになったか、木に既に在るノード（id を持つ）に畳まれたかで見る。
  - リーフ（実物で確かめて決まった問い）でないので、答えを覆せるか試す段（反証）も通らず、問いが開いたまま「答えた」に見えていた。
- **W7 のクラスタを木のノードに当てる規則を 1 つにする**: 以下がその規則。
  - **前提**: W7 は、違う親ノードが出した同じ問いをクラスタにまとめる段。クラスタは、クラスタを見分ける印（key）と問いの文を持つ。
  - **当て方**: ノードは key と問いの文の両方で引けるようにする。
    - key か問いの文のどちらかがノードに当たれば、そのノードに畳む（新しいノードは作らず、既存ノードに統合する）。
    - 当たる＝大文字小文字・空白・文末の句読点をそろえた後の字が一致すること。言い回しの違いは W7 が束ねる。
    - 句読点だけの key（`?` など）は、そろえると空になるので key に使わず、問いの文で見分ける。
  - **W7 に見せる key の一覧**: 当てるのに使う key の全部（ノードの key・問いの文・組のほかの key）を、400 件まで並べる。
    - W7 は、問いを短く言い換えた語（大文字小文字や言い回しをそろえた形）を key にしうるため。
    - 子が繰り返しうるのは自分の筋の問いなので、新しい問いの親とその祖先の key を先に置く。
    - 400 件を超えたら、後ろの key から切る。
  - **類**: W7 が同じ問いと言った key（1 つのクラスタの key と問いの文、1 つの組の key の全部）は、1 つの類にまとめる。
    - 類は、その key の集まりと、その問いを問うノードの全部を持つ。
    - `seen` は key ごとに、その類を指す。
    - 2 つの類に当たった組は 1 つの類に合わせるので、W7 が後でどちらの key を書いても、同じノードの全部に当たる。
    - 同じ問いのルートが 2 つ在れば、2 つのルートが 1 つの類になる。
  - **親の筋の繰り返し**: 子の問いの親ごとに、類のノードのどれかがその親の筋に在るかを見る。
    - 親の筋は、親自身と、`parents` と `alsoFrom` をルートまでたどった祖先。
    - 在れば、その子は自分か祖先の問いを繰り返した子とし、輪を作らない。
      - W7 は類のノードを全部同じ問いと言ったので、祖先と同じ問いを別のノードで答えたことにはしない。
    - 無ければ、その親を類のノードの全部の `alsoFrom` に足す。
    - `alsoFrom` には、既に `parents` か `alsoFrom` に在る親を足さない。
  - **繰り返した子の扱い**: 畳んだ先の `alsoFrom`（畳んだ問いの別の親の一覧）に足さない。
    - `counts.repairs.foldIntoOwnLine`（繰り返した子の一覧。報告の `counts` に出る）に数える。
    - その親と、その親からルートまでの祖先の全部に、「確かめていない物に乗る」印（`dependsOnUnverified`）を付ける。
    - 親の答えが、上でまだ開いている問いに乗るから。ほかに掘った子が在っても、印は付ける。
    - `split`（答えが子の問いしだいで、子を掘って分ける状態）のままでも、印を付ける方を選んだ。
      - 印を付けすぎれば確かめる手間が増えるだけだが、付け損なえば開いた問いが「答えた」に見える。
  - **落とした問い**: W7 が落とした問いは、同じ W7 の答えより後の段（木の 1 つ下の深さ）で W7 がまた束ねてきたら掘る（落とした記録で止めない）。
    - 落とした問いのうち既に木に在る問いの物は、そのノードに畳む。
    - クラスタに入った物とあわせて、`counts.repairs.droppedKnown`（落とした問いを既知として畳んだ一覧）に、W7 が書いた訳と一緒に数える（「もう聞いた」として落とすことがある）。
  - **1 回の答えの中の組**: W7 の 1 回の答えの中では、次を 1 つの組にまとめ、組ごとに 1 つのノードに当てる。
    - key か問いの文が重なるクラスタ（同じ key のクラスタが 2 つ並ぶ・あるクラスタの key と別のクラスタの問いの文が同じ、など）
    - W7 が落とした問いのうち、クラスタと同じ問いの物
    - 組の中のどの問いの親も、そのノードの親に数える。
    - 重さ（`weight`。W6 が子の問いに付ける大きさの区分〔big・small など〕で、数ではない）は、組の中で一番重い問いの物を、そのノードの重さにする。
      - ノードの上限（`limits` のノード数、既定 80）に達するまでは、重い問いから掘る。
    - 後の深さでは、組のどのクラスタの key でも、そのノードに当たる。
  - **組が木のノードに畳まれたとき**: 組の key を、当たったノードの類に入れる。当たった類が 2 つ以上なら、1 つの類にまとめる。
    - こうすると、後の深さで W7 が同じ問いのどの key を書いても同じノードの全部に当たり、親の筋に在るかの答えも変わらない。
    - key ごとに指すノードを覚えると、W7 がどちらの key を書くかで答えが割れた。
  - **類をまとめる順**: W7 の 1 回の答えの類は、どの組も木に当てる前に全部まとめる。
    - クラスタの並びが先の組を、後の組が類を合わせる前のノードに乗せると、W7 がクラスタを並べた順で、組が当たるノードが変わる。
    - ただし、同じ答えの 2 つの組が互いの親を通して輪を作るときは、後に当てる組の親を自分の筋の繰り返しに数える。
      - どちらを数えるかは並びで決まるが、どちらでも両方の親に「確かめていない物に乗る」印が付く。
  - **後の深さで類が合わさったとき**: 合わさる前の類のノードの親（`parents` と `alsoFrom`）を、合わさった相手のノードにも、新しく乗る親と同じ規則で当て直す。
    - 類のノードが親の筋に在れば、自分の筋の繰り返しに数えて印を付ける。
      - 前の類のノードの `alsoFrom` からは外さない。前に数えた繰り返しは数え直さない。
    - 無ければ相手のノードの `alsoFrom` に足し、相手のノードが確かめていない物なら印を継ぐ。
  - **類が広がるとき**: 類は合わさるだけで分かれないので、W7 が問いをゆるく束ねると、類が連鎖して広がり、自分の筋の繰り返しに数える子が増えうる。
    - その子は掘らないが、親に「確かめていない物に乗る」印が付く。
    - 開いた問いが「答えた」に見えることはなく、確かめる手間が増えるだけである。
    - key ごとに指すノードを固める形も試したが、W7 が同じ問いのどちらの key を書くかで答えが割れた。
  - **畳んだノードが確かめていないとき**: 親が畳んだノードのどれかが確かめていない物（検証が済んでいないノード、またはそれに乗るノード）なら、親にも `dependsOnUnverified` を付ける。
    - 印は 1 回の実行の中で外さない。
  - **上限の後の W8 の漏れ**: ノードの上限に当たった後も、W8（木の全部を見て、問いの漏れを探す段）が漏れを返しうる。
    - その漏れも、木のノードに当たる物だけを既に在る物とする。
    - W7 が前に落とした問いと同じ漏れは、既に在る物とせず、「未確認」の状態で返す。

## 残した限り

- **設定のファイルにだけ書いた認証**: 子の会話は設定のファイルを読まない（`--setting-sources ""`）ので、設定のファイルにだけ書いた認証（`apiKeyHelper` など）は子に渡らない。
  - 渡るのは、環境変数と `CLAUDE_CONFIG_DIR` の下の資格情報だけ。
  - そのときは、認証の失敗の形で止まる。
- **記録の写しが切れうる**: Workflow の script はファイルを書けないので、記録は W11（haiku）が JSON を写して書き、照合はノードの数と head だけ。
  - ノードの多い PR では、W11 の出力の上限で写しが切れうる。
  - そのときは `recordWritten` が偽になり、会話が手順 15 で書く。
