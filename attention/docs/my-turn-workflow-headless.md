# /my-turn の掘る段: ヘッドレスの形の起動の細部

[設計書](my-turn-workflow-design.md)のセクション 2 から移した細部。ヘッドレスの形（/my-turn の引数 `--headless`。`claude -p` をもう 1 つ起動して Workflow を回す）の、環境・引数・役・許可・モデルの照合と、確かめの 5 つの点（1 は 2026-11-17 の試しで直し、残り 4 つは未確認）を書く。2026-11-18 に設計書から移し、同じ日に実装との照合で直した。

- 起動の仕方は、持ち主の別のリポジトリ my_notes が評価と調べものの呼び出しに使っている `claude -p` の起動（`tools/primary_pipeline/claude_call.py` の `child_env` と 「CONTEXT_FLAGS」、`tools/claude_child.py`）に倣う。my_notes の呼び出しはツールも作業ツリーも持たない 1 回きりの物で、この形は裏のエージェントにツールと作業ツリーを残すので、取るのは環境と引数の絞り方だけにする。
  - 環境: 親の環境変数のうち、名前が CLAUDE か ANTHROPIC で始まる物を持ち込まない。my_notes はアカウントを決める `CLAUDE_CONFIG_DIR` も外し、works-dispatch が選んだアカウントの鍵を `CLAUDE_CODE_OAUTH_TOKEN` で子にだけ渡し直す。ここは /my-turn の会話のアカウントで回すので、`CLAUDE_CONFIG_DIR` と認証の経路（`CLAUDE_CODE_OAUTH_TOKEN`・`ANTHROPIC_API_KEY`・`ANTHROPIC_BASE_URL` など。親に無ければ、attention の `scripts/lib/claude_auth.py` が利用者の窓口のコマンドか Keychain から足す。子は対話の claude の認証を継がず、認証が無いと終了の値 0 のまま 1 行で落ちる）を残す点が違う。これで、全部の段を 1 つのモデルにする `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` も、モデルの別名を別のモデルに読み替える環境変数（my_notes の `.claude/AGENTS.md` の「読み替えの環境変数とその鍵を外し」）も届かない。足すのは、CLAUDE.md を入れない `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` と、安全分類器に当たった要求を別のモデルで打ち直させない `CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1`（打ち直されると反証が頼んだのと別のモデルで動く。my_notes の 「NO_MODEL_SWITCH」）。打ち直さない要求は失敗して返るので、そのノードは `null` になり、セクション 4 の件数に「返らなかった」として出る。my_notes が呼び出しごとに選ぶキャッシュの寿命（`FORCE_PROMPT_CACHING_5M`）は足さない。Workflow の裏のエージェントのキャッシュは、既定で 5 分になっている（https://code.claude.com/docs/en/workflows 「its cache holds for five minutes by default, including on a Claude subscription」）。
  - 引数: ヘッドレスの会話は `--model sonnet` で起動する（段のモデルは script が `agent()` に渡す値で決まる）。`--tools Read,Grep,Glob,Bash,Write,Workflow,WebFetch,WebSearch` で、会話のツールを絞る（WebFetch と WebSearch は一次の文書を読む段のため。セクション 13）。裏のエージェントは会話のツールから受け取るので（セクション 9）、役の引き当て（下の確かめの 2）が効かなくても Edit などは届かない。`--add-dir` で script のフォルダと記録のフォルダを足す（Workflow の `scriptPath` は、作業ツリーか足したフォルダの下のファイルしか受けない。セクション 13）。`--setting-sources ""` で設定のファイルを読まない（フック・プラグイン・設定に書いた許可も入らない。Workflow は既定で使える物で、切るのは設定の `disableWorkflows` なので、設定を読まなくても Workflow は残る。同じ文書の「Set `"disableWorkflows": true`」）。`--disable-slash-commands` でスキルとコマンドを、`--strict-mcp-config` で MCP を切り、`--settings '{"disableAllHooks":true}'` も重ねる。`--system-prompt` で、ヘッドレスの会話の system prompt を「`args` のファイルを読み、Workflow を 1 回呼び、終わりを待って結果を出す」だけの短い文に替える。
  - 役: `--agents` で段ごとの役をその会話の中だけに定義し、`omitClaudeMd`（役の定義の項目。真にするとその役に CLAUDE.md を入れない）を真にする。役の `tools` は Read・Grep・Glob・Bash・WebFetch・WebSearch（W6・W9・W10 が公式の一次の文書の URL を読むため）で、`disallowedTools` で Write・Edit・NotebookEdit を外す。W11 の役は Read と Write だけを持ち、Edit・Bash・NotebookEdit を外す。W2 の役は、ブラインドの判定役の定義（convergence-loops の `agents/blind-judge.md`。ツールを持たず、渡された前提と問いだけから考える役）の本文の英訳を持ち、ツールを持たない。役には `model` と `effort` を書かず、script が `agent()` に渡す値（セクション 9）で決める（役の `model` と `agent()` の `model` のどちらが勝つかに頼らないため）。
  - 許可: `--permission-mode dontAsk` と `--allowedTools` で通すのは、Workflow、読むツール（Read・Grep・Glob。読むだけの段が作業ツリー・記録のフォルダ・`args` のファイルを読むので、path で絞らない）、WebFetch・WebSearch、記録のフォルダへの書き込み（`Edit(//<記録のフォルダの絶対の path>/**)`。ファイルを書き換えるツールの全部に効く形。path はリンクを解いた実パスで、Windows は `/c/Users/…` の形に直す。allow の規則はリンクの綴りと解いた先の両方に当たるときだけ効き、当たらなければ dontAsk の下では黙って拒まれる〔macOS の /tmp → /private/tmp〕。graphloops の `engine/role_run.py` の `read_rule` と同じ）、Bash の `git show`・`git blame`・`git log`・`git diff`・`git cat-file`・`git ls-files`・`git rev-parse`、`gh pr view`・`gh pr diff`・`gh pr list`・`gh issue view`・`gh issue list`・`gh search` に限る（`gh api` は書き込みもできるので通さない）。`git diff`・`git log`・`git show` は `--output=<ファイル>` で書き込めるので、`--disallowedTools` で `Bash(git *--output*)` を禁じる（禁止は許可より強い。https://code.claude.com/docs/en/permissions 「An allow rule can't carve an exception out of a deny rule」）。`git grep` は `-O`（`--open-files-in-pager`）で名指しのコマンドを動かすので、許可に入れずに禁じ、探すのは Grep のツールでする。
  - モデルの照合: 出力の JSON の `modelUsage`（使ったモデルごとの使用量）に、セクション 9 の表と `models` の上書きに無いモデルが在れば、報告に書く（my_notes の納品のゲートの `deliver_check.check_model` は 1 つのモデルだけを許す照合で、これは複数のモデルを許すように広げた物）。`modelUsage` のキーはモデルの完全な名（`claude-opus-5-5` など）なので、表の別名（opus・sonnet・haiku）を完全な名に当てる対応表（`ALIAS`）は台本 `my-turn-headless.py` に持ち、完全な名が別名の接頭辞（`claude-opus` など）を含むかで照合する。
  - 引数と環境変数の意味は https://code.claude.com/docs/en/cli-reference 、https://code.claude.com/docs/en/sub-agents の「omitClaudeMd」、https://code.claude.com/docs/en/env-vars 、許可の書き方は https://code.claude.com/docs/en/permissions に在る。進み具合の木は持ち主の画面に出ず、結果は終わってから届く。
  - 採らない物: `--bare`（OAuth を読まず API キーだけで動く）と `--safe-mode`（workflows も読まない）（cli-reference）。my_notes の空のフォルダで走らせる形（裏のエージェントが作業ツリーの git とファイルを読めなくなり、全部の段の指示を書き直すことになる）と、`--tools ""`（裏のエージェントのツールも無くなる）と、`--no-session-persistence`（確かめに要る会話の記録と、Workflow の run の記録が残らない）。
- ヘッドレスの形の確かめの点は 5 つある。1 は 2026-11-17 の試しで `scriptPath` が断られ、`--add-dir <script のフォルダ>` を足して直した（[実装で設計から変えた所](my-turn-workflow-impl-changes.md)）。残りの 4 つは確かめていない。直した版の 1 対の試し（セクション 11）のヘッドレスの会話の記録（出力の JSON と、Workflow の run の `journal.jsonl` と裏のエージェントごとの会話の記録）で確かめ、駄目だった物ごとに次の手に戻す。どの点でも、駄目だった回は「測れなかった」と書いて走らせ直さない。直した版を確かめる回は司令塔（持ち主の別のリポジトリ my_notes に在る、持ち主への中継と部署への頼みの振り分けをする部署）に問う（このリポジトリの直下（ルート。問いのルートとは別）の CLAUDE.md の「判断の線」。試しは前の版と直した版の 1 対までで、それより多く走らせたいときは、何を確かめるか・何回・見込みの額を添えて走らせる前に司令塔に問う、という決まり）。
  1. 設定のファイルを読まず、名前が CLAUDE か ANTHROPIC で始まる環境変数を `CLAUDE_CONFIG_DIR` と認証の経路（attention の `scripts/lib/claude_auth.py` が足す物）のほかに持たない会話で、アカウントの認証が通り、Workflow のツールが在り、`scriptPath` で Workflow を呼べるか。見る所: ヘッドレスの会話の記録に Workflow の呼び出しが在り、エラーで返っていないか。駄目なら、認証は my_notes と同じく鍵を `CLAUDE_CODE_OAUTH_TOKEN` で子にだけ渡す形を考える（鍵の取り出し方は、my_notes の `tools/secret_store.py` を見てそのとき決める）。Workflow のツールが無ければ、落とした環境変数のうち要る物を残す形に戻す。呼び出しは `--plugin-dir` で attention を読ませて名前で呼ぶ形に直す。それでも呼べなければヘッドレスの形を取り下げ、`--headless` は訳を言って止まる。
  2. script の `agentType` で `--agents` の役を引けるか。見る所: 裏のエージェントの会話記録の持つツールに Write が無いか（W11 を除く）と、W11 の記録のフォルダの外への書き込みが許可で断られるか（`--allowedTools` が効いているか）。駄目なら `roles` を渡さない。Edit などは `--tools` で、記録の外への書き込みは許可で止まり、残る Write は手順 20 の `git status` で見る。script は、実際に CLAUDE.md が入ったかでなく `roles` の有る無しだけで CLAUDE.md の書き足し（セクション 3 の共通の決まり）を決める。`roles` を渡さなければ script は既定の形とみて書き足しを入れるので、書き足しは自動で戻る。
  3. 環境変数 `CLAUDE_CODE_DISABLE_CLAUDE_MDS` が Workflow の裏のエージェントにも効くか。見る所: 裏のエージェントの会話記録に、作業ツリーの CLAUDE.md の決まった 1 行が無いか。2 の `omitClaudeMd` と二重にしてあり、どちらか 1 つが効けば足りる。両方が駄目なときは、2 の手で `roles` を渡さなくなるので、script は既定の形とみて CLAUDE.md の書き足しを入れる（書き足しを入れるかは `roles` の有る無しだけで決まるので、この食い違いは起きない）。
  4. ヘッドレスの会話が Workflow の終わりまで待つか（`claude -p` はターンを終えるとプロセスが終わり、裏の run も切れうる）。見る所: 出力の JSON に Workflow の結果（件数）が在るか。駄目ならヘッドレスの形を取り下げ、1 と同じく `--headless` は訳を言って止まる。
  5. 出力の JSON の `modelUsage` に、裏のエージェントのモデルも載るか。見る所: `modelUsage` に、セクション 9 の表の opus・sonnet・haiku が揃って在るか。載らなければモデルの照合を外し、報告に「モデルを照合していない」と書く。
