# /catchup の参照（要るときだけ読む）

`/catchup` の命令書（`attention/commands/catchup.md`）が毎回読まれる本文で、この file はその場面でだけ読む部分。数値の正本は `attention/docs/catchup-spec.md`。

## 一覧（仕様 `catchup-spec.md` の写し。数値の正本はそちら）

`/catchup [対象] [焦点]`。対象は 1 つ、焦点は 0〜3 語（`指摘`・`地図`・`CI`）。`/catchup setup` は準備の口（下の「準備」）。

| 対象 | 例 | 移る | GitHub | 主な材料 |
|---|---|---|---|---|
| 番号 | `1505` `#1505` | PR の head へ | 見る | PR / issue |
| URL | `https://…/pull/1505` | 同上 | 見る | PR / issue |
| ブランチ名 | `feat/123-x` | そこへ | 枝の PR が有れば | PR、無ければ手元 |
| 引数なし・`this`・焦点だけ | `/catchup` `/catchup 指摘` | 移らない | 今の枝の PR が有れば | PR、無ければ手元 |
| commit | `2971ea2` `HEAD~2` `v1.2` `2971ea2..HEAD` | 移らない | 見ない | その commit（範囲なら全部） |
| 会話の話題 | `新しく出たもの` `今の修正` | 移らない | 結び付いた番号だけ | 結び付く対象か、会話 |

| 旗 | 効き | 効く対象 |
|---|---|---|
| `--switch` | 該当の枝へ移る | 番号・URL・ブランチ名 |
| `--full` | 本文・発言の上限を外す | 全部 |
| `--frame <path>` | その 1 file の変更を上限なしで | PR・commit（手元は what-am-i-doing.py の `--frame`） |
| `--limit N` | その後の出来事の件数（既定 12） | PR・issue |
| `-R owner/repo` | リポジトリを指す | 番号 |
| `--me <login>` | 「私」を差し替える | PR・issue |
| `--render <材料> <欄>` | ページを描き、一覧（`index.html`）を組み直し、VS Code で開く。材料は `--out` が書いた JSON の path、欄は AI が書いた JSON の path | 全部（会話の話題は材料が `-`） |
| `--setup [--check]` | VS Code で見る準備（`--check` は確かめるだけ） | なし |

ページは `~/.cache/attention/catchup/<owner>-<repo>/<番号>.html`（役割分担）。節はこの順で、機械が材料の有る節だけを描く。焦点の語で絞ったときも見出し・いまの番・前回からは描き、後ろは絞った材料の節だけ（説明と図は `地図` のときだけ書く）:

| # | 節 | 中身 | 書くのは |
|---|---|---|---|
| 1 | 見出し | 件名・番号・状態・作者・規模・閉じる issue | 機械 |
| 2 | いまの番 | 番の札と立場、`headline`、`next`、止めているものの行 | 札と行は機械、文は AI |
| 3 | 前回から | 番の受け渡しの流れ（GitHub の PR の会話の流れの形）、`where`、`turn` | 流れは機械、文は AI |
| 4 | この PR がすること | `lead`、`figure`、`terms`（この節の語）、`explain`、`points`（変更点ごとに差分を開ける） | AI（差分は機械） |
| 5 | 指摘 | 人が入っている未解決スレッド（差分の抜粋・私と相手の最後の発言・前回から変わったか） | 機械 |
| 6 | CI | 赤ごとに、落ちた step のログの末尾 | 機械 |
| 7 | 変更 | 前回から（私の痕跡以降）と全体の差分 | 機械 |
| 8 | 手元 | 「ブランチ」の行と「手元のブランチ」の節 | 機械 |
| 9 | 見ていないもの | `unseen` と機械の申告 | 両方 |

対象ごとに描かれる節（○ 描く／△ 材料が有れば／– 描かない）:

| 対象 | いまの番 | 前回から | がすること | 指摘 | CI | 変更 | 手元 |
|---|---|---|---|---|---|---|---|
| PR | ○ | ○ | ○ | △ | △ | ○ | △ |
| issue | ○ | ○ | △ | – | – | – | △ |
| 枝に PR 無し | ○ | ○ | △ | – | – | △ | ○ |
| commit | ○ | ○ | △ | – | – | ○ | – |
| 会話の話題 | ○ | ○ | – | – | – | – | – |

会話の話題が番号・枝・commit に結び付いていれば、この表の**その対象の行**（受け口で先に解く）。話題の行は、会話にしか無いものだけ。

上限と、続きを出す口（材料の上限。ページの差分は全部載る）。「切れた」は機械が数で言う——「N 行で切った」「上限 N 件」「古い方 N 件」「本文の残り N 行」。切れていればその口で取ってから書き、取ったものは見ていないものに書かない（もう見ている）:

| 何 | 上限 | 続き |
|---|---|---|
| 作者の本文 | 60 行 | `--full` / `gh pr view` |
| 閉じる issue・参照先の冒頭 | 12 行 | `--full` / `gh issue view` |
| 閉じる issue・参照先の件数 | 3 件ずつ | `--full` |
| 相手の発言（スレッド） | 40 行 | `--full` |
| その後の出来事 | 12 件 | `--limit` |
| 指摘（スレッド）の件数 | 10 件 | `--full` |
| CI の赤の件数 | 3 件 | `--full` |
| 取った commit | 100 本 | 見ていないものに書く |

## PR でないとき


- **枝に PR 無し**（未コミット・push していない commit・既定ブランチより先の commit のどれかが有るとき。どれも無ければ受け口の推定か聞き返し）: `headline` は「今のブランチ main に PR は無く、名前にも番号が無い」。`turn` は「GitHub 側は見ていない」と断って、手元の事実（未コミット・push していない commit・PR が無いこと）。`next` は手元から決まる一手（push する・PR を立てる・書きかけを続ける）
- **commit**: 作者が私かは機械の名前でなく `git show -s --format=%ae <sha>` と `git config user.email` の一致で決める（違えば作者の名前で）。枝は `HEAD~n` なら今の枝、sha なら `git branch --contains <sha>` を 1 回。`headline` は「2971ea2 は 9/6 に私が作った commit で、いま居る枝 main に入っている（PR を経たかは見ていない）。動かすものは無い」——「済み」とは言わない。`where` に手元の 1 文は書かない（枝の名前が無い）。`turn` は「GitHub 側も手元の未コミットも見ていない」と断り、止めているものは無いと書く。`next` は「PR が有るなら番号で呼び直す」「前後を読むなら HEAD / HEAD~n で呼ぶ」「手元は引数なしで呼ぶ」。範囲 `A..B` は「e824033 から b27cb3d までの commit 4 件は 9/6 に私が main に入れた」と、機械の見出しの括弧（含まれる両端）で言い切る（A は範囲の外なので 4 件の 1 つとして書かない）
- **会話から推定した番号**: `headline` の直後に「今のブランチ main には PR も名前の番号も無く、会話に出ていた #N を出している」を 1 文。手元の 1 文は、最初の `this` の手元の節から書く（絶対名。その枝に移していないことも）

## 会話の話題

受け口で番号・枝・commit に解けた話題はここではない（その対象の形で全部出す）。会話の中にしか無い話題（レビューで見つけた指摘の束・検討中の案）は、材料を `-` にして描く: `catchup.py --render - <欄の JSON>`（欄の JSON は一時の階層に置く。置き場は `~/.cache/attention/catchup/topics/` で、`title` ごとに 1 枚）。欄は同じで、`title` に話題の名前（読む人の語）を足す。`headline` は「「新しく出たもの」は #1505 の再レビューで私が見つけた suggest 4 件で、まだ PR には書いていない」のように**話題が何かを言い切る**。材料は会話そのもので、要約で前半が消えていれば `what-am-i-doing.py --topic` の往復で補う。結び付いた番号があれば、その番号の機械の出力で「PR に書いたか・相手が動いたか」を確かめる。会話に無いことは書かず、会話の中で確かめていないことは「（未確認）」。引数なしから会話で番号を推定したときは違う（受け口——番号で呼ばれたときと同じ形）。

## 準備（`/catchup setup`）

ページは VS Code の Remote-SSH の窓で、拡張 Simple HTML Viewer が開く。準備は `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/catchup.py --setup` 1 本で、機械が次をする:

1. 生きている VS Code の窓を探す（`code --status` が通る socket）
2. 拡張が `~/.vscode-server/extensions` に無ければ `code --install-extension austin-spagnolo.simple-html-viewer` で入れる
3. `~/.vscode-server/data/Machine/settings.json` に 2 つを足す——`workbench.editorAssociations` の `"**/.cache/attention/**/*.html": "simpleHtmlViewer.preview"` と `"simpleHtmlViewer.autoRefresh": "onFileChange"`。他の key は消さず、書く前に同じ階層へ控え（`settings.json.bak-<日時>`）を置く。注記（`//`）の有る file は書き直さず、足す行を示す
4. 見本のページを描いて開く
5. したことと、まだ足りないものを並べる

`/catchup setup` と打たれたら、これを走らせて出力をそのまま返す。何も変えずに確かめるだけなら `--setup --check`。窓が繋がっていない（VS Code を閉じている）と拡張は入れられない——繋いでからもう一度と返す。
