## 結論

- 合否は否。札 1（世の中の普通の作りは、LLM が聞く専用のツールを呼び、その中で止める）は、2 回目でも拾えなかった。重い版も外していた。

## 札ごとの中身

採点は `attention/scripts/score-world.py`（返りの head が札の head と同じことも合の条件にした）。札の正規表現は緩い所がある（札 1 の text が「ツール」の 1 語でも当たる、札 3 の name の `mcp` が `fastmcp` にも当たる）。札は走らせた後に変えない決まりなので変えず、当たった行を目でも読んだ。

- **札 1**: 依存の LangGraph か assistant-ui の行で、作りの層（`architecture`）の物が 1 件も無かった。いちばん近いのは行 1 の deepagents の行（作りの層・`differs`。道具ごとの割り込み `interrupt_on` に任せる形）で、聞く専用のツールを LLM が呼ぶ形ではない。行 1 の差分を見ない目も「外部の道具: 問いを発する」から部品を分けた。
- **札 2**: 行 2 の LangGraph の行が「再開時はノードを先頭から再実行する」、fastmcp の行が「ツールは先頭から再実行され」と述べた。層が `implementation` か、判定が `same` だったので、機械の照合では外れた。
- **札 3**: 行 1 などの MCP・fastmcp・標準の行が、InputRequiredResult と elicitation の違いを `contract`・`differs` で述べた。

## そのほかの数

- 言い直し: 3 回で受け付けた。識別子の機械の当たり 1・手段の当たり 0・漏れの照合で差し戻した 7。
- 検索語の漏れ: 探す役の WebSearch 8 回のうち、対象の名前に当たったのは 2 回。当たった語は「cancelled」（PR の文の「waiting/answered/declined/cancelled」を、機械が名前の形として切り出した普通の英単語）だけで、リポジトリ名・パス・社内の部品名は出なかった。
- 抜き書き: 残った 39・落ちた 3・照合できなかった 4（上限越え 0・写し違え 0）。照合できなかった 4 件は 1 つの類で、取り直しの haiku がコマンドの末尾に「"」を足して許しの規則に当たらず、拒まれた分。比べ 72 件のうち、根拠が web の物は 33 件（45.8%）。
