# attention

並行作業から**戻る**ための道具。1 件の PR / issue について「前回自分が触ってから何が起きたか」を機械で取り切り、画面 1 つに収めて出す。

## 何を解く道具か

複数の作業を並行で回していると、1 件に戻ったときに失われているのは「何を変える PR か」ではない——それは本文に書いてある。失われているのは**会話のどこで自分が止まったか**の方で、これは GitHub の画面を上から読み直さないと復元できない。

だからこの道具の基準点は diff ではなく、**自分の最後の発言**である。本文コメント・レビュー・レビュースレッド・push を全部見て最も新しい自分の痕跡を探し、その後に起きたことだけを並べる。まだ一度も触っていない件では、自分に渡された時点（レビュー依頼・assign・メンション）まで基準点を落とす。

## 使い方

```
/catchup 1505
/catchup https://github.com/owner/repo/pull/1505
```

**番号だけを渡したときは、いま居るリポジトリを見る。** 別のリポジトリの件は、URL を渡すか `-R owner/repo` を足す。

スクリプトを直接叩いてもよい。

```
python3 scripts/catchup.py 1505 [-R owner/repo] [--full] [--limit 12] [--me <login>]
```

依存は `gh`（認証済み）と `python3` だけ。**「私」は `gh` の認証ユーザー。** `--me` は、それを別の人に差し替えて見たいときだけ渡す。

## 出力の形

実際に出るのはこれ（人名とリポジトリ名は伏せてある）。

```

見ていないもの:
  - GitHub の外（チャット・口頭・メール）でのやり取り
  - 本文と diff の中身。この道具は会話の位置だけを出す（差分は gh pr diff で見る）
  - 発言の全文。--full で出る
```

**戻るのに要るのは最初の 3 つだけ。** 1 行目の `● 私の番` で**自分が動かせるのか待ちなのか**、
「求められていること」で**相手が何を待っているのか**、「私が最後に置いた場所」で**自分がどこまで
言ったのか**が分かる。この例なら「指摘を出した → 相手が直して報告した → いま自分が見る番」まで
3 行で戻れる。残りは裏を取るための材料で、要るときだけ読めばよい。

**「求められていること」と「私が最後に置いた場所」を並べて出すのが要点。** 片方だけでは戻れない
——自分が何を言ったかを思い出しても、相手が今何を求めているかは分からないし、逆も同じ。

## この道具がしないこと

- **判定をしない。** 「次に何をすべきか」は読む人か `/catchup` の AI が決める。スクリプトは材料だけ出す
- **差分を要約しない。** 変更の中身が要るなら `gh pr diff` を見る。ここは会話の位置だけを扱う
- **全件の棚卸しをしない。** 「今どこに何が残っているか」を一度に見渡す手段は**同梱していない**。この道具は番号を 1 つ渡して呼ぶもので、その番号を決めるところは持っていない

## 先行例

手番を明示するという考え方は Gerrit と Google Critique の **Attention Set**（Critique は 2015 導入）が先行例で、「なぜ今あなたの番か」を 1 行で示す点まで同じ。この道具が足しているのは、その理由に加えて**依頼の中身と自分の最後の発言を並べる**ところで、一覧ではなく 1 件に絞ったときだけ意味を持つ。
