# attention

並行作業から**戻る**ための道具。**戻り方は 2 つあり、失われているものが違う。**

| コマンド | いつ使うか | 失われているもの |
|---|---|---|
| `/catchup <番号>` | 1 件の PR / issue に戻るとき | **会話のどこで自分が止まったか** |
| `/whatamidoing` | セッションを切り替えて戻ってきたとき | **このスレッドが何の作業だったか** |

## 何を解く道具か

複数の作業を並行で回していると、戻ったときに失われているのは「何を変える PR か」ではない——それは本文に書いてある。失われているのは**会話のどこで自分が止まったか**の方で、GitHub の画面を上から読み直さないと復元できない。

同じことがセッションにも起きる。ターミナルを何十個も開いていると、**そのタブが何の作業だったかが分からなくなる。** 毎回「これ何をしてたんだっけ」と聞き直すことになる。

どちらも、要るのは変更の中身ではなく**位置**である。

## `/catchup` — 1 件の PR / issue に戻る

### 使い方

```
/catchup 1505
/catchup https://github.com/owner/repo/pull/1505
```

**番号だけを渡したときは、いま居るリポジトリを見る。** 別のリポジトリの件は、URL を渡すか `-R owner/repo` を足す。

スクリプトを直接叩いてもよい。

```
python3 scripts/catchup.py 1505 [-R owner/repo] [--full] [--limit 12] [--me <login>]
```

依存は `gh`（認証済み）と `python3` だけ。**「私」は `gh` の認証ユーザー。** `--me` は、それを別の人に差し替えて見たいときだけ渡す。

### 出力の形

実際に出るのはこれ（人名とリポジトリ名は伏せてある）。

```
# #482 fix(api): 添付ファイルの取りこぼしを塞ぐ
  ● 私の番 — レビュー依頼が私に来ている
  PR open · 作者 hanako · 21 ファイル +328/-381
  https://github.com/example/app/pull/482

## 求められていること
  09-01 17:45  hanako の コメント
  ご指摘ありがとうございます。[block] 1 件と [suggest] 7 件すべてに対応し、e5096175 として push しました…

## 私が最後に置いた場所
  09-01 09:15  コメント
  レビュー結果です。eec214ad まで確認しました。[block] 1 件・[suggest] 7 件・軽微 6 件です…

## その後に起きたこと — 4 件
  09-01 17:44  hanako が push
      e5096175 レビュー指摘対応 — ローカル層の打ち消しと注入の絞り込み (+62/-12)
  09-01 17:45  hanako が コメント
      ご指摘ありがとうございます。[block] 1 件と [suggest] 7 件すべてに対応し…
  09-01 19:13  taro が スレッド config/values.yaml:195（解決済）
      確認しました。接尾辞を畳んだ位置で引く形ですね…
  09-01 19:38  hanako が push
      fbf466b9 review round 4 対応 — 検査の素通り 3 点を塞ぐ (+162/-48)

## いまの状態
  承認: まだ承認されていない（REVIEW_REQUIRED） ／ 取り込み: 衝突なし（MERGEABLE）
  CI: 全 pass（緑 72）
  未解決スレッド: 0 件（うち人が入っているもの 0 件）

## つながっている先
  参照    #470 本番を main へ追随させ、自動同期を再開する

見ていないもの:
  - GitHub の外（チャット・口頭・メール）でのやり取り
  - 本文と diff の中身。この道具は会話の位置だけを出す（差分は gh pr diff で見る）
  - 発言の全文。--full で出る
```

**戻るのに要るのは最初の 3 つだけ。** 1 行目の `● 私の番` で**自分が動かせるのか待ちなのか**、
「求められていること」で**相手が何を待っているのか**、「私が最後に置いた場所」で**自分がどこまで
言ったのか**が分かる。この例なら「指摘を出した → 相手が直して報告した → いま自分が見る番」まで
3 行で戻れる。残りは裏を取るための材料で、要るときだけ読めばよい。

**「求められていること」と「私が最後に置いた場所」を並べて出すのが要点。** 片方だけでは戻れない
——自分が何を言ったかを思い出しても、相手が今何を求めているかは分からないし、逆も同じ。

## `/whatamidoing` — いま居るセッションに戻る

### 使い方

```
/whatamidoing
```

スクリプトを直接叩いてもよい。`CLAUDE_CODE_SESSION_ID` から自分の記録を引くので、引数は要らない。

```
python3 scripts/whatamidoing.py [--full] [--limit 20]
```

### 出力の形

```
# このスレッド — PR残件確認
  /Users/me/src/app · ブランチ ci/1497-double-extension-yaml
  開始 09-01 19:22 · 最後の動き 09-01 20:30 · 依頼 14 件

## 頼まれてきたこと（依頼者の言葉のまま・古い順） — 14 件
  - 残件を教えて
  - それぞれ本当に私の残件があるのかPRの上から２つかくにんして
  - では横に、プラグインリポジトリがあるので、組み込みたいね。種類は新設な気がします。
  …

見ていないもの:
  - 私（AI）が何を返したか。ここに出るのは依頼者の発言だけ
  - 記録に残らないやり取り（別のセッション・チャット・口頭）
  - 題は序盤に付いたまま更新されない。古い可能性がある
```

**依頼者の発言をそのまま並べているのが要点。** 会話は長くなると要約されて前半が消えるが、
記録の側には全部残っている。要約を挟まないので、**何を頼まれてきたかが痩せない。**

**題（`aiTitle`）は当てにしない。** Claude Code が序盤に付けたまま更新しないので、話題が
移った後も古い題が出続ける（実測: 棚卸しからプラグイン作りへ移った後も「PR残件確認」のまま
だった）。判断の材料は依頼の並びの方である。

## この道具がしないこと

- **判定をしない。** 「次に何をすべきか」は読む人か `/catchup` の AI が決める。スクリプトは材料だけ出す
- **差分を要約しない。** 変更の中身が要るなら `gh pr diff` を見る。ここは会話の位置だけを扱う
- **全件の棚卸しをしない。** 「今どこに何が残っているか」を一度に見渡す手段は**同梱していない**。この道具は番号を 1 つ渡して呼ぶもので、その番号を決めるところは持っていない

## 先行例

手番を明示するという考え方は Gerrit と Google Critique の **Attention Set**（Critique は 2015 導入）が先行例で、「なぜ今あなたの番か」を 1 行で示す点まで同じ。この道具が足しているのは、その理由に加えて**依頼の中身と自分の最後の発言を並べる**ところで、一覧ではなく 1 件に絞ったときだけ意味を持つ。

- <https://www.gerritcodereview.com/design-docs/attention-set-use-cases.html>
