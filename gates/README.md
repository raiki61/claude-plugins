# gates — 門番フック集

外に出る操作を、検査が通るまで止める PreToolUse フックを配る。現在の門番は 2 本——coldread(通じやすさ)と destgate(宛先の許可制)。

版ごとの変更は [CHANGELOG.md](CHANGELOG.md) に在る。版の出し方（tag の名前と付ける commit・変更の記録を書き足す段）は [docs/releasing.md](../docs/releasing.md)（リポジトリのルート基準で、プラグインとして入れた実体には無い。clone か GitHub で見る: https://github.com/raiki61/claude-plugins）。

## coldread — 外部投稿の門番

gh で GitHub へ本文を投稿するコマンド(issue/PR のコメント・本文、release notes、gist 等)を
PreToolUse フックで捕まえ、**フック自身が
coldreader(文脈ゼロの読み手。別プロセスの headless Claude)を走らせて**本文を初見検査する。
理解を妨げる「詰まり」があれば、その指摘を deny 理由に載せて投稿を止める。
「疑問」(理解はできたが答えが本文に無いもの)は止めずに申し送る。

読み手が持つ文脈は投稿先で変える。既に在る PR/issue のスレッドへ付く返信・編集は、題・番号・
file と行・元の指摘・これまでの返信が同じ画面に見えている状態で読まれるので、**フックが gh で
その画面を取り、読み手に既知として渡す**。新規作成(issue/PR/release/gist/discussion の create)は
読み手が何も持たないので文脈ゼロのまま。画面を渡さずに読ませると、@相手の名前・PR 番号・相手が
付けた印・相手自身の語まで詰まりに出て、書き手がそれを直すと宛先本人に本人の名前と自分の指摘の
意味を説明する返信になる(2026-09-06 に PR 1583 で実測: 1 本の返信が 39 回止まり、1,021 字 →
2,555 字に膨れて逃げ道で出た。短く戻した版も止まった)。画面に有るものを本文で説明している箇所は
「冗長」として止めずに申し送り、deny の直し方も返信では「足すより削る」になる。

画面は参加者が実際に見ているものまで渡す: 題・番号・状態(open/merged/draft)・本文の全文・変更ファイルの
一覧・これまでの返信(答える相手の直前のものは切らない)・本文とスレッドが参照する #番号 の題。
**画面が既知にするのは「何を指しているか」であって「どう書くか」ではない**——相手の言い回し・業界外の
横文字・比喩を本文が自分の地の文として使えば、画面に同じ語が有っても詰まり(相手の語を指して答えるのは既知)。
画面をスレッドの語彙の辞書にすると、スレッドの癖のある書き方に読み手が引っ張られ、本文がその癖を写す向きに
働く。写した箇所は「なぞり」として詰まりと同じく止める(直し方は説明を足すことではなく、自分の言葉に置き換える)。
詰まりの条件文に埋めた形は実物の読み手に 1 件も拾われなかったが、独立の欄として問うと 3 語とも拾い、引用して
指す返信は拾わなかった(2026-09-07 に北極星・ニアバイ・クロージングで実測)。2026-09-07 に PR 1429 で実測: 文脈ゼロの読み手(更新前に開始し 0.8.0 のまま走っていたセッション)が
「#1231 #1581 #1283 が何か」「9/2 の提案とは」を詰まりに出し、6 回の deny で 5,455 字 → 10,179 字
(用語集 19 語が全体の 25%)に膨れて逃げ道で出た。詰まりは全件、スレッドを見ていれば出ないものだった。

- 検査の実行を書き手の申告に頼らない——「検査した印だけ押して通す」穴が構造的に無い
- 検査するのは通じやすさだけ——出してよい投稿か・名義・宛先は見ていない。**通過を承認と
  読み違えるな**(通過・差し戻しの文言でも毎回言う)。宛先は下の destgate が縛る
- 再実行のたびに新しい coldreader が直した本文を読む——収束をフックが機械的に駆動する
- 逃げ道は `COLDREAD_SKIP=1` の 1 本(`$CLAUDE_CONFIG_DIR/coldread-gate/skip.log` に記録が残る)
- 網から落ちた疑いのある素通しは `misses.log` に残る——「投稿でなかった」と区別が付かないと、
  門番を締めたときにどれだけ裏口へ押し出したかを測れない。400 文字未満のコマンドの解析が落ちて本文ファイルを
  審査せずに通した回も、`parse-error` と種類(例外の型名か `unparseable`。値は書かない)の行で残る
- 400 文字未満の定型返信・読み取り系の gh コマンドには掛からない。ただし短いコマンドでも、本文旗のファイル
  (下の「網の射程」の本文ファイル)から読めた 200 字以上の本文だけは審査する——下限は「コマンドが短ければ本文も
  短い」を前提にした素通しで、本文がファイルから来ると成り立たないため。短いコマンドでは、読めない本文や止めた
  理由が同居しても止めない
- 審査の通過は権限の付与ではない: 400 文字未満のコマンドと、本文をファイルから読んだ投稿は、通過しても
  `permissionDecision` を出さない(人の権限の確認が残る。申し送りは `additionalContext` で返す)。本文がコマンドの
  字に在る 400 文字以上のコマンドの通過は、0.11 系と同じく `allow` を出す
- coldreader が起動できない環境でも投稿不能にはならない(deny + 逃げ道の案内)
- 画面を取れない(gh 無し・認証無し・オフライン)ときは文脈ゼロで読み、その旨を書き手に伝える(止めない)
- coldreader は利用者の CLAUDE.md と settings を読まない(`--setting-sources ""` で起動)。書き手向けの
  「初見でも分かるように書く」等の規則を読み手が自分の指示として持つと、識別子を全部詰まりに出す側へ
  寄る(2026-09-06 に実測: 素の起動では利用者の CLAUDE.md の見出しを引用した)
- 3 回連続で止まったら、案内を deny 理由の先頭に置き、1 回ごとの本文の字数の数列を示し、**最初の本文に
  戻してから**出せと言う。coldreader の指摘は読み手ごとに揺れる(2026-09-07 の試走: 3,693 字の実物の返信が
  3 回とも別の詰まり 1〜2 件で止まり、10,179 字版は 3 回中 1 回通った。揺れは画面の広さでは消えない)。
  揺れの中身は疑問(意味は取れたが根拠が欲しい)を詰まりに格上げする癖なので、依頼文で詰まりの線を
  「その箇所で意味が取れず読み進められない」に絞り「迷ったら疑問」と明記した(同じ返信が 4 回中 3 回通り、
  10,179 字版は 2/2。コンサル語・未解決の参照・文脈ゼロの未定義略語は止まったまま)(末尾に置いた案内は 36 回無視された。「今の本文を出す」の文言は膨れた版を出せと読めた)。
  連続は書き手(session)と投稿先の組で数える——log は profile で共有なので、並行セッションの deny を数えると
  1 回目の書き手に案内が出て、他所の skip が自分の案内を消す(2026-09-07 に実測)
- `denies.log` の各行に session・版・投稿先が付く(どの版のどのセッションがどこへ出したかを grep で引く)。
  本文を取り出せずに止めた行(`deny blocked`)には、止めた理由の語(`本文ファイルを読めない` 等を `,` で連結。
  値は書かない。語の一覧と意味は下の「網の射程」)も付く——どの形の止めが多いかを数えるため。
  cache に自分より新しい版が在れば検査結果に 1 行添える——フックの版はセッション開始時に固定され、
  長く開いたセッションは更新後も古い版で検査し続ける(16 時間 0.8.0 のままだった実測)

設定は環境変数(すべて任意): `COLDREAD_MODEL`(既定 sonnet)・`COLDREAD_EFFORT`(既定
medium)・`COLDREAD_MIN_LEN`(これ未満のコマンドは素通し。本文旗のファイルから読めた 200 字以上の本文だけは
審査する。既定 400)・`COLDREAD_MAX_LEN`
(これを超えるコマンドは解析せず止める。既定 100000)・`COLDREAD_KEYCHAIN_SERVICE`(macOS で
OAuth トークンを Keychain から読むときのサービス名)・`COLDREAD_READER_CMD`(coldreader の差し替え)・
`COLDREAD_GH_CMD`(画面を取る gh の差し替え。テスト用)。

## 網の射程(正直な限界)

判定は「本文を運ぶ旗が gh 自身の引数列にあるか」で行う(単純コマンド単位で帰属を見る。
方式の経緯と次段の PATH シム案は [docs/coldread-gate-next.md](../docs/coldread-gate-next.md))。
次は原理的に対象外・または内容を読まずに止める形で受容している:

- 旗を持たない投稿は対象外: `gh pr create --fill`(本文はコミットメッセージ由来)・エディタ起動(人が対話で書く)
- graphql は `mutation` キーワード検出——`-f query=@file` のようにクエリをファイルで渡す形は素通し
  (`--input file` の方は本文ファイルとして、下の条件を満たせば読み、満たさなければ止まる)。捕まえた mutation は本文を取り出さず必ず止める
  ——クエリ中のブロック文字列を本文として抜くと、`body:` 以外のフィールド(ID・トークン・設定値)まで
  coldreader へ渡るため。投稿するときは本文を `--body` 系の旗かヒアドキュメントに書き直す
- `gh` が文字列として渡る形は判定外: `xargs -I{} gh ...`・`sh -c "gh ..."`・`eval "gh ..."`・`env -S "gh ..."` の文字列の中の gh。
  ここだけは素通し(allow)に倒れる——`env`・`command`・`exec`・`nohup` の前置は判定内だが、
  `sudo`・`timeout` 等それ以外の前置は網に入らない。bash が命令として走らせる gh は、走査が写した構文の範囲で判定内:
  二重引用の中の `$(…)`・`` `…` ``、`${X:-$(…)}`、区切りを引用しないヒアドキュメントの中身の `$(…)`、
  プロセス置換 `<(…)`・`>(…)`、`${ …; }` の中の gh も見る。注釈の境(`$(…)` を閉じた直後の `#` は語の続き、`$(` の直後の
  `#` は注釈)・算術(`$[…]`・`$((…))`・`((…))` の中の `<<` はシフト)・行継続(行末の `\` と改行)を挟んだ `$` と `(`、
  `<` と `<`・引用した演算子の字(`--title ';'` の `;` は語)も bash と同じに読む。写していない構文は判定外で、bash と読みがずれうる:
  算術として読めない `$((…);…)`・入れ子の退避したバッククォート・`$'…'` の中の退避・区切りに置換を含む `<<$(E)`・
  命令の位置の `if`・`while`・`until`・`coproc` の直後の gh・GNU env の長い旗の略記・`gh $SUB …`・`gh "$@"` のように
  副命令の位置に置いた展開。置換の中の case で枝の型を括弧で囲まない形(`$(case x in x) …;; esac)`)は、読みを推さずに
  解析できないものとして止める(`(x)` と囲めば読む)
- `gh` の呼び出しと分かった後は、読めなかったものを素通しにしない: サブコマンドを特定できない
  (知らない global 旗が前にある)・本文が変数やコマンド置換で渡る・`--input` の JSON が
  `.body` 以外の場所に長い文字列を持つ・graphql の mutation から本文を取り出せない、はいずれも
  「検査できない」として止める。本文の値のどこかに `$` か `` ` `` による展開(`"前 $(cat x)"`・`"Hello $NAME"`・
  `x$Y`・`"$1"`・`"$[1+1]"` のように前後に字を伴う形も)が在れば止める——bash は展開してから gh に渡すので、
  字面は投稿される本文でない。展開は値ごとに見るので、同じコマンドの別の値の置換で `'costs 5$'` は止まらない。
  単一引用の中の `` ` `` や `$(`、名前や括弧の続かない `$`(`5$`・`US$ 5`)は展開されないので、本文の一部として
  読ませる(コードフェンスを含む普通の文章を止めないため)。引用しない語のパス名展開(`*` `?`)・チルダ・
  波括弧の展開は見ていない(本文はふつう引用して渡すため)
- コマンド置換のうち、二重引用の中の `"$(cat <<'EOF' … EOF)"`(置換の中が cat とヒアドキュメントだけ)は
  値が静的に決まるので、bash と同じ値(末尾の改行を落とす)として読む。前後に字が在っても、その字と連結した値を読む。
  `cat<<'EOF'` と空白が無くても、`2>/dev/null` のように fd 2 以上のリダイレクトが付いても読む。
  値は、旗や命令の意味を決める前に解く——gh は解いた後の字を読むので、`-F body="$(cat <<'EOF' … @/path … EOF)"` は
  ファイル(下の本文ファイルの条件で読むか止める)、値が `--body-file=…` や `gh` なら本文旗や gh の呼び出しとして見る。
  cat 以外のコマンド・パイプ・ファイルの cat・stdout の行き先の差し替え・引用の外の置換・
  バッククォートは止める。同じコマンドの中にシェルの状態(変数・関数・命令の探し先)を書かないと言えない形が
  在れば、cat が別物になりうるので置換の中の cat を静的と読まずに止める(止めた理由は「同じコマンドがシェルの状態を書く」)。
  書かないと言えるのは、子のプロセスで
  走る命令(`git`・`cat` など。前置の `NAME=値` はその命令にだけ効く)と、状態を書かない少数の組み込み(`cd`・`echo`・
  `printf`(`-v` なし)など。一覧の正本は coldread-gate.py の `PURE_SHELL_WORDS` で、bash の組み込みと予約語の 1 語ずつを
  tests/py/test_coldread_gate.py が縛る)と、`$NAME`・`${NAME}`・`$1` の形の展開だけ。ほかの組み込みと
  予約語(`set`・`read`・`export`・`for`・`if` など)・代入だけの命令・関数の定義・`(( ))`・`${X:=…}` や `$((…))` の
  形の展開が 1 つでも在れば止める。置換の値が命令名になってそれらの語になる形も同じ
- ヒアドキュメントは POSIX 2.7.4 どおりに読む: 開始行の続き(`<<'EOF' 2>&1 | tail -1`)はコマンドの
  続きとして読み、中身は次の行から終端行まで。区切りは bash が語として読むもの全部(`<<1X` も)。
  部分的な引用(`<<\EOF`・`<<E"OF"`)も区切りの引用になる。
  終端行は字のまま照合する(字下げした終端行は終端でない)。区切りを引用しない `<<EOF` では、行末の `\` で
  次の行と連結してから終端と照合する(`\` の行の次に区切りの語だけの行が来ても、そこでは終わらない。
  字のまま出すなら `\\` と退避するか区切りを引用する)。終端行が無ければ、bash と同じく入力の終わりまでを
  中身と読み、gh の stdin なら止める(止めた理由は「終端行の無いヒアドキュメント」。字下げした終端行や、
  後ろに空白の付いた終端行もこれになる)。
  区切りを引用しない `<<EOF` の中身は bash が展開するので、展開(`$NAME`・`$(…)`・`` `…` `` 等)を含めば止める
  (`<<'EOF'` と区切りを引用すれば、同じ本文を字のまま出せる)
- gh の stdin は、その単純コマンドの fd 0 への最後のリダイレクトで決める(bash は左から順に効かせる)。
  それがヒアドキュメントのときだけ読み、後ろの `< file`・`<<< "$X"`・`<&3` は止める(「ヒアドキュメント以外の stdin の
  リダイレクト」)。fd の番号は演算子に密着した数字だけ(`2>&1`)で、空白で離れた数字(`gh … --body-file - 123 <<'EOF'`)は引数。
  fd 0 へのリダイレクトが無くパイプの右に在るときは、左が `cat <<'EOF'` 1 本だけ(fd 0 と 1 をほかに差し替えず、
  その cat 自身はパイプの右に無い)ならその中身を読む: `cat <<'EOF' | gh … --body-file -`(パイプは末尾の改行を
  落とさない。POSIX 2.9.2)。左がほかの命令・`( … ) |`・2 段のパイプ・`|&`・シェルの状態を書く形の同居は
  「パイプからの stdin 渡し」で止める。同じ行に別の
  コマンドのヒアドキュメントがあっても gh の本文には混ぜない。位置引数の無い `gh gist create` は stdin を本文と
  して読むので、stdin がヒアドキュメントでなければ止める(パイプ・`< file`・`<<<`・囲む `( )` や `{ } < f`・
  `exec < f`・`done < f` のどれでも)。区切りが `;`・改行・`&&`・`||`・`( )` だけ(パイプも背景の `&` も無い)で、
  どの単純コマンドも fd 0 を差し替えないときは、gh の stdin はフックを起こした側から受け継いだままで本文が
  無いので何もしない(`cd x && gh gist create -d 説明` も。`gh gist create - <<'EOF' … EOF` と書けば読む)。
  同じ行のほかのコマンドが fd 0 を差し替えるだけ(`cat > f <<'EOF' … EOF` の後の `gh gist create -d 説明`)でも
  止める——囲む `{ } < f` との区別を数え上げないため。受け継いだかどうかを確かめられない stdin(置換の中の gh・
  囲む構文の外のリダイレクト)は「別プロセスからの stdin 渡し」で止める
- 本文ファイル(`--body-file`・`--notes-file`・`-F`・`-F body=@`・`--input`・gist の位置引数)は、次をすべて
  満たすときだけフックの時点で読み、ほかの本文と同じ審査(200 字の閾値・coldreader)に回す:
  パスに `$`・`` ` ``・グロブ・ブレース・先頭の `~` が無い。相対パスは payload の cwd を基準にし、同じコマンドに
  `cd` があれば絶対パスに限る。同じコマンドに並ぶのは `cd` と `cat` だけで、区切りは `;`・改行・`&&` だけ
  (ほかのコマンドはどのファイルを書くか分からない)。同じコマンドに命令を走らせる展開(`$(…)`・`` `…` ``・
  プロセス置換。値の決まる `"$(cat <<'EOF' … EOF)"` は除く)や、シェルの状態を書かないと言えない形(上の置換の箇条と同じ)が
  無い。そのファイルを書くリダイレクトが無い。通常のファイルで、
  大きさが上限内で、UTF-8 として読める。1 つのコマンドで読むファイルの合計も 1 ファイルの上限まで(同じファイルは
  1 度だけ開く)。前の `cat > パス <<'EOF'` 1 本だけがそのファイルを書くなら、読むのは
  ファイルでなくそのヒアドキュメントの値(書けないファイルなら読まずに止める)。満たさなければ、原因ごとの語で止める:
  「字のまま決まらないパス」(展開・グロブ・`~`・`cd` の後の相対パス)・「同じコマンドの別の命令がファイルを変えうる」
  (ほかの命令・順に走らない区切り・命令を走らせる展開・書き手)・「同じコマンドがシェルの状態を書く」・
  「本文ファイルを読めない」(無い・権限・読む間の書き換え)・「本文ファイルが通常のファイルでない」(ディレクトリ・FIFO)・
  「本文ファイルが上限より大きい」・「本文ファイルが UTF-8 でない」・「本文ファイルの合計が上限を超える」・
  「区切りを引用しないヒアドキュメントの展開」(書き手の中身)。ファイルを開かない destgate と表の検査では「実ファイル指定」になる。
  この読み方は、決着済みだった「本文ファイルの中身はフックで読まない」を持ち主が開き直したもので、決定と代償の
  記録は [docs/coldread-gate-next.md の「2026-10-02 の判断」](../docs/coldread-gate-next.md#2026-10-02-の判断)。
  代償(2026-10-02 に持ち主が受け入れた): ファイルの中身は、destgate が宛先を拒む場合や
  権限の確認で投稿が止まる場合にも coldreader(claude -p)へ送られ、詰まりの引用が会話に戻る。フックが
  読んだ後で gh が読むまでの間に別のプロセスがファイルを書き換える余地(CWE-367)は残る
- 変数で渡るパス(`$S/body.md`)・パイプ・変数で渡る本文は内容を読めないため「検査できない」として止める
  (fail-closed)。読める本文が同居していても止める
- 引用が閉じていない・写していない構文に当たる・解析が例外で落ちる・上限(既定 10 万字)を超えるコマンドも、投稿かどうか
  確かめられないので止める(fail-closed)。区切りを引用しないヒアドキュメントの中身の `$(…)` の中のヒアドキュメント…を
  8 段より深く重ねたコマンドも同じく止める(段ごとに中身を読み直すので、深さを縛らないと重さが長さの 2 乗になる)。上限の判定より前に効く逃げ道は、コマンドの先頭に置いた
  `COLDREAD_SKIP=1` だけ——`cd x &&` の後などに置いた逃げ道は解析しないと見つからないので、上限を超える
  コマンドでは効かない(解析を上限と例外の柵の内側でだけ走らせるため)
- 本文を取り出せても 200 字未満なら coldreader に渡さず通す(コマンド長の下限 400 字とは別の閾値。
  短い定型の返信で coldreader を起こさないため)
- 1 つのコマンドが複数の本文を運ぶときは、最長の 1 本だけを coldreader に渡す
- 旗の綴りは文脈で意味が変わるので、長い旗(`--body`・`--notes`・`--comment`・`--readme`・
  `--body-file`・`--notes-file`)は綴りだけで本文と見なし、短縮形(`-b`・`-c`・`-n`・`-F`)は本文を意味する
  サブコマンドの中でだけ本文と見る(gh 2.96.0 の全サブコマンドを走査して決めた)。
  よって `gh pr checkout -b <ブランチ名>`・`gh issue view -c`・`gh run download -n` 等は
  投稿ではないので網に入らない。逆に、gh が投稿サブコマンドを増やしても長い旗で書かれていれば
  網に入る。短縮形しか使われない新サブコマンドは取りこぼす
- フックの起動行は POSIX シェル(bash)で評価される前提で書いてある(`command -v` と `$(...)` で
  `python3`/`python` を選ぶ)。bash が無い環境では本体がフック自体を起動できないので、
  起動行の書き方に関わらず門番は動かない
- 画面を渡すのは投稿先が既に在るスレッドのときだけ: `gh api` の path が
  `repos/o/r/pulls/N/comments/ID/replies`(PR 番号無しの形も)・`repos/o/r/pulls/comments/ID`・`repos/o/r/pulls/N/comments`・
  `repos/o/r/pulls/N/reviews`・`repos/o/r/issues/N/comments`・`repos/o/r/issues/comments/ID`・
  `repos/o/r/(issues|pulls)/N` のとき、または `gh pr comment/review/close/reopen/merge/revert/edit`・
  `gh issue comment/close/reopen/edit`(番号・URL・ブランチの解決は gh 自身に任せる。番号を省いた
  `gh pr comment` は今のブランチの PR)。review スレッドは同じ根に連なる返信だけを渡し、PR/issue の
  会話は本文(12,000 字まで)と直近 30 件(一覧は 100 件ずつ最大 5 ページ。全体 40,000 字を超えたら古いものから
  落とし、答える相手の直前の 1 件は切らない)。本文とスレッドが参照する #番号 の題は 8 件まで。画面取得の gh 呼び出しは合計 40 秒で
  打ち切り、文脈ゼロへ倒す(フック自体が時間切れになると投稿が無検査で通るため)。`gh discussion` は
  画面を取らない(文脈ゼロ)
- 値が本文でないものは coldreader(外部プロセス)へ送らない: `gh secret set --body`・
  `gh variable set --body`(値は秘密そのもの)、`gh api --input` の JSON(`.body` を持つときだけ
  その中身を読ませ、持たない JSON は送らない)

リポジトリ全体の文書の初読検査は convergence-loops の `/firstread-loop`(重い姉)。
こちらは単体で読まれる短文向けの軽い妹で、フックなので呼ばなくても効く。

## destgate — 投稿先の許可制(既定で眠る)

coldread とは別の軸「その宛先へ出してよいか」を縛る 2 本目の門番。判定は決定的(LLM なし)。

- `$CLAUDE_CONFIG_DIR/destgate/allowlist` が無ければ何もしない。作ると有効になる
- 書式は 1 行 1 パターン: `owner/repo`・`owner/*`・`gist`(# 始まりと空行は無視)
- 宛先の決め方は gh 自身の解決順に合わせる: `-R/--repo` → `gh api` の
  `repos/{owner}/{repo}`・`orgs/{org}` パス → どちらも無ければ `GH_REPO` → git の remote(`gh repo set-default` が
  在ればそれ。値が `base` でなく `owner/repo` の字ならその repo。無ければ remote の全部——gh は upstream を origin より
  先に見る優先順で選ぶので、どれになっても許可一覧に当たる必要がある)。
  `-R` を 2 つ以上書けば gh は最後の値を使うので、どれも許可一覧に当たる必要がある。`-R` の読みは coldread と同じ旗の表で、
  ほかの旗の値の位置(`-H -R…`・`--body -R` の `-R`)と `--` より後ろは読まない(`gh pr review` の `--comment` は値を
  取らない)。サブコマンドより前に知らない旗があれば、宛先が api のパスか `-R` かも決まらないので止める。
  特定できない投稿は `-R` の明示を求めて止める
- `GH_REPO` は、フックの環境の値と、コマンドの中で字のまま書いた値(gh の前置の `GH_REPO=owner/repo`・
  `env GH_REPO=…`・`export GH_REPO=…`・代入だけの命令)で照らす。書いた位置と `export` の有無は推さず、なりうるものの
  和で照らす(`unset GH_REPO`・`env -u GH_REPO`・`env -i` が在れば remote も)。値を字から読めない形(展開を含む値・
  `read`・`for`・`printf -v`・`declare -n`・`eval` などの引数の `GH_REPO`・`${GH_REPO:=…}`・`env -S` の前置)は
  特定できない宛先として止める。`echo`・`test` など変数を書かない語と、子のプロセスの引数(`git commit -m 'GH_REPO …'`)の
  字は数えない
- `cd`・`pushd`・`env -C` で移る投稿は、移る前のディレクトリと、コマンドの中の行き先の全部の remote の和で照らす
  (書いた位置は推さない)。行き先は絶対パス・`~`・`~/…`・ほかに移動が無いときの cwd からの相対パスで読み、展開・
  `cd -`・`~user`・移動を重ねた相対パスは特定できない宛先として止める
- 宛先は bash が gh に渡す字で照らす: 値の決まる `"$(cat <<'EOF' … EOF)"` は値に解いてから読み、解けない展開
  (`$…`・`` `…` ``・`$(…)`)や GitHub の名前に入らない字(英数字と `.` `-` `_` 以外)を含む `-R` の値・api のパスは
  特定できない宛先として止める——展開前の字を許可一覧に照らすと、展開した後の別の宛先へ投稿する。
  宛先を字のまま書いた投稿(`-R owner/repo`)は止まらない
- `gh api` のパスの `{owner}`・`{repo}` は gh 自身が今のリポジトリで置き換える。上の `GH_REPO` と remote の候補で
  置き換えて照らす。remote が読めなければ、置き換えの前の字 `{owner}/{repo}` のまま照らす(`*` の一覧なら通る)
- **逃げ道は無い**。通したければ人が一覧へ追記する——その追記が記録になる。
  `COLDREAD_SKIP=1`(通じやすさ検査の逃げ道)ではこの門番は外れない(別フックで動く)
- **一覧の管理は人の仕事**。deny を受けたモデルが一覧を自分で編集して通すのは門番の無効化で、
  deny 文言でも禁じている(機械では強制できないので、規約として明示する)
- 射程: 許可一覧が有効なら、gh の綴りを含むのに解析できないコマンドも止める——解析できない形には bash が走らせる形
  (置換の中の括弧で囲まない case の枝・深い入れ子)も在り、coldread は短いコマンドと逃げ道付きのコマンドを通すため。
  見るのは本文を運ぶ投稿(coldread が本文の候補か止めた理由を積む gh)だけで、本文旗の無い投稿(`gh pr create --fill`・
  本文の無い `gh pr merge` や review)の宛先は見ない。宛先の材料はフックの時点の git の remote と set-default・フックの
  環境の `GH_REPO` で、同じコマンドの中で書き換える形(`git remote add`・`git config`・`gh repo set-default` を前に置く・
  `GIT_DIR=` などの前置)と、`source` や `.` で読み込むファイルの中身、Bash の道具が読む rc の `GH_REPO` は判定外。
  解析の重さに上限は持たない(フックの timeout は投稿を止めない)。gh・ファイル・書き手・語・展開・行継続で割った数字を
  並べた形で、走査の手数と内側の判定の回数が長さに比例することを tests/py/test_coldread_gate.py が呼び出しの回数で縛る
  (字の写しの量は数えない。語と数字は部品を集めて 1 回で連結する作りで長さに比例させている)
