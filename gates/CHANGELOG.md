# 変更の記録（gates）

gates の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版の出し方（この記録を書き足す段。git の tag は作らない）は、リポジトリのルートの `docs/releasing.md` に在る（プラグインとして入れた実体には無いので、clone か GitHub で見る: https://github.com/raiki61/claude-plugins/blob/main/docs/releasing.md）。gates の 0.1.0 の前は、coldread という名前の plugin（coldread 0.1.0）だった。

## [Unreleased]

### Fixed

- 初見読みの「入っている版は X」の注記が、別のプロジェクトにだけ入れた版（`installed_plugins.json` の scope が project・local で、projectPath が今のプロジェクトでない行）も数えていた。今のプロジェクトに効く行（user の行と、projectPath が今の作業フォルダ・その git の作業ツリー・linked worktree の主の作業ツリー・CLAUDE_PROJECT_DIR に当たる project・local の行）だけを見て、狭い scope（local・project・user の順）の行の版で決める。狭い行の場所が無いか消す印が付いていれば、広い行の版には倒さずに注記を出さない。

## [0.36.1] - 2026-10-19

### Fixed

- 手元の文書のゲート（会話で書いた文書を、ターンの終わりにフックで初見の読み手に読ませる仕組み。止めずに指摘を返す）は、役（親の会話か、サブエージェント）が書いた文書の待ちの一覧（`docs/<session>.pending`。まだ読んでいない文書のパスの並び）を、読む前に消さず、`<一覧>.<pid>-<時刻>.reading`（読みかけ）に名前を替えて取り、読み終えてから消す。前は読む前に一覧を消し、中身を読んだ物として覚えていたので、読みの途中でフックが切られる（Stop の timeout・会話を閉じたときにバックグラウンドの読みが止められる）と、その文書は読まれないままになった。切られて残った古い読みかけは、同じ役が次にターンを終えたとき（Stop・SubagentStop のフック）に取り戻す。古い読みかけに在る文書のパスを、今回の読みかけへ移して古い読みかけを消し、切られた読みが読んだ物として覚えた中身を忘れて、それらの文書を今回の読みでもう一度読む（960 秒〔フックの timeout の 900 秒に余裕を足した長さ〕より古い物だけ。まだ読んでいる物には触らない）。返す詰まりが無く読み終えた文書は、読みかけに `#done` の行で印を付け、切られても読み直さない。
- 手元の文書のゲートが 1 回のターンの終わりに読む文書は 8 本まで（4 本ずつ並べて、読み手の上限 420 秒で 2 巡。フックの timeout の 900 秒に収まる数）。残りは待ちの一覧に戻し、書いた役に残りの本数を知らせて、次の終わりに読む。上限を掛けないのは、対話でなく 1 回の頼みを流して終わる形（`claude -p`）で起動した会話の、親の会話のターンの終わりだけで、そこでは全部を読む（この会話はこのターンの後に終わるので、残りを読む次の終わりが来ない）。前は上限が無く、多く書いた役の読みが timeout で切られ、切られた読みを次の終わりに全部読み直してまた切られることがありえた。
- 書いた会話が終わったまま、最後に書き換えてから 1 日より古い待ちの一覧と読みかけは、親の会話（サブエージェントでない会話）のターンの終わりに 1 度だけ、会話と持ち主の画面に、パスと読み方・消し方を添えて知らせる。前は誰にも知らされずに残った（2026-10-18 に、ある会話の一覧に 38 本が読まれずに残っていた）。
- 入っている版と違う版のフックで検査したときの注記を、モデルへの理由と文脈だけでなく、持ち主の画面（フックの出力の `systemMessage`）にも出す。入っている版は、cache のフォルダの名前の版の大小でなく、Claude Code の `installed_plugins.json` の `installPath` で決め、消す印 `.orphaned_at` の付いた場所は数えない。前は注記がモデルにしか届かず、古い版（0.25.0・0.31.0）の会話が開いたまま検査し続けた。
- `denies.log`・`docs.log` などの記録は、2 MB を超えたら `<名前>.1` に替えて新しく書き始める（前の `.1` は消える）。投稿のゲートが同じ会話から同じ宛先への同じ投稿（gh で issue や PR に書き込むコマンド）を続けて止めた回数は、`denies.log` の全体でなく末尾の 400 行だけを読んで数える（Windows で書いた記録の行末の `\r` も外して読む）。前は記録が上限なしに育ち、投稿のたびに全体を読んでいた。

## [0.36.0] - 2026-10-19

### Changed

- coldread の読み手（`claude -p`）を `--output-format json --json-schema` で起動し、答えの `structured_output` の指摘の一覧（種類のキー `stuck`・`echo`・`question`・`guess`・`redundant`、原因のキー `word`・`referent`・`flow`、前の回の印 `carried`）を読む。前は答えの文から「詰まり:」などの日本語の見出しと「なし」の語を拾い、答えのどこかに CLEAN があれば形が合ったとしていた。決めた形でない答え（JSON でない・`is_error`・知らない種類・空の text）は指摘ゼロと読まずに止める。メインブランチの版と比べる係の答え（OLD/NEW の行）と、ブランチのゲートの打ち直しで前の回の詰まりを問い直す係の答え（STILL/FIXED の行。0.34.0）も、`old`・`new` と `still`・`fixed` のキーの JSON にした。止める理由に出す日本語のラベル（詰まり・なぞり・疑問・補完・冗長）は変えていない。読み手が詰まりの text を書き出してから終わりで自分で取り消した物（「…意味は取れる。詰まりなし。」など）を、止めずに疑問に回すのは、今までどおり（0.33.1 で足した動き）。
- destgate は、`-R` の無い投稿の宛先を `origin` の URL でなく `gh repo view --json nameWithOwner`（gh が投稿する先と同じ解き方）で引く。gh が `gh repo set-default` の印やほかの remote を選ぶとき、前は gh が投稿する先と違う repo を許可一覧と比べていた。`-R` の旗の読み方は coldread と同じ 1 本にした。

### Fixed

- coldread と destgate は、フックの入力（JSON）を読めないとき、コマンドを通さずに止める。前は coldread が allow し、destgate は例外のまま素通しにしていた。destgate は、許可一覧が在るとき、解析できない gh のコマンドも止める（前は coldread に任せて通していた）。
- 手元の文書のゲート（Claude Code の会話で書いた文書を、フックで初見の読み手に読ませる仕組み）とブランチのゲート（`branch-check`）は、状態の記録（回の記録・帳面・読んだ中身の一覧・覚えた結果）を読み書きできないとき、黙らずに標準エラーに出す。帳面と読んだ中身の一覧は、ロックの中で読み書きする（並ぶ役のフックが足した行を、書き直しで消さない）。ブランチのゲートは、UTF-8 で開けない文書を数えずに飛ばさず、終了コード 1 で止める。
- 投稿のゲートは、読み手に渡す画面（投稿先の issue や PR のスレッドの中身。状態・本文・コメント・本文が参照する番号の題）を gh で取る。コメントが 500 件を超えて取り切れなかったときと、参照している番号の題を取れなかったときは、そのことを画面の中に書いて読み手に知らせる（前は黙って落としていた）。
- destgate は、`cd <別のリポジトリ> && gh …` の投稿を、移った先の repo を宛先として比べる（前はフックの cwd の repo と比べて通していた）。移った先を読み切れない形（相対パスの cd など）と、コマンドが環境変数 `GH_REPO` を書いている形は、`-R` の無い投稿を宛先不明で止める。`-R` の無い投稿の宛先を引く時間は合わせて 20 秒までにし、引き切れなければ止める（フックの時間切れ〔30 秒〕で検査なしに通らないように）。
- 帳面のロックを取れないとき（Windows で待ちきれなかったときなど）に、フックが例外で落ちず、標準エラーに出してロック無しで続ける。

## [0.35.0] - 2026-10-19

### Added

- 共有の認証の部品 `hooks/claude_auth.py`（ルートの scripts/claude_auth.py の写し。プラグインが別の claude を `claude -p` で起動するときに、その claude に認証を足す部品）に、関数を 2 つ足した。足したのは、トークンが切れたときに、起動した claude が黙って失敗し、起動した側がそれを「済んだ」と数えるのを防ぐため。この版では呼ぶ所が無く、利用者から見た動きは変わらない。呼ぶ所は、claude を起動する処理を持つプラグインの担当が後の版で足す。
  - `expiry_note(項目の名前)`: 利用者が Keychain（macOS の資格情報の保管庫）に自分で入れたトークンが、入れた日から 335 日を過ぎていれば、作り直しを促す 1 行を返す。過ぎていなければ None。このトークンは `claude setup-token`（CI などで使う長持ちのトークンを作る Claude Code のコマンド）で作る物で、寿命は 1 年。
  - `auth_failed(出力)`: 起動した claude の標準出力が認証の失敗の形なら真を返す。真になるのは 2 つ: 300 バイト以下の 1 行で JSON として読めない文と、JSON の結果のうち `is_error`（失敗の印）が真で `result`（返答の文）に authenticate か /login を含む物。複数行の文・300 バイトを超える文・失敗でない JSON は偽。認証の切れた claude は、この形の文を出して終了の値 0 で終わり、終了の値では見分けられないため。

## [0.34.0] - 2026-10-19

### Changed

- ブランチのゲート（`branch-check` と `--land`）は、同じブランチで打ち直したとき、前の回に読み終えた版から変えたセクションだけを新しく読み、字の変わらない文書は読み直さない（スキルの別ファイルは、前提の `SKILL.md` だけが変わったときも読み直さない）。前の回に止めた詰まりは、文書の字か前提が変わったときだけ、今の版の全体と前提と一緒に同じモデルの読み手へ渡し、同じ箇所で同じ理由でまだ詰まるか（STILL）、直ったか（FIXED）を答えさせる。ただし、詰まりの行の中で、読み手がかぎ括弧（「 と 」）に入れて文書から引き写した文が、その詰まりを出した版に字のとおり全部在り、今の版から全部消えたときは、問い直さずにその詰まりを外す（引き写した文が在ったセクションは書き換えたので、今回新しく読んでいる）（2026-10-19 に、引いた文を書き換えて直した詰まりにも問い直しが STILL と答え、直した詰まりで止まった）。STILL の詰まりは今までどおり止め、答えが迷ったときと問えなかったときも止める。FIXED の詰まりは止めない。字も前提も変わらなければ問い直さずに止める（問うたびに、読み手の揺れで直していない詰まりが通りうる）。メインブランチの版と比べる（メインブランチの版でも同じ所で詰まるなら止めない）のは、その回に読んで出た詰まりだけにする。前の回の版と判定は、ブランチと文書ごとに `$CLAUDE_CONFIG_DIR/coldread-gate/docs/branch-last/` に覚える（新しい 2,000 件を残す）。読み手を起動できなかった回と、問い直しかメインブランチの版との比べを問えなかった回は覚えない。読み手への依頼文・モデル・effort（読み手の推論の強さの設定）が替われば（gates の版を上げたときなど）覚えた版を使わない。`--land` はブランチに居ない一時の作業場（ブランチの頭に版上げの commit を足した所）でゲートを回すので、そこでは、最新の commit が HEAD の履歴に在り、しかもメインブランチとの分かれ目（ブランチがメインブランチから分かれた commit）より後に在る手元のブランチを探す（メインブランチなど、最新の commit が分かれ目かそれより前に在るブランチは当たらない）。一時の作業場は main に入れるブランチに版上げの commit を足した物なので、ふつうはそのブランチ 1 本だけが当たり、そのブランチの前の回を使う。そういうブランチが 0 本か 2 本以上なら前の回を使わず、今までどおり分かれ目から読む。1 行直すたびに同じ抜き出しの直していない段落まで読み手が読み直し、読み手は回ごとに拾う所が替わるので、手を付けていない段落から新しい詰まりが出て、直しが収まらなかった（2026-10-19、このリポジトリの works プラグインのスキルの分けで `--land` を 4 回打ち、詰まり 10 → 2 → 約 10 → 7 件）ため。引き換えに、ほかのセクションや前提の `SKILL.md` を変えたせいで分かりにくくなった文（`SKILL.md` から語の説明を消したなど）は、その文のセクションを変えるまでブランチのゲートでは拾わない。消したブランチと同じ名前で作り直したブランチは、消したブランチの前の回を引き継ぐ。

## [0.33.1] - 2026-10-19

### Fixed

- 初見読み（文脈を持たない読み手に文書や投稿を読ませ、読み進められなかった所を「詰まり」として返させる検査）で、読み手が「詰まり: 」と書き出してから同じ行の終わりで自分で取り消した行を、詰まりに数えず疑問に回す。例は「…説明されているので意味は取れる。詰まりなし。」「…推測可能。詰まりとしては扱わない。」で、「なぞり: 」（相手の言い回しを写した所の指摘）の行も同じに扱う。2026-10-19 に、ブランチのゲート（`branch-check` と `--land`）の読み手が詰まり 4 件のうち 3 件をこの形で出し、`--land` が止まったため。
- 取り消しと見るのは、行の最後の文の全体が取り消しの形（頭に「ここは」「ただし」程度、終わりに「として扱う」「です」程度だけを許す）のときだけ。「見出し「詰まりなし」の意味が取れない」のように語を引いた本物の詰まりは、今までどおり止める。回した行は「(読み手が取り消した詰まり)」を付けた疑問として、投稿のゲートとブランチのゲートの知らせに出る（ターンの終わりの文書の読みは、疑問だけなら今までどおり知らせない）。
- 読み手への依頼文に、書いている途中で意味が取れたら詰まりの行のまま取り消さず、疑問か補完として書く、と足した。

## [0.33.0] - 2026-10-19

### Changed

- 文書の初見読み（ターンの終わりの読み・ブランチのゲート `branch-check`・`read`）は、スキルのフォルダ（`skills/<名前>/` で `SKILL.md` の在るフォルダ）の文書を読むとき、AI がその文書より先に読む物を補足として添える。別ファイル（`references/*.md` など）には同じスキルの `SKILL.md` を前提として添え、読み手は `SKILL.md` で説明している語を分かっているものとして本文についてだけ報告する。`SKILL.md` には指した先の中身を添えず、本文がパスで指す同じフォルダのファイルの名前と、それは指す場面で開く物なので中身が無いことは詰まりにしない旨を添える（いつ開くか・何が入っているかが分からない指し方と、`SKILL.md` の中だけで取れない語は今までどおり詰まりにする）。スキルのフォルダの外の文書（この CHANGELOG など）には何も添えず、これまでどおり本文だけを読む。スキルの本文を標準に合わせて別ファイルに分けると、1 本ずつ読ませた読み手が本文の語や指した先の中身が無いと詰まり、直すたびに別の所で詰まって `--land` が止まった（attention の 3 本の分けで 7 → 19 件）ため。

## [0.1.1] - 2026-08-28

### Fixed

- Windows で日本語の deny の文言を出すときに文字コードのエラーで落ちていた。

## [0.1.0] - 2026-08-28

### Added

- gh の issue・PR への投稿を PreToolUse フックで捕まえ、別プロセスの claude（文脈を持たない読み手）に本文を初見で読ませる門番。詰まりが有れば指摘を付けて止め、疑問だけなら通して申し送る。
- 検査を飛ばす逃げ道 COLDREAD_SKIP=1（使うと記録が残る）。3 回連続で止まると、採否の判断と skip を案内する。読み手が故障したときは止める側に倒す。

### Changed

- plugin の名前を coldread から gates に変えた（skill の /coldread は gates の中に残る）。
