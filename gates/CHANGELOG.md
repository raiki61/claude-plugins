# 変更の記録（gates）

gates の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版を名指しする git の tag（例: `gates--v0.11.3`）の名前の決まり・付け方・付ける commit の一覧への案内と、この記録を書き足す段は、リポジトリのルートの `docs/releasing.md` に在る（プラグインとして入れた実体には無いので、clone か GitHub で見る: https://github.com/raiki61/claude-plugins/blob/main/docs/releasing.md）。gates の 0.1.0 の前は、coldread という名前の plugin（coldread 0.1.0）だった。その版には gates の tag は付かない。

## [Unreleased]

### Changed

- リテラルのパスの通常のファイルで渡す本文(`--body-file /path`・`-F body=@/path`・`--input /path`・gist の位置引数)を、フックの時点で読んで審査する。読む条件と、持ち主が受け入れた代償(宛先や権限で投稿が止まる場合にも中身が coldreader へ送られること、読んだ後の書き換えの余地)は README の「網の射程」に在る。変数で渡るパスは今までどおり止める。
- `cat > パス <<'EOF' … EOF` の後に同じパスを gh が読む形は、そのヒアドキュメントの値を本文として審査する。
- denies.log の `deny blocked` の行に、止めた理由の語を `,` で連結して残す(理由の語は「・」を含むので、「・」で連結すると数えられない)。
- 本文を取り出せずに止めたときの案内に、受け付ける形(`--body "$(cat <<'EOF' … EOF)"`・`gh gist create - <<'EOF'` など)と、区切りを引用すれば本文が字のまま出ること、引用しない `<<EOF` で行末の `\` を `\\` と退避することを書く。
- コマンド長の下限(400 字)より短いコマンドでも、本文旗のファイルから読めた 200 字以上の本文は審査する。短いコマンドの読めない本文や止めた理由は、今までどおり止めない。
- 上限(10 万字)の判定より前に効く逃げ道は、先頭に置いた `COLDREAD_SKIP=1` だけにした。`cd x &&` の後などに置いた逃げ道は、上限を超えるコマンドでは効かない。
- 本文を取り出せずに止めた理由の語を、原因ごとに分けた: `パイプからの stdin 渡し`・`ヒアドキュメント以外の stdin のリダイレクト`・`終端行の無いヒアドキュメント`・`字のまま決まらないパス`・`同じコマンドの別の命令がファイルを変えうる`・`同じコマンドがシェルの状態を書く`・`区切りを引用しないヒアドキュメントの展開`・`本文ファイルを読めない`・`本文ファイルが通常のファイルでない`・`本文ファイルが上限より大きい`・`本文ファイルが UTF-8 でない`・`本文ファイルの合計が上限を超える`。今まではファイルの止めがすべて `実ファイル指定`、置換の止めが `変数・コマンド置換渡し` になり、案内どおりに直せなかった。止める・通すの判断は変わらない。止めたときの案内に、パイプは `cat <<'EOF'` 1 本から gh 1 本へつなぐこと・終端行を字下げしないこと・`set` や `export` などを同じコマンドに並べないこと・本文ファイルは UTF-8 で上限以内の通常のファイルにすることを足した。
- 審査を通った投稿のうち、400 字未満のコマンドと、本文をファイルから読んだ投稿には `permissionDecision` を出さない(人の権限の確認が残る)。申し送りは `additionalContext` で返す。
- 400 字未満のコマンドの解析が落ちて本文ファイルを審査せずに通した回を、misses.log に `parse-error` と種類(値は書かない)で残す。
- `cat <<'EOF' … EOF | gh … --body-file -` のように、`cat <<'EOF'` 1 本だけをパイプの左に置いた形は、その中身を本文として読む(止めていた)。
- 二重引用の中の `"$(cat <<'EOF' … EOF)"` は、前後に字が在っても、その字と連結した値を読む(止めていた)。
- 置換の中の case で枝の型を括弧で囲まない形(`$(case x in x) …;; esac)`)は、解析できないものとして止める。`(x)` と囲めば読む。引用や `\` の退避の中の `case`・`esac` は数えない。
- destgate は、許可一覧が有効なとき、gh の綴りを含むのに解析できないコマンドを止める(今までは coldread に任せて何もしなかった)。`COLDREAD_SKIP=1` では外れない。
- destgate は、`-R` の無い投稿の宛先を gh と同じ材料で照らす: 環境変数 `GH_REPO`、コマンドの中で字のまま書いた `GH_REPO` の値(gh の前置の `GH_REPO=owner/repo`・`env GH_REPO=…`・`export GH_REPO=…`。`env "$(cat <<'EOF' … EOF)" gh …` の値で渡す形も)、git の remote(`gh repo set-default` が在ればそれ、無ければ remote の全部)、`cd`・`pushd`・`env -C` で移った先の remote(`builtin export …`・`builtin cd …` のように `builtin` を前に置いた形も)。値を字から読めない `GH_REPO`(展開を含む値・`read`・`for`・`printf -v`・`declare -n` など)と、行き先が字のまま決まらない移動(`cd "$D"`・`cd -`)・`env -S` の前置・サブコマンドより前の知らない旗は、宛先を特定できないとして止める。`gh api` のパスの `{owner}`・`{repo}` も同じ候補で置き換えて照らす(remote が読めなければ今までどおり字のまま照らす)。`source` や `.` を同じコマンドに置いた投稿は今までどおり照らして通す。

### Fixed

- `--body "$(cat <<'EOF' … EOF)"` の形(pr comment・pr create・release --notes・api -f body= など)を、置換渡しとして止めていた。bash と同じ値として読む。`cat<<'EOF'` と空白の無い形・`2>/dev/null` の付いた形も読む。
- 開始行に続きのあるヒアドキュメント(`<<'EOF' 2>&1 | tail -1`・`<<'EOF' && echo ok`)と部分的に引用した区切り(`<<\EOF`)を読めず、stdin 渡しとして止めていた。英字で始まらない区切り(`<<1X`)も読む。
- 空白で離れた数字(`gh issue comment --body-file - 123 <<'EOF'`)をリダイレクトの fd と読み、stdin 渡しとして止めていた。fd は演算子に密着した数字だけにした。
- `cd /tmp;` の後の改行・空行・`&&` の後の改行を挟んだ形で、本文ファイルを読まずに実ファイル指定として止めていた。
- 二重引用の中の値ごとに展開を見るようにした。同じコマンドの別の値に置換が在るだけで、`'costs 5$'` のような本文まで止めていた。

### Security

- 区切りを引用しないヒアドキュメント(`--body-file - <<EOF`)の中身を字面のまま審査していた。bash は `$(…)` などを展開するので、投稿される本文と審査した本文がずれていた。展開を受ける中身は止める。
- 字下げした終端行を終端と読み、投稿されない短い本文を審査していた。終端行は字のまま照合する。区切りを引用しない `<<EOF` では、行末の `\` で連結してから終端と照合する(連結の前に照合して、投稿されない短い本文を審査していた)。
- 本文の値の途中の展開(`"前 $(cat 長い本文.md)"`・`"Hello $NAME"`・`x$Y`・`"$1"`)を字面のまま審査していた(200 字に届かなければ審査なしに出ていた)。値のどこかに展開が在れば止める。
- bash が走らせる gh が両方のゲートに見えていなかった: 二重引用の中の `$(…)`・`` `…` `` の中、引用しないヒアドキュメントの中身の `$(…)` の中、`$(…)` を閉じた直後の `#` の後ろ、`$[…]`・`$(#` の後ろ、`<<1X` の中身に呑まれた後ろ。字句の文脈を 1 本の走査で読み、bash を判定役にした差分検査で突き合わせる。
- 位置引数の無い `gh gist create` にパイプ・`< file` などで stdin を渡す形を、候補も止めた理由も積まずに通していた(destgate も宛先を見ていなかった)。stdin がヒアドキュメントでなければ止める。stdin を受け継いだままと言える形(区切りが `;`・改行・`&&`・`||`・`( )` だけで、どの単純コマンドも fd 0 を差し替えない。`cd x && gh gist create -d 説明` など)は今までどおり通す。今まで通っていて止まるようになるのは、パイプ・背景の `&`・`< f` などで stdin を差し替える形と、同じ行のほかのコマンドが fd 0 を差し替える形(`cat > f <<'EOF' … EOF` の後の `gh gist create -d 説明`)。後者は gh の stdin を差し替えないが、囲む `{ } < f` や `done < f` と区別する規則を足さずに止める側へ倒した(ファイルを付け忘れた gist で、受け継いだ stdin は空なので投稿にならない形)。
- `env -u NAME gh …`・`env -C DIR gh …`・`env -S STRING gh …`・`exec -a NAME gh …` の gh が両方のゲートに見えていなかった(旗の値を命令名と読んでいた)。値を取る包みの旗の値を読み飛ばす。束ねた短い旗(`env -iC DIR`・`env -0uNAME`)も字ごとに読む。`env -C DIR` の後の相対パスの本文ファイルは読まずに止める。
- 400 字未満のコマンドの本文ファイル(`gh issue comment 1 --body-file /abs/body.md`)を、読む前に通していた。
- 走査の例外(末尾が `<<EOF\` の形)と、終端行の無い `<<` を並べた重い入力で、門番が落ちるか時間切れになって無検査で通っていた。解析は上限の判定と例外の柵の内側だけで走らせ、終端行の無いヒアドキュメントは bash と同じく入力の終わりまでを中身にする(読み直さない)。
- 値の決まる置換の値が gh の命令名・本文旗(`--body-file=…`)・`key=値` になる形を、gh の呼び出しや本文旗として見ていなかった。置換は旗や命令の意味を決める前に値へ解く。
- destgate が、展開を含む `-R` の値と `gh api` のパス(`-R "evil/repo$(: /owner/x)"`)を展開前の字で許可一覧に照らし、bash が展開した後の別の宛先への投稿を通していた。展開や GitHub の名前に入らない字を含む宛先は、特定できないとして止める。`-R` を 2 つ以上書いた投稿は最初の値だけを照らしていた(gh は最後の値を使う)。どれも許可一覧に当たる必要がある。
- destgate が `-R` の無い投稿を git remote の origin だけで照らし、gh が実際に投稿する upstream など別の remote・`cd` や `env -C` で移った先の remote・コマンドの中で書いた `GH_REPO` の宛先を見ていなかった。ほかの旗の値の位置の `-R`(`gh api repos/evil/x/… -H -Rx:owner/y`)を宛先と読み、api のパスを照らさずに通していた。
- 解析の重さが入力の長さの 2 乗になる形(gh を数万並べる・展開を数万並べる・長い 1 語・行継続で 1 字ずつに割った数字)で、上限の無い destgate がフックの timeout に届き、宛先の検査が外れていた。解析は 1 回にし、gh の呼び出しに依らない判定は字列ごとに 1 回だけ作り、トークン化を長さに比例する走査に替え、語と数字は部品を集めて 1 回で連結する。同じファイルは 1 度だけ開き、読むファイルの合計を 1 ファイルの上限までに縛る。これらの形で走査の手数と内側の判定の回数が長さに比例することを tests/py/test_coldread_gate.py が縛る(字の写しの量は数えない)。
- `--title ';'` のように引用した演算子の字を区切りと読み、後ろの本文旗と `-R` を gh の引数から落としていた。引用した字は語として読む。
- 同じコマンドの中の置換や関数の定義(`cd "$(cp evil body; echo /)" && gh … --body-file body`・`cat() { … }; gh … --body "$(cat <<'EOF' …)"`)で、フックが読んだ本文と bash が投稿する本文がずれていた。命令を走らせる展開か、シェルの状態(変数・関数・命令の探し先)を書かないと言えない形(子のプロセスで走る命令と、`cd`・`echo` などの書かない組み込み・`$NAME` の形の展開のほかすべて——`read PATH`・`printf -v PATH`・`for PATH in`・`declare -n`・`BASH_CMDS[cat]=`・`$((PATH=0))` も)が在れば、ファイルも置換の中の cat も読まずに止める。

## [0.10.0] - 2026-09-07

- 相手の言い回しを地の文に写した箇所を「なぞり」として止める。引用して指す形は通る。
- 記録の各行にセッション・フックの版・投稿先を残し、新しい版が入っていれば検査結果でそれを知らせる。

### Changed

- 3 回連続で止まったときの案内は字数の推移を示し、「最初の本文に戻す」を勧める。

### Fixed

- 連続で止まった回数を書き手のセッションと投稿先の組で数える。並行するセッションの deny が足され、よそでの skip で案内が消えていた。

## [0.9.0] - 2026-09-06

### Added

- PR・issue への返信と編集では、フックが gh でスレッド（題・対象のファイルと行・元の指摘・これまでの返信）を取り、coldreader に「既に見えているもの」として渡す。新規の作成は従来どおり文脈ゼロで読ませる。

### Changed

- 画面に有るものを本文で説明した箇所は「冗長」として止めずに申し送る。返信が止まったときの直し方は「足すより削る」にした。
- 3 回連続で止まったときの案内を先頭に置き、本文の字数の膨れ方を示す。
- coldreader は利用者の CLAUDE.md などの設定を読まずに起動する。
- スレッドが取れないときは文脈ゼロで検査し、画面に有るものへの詰まりは無視してよいと書き手に伝える。

### Fixed

- 読み手が「詰まり: なし」と書いたとき、詰まり 1 件と数えて止めていた。

## [0.8.0] - 2026-09-04

### Added

- coldreader の報告に「補完」（読み手が推測で埋めた中身）の欄を足した。投稿は止めず、書き手へ返す。
- 網から落ちた疑いのあるコマンドを misses.log に残す。残すのは旗の綴りだけで、値は残さない。

### Changed

- 止めたときの指摘を「直す詰まり」と「直さなくてよい補完・疑問」の見出しに分けた。

### Fixed

- 行継続（`\` と改行）で割れた gh の呼び出し、予約語（`{`・`!`・`then`・`do` など）の後ろの gh、注釈と行継続の組み合わせで、投稿が無検査・無記録で通っていた。destgate の宛先検査も同時に外れていた。

## [0.7.0] - 2026-08-28

### Added

- destgate: 投稿先を人が管理する許可一覧（`$CLAUDE_CONFIG_DIR/destgate/allowlist` に owner/repo・owner/*・gist）で縛る門番。一覧が無ければ働かない。宛先が特定できない投稿は `-R` の明示を求めて止める。
- destgate は COLDREAD_SKIP=1 では外れない。逃げ道は一覧への人の追記だけ。

### Changed

- coldread が通したときにも「見たのは通じやすさだけで、出してよい投稿か・名義・宛先は検査していない」と毎回伝える。止めたときの文言の末尾にも同じ注を足した。

## [0.6.0] - 2026-08-28

## [0.5.1] - 2026-08-28

### Fixed

- 同じ行の別コマンドのヒアドキュメント（例: `cat > cfg.json <<SEC`）の中身が gh の本文として coldreader へ送られていた。本文はそのコマンドに付いたヒアドキュメントからだけ取る。

## [0.5.0] - 2026-08-28

### Changed

- gh の呼び出しと分かったのにサブコマンドを特定できないときは、投稿でないと見なさず「検査できない」として止める。
- `gh api --input` の JSON が `.body` 以外に長い文字列を持つときは、coldreader へ送らずに止める。

### Fixed

- 融合形の global 旗（`--repo=o/r`・`-Ro/r`・`--method=POST` など）を使うと、短縮形の本文旗が無検査で通っていた。
- 引用していないコマンド置換の本文が、断片に割れて検査をすり抜けていた。
- 長さの上限を超えたときの案内が、効かない手順（コマンドの前に環境変数を付ける）を示していた。実際の設定先を案内する。

### Security

- graphql の mutation で、引用文字列を無差別に本文として取り出し、トークンや ID を coldreader へ送っていた。

## [0.4.0] - 2026-08-28

### Changed

- 長い旗（`--body`・`--notes`・`--comment` など）は綴りだけで本文と見なし、短縮形（`-b`・`-c`・`-n` など）はその綴りが本文を意味するサブコマンドの中でだけ本文と見る。`gh pr checkout -b` などが的外れに止まっていた。
- 入れ子の遮断で検査せずに通した投稿も記録に残す。

### Security

- `gh api --input` の JSON は `.body` を持つときだけその中身を coldreader へ送る。持たない JSON（secrets の暗号値・設定）は送らない。

## [0.3.2] - 2026-08-28

### Changed

- coldreader を道具なし（`--tools ""`）で起こす。本文に紛れた指示で読み手が道具を使う経路を断つ。

### Fixed

- coldreader の中で門番がもう一度発火し、入れ子の末にフックのタイムアウトで投稿が無検査のまま通っていた。
- 長さの上限を超えたときに「引用を直せ」と誤った案内をしていた。上限の上げ方を案内し、README の設定一覧に載せた。

## [0.3.1] - 2026-08-28

### Changed

- 必要な Python を 3.8 以降と文書に明記した。

### Fixed

- 本文旗の直後のリダイレクト（`--body >&2 'text'`）、解析中の例外、検査できない本文と読める本文の同居で、投稿が無検査で通っていた。どれも止める側に倒す。
- ヒアドキュメントの `<<"EOF"`・`<<-`・ハイフン入りの終端を認識できず、正しい投稿を「stdin 渡しなので検査できない」と誤った理由で止めていた。
- `--input -` の JSON は、外側の殻でなく `.body` を coldreader へ渡す。
- `gh secret set -b`・`gh variable set -b`・`gh workflow run -F` を投稿と誤認し、値を読み手へ送ったり止めたりしていた。

## [0.3.0] - 2026-08-28

### Changed

- 投稿の判定を、シェルの単純コマンドごとに旗の持ち主を見る形に作り直した。引用の中の gh や、別のコマンドの旗を巻き込まない。
- graphql は mutation のときだけ投稿と見なす。
- 変数・コマンド置換・実ファイル・パイプで渡す本文は検査できないので止める。
- 原理的に対象外のもの（`--fill`・エディタ・ラッパー越し）を README の「網の射程」に書いた。

### Fixed

- 短縮形の `-F`・`-n`・`-c`、`--input` の実ファイル、引用の前置で投稿を取りこぼしていた。複合コマンドで別のコマンドの旗を拾って誤って止めていた。

## [0.1.0] - 2026-08-28

### Added

- gh の issue・PR への投稿を PreToolUse フックで捕まえ、別プロセスの claude（文脈を持たない読み手）に本文を初見で読ませる門番。詰まりが有れば指摘を付けて止め、疑問だけなら通して申し送る。
- 検査を飛ばす逃げ道 COLDREAD_SKIP=1（使うと記録が残る）。3 回連続で止まると、採否の判断と skip を案内する。読み手が故障したときは止める側に倒す。

### Changed

- plugin の名前を coldread から gates に変えた（skill の /coldread は gates の中に残る）。
