# 初見読みの費用と使用量の記録（2026-10-22）

初見読みの読み手に渡す不要な入力を減らし、依頼元と使用量を結べる記録を追加した。
前後1対では入力合計が6,064から2,843トークンに減ったが、推論量は増え、総費用の削減は約4.9%だった。
検査の観点・止める条件・モデル・effortは変えていない。この1対だけで品質や継続的な費用削減を保証しない。

## 依頼と決定の記録

依頼は my_notes の棚卸しを受けた受付 `20261022-002632-b8d969`。10月17日から22日未満の通常の初見読みは11,282会話・11,295要求、初期入力の中央値7,217トークン、API換算175.78ドルだった。既存の `docs.log` には書き手の会話番号の先頭8文字しかなく、読み手や会社へ使用量を結べなかった。これらは依頼元の数で、今回同じ期間を再集計した数ではない。

採った変更は次のとおり。

1. コード作業用の標準指示を、文章の理解を検査する短い専用の指示に置き換える。本文・画面・書き直し履歴・検査手順は変えず、標準指示の役割と検査対象のデータを区別する。
2. 読み手のツール・外部ツールの設定（MCP）・スキルを無効にする。`--tools ""` だけではMCP設定を外せないため、空の設定と `--strict-mcp-config` も渡す。読み手の会話本文は `--no-session-persistence` で保存しない。
3. 入力のキャッシュを全面無効化せず、読み手の子に `FORCE_PROMPT_CACHING_5M=1` を設定する。別の単発会話でも同じモデルの同じ先頭部分は再利用できる。一度しか使わない本文に1時間の書込料金を払うのを避ける。保存停止の引数は料金の割引ではない。
4. モデルとeffortは据え置く。投稿は sonnet / medium、手元文書は haiku / high。異なる仕事の手元の数字では選ばない。今回はモデルやeffortを下げるための対象用途の品質評価をしていない。
5. 最終の `result` から使用量を取り、内部推論とそれ以外の出力を分ける。推論量は `output_tokens` に含まれるため、二重加算しない。推論の内訳が無ければ両者の区別は欠測とする。

## 前後1対の実測

macOS、Claude Code 2.1.307で、同じ本文・検査手順・結果のJSON Schemaを、前版と変更版へ1回ずつ渡した。モデルは実モデル名 `claude-haiku-5-5`、effortはhigh。前版は変更開始時のcommit `39c7a110` の読み手引数、変更版は専用の標準指示と5分キャッシュを含む引数を使用した。

試験用の作業場から会社の属性を除き、フックを無効にして起動した。使用率の控えのある、モデルを読み替えていないアカウントのうち、5時間と7日の使用率の大きい方が最小のものを起動直前に選んだ。本文に未定義の略語を混ぜ、両版とも略語の意味が取れない詰まりを引用付きで返した。1件だけの確認であり、品質が落ちないことの証明ではない。

使用量を確認するため試験では `--output-format stream-json --verbose` を付け、最終 `result` の数を採用した。途中の同じメッセージのイベントが重複し、出力量は部分値だったため、途中のイベントは合計していない。本番は既存の `--output-format json` のままにした。両版に保存停止・フック無効・1ドルの歯止めを付け、上限に達した回や走らせ直した回は無い。

入力合計は通常入力・キャッシュ書込・キャッシュ読込の和で、53.1%減った。総費用は4.9%減った。推論以外の出力は減ったが、内部推論は増えたため、入力削減の割合を総費用へ当てはめられない。推論以外の出力は、表示したJSONだけの厳密な量ではなく、構造化出力の処理なども含みうる。

前版にはキャッシュの読込があり、変更版には無かった。キャッシュの条件は完全には同じでない。数の差には生成の揺れもあるので、この1対から総費用の削減率を一般化したり、推論量が減ったと報告したりしない。今回の仕組みの変更後に、各社の通常運用で欠測も含めて集計するための記録を残す。

再照合用に、本文と指摘を除いた最終結果の数をリポジトリの試験用データに残した。前版は `tests/fixtures/coldread-result-before-2.1.307.json`、変更版は `tests/fixtures/coldread-result-2.1.307.json`。これらの `findings` が空なのは保存前に指摘を除いたためで、実測で指摘が無かった意味ではない。

## 使用量の取り込み

記録は書き手のClaude Code設定フォルダ内の `coldread-gate/reader-usage.jsonl`。既定なら `~/.claude/coldread-gate/reader-usage.jsonl` で、別アカウントの読み手へ切り替わっても保存先は書き手側である。新規ファイルは所有者だけが読める権限で作る。

1. 各アカウントの現行ファイルと、ローテーション後の `.1` を取り込む。2 MBを超えると回転し、その次の回転で古い `.1` は消える。取り込み側は回転前に回収する。
2. 起動を表す `call_id` と、同じ呼び出し内の認証切替の回数 `attempt` の組で重複を除く。
3. 会社 `company`・部署 `department`・依頼の受付 `request_id`・書き手の完全な会話番号 `writer_session_id` / 役番号 `writer_agent_id` と、読み手の完全な会話番号 `reader_session_id` を結ぶ。実モデルは `models` のキー、頼んだモデルは `requested_model`。`effort` も残る。
4. 最終結果の無いタイムアウト・起動失敗・認証切替を、使用量ゼロにしない。数の欠測は `null`。実測ゼロは `0`。モデル別の `costBasis` が `list` のドルは公開料金によるAPI換算で、サブスクリプションの請求額ではない。他の基準は欠測として扱う。
5. 内部推論を含む課金の総出力量は `usage.output_tokens`。`thinking_tokens` と `nonthinking_output_tokens` はその内訳で、合計へ再加算しない。5分と1時間の書込内訳も合計の書込に再加算しない。

本文・指摘・資格情報・標準エラー・ファイルのパスは使用量記録へ保存しない。既存の判定キャッシュで読み手を起動しない回には使用量行が無い。会社の属性の無い場所やフックの会話番号の無い手動実行では帰属が欠測になりうる。読み手の会話番号は起動前に割り当て、タイムアウトでも残す。保存の失敗は検査結果を失わせず、書き手へのフック出力または手動実行の標準エラーへ通知する。

古い記録へ読み手の会話番号を補うことはできない。今回の試験は手元文書の読み手1対だけで、投稿の通常運用の費用効果、総費用の継続的な差、内訳を返さないClaude Code版の推論量は未測定。これらは記録の取り込み側が欠測件数と一緒に追う。
