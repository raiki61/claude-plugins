# 変更の記録（rent-or-buy）

rent-or-buy（「借りるか買うか」を計算だけで決める Claude Code のプラグイン。keepalive と compact の判断に当てる。keepalive はキャッシュが切れないよう送る短い要求、compact は会話を要約して縮める操作）の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。

版の出し方（この記録を書き足す段。git の tag は作らない）は、リポジトリのルートの `docs/releasing.md` に在る。

## [Unreleased]

### Fixed

- 記録のファイルを大きさで切り替える所（`rent_or_buy/record.py`）の、同じ大きさの確かめの入れ子（内側は何も狭めていなかった）を外側の 1 つにし、注を合わせた（動きは変わらない）。

## [0.4.0] - 2026-10-25

### Changed

- compact の損得の式を直した（設計書の 4.4。works-dispatch の compact の計画の 7 の 1）。
  - 縮める費用に、要約を作る要求が今の文脈を読む分を足した。この要求は文脈の全部を読むので、その 1 本は読む量を減らせない。規則は「前の compact から余分に読んだ累計 ≥ 縮める費用 + 問いの費用」になる。前の式は、この 1 本の分だけ早く「得」と言っていた。
  - compact の後の文脈を、記録の `postTokens`（要約だけの大きさで約 1 万トークン）でなく、compact の後の最初の要求がキャッシュに書いた量と読んだ量（入力の `after_write_tokens`・`after_read_tokens`。キャッシュに無い入力は書いた量に数える）から取る。読んだ分の費用も縮める費用に入れた。会話に compact がまだ無ければ、`prices.toml` の既定（7 日分の記録の中央値で、書き込み 37,000・読み 8,000 トークン。前の既定の 25,000 は例の値だった）を使う。
  - 出力に `compact_cost`（縮める費用のうち、要約の要求の外の分）を足した。
  - compact の入力の `post_tokens` は無くなり、渡すと知らない鍵として止まる。
  - compact が初めて得になる文脈は大きくなる（計画の 3.3 の試算で、中央が約 8〜9 万から約 13〜14 万トークンに）。

## [0.3.0] - 2026-10-25

### Changed

- compact の損得の式で使う要約の出力の既定（`prompt_cache/prices.toml` の `summary_tokens`）を、例の値の 5,000 から、実際の要約から見積もった 9,000 トークンに替えた。要約の本文（8 日分の記録の 613 件で中央 5,800 トークン）に、Claude Code が要約の前に書かせて捨てる下書きを本文の半分と見て足した。要約を作る要求の出力は記録に残らないので、出力の量そのものは測れない。見積もり方は設計書の 4.2。会話ごとの値にはしない。compact が得になる線は少し上がる（7 日分の記録を今の式に流すと、初めて得と言う文脈の中央が、約 7.6〜8.5 万から約 8.8〜9.6 万トークンに）。

## [0.2.2] - 2026-10-25

### Added

- 設計書に 4.6「compact の直す項（後の版）」を足した。compact の費用の見積もりに抜けていた項（要約を作る要求が今の文脈をキャッシュから読む費用・compact の後の最初の要求が実際に書き込む量・問いを送る費用）と、キャッシュを切らせる直前かを伝える入力を、会話の記録の実測と照合して書いた。問いは、会話に「縮めるなら残す話題を書いて」と頼む文で、問いの費用（それを送るのにかかる額）は呼び出し側が `consult_cost` で渡す。式はまだ変えていない。

## [0.2.1] - 2026-10-25

### Changed

- 設計書（`docs/design.md` と `docs/design.ja.md`）の 7 の、呼ぶ側の compact の指針を直した。compact を判断する時を、keepalive の時刻だけから、待ちに入るターンの終わりにも広げた。どの待ちもキャッシュの寿命より短い会話では keepalive の時刻が来ないため。ターンの終わりは人が次の文を打とうとしている間でありうるので、問わずに compact するのは `forced` のときだけにする。コマンドの振る舞いは変えていない。

## [0.2.0] - 2026-10-24

### Added

- 設計書をプラグインのフォルダに同梱した。`docs/design.md`（英語の正本）と `docs/design.ja.md`（日本語の訳）。解く問題・式と「費用が後から見た最適の 2 倍未満に収まる」上限の証明・入出力・値段の取り方（LiteLLM の値段表と ccusage に倣った方式）を、このリポジトリの外でも読める形で書いた。英語と日本語の 2 つの文書の見出しの数と並び・引く URL がそろうかを `tests/test_docs.py` が確かめる。コマンドの振る舞いは変えていない（文書を足しただけで、利用者が読めるようになる点が違い）。

## [0.1.0] - 2026-10-24

### Added

- 最初の版（これから出す 0.1.0 の中身）。「借りる」は少しずつ払い続けること（keepalive なら短い要求を 1 本送る、compact なら縮めずに大きな文脈を読む）、「買う」は 1 回まとめて払うこと（keepalive なら止めて切れたキャッシュを書き直す、compact なら要約して縮める）。「中心」は `decide` の本体で、`rent`・`buy`・`spent`（この回で借りに払った累計）・`certain`（借りるのを終わらせる出来事が確かに来るか）などを渡すと `action`（`rent` か `buy`）と理由を返す。「強制」は、呼ぶ側が `forced` を真で渡したら（たとえば文脈の大きさが、Claude Code が自動で compact を打つ大きさの手前に呼ぶ側が決めた値に着いたとき）必ず買わせること、「延期」は買うと出た後に、問い合わせ口（買う前に、買うと仕事を中断される相手〔たとえば compact で要約される会話のエージェント〕に呼ぶ側が聞く口）で、その相手が「今は待って」と返したら借り続けること（`defer_limit` の回数まで。値は呼ぶ側が渡す）。決め方の表は、止め時の決め方を名前で引く表。モデル名の揃えは、記録に書かれたモデル名を値段表の名前に直すこと。キャッシュは最後の要求から 5 分か 1 時間で切れ、切れると次の本物の要求が書き直しの費用を払う。借りるか買うかを決める計算の部品 `bin/rent-or-buy`（`decide`・`keepalive`・`compact`・`prices`・`snapshot`）。標準入力の JSON を受け、標準出力の JSON を返し、判断の状態を持たない。出力には機械の読む理由の鍵 `reason`（`within_buy_cost`・`forced` など）と英語の訳 `why` が付く。`decide` は中心をそのまま呼び、`keepalive`・`compact` は場面の事実を中心の入力に直して（翻訳）判断し、`prices <モデル>` は使う単価と出どころを返し、`snapshot` は同梱の値段の写しを作り直す。設計は `docs/specs/2026-10-24-rent-or-buy-design.md`。
  - 中は 2 つのモジュール。`rent_or_buy/` は Claude を知らないアルゴリズム（決め方の表と、今ある唯一の決め方 `fixed`（確率で決める `random` などは後の版で足す予定）・強制と延期の上限・問い合わせ口・判断の記録）、`prompt_cache/` は Claude のプロンプトキャッシュへの当てはめ（LiteLLM（モデルの値段表を公開している外部のプロジェクト）の値段表の写しと、1 日 1 回までの取り直し（取れなければ写しで計算する）・モデル名の揃え・会話の記録の読み取り・翻訳）。境目の 4 つの決まり（アルゴリズムは標準ライブラリと自分だけを読む・キャッシュの層はアルゴリズムが公開する名前（`__all__` に並べた `decide` など）だけを使う・プラグインの外から 2 つのモジュールを読み込まない・アルゴリズムに Claude の語を書かない）を `tests/test_boundary.py` が守る。
  - `fixed` は、借り賃が一定なら借りるのをやめて買う時点を、総額がどんな終わり方でも「終わりを先に知っていた場合の最小の費用（後から見た最適）」の 2 倍未満に収まるように選ぶ（借り賃が回ごとに変わるときの保証はこの試験の範囲外で、確かめるのは一定の場合だけ）。
