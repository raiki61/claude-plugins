## TDD の流れ（この run は TDD の流れで回っている）

前の段（p3.tdd_tests）であなたが書いたテストと振り分け: {{out.p3.tdd_tests}}
赤の確認の結果（red が版なら、名指しのテストが狙いどおり落ち、元の結末で通っていたテストは緑だった。red が failed なら上限で TDD を諦めた）: {{loop.tdd}}

- **tdd に振った単位は、名指しのテストを通す実装を書け。** 実装が済むと engine がテスト一式を 1 回走らせ、名指しのテストと、元の結末で通っていたテストが全部通ることを確かめる（緑の確認）。通らなければこの段が差し戻される（上限 3 回。越えたら諦めて進み、理由は次の周の判定役に渡る）。
- **`test_files` のファイルを書き換えるな**——緑の確認が赤の確認の版からの差を見て拒む。テストの側が誤っていたと分かっても書き換えるな: 誤りの箇所（どのテストのどこか）を `rejudge_requested` に書け。
- `surface_change` を出した単位は、その呼び口・名前を作れ（テストはもうその呼び口を叩いている）。
- direct に振った単位と、赤の確認が上限で通らなかった周（red が failed）の単位は、上の今の修正の流れの指示どおりに直せ。
- `closure.sites[].red_seen` は、tdd に振った単位では赤の確認が見た赤を指してよい（`verified_how` に名指しのテストを書け）。
