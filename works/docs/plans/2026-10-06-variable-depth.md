## 決めたこと（理由つき。迷った所は今の設計に一番揃う方を採った）

- **決め 1（語）:** 深さの語は今ある入力 `thickness` の語を使い、新しい語の組を作らない。標準＝今の振る舞い（持ち主の決まり「全部の深さは今と同じ」）。入力の既定を「自動」にし、単位ごとに機械が決める。`thickness` を名指せば全部の単位をその深さに固定する（軽量でも決め 4 の信号で標準へ上がる）。重厚は今どおり拒む。2026-09-27 の持ち主の決定「軽量は受けない（graph で省けない節を省くことになる）」は、上の持ち主の依頼で置き換わる。ただしその理由は保つ: 軽量が省くのは graph の外の物と、graph が optional と言う物だけ。
- **決め 2（2 段）:** 軽量と標準の 2 段だけ。間の段に何を省くかを測りで言えない。
- **決め 3（単位の深さの決まり）:** 単位の深さは、その単位を `unit_keys` に載せる修正案の項目の欄から決める。次の全部を満たす時だけ軽量、1 つでも外れれば標準で、外れた理由を控えに残す。
  1. 単位を載せる項目が在る（無ければ形が分からない）
  2. `allowed_paths` が 3 個以下で、glob（`*`・`?`・`[`）を含まない
  3. 受け入れのテストと書き換える既存のテストが合わせて 2 本以下
  4. `allowed_paths` に約束の形のファイル（拡張子 .json・.yaml・.yml・.toml、またはパスに schemas/ を含む）が無い
  5. run に機械の確かめが在る（入力 `tdd_suite` か start の `test_cmd` が空でない。無ければ省いた確かめを機械が補えない）
  しきい値 3 と 2 は測りの値（何も見つけなかった 245・246 は 1〜3 個と 1 本、見つけた 244 は 4 個と 4 本）。
- **決め 4（上げる信号）:** 修正の後に次のどれかが立てば標準へ上げる。単位に結べる信号: その単位の食い違いの申し出（修正のブロックの各 include の置き場の `conflicts.json`）・修正の受け付けが最後の回に止めた単位（盤面の trace の `fix_bound_parked` の行）。単位に結べない信号（全部の単位を上げる）: 同じ run の案の直しが走った（境の節 `h-replan` の go）・判定への異議の再審が走った（境の節 `h-rejudge` の go）・答えていない問い（問いの台帳の held・escalate）が在る。上げた理由は控えに残す。下げる道は作らない。
- **決め 5（run の深さ）:** 切った後の run 全体の段（レンズ・独立の目）は単位をまたいで差分全体を見るので、全部の単位が軽量の時だけ軽量。単位が 1 つも無い run は標準。
- **決め 6（軽量で省く物。どれも測りで何も見つけなかった物だけ）:**
  1. レンズの全部（245・246 で 0 件、244 で 1 件）。graph の外。行は lens.json に「起こさなかった（理由）」で残り、報告の未確認のレンズの節にも出る。
  2. 独立の目の r1.comment_candidates（245・246 で候補 0、244 で候補あり）。盤面の省く口で省き、記録の省略した機構に残る。R1 の本体は今どおり回る。
  省いた物は報告の冒頭 2 に「軽量で省いた: <物>」と 1 行ずつ出す。（決め 9 で、差分の審査と独立の目の本体 4 つを足した）
- **決め 7（置き場）:** 決めた物は盤面の根の `depth.json`（単位ごとの深さと理由・固定の語・run の深さ・上げた理由）。読み書きは `darkfactory/lib/depth.py` だけ。ブロックはこの控えを読まない。
- **決め 8（節）:** `h-depth`（`h-fix` の後・修正の前。決める）と `h-redepth`（`h-mid` の後・`h-review` の前。上げて run の深さを出す）の 2 つの script の節。境の節と同じく start と前の境の節に依っていつも走り、上流が飛ばされた run は「単位が無い」で標準を返す。`fixing` は `h-depth` を待つ（つなぎ目で入力を 1 つ足すだけで済むように）。

- **決め 9（持ち主の決定を受けて省く物を広げる）:** 写しの graph（`graphloops/graphs/review-loop.json`）で、差分の審査（p3.delta_review）と独立の目の本体 4 つ（r1.minimality・r2.compare・r3.coherence・r4.hidden_scope）に `"optional": true` を足し、節の表 `darkfactory/nodes.json` で skippable にした。どれも 245・246 で pass（差分の審査は compliance・quality とも pass、目は 4 つとも pass）。optional は省く口だけが読むので、標準の振る舞いは変わらない。写しの手直しは台帳 `.shared/core/COPIED_FROM` の `!` 行に 1 つずつ載せた（写しの一致の試験が台帳ごと照らす）。合わせて次の 2 つも `!` 行で手直しした。
  1. 周の記録（`graphloops/rules/review-loop.py` の record_round）: 省いた R を「走らせるべき周に返答が無い」の not_run（収束を止める）でなく、省いた理由つきの新しい値 skipped で書く。
  2. 検証器（`scripts/review-record.py`）: 俯瞰の判定の表に skipped（理由が要る・阻害でない・持ち越さない・機械が書いた値）を足す。
  省く口: 差分の審査は線の `h-redepth` が盤面で省く（境の節 `h-review` が盤面の待ちを見て差分の審査・レンズ・手直しを回さない）。目は目のブロックが入力 `skip_optional` の理由で、表で skippable の目を全部省く。目のブロックが「諦めたら省く」のは今までどおりコメントの削除候補だけ（ほかの目は諦めたら今どおり盤面を止める）。graph_sha は 9a1e3957f23d から 2eb140b879e5 に替わり、節の表・試験の表の見本・実物の盤面の写し・盤面の手本（make.py で撮り直し。12 場面・失敗 0）を付け替えた。
- **決め 10（AI の報告は省かない）:** 持ち主は AI の報告も省いてよいと言ったが、条件は「測りで安全と言える物」。AI の報告は確かめでなく、人が読む面（平易な 3 行と人が決めること）で、「何も見つけなかった」を測る物が無い。省くと軽量の run の人は機械の報告だけを読むことになり、人の読む物を減らす（今ある能力を減らさない決まり）。費用は 245・246 で $1.03・$1.20 と一番大きいので、省くなら持ち主が「軽量の run は機械の報告だけでよい」と決めた時に、同じ形（graph の optional と線の省く口）で足せる。

- **決め 11（配線だけの単位は軽量。2026-10-06 の残り「配線だけの単位は軽量と見る」を入れた）:** 触るファイルが全部配線のファイルの単位は、決め 3 の条件 4（約束の形のファイル）に数えない。ほかの条件（3 個以下・glob なし・テスト 2 本以下・機械の確かめあり）は今どおり当てる。配線のファイルは `depth.wiring` の決まり 1 つ: 名が `manifest.json`（部品の consumes・produces の宣言）か、`<名>/<名>.yaml`・`.yml`（フォルダと同じ名の YAML＝線とブロックの節・include・with の配線）で、パスに schemas/ を含まない物。表（nodes.json など）・schema・ほかの YAML（CI の設定など）は今どおり約束の形。配線とコードを一緒に触る単位も今どおり標準（配線だけの時だけ外す）。理由: 配線の変更は層と配線の試験（YAML の形・manifest の照らし）が機械で確かめ、線とブロックの約束の形（schema・表）は変えない。限り: 決まりは works の pack の形で決めたので、ほかの対象の `manifest.json`（ブラウザの拡張など）も配線に数える。その単位も修正の後の信号（決め 4）で標準へ上がる道は残る。試験は `tests/test_depth.py` の UnitDepthCase。

## ブロックの入出力と配線でできない物（理由つき）

- **（2026-10-06 の持ち主の決定で解けた）独立の目の R1 本体・R2 の比較・R3・R4、差分の審査**: 写しの graph で optional でない節で、盤面の省く口が拒んでいた。決め 9 で写しの graph を `!` 行で手直しして省けるようにした。AI の報告は決め 10 のとおり省かない。
- **切る前の段（目的・前提・判定・修正案・事前審査）**: 単位がまだ無い。測りでは事前審査は穴が無ければ 1 往復で済み（読み取り 2）、前の決定を洗う役は 244 でも 245 でも材料を返した。省く根拠が無いので変えない。
- **修正のブロックの中の単位ごとの段**: 次の節。

## blk-fix へのつなぎ目（0.2.30 で入れた。下の「入れた時の決め」）

- 線: `fixing`（と `refitting`）の `with:` に `unit_depths: $h-depth.output.unit_depths` を足す。値は `{"<単位の key>": "軽量" | "標準"}` の JSON の文字列。
- ブロック: `blk-fix` の入力 `unit_depths`（既定は空＝全部の単位が今どおり）。単位ごとの修正役を起こす script の節がこの入力を読み、軽量の単位だけに次を当てる。Archon の `when:` は節ごとで輪の回ごとに分けられないので、分けるのはブロックの script の節の中。
  1. TDD の輪の緑の後に毎単位走らせる run の `test_cmd`（dogfood では 1 回 4〜5 分）を走らせない。同じコマンドを線の最後のテストが木の全部で走らせるので、確かめは消えない。
  2. ほかは今どおり（赤緑の確かめ・受け付けの選んだ試験・裁定の輪は省かない）。
- 上げ: 単位ごとの受け付けが拒んだ・申し出た単位は、ブロックの出口に平の印で出し、線の `h-redepth` が上げる（決め 4 の口に信号を 1 つ足すだけ）。
- 測り: つなぎ目が入ったら、同じ依頼（245・246）を自動と標準で回し、TDD の輪の時間の差を測ってから既定に残す。

入れた時の決め（2026-10-06）:

- 線は `fixing` にだけ `unit_depths: $h-depth.output.unit_depths` を渡し、`refitting` には渡さない。2 回目の修正は案の直し（`h-replan` の go）の後にだけ走り、案の直しは決め 4 で全部の単位を標準へ上げる信号なので、渡すと上がる前の軽量を当ててしまう。渡さなければ入力の既定（空）で全部の単位が今どおり。
- 読むのは輪の頭の script の節 tdd-start（`tddloop.start` の引数 unit_depths。状態の light に軽量の単位の key を置く）。省くのは緑の後の test_cmd だけで、ここは輪の中にしか無い（修正役・単位ごとの並行の下請け・修正の受け付けは test_cmd を走らせない）ので、単位ごとの修正役の並行（parallel-units）と食い違わない。軽量の単位は、状態の関門が on のままでも緑の後に走らせず、出口の単位の欄 test_cmd を light にする。指示書の「緑の後に機械が run の test_cmd も走らせる」の行も軽量の単位には出さない。名指しの無い単位・標準・空は 1 字も変わらない。形の違う値は配線の誤りとして tdd-start が 2 で落ちる。
- 修正の後に上がった単位（決め 4）は、輪の中では既に軽量で回っている。省いた確かめは同じコマンドを線の最後のテストが木の全部で走らせるので、上げの後に取り戻す口は足さない。
- 残り: 上の「上げ」（単位ごとの受け付けが拒んだ・申し出た単位をブロックの出口に平の印で出す）はまだ入れていない。今の決め 4 の信号（各 include の置き場の conflicts.json・trace の fix_bound_parked の行）で足りるかを、測りの run で見てから決める。
