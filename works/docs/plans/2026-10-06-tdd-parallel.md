# TDD の輪の単位を、範囲の重ならない物だけ単位の worktree で並べる（依頼 243 の並べ・2 段目）

状態: 入れた（既定の形 g3 の TDD の輪の、振り分けの直後の 1 回だけ）。残りは本物の run での確かめ（下の「残り」）。単位を項目ごとの枝にまとめ、範囲が重なる枝も並べる形へ広げた（works/docs/plans/2026-10-07-overlap-lanes.md）。

## 目的と語

読む前提: works（このリポジトリの works/ にある、修正依頼を直して出荷する仕組み）の全体は works/README.md と works/docs/specs/2026-09-27-darkfactory-single-run-design.md に在る。前の一切れは、修正役の下請けを範囲の重ならない項目だけ単位の worktree で並べた works/docs/plans/2026-10-06-parallel-units.md（以下「1 段目」）と、単位ごとに新しい会話で起こす works/docs/plans/2026-10-06-fresh-session.md。

1 段目で並んだのは TDD の輪の後の修正役だけで、輪の中（テスト → 赤 → 直し → 緑 → 整え）は今も単位を 1 つずつ回す。run 195g の輪は 5 単位で 67 分かかった。この一切れは、範囲が互いに重ならない単位の TDD を、単位ごとの worktree で同時に回す。赤・緑は今どおり機械が試験を走らせて決める。

この文書の語:

- 輪・周・段: TDD の輪（`works/blk-fix/blk-fix.yaml` の tdd-loop。Archon の loop_group）。1 回の繰り返しが周で、周ごとに支度 tdd-prep → 役 tdd → 確かめ tdd-step。段は route（振り分け）・test（テストを書いて赤）・fix（直して緑）・refactor（整え）。状態は盤面の `tdd-<k>/state.json`（`works/blk-fix/lib/tddloop.py`）
- 単位: 判定が切った直す単位（単位の key で呼ぶ）。振り分けで tdd の単位だけが輪で直る
- 範囲: 単位を持つ修正案の項目の「書いてよいパス」（allowed_paths の glob）と受け入れのテストのファイル（`fixrules.item_ranges`）。単位が 2 つ以上の項目に在れば和
- 単位の worktree・run ごとの置き場・包み・柵・書き込みの記録・当てる: 1 段目の語と同じ（`works/.shared/core/unittrees.py`・`adapter.run_place_of`・`claude-adapter`・`writes.py`）
- 並べる単位（並べ）・順の単位: この一切れで機械が分ける 2 組。並べる単位は単位の worktree で同時に、順の単位は今どおり run の作業ツリーで 1 つずつ
- まとめ役・単位の下請け: 並べの周の役 tdd（まとめ役）と、まとめ役が Claude の Agent の道具で起こす単位ごとの下請け
- 段のコマンド: 単位の下請けが Bash で走らせる機械のコマンド（`works/blk-fix/lib/tddlanes.py`）。単位の worktree で、tddloop の確かめ（赤・緑・凍結・名指しの外の書き換え・消えたテスト・test_cmd・整え）をそのまま回す
- 単位の控え: 単位ごとの状態（`<run ごとの置き場>/tdd-<k>/lanes/lane-<n>/state.json`）。tddloop の状態と同じ形で、単位 1 つだけを持つ
- 戻す: 並べで済まなかった単位を順の単位に移し、run の作業ツリーで最初の段（test）から直させること

## 前の道が止まった所と、この一切れの形

Archon の fan_out は子ごとに cwd を単位の worktree へ向けられない（1 段目の「前の道が止まった所」）。この一切れも 1 段目と同じ形を使う: 輪の 1 つの周（並べの周）で、まとめ役が単位の下請けを Agent の呼びで 1 つのメッセージに並べて起こし、下請けはそれぞれの単位の worktree で働く。

赤・緑を役の申告で決めないために、下請けは段ごとに段のコマンドを走らせる。コマンドは tddloop の段の確かめ（`tddloop.step`）を、単位の控えと単位の worktree でそのまま呼ぶ。決まりの写しは作らない。並べの周の確かめ（tdd-step。sandbox の外）が、単位の控えを読んで差分を run の作業ツリーへ当て、当てた後の木でもう 1 度緑を確かめる。

## 柵との突き合わせ（止めになるかを先に見た）

1. 単位の worktree への書き込み: 包みは、run ごとの置き場の下にあってこの作業ツリーの守りの参照を持つ worktree を、守る所から外す（1 段目で入れた。役の名を問わない）。worktree は tdd-step（sandbox の外）が切るので、次の周のまとめ役の起動の時には在る。
2. 共通の .git への書き込み: 段のコマンドは作業ツリーの姿を木に固める（`git write-tree`。object を書く）。sandbox は共通の .git を書かせない。
   - 決め: コマンドは git の新しい object を単位の控えの隣の objects（run ごとの置き場の下。sandbox が書ける）に書き、元の objects を代わりの置き場として読む（GIT_OBJECT_DIRECTORY と GIT_ALTERNATE_OBJECT_DIRECTORIES）。コマンドが起こす試験と test_cmd にはこの 2 つを渡さない（試験の中の git が別の置き場に書かないように。`tree_run.outside_env` が印 `LANE_GIT_ENV` の在る時だけ落とす）。
3. 盤面は書けない: 単位の控え・試験のログ・JUnit・地図のキャッシュは run ごとの置き場の下。コマンドは盤面を開かない（修正案の約束は単位の控えに写しておく）。食い違いの申し出の確かめは盤面を読むので、コマンドは申し出を控えに書くだけにし、確かめと盤面への積みは tdd-step がする。
4. 書き込みの記録: 包みのフックが下請けの Edit・Write を run の作業ツリーの記録（`writes.sink`）に実パスで残す。コマンドは記録を書けない（包みの家）ので、突き合わせは tdd-step が単位の worktree の実パスで行い（`writes.unrecorded`）、当てた後に `writes.carry` で run の作業ツリーへ写す（1 段目の fix-units と同じ）。Bash で書いた物の申告（bash_writes）は、コマンドが単位の控えに積み、tdd-step が記録に足す。
5. 道具: 輪の役 tdd は Agent を持たなかった。役の節の allowed_tools に Agent を足し、包みの形ごとの柵（`fixshape.DENY`）で g3 の外の tdd の Agent を拒む（af・current の輪は今と同じ道具）。
6. Python: 役の sandbox の `python3` は 3.9 のことがある。段のコマンドは支度の節（uv で走る）の実行ファイルの絶対パスで書く（範囲の相談と同じ）。
7. 試験の枠（`slotwrap.sh`）: 置き場に書けなければ枠を取らずに回す決まり（今のまま）。コマンドは盤面の待ちの印を書かない（ARTIFACTS_DIR を落とす）。

止めになる物は無かった。

## 案

### 分け方（機械。振り分けの直後）

振り分けの返答を tdd-step が受けた後、状態の `lanes_on`（tdd-start が形 g3 の時だけ立てる）が真なら、`tddlanes.plan` が tdd の単位の範囲を引き（盤面の項目の範囲と、単位ごとの brief の項目 `planbrief.by_unit_at`）、`unitlanes.lanes`（1 段目の分け方をそのまま）で並べる単位を選ぶ。範囲の引けない単位（修正案の無い run・項目に無い単位・allowed_paths の欄の無い項目・範囲が空）と、ほかの単位と範囲が重なる単位（同じ項目の 2 単位を含む）は順。並べる単位が 2 つ未満なら並べず、今と同じ（次の段は最初の単位の test）。

並べるなら `unitlanes.plant` で単位の worktree を `<run ごとの置き場>/tdd-<k>/lanes/item-<n>` に切り（base は振り分けの後の run の作業ツリーの今の姿）、単位ごとに単位の控えを書き、控えの目録（盤面の `tdd-<k>/lanes.json`。役は書けない）を置いて、次の段を lanes にする。

### 並べの周（AI。まとめ役と下請け）

tdd-prep は lanes の段で、まとめ役の指示書と、単位ごとの下請けのファイル（盤面の `tdd-<k>/lane-<n>.md`）を書く。下請けのファイルは TDD の輪の役の決まり（全文）・その単位の brief・座（g3）・test・fix・refactor の 3 段の約束と返す形・段のコマンドの 1 行・「この worktree の中だけで読む・書く・試験を回す」の決まりを持つ（下請けはまとめ役の指示書を読まない）。

1. まとめ役は、並べる単位の下請けを 1 つのメッセージの中で全部 Agent で起こす（同時に走る）。prompt は「下請けのファイルを Read で全部読み、その指示に従え」の 1 行。
2. 下請けは単位の worktree で段ごとに書き、段の返答の JSON を単位の置き場の reply.json に書いて段のコマンドを走らせる。コマンドの出力（ok・phase・reason・done）に従い、done が真になるまで続ける（拒否の理由を直して出し直す・次の段へ進む）。拒否 3 回の諦め・direct への渡し・食い違いの申し出も、tddloop の決まりのまま。
3. 全部の下請けが終わったら、まとめ役は `{"phase": "lanes"}` を返す。止まった下請けを起こし直さない（機械が残りを順に回す）。

### 締める（機械。lanes の段の tdd-step）

`tddlanes.settle`: 目録の単位の順に、

- 単位の worktree の `.git` の 1 行が切った時と違う・控えが読めない → 戻す
- 食い違いの申し出 → `conflict.problems` で確かめ、通れば今どおり止めて盤面に積む（tdd_step が `conflict.park`）。通らなければ戻す
- 下請けが direct に渡した（direct_why。約束の tdd の単位は段のコマンドが拒む）→ direct
- 緑まで済んだ → 赤の確かめ直し（単位の worktree を単位の頭の木に赤の時のテストのファイルだけを置いた姿にして名指しだけを回し、写しの red_problems と記録の赤の種類で照らす。回した後は元の姿に戻す。再現しなければ戻して理由を残す）→ 書き込みの記録の突き合わせ（記録の無い変更が在れば戻す）→ 差分を 3 方向で当てる（当たらない・当てた中身が単位の worktree と違う・凍ったテストの中身が赤の時と違う → その単位の当てを戻して戻す）→ 記録を写す
- ほか（拒否 3 回の諦め・実行器が走らない・回数の上限・途中で止まった・起こされなかった）→ 戻す

当てた単位が 1 つ以上在れば、当てた後の run の作業ツリーで、当てた単位の名指しのテスト全部と変更に直に関わる試験を 1 回走らせて緑を確かめ（`green_problems`。test_cmd の関門が on で、軽量でない単位が在れば test_cmd も 1 回）、赤・走らなければ当てた単位を全部作業ツリーから戻して戻す。

最後に単位の worktree を片付け、戻した単位を順の単位の先頭（振り分けの順）に置いて、順の最初の単位の test の段へ進む（無ければ輪は済む）。戻した単位の指示書には、並べで済まなかった理由と前の試みの差分のファイル（盤面の `tdd-<k>/lanes/item-<n>.patch`）を添える。引き継ぎの節には、並べで済んだ単位も並ぶ。

まとめ役が run の作業ツリーを書いていたら（並べの周は書かない約束）、機械がその変更を戻して trace の代わりに状態の lanes に残す（拒んで出し直させない。並べの周は 1 回で締める）。

### 今と同じに保つ物

- 赤は名指しのテストが failure で落ちる・緑は名指しと元で通っていたテストが通る（写しの red_problems・green_problems）・凍結（赤の時のテストのファイルの sha）・名指しの外の既存のテストの書き換え・消えたテスト・赤の種類・約束の受け入れのテストの名指しと direct への渡しの拒否・選んで回す試験（direct_only）・軽量の単位の test_cmd の省き: 全部 `tddloop.step` の同じ関数が単位の worktree で決める
- 単位ごとの新しい会話: 下請けは Agent の 1 回の呼びで、単位ごとに新しい会話。まとめ役も単位の鍵 `tdd-<k>:lanes` で新しい会話
- 範囲の相談: TDD の輪の役は今も相談を持たない（範囲の外は食い違いの申し出 scope_needed）。下請けも同じ
- 盤面の柵: 盤面に足すファイル（目録 lanes.json・下請けのファイル lane-<n>.md・戻した単位の差分 lanes/item-<n>.patch）は全部 `tdd-<k>/` の下（共有の記録 `tdd-*/**`）。単位の控え・ログは run ごとの置き場
- 形 g3 で並べる単位が 2 つ未満・形 af・current・修正案の無い run: 今と 1 バイトも同じ段の並び（lanes の段は来ない）
- 出口の calls は今どおり tdd の節の起動 1 回に 1 行（並べの周は phase lanes の 1 行）。段のコマンドの呼びは出口の `lanes.calls` に別に並ぶ（`dev/fixmeasure.py` の数え合わせを崩さない）

## 決定（設計に無かった所。既存の設計に一番近い物を選んだ）

- 並べるのは振り分けの直後の 1 回だけ。順の単位の途中で並べ直すと、前の単位の緑の木を base にした切り直しと、引き継ぎの節の前提が増える。1 段目の「pass first の 1 回目だけ」と同じ考え
- 並べるのは g3 だけ。af と current は比べの腕と基準なので変えない。g1 は輪を回さない
- 段の確かめは下請けのコマンド（sandbox の中）で回す（持ち主の指定）。周ごとに全部の単位の段を揃えて tdd-step で確かめる形（段の足並み）は、sandbox の外で確かめられるが、単位ごとに段の数が違うと速い単位が遅い単位を待ち、下請けも段ごとに起こし直すので単位の中の会話が切れる
- 単位の控えは下請けが書ける所に在るので、偽れる。締め（sandbox の外）が赤・緑の両方を確かめ直す: 赤は単位の頭の木に赤の時のテストのファイルだけを置いて名指しを回し直し（名指しだけなので安い。持ち主の決め 2026-10-06: 本物の run を待たずに塞ぐ）、緑は当てた後の木で回し直す。凍ったテストの中身・書き込みの記録・差分の当たりも sandbox の外で見る
- 並べで済まなかった単位は全部、順の単位として最初から回し直す（direct にしない）。単位の worktree には git が無視するファイル（.venv など）が無く、試験が環境で落ちうるので、並べの失敗を単位の失敗に数えない。害は時間だけ
- 当てた後の緑が赤なら、当てた単位を全部戻す（どの単位の組み合わせが割ったかを 2 分しない。範囲が重ならない単位どうしで起きるのは稀で、順に戻せば単位ごとの確かめが拾う）
- まとめ役の拒否と出し直しは作らない（並べの周は 1 回で締める）。止まった下請けを起こし直させないのも同じで、残りは機械が順に回す
- 期限・時間切れは足さない（R50）

## 危険

1. 赤の記録は単位の控え（下請けが書ける所）に在り、手で書き換えられる。締めが赤を確かめ直すので、偽った単位は当たらずに順へ戻り、理由が出口の lanes の単位の行に残る（塞いだ。残るのは、赤の時のテストのファイルが凍結の照らしで今の中身と同じことに依る点で、凍結の照らしも sandbox の外）
2. 単位の worktree に .venv・node_modules が無いと、実行器が走らない・試験が環境で落ちる。その単位は戻されて順で直る（時間だけの害）。全部の単位が戻ると、並べの周の分だけ今より遅い
3. 下請けが段のコマンドを走らせずに終わる・まとめ役が下請けを起こさない: その単位は戻され、今と同じに順で直る

## 残り

- 本物の run での確かめ: まとめ役が下請けを 1 つのメッセージで起こし、同時に走ること。下請けの Edit が単位の worktree に書け、書き込みの記録が run の作業ツリーの記録に実パスで載ること。段のコマンドが sandbox の中で共通の .git を書かずに走ること（試験は共通の .git を読み取りだけにして見た）。実行器が単位の worktree で走ること（対象の .venv を使う実行器では戻されるか）。並べの周が順の周より短いこと（起動の記録と calls の秒）
