## 1. 今の流れと、重なりで並ばない所

分け方はどちらの段も範囲の重なりで切る:

- 修正役: `fixrules.g1_values`（side が立つ g3 の 1 回目）が `fixrules.item_ranges` の範囲を `unitlanes.lanes` に渡す。`lanes` は範囲の在る項目のうち、ほかのどの項目とも `overlap`（glob の字のままの頭の比べ）しない物だけを返す。
- TDD の輪: `tddlanes.plan` が `tddlanes.ranges`（単位を持つ項目の範囲の和）を引き、同じ `unitlanes.lanes` で並べる単位を選ぶ。同じ項目の 2 単位は範囲が同じなので必ず重なり、順になる。

合わせる道具は既に 3 方向: `unittrees.apply` は一時の index で `git apply --cached --3way` を試し、未解決の段が残れば作業ツリーを変えずに (False, 理由) を返す。字の食い違いの逃げ道（その枝を順へ戻す）も両方の段に在る（修正役は `unitlanes.merge` の conflict を順で直し直す。TDD の輪は `tddlanes._merge` の失敗で戻す）。

それでも重なる枝をそのまま並べると止まる所が 6 つ在る:

1. 分け方: `unitlanes.lanes` が重なる物を外す（上）。
2. TDD の輪の当ての後の照らし: `tddlanes._merge` は当てたファイルの中身が単位の worktree と同じか（`unitlanes._same`）と、凍ったテストのファイルの sha が赤の時と同じか（`test_hashes`）を見て、違えば戻す。重なりのファイルは前の枝の変更を含むので、必ず違う。
3. 書き込みの記録: `writes.carry` は単位の worktree と run の作業ツリーの中身が同じファイルだけを写す。TDD の輪の締め（`tddlanes.settle`）には申告（bash_writes）の道が無いので、重なりのファイルは記録の無い変更として残り、後ろの受け付け（`writes.unrecorded`）が拒む。修正役は `unitlanes._summary` の differ を役が bash_writes に書く道が既に在る。
4. 同じ項目の単位: 単位の控え（`tddlanes._lane_state`）は単位 1 つだけを持つ。同じ項目の 2 単位を別の枝にすると、どちらの枝も項目の受け入れのテストを名指しで書かされる（`tddloop._test` の `_plan_tests` と、前の単位の確かめ済みを外す `_verified` は 1 つの状態の中でしか効かない）。同じテストを 2 本書いて必ず字の食い違いになる。
5. 試験のファイルの末尾: 2 つの枝が同じ試験のファイルの末尾にクラスを足すと、3 方向でも挿しだけの食い違いになる。この repo の試験の足し方はほとんどこの形。
6. 合わせた木の緑: `tddlanes._green_after` が赤なら、当てた枝を全部戻す（どの組み合わせが割ったかを見ない）。範囲の重ならない枝どうしでは稀だった（2 段目の決定）が、重なる枝では意味の食い違いの主な出口になる。

run 195g の事実（持ち主の指示に在る数）: TDD の輪の 3 単位が全部 `works/.shared/core/report.py` を触り、並べは 1 本も立たず、輪は 8.4 分を順に回った。修正役も同じ理由で順。

## 2. 案

### 2.1 分け方（機械）

- TDD の輪: `tddlanes.plan` は tdd の単位を枝に組む。単位どうしが修正案の項目を共にすれば同じ枝（`planbrief.by_unit_at` の項目でつなぐ。単位が 2 つの項目に在れば、その 2 項目の単位は全部 1 本）。範囲の引けない単位（今の `ranges` が None）を含む組は順。枝が 2 本以上なら並べる。範囲の重なりでは外さない。
- 修正役: `unitlanes.lanes` は範囲の在る項目を全部返す（2 つ未満なら []）。範囲の無い項目（修正案の無い run の項目・どの項目にも無い単位）は今どおり順。
- `unitlanes.overlap` は外さずに「重なりの見込み」を測りに使う（見込みの組と実際の重なりのファイルを出口に並べ、glob の頭の比べがどれだけ当たったかを見る）。
- base はどの枝も同じ（`unitlanes.plant` が `unittrees.snapshot` を 1 回取る。今のまま）。

### 2.2 枝の中（TDD の輪。AI と段のコマンド）

- 枝に単位が 2 つ以上あれば、単位の控えに枝の単位を全部、振り分けの順で持たせる（`_lane_state` の open_units・order・queue・units・contract・light を組の分に）。単位から単位への進みは `tddloop.step` と `tddloop._next_unit` がそのまま回す（枝の中は今の輪と同じ順）。下請けは枝ごとに 1 つ（単位が替わる時の新しい会話は持たない。枝の中の 2 単位目は同じ下請けが続ける）。単位ごとに新しい会話で起こす決まり（works/docs/plans/2026-10-06-fresh-session.md）からの差で、理由は 2 つ: 同じ項目の単位どうしは読む物（brief・範囲・受け入れのテスト）が同じで、会話に積もる物が少ない。下請けを単位ごとに起こし直すにはまとめ役が枝の途中を待つ必要があり、並べの周を 1 回で締める 2 段目の形が崩れる。
- `tddloop._test` は赤を受けた時に単位の行へ単位の頭（`unit_head`）を `head` として残す。締めの赤の確かめ直し（`tddlanes._red_again`）は単位ごとにこの `head` を使う（今は控えの `unit_head` 1 つ。単位が 1 つなら同じ値）。
- 食い違いの申し出（`tddlanes._park`）は今の単位（`queue[cur]`）を止め、枝の残りの単位は戻す（順の単位へ）。

### 2.3 枝ごとの確かめ（関わる試験だけ）

変えない。枝の中の赤・緑は `tddloop.step` が単位の worktree で決め、緑は名指しと変更に直に関わる試験（`tddloop._reached` の direct_only）だけ。締めの赤の確かめ直しも名指しだけを単位の worktree で回す。持ち主の決まり「枝では関わる試験だけ」はこのまま。

### 2.4 合わせる（機械。TDD の輪は締めの `tddlanes.settle`、修正役は当てるコマンド `unitlanes.merge` と締めの `unitlanes.settle`）

1. 当てる順は枝の番号の順（TDD の輪は振り分けの順、修正役は項目の番号。今のまま）。
2. 字の食い違い（未解決の段が残る）: その枝は当てずに戻す（今の逃げ道）。前の試みの差分は盤面に残す（今のまま）。戻した枝は、合わせた木の上で順に最初から直し直す。
3. 挿しだけの食い違い: 未解決のファイルが全部「試験のファイル」（並べた枝の受け入れのテストのファイル `planmarks.test_paths`）で、ぶつかった塊がどれも base の側に行を持たない時だけ、先の枝の行の後に後の枝の行を置いて合わせる（`git merge-file --union` と同じ並び）。ほかは 2 と同じ。合わせた試験のファイルに、同じ名のテストの関数・クラスが同じ所に 2 つ在れば（後の定義が前を隠す）、字の食い違いと同じに戻す。
4. 当てた後の照らし（`tddlanes._merge`）は、ファイルを 2 つに分ける:
   - 前に当てた枝の差分に出ていないファイル: 今どおり、中身が単位の worktree と同じか・凍ったテストの sha が赤の時と同じか。
   - 重なりのファイル: 中身は違ってよい（前の枝の変更を含む）。代わりに、この枝の名指しのテストの関数の源が、単位の worktree と合わせた木で同じかを見る（`tddloop._unnamed_edits` と同じ関数の幅の引き方）。違えば戻す。
5. 書き込みの記録（TDD の輪）: 重なりでないファイルは今どおり `writes.carry`。重なりのファイルは新しい口 `writes.carry_merged` が、合わせたファイルの今の中身に 1 行を足す（tool_name `unit-merge`・from は合わせた枝の元の実パスの並び）。足すのは、合わせたどの枝のそのファイルの中身にも単位の worktree での記録が在る時だけ。合わせたのは sandbox の外の機械なので、機械が出どころを請け負う。
6. 書き込みの記録（修正役）: 変えない。当てるコマンドは役の sandbox の中で走るので、機械の請け負いにしない。重なりのファイルは今の differ に出て、修正役が返答の bash_writes に書く（1 段目の決まりのまま）。
7. 修正役の当てるコマンドの出力に `shared`（重なりのファイル）と `union`（挿しだけの食い違いを合わせたファイル）を足す。挿しだけの食い違いの合わせは修正役の道でも同じ口（`unittrees.apply` の union の口）で行う（控え units.json に試験のファイルの並びを置く）。

### 2.5 合わせた木の確かめ（広めの試験を 1 回）と、意味の食い違いの逃げ道

TDD の輪（`tddlanes._green_after`）:

1. 当てた枝の名指しのテスト全部と、当てた変更の全部を起点に直に関わる試験（今と同じ）に、重なりのファイルを起点に地図が届く試験の全部（`impact.select_tests` の direct_only を外した選び）を足して 1 回走らせる。test_cmd の関門は今のまま。持ち主の決まり「広めの試験は合わせる所で」をここで満たす。一式は今どおり線の最後のテストの段。
2. 赤で、重なりのファイルが在れば、1 回だけ確かめ直す: 合わせた木を合わせる前に戻し、「前に当てた枝とファイルを共にしない枝」だけを当て直して同じ選びで走らせる（重なりの組ごとに後の枝を落とす）。緑なら当て直した枝を受け、落とした枝を戻す（理由「意味の食い違い」と、ぶつかった相手の枝・重なりのファイルを指示書に添える）。戻した枝は合わせた木の上で順に直し直す。
3. それでも赤か、重なりのファイルが無ければ、今どおり当てた枝を全部戻す。
4. 書き込みの記録の写し（2.4 の 5）は、受けた枝が決まった後に 1 度だけ行う（戻した枝の記録を写さない）。

修正役: 新しい確かめは足さない。合わせた木は受け付け（fix-accept）が今どおり見る: 変更に当たる試験（`check_tests`）・事後の関門の束の受け入れのテストの赤→緑（`fixgates.problems`）・範囲（`planscope.check`）。意味の食い違いは受け付けの拒否になり、出し直しの回（並べない。`fixrules.side_on` は 1 回目だけ）で修正役が合わせた木の上で直す。出し直しの支度は、前の周の締めの trace（`fixrules.UNITS_OP` の行の shared）を見て、拒否の理由のファイルの頭に「前の周は項目 a・b を並べて同じファイル f を合わせた」を 1 行足す。

### 2.6 凍ったテストと書き換えの許し（rewrite_tests）

- 枝の中の凍結（`tddloop._frozen_moved`・`_other_test_edits`・`_unnamed_edits`）は単位の worktree で今どおり効く。書き換えの許しは単位の約束（`tddloop._contract`。項目の rewrite_tests）のままで、枝ごとに自分の項目の許しだけを持つ。
- 合わせた後: 2.4 の 4 が枝ごとに名指しの関数の源を見る。他の枝の項目の rewrite_tests に在るテストを、この枝が書き換えていれば、枝の中の `_unnamed_edits` が既に拒んでいる（許しは枝の項目の分だけ）。
- 輪の全体の凍結（`tddloop` の終わりの `frozen`・`frozen_tree`）は合わせた後の木で取るので、今のまま（後ろの修正役の受け付け `tddloop.frozen_problems` も今のまま）。

### 2.7 範囲の相談（askplan）との関わり

- TDD の輪の役と下請けは今も相談を持たない（範囲の外は食い違いの申し出 scope_needed。2 段目のまま）。
- 修正役の下請けの相談（`askplan.ask`）は、項目の範囲を run の途中で広げうる。今は広げた範囲が別の枝の範囲に入っても並べの前提（重ならない）が黙って崩れ、当てる所で食い違えば順に戻るだけだった。楽観の並べでは重なりを前提にするので、相談の許しで枝を組み直さない（分け方は支度の 1 回だけ）。広げた範囲の正しさは今どおり受け付け（`planscope.check` が合意の `granted_paths` を項目の範囲に足す）が見る。
- 同時に走る枝の相談は `askplan` の錠（LOCK）で 1 つずつになり、相手の会話（写し）も 1 本を順に継ぐ。相手が見るのは run の作業ツリー（控えの repo）で、枝の作業ツリーではない（今と同じ。相手は範囲の判断だけをする）。

## 3. 置き場（ブロックの独立・盤面の柵・run ごとの置き場）

- 節の出口: fix-units の output_format に `shared`（ファイルの並び）を足す（今の欄の足し方と同じ。additionalProperties を閉じていないが、型の宣言として書く）。役の型（tdd の節の output_format）は変えない。

## 4. 測る事（次の本物の run）

1. 段ごとの待ちの損（線の木の 6 節の残りを、この一切れで閉じる）: Archon の出来事の task_activity（task_type `local_agent` の started と completed。task_id で組み、created_at の差が下請けの時間）を節（step_name）ごとに読み、続けて起きた started の並び（間に local_agent の completed を挟まない並び）を 1 束とする。束ごとに「一番遅い − 平均」を出し、段（修正案の事前審査・TDD の輪の並べの周・修正役の 1 回目）ごとに足す。新しい時計は足さない（`dev/fixmeasure.py` に足し、出来事の欄の印 `FIELDS_CHECKED` に completed の印を足す）。
2. 並べの効き: TDD の輪の全体の時間（195g の 8.4 分と比べる）・並べの周の時間・戻した枝の順の直し直しの時間。修正役の 1 回目の時間。

## 7. 決め事（推しつき）
