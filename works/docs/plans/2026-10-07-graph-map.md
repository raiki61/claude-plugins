# 工程の地図: 役に「全体のグラフはこの形で、あなたはここ」を機械で差し込む

状態: 入れた（部品 `.shared/core/graphmap.py`・包みの差し込みの表・地図の元 `darkfactory/darkfactory.graph.json`・旗 `map` を修正案の役の会話の 4 節に）。残りは本物の run での確かめ（9 節）。

## 平たく言うと（3 行）

- 役（AI の節）は自分の指示書しか読まないので、自分の出力が後でどう使われるかを知らない。修正案の役は「項目は後で並べの枝になり 3 方向で合わさる」を知らずに、同じファイルを触る項目を 1 つにまとめた（枝 wip/canary3 の 1c42d882）。
- 工程の YAML から全体のグラフを機械で組み、「あなたはここ（★）」と後の流れを描いた短い地図を、包み（claude-adapter）が役の system prompt に足す。指示書は書き換えない。
- 足すのは印に旗 `map` を持つ節だけ（今は修正案の役の会話の 4 節）。run の入力 `features_off` の語 `graph_map` で run ごとに切れる。

## 目的と語

持ち主の依頼（2026-10-07）: 「後工程の流れも教えるやつはさ、全体のグラフがこの形で君はここってのを機械的にミドルウェアっぽく差し込むノードつくる」「上手く部品化しておいてね」「機械で差し込みたいからねミドルウェア的に」。持ち主の決め: 地図は節ごとに選んで足す（旗 `map`）。全部の AI の節には足さない（トークンの費用と、後の流れを見た役が後の段の仕事に手を出す恐れ）。

語:

- 地図の元（graph）: 入口の工程の YAML と、そこから include・workflow で呼ぶ工程の YAML を機械で読んだ JSON（`<入口の YAML の名>.graph.json`。入口の YAML の隣）
- 地図: 地図の元から、ある節について描いた短い文（system prompt に載る物）
- 会話の席（seat）: 印の `continue=X` で同じ会話を継ぐ節の組。根は `continue` を持たない節
- 差し込みの表: 包みが印のある起動ごとに system prompt に足す塊の表（`adapter.INJECTORS`）。行は検索語の規律と地図の 2 つ
- 目的の 1 行: YAML の節の `description:`（Archon v0.11.1 の節の型に在る鍵）

## 1. 決め

1. **地図の元は YAML そのもの**。節の種類（AI・script・関所・輪・呼ぶ節）・輪の中・`when:`・`depends_on`・include の `with:`・印は YAML に既に在る。手で書く地図の表は作らない（YAML とずれる）
2. **目的の 1 行は節の `description:`**。Archon v0.11.1 の節の型は `description: string`（任意）を持ち、`archon validate` の warning も出ない（試し: 知らない鍵 `purpose:` は `unknown_key ... will be ignored` の warning、`description:` は無言で通る。輪の中の節・include の節でも同じ）。部品は節ごとの文を持たない。目的の無い script の節は配管として地図から省く（境の節 `h-*` など）。AI・輪・呼ぶ節で目的の無い物は id だけで出る（旗 `map` の節の地図に載る物は試験が目的を求める）
3. **切り替えは `[needs: <入力>]`**。`description:` の末尾の `[needs: tdd_lanes]` は「この工程の入力 tdd_lanes が off なら、この節は仕事をしない」。ブロックは自分の入力の名だけを書き（ほかのブロックを知らない）、線の include の `with:`（`tdd_lanes: $start.output.tdd_lanes`）の最後の語を run の `features_off` と突き合わせる。切られた節は地図に出さず、分からなければ `[needs tdd_lanes]` を残す
4. **組むのは作る時、描くのは起動の時**。包みは標準ライブラリだけで動く（Python 3.9 でも。PyYAML を持たない）ので、YAML は読めない。そこで地図の元は作る時に開発の道具 `dev/graphmap_build.py build` で JSON に書き、試験（`test_graphmap` の `test_graph_file_is_fresh`）が今の YAML から組み直した物と字で同じかを縛る（YAML を替えて書き直し忘れると赤）。起動の時は包みが元の sha を今の YAML と比べ、違えば地図を足さずに理由を残す（古い地図で嘘を言わない）。run ごとに組む案は、包みに YAML の読み手を持たせることになるので採らない
5. **地図は会話ごとに同じ字**。同じ会話（`continue=` で継ぐ節）の起動ごとに system prompt が替わると、prompt のキャッシュが会話の全部で切れる。そこで地図の ★ は「その節」でなく「その節の会話の席」に付け、席のどの節で起こしても同じ字にする。修正案の役（plan）・直し（plan-revise。continue=plan）・範囲の相談の答え（plan-answer・plan-answer-ruled。continue=fix-planner）は 1 つの席で、地図は 4 節で同じ。席の中で旗 `map` が揃うことを試験が縛る。system prompt は会話の記録（transcript）に積まれないので、続きの起動で地図が重なることもない
6. **差し込むのは包みの差し込みの表**（ミドルウェア）。足す物を増やすのは表に 1 行足すだけで、起動の手順と指示書は替えない。今までの検索語の規律（頭の 13）も同じ表の 1 行にした（下の 4 節）
7. **切るのは `features_off` の語 `graph_map`**（ほかの機能と同じ口。`entry.FEATURES`・start の出口・`versions.json` の settings・報告の冒頭 2 に乗る）。ブロックへは写さず、包みが切符の盤面の start の控え（`r1/start.json` の `features_off`）を読む
8. **包みを外した run（`WORKS_DEV_ADAPTER=0`）には載らない**。検索語の規律・柵と同じ制約。代わりの道（指示書に地図を書き込む支度）は作らない: 指示書は回ごとに書き直され、地図の字が会話に積まれる（system prompt と違ってキャッシュに優しくない）うえ、支度ごとに同じ口を足すことになる。包みを外すのは開発の比べの時だけで、その run は報告の冒頭に「包み無し」と出る

## 2. 旗 `map` を付ける節（持ち主の決め: 節ごとに選ぶ）

付けた（修正案の役の会話の 4 節）:

- `plan`（修正案の役）: 判定の単位を項目（書いてよい範囲・テスト）に分ける。項目の分け方は後の流れに直に依る——同じ単位を共にする項目の組が並べの枝になり（tdd-fork）、枝は同時に走り（tdd-lane-loop-1〜3）、差分は 3 方向で合わさる（tdd-join）。これを知らないと「同じファイルを触るから 1 項目に」とまとめる（canary3）。地図は枝と合わせを描くだけで、まとめるかの決まり（同じファイルの別の所はまとめる理由にならない）は別の枝が指示書に足す
- `plan-revise`（continue=plan）: 案の直し。修正案の会話の続きなので、1 の 5 のとおり地図も同じ字が要る（付けないと会話の system prompt が替わる）
- `plan-answer`・`plan-answer-ruled`（continue=fix-planner。包みの置き場で plan の会話の別名）: 範囲の相談の答え。同じ会話の続きなので同じ理由で付ける。範囲を広げるかの判断も、項目が枝で並ぶことに依る

付けない:

- 判定役 `judge`: 単位は根本の原因で決まり、後の段の都合で分けたり合わせたりする物ではない（並べの枝を決めるのは単位でなく修正案の項目の組）。地図を見せると単位を後の段の都合に寄せる恐れの方が大きい。再審の `rejudge`（continue=judge）も同じ席なので付けない
- 修正役 `fix`・TDD の役（`tdd`・`tdd-lane-<n>`・`tdd-rest`）: 持ち主の言う恐れ（後の段の仕事に手を出す）がいちばん大きい役。今の範囲と受け付けで十分に縛られている
- 道具ゼロの独立の目（旗 isolated）: 文脈を遮るのが役の意味

広げるのは本物の run で効きを見てから（持ち主）。広げる時は YAML の印（とそれを作る関数 `planblk.output_format`・`consult.answer_format` のような口）に旗を足し、席の全部に揃える（試験が名指す）。

## 3. 部品 `graphmap`（`.shared/core/graphmap.py`。層 L1）

Archon の YAML の形と pack の宣言 `archon-plugin.json` の `entrypoints` だけを読み、線・ブロックの名前も中身も知らない（`test_layers` の name の柵）。印の読みは `node_marker`。

口:

- `build(entry, resolve, base, parse) -> dict`: 入口の YAML から地図の元を組む。呼ぶ工程は `resolve(名)` で引く。`parse` は YAML の字を読む関数（`yaml.safe_load`）。pack の模块は標準ライブラリだけ（`test_layers`）なので受けて使う
- `pack_resolver(pack, parse)`: pack の直下の `<d>/<d>.yaml` を YAML の `name:` で引く既定の resolve
- `entrypoints(pack)`・`graph_path(pack, rel)`: 入口の一覧と、入口の隣の地図の元のパス（`<stem>.graph.json`）
- `load(path)`: 地図の元を読む（版・形が違えば ValueError）
- `stale(graph, base)`: 元の YAML の sha が控えと違う物
- `markers(graph)`・`seat(graph, name)`: 印の居場所と会話の席（別名の解き方は下）
- `render(graph, name, off=None) -> str`: 印 `name` の地図。`off` は切った切り替えの語の集合（None は分からない）
- 書く道具は pack の外の `dev/graphmap_build.py`: `uv run --no-project --with pyyaml python3 works/dev/graphmap_build.py build <pack> [<入口>…]`（書く）・`check`（古ければ名指して 1 で抜ける）

約束:

- 同じ地図の元・印・`off` からはいつも同じ字（並びは YAML の順。集合は並べてから出す）
- 席の別名: `continue=X` の X がどの工程にも無い名（ブロックの中の名。blk-fix の `fix-planner`）なら、その工程を呼ぶ節の `with:` の字の値（`$` で始まらない）のうち印の名である物がちょうど 1 つの時だけ、それを X の正体とする（線が `plan_session: plan` を渡す形）。2 つ以上・無いなら解かない（席はその節だけ）
- 開く工程: 席の節が居る工程の全部と、入口の工程で席の工程を最初に呼ぶ節の後に最初に呼ばれる工程（次に何が起きるか）。入口の工程は 1 行ずつ全部
- 記号: `⇒` 呼ぶ工程・`⟳n` 輪（上限 n 周）・`∥` 同じ depends_on を持つ兄弟の輪・AI の節（Archon v0.11.1 は兄弟の loop_group を同時に回す）・`[X.f]` 条件（`$X.output.f == true`）・`(off: 語)` 呼ぶ節の切られた入力・`人` 関所

地図の頭の 1 行は「指示ではない——あなたの仕事は指示書のとおり」と言う（後の段の仕事に手を出させないため）。

## 4. 包みの差し込みの表（`adapter.py` の頭の 13）

表 `INJECTORS` の行は `Injector(name, label, selector, producer, required)`:

- `selector(Launch) -> bool`: この起動に当てるか。`Launch` は印の名・continue・旗・道具・道具ゼロか・切符の盤面を返す関数
- `producer(Launch) -> Block | Skip`: 塊（`Block(text, digest)`。`adapter.block(text, of=None)` が組む）か、足さない理由（`Skip(why)`）
- `required`: 作れない・繋げない時に claude を起こさないか（fail closed）。偽なら `fence.<name> = {skipped: 理由}` を残して起こす

`inject(argv, launch)` は行を表の順に当て、塊を `--append-system-prompt` に 1 つの繋ぎ方で足す（SDK の値の後ろに空行 1 つ。塊どうしも空行 1 つ）。塊ごとの sha256 の先頭 16 字を起動の記録の `fence.<name>` に残す。SDK が `--append-system-prompt-file` を渡した・`--append-system-prompt` が 2 つの起動は、required の塊が在れば拒み、無ければ全部 skipped にして argv を替えない。

今の行:

| 名 | 当てる起動 | required |
| --- | --- | --- |
| `query_rule` | 道具を持つ起動 | 真 |
| `graph_map` | 旗 `map` の起動 | 偽 |

`query_rule` の塊と digest は前と同じ字・同じ値（digest は規律の塊だけの sha）。`graph_map` の作りは、切符の盤面の start の控えの `features_off` に `graph_map` が在れば Skip、無ければ入口ごとの地図の元のうち印を持つ物がちょうど 1 本で新しい時だけ `render(graph, 印, off)`。控えが無い・切符が無い起動は `off=None`（`[needs …]` を残す）。地図は足す物なので、作れなくても役は起こす。

## 8. 危うい所

- YAML を替えて `uv run --no-project --with pyyaml python3 works/dev/graphmap_build.py build works` を忘れると、試験が赤になり、run では地図が足されない（`fence.graph_map.skipped` に古い YAML の名）。並行の枝（blk-fix の修正役の並べの節など）を合わせた後は書き直す。新しい節が旗 `map` の地図に載るなら目的の 1 行も要る（試験が名指す）
- 地図の元は包みと同じ pack（包みの `.shared/core` の 2 つ上）から読む。run の pack の写し（対象の `.archon/workflows/works`）と包みの pack が違う版なら、地図は包みの版を描く（開発の殻では同じ worktree から写すので同じ）。run の途中で包みの pack の YAML を書き換えると、古さの確かめでその後の起動の地図が外れ、同じ会話の system prompt が替わってキャッシュが切れる（地図の字は変わらないが、足すか足さないかが替わる）。run の間は包みの pack を書き換えない
- 地図の元の JSON を手で書き換えて形が崩れても、包みは地図を足さずに理由を残して起こす（required でない行の作りの失敗は、どの型の例外でも skipped）
- 席の別名の解き方は「呼ぶ節の with の字の値で印の名が 1 つ」に依る。線が別の印の名を字で渡すと解けなくなり、答えの節の地図が修正案の役と違う字になる（キャッシュが切れるだけで、地図は出る）。試験が今の席を名で縛る
- 地図は事実を言うだけで、指示書の決まりを替えない。後の流れを見た修正案の役が、項目を枝の数に合わせて刻む・後の段の仕事を案に書く、などの寄りは本物の run で見る（9 節）

## 9. 本物の run で確かめる事

1. 起動の記録（`<家>/launches/<cwd の hash>.jsonl`）の plan・plan-revise・plan-answer の行の `fence.graph_map` が同じ digest で、`fence.query_rule` が前と同じ値
2. Archon の DB の plan の会話の 2 回目からの起動（plan-revise・plan-answer）で、キャッシュの読みが前の run と同じ桁（system prompt が替わっていない）
3. canary の (b)（同じファイルの 2 件）で、修正案の役が 2 項目に分け、tdd-fork が枝を 2 本切る
4. `features_off=graph_map` の run で `fence.graph_map.skipped` が「切った run」、地図の無い system prompt
5. 修正案の役が地図に引かれて項目の分け方を寄せていないか（枝の数に合わせた刻み・後の段の仕事の書き込み）を案の文で見る
