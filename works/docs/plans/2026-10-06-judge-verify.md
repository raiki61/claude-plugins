# 判定の根を開く（線の木の段 3。単位ごとの裏取りと単位どうしの相乗り）

状態: 入れた（wip/tree3）。残りは本物の run での測り（下の「残り」）。

## 平たく言うと（3 行）

- 今の工場は、判定役 1 人が依頼を「直す根本の件（単位）」に切り、そのまま修正案を書く役へ渡している。切り方が合っているかを別の目で確かめる段が無い。
- 案: 判定の後に、単位ごとの確かめ役を同時に立てて「本当に根本か・証拠は在るか・場所は合っているか」を見させ、同時に単位どうしの重複・関わり・順番を見る役を 1 つ立てる。機械が答えをまとめて修正案を書く役に渡し、報告にも載せる。
- 単位は消さない（直す義務を減らさない）。「根本でない」と出ても申し送りになるだけで、消すのは今どおり人の関所か再審の道。

## 目的と語

読む前提: works の全体は works/README.md と works/docs/darkfactory-flow.md、木の形の全体と段 1 の作りは works/docs/plans/2026-10-06-tree-line.md（2.1・2.2・6 節の段 3・7 節の決め事 5・8 節の速さの教訓）。

この文書の語:

- 単位: 判定役（判定のブロック `works/blk-judge` の節 judge）が依頼を切った根本の 1 件（盤面の根の `judgment.json` の units）。直す義務の残る単位（開いた単位）は検証器の is_open（block か do-now の suggest）
- 裏取り: この段で足す確かめ。単位ごとの下請けが 3 つを見る: 根本か（verdict: root・not_root・unsure）・証拠（evidence_found と見た所）・場所（location_ok と正しい場所）
- 相乗り: 単位どうしの関わりを 1 つの下請けが見る: 重複（同じ根の別の現れ）・関わり（同じファイル・名・試験）・順番（片方を先に直さないと直せない・試せない）
- 束ね役: 裏取りの AI の節 judge-verify。単位ごとの下請けと相乗りの下請けを Agent の道具で 1 つのメッセージに並べて起こす（段 1 の事前審査の束ね役と同じ形）
- 申し送り: 機械がまとめた裏取りと相乗りの控え（今の周の `judge-verify.json`）。修正案を書く役の指示書に貼り、報告の冒頭 1 に載せる

## 形

判定のブロックの中に、判定の輪の後・出口の前で 3 つの節を足す（新しいブロックにしない。入力は判定の控えだけで、判定の輪と同じ周に閉じるため）:

1. **verify-prep（機械）**: 盤面の `judgment.json` の開いた単位に 1 から番号を振り、単位ごとの下請けのファイル（`<scope>/r<N>/verify/unit-<n>.md`）と相乗りの下請けのファイル（`verify/synergy.md`）と束ね役の指示書（`verify/prompt.md`）を書く。答えの置き場は盤面の外の run ごとの置き場（`<run-place>/<scope>/judge-verify/r<N>/`。盤面は役が書けない）。作業ツリーの姿を控え、申し送りの初めの形（全部の単位が「確かめられなかった」）を `judge-verify.json` に置く（束ね役が落ちても修正案の役と報告に「確かめていない」が届く）。開いた単位が 2 つ未満・盤面が無い（単独の run）・止まった盤面・判定が無いなら go: false（申し送りの古い残りは消す）。
2. **judge-verify（AI。opus・effort high。確かめる目の役）**: 指示書の下請けのファイルごとに `general-purpose` の下請けを 1 つのメッセージに並べて起こし、返答は 1 行の要約 `{summary}` だけ（答えの中身を写さない。8 節の教訓 1）。道具は Read・Grep・Glob・WebSearch・WebFetch に Agent と Write（下請けが答えのファイルを盤面の外に書く。作業ツリーは書かないので `mutates_checkout: false`）。
3. **verify-merge（機械）**: 答えのファイルを型で確かめ、単位ごとの行（確かめた・確かめられなかった＋理由）と相乗り（番号を単位の key に戻す）を `judge-verify.json` にまとめる。作業ツリーが変わっていれば盤面を止める（読むだけの役の決まり）。trace に `judge_verify`（確かめた数・確かめられなかった数・相乗りの有無）。

出口 collect は verify-merge を待つ（verify-merge が飛ばされても走る）。出口の欄は変えない。

### 下請けのファイル（8 節の教訓を当てる）

- 自分の単位だけを字のまま持つ。頭（全部の下請けで同じバイト）に役の名乗り・決まり・判定者の見立て（framing・one_shot）を置き、`## お前の単位: 単位 <n>` の後にその単位の行（key・label・disposition・reason・origin_analysis・why_chain・prescriptions）と答えの置き場。判定の材料の全部や束ね役の指示書を読ませない。
- 答えは JSON 1 つを答えのファイルに Write（中身は機械が確かめてまとめる。束ね役は写さない）。
- web は根拠のコードで決まらない時だけ。判定の先行例の出典は開き直さない（出典の確かめは事前審査の下請けが run の中で 1 度だけする）。
- 下請けの型は `general-purpose` 1 つ（答えのファイルを書ける型）。

### 単位を消さない（7 節の決め事 5）

裏取りは単位を消さず、ラベルも変えない。`not_root`・`location_ok: false`・証拠なしは、修正案の役への申し送り（「この単位は案から外せない。根本の単位と同じ項目にまとめるか、approach に申し送りへの答えを書け」）と報告の冒頭 1 の行になるだけ。単位を減らしたい時は今どおり、修正前の関所で人が決めるか、修正役の異議から再審（`blk-rejudge`）へ。

### 1 単位の時は回さない（費用の決め）

開いた単位が 1 つの時は、この段の全体を飛ばす（裏取りの下請けも起こさない）。理由:

- 相乗りは 2 つ以上でしか意味が無い。残るのは単位 1 つの裏取りだけ。
- それでも opus の会話が 1 つ要り、線の頭（判定と修正案の間）の待ちに直に乗る（段 1 の項目の下請けの測りでは 1 本 2〜4 分）。
- 1 単位の判定は、修正案の事前審査の下請けがその 1 項目を判定の理由と独立設計で深く見る（段 1）。裏取りの見る所（根本か・証拠・場所）の大半はそこで重なる。
- 1 単位の切り違えは、修正役の異議から再審の道で直せる。

2 単位以上でも、束ね役の会話 1 つと下請け N＋1 本の分が増える。下請けは同時に走るので、待ちは一番遅い下請けの 1 本分（2〜4 分の見込み。測っていない）。

### 配線（ブロックの独立）

- 判定のブロックは `judge-verify.json` を manifest の produces（周の置き場）で宣言する。境の節 h-plan（`line_edge.plan_edge`）が今の周の控えのパスを出口の欄 `verify_file` で返し（波及の一覧 `ripple_file` と同じ形。境の節の出口の型は全部同じなので、全部の境の節の output_format と筋書きの stub に欄を足す）、線が修正案のブロックの入力 `verify_file` へ渡す。
- 修正案のブロックの入力 `verify_file` は形で述べる（「単位ごとの裏取りの申し送りの JSON。units と synergy。空か文字列 null なら無い」）。ブロックは出どころを名指さない。支度の節 prep の全部が入力を受け（同じ script を回す節は同じ with: を持つ決まり）、使うのは修正案の役だけ。直しの役は修正案の役の会話の続きなので、もう読んでいる。同じ run の中の案の直し（2 度目の include）には渡さない（修正の段の食い違いを直す道で、根の切り方は 1 度目に読んだ）。
- 報告（core の report）は周ごとの `judge-verify.json` を名で読む（`rejudge-diff.json` と同じ形。書き手のモジュールを import しない）。

## 抜け方と失敗の扱い

- 束ね役の節が落ちた（返答の型に合わない等）: verify-merge は飛び（依存は all_success）、出口 collect は走る（none_failed_min_one_success で、飛んだ依存は落ちに数えない）。申し送りは支度が置いた初めの形（全部「確かめられなかった」）のまま修正案の役と報告に届く。
- 下請けの答えのファイルが無い・型に合わない: その単位だけ「確かめられなかった」と誤りの行を控える。出し直しの輪は持たない（申し送りは義務を変えないので、1 単位の確かめのために束ね役をもう 1 度起こす費用に見合わない）。
- 作業ツリーが変わった: 盤面を止める（by `works:judge-verify`）。次の境の節が止まった盤面を見て線を止める。

## 既定を off にした（持ち主の決め 2026-10-08）

測り: 27 単位の 11 run で、この段は後の段（修正案の項目の組み方・修正）を 1 度も変えず、1 run に 0.6〜3 USD と 1〜2 分を足した。事前審査の木（`2026-10-06-tree-line.md` の 2.3）と合わせて切った組の測りでは、費用が約 30%（2.6 USD）・時間が 2.3 分減った。よって線の既定でこの段を回さない（線の start の出口 `judge_verify` が既定で `off`）。ブロックと線の配線はそのまま残し、入力 `features_on=judge_verify`（`use.sh` は `WORKS_USE_FEATURES_ON`、`dogfood.sh` は `WORKS_FEATURES_ON`）で回せる。前からの入力 `features_off=judge_verify` は既定と同じ off のまま受ける。ブロックの入力 `verify` の空は今どおり on（ブロックの既定は変えず、線が off を渡す）。
