  - 部分: 一部だけ効いている（効く所と欠けた所を書く）

- 隙間: 観点のうち、まだ works が持っていない所。埋める先の部品と、計画の段を書く
- 段: 計画の段の番号（段 0〜段 7）。行の末尾の「→ 段 N」がその隙間を埋める段

## 開発の進め方（works を作る人の決まり。工場の観点とは別）

工場の判断ではなく、works を作る人（運び役の AI を含む）の進め方。短く保ち、works が機械で持てる所だけ書き添える。

- 自分食いと手の直し: 危ない直しは run を通す。手で入れるのは入れた方がよい物だけ（09-30）。グラフ全体を変える直しは会話の下請け（superpowers の手順）で作り、本物の run で確かめる（10-07）。どちらの道も同じ機械の関門（柵・全体の歯止め）を CI で通す（計画の段 3）。V105・V174
- 進め方: 既存の改善を先に固め、分かっている弱点を直した版で試す（V023）。構造を変える方が良ければぶつかるのを恐れない。大きな作り替えは先に設計し、旧い物を横に残す（V024）。土台とブロック分けを先に（V040）。依存を入れるかは保守性で、両方式で試作して比べる（V015）。今困っていない事には手を付けない（V016）。決めた規則は仕様書に実測を添えて残す（V035）。合流の後は整合を点検する（V103）。武器を外す候補は最小限にし、捕まえた件数だけで外さない（V090）
- 外の物: 外の道具（superpowers・Archon・その競合）は自分から調べて良い所を取る（V138）。review-graph と常に比べるが写しにしない。今は review-graph を気にせず写しを works の持ち物として育てる（V142・V143・V144）。Archon の開発元へ連絡しない（V141）。シェルの柵は shellcheck（V150）
- 試験と出荷: 重い試験は手元で回さず CI。全部の CI は版を上げる時の 1 回（V109・V110）。試験が軽くなったら同時に出す run を増やす（V132）。区切りで commit・push・版上げをまとめ、版上げは最後の commit、機能ができたら早く出す（V116・V118）。push の時期は任された（V117）。タグは作らない（V119）。プラグインのリポジトリは PR を通さず main へ（V120）
- run と枠: run を勝手に止めない・寝ている間も進める（V160）。使用枠は使い切り、尽きたら別アカウントへ（V161・V162）。複数アカウント・複数ターミナルで競合しない起こし方（V163）。確かめは常に最新の版で（V164・V172）。各 run は 1 周（V165）。端末の多重化の道具 herdr で人の番に見えない形（V167）。試しで残したプロセスは終わりに止める（V169）。1 時間を超える回し役の会話を疑う（V170）。定期の見回りはしない（V171）。run を細かく切りすぎない（V127）。試運転の費用は気にしない（V122）
- 下請けと片付け: 並行で出せる作業は先に出す・上限 30（V176）。使い終わった worktree・一時ファイルは中身を確かめて片付ける（V177）。works の開発は superpowers の TDD とサブエージェント方式（V178）。web 検索の上限は外してよい（V179）。Archon 版の作業は別のセッションに、この clone で枝を切る（V181）。並行する他人の PR には書き込まない（V182）。いずれ切り出して OSS に（V184）
- 引き継ぎと文書: compact（会話の要約）の前に残件・引き継ぎ・クリティカルパスをリポジトリの文書に自己完結で残す。引き継ぎ先のアカウントを推測しない（V173）。課題・利用者の声は 1 つの文書に整理し、済んだら印を付ける（V157）。利用者の声は本質で読み、「works で直すことは無いか」で依頼にする（V013）。流れの mermaid 図は今の姿に保つ（V153）。スキルの手順書は短く（V158）

## 食い違いと解き方（日付の新しい持ち主の言葉で決めた）

文書・記憶・CLAUDE.md の間の食い違いのうち、持ち主の言葉で決まる物。どれも持ち主に聞かずに済む。リポジトリの根の CLAUDE.md は 2026-09-29 05:24 に書かれ、下の持ち主の言葉はどれもそれより新しい。

- タグ: CLAUDE.md は「タグは人が作って push する」、記憶は「作らない」。持ち主「タグはつくりません」（2026-09-29 09:06）→ 作らない。CLAUDE.md の行を直す（計画の段 0）
- 下請けの模型: CLAUDE.md は「全部 opus・sonnet 以下は使わない」。持ち主「sonnetとかつかってもいいしね。WEBからとってきてまとめるところは」（2026-09-29 11:59）→ 下請けは opus、web から集めてまとめる役だけ Sonnet を許す（判断は opus）。CLAUDE.md の行を直す（段 0）
- 手での直し: CLAUDE.md は「hotfix も例外にしない」。持ち主「いれたほうがいいやつだけいれて」（2026-09-30）、「グラフ全体を変えてしまうので、superpowerで軽く治して、実際に動かしてみるのがいいのでは」（2026-10-07）→ 危ない直しは run を通し、グラフ全体を変える直しは下請けで作って本物の run で確かめる。どの道も同じ機械の関門を通す（計画の段 3）。CLAUDE.md の行を直す（段 0）。外の開発は工場が遅い間の暫定の道で、審査の run は足さない（持ち主 2026-10-09「工場がよくなったら工場がいい」。計画の 1 節の決め 3）
- 手元の重い試験: CLAUDE.md は「works に入れる前に全段を通す」。持ち主「手元の重いのはやめます。」（2026-10-06）→ 手元は速い段と根の柵、重い段は CI。CLAUDE.md の行を直す（段 0）

## この地図の育て方

- 持ち主の観点の正本は、この地図と works の部品そのもの。アカウントごとの会話の記憶は、決定の中身を持たず、この文書を指すだけにする

- 文書の要素ごとの細かい穴（約 400 の要素の照合）の振り分けは計画の 6 節に在る。ここには観点の単位でだけ書く
