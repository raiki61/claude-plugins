## 2. 流れとノード

```
[prs] 自分の番の PR ─────┐
[sessions] 開いている会話 ─┤
[accounts] アカウントの順 ─┼─► [assign] 割り振りの案 ─► [launch] 起こす ─► [turn] 1 ターン目 ─► [turn] 2 ターン目 ─► [report]
[slots] 作業場の空き ─────┘        （--dry-run はここで report へ）
```

| ノード | 外に書くか | 入力 | 出力 |
| --- | --- | --- | --- |
| prs | しない | リポジトリ | PR の並び |
| sessions | しない | 設定 | 会話の並び |
| accounts | しない | 設定 | アカウントの順 |
| slots | しない | 設定、会話の並び | 作業場の並び |
| assign | しない | 上の 4 つ | 割り振りの案 |
| launch | する | 案の 1 行 | 起こした結果 |
| turn | する | ペイン、文 | ターンの結果 |
| report | しない | 全部の結果 | 報告の行 |

各ノードの中身:

1. **prs**: `whose-turn.py` に足す機械向けの出力（`--json`）を読み、「自分の番」の節の PR を全部取る。出力の 1 件は、番号、URL、タイトル、head の枝、役割（実装者かレビュアーか）、日数。
2. **sessions**: 開いている会話を、Claude Code 自身から機械で集める。設定のアカウントごとに、その設定のフォルダを `CLAUDE_CONFIG_DIR` に入れて `claude agents --json` を呼ぶ。Claude Code の文書は、これを外から会話の状態を読む公式の口としている。返る 1 件は、会話のプロセスの作業フォルダ（`cwd`）、会話の ID、状態など（2026-10-14 に 2.1.299 で、対話の会話も出ることを確かめた）。各会話の `cwd` から、git で origin のリポジトリ（`OWNER/NAME`）と今の枝を読み、`(リポジトリ, 枝)` の組にする。herdr にも持ち主の設定にも頼らない。出力の 1 件は、アカウント、会話の ID、`cwd`、状態、リポジトリ、枝。持ち主の言葉は「リポジトリ, ブランチ（ＰＲ）とかそういう組み合わせがいいかな。できればclaudeからとれるのがいいかな。機械で。」（2026-10-14）。
3. **accounts**: 設定のアカウントごとに使用率の控えを読み、選べるかと順を決める。
   - `seven_day.used_percentage` が上限（既定 95）を超えるものは外す（持ち主の決め）。
   - `five_hour.used_percentage` が上限を超えるものも外す。5 時間の枠が尽きていると、起こしても最初の返事で止まる（判断）。
   - `resets_at` が過ぎた枠は、切り替わった後なので使用率 0 とみなす（判断）。
   - 残りを `seven_day.resets_at` の近い順に並べる（持ち主の決め）。同じ時刻なら週の使用率が低い順（判断）。
   - 出力の 1 件は、名前、起動のコマンド、2 つの枠の値、選べるか、外した訳。
4. **slots**: 作業場の空きを出す。差し替えるのはこのノード（3 節）。出力の 1 件は、workspace の名前、ペイン ID、作業フォルダ、今の枝、空きか、空きでない訳。
5. **assign**: 純粋な関数。PR ごとに結末を 1 つ決める。
   - `(対象のリポジトリ, PR の head の枝)` の組が sessions にあれば `already_open`（会話が開いている）。リポジトリまで見るので、`main` のような同じ名前の枝を別のリポジトリの会話と取り違えない。会話が終わって枝だけが残った作業場は、会話が開いているとはみなさない。会話の有無で見なければ、その PR は二度と割り振られない。
   - 選べるアカウントが無ければ `no_account`。1 回の実行の PR は全部、順の先頭のアカウントに入れる。控えは実行の途中で更新されず、持ち主の決め（切り替わりの近い枠から使い切る）とも同じ向きなので、散らさない。
   - 空いた作業場が無ければ `no_slot`。空きの中にその PR の枝にいる作業場があれば、それを先に使う（枝を移さずに済む）。
   - どれにも当たらなければ `assigned` で、作業場とアカウントを付ける。
   - PR の並びは prs の順のまま。作業場は 1 つにつき 1 件。
6. **launch**: 案の 1 行を受け、作業場のペインのシェルに、アカウントの起動のコマンド（例 `claude-p1`）を `herdr pane run <ペイン> <コマンド>` で打ち込む。最初のプロンプトは付けない。herdr が会話を見つけて `idle` になったことを読み戻してから返す。
   - `CLAUDE_CONFIG_DIR=… claude` の形は使わない。持ち主の `claude` はシェル関数で、Keychain の既定のアカウントのトークンを `CLAUDE_CODE_OAUTH_TOKEN` に入れてから起こすので、設定のフォルダを替えても既定のアカウントで動いてしまう。アカウントごとの関数は、設定のフォルダとトークンの両方をそのアカウントのものにする（2026-10-14 に持ち主の `~/.zshrc` の関数を読んで確かめた）。
   - herdr の `agent start` も使わない。素の `claude` を起こすので、アカウントを選べない。
7. **turn**: ペインと文を受け、`herdr agent prompt <対象> <文>` で送る。`--wait` を付けたときは、送った後に動き出したのを見てから、`idle`・`done`・`blocked` のどれかになるまで待ち、その状態を返す。
   - 1 ターン目は `/catchup <番号>` を `--wait` 付きで送る。`herdr agent wait` だけで待たないのは、help が「It does not track turns」と書く通り、ターンの区切りを追わず、始まる前の `idle` に当たりうるため。
   - 2 ターン目は、1 ターン目が `idle` か `done` のときだけ、2 ターン目の文を `--wait` 無しで送って終える。`blocked`（許可の確認などで止まっている）なら送らない。
   - こちらの手では期限を付けない。このリポジトリで作業する決まりの文書（直下の `CLAUDE.md`）が、期限とタイムアウトを新しく足すことを禁じているため。herdr に組み込みの見張り（`--wait` は、送って 5000ms 以内に動き出さなければ `agent_prompt_stalled` で返す）は、こちらが足すものではないので、そのまま受けて結末にする（判断）。
8. **report**: PR ごとに 1 行。番号、タイトル、作業場、アカウント、結末（`sent` 2 ターン目まで送った・`blocked` 止まっている・`stalled` 動き出さなかった・`already_open`・`no_slot`・`no_account`・`launch_failed` 起こせなかった・`send_failed` 送る命令が誤りを返した）。

PR が複数あるときは、launch を全部先に済ませてから、turn を PR ごとに並べて走らせる。1 件の `/catchup` が長くても、ほかの件が遅れないようにするため。

## 3. 作業場のノード（差し替える所）

slots と同じ出力の形を守れば、中身を替えてよい。assign と launch は、作業場がどう用意されたかを知らない。

最初の実装は **固定の作業場**:

- 設定にリポジトリごとの作業場の並び（herdr の workspace の名前と clone のパス）を書く。
- 空いているとみなす条件（どちらも満たす）:
  - そのペインに Claude Code の会話が無い（`pane list` の `agent` 欄が空で、シェルの入力待ち）。入力待ちの会話が残っている作業場は空きとみなさない。会話を閉じるのは持ち主だけ。
  - どのアカウントの会話（sessions）も、その作業場の path かその下を `cwd` に持たない。herdr が会話を見落としても、空きと誤らないため。
  - clone の追跡しているファイルに未コミットの変更が無い（`git status --porcelain --untracked-files=no` が空）。`/catchup` も同じ条件で枝を移る。
- 空きが無ければ、残った PR は `no_slot` になる。

後で足せる実装の例（今は作らない）:

- **PR ごとの作業フォルダ**: `claude --worktree "#<番号>"`（Claude Code 自身が PR の作業フォルダを作って、そこで会話を始める）や `herdr worktree create` で、PR ごとに作って終わったら消す。固定の作業場と比べてどちらがよいかは、ほかの人の並行作業の道具と herdr の使い方を調べてから決め、決めたらこの節に書き足す。作る実装は作業場を作る（外に書く）ので、そのときは slots を「作業場を選ぶ」と「作業場を作る」の 2 つのノードに分ける。

## 4. ノードの作りの決まり

倣う先は works-factory で、同じリポジトリの darkfactory（旧 works）の作りではない。持ち主の言葉は「works と新工場は少し作り方が違うので、引っ張られないようにしてね旧に」（2026-10-14）。決まりは 1 つずつ試験と対にし、試験で縛れないものは「人が見る」と書く。

- **D1 旧 works の部品に頼らない。** `works/dispatch/` は、`works/.shared/`・`works/dev/`・`works/darkfactory/`・`works/blk-*` のファイルを読まず、import もしない。darkfactory は works-factory に置き換わったら外されるので、頼ると一緒に壊れる。機械: `works/dispatch/` の字にそれらのパスが無い。
- **D2 処理は Python に置き、シェルの文字列に Python を埋めない。** 旧 works は起動の処理を sh の関数と、sh の文字列に埋めた Python に持ち、写しが食い違った。入口も Python にする。機械: `works/dispatch/` に `.sh` が無い。
- **D3 ノードは流れを知らない。** ノードは引数と JSON のファイルのパスで受け、JSON で返す。どのノードの次に何を呼ぶかは、入口の `works/dispatch/dispatch.py` だけが持つ（works-factory の、流れはグラフだけが持ち助け手は流れを知らない、の形）。機械: `works/dispatch/nodes/` のファイルがほかのノードを import しない。
- **D4 外に書くのは 2 つのノードだけで、書いた後に読み戻す。** launch と turn。機械: Python の構文木で見る。`subprocess` を import するのは外への口（`herdr.py`・`gitx.py`・`claudex.py`）と、whose-turn を呼ぶ prs のノードと、始める前の確かめを持つ入口だけ。herdr に書く 2 つの関数（`run`・`prompt`）を呼ぶのは launch と turn のノードだけ。字の書き方を変えても逃げられないようにするため、字では探さない。読み戻しは人が見る。
- **D5 こちらから期限を足さない。** 機械: `works/dispatch/` に `timeout` の字が無い（herdr の組み込みの見張りの結末の語 `agent_prompt_stalled` は除く）。
- **D6 持ち主の環境の値をリポジトリに書かない。** アカウントの名前、起動のコマンド、置き場のパス、使用率の控えの場所は、設定のファイルで渡す（works-factory の「既定の道は普通の利用者の環境でそのまま動く」と同じ）。機械: `works/dispatch/` に `raiki61`・`claude-code-oauth-`・`/Users/`・`claude-p` の字が無い。
- **D7 普通の利用者の環境でもそのまま動く。** 設定にアカウントが無ければ、`claude` 1 つだけのアカウントとして扱う。使用率の控えが無いアカウントは、使用率が分からないものとして選べる側に残し、順の最後に置く（判断）。人が見る。
- **D8 出力の形は schema に書き、試験がそれで照らす。** 機械: 各ノードの試験の出力が `works/dispatch/schemas/<名>.schema.json` に合う。

ほかの決まり:

- 各ノードは `works/dispatch/nodes/<名>.py` の単独のコマンド。入力は引数と JSON のファイルのパス、出力は JSON を標準出力か `--out <パス>` に書く。標準ライブラリだけで書く。
- 各出力の頭に `schema: 1` を置き、読む側は知らない版を読んだら止まる。
- herdr を呼ぶのは `works/dispatch/herdr.py` の 1 か所だけ。git と Claude Code（`claude agents --json`）も同じく 1 か所ずつ（`gitx.py`・`claudex.py`）に寄せる。herdr は互換を約束していない（herdr の文書は、手元の版の API を `herdr api schema` で確かめるよう求めている）ので、壊れたら直すのはこの 1 か所になる。
- `works/skills/dispatch/SKILL.md`: `/works:dispatch` の入口。`dispatch.py` を 1 回走らせ、出た報告をそのまま見せるだけ。判断はさせない。`dispatch.py` は端末から直に打っても同じに動く。
- `whose-turn.py` の場所: works は attention をそのまま呼べない（プラグインは 1 つずつ配られ、ほかのプラグインのフォルダは手元に無いことがある）。このリポジトリの写しの仕組み（`scripts/shared-copies.py`。正本を 1 つ持ち、写しが割れたら試験が赤になる）で、正本の attention から works へ写す。写すのは `whose-turn.py` と、それが読む部品（`attention/scripts/lib/outfile.py`）。

## 6. 始める前の確かめ

`dispatch.py` は、何かを起こす前に次を確かめ、足りない物を全部並べて止まる。

- herdr があり、サーバに届き、`herdr api schema` に使うメソッドがある。
- 設定のファイルと 2 ターン目の文のファイルがあり、形が合う。
- 使用率の控えが無いアカウントがあれば、止めずに 1 行出す（D7）。
- アカウントの起動のコマンドが、作業場のシェルで見つかる（`zsh -ic 'whence <コマンド>'` の形で、作業場と同じ種類のシェルに聞く）。
- `/catchup` を持つ attention が、各アカウントの設定のフォルダに入っている（`<設定のフォルダ>/plugins/installed_plugins.json` に `attention@raiki61` がある）。2026-10-14 には 4 つとも入っていた。
- `gh` が使える（whose-turn が使う）。

`--dry-run` を付けると、assign まで走らせて report を出し、何も起こさずに終わる。

## 7. 作らないもの

- 作業場を作る・消すこと（固定の作業場の実装では。差し替えの実装で扱う）。
- 会話を閉じる・止めること、`/clear` を打つこと。
- issue への割り振り（PR だけ）。
- こちらが足す期限・タイムアウト。
- 2 ターン目より後の操作。

## 8. 確かめ方

- 試験は `works/dispatch/tests/` に置き、旧 works の試験の殻（`works/tests/run.sh`）には載せない（D1）。CI で回す道は、リポジトリの根の試験の殻から呼ぶ形にし、計画で決める。
- 判断のノード（accounts・slots の判定・assign・report）は、速い段の単体テストで確かめる。外とのやりとりは偽物に差し替える。出力は schema で照らす。
- slots の約束（出力の形と、空きの判定の意味）を試験 1 つにし、差し替えの実装も同じ試験を通す。
- 外とのやりとりは、手元の herdr で `--dry-run` を走らせ、持ち主の今の作業場の一覧と照らして確かめる。実際に起こすのは、持ち主が見ている前で 1 件だけ試す。

## 9. 作り手に任せること

- ファイルの分け方の細部、関数の名前、schema の細部。
- 報告の行の形の細部（1 PR 1 行は守る）。
- herdr の `agent prompt` の対象（TARGET）に、ペイン ID を渡すかエージェントの名前を渡すか。手元の版の help と `api schema` で決める。
- launch で、herdr が会話を見つけて `idle` になるまでをどう待つか（会話が見つかる前のペインに `herdr agent wait` が効くか）。手元の版で、持ち主が見ている前で、空いている作業場 1 つで確かめてから決める。
- 既定のアカウントで、`CLAUDE_CONFIG_DIR=~/.claude` と明示した時と何も付けない時に、`claude agents --json` が同じ一覧を返すか。読むだけなので、作る前に確かめてよい。
- `claude agents --json` の `cwd` は会話を起こした時のフォルダで、会話の途中で別のフォルダへ移ったことは追えない。作業場は clone ごとに分かれているので実害は小さいと見るが、持ち主の前の確かめで、起こした会話が選んだアカウントの一覧に出るかと合わせて見る。
- 複数行の 2 ターン目の文を `herdr agent prompt` で送ったときに、途中の改行で送信されずに 1 つの文として届くか。同じく持ち主の前で確かめる。届かなければ、herdr の貼り付けの口か、改行の送り方を探す。
