## 3. 実測の script（AI なし・名前にも言語にも依らない）

入力はパスの一覧と、任意で差分（案の patch か、新しく足す名の一覧）。数え方は固定し、その規則も出力に書く。閾値で止めない（返すのは値だけ）。

- 行数と伸び: 今の行数、窓の始まり（既定 90 日前・引数で変える）の行数、その差。窓の始まりの行数は、その時の名前で数える（改名を追う）。浅い clone なら伸びも「測れない」と書く。
- 変更の頻度: `git log --follow` の回数を主の値にし、`--follow` 無しの回数（素の値）と、`--follow` 無しに `--no-merges` を掛けた回数も並べる（素の値との差はマージ、`--follow` との差は改名の揺れの信号）。値はパスごとに出し、複数のファイルを 1 つの単位で数える時は commit の和集合も出す。`--follow` は 1 本のファイルにしか効かないので（2026-09-29 に 122 件目の run で実測）、和集合は 1 本ずつ集めた commit の和で取る。`--follow` 無しは 1 度の git log に全部のパスを渡す。浅い clone なら数を出さず「測れない」と書く。
- 写しの在りか: 空行と空白を正規化した 6 行の塊をハッシュし、追跡ファイル全体の中で同じ塊が在る場所を並べる。言語の文法は見ない。
- 入口の数: そのファイルの名を名指す追跡ファイルの数と、そのうち実行できる物の数。
- 環境変数と設定の口: 大文字とアンダースコアの名を集め、一番多い接頭辞を自動で割り出す（接頭辞を決め打ちしない）。数え方は 3 つ（追跡ファイル全体・試験と文書を除く・読み書きの形に限る）を全部並べる。1 つの名が何ファイルに散っているかと、消す・上書きする所が何か所在るかも出す。
- 差分の形: 上の値が案でどう増減するかと、新しい名や口が既存の骨組み（すでに在る設定の表や関数）を通るか、殻ごとに直に読むかを、名が現れる場所の一覧で出す。汚れかどうかは判断しない。
- 単体の CLI として走る（`blk-structure/scripts/measure.py --paths … [--diff …]`）。全体を俯瞰する入口（依頼 112 番）もこの script を使い回す。

## 4. 構造の目

- 独立した会話の AI（opus）。見せるのは実測と単位の要約だけ。問いは 1 つ:「この案を入れた後、次に同じ領域を直す人が、設計を知らないまま足す形が増えるか」。
- 見る形は 6 つ:
  1. 共有の物を run や呼び手ごとに書き換える
  2. 責務を 2 か所に割る
  3. 既存の仕組みを横から曲げる
  4. ブロックの境をまたいで、他のブロックの中身を前提にする
  5. 骨組みの無いまま新しい名前や口を足す
  6. 外の道具の事情を名指しで抱え込む
- 返すのは、単位ごとの判定（汚れる・汚れない）、当たった形の番号、根拠にした実測の欄、理由。汚れないと見た時も、実測と理由を残す（黙って通さない）。
- 目の指示書には、試験の例に使う実物の名を書かない（書くと名前を覚えて当てるだけになる）。

## 5. 先例の調べ（汚れると見た時だけ）

役を 2 つに割り、間を機械で照らす（置き換わった元の設計。今の割り方（言い直す役と web の役）とその理由は計画 `docs/plans/2026-10-09-world-solution.md` の 5.2 節の「役の割り方の理由」。持ち主の言葉は安い模型を使ってよいという許しで、割り方の要求ではない）。

- 集める役（軽い模型。役の定義の前付けの model: で指定し、段の model: で渡す。依頼 118 番の仕組み）: 対象のファイルを読まない。検索語は、その形の一般的な言い方だけにする。返すのは URL と原文の抜き書きだけで、要約も評価もしない。
- 検索語の検査（機械）: 対象から取った識別子（パスの成分・環境変数の名・ブロックの名・run の id）が 1 つでも入った検索は捨てる。
- 抜き書きの照合（機械）: 抜き書きごとに、機械が同じ URL を取り直した本文に原文として現れるかを照らし、外れた物は落とす。落とした数も残す。
- 判断する役（opus）: 残った抜き書きだけを材料に、どの先例が効くか、一次情報か、古い版の話でないかを決め、設計の行を組む。1 行の中身は、推しの案 1 つ・捨てた案とその代償・推しの理由・先例の出典・形の番号・単位の id・行き先（自分で決める／人に上げる）とその理由。

## 6. 自分で決めるか、人に上げるか

関所でも設計のブロックでも、まず AI と機械が考える。人に上げるのは、考えても決まらない時だけ。

- 自分で決める: 先例がそろい、人の優先の付け方で答えが変わらず、人の前の決定（記録の human_items の履歴と方針の文書）とぶつからない時。決めた行は design.jsonl と報告に残し、修正の計画に渡す。
- 人に上げる: 先例が割れる・人の優先の付け方で答えが変わる・人の前の決定や方針とぶつかる、のどれかに当たる時。
- 設計の関所は、既存の関所を横から曲げず、blk-structure の中に新しい approval の節として置く。答えの口は「案 X を選ぶ」「全案 NG（言葉を添える）」「止める」の 3 つ。
- 全案 NG の時は、人の言葉を入力に足し、loop_group で構造の目から回し直す（実測は使い回す）。人が答える輪なので、AI だけで回り続けることは無い。

## 7. 事前審査とのつなぎ

- 事前審査は、段 B の実測と design.jsonl を見て、案が 6 つの形のどれかを取るなら、穴とは別の種（design）として挙げる。
- 写しの graph の穴の種の語は足せない（graphloops の版に縛られている）ので、盤面へは既知の語に写し、design の穴かどうかは design.jsonl の face の key の一覧だけで見分ける。説明文では見分けない。見分ける関数は 1 か所に置く。
- 穴の戻し先を 2 つに分ける: 細部の穴は修正役の義務として修正の段で吸収する（graph に計画へ戻る辺は無い）。選んだ形そのものが成り立たない穴は blk-structure へ戻す。同じ所（単位の id と形の番号）で 2 度目に設計へ戻る時は、難しい印として人に上げる。
- 2026-10-03 の持ち主の決定（依頼 231）で、細部の穴を修正の段で吸収する形をやめ、事前審査の block は壁打ちで修正案へ戻す（修正案の役に同じ会話で返して直させ、新しい会話の事前審査に掛け直す）。graph の写しに辺は足さず、engine の Board.rewind で役の節 2 つ（修正案 p2.fix_plan と事前審査 p2.plan_review）だけを同じ周の待ちに戻す。後ろの節（直す前の関所の節 p2.human_gate など）が受けた後は戻さない（守りが BoardGap で落とす）。同じ block が続いた（か 3 往復でも消えない）案は修正前の関所で止まる。依頼 226 の「Board.rewind を使わない」は修正の後の戻り（修正の出力・機械の節が絡む）についての決まりで、後ろの節がまだ走っていない修正の前の戻しには当たらない。選んだ形そのものが成り立たない穴の blk-structure への戻しは、先例の調べが入るまで同じ壁打ちで修正案へ戻る。
- 独立設計との隔て: 独立設計の役に渡す入力は明示した一覧で組み、structure.json と design.jsonl を入れない。独立設計の指示書に設計の行の id が現れないことを試験で縛る。

## 8. 記録・時間・撤収

- 人の選んだ案は、記録の human_items・報告の「人が決めること」・次の run の依頼の下書きの 3 か所に残す。決めた設計の置き場は対象の宣言（方針の文書など）に従い、宣言が無ければ報告に下書きを載せて人に聞く。人の答えなしに対象の作業ツリーへは書かない。
- 汚れない回も節ごとの壁時計の時間を残し、このブロックで増えた分を報告に 1 行で出す。
- 撤収: include 1 行・判定の単位を入力の契約の形に写す線の側の節 1 つ・修正の段の when の条件・穴の種の design を外せば元に戻る。design.jsonl は残るので、過去の判断は消えない。
- 判定の単位を契約の形（id・where のパス・要約）に写すのは線の側の節 1 つ（形の違う 2 者の間に翻訳の節を挟み、両方を変えない）。ブロックが判定役の返答の形を直に読むと、他のラインに差し込めなくなる（2026-09-29、138 件目の修正前の関所で決めた）。
