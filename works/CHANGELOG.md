# 変更の記録（works）

works（Archon の上の生産ライン darkfactory の pack と、Claude Code 側の入口 `/works` スキル）の版ごとの、利用者に効く違いを新しい順に並べる。形は [Keep a Changelog 1.1.0](https://keepachangelog.com/ja/1.1.0/) に従い、版の番号は [Semantic Versioning](https://semver.org/lang/ja/) の形（x.y.z）で振る。節は Added（足した）・Changed（変えた）・Deprecated（やめる予定）・Removed（消した）・Fixed（直した）・Security（安全の直し）のうち、中身の有るものだけを使う。

版を名指しする git の tag（例: `works--v0.2.0`）の名前の決まり・付け方と、この記録を書き足す段は、リポジトリのルートの `docs/releasing.md` に在る。0.1.0 はこの記録に無い。

## [Unreleased]

### Added

- 構造の実測の単体 CLI `blk-structure/scripts/measure.py --paths … [--since YYYY-MM-DD | --window-days N] [--max-bytes N]` を足した（設計書 `docs/specs/2026-09-29-structure-block-design.md` 3 節のうち差分の形を除く 5 つ）。行数と伸び（窓の始まりの行数は改名を追ったその時の名前で数える）・変更の頻度（`--follow`・素の値・`--no-merges` をパスごとと和集合で）・6 行の写し・入口の数・環境変数の接頭辞と 3 つの数え方を、数え方の規則ごと JSON 1 つで出す。浅い clone では頻度と伸びを「測れない」と書き、読めない・大きすぎる・追跡されていないパスは skipped に理由つきで並べて続ける。標準ライブラリだけで、ほかのリポジトリでも単体で走る。ブロックの YAML とラインへの差し込みはまだ無い。

### Changed

- 開発の殻の全体の模型 `WORKS_DEV_MODEL` の既定を埋めるのは `dev/archon.sh` だけになった（既定の値は `dev/guard.sh` の `WORKS_DEV_MODEL_DEFAULT`。環境では替わらない）。`use.sh`・`dogfood.sh`・`real-run.sh` は未設定のまま渡し、`archon.sh` は明示か既定かを `WORKS_MODEL_FROM` に残して下へ渡し、解いた値を `WORKS_DEV_MODEL` に書き戻さず `WORKS_MODEL_RESOLVED` で渡す。模型を明示せずに起こした run の控えの `model` は空で、start の時に解いた値と出どころを `model_resolved` に残す。続き・答えの行は空の指定にその既定を別の名 `WORKS_MODEL_PINNED` で添えて起こし、run の途中で既定を解き直さない（`archon.sh` は出どころにその名を残し、Archon には継がせない。入口の殻 `use.sh`・`dogfood.sh`・`real-run.sh` は起動の時にその名を外し、控えから来た値だけを受ける）。今までは入口ごとに opus を埋めていたので、既定と利用者が opus を明示した run が見分けられず、再開では既定が明示に化けていた。
- 差分の審査の後の手直しの役（`blk-refix` の refix・refix2）にも、修正の決まりの正本（根本の単位ごとに直す・同じ形を全部直す・既製の物を先に確かめる・動きを変えたら文を直す・証拠・食い違いの申し出）が届くようになった。正本を `blk-fix/rules/common.md` から共有の置き場 `.shared/core/writerules/common.md` に移し、組み立ての口 `.shared/core/rulebook.py` を `blk-fix` と `blk-refix` が同じように通す。手書きの `blk-refix/commands/refix.md`・`refix2.md` は消した。手直しの役の指示書は正本の全節を載せるので長くなる。今までは手直しの役の指示書が手書きで、修正の決まりの句が 1 つも入っていなかった。
- テストのコマンド（`test_cmd`・blk-tests の `cmd`）は、シェルが要る形の時だけ `bash -c` で起こし、ほかは語に割って直に起こす。シェルに渡すのは、割れない・展開や区切りや向け直しや引用や注釈や改行の字を含む・代入で始まる・先頭の語が bash の組み込みか予約語、のどれかに当たる時。どちらで起こしたか（`direct`・`shell`）を素材の文・最後のテストの出口 `test_cmd_how`・mid の結果とログ・報告の「走らせた」の行に出す。直に起こして見つからなかった時は、`BASH_ENV` や `export -f` のシェルの関数に頼るなら `bash -c '…'` で包んで書く、と添える（`bash -c` の非対話では alias はもともと展開されない）。今までは単純なコマンドも毎回 `bash -c` で起こし、どちらで起こしたかが記録に無かった。
- 0.2.3 の Fixed の「`bash -c` 越しの終了コード 126・127 は起こせなかった疑いと名指して、普通の赤と分ける」をやめた。126・127 はプログラム自身の終了コードとして、普通の赤と同じに読む。起こせないのが確かな時（起こす前の証明で落ちた・直に起こして見つからない）は今までどおり「環境で起こせなかった」（not_run）になる。
- 3 つの役（調べ役 investigator・点検役 inspector・初見の読み手 cold-reader）を起こす 12 段を、Archon の段の標準の欄 `model: sonnet` で Sonnet で動かす。ほかの段は今までどおり全体の模型（既定 opus）で動く。模型の正本は役の定義の前付けの `model:` で、段の `model:` がそれと一致することを試験が縛る（固定する模型の集合は試験の宣言 `PINNED`）。Archon は段の値を全体の値より先に効かせるので、`WORKS_DEV_MODEL` はこの 3 役には効かない。包みを外した run でも同じに効く。使う枠が減る。
- 0.2.3 の Changed の「remote の `origin` も求めない」をやめた。`use.sh check` は remote の `origin` の無い対象を足りない物として入れ方つきで並べ、`start` は Archon も pack の写しも起こさずに 1 行で止まる（`git remote add origin <URL>`、手元だけなら対象の外の裸のリポジトリを案内する。殻は remote を書き換えない）。Archon v0.11.1 は `--from` を渡しても origin の無い対象では run の worktree を切れず、終了コード 1 で落ちると測れたため。今までは check が緑のまま、start が Archon を起こして落ちていた。

### Fixed

- 判定が保留した問い（fork・escalate）が、修正の前の関所にも最後の関所にも報告にも出ずに飛ばされることがあった。保留の問いを読む所を 1 か所にまとめ、4 か所とも必ず並べる。保留が 1 件でも在れば「盤面の問い: 無い」と書かない。無人の run でも報告の冒頭に並べる。人が関所で答えた問いの出どころの単位は、直す義務に戻す（答えた後に `not_done` で逃がさない）。

## [0.2.3] - 2026-09-29

### Added

- `use.sh` に、関所で待つ run を進める・答える・止める口と、終わった run を片付ける口を足した: `approve <対象> <run-id>`（起動の関所を越える）・`answer <対象> <run-id> continue|stop "<一言>" "<答えた者>"`・`stop <対象> <run-id> "<理由>"`（関所で待つ run は答えの stop、走っている run は止め札）・`wait <対象> <run-id>`（決まった時間 `WORKS_USE_WAIT_SECONDS`、既定 540 秒のうちに戻り、状態を 1 行と終了コード（0 = 関所で待つ・3 = まだ走っている・5 = 終わった・1 = 落ちた）で返す）・`apply <対象> <run-id>`（差分を書き直し、`git apply --check` の後に当てる。commit はしない。ファイルを消す差分は `WORKS_USE_ALLOW_DELETE=1` の時だけ当てる）・`clean <対象> <run-id>`（終わった run の worktree と枝を消す。走っている・関所で待つ run は拒む）。`approve`・`answer`・関所で待つ run の `stop` は残りの工程を切り離して回してすぐ戻り、出力は `<利用の家>/logs/` に書く。今までは答え・止め方・差分の取り込み・片付けを、利用者の PATH に無い `archon workflow respond` や `git apply`・`git worktree remove` を手で打つ形でしか書いていなかった。
- `use.sh answer` は答えた者（第 6 引数）を必須にし、一言と一緒に `<利用の家>/answers.jsonl` に残す（省くか空白だけなら拒む）。`/works` スキルには、人が決める関所（修正の前の関所と最後の関所）を回す Claude が自分で通さず、依頼者に聞いてその言葉で答えるよう書いた。`continue` の後ろに `--exclude <単位の番号>=<理由>` を足すと外す単位を盤面の `answer-detail.json` に残せるが、今の版の線はまだそれを読まない（外した単位も直す義務に数える）。
- `use.sh start` に変更から入る口を足した: 旗 `--base <版>`（base と HEAD の merge-base から HEAD までの差分）か `--pr <番号>`（`gh pr view` で読むだけで投稿しない。対象の HEAD が PR の head でなければ拒む）で、差分に局所の審査の目を回す。変更だけなら依頼の JSON を `-` にし、依頼も渡せば差分の目と依頼を一緒に判定へ流す。旗は対象より前に置く。今までは依頼の JSON から判定に入る形しかなく、枝や PR の審査を頼めなかった。
- `use.sh start` がラインの入力 `policy_md`・`gates`・`thickness` を env の `WORKS_USE_POLICY_MD`・`WORKS_USE_GATES`・`WORKS_USE_THICKNESS` から渡す。`WORKS_USE_UNATTENDED=1` で無人の run にでき、起動の関所を越え、人が決める関所に着いたら止めて報告へ進める。今まではこれらを `use.sh` から渡せなかった。
- `use.sh show` が、状態の下に `launched_min`（起こしてからの分）を出し、走っている run では今走っている節・`alive`（最後の動きから 30 分以内なら true）・節ごとの費用を出す。run id を後ろに足せば、その run について出す。今までは走っている run が止まっているのか動いているのかを見分けられなかった。
- 認証で、`CLAUDE_CODE_OAUTH_TOKEN` と `WORKS_KEYCHAIN_ITEM` がどちらも無い時に、macOS で Claude Code 自身が keychain に置いたログインの項目（`CLAUDE_CONFIG_DIR` から名を導く）を拾う。拾った出どころの名を 1 行出す（値は出さない）。今まではトークンを作って置かないと回せなかった。ログインのトークンは数時間で切れるので、長い run には今までどおり `claude setup-token` で作るトークンを置く。
- `use.sh check` が、Archon の validate に加えて、`start` に足りない物（uv・claude・認証・対象の条件）を入れ方つきで全部並べ、1 つでもあれば 0 以外で終わる。今までは足りない物が `start` を打つまで分からず、しかも 1 つずつしか出なかった。
- 対象の根の mise の設定を利用者が `mise trust` 済みなら、`archon.sh` が run の worktree の置き場を `MISE_TRUSTED_CONFIG_PATHS` に足す（前の値は残す。信頼していない対象では足さない）。今までは run の worktree が別のパスなので mise の設定が信頼されず、run の中のテストが道具の失敗で偽の赤になった。
- herdr の枠の中（`HERDR_ENV=1`）で `use.sh` を打つと、起動・`show`・`wait` のたびに、その枠から起こした run の集計（人の番・走る・終わった）を 1 つの信号で枠に出し、全部終わった時だけ外す。
- works の `plugin.json` に、借りる 3 つ（superpowers・coldwrite・pr-review-toolkit）を依存（`dependencies`）として書いた。今までは宣言が無く、works が 3 つに依ることが Claude Code から見えなかった。

### Changed

- 独立設計（R2 の設計の半分。目的だけから理想解を作る道具ゼロの役）を、最後のテストの後ではなく修正案と同じブロックで修正の前に作る。修正案の事前審査の指示書の頭にその設計を貼り、案と設計の構造の食い違いを block の穴として挙げさせる。最後の R2 は先に作った設計と差分の比較だけを回す。今までは設計が修正と最後のテストの後にしか作られず、作り直しが要ると分かっても同じ run に直す周が無かった。設計は作り直さないので、比較の頭に修正の中で申告された前提のずれと記録の制約を貼り、設計の前提を崩していれば「設計の前提が変わった」と理由つきで出させる（`darkfactory/downgrades.json` に下げた所として載せた）。設計の役が 3 回とも拒まれても修正案・事前審査・修正・最後のテストは止めず、事前審査は設計なしで進み、最後の R2 が「独立設計が取れなかった」と言って目の層で止める。直す物の無い判定でも、設計を作るために修正案のブロックへ入る。
- 修正の受け付けが、閉じたかを判定役の問いの数え直し（修正前の版と修正後の作業ツリー）で決め、修正役の申告（塞いだ site の件数・remaining）と合わない時は返答を拒まずに単位ごとの表（盤面の置き場）に記録する。合わない単位は最後の人の関所を開けて並べ、報告にも載る。今までは申告が数え直しと合わないだけで返答全体が拒まれ、輪の最後の回は拒否の文の句を照らして単位を外していた。輪の最後の回は、写しの受け付けの拒否も凍ったテスト・赤い試験と同じく単位の key かファイルで 1 単位に結べればその単位だけを戻して人に回し、残りの単位で通し直しが通らなければ戻した直しと裁定を元に戻す。
- 依頼のファイルが在る run の裁定役の `ask_human` は、裁きの出どころ（`grounds`）に依頼の行を挙げるか、`request_searched` に依頼で何を探して答えが無かったかを書かないと拒まれる。`grounds` の名指しは機械が現物で引く。今までは依頼に先に書かれた人の答えを読んだかが残らなかった。

- 素材集めの p1.local_review の受け付けが、必須のレンズを起こさなかった返答と、そのまま material を awaiting_human にした返答を拒み、同じ会話で起こし直させる。拒みが 3 回目に届いた時だけ人に渡す。今までは最初の失敗で run が人待ちに止まっていた。レンズのプラグインが隔離した設定に入っていない時は、起こし直しても毎回落ちるので、プラグインを名指してすぐ人に渡す。`/simplify` の持ち越し（`simplify_carried: true`）は、本流と同じ条件（前の周から 1 ファイルも変わっていない周）の時だけ認める。写しは本流の `changed_since_prev_round` を出さないので、写しが周ごとに残す周の頭の版の木を前の周と比べて決める。写しの指示書の「ロジック変更が無いなら持ち越してよい」より狭く、どれかのファイルが変わった周と 1 周目は `/simplify` を起こし直させる（役への読み替えの文にもそう書く）。条件付きのレンズ（`/security-review`）の失敗は今までどおり受ける。
- `use.sh start` の対象の条件を緩めた。対象はリポジトリの下のフォルダでもよく（git の根で回す）、省けば今いるフォルダの git の根。commit していない変更・未追跡のファイルが在っても止めず、一時の index で包んだ commit（`.gitignore` の物は入れない。対象の作業ツリー・index・枝は動かさない）から run を切り、「包んだ（wrapped）」の行に出す。包んだ commit は `refs/works/wraps/<commit>` で守り、`clean` が run と一緒に消す。remote の `origin` も求めない（無ければ 1 行で知らせる）。`test_cmd` も省ける（対象の宣言か CI の役に任せる）。今までは汚れた対象・`origin` の無い対象・根でないフォルダを 1 行で拒み、`test_cmd` は必須の引数だった。
- `use.sh` の既定を変えた。最後の関所は要る時だけ開く（`when_needed`。毎回開くなら `WORKS_USE_FINAL_GATE=always`）。Claude の包みは既定で通す（外すなら `WORKS_DEV_ADAPTER=0`。起動の 1 行目と報告に「包み無し」と出る）。今までは最後の関所が毎回開き、包みは `WORKS_DEV_ADAPTER=1` を付けた時だけ通ったので、付け忘れると包みの守り無しで回った。
- 対象に `.review-checks.json` の宣言が在っても、渡した `test_cmd` を宣言の一式の後に走らせ、両方が緑の時だけ緑にする（宣言の段と同じコマンドなら 1 度だけ）。最後の関所と報告に、走らせた一式・環境で起こせなかった段・走らせなかった物を 1 行で並べる。今までは宣言が在ると渡した `test_cmd` は走らず、何を根拠にした緑かも出なかった。
- TDD の輪と修正の受け付けが、修正役が足した・変えた試験を、実行器の既定の一覧の外に在っても回す。`tdd_suite` の実行器は、後ろに試験のファイル・node id（絶対パス）と `-k` を足して呼ばれることがある。受け付けは、元の結末に無い試験の赤を版の姿（一時の写し。作業ツリーは動かさない）でも回し、版でも赤なら外す。選んだ試験が 1 件も走らなかった時は「新しい赤なし」にせず知らせる。今までは一覧の外に書いた試験が走らないまま通った。
- 修正前の関所で、修正案の狭めと事前審査の後退・方針の穴の行のうち、役が決め手の出どころ（依頼の引用・URL と節・本流の同じ場面・持ち主の前の決定）を書き、決め手を当たっても答えが割れず、柵（外への書き込み・取り消せない操作・方針の文書の変更・守りを広げる・web の結果が新しい疑いを出した）に当たらない行は、人に聞かずに通す。通した行は出どころつきで報告の冒頭にいつも並び、最後の関所が開いた時はその文にも並ぶ（通した行だけでは既定の最後の関所は開かない）。今までは決め手が明らかな行も全部関所に出て、人の答えを待った。
- run の中で試験を起こす所（宣言の段・`test_cmd`・最後のテスト）が、機械全体の重いテストの枠（台本は `WORKS_TESTSLOT`。同時に 4 本まで）を通る。枠を待つ間は `use.sh show` に `試験の枠: 待っている（N 分…）` の 1 行が出る。台本が無い・枠の置き場に書けない機械では 1 行出して枠を取らずに回す。今までは並べた run の重い試験が同時に何本でも走った。

### Security

- Claude の包みが、道具を持つ役の system prompt に「検索語に対象の名前を載せるな」の規律（写しの `agents/judge.md` の塊を字のまま）を足す。今までは works の役の指示書にこの規律が無く、WebSearch・WebFetch の問い合わせに対象のリポジトリ名・本文が載りえた。SDK が `--append-system-prompt-file` を渡す起動と、規律の正本を読めない起動は起こさない。包み無しの run には載らない。
- Claude の包みが、対象リポジトリの `.claude/settings.json`・`.claude/settings.local.json` の `permissions.deny` を役の `--settings` に写す。今までは役が隔離した設定で起きるため持ち主の禁止（例: e2e の一式を手元で回さない）が役に効かなかった。ファイルが読めない・形が違う時は、そのファイルを名指して役を起こさない。包み無しの run には載らない。
- Claude の包みが、AI の役の子の env に `GRAPHLOOPS_ENGINE_CHILD=1`（graphloops の engine と同じ目印）を立てる。今までは works の役に目印が無く、対象の重い一式（e2e・変異の撃ち）が AI の役からの起動を見分けて拒めなかった。線の節が走らせる最後のテストと、包み無しの run には立たない。

### Fixed

- 報告が、周の記録の検証器の阻害（1 周目にいつも出る帳尻の行「前ラウンドの記録が無い…」を除く）・最後のテストの赤・独立の目の block が残った run にも `fixed` を出していた。残りが 1 つでも在れば新しい結末 `round_limit` にし、報告の冒頭 1 と次の run の依頼の下書きに残りの各行を出す。
- 報告の費用の行がいつも「取れない」だった（Archon v0.11.1 の実物に無い平らな `cost_usd` と `workflow_completed` を読んでいた）。節の費用は実物の `data.spend.costUsd` を読み（報告された費用は Archon の `executionSpendSchema` の `{source: provider, value}`）、報告されなかった費用（`source: unavailable`）は 0 と混ぜずに見た欄・`reason`・版を添えて「取れない」と出す。報告は run の中で走るので run の和は読まず、合計は節の和を「途中」として出す。会話を継いだ起動の費用は、`costUsd` が累積か 1 回分かを測れていないので引かず、「累積かどうか未確認」と添える。0.2.2 の「`cost_usd` だけを読む」決定を上書きした。
- 走っている run の `use.sh show` が、節ごとの費用をいつも「取れない（report を読めない…）」とだけ出していた（報告の費用の直しで消えた関数を呼んでいた）。報告の費用の行（`report.head_cost`）をそのまま出す: 節ごとの `data.spend.costUsd`、報告されなかった節の件数と理由（合計に数えない）、1 つも取れない時の「取れない」、欄の形が未確認の印、run の中の和を読まない途中の節の和。
- AI の報告の初見の読み手が「作り直しが要る」（redesign-needed）と言っても、書き手に戻らずにそのまま報告が出ていた。書き手が本文を書くたびに、道具を持たない初見の読み手がその頭（平易な冒頭と人が決めること）だけを読み直し、redesign-needed なら止まった所・推測で埋めた所を理由にして書き手に書き直させる。出し直しの上限の回は受け取り、報告の冒頭（来歴の行の直後）に「初見の確かめを通っていない: <理由>」と出す。
- 関所の文（仕様の承認・修正の前の関所・最後の関所）と起動の関所の文が、答え方に利用者の PATH に無い `archon workflow respond`・`approve --detach` を書いていた。起動した殻の行（`use.sh` なら `use.sh answer <対象> <run-id> …` と `use.sh show`・`wait`、`dogfood.sh` なら隔離した `archon.sh` の respond）で書く。
- `use.sh show` と `start` の後の表示が Archon の run の一覧の先頭を選んでいたため、同じ家から並べて起こした別の run を出すことがあった。`start` は起動の直後に、この起動の依頼を盤面に持つ run を 1 つに結んで控え（`<利用の家>/runs/<run-id>.json`。模型・claude の実行ファイル・keychain の項目の名・包み）を書く。run id を省いた `show` はその対象で結んだ一番新しい run を出し、結べなければ候補の run id と `show` の行だけを出す。別の殻で打つ `answer`・`stop` と、`show` が出す続きの行は、控えの値で Archon を起こす。
- テストのコマンドを起こせない（先頭の語が見つからない・実行できない）時に、落ちたテストの赤に数えていた。起こす前に先頭の語を `command -v` で引き、引けなければ走らせずに「環境で起こせなかった（コードの赤ではない）」（not_run）にする。`bash -c` 越しの終了コード 126・127 は「起こせなかった疑い」と名指して、普通の赤と分ける。
- resume で続けた run の報告が、前の試みで落ちた下流の節（報告より後の節）の失敗を今の失敗に数え、結末を `interrupted` にしていた。前の試みで落ちて続きで済んだ節は、止めた理由でなく冒頭 3 の試みの記録として出す。
- Claude の包みを通す run で、AI の役が 1 手も進まずに終わった（assistant の行が無く `num_turns` が 0）時、SDK がそれを型に合わない答えとして扱い、Archon が起こし直さずに節が落ちていた。包みはその result を Archon へ写さずに終了コード 75 で返して Archon の起こし直しに任せ、全文を包みの置き場の `exits/` に残す。報告にも節ごとの回数が出る。
- `use.sh show` と `dogfood.sh` が、差分が空（起動の直後の関所など）でも 0 バイトの差分ファイルと取り込むコマンドを出していた。空なら書かず、前に書いた同じ名のファイルを消す。`dogfood.sh` が出す承認・関所の答え・続きの行は、Archon が戻った後に差分を書き直す（書き直すだけの口 `dogfood.sh --show <dir> <run-id>` も足した）。今までは関所に答えた後も差分が古いまま残った。

## [0.2.2] - 2026-09-28

### Added

### Changed

- darkfactory の独立の目（R1〜R4）を、最後の人の関所の後から前へ移した（最後のテスト → 独立の目 → 最後の関所 → 報告）。関所の全文に目の判定と、R4 が人に聞く問いが載る。人は審査の結果を見てから答える（graphloops が r4.human_gate で聞くのと同じ順）。`final_gate: when_needed` でも、目が阻害（redesign-needed・unverifiable・premise-invalid）を返せば関所が開く。関所の `continue` は R4 の問いには答えない（問いは今までどおり報告の冒頭と次の run の依頼の下書きへ渡る）。`stop` しても目の費用は戻らない（目はもう回っている）。
- 報告の費用の行: 節の費用は Archon の `node_completed` の `cost_usd` だけを読む（推測の別名 `costUsd`・`total_cost_usd` は読まない）。合計は節の和でなく Archon の run の和（`workflow_completed` の `cost_usd`）にし、節の和と食い違えば両方を出す（包みの節と子を二重に数えうるため）。run の和がまだ無い run は、節の和を「途中」と添えて出す。

- 判定役の欠陥を数える問い（class_query）に「当たる例・当たらない例」を添えられるようにし、判定の時点で例を問いに当てて、合わない問いを単位の名指しで拒む（Semgrep の規則の試験と同じ形）。例の無い問いは今までどおり受ける。
- 修正の返答が輪の最後の回に数え合わせで拒まれた時、その単位だけを人に回して（裁定 ask_human）残りの直しを受ける。今までは 1 単位の食い違いで run 全体が止まった。
- 借りる道具（superpowers・coldwrite・pr-review-toolkit）を、Claude Code が実際に読み込む scope の `installed_plugins.json` の行から取る。知らない形の `installed_plugins.json` や、勝った scope の置き場が消えている時は、下の scope へ戻らずに名指しで止まる。入れたが無効にした物も今までどおり借り、有効・無効を記録に残す。
