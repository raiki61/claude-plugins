# works: 報告の読み方・結末・差分の取り込み・片付け

/works のスキルの本文（このフォルダの 1 つ上の SKILL.md）から指される別ファイルで、run が終わって `show` で報告を出した時と、差分を `apply` で当てる・`clean` で消す時に読む。殻・盤面・鎖・報告の冒頭 1〜3 などの語は SKILL.md の「語」に在る。命令の頭の `<works の置き場>` は、SKILL.md の命令の置き場（入れたプラグインの置き場の絶対パス）に読み替えて打つ。

打つのは SKILL.md の「命令」の `show` の行（`sh "<works の置き場>/dev/use.sh" show <対象リポジトリの根> [<run-id か鎖の id>]`）。

その対象で start が結んだ（控え `<家>/runs/<run-id>.json` の在る）一番新しい run について、状態・報告の置き場・差分のファイルを出す（run id を後ろに足せば、その run について出す）。start は起動の直後に、この起動の依頼を盤面に持つ run を 1 つに決める（結ぶ）。結べなければ候補の run id と show の行だけを出すので、その run id を名指しして show する（依頼を `-` で省いた start は結ぶ依頼が無いので、いつもこの形で終わる）。状態の下には `launched_min`（起こしてからの分）が出る。走っている run なら、今走っている節・`alive`・`持ち主:`（Archon が run に刻む持ち主の host・pid が、この機械で今も同じ process として居るか。生きている・消えた・確かめられないの 3 つと理由）・節ごとの費用 `cost_usd` も出る。`alive` は持ち主が生きていれば静かでも true、消えていれば false（長い節で静かなだけの run と、Mac の停止などで持ち主が消えた run を見分ける）。持ち主が確かめられないのは、別の host の run・持ち主の記録が無い古い run・番号が使い回されたかもしれない run の 3 つで、この時だけ `alive` を、最後の動きが 30 分以内なら true、それより前なら false にする。持ち主が消えた run には、Archon が拒む承認・取り消し・続けるの行を出さず、記録を閉じる `abandon` の行と、起こし直す案内（元の依頼・渡した入力・run の基の版）を出す。試験の段が機械全体の試験の枠（同時に 4 本まで）の空きを待っている間は `試験の枠: 待っている（N 分・置き場 …）` の 1 行も出る（期限なしで待つので、止まった run と見分けるための行。枠の中なら `試験の枠: 中`）。

- 報告: 盤面の `report.md`（冒頭に決めてほしいこと・入口・止めた理由・読んだ証拠・置き場）と `next-request.json`（次の run に渡す依頼の下書き `{"findings": [...], "prior_failures": [...]}`。下書きの印の無い行はそのまま次の run の依頼に使える。判定が凍結した目的の外として単位にしなかった材料の所見（最後の周の分）も、材料の行の全部の欄で `findings` に載るが、`draft: true`・`source` の印つきで、依頼の入口が拒む——依頼者に見直してもらい、次の run の目的に入れる行は印を消し、入れない行は消す（人が決めることではなく次の run に回すかの材料なので、報告の「1. 人が決めること」には件数と置き場だけが載り、1 件ずつの中身は本文の節「判定が目的の外とした所見」に在る）。保留のままの問い（人の居る run でも）・問いの立っていない run の中で測れなかった素材・無人の run が関所で止めた項目を残した時だけ、答えの下書き `answers`（`draft: true`・`source` つき。推しの無い行は `text` が空で、材料は `note`）が足され、それは依頼者が見直すまで使えない。下書きの `question` は答える時に字のまま書く名で、報告の保留の行の尾「答える時の answers の question: "…"」と同じ）と `prior-failures.json`（この run で最後まで通らなかった受け付けの理由と R2 の作り直しの理由）。
- 結末（run の出口の `outcome`）: `fixed`・`fixed_needs_check`（直しは受け付けを通り最後のテストも緑で、残ったのが run の中で測れなかった確かめ——例えば、同じ所を触るほかの PR が無いかを gh で見る確かめ（並行 PR の確かめ）が、役の sandbox が網（ネットワーク）を拒んで回らなかった時や、直した経路を実際に動かして見る観測がクラウドの資格を要した時。こうした確かめの材料（素材）が未実施か、人が起動するのを待つだけ——の時。報告の冒頭 1 に「人が確かめる物」として各行が並び、次の run の依頼の下書きにも今と同じく載る。手元で確かめたら、次の run の依頼の `answers` に素材の名と `command`・`output` を添えて返す。`use.sh apply` は `fixed` と同じく当てる）・`no_fix_needed`・`round_limit`（直しは受け付けを通ったが、検証器（直しの記録を機械で照らす確かめ）が阻んだ・最後のテストが赤・独立の目（直しを別の役が 4 つの観点 R1〜R4 で審査する目）が阻む（block）と返した、のどれかが残った、または受け止めると宣言した段が落ちて確かめていない。冒頭 1 に残りの各行。本線 graphloops の runner の `round_limit`＝`--stop-after-round` の周で止めた、とは別の意味）・`stopped_by_human`（関所で止めた）・`stopped_by_request`（止め札）・`stopped_by_line`（機械が止めた）・`needs_human`（盤面が人に聞いたまま）・`record_invalid`（周の記録が検証器を通らない）・`interrupted`（run が途中で終わった。冒頭 3 に落ちた節。ただし、線が「落ちても受け止める」と宣言した段（`[optional]`）だけが落ちて、線の終わりまで届いた run は `interrupted` にしない。その run は冒頭 3 に受け止めた節の行が並び、落ちた段は確かめていないので、結末は `fixed` にならず、その段が残りに載る）。
- 差分: run の worktree と周の頭の版の差（手直しと未追跡も入る）を、利用の家の `diffs/run-<id>.diff` に書く。修正は commit されない。取り込むかは人が決め、`sh "<works の置き場>/dev/use.sh" apply <対象リポジトリの根> <run-id>` で当ててから、手元でテストを回して commit する。`apply` の時、殻は差分を盤面から書き直し、`git apply --check` で当たるかを先に見る。対象のファイルを消す差分は、消すファイルを並べて止まる（消してよければ `WORKS_USE_ALLOW_DELETE=1` を前に付けて打ち直す）。記録が止まりを示す run（人が最後の関所で `stop` と答えた・止め札・ラインの止め）の差分は、止まった結末と一言を 1 行で出して止まる。当てるのは依頼者が当てると決めた時だけで、`WORKS_USE_ALLOW_STOPPED=1` を前に付けて打ち直す。止まったかを記録で確かめられない run（途中で終わった・関所で待つ run など）は、止まった run と言い切れないので旗なしで当て、確かめられなかったことを 1 行出す（当てるかは、ほかの run と同じく依頼者が決めてから打つ）。鎖（`--rounds`）の差分は run の id でなく鎖の id を渡す: `apply <対象リポジトリの根> <鎖の id>` が、鎖が止まった時に書いた最後の差分 `final.diff`（元の基から、止まりと言われていない最後の周の結果まで）を同じ確かめで当て、`show <対象リポジトリの根> <鎖の id>` が周ごとと合計の報告 `chain.md`（周・run・結末・分・費用・残り・ファイルと止めた訳。読めない費用は「読めない」と書く）を出す。独立の目 R2 の作り直しが残ったまま止めた鎖は、報告の頭に「閉じていない」と出る。取り込み終えたら `clean <対象リポジトリの根> <鎖の id>` が鎖の控えと周の結果を守る参照を消す。
- 片付け: 次の物は自動で片付く。run の worktree・枝・控え（`start` が手元の変更を包んだ一時の commit を守る参照）と、修正の段が直す単位ごとに run の worktree から切った worktree・それを守る参照（`refs/works/units/` の下）。正常に終わった・取り消した run（状態 completed・cancelled）は `wait`・`show` が差分を書き終えた後に消し、落ちた run（failed）などの生きていない run は次の `start` が差分を書いてから消し、落ちた run の Archon の記録も abandon で閉じる。差分を書けなかった run と、走っている・関所で待つ run は残す。差分のファイルと盤面は残るので、取り込みは片付けの後でも `apply` で当たる（片付けた run は Archon の resume で続けられない）。`start` が片付けた run の id と状態は、`start` の出力と報告の冒頭 2 に出る。手で消すのは `sh "<works の置き場>/dev/use.sh" clean <対象リポジトリの根> <run-id>`（走っている・関所で待つ run は拒む。落ちた run は Archon の記録も abandon で閉じるので resume できなくなる。worktree がもう無い run でも閉じる）。
- `report_file`: 最後の報告。盤面が報告の節を出した run（人か止め札で止めた・収束した）では AI が書いて初見の読み手が確かめた `report-ai.md`（最後に機械の報告が字のまま付く）、そうでなければ機械の `report.md`。機械の報告はいつも `machine_report_file`。
