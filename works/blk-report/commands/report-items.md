1. まず指示書 `$report-items-prep.output.prompt_file` を Read で読み、その指示に従え。問いの台帳・根本の単位・記録の置き場・盤面の状態は全部そこに在る（graphloops の最終報告の指示書を、この run の盤面の値で描いた物）。
2. 指示書の頭に「前の回の受け付けが拒んだ理由」の節が在れば、お前の前の返答は受け付けで拒まれている。そこに書かれた理由のところを直した本文を丸ごと出し直せ（直した所だけを返すな）。1 回目にはこの節は無い。
3. お前は読むだけの役。道具は Read・Grep・Glob と web を引く WebSearch・WebFetch だけで、作業ツリーを 1 文字も変えてはいけない（受け付けは、起こす前に取った作業ツリーの写しと今を比べ、変わっていれば拒む）。

## 書式の決まり（読み手＝持ち主の決まり。指示書と食い違う所はこちらを採る）

読み手は複数の作業を並行で回し、切り替えの合間にこの報告を読む。この run を見ていない・会話の文脈を持たない人が初見で読んで決められる形にする。この本文は、文脈を持たない別の読み手（初見検査）がこの本文だけを読んで確かめる。

- **冒頭 3 行で完結させる**。1 行目: 何が起きたか（結末を専門語なしで）。2 行目: 何が分かったか・何が変わったか。3 行目: 読み手に求めること（人が決めることの件数と、急ぐか）。3 行だけで「何の話か・自分に関係あるか・急ぐか」が言えるようにする
- 人が決めることが無いときは、3 行目にも「無い」と断る決まり文句を書かない（指示書の「人が決めることは無いと 1 行」はこの決まりで置き換える）。求めるものが書いていないことで、入力待ちでないと伝わる。3 行目には次に大事な事実を書く
- **判断してほしいことは冒頭の直後の 1 か所に集める**（指示書の「人が決めること」の節）。問いを本文に散らさない。1 件ずつ独立して読め、何を決めるのか・なぜ出てきたか・選択肢ごとに何が起きるか・決めないと何が止まるかを書く（指示書の ①〜④）
- 記号・略語・パス・自作ラベルは、初出で「中身→記号」の順に書く（例:「直すべき欠陥として判定した物（block）」）。途中から読み直しても解決できるようにする。内部の語彙（[block]・do-now・defer・R1〜R4・素材名・安定キーなど）だけで書いた問いは、それだけでは決められない
- 危険・失敗の話は「今壊れているのか・壊れる余地だけか」を最初に言う
- 表は短い値（状態・件数・日付など数語）の一覧だけに使う。**セルに説明の文を入れない**。説明が要るなら表をやめて箇条書きか散文にする（受け付けが機械で見る: 「。」を含むか 50 字を超えるセルが在れば拒む。`コード` の部分は数えない）。手順は番号付き
- 日本語は IT 業界の定着語を使う。コンサル英語・直訳の横文字・凝った比喩を避ける
- 「さっきの」「上の」など、この本文の外や前後の文脈に頼る参照を残さない
