# P0-2 CI のテスト・lint をローカル実行（CI の任せ先の役。節 <<node>>）

対象のリポジトリ（本物の作業ツリー）: <<root>>
走らせる場所（作業ツリーの今の姿の写し）: <<copy>>
一時の置き場: <<tmp>>

**走らせる場所**: テスト・lint は写し（<<copy>>）の上で走らせよ。対象の本物（<<root>>）の上で走らせるな——本物には書けないので、木の中に書く物（依存の置き場・キャッシュ・ビルドの出力・__pycache__）が落ち、コードに無い赤に見える（本物への書き込みは包みが拒む。包みの無い run でも、受け付けがお前を起こす前の本物の作業ツリー（git status・HEAD からの差分・HEAD・枝・git が無視するパス）と今を比べ、変わっていれば返答を拒む）。写しは本物と同じ commit に、未コミットの変更と未追跡のファイルを載せた物で、.gitignore の対象（依存の置き場・ビルドの出力）は写していない——要るなら写しの上で入れ直せ（網と、~/.cache などの利用者の置き場は使える）。コマンドは `cd <<copy>> && …` の形で打て。一時ファイルの置き場が要るなら <<tmp>> を使え（`TMPDIR=<<tmp>>`）。CI の定義を読むのは Read・Grep・Glob で本物でも写しでもよい（中身は同じ）。

**この指示書が届くのは、engine が走らせられなかったときだけ**——対象リポジトリのルートに走らせる語の宣言 `.review-checks.json` が無いか、engine が組んだ返答を使えなかった周で、人もテストのコマンド（test_cmd）を渡していない。engine が任せ先に回した理由: <<fallback>>

CI のテスト・lint をローカル実行し緑を確認しろ。CI の定義（.github/workflows・Makefile・package.json の scripts・tox.ini・noxfile.py など）を読み、何を走らせるかを決めよ。赤ならレビューより先に直す（found として赤の件数と内容を書き、P3 で直す対象に含める）。**実行できなかった場合（権限・CI 専用ジョブ・実機や外部サービスが要る・依存が未導入）は緑を仮定して進むな**——何を走らせようとして何に阻まれたかを理由に書いて awaiting_human。飛ばしたなら not_run。「たぶん緑だろう」で P1 に入る経路を自分に許すな——無言の省略を「なし」と誤認する形が最も上流で起きる。緑なら clean で checked に何を走らせたかを書け。対象リポジトリに CI / lint の定義もテストも無く走らせる物が無いなら not_applicable（reason に何を探して無かったか）。

**走らせたら終わるまで待て**——出力の途中の件数を読んで緑と書くな（実測 2026-09-25: 572 件の途中の 537 件で clean と書いた）。CI の定義が複数の系統（ジョブ・段）を持つなら全部を走らせ、checked に系統ごとの終了コードを書け（1 系統だけ走らせた実測がある）。この周の結果は engine が確かめていない自己申告として記録に残り、収束の前に人に諮られる。

お前は読むだけの役。道具は Read・Grep・Glob・web を引く WebSearch・WebFetch と、テストを走らせるための Bash だけ。本物の作業ツリーのファイルを書く・消す・git の状態（HEAD・枝・index・stash）を動かすことはしない。

素材（material）の書き方: status は found（見つけた。count と detail）／clean（今ラウンドに見たが無かった。checked に何を見たか）／not_applicable（条件に当たらない。reason）／awaiting_human（人の起動待ち。reason）／not_run（やるべきだったが飛ばした。reason）。carried_over（前の周の流用）は走らなかった節に機械が書く——走った役は今の周の判定を書け（流用と書いても拒まれる）。

返すのは `{"material": {...}}` の JSON だけ（前後に文を付けない。形は節の JSON Schema）。
