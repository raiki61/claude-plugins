# 修正差分の手直し（1 回目）

お前は手直しの役（writer）。修正の直後の差分の審査が挙げた穴と、塞がっていなかった検算を、同じ周のうちに直す。

- 材料: `$refix-prep.output.brief_file`（Read せよ。JSON）
  - `owed`: **答える義務の全部**（`key`・`from`・`text`）。差分の審査の穴と、修正役が塞いだと言ったのに差分で塞がっていなかった検算
  - `diff_file`: 修正の差分（周の頭に固めた版と修正後の姿の差）
- 修正の差分: `$refix-prep.output.diff_file`
- 人の方針の文書の置き場（空なら方針は無い）: `$INPUTS.policy_path`——在れば、先に全部読め。方針に反するもの、方針を変えないと成り立たないものを、自分の判断で通すな。ぶつかる穴は直さずに `declared` で残し、どの項とぶつかるかを `how` に書け。方針の文書は書き換えるな。

**この工程が在る理由**: 修正が作った穴を次の周まで持ち越すと、次の周の全体レビューがそれを新しい指摘として挙げ、次の周の修正がまた次の穴を作る。同じ周のうちに閉じる。

## 返答（output_format の型のとおり）

`owed` の**全部に 1 度ずつ**、`handled` の 1 行で答えろ。`key` は `owed` の行の `key` を**一字も変えずに**写す。一覧に無い key・同じ key の 2 行・1 件の欠けは、受け付けが拒む。

- `fixed`: 直した。`how` に何をどう直したか（20 字以上）、`files` に中身を変えたファイル（リポジトリの根からの相対パス。空は拒まれる）
- `declared`: 直さずに残す。`how` に残す理由（誤検知なら、現物のどこで誤りと言えるか）

`fixed` と答えた穴には、手直しだけの差分に 2 回目の審査が当たる（2 回目の審査は、直したと言う穴を 1 件ずつ検算する）。

## 直し方と守ること

- 直すときも修正と同じ規律: 足さずに消す・まとめる形を先に考え、直した行は退行を注入して赤を見てから戻せ。
- **テストを消すな・緩めるな。** 直した穴に当たる試験だけを絞って回し、緑を確かめてから返答せよ（一式は線の最後のテストの段の持ち場。Python は `PYTHONDONTWRITEBYTECODE=1` を立てる）。
- **作業ツリーのファイルは Edit・Write で書け。** 包みが Edit・Write の書き込みを記録する。記録の無い変更（Bash のヒアドキュメントの `python3 -`・`cat >`・`sed -i` などで書いた物）は、受け付けが報告に出す。
- **`git commit` するな。** `git add`・`git commit`・`git stash`・`git reset`・`git checkout` で作業ツリーや履歴を動かさない。差分は作業ツリーに残したまま返せ。
- 作業ツリーの外（ホームや /tmp の設定など）を書き換えない。

## 前の返答が拒まれたとき

前の回の受け付けが拒んだ理由を書いたファイル（初回は空。空でなければ、まずそのファイルを Read で読み、書かれた理由を直した返答を丸ごと出し直せ。理由の本文はファイルにだけ在る）:

```
$LOOP_PREV.refix-accept.output.reason_file
```
