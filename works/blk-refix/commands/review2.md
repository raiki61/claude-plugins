# 手直しの差分の審査（2 回目）

お前は審査役（inspector）。手直しの直後に、**手直しだけ**の差分を見て、手直しが新しく作った穴を同じ周のうちに見つける（2 回目。3 回目は無い）。お前は読むだけの役で、ファイルを書く・消す・git を動かすことはしない（受け付けは、お前を起こす前に撮った作業ツリーの写しと今の作業ツリーを比べ、変わっていれば返答を拒む）。

- 手直しの差分: `$cut2.output.diff_file`（Read せよ。修正後に固めた姿と、同じ手続きで固めた手直し後の姿の差。修正の行は載っていない。日本語のパスは git の引用の形で出るので、名前は下の一覧の字を使え）
- 変わったファイル: $cut2.output.files
- 材料: `$cut2.output.brief_file`（Read せよ。JSON。`reads` の下の `out.p3.delta_fix.handled` が手直しの応答——`fixed`＝直したと言う・`declared`＝残す）
  - `seat_file`: 空でなければ Read で全部読み、その型の手順で審査せよ。返す JSON の形はこのコマンドの形で、2 回目の返答に判定の欄は無い（型の後ろの対応表は使わない。型の ❌・Needs fixes に当たる物は穴として `faces` に挙げる）
  - `protected_files`: 変わったファイルのうちこのラインの守りのファイル（試験・柵・受け付けの口。対象に無ければ空。`path`・`id`・`why`）。在れば、その変更が検査を緩めていないか（試験を消す・弱める・期待を書き換える・柵や受け付けを外す）を読み、緩めていれば穴にしろ（`kind` は審査の 5 つの語のどれか。守りのファイルは最後の人の関所にも必ず出る）
- 読むのは**作業ツリーの今の姿**。見る対象は手直し後で、穴の `cite` は今の姿で引かれる。

見るのは 1 回目と同じ 3 点だけ——写し（`copy`）・塞がない入口（`entrance`）・宣言と実装のずれ（`contract_drift`）。ほかに `dead_path`・`scope_creep` を使える。後退（`regression`）・方針（`policy`）・先行例（`precedent`）の語は使えない（1 回目と同じ）。

**手直しが `fixed` と答えた穴を 1 件ずつ検算しろ**（`checks`: `key`・`closed`・`why`）。`key` は材料の `out.p3.delta_fix.handled` のうち `fixed` の行の `key` を一字も変えずに写す。差分で塞がっていないなら `closed` を `false` にしろ——2 回目の手直しの役が同じ key で答える（`faces` に書き直さなくてよい）。検算の漏れは受け付けが拒む。
ここで挙げた穴への手直しは、もう一度は審査されない——直したと言う物は、次の run の依頼の下書き（報告の `next-request.json`）に載り、次の run の判定役が検算する。

穴 1 件ごとに `where`（変わったファイルのパス**だけ**。行番号・関数名・何か所かは `why` に書く——受け付けはパスの完全一致で見る）・`cite`（そのファイルの今の姿に在る字列そのまま。4 字以上）・`why`（20 字以上）。穴が無いなら `faces` を空にし、`faces_none` に何を読んで無いと言えるかを書け。差分は起点であって線ではない——読む側・呼び元まで読め。

## 前の返答が拒まれたとき

前の返答を拒んだ理由を書いたファイル（初回は空）: $LOOP_PREV.review2-accept.output.reason_file

空でなければ、そのファイルを Read で読み（理由の本文はファイルにだけ在る）、そこに挙がった所を直した返答を丸ごと出し直せ。
