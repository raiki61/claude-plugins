# coldwrite — 書かれる文書の門番(試作)

Write ツールで書き込まれる文書を、書き込みの前に coldreader(文脈を持たない初見の読み手)に
読ませ、初見で意味の取れない箇所が直るまで書き込みを止める PreToolUse フック。
出口(gh への投稿)で見る gates/coldread の姉妹で、こちらは書く時点で見る。
設計の経緯と実測は `docs/coldread-gate-next.md`「乗り換え先の案 2」。

## 仕組み

prompt 型フック(Claude Code 本体の LLM 判定フック)だけで出来ていて、自作コードを持たない。

- 判定モデルは**会話の履歴を構造的に見られない**(道具も持たない)。初見性が指示への従順さでなく
  機構で守られる——2026-08-28 に claude 2.1.250 で実測(会話中に宣言した合言葉を判定モデルが
  再現できないことを確認)
- deny の理由(詰まり箇所の引用付き列挙)は書き手のモデルへツールエラーとして返り、
  直して再実行する修正ループが成立する
- 対象の絞りは宣言的な `if`(パス規則)で行い、対象外のファイルでは判定モデルを起こさない

## 射程

- **Write の `**/*.md`・`**/*.adoc` のみ**。Edit は対象外——断片(new_string)の初見検査は
  「断片だから文脈が無い」を詰まりと誤認しやすく、成立しない
- content がおおよそ 300 字未満・散文でない(コード・設定・データ・表・箇条書きの断片)・
  転記主体のものは検査せず通す。この除外判定も判定モデル自身が行うので確率的で、
  境界(300 字前後)の挙動は揺れる
- 指摘は読み手ごとに揺れる。止まったら詰まりを直すのが本線で、指摘に同意できないまま
  恒常的に外したいときは `/hooks` でこのフックを無効化するか `claude plugin disable coldwrite`

## 設計条件(変えるときに読む)

- `model` は**意図的に書いていない**。書かなければ既定の高速モデルへ本体が追従し、モデルの
  引退で壊れない。エイリアス(sonnet 等)や無効な ID を書くと、警告だけ出してフックごと
  スキップ=素通しになる(fail-open。claude 2.1.250 で実測)。書くならフル ID にし、
  わざと詰まる Write が deny されることを手で確かめてから使うこと
