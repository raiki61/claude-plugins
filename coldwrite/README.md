# coldwrite — 書かれる文書の門番(試作)

Write ツールで書き込まれる文書を、書き込みの前に coldreader(文脈を持たない初見の読み手)に
読ませ、初見で意味の取れない箇所が直るまで書き込みを止める PreToolUse フック。
出口(gh への投稿)で見る gates/coldread の姉妹で、こちらは書く時点で見る。
設計の経緯と実測は `docs/coldread-gate-next.md`「乗り換え先の案 2」。

## 仕組み

prompt 型フック(Claude Code 本体の LLM 判定フック)だけで出来ていて、自作コードを持たない。

- 判定モデルは**会話の履歴を構造的に見られない**(道具も持たない)。初見性が指示への従順さでなく
  機構で守られる——2026-08-28 に claude 2.1.250 で実測(会話中に宣言した合言葉を判定モデルが
  再現できないことを確認)
- deny の理由(詰まり箇所の引用付き列挙)は書き手のモデルへツールエラーとして返り、
  直して再実行する修正ループが成立する——**ただし各ハンドラの `continueOnBlock: true` が前提**。
  Claude Code 本体は 2.1.210 以降、prompt 型フックの `ok:false` を既定で「ツールを拒否して
  **ターンを終える**」に変えた(理由は警告行として人に見えるだけで、書き手のモデルは直せない)。
  `continueOnBlock: true` を付けると従来どおり理由がツールエラーとして返り、ターンが続く
  (公式 docs hooks-guide「Prompt-based hooks」、および 2026-08-30 に claude 2.1.251 で実測)
- 対象の絞りは宣言的な `if`(パス規則)で行い、対象外のファイルでは判定モデルを起こさない

## 射程

- **Write の散文拡張子(`**/*.md` `**/*.mdx` `**/*.adoc` `**/*.asciidoc` `**/*.rst` `**/*.txt`)のみ**。
  コード等それ以外の拡張子では判定モデル自体を起こさない。対象集合を変えるときは
  `coldwrite/hooks/hooks.json` のハンドラ(1 拡張子 1 本)を足し引きする。Edit は対象外——断片(new_string)の初見検査は
  「断片だから文脈が無い」を詰まりと誤認しやすく、成立しない
- content がおおよそ 300 字未満・散文でない(コード・設定・データ・表・箇条書きの断片)・
  転記主体のものは検査せず通す。この除外判定も判定モデル自身が行うので確率的で、
  境界(300 字前後)の挙動は揺れる
- 指摘は読み手ごとに揺れる。止まったら詰まりを直すのが本線
- 書いた文書がのちに gh の投稿本文になった場合は、投稿時に gates/coldread が改めて検査する。
  書いた時点の文書と投稿本文は別の成果物(間で編集されうる)なので、重なりは意図

## 逃げ道

- **1 回限り**: content の 1 行目に `coldwrite:skip` を書く(md/mdx は `<!-- coldwrite:skip: 理由 -->`、
  adoc は `// coldwrite:skip: 理由`、rst/txt は素の行でよい)。2 行目以降では効かない。
  印はファイルに残るので、飛ばした記録はファイル自身と git 差分が担う——消すのを忘れた印は
  後から読む人に見える
- **恒常停止**: `/hooks` でこのフックを無効化するか `claude plugin disable coldwrite`

## 見えないもの(試作の受容と昇格条件)

prompt 型フックは状態もログも持てないため、無言の ok が「検査して通った」「300 字未満などの
除外」のどちらかは外から区別できない。観測できるのは、判定モデルが起きたことを示す
スピナー(statusMessage)まで。この区別・スキップの集計・連続 deny の回数制御が実害として
必要になったら、この門番は coldread 型(コードを持つ command フック)へ昇格する——
それまでは試作としてこの不可視を受容する。

## 設計条件(変えるときに読む)

- `model` は**意図的に書いていない**。書かなければ既定の高速モデルへ本体が追従し、モデルの
  引退で壊れない。エイリアス(sonnet 等)や無効な ID を書くと、警告だけ出してフックごと
  スキップ=素通しになる(fail-open。claude 2.1.250 で実測)。書くならフル ID にし、
  わざと詰まる Write が deny されることを手で確かめてから使うこと
- `continueOnBlock: true` は**消さない**。無いと deny のたびにターンが終わり、人が次の発話をするまで
  書き手が直せない(「言われないと動けない」門番になる)。`tests/coldwrite-config-check.py` が
  6 ハンドラ全部に付いていることを機械で検査する
