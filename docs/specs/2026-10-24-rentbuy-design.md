# 借りるか買うかの部品（rentbuy）の設計

状態: 下書き（2026-10-24。持ち主と話して詰める途中。決まった所から「決めた」と書き替える）

頼み: my_notes（持ち主のノートのリポジトリ）で頼みに付く番号→受付 の 20261024-044835-ea3e82（前の取り下げた頼み 20261024-033714-c5f1de の言葉も同じ件）

頼みの中身: keepalive と compact の打ち時を、決まった数でなく「借りるか買うか」の判断で決める部品を作る。

読んだ後に要るもの: 8 の「持ち主と決める所」への答え。「決めた」と書いた所は、その形で実装に進む。

## 0. これは何か

Claude Code の会話が待っている間、プロンプトのキャッシュが切れないよう小さな要求を送り続ける仕組み→keepalive（送る要求 1 回→1 本）と、会話を要約して縮める操作→compact がある。keepalive の止め時・compact の打ち時・キャッシュの寿命の選び方は、どれも「少しずつ払い続ける（借りる）か、まとめて 1 回払う（買う）か」を、先が分からないまま決める問題（古典の名は ski rental。https://en.wikipedia.org/wiki/Ski_rental_problem ）。今はどれも決まった数を手で持っている（下の 3 つ。以下「今の決まった数」はこれを指す）。

- keepalive: works-dispatch が 5 分で 25 本・1 時間で 40 本まで、寿命 − 90 秒おき（`works-dispatch/dispatch/nodes/role.py` の `keepalive_for`）
- compact: works-dispatch の `COMPACT_FLOOR = 100000`（`works-dispatch/dispatch/nodes/wake.py`）と、my_notes の役（会話に与える役割の本文）「相談」の「10 万トークンを超えていそうなら」の目安
- 単価: works-dispatch の `claudex.py` の倍率（読み 0.1 倍。5.5 系は 0.05 倍で古い）、my_notes の `claude_call.py` の `PRICES`

この設計は、判断の中心を 1 つの小さな部品にまとめ、keepalive と compact をその上に載せる。会話の文脈には何も足さず、フック（ハーネス）の側で判断する。呼ぶ側は works-dispatch（このリポジトリのプラグイン）のフックで、中でも知らせを待って会話を起こすフックのプロセス→待ち受け（`wake_hook.py`）が主。

## 1. 形（全体）

```
       呼ぶ側（フック・待ち受け・スクリプト）
              │ JSON（その場の事実: モデル・寿命・文脈の量・送った累計 …）
              ▼
  ┌───────── 翻訳（場面ごとに 1 つ）──────────┐
  │ keepalive │ compact │ （後で）寿命 │ 続けるか新しく │
  └─────────────────┬───────────────────────┘
                    │ rent・buy・spent・certain（同じ単位＝ドル）
                    ▼
            中心: decide（止め時の決め方は差し替え: 固定 → 乱数 → 記録から学ぶ）
                    │ {action: rent|buy, why: 1 行}
                    ▼
            JSONL に 1 行残す（後で効きと外れを測る）
  値段の表（prices.toml。値ごとに原典の URL と確かめた日）を翻訳が読む
```

- 中心は場面を知らない。場面の知識（何が rent で何が buy か）は翻訳だけが持つ。
- 状態を持たない。呼ぶ側が毎回、累計（送った本数の費用・余分に読んだ累計）を渡す。
- 部品が無い・落ちたら、呼ぶ側は今の決まった数で動く（費用の最適化で、止めるゲートではない）。

## 2. 中心: decide

式と記号の表の正本は my_notes の指南（`notes/knowledge/llm-agent-workflow-cost-design-guide.md`。3.3・3.5・13.1 を 1 つの借りるか買うかの形に詰め直している途中。my_notes の受付 20261024-045046-a709f3）。この設計書は式を写さず、部品の作りだけを決める（持ち主 2026-10-24「ほとんどは計算式なので、自明に決まります。なので、mynotes内でほぼ詰めれるはずで」。足し 02c72e）。式が替わったら、部品のコードを指南に合わせ、この設計書は替えない。

### 2.1 入力と出力

| 鍵 | 型 | 意味 |
|---|---|---|
| rent | 数 | 次の 1 回を借りる費用 |
| buy | 数 | 買う（まとめて 1 回払う）費用 |
| spent | 数 | この回（エピソード）で借りに払った累計 |
| certain | 真偽 | 次の出来事（待っている物）が来ることが確かか |
| miss | 数（既定 0） | 借り続けても買いを避けられない割合（外れ率） |
| hazard | 数か無し | 次の区間で出来事が来る確率（分かるときだけ） |
| policy | 字（既定 fixed） | 止め時の決め方 |

出力は `{"action": "rent" | "buy", "why": "…", "policy": "fixed", "version": "…", "guide": "<指南の commit>"}`。`version` は部品 `rentbuy` の版（commit の SHA）。`guide` は、コードが合わせた指南の版（commit の SHA）で、式と部品のずれを後で見つけるために JSONL にも残す。

### 2.2 決め方の差し替え

- fixed（最初の版）: 指南の決定的な止め方（最悪で後から見た最適の 2 倍以内。https://en.wikipedia.org/wiki/Ski_rental_problem ）。
- random（後の段）: 買う時点を確率で選ぶ（同じ原典で e/(e−1) 倍）。乱数の種を JSONL に残す。
- learned（後の段）: 記録から待ちの長さや残りのターンの見込みを出し、見込みを信じる度合いを付けて止め時を決める（予測つきの ski rental。https://proceedings.neurips.cc/paper/2018/hash/73a427badebe0e32caa2e1fc7530b7f3-Abstract.html ）。

決め方は `policy` の名前で選び、中心の外から足せる（関数 1 つを表に登録する形）。

## 3. 翻訳

翻訳は場面の事実を rent・buy・spent・certain に直す関数。何をどれに当てるかの式は指南の該当の節に従う。部品が決めるのは、翻訳が何を受けて何を返すかと、呼ぶ側がどこから値を取るか。

### 3.1 keepalive

- 受ける物: モデル・寿命（今その会話で使っている値。寿命の選び方は 3.3 で後から足す）・文脈の量（会話の記録の最後の usage の `input_tokens`・`cache_read_input_tokens`・`cache_creation_input_tokens` の和。works-dispatch の `wake_hook.py` が今読んでいる値と同じ）・この待ちで送った本数の費用の累計・仕事が終わっていないか（受けた頼み・出した頼み・保留の頼み）・最後の `api-request` の時刻。1 本のキャッシュの書き込みと出力のトークン数（実測で書き込み 335〜380・出力 5）は値段の表の既定で、呼ぶ側が上書きできる。
- 返す物: 送るか止めるかと、送る時刻 `next_at`。
- 送る時刻: 会話の記録（transcript の JSONL）の最後の `api-request` の行の時刻 + 寿命 − 余裕。キャッシュの寿命は要求の開始から数える（https://code.claude.com/docs/en/prompt-caching ）。記録の時刻は手元で要求を出す前に付くので、測りは安全側に寄る。余裕は待ち受けの見る間（`POLL = 1.0` 秒）・フックから要求が出るまでの遅れ（実測 0.3 秒）・ずれの余裕。今の 90 秒は、ターンの終わりからの応答の生成の時間も含んでいた。ずれの余裕を含めた最初の値は `m`（8 で持ち主と決める）。
- 寄せの詰め（余裕 `m` を少しずつ下げること）: ここでの外れは、送るのが遅れてキャッシュが切れた本（その本のキャッシュの書き込みが大きく出る）。`m` を下げると送る本数は減るが外れは増える。減った本数と増えた外れを JSONL と会話の記録で数え、外れの増え方が指南の境を超えたら `m` を 1 つ前の値に戻す。境の式は指南の 3.5 に従う。
- 無駄撃ちを避ける: 送る直前に、待っている物の知らせが届いていないか（台帳・裏の処理の終わり）を見て、届いていれば送らない（台帳は works-dispatch が知らせを 1 行ずつ足す受付箱の `log.jsonl`、裏の処理は会話が裏で回したコマンド。調べものの部署の 04:30〜04:38 の 1 本目は、裏の処理の終わりと同じ秒に送っていた）。

### 3.2 compact

- 受ける物: モデル・寿命・文脈の量・キャッシュが温かいか（最後の要求からの秒が寿命より短いか）・前の compact の後の文脈の量（無ければ指南の例の値）・前の compact から後に余分に読んだ費用の累計。
- 返す物: 打つか待つか。
- 誰が打つか: 判断は待ち受け（works-dispatch の `wake_hook.py`）に移し、役の本文から「10 万トークンを超えていそうなら」の目安を外す。打ち方は今ある `--compact` の仕組み（Claude Code の入力欄が空なら、機械がその会話の端末の画面に `/compact <焦点>` を打つ）をそのまま使い、`COMPACT_FLOOR` の決まった数を decide に替える。

### 3.3 後で足す翻訳（最初の版の外）

- キャッシュの寿命（5 分か 1 時間）を選ぶこと。最初の版は、呼ぶ側が今の寿命を渡すだけ。
- works-factory の「前の会話を続けるか、新しく始めるか」（compact と同じ形で、縮めた後の量を引き継ぎの量にする）。

## 4. 入出力の形と置き場

### 4.1 コマンド

```
rentbuy decide    < {"rent":…, "buy":…, "spent":…, "certain":true}
rentbuy keepalive < {"model":"claude-opus-5-5","ttl":300,"context":100000,"spent":0.033,
                     "certain":true,"last_request_at":"2026-10-24T04:30:44.330Z"}
rentbuy compact   < {"model":…, "ttl":…, "context":…, "after":25000, "warm":true, "spent":…}
```

- 標準入力に JSON、標準出力に JSON。Python の標準ライブラリだけで書き、関数としても読み込める（works-dispatch は Python なので、毎回プロセスを立てずに呼べる）。
- 判断ごとに JSONL を 1 行残す（入力・出力・版・時刻）。置き場は `~/.cache/rentbuy/decisions.jsonl`。足し続ける物なので上限を持つ（docs/standards/breakage-detection.md の「足し続ける物の上限」）。

### 4.2 値段の表

`prices.toml`。モデルごとに入力・出力・5 分の書き込み・1 時間の書き込み・読みの単価と、原典の URL（https://platform.claude.com/docs/en/about-claude/pricing ）と確かめた日。実測の値（`g_k`・`o_k`・`miss`）も同じファイルに、測った日と出どころ（受付番号）を付けて置く。呼ぶ側は JSON で上書きできる。works-dispatch の `claudex.py` の倍率と、my_notes の `claude_call.py` の `PRICES` は、この表を読む形にする。

### 4.3 置き場（決めた）

- 式と記号の表の正本は my_notes の指南。部品の作り（入出力・置き場・つなぎ込み・落ちたときの戻り先・記録の形）の正本はこの設計書。
- コードと値段の表は、このリポジトリ（claude-plugins）の新しいプラグイン `rentbuy/`（marketplace に載せる）。中に薄いスキル（判断の読み方と JSONL の見方）を添える。
- 版の固定はタグでなく commit の SHA にする（このリポジトリはタグを作らない。持ち主 2026-09-29。works-factory の `PIN` と同じ形）。同じリポジトリの works-dispatch は、Claude Code の入れた物の控え（`installed_plugins.json`）から `rentbuy` の置き場を引き、無ければ今の決まった数で動く。

## 6. 試験

置くのは部品の約束 1 本: fixed の決め方は、どんな待ちの長さでも、費用が後から見た最適の 2 倍以内（持ち主 2026-10-24「テストは最小に」）。

## 7. 実装の割り振り（決めた）

このリポジトリでは、役を持った別の Claude Code の会話→部署 が仕事を分けて受け持つ（役と受け持ちは `.claude/company.toml`→会社の形 に書く）。

- 部品 `rentbuy/` はこの部署（この設計書を書いた部署）で作る（受け持ちの無い新しいプラグイン）。8 の前例の調べの結果で変わりうる。
- works-dispatch のつなぎ込み（`keepalive_for` の上限・送る時刻・`COMPACT_FLOOR`）は、works-dispatch を受け持つ部署→割り振り へ頼む（会社の形 `.claude/company.toml` の受け持ちの決まり）。
- my_notes の側（役「相談」の目安の削除・`claude_call.py` の `PRICES` を値段の表に替える）は my_notes の部署へ一覧で渡す。
