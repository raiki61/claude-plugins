# 自分のリポジトリに合わせる

## 固有の規約はどこにも書かない

同梱の `REVIEW.md` には固有の技術名が無い。アーキテクチャ境界・標準機構・機械強制されている検査は、grader が対象リポジトリの一次情報から毎回把握する（`REVIEW.md` の「固有規約の把握」）。

**書き写したくなったら止まる。** 書いた瞬間に正本の複製になり、リポジトリが変わっても古いまま残る。lint 設定を 1 行変えたのに観点側の記述が古い、という形で事故が起きる。

一次情報が薄いリポジトリ（README にアーキテクチャの記述が無い等）では、grader は近傍の実際の import から推定し、推定であることを明記する。**推定が続くなら、直すべきは観点ではなくリポジトリの文書のほう**——それ自体が「開発者導線の整合性」観点の指摘になる。

なお grader が見るのは、文書に書かれた理想ではなく**近傍が実際に使っている機構**である。両者が食い違っていれば、その食い違い自体が指摘になる。

## 自分のリポジトリの観点を足す

対象リポジトリのルートに `REVIEW.md` を置くと、同梱の観点と併用される。同梱側と同じ観点を書き写さず、そこに無いものだけを置く。

## 言語・ホストが違う場合

**注釈比率が測れない言語**: `comment-ratio.sh` は Python（`tokenize`）と C 系コメント（`//` `/* */`）の言語だけを数える。`#` 系（Ruby・Shell）を `EXTS` に足すと、注釈を 1 行も拾えないまま「注釈 0%」を出す——足さず、行数で別に測る。C 系の言語で対象に入っていないものは `EXTS` に足せば動く。

**GitHub 以外のホスト**: `/review-loop` の P0-5（並行 PR の衝突チェック）が `gh` を使う。同等コマンドに読み替える。読み替えられないなら、未確認を「衝突なし」と書かせず「確認できなかった」と報告させる。

**fork 運用・複数アカウント**: 同じ P0-5 は、対象リポジトリを明示的に解決して `-R owner/repo` を渡す形にしてある。`-R` 無しの `gh` は cwd の remote と `gh` のログイン状態に暗黙依存し、**別リポジトリの PR 一覧をエラーなしで返す**——取り違えは正常終了するので上のフォールバックには乗らない。`gh auth switch` で複数アカウントを使い分けているなら、解決された `owner/repo` が意図したものか毎回確認させること。

**計測が exit 2 で止まる場合**: `comment-ratio.sh` は、差分に載っていない未追跡の対象言語ファイルを見つけると数えずに落ちる。`git add -N <path>` で載せてから測る（P0-1 が指示している手順）。落ちずに 0 を返すと、計測漏れのある状態と本当に対象ファイルが無い状態が同じ出力になる。

**`Workflow` ツールが無い環境**: `/research-loop` の P1 はワークフロースクリプトで checker → refuter の扇を回す。使えない環境では、同じ構造（checker=sonnet → 相違と【荷重】確証に refuter=opus・同じ判定語彙と schema）を `Agent` の並列起動で再現する。手順本文にその指示がある。

## ラウンド記録の置き場所

既定は `.claude/review-rounds/round-<N>.json`。作業ファイルなので `.gitignore` に入れておく。

**前ラウンド分を消さないこと**。連続 2 ラウンドの突合と、`defer` の台帳がこれで成立している。新しい context での再採点は前ラウンドの受容判断を知らないので、台帳が無いと同じ提案が毎ラウンド再燃して収束しない。

チームで記録を証跡として残す方針ならコミットしてよい。記録には findings の要約が入るので、レビューの経緯が追える。

## 記録の schema

正本は `scripts/review-record.py` の `MATERIALS` / `STATUS` / `LABELS`。手順書は列挙を持たない（二重管理を避けるため）。実例は `templates/round-1.example.json` と `templates/round-2.example.json`。

素材の状態は 5 値。**`not_applicable`（条件に当たらない）と `not_run`（やるべきだったが飛ばした）と `awaiting_human`（人の起動待ちで止まっている）を潰さない**のがこの schema の要点で、潰すと報告上で見分けられなくなる。`clean`（見たが無かった）には「何を見たか」を要求する——見た範囲が書けないものは、見たと言えない。
