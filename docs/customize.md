# 自分のリポジトリに合わせる

## レビュー観点の正本を置く

`/review-loop-init` が `templates/REVIEW.md` をリポジトリルートへ `REVIEW.md` として置き、固有欄を埋める。あとから手で直すときは次を守る。

- **観点の本文をプラグイン側と対象リポジトリ側の両方に置かない**。二重管理は片方が stale 化し、レビューが古い規約で走る。`REVIEW.md` が唯一の正本
- **固有欄は正本のパスを指す**。依存表の中身を `REVIEW.md` に写さず、「依存表は `docs/architecture.md`」と書いて grader に Read させる
- **空欄で残さない**。調べて無かった項目は「該当なし（探した先: ...）」と書く。空欄は「無い」のか「まだ書いていない」のか区別が付かない

固有欄のうち効くのは 2 つ。**アーキテクチャ境界**（設計観点が照らす先）と**標準機構の一覧**（整合性観点の「標準機構の迂回」が照らす先）。ここが空だと、grader は近傍コードからの推測に落ちる。推測は当たるが、規約に無い流儀を「このリポジトリの標準」と誤認する取り違えが出る。

**機械強制されている検査**の欄も埋める価値が高い。CI で既に赤くなる検査を列挙しておくと、設計観点はそれを「緑の確認だけ」に留める——列挙が漏れると、人と LLM が既に自動化されている検査を二重にやる。

## 観点を足す・削る

`REVIEW.md` の「この規約の育て方」が正本。要点は 3 つ。

- **クラス単位でだけ足す**。個別インシデントの写しでなく、再発の機構を一文で言えるクラスに束ねてから足す
- **原則名・パターン名で足さない**（「SOLID に従っているか」の形）。反証できず、抽象を増やす方向にしか働かない。`import` を読めば決着する問いの形に翻訳してから足す
- **新規観点は追加前に追試する**。それが捕まえるはずだった過去の実見逃しを、文脈を伏せて当該レンズだけを持つ grader に読ませ、独力で発火するか実測する。不発なら入れない

## 言語・ホストが違う場合

**注釈比率が測れない言語**: `comment-ratio.sh` は Python（`tokenize`）と C 系コメント（`//` `/* */`）の言語だけを数える。`#` 系（Ruby・Shell）を `EXTS` に足すと、注釈を 1 行も拾えないまま「注釈 0%」を出す——足さず、行数で別に測る。C 系の言語で対象に入っていないものは `EXTS` に足せば動く。

**GitHub 以外のホスト**: `/review-loop` の P0-5（並行 PR の衝突チェック）が `gh` を使う。同等コマンドに読み替える。読み替えられないなら、未確認を「衝突なし」と書かせず「確認できなかった」と報告させる。

**`Workflow` ツールが無い環境**: `/research-loop` の P1 はワークフロースクリプトで checker → refuter の扇を回す。使えない環境では、同じ構造（checker=sonnet → 相違と【荷重】確証に refuter=opus・同じ判定語彙と schema）を `Agent` の並列起動で再現する。手順本文にその指示がある。

## ラウンド記録の置き場所

既定は `.claude/review-rounds/round-<N>.json`。`/review-loop-init` が `.gitignore` に追記する。

**前ラウンド分を消さないこと**。連続 2 ラウンドの突合と、`defer` の台帳がこれで成立している。新しい context での再採点は前ラウンドの受容判断を知らないので、台帳が無いと同じ提案が毎ラウンド再燃して収束しない。

チームで記録を証跡として残す方針なら `.gitignore` に入れずコミットしてよい。記録には findings の要約が入るので、レビューの経緯が追える。

## 記録の schema

正本は `scripts/review-record.py` の `MATERIALS` / `STATUS` / `LABELS`。手順書は列挙を持たない（二重管理を避けるため）。実例は `templates/round-1.example.json` と `templates/round-2.example.json`。

素材の状態は 5 値。**`not_applicable`（条件に当たらない）と `not_run`（やるべきだったが飛ばした）と `awaiting_human`（人の起動待ちで止まっている）を潰さない**のがこの schema の要点で、潰すと報告上で見分けられなくなる。`clean`（見たが無かった）には「何を見たか」を要求する——見た範囲が書けないものは、見たと言えない。
