# 部署のモデルと effort を替えたときの質と費用（済んだ頼みの再演）

部署（会社の形の役を受けて動く Claude Code の会話）を安いモデル（Sonnet）や低い作業量（effort）で回したら、質がどれだけ落ち、費用がどれだけ減るかを、済んだ頼みを同じ条件でやり直して測った記録。役（会社の形 `.claude/company.toml` の `[[roles]]`）の `model`・`effort` を替えるかを決める材料にする。

## 平易版（3 行）

- 作業の役が受けた文書の整地の頼み 2 件のそれぞれを、答えが入る前の commit から、Opus 5.5・effort high（今の部署と同じ）、Sonnet 5.5・effort high、Opus 5.5・effort medium の 3 通りで 1 回ずつ、計 6 回やり直した（2026-10-17）。
- 費用は今の形を 100 とすると、Sonnet が 40、Opus の medium が 56。漏れと誤りの合計は、今の形が 2 件、Sonnet が 5 件、Opus の medium が 2 件。
- 1 通りにつき 2 回だけなので、1〜2 件の差は揺れの内。Sonnet の回でも、中で起こしたサブエージェントは Opus で動き、費用の 47% を占めた（下の「読むときの注意」）。

## 比べ方

### 頼み

作業の役が受け、本流（main）に入った文書の整地（古い記述や索引の抜けを直す片付け）を 2 件使った。済んだ答えが本流に有るので、答え合わせができる。

| 札 | 頼み（受付） | 始めの commit | 本流の答え |
|---|---|---|---|
| 頼み 1 | 20261016-201902-22ce59 | 334daa0f | 88d3b269 |
| 頼み 2 | 20261016-201935-9fb74d | b951bc85 | 91b1e6ed |

- 受付: 頼みのファイル（`.git/company/inbox` の中。リポジトリには入っていない）の名前。
- 本流の答え: その頼みで本流に入った commit。本物の部署（形は A と同じ）が作った。
- 頼み 1: `docs/trials/README.md`（試しの記録 10 本の索引）を作る。試しは、まっさらな環境にプラグインを入れて動かした回で、1 回ごとに記録が 1 本ある。記録を読んで、どの版で直ったかを確かめて書く、事実の多い仕事。
- 頼み 2: どの担当の受け持ちにも入らない所の古い記述 4 か所（graphloops の README・convergence-loops の CHANGELOG・`.gitignore` の注・marketplace の tiers の説明）を直し、プラグインの依存の版の範囲の解き方を Claude Code の公式の文書で確かめる。

### 3 通り

| 札 | モデル | effort |
|---|---|---|
| A | claude-opus-5-5 | high |
| B | claude-sonnet-5-5 | high |
| C | claude-opus-5-5 | medium |

A は今の部署と同じ形（役に effort が無く、持ち主のアカウントの設定の high が効いている）。B はモデルだけ、C は effort だけを A から替えた。

### そろえた物

- 頼みの文（受付のファイルをそのまま）と、始めの commit。
- 役の本文と起動の設定: 始めの commit の会社の形の作業の役の `instructions` と `settings`（`autoMode` だけ外した）。
- アカウント（6 回とも同じ 1 つ）と、そのアカウントのプラグイン・CLAUDE.md・記憶。
- 回し方: 1 回ずつ順に、`claude -p`（画面を持たない会話）で回した。

### 回し方

1. 始めの commit だけを持つ使い捨ての bare のリポジトリを作り、そこから clone する。`git fetch` をしても本流の答えは見えず、push しても本物の origin には届かない。
2. 役の本文を `--append-system-prompt` に、役の `settings`（`permissions.deny` に `git push`・`gh pr`・`gh issue` を足した物）を `--settings` に渡す。`--model` と `--effort` だけを 3 通りで替える。権限は `--permission-mode bypassPermissions`。
3. 最初の文は「頼みです: <頼みのファイル> を読んで進めてください」に、再演のための読み替えを 3 つ足した物。
   - 本流に入れる命令（`--land`）・頼む命令（`--ask`）・納品の命令（`--deliver`）は打たない。commit の後に、本流に入れる前の関門（始めの commit の会社の形の `[land]` の `check`。`python3 scripts/shared-copies.py && bash tests/count-fences.sh`）を手で回し、通るまで直す。
   - ほかの部署に頼む物は、納品の要約の「残った疑問」に書く。
   - 要約は、納品と同じ 結論・決め手・残った疑問・枝（作業した git のブランチ）の見出しで、納品の代わりにファイルに書く。
4. 回す前と後に、使用率の控え（works-dispatch の `limits.py` と同じ問い合わせ）を取る。

### 数えた物

- 関門: 始めの commit の `[land]` の `check` が通るか。各回の枝の文書を、今の本流に在る初見読み（文脈の無い読み手に読ませる gates の検査。`gates/hooks/coldread-gate.py branch-check --base origin/main`）に読ませたときの、詰まりと推測で埋めた箇所の数。
- 漏れと誤り: 頼み 1 件ごとに、どれがどの通りかを伏せた（A・B・C を別の札に替えて渡した）判定役 1 人（Opus のサブエージェント）が数えた。事実の正しさは始めの commit のファイルで確かめ、本流の答えは手掛かりにとどめた（本流の答えも同じ物差しで数えた）。判定役が git を使えず確かめられなかった所（書かれた `git diff` の出力）は、判定役を起こした側が打って確かめた。
- 漏れは頼みが求めたのに書かなかった事実、誤りは事実と違う記述。1 つの事実を 1 件と数えた。
- 本流の答えに無い正しい物: 本流の答えには無く、判定役が正しいと見た記述の数。多いほど、本流の答えより多くの正しい事実を書いた。
- 費用: `claude -p` の結果の `modelUsage`（モデルごとのトークンと、定価で換算した USD）。
- 番の数: 会話の記録（`~/.claude*/projects/` の jsonl）の、本筋の assistant の応答の数。`claude -p` の結果の `num_turns` は、裏の作業を待って会話が再開すると最後の区切りの分しか数えないので使わない。
- 時間: 起こしてから終わるまでの壁の時計の時間。表では分で出す。

### 漏れと誤りの中身

- 頼み 1・A: 1 回目の記録の行で、後の版で直った時期の書き方が違う（1 項目は 2 回目の試しの時点でもう直っていた）。後の試しで確かめていない 1 項目を「確かめた」側に入れた。
- 頼み 1・B: 9 回目の記録の大きな見つけ（止めた会話が約 1 分後に自分で再開する。まだ閉じていない）を行からも閉じていない物の一覧からも落とした（漏れ）。2 回目の記録で、人が止めた 4 件と別に並ぶ件を 4 件の中に入れた。2 回目の記録の直しを、確かめたのは 4 回目なのに 3 回目と書いた。7 回目の記録の Linux での戻し方を確かめていないのに「確かめた」と書いた（本流の答えと同じ誤り）。
- 頼み 1・C: 1 回目の記録の行で、後の試しで確かめていない 1 項目を「確かめた」側に入れた。
- 頼み 2・B: graphloops の README に書いた確かめの命令（`git diff <BASE> --stat -- convergence-loops/commands/`）は、移す前の版を `<BASE>` にすると、README が触ったと書く 3 本を丸ごと足した物として出す（打つとほかの 1 本も入り、4 本・1416 行の追加。README が書く計 5 行の差し替えが見えない）。
- 頼み 2・C: tiers の説明の古い 1 文を `.claude-plugin/marketplace.json` だけ直し、同じ文の在る `tiers/.claude-plugin/plugin.json` を残した（2 つの説明が食い違う）。
- 頼み 2 の依存の版の範囲は、3 回とも正しく調べ、範囲を残した（公式の文書: 相対の道で置いたプラグインは、範囲に合うタグが無ければ marketplace の今の写しを入れ、読み込むときに範囲を確かめる。https://code.claude.com/docs/en/plugin-dependencies ）。

## 読むときの注意

- 1 通りにつき 2 回だけ。同じ形でもやり直すたびに結果は揺れるので、1〜2 件の差は揺れと見分けられない。
- Sonnet の回（B）でも、中で起こしたサブエージェントは Opus で動いた。このリポジトリの根の CLAUDE.md が「サブエージェントは全部 opus を明示する（sonnet 以下は使わない）」と書くため。B の費用のうち Opus は頼み 1 で 37%、頼み 2 で 63%（合わせて 47%）で、初見読みの指摘の直しは Opus のサブエージェントが書いた。B の質は Sonnet だけの質ではない。役に `model = "sonnet"` を書いても、この CLAUDE.md の決まりがある限り、部署の費用の半分ほどは Opus のまま残る。
- 費用の USD は、API の定価で換算した値（結果の `costBasis` は `list`）。持ち主のアカウントは定額の契約で、減るのは使用上限の側。使用上限の減りは 1% 刻みで、同じアカウントを使うほかの会話の分も混じるので、目安にとどめる。
- 部署の中の初見読みの関門（gates のフック。読み手は Haiku）が起こす会話の費用と、判定役の費用は、上の数に入っていない。どちらも再演の会話の外で走るため（初見読みはどの通りでも同じ読み手、判定役は頼み 1 件につき 3 通りをまとめて 1 回）。
- 本物の部署（`claude --bg` で起こし、役の文を SessionStart のフックで足す）とは起こし方が違う。3 通りの間では同じ起こし方なので、比べには効かない。

## 再演をやり直すとき

数を増やすときも、上の「回し方」でよい。受け持ちの無い一度きりの作業なので、作業の役に頼む（`--ask claude-plugins/作業`）。頼みの文には、上の「回し方」の 4 段と「数えた物」を写さずにこの文書を指す。本流には入れない。
