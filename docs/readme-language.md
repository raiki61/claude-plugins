# README の言語: 英語の 1 版だけ

README（GitHub でこのリポジトリを開くと最初に出るルートの `README.md` と、各プラグインのフォルダの `README.md`）を直す人とエージェントは、英語で書く。日本語の訳の版（`README.ja.md` など）は作らない。スキルとコマンドの名前・説明・本文、CONTRIBUTING.md、`docs/` は日本語のままでよい。

- 決めた日: 2026-10-18（ルートの README）、同じ日に各プラグインの README へ広げた
- 決めた人: ルートの README は、このリポジトリの文書（ルートの README・CLAUDE.md・CONTRIBUTING.md など）を受け持つ会話「説明書」が、持ち主（このリポジトリの所有者で、エージェントに仕事を頼む人）の委任で決めた。「説明書」は、仕事ごとに役を分けて立てる会話の 1 つで、役の一覧は `.claude/company.toml`（会社の形）に書いてある。
- もとになった持ち主の言葉: 頼み「外部の人に使ってもらうことを考えると英語がいい。煩わしくなければやっておいていい」と、2026-10-18 の決め「英語の正本は claude-plugins の repo の README と docs の 1 つだけにする」。説明書はこの決めを、英語の正本を置く場所をこのリポジトリ 1 か所に絞る物と読み、`docs/` は英語にしていない（「決定」の 4 つ目）。`docs/` まで英語にするかは持ち主に問うている（2026-10-18）。
- 各プラグインの README へ広げることと、スキルの名前と説明を日本語のまま置くことは、両方を書いた案に持ち主が「うん。いいよ。英語にしましょう。」と承認した。
- 括弧の中の「受付 da159a」「頼み 320497」などは、持ち主の頼みを受けた記録の番号。記録は持ち主の別のリポジトリ my_notes（司令塔は、その中で持ち主との中継をする会話。前の名前は社長室）に在り、このリポジトリからは見えない。

## 文脈

- claude-plugins は公開して外の人に配っているが、README は日本語で、英語の読み手（日本語の読めない外の利用者）は入れ方から分からなかった。ルートの README だけを英語にすると、英語の読み手はプラグインの README を開いたところで日本語に当たった。
- 持ち主の条件は「煩わしくなければ」。2 つの言語を手でそろえ続ける手間を、持ち主にもエージェントにも増やさない。
- 世間の形: GitHub は README を `.github`・ルート・`docs` の順に探して 1 つを出し、言語の版の仕組みは持たない。言語の版を持つ OSS は、英語の `README.md` の横に言語の接尾辞の付いた版（`README.zh-CN.md` など。lobehub/lobe-chat）を置き、頭に互いを指す行を置く。訳を元の文と揃える文書の仕組み（OpenTelemetry）は、英語を元とし、訳したページごとに元のページのコミットを書き、古くなった訳をツール（`check:i18n`）で一覧にする。英語を直すと訳は古くなったまま残り、言語のチームが直す。

## 決定

- ルートの `README.md` と各プラグインの `README.md` を英語だけで書く。日本語の訳の版は持たない。
- スキルとコマンドの名前と説明（会話を起動するたびに読み込まれる `description`）と本文は日本語のまま置く。各プラグインの README の頭に、スキルとコマンドの説明と本文は日本語だと書く。
- ルートの README の「Language」のセクションに、README のほか（スキルとコマンド・CONTRIBUTING.md・`docs/`）は日本語だと書く。
- `docs/` は英語にしない。中身は設計の決定・会社の形・改善の台帳など、持ち主とエージェントが日本語で保守する記録で、使い始める人が読む物ではない。

## 比べた案

- 英語の `README.md` と日本語の `README.ja.md` の 2 版を持ち、訳の頭に元の版を書いて、ずれを試験で落とす（捨てた案）: 世間の形に合い、ずれは機械で見つかるが、README の直しのたびに 2 版を直す手間が残る（2026-09-18〜10-18 の 30 日で、ルートの README の直しは 17 回、プラグインの README は計 110 回。プラグインの 1 つ works の README はこの数に入れていないが、決定の対象には入る）。
- スキルの名前と説明も英語にする（捨てた案）: 持ち主の日本語の言い方（「工程に回して」など）でスキルが選ばれるかが落ちうる。持ち主の承認が日本語のまま置く形だった。
- `docs/` まで英語だけにする（捨てた案）: `docs/` は約 100 本・7,500 行の日本語の記録で、持ち主とエージェントの保守の言語を変えてしまう。
- 今のまま日本語にする（捨てた案）: 外の人が入れ方から読めない。

## 理由

- 1 版だけなら、そろえる相手が無いので、ずれが起きない。
- 外の読み手が最初に開く物（ルートとプラグインの README）が英語でそろう。

## 結果

- 楽になる: 英語の読み手がルートの README から各プラグインの README まで読める。訳をそろえる手間が無い。
- 難しくなる: README を直す担当とエージェントは英語で書く。試験の中には、README の中に決まった文が在るかを探して、無ければ落とす物がある（`tests/run.sh` と各プラグインの `tests/`）。README を英語にしたので、そうした試験が探す文は、試験の側を書き換えて英語の README の文にした（README の側は日本語に戻さない）。スキルの名前や、利用者が打つ日本語の語・機械が出す日本語の文は、README の中でも日本語の字のまま引き、英語の意味を括弧で添える。
- `tests/run.sh` の README_PLUGINS_OK（表と本数が marketplace.json と揃うか）は、本数の文の英語の形（`ships N plugins`）も認める（CI とルートの `tests/` を受け持つ会話「点検」が直した。commit 979dca83）。

## 見直す条件

- 英語の読み手から、スキルの説明や `docs/` が読めないという声が出たとき。2 言語の版を持つなら、「比べた案」の 1 つ目の形（英語を元とし、訳の頭に元の版を書き、ずれを試験で落とす）にする。
