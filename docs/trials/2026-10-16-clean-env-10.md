- Linux の `--init-company` は、試しの段取りの都合で窓口の会話を通さずにシェルから打った（同じ命令で、結果は同じ）。
- 「測っていない」は、窓口の会話を通さずにシェルから打った物（Linux の `--init-company`）か、時間を書き出し損ねた物（macOS の `--clean --apply` と前の名前での頼み）。どれも通った。
- `--clean --apply` は、3 つの OS とも「部署 説明：使い方 消した」と出し、担当（常駐）を残した。
- `--reorg` の後、前の名前の `--ask 計算` は 3 つの OS とも計算係に届き、担当は本流に入れて納品した。

## 形 B（未納品の頼みを持ったまま落とした担当）

- macOS（ペインを閉じてから `claude stop`）:
  - 頼み 5・納品 4 の所で、部署のペイン w2:p1 を閉じて止めた。
  - `--ask` は作業場を開き直し、新しいペイン（w4:p1。名前は `計算係` が付いた。9 回目の名前の付かない所は直った）に attach を打って戻した。
  - 続けて「戻した部署に、受付 … の納品を促した（sent）」と出して止まった（終了の値 2）。担当は納品した（頼み 5・納品 5）。
- Linux（Ctrl+Z の後に `claude stop`）:
  - 頼み 5・納品 4 の所で、Ctrl+Z を送ると部署の窓は bash の入力待ちに戻った。`claude stop 9d26c25c` で止めた。
  - `--ask` は戻して「納品を促した（sent）」と出して止まり、担当は納品した（頼み 5・納品 5）。
- Windows（VM の再起動）:
  - 頼み 5・納品 4 の所で `Restart-Computer -Force` を打った。
  - 起き直った後、herdr の server と窓口を起こし直し、`--desk` の後に `--ask` を打った。
  - `--ask` は「ペイン w2:p1 で claude attach bede802c を打って戻した」「戻した部署に、受付 … の納品を促した（sent。入力欄に残っていたので Enter を足した）」と出して止まった。
  - 9 回目と違い、担当は続きを進めて納品した（頼み 6・納品 6。担当が自分で作業の部署に頼んだ 1 件を含む）。

## 起き直り（頼みの 3）

- `claude stop` を打ったのは macOS（ペインを閉じた後）と Linux（Ctrl+Z の後）の 2 回で、どちらも止めてから `--ask` を打つまで（macOS は約 10 秒、Linux は約 4 秒）の間に会話が自分で起き直ることは無かった。Windows は VM の再起動で落としたので、`claude stop` は打っていない。9 回目の macOS の起き直りは、止めてから約 1 分後だった。今回は待つ間が短いので、起き直らないと言い切れる確かめではない。
- Linux で止めた直後の裏の処理の置き場（`/tmp/cc-daemon-<uid>/`）の様子: 置き場は 1 つ（`99b1807e`）で、中に `control.sock`・`pty`・`rv`・`spare` があった。claude の処理は 7 つ動いていた。会話は起き直らなかったので、起き直る前との比べは無い。
