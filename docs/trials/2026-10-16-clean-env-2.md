この記録の言葉:

- 窓口: 持ち主（ここでは試した人がその役をした）と話し、部署に頼む Claude Code の会話。
- 部署: 頼まれた仕事をする、git の枝 1 本の作業場と Claude Code の会話の組。役が 2 つある。担当は受け持ちに常設で、頼みを続けて受ける。作業は頼みごとに立ち、済んだら片付ける。

- 「部署の回」は部署を立てて頼む使い方、「PR を開く回」は自分の番の PR を作業場に開く使い方。
- 「人だけなら止まる」は、説明書だけを頼りにする人ならそこで止まる、という意味。今回は原因を調べて回避し、先へ進んだ。
- 1 回目の N は、1 回目の記録の N 番目の項（下の「1 回目の 14 件の今」に並べた）。

## 記録（どこで・何をして・どうなったか・文書の何が足りないか）

### 1. gh にログインしていないと、`--init-company` の下書きが TOML として壊れる（人だけなら止まる）

- どこで: `--init-company` が書いた `.claude/company.toml` の `gh_user` の注記。
- 何をして: gh にログインしていない状態で、窓口から `/works-dispatch:dispatch --init-company` を打った。
- どうなったか:
  - 下書きの `# gh_user = …` の注記に、gh の誤りの文（2 行）がそのまま入った。2 行目の `Alternatively, populate the GH_TOKEN …` は `#` の外に出た。
  - その結果、ファイルは TOML として読めなくなった（`tomllib`: `Expected '=' after a key …（at line 11, column 14）`）。
  - 窓口は「書いた」とだけ報告した。壊れていることは誰も言わない。
  - 試しでは、壊れた 2 行を手で 1 行の注記に直してから先へ進んだ。
- 文書の足りない所: 文書の穴ではなく、下書きを書く所の不具合。gh が誤りを返したときは、注記を 1 行に畳むか、誤りの文を入れない形が要る。

### 2. `--task` に `--brief` が要るのに、下書きの注記は要らない形で書く

- どこで: 下書きの `[[roles]]` の担当の上の注記（「立てるのは --task <受け持ち> --branch <枝> --role 担当」）。今回の頼み（試しの手順）も「担当を立てる（--task <受け持ち> --role 担当）」と書いていた。
- 何をして: 注記どおりに `--task 計算 --branch work/calc --role 担当` を打った。
- どうなったか: 「止めた: --task には、名前と --branch <枝> と --brief <頼みのファイル> が要る」。窓口に 1 文の頼みのファイルを書かせて、打ち直した。
- 文書の足りない所: SKILL.md の `--task` は `--brief` を書いている。下書きの中の注記（担当の上の注記と、末尾の組織の決まりの注記）は書いていない。担当を最初の頼みと一緒に立てるなら `--ask <会社>/担当 --task <受け持ち> --branch <枝> --text …` で足りるが、その道は下書きに無い。

### 3. 手元の bare リポジトリを origin にすると、部署を立てられない（1 回目の 9 がまだ。人だけなら止まる）

- 何をして: gh にログインしないまま `--check` を打った。続けて `--task` を打った。
- どうなったか:
  - `--check` は、段 1 の「gh のログイン」が足りないとして止まった（段 2 の点検は段 1 も含む。下の「通ったこと」の `/tiers:check 段 2` と同じ項目）。
  - `--task` も「始める前の確かめで足りない物: gh が work/origin を読めない。whose-turn が自分の番の PR を集められない」で止まった。
  - `work/origin` は、origin の手元のパス（`…/work/origin.git`）の末尾 2 段を GitHub の `OWNER/NAME` として読んだ物。
  - gh の鍵を渡しても、同じ文で止まった（GitHub に `work/origin` は無い）。
  - 確かめたコード（`dispatch.py` の始める前の確かめ）では、部署の回でも、gh で origin のリポジトリを読めることを確かめる。本流の枝の名前も、`--task`・`--clean`・`--land` のどれも `gh repo view` の `defaultBranchRef` で GitHub に問う（`ghx.default_branch`）。手元の `origin/HEAD` は使わない。
- 回避: 上の「使い捨てのリポジトリ」のとおり、bare の置き場の名前を公開のリポジトリに合わせ、gh の鍵を渡した。すると今度は「`git fetch` で `couldn't find remote ref master`」（`provision_failed`）で止まった。本流の名前を GitHub の側（`master`）から取ったため。bare の既定の枝も `master` に替えて通した。
- 文書の足りない所:
  - README の「要る物」・「5 分で試す」と SKILL.md の「部署を立てる」は、部署の回にも GitHub に在って gh で読めるリポジトリが要るとは書いていない。今回の頼み（試しの手順）も、手元の bare で通せると読んで書かれていた。
  - 会社の形のファイルは、手元の `origin/HEAD` が指す枝から読む（SKILL.md の `--tree` の節）、部署の作業場は GitHub の既定の枝から作る。どちらの元から本流を決めるかが、命令によって違う。
  - 止めたときの「whose-turn が自分の番の PR を集められない」は、PR を開く回の訳で、部署の回の人には何を直せばよいかが分からない。

### 4. 納品の「決め手」は http(s) の URL が無いと送れない。コードの直しでは、部署が URL を足すか、止まる（人だけなら止まる）

- どこで: `--deliver` の項目の確かめ（`nodes/deliver.py` の `URL_ITEMS = ("決め手",)`。会社の形で項目を替えても、「決め手」という名前の項目には必ず URL を求める）。
- 何をして: 担当と作業に、`src/calc.py` に関数を足す頼みを 5 回出した（macOS 4 回・Linux 1 回）。
- どうなったか:
  - macOS の担当: 1 回目は「原典の URL が無い」で送り返され、窓口へ SendMessage で判断を求めた。その後、Stop のフックに差し戻されて、Python の言語仕様の URL を足して送った。2 回目と 3 回目も同じ形で、言語仕様と PEP 257 の URL を足した。どれも、直した中身の原典ではない。
  - macOS の作業: `https://example.invalid/none` という、無い URL を足して送った（要約の中で、無い物だと断っていた）。
  - Linux の担当: URL を作らずに止まった。Stop のフックが 3 回差し戻し、3 回目の後に止まった。納品は届かず、窓口は要約の本文を受けていない。会社の形の担当に `deliver = ["結論", "やったこと", "残った疑問", "枝"]` を足して本流に入れ、担当の窓に「決め手を やったこと に直して返す」と打ち込んで、ようやく届いた。
- 文書の足りない所:
  - 頼みの文（`--ask` が打ち込む「要約を 結論・決め手・残った疑問・枝 の見出しで書いた…」）は、URL が要るとは言わない。部署は送り返されて初めて知る。
  - SKILL.md は既定の項目を「決め手（原文の一句と原典の URL）」と書き、コードを書く部署の例（`deliver = ["結論", "差分", "試験", "残った疑問", "枝"]`）も出す。ただし `--init-company` の下書きの担当と作業は既定の項目のままで、`deliver` は注記に入っている。下書きどおりに会社を作ると、コードの直しの部署が全部この形で詰まる。
  - URL を求める決まりは、無い URL を足して通す振る舞いを招いた（上の macOS の作業）。

### 5. 担当が、作業の部署の入れた変更を消して本流に入れた（試しの中で起きた。関門は通った）

- 何をして: 担当「計算」に `sub` と `mul` を頼んだ（どちらも本流に入った）。続けて、窓口から作業「計算：割り算」に `div` を頼んだ（本流に入った）。その後、担当に「各関数に 1 行の docstring を足す」を頼んだ。
- どうなったか:
  - 担当は、`git fetch origin` と `git switch -c feat/calc-docstrings origin/master` の直後に、`src/calc.py` を読み直さず、前の頼みで覚えた中身（`add`・`sub`・`mul`）を heredoc で丸ごと書いた。
  - `div` が消えた commit が、関門（`python3 -m py_compile src/calc.py`）を通って本流に入った。
  - 担当の納品は「add・sub・mul に docstring を足した」と書き、消したことには触れなかった。窓口は、その後の `--clean` のときに自分で気づいた。
- この試しの作り方の分:
  - 会社の形の決まり（注記）では、担当の受け持ちの中の並べたい作業は、担当が作業に頼む。窓口から直に作業に頼んだのは、その決まりから外れている。
  - 関門を `py_compile` だけにしたのも、試しの側の選び。
- 文書の足りない所:
  - 常設の担当は、前の頼みの中身を覚えたまま次の頼みを受ける。下書きの担当の本文は「頼みごとに fetch して枝を切る」までで、切った後に触るファイルを読み直すことを言わない。
  - 組織の決まり（担当の受け持ちに窓口が直に作業を頼まない）は、会社の形の注記にだけ在り、どの会話にも届かない（下の 7）。

### 6. gh の鍵を `GH_TOKEN` で渡す人は、下書きの `gh_user` のせいで部署を立てられない（Linux。人だけなら止まる）

- 文書の足りない所: SKILL.md の `gh_user` の節は、鍵を `gh auth token --user` で取り出すとは書く。`GH_TOKEN` で gh を使う人（コンテナ・CI の形）が `gh_user` を書いてはいけないことは書かない。下書きは、今のアカウントが `GH_TOKEN` から来たときにも `gh_user` を書く。

### 7. 組織の決まりが会話に届かないので、窓口と担当が持ち主に聞きに来る

- どうなったか:

- 文書の足りない所: 下書きの注記は「部署の会話には届かないので、部署に守らせることは役の本文にも書く」と言う。窓口にも届かないこと、窓口の役の本文を書くかは、言わない。

### 8. 小さな詰まり

- `--desk` は、`claude --name 窓口` で起こして名前がもう `窓口` の会話にも、「揃えるなら /rename 窓口 を打つ」と出した。

## 通ったこと

- 入れる（macOS・Linux）: `claude plugin marketplace add raiki61/claude-plugins` と `claude plugin install works-dispatch@raiki61` で、works-dispatch 0.17.2 と tiers 0.4.1 が入った。
- 初めての画面: 色の選び・安全の注意・フォルダの信頼の 3 つが順に出た（1 回目と同じ）。
- 点検: `/tiers:check 段 2` は、gh の鍵が無いときは「gh のログイン」だけを足りない物として出し、入れ方（`gh auth login`）を添えた。鍵を渡した後は全部 ok（Linux も）。`--check` は、設定が無いときに「部署の回の前提だけを確かめた」と言い、herdr の連携を入れる命令（`CLAUDE_CONFIG_DIR=… herdr integration install claude`）を注記に出した。
- `origin/HEAD` が無い clone（空の bare を clone した物）では、`--desk` が直す命令（`git remote set-head origin --auto`）を出した。
- `--desk`: 代表の clone の属性に、役 `窓口`・常駐・名前・アカウント・会話の id を書き、ペインの名前を付けた。窓口を起こし直して打ち直すと、会話の id を付け替えた。
- 担当（常駐）: `--task 計算 --branch work/calc --role 担当 --brief …` で立ち、会話の始まりに受け持ち（`src/ の直し`）が入った。頼みを 3 回続けて受け、毎回 `--land 計算` で本流に入れて納品した。`--tree` で「終わった」と出ている間も、次の `--ask` は届いた。
- 作業（都度）: 会社の名前は clone の名前と同じ `demo` になった。`--ask demo/作業 --task 計算：割り算 --branch feat/calc-div --text …` で新しく立ち、`--land` で本流に入れた。部署の会話がまだ動いている間に入れたので、`--land` は部署を消さず、入れた印（属性 `company.landed`）を書いて残した。`--clean --apply` で、会話・作業場・手元の枝を消した。
- `--reorg --name 計算係` を担当の作業場から打った。属性 `company.former-names` に `計算` が入り、作業場とペインの名前が替わった。前の名前で `--land 計算 --dry-run` を打つと「計算 は前の名前。部署の今の名前は 計算係」と出て引けた。窓口から前の名前で `--ask 計算` を打つと、計算係に届いた。
- 連絡: 窓口と部署は同じアカウントなので、部署から窓口へ SendMessage も届いた。納品は窓口の窓への 1 行と受付箱（`.git/company/inbox/`）の両方に届き、`log.jsonl` に頼みと納品が 1 行ずつ並んだ。

## 片付け

次の順に済ませた。最後に、一時の場所を指す処理が無いことを `ps` で確かめた。持ち主の herdr の server と `~/.config/works-dispatch/` は触っていない。

1. macOS: 担当の会話を `claude rm` で消した（作業の部署は `--clean --apply` で消えていた）。
2. 窓口を `/exit` で閉じた。裏の会話を抱える Claude Code の daemon（`claude --bg` が起こす、一時の HOME の物）は、会話が無くなって自分で止まった。
3. 一時の herdr の server を `herdr server stop` で止めた。
4. 一時の場所（HOME・clone・bare リポジトリ）を `rm -rf` で消した。
5. Linux: コンテナの herdr の server を止めた。コンテナと、試しのために作ったイメージを消した。
