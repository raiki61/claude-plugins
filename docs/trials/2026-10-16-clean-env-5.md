### 1. VM の再起動で落ちた担当は、次の頼みを受けない。戻し方が書いていない

  - herdr の server を起こし直すと、作業場とペインの名前は戻った。担当の会話は一覧に残っていたが、動いていなかった。
  - 窓口を起こし直して `--desk` を打つと、属性の会話の id を新しい窓口へ付け替えた。

## macOS と Linux（4 回目の直しの確かめ）

- 本社の属性が部署に写らない（4 回目の 3）: 直った。`--desk` の後に立てた担当の作業場の git の設定には、`company.former-names` が無く、`company.session` は部署自身の会話の id だった（macOS と Linux）。
- `--land` と auto mode（4 回目の 6）: 直った。下書きの担当と作業の役の設定に `autoMode.allow`（「この部署が works-dispatch の --land で自分の枝を本流に入れること。…関門を通してから早送りする決まりで、持ち主がこの会社の部署に許している」）が入り、担当の `--land` は止められなかった（macOS と Linux で 1 回ずつ。拒否は 0 件）。判定は毎回同じではないので、1 回ずつでは確かとは言えない。
- `.gitignore` の無いリポジトリの `__pycache__`（4 回目の 7）: 直った。担当に「手で動きを確かめてから入れて」と頼み、担当が `from calc import sub` で `src/__pycache__/` を作った。代表の clone の `.git/info/exclude` に `__pycache__/` が足されていて（`git status --ignored` で `!!`）、`--land` は止まらずに本流に入れた。
- commit に足すファイル: 担当は `git add src/calc.py` だけを打った（macOS と Linux）。
- 古い Python の止まる前のフック（4 回目の「3 回目の直しの確かめ」）: 直った。PATH を `/usr/bin` だけにした macOS の会話を `claude -p` で 1 ターン、続けて `--continue` でもう 1 ターン回した。止まる前のフックの 1 行は、1 ターン目にだけ出て（終了の値 1）、2 ターン目は何も出さなかった（終了の値 0）。

### 2. 古い Python の会話の始まりのフックは、起こすたびと戻すたびに出る

- 上の 2 ターン目（`--continue`）でも、会話の始まりのフック（`SessionStart:resume`）は同じ 1 行を出した（終了の値 1）。会話ごとに 1 回にしたのは止まる前のフックだけ。

### 1 回目の 11（`CLAUDE_CONFIG_DIR` を環境で入れる人）: 変わらない（文書のとおり）
