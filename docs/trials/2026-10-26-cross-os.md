# macOS 専用の書き方の直しの後の版を、Linux と Windows で入れて試す（2026-10-26）

macOS でしか動かない書き方の直しが 4 件 main に入った（頼みの言葉では「標準の受付 062135-00c4c3 の 5 回目」。標準の部署が OS ごとのずれを見つけて各担当に頼んだ回）。

- 仕組みの受付 79c989: tiers の statusline と works-dispatch。
- 点検の受付 6f4c7d: gates のフックと探しのゲート（searchgate）。
- 見直しの受付 67d953: graphloops と convergence-loops の Python の選び方。
- 見渡しの受付 f788d9: attention のスキルとコマンドの Python の選び方。

受付は works-dispatch の頼みの番号で、仕組み・点検・見直し・見渡しは直しを受け持つ部署の名前（仕組みは works-dispatch と tiers、点検は gates、見直しは graphloops と convergence-loops、見渡しは attention、説明書はルートの README などの文書の受け持ち）。

[docs/standards/cross-os.md](../standards/cross-os.md) の決まり 6 のとおり、フックの起動の行・ステータスラインの殻・スキルの本文が打たせるコマンドは CI が起動しない。そこで、main の marketplace から Linux と Windows に入れて、実際に起きるかを試した。試しでは直していない。macOS は持ち主が手元で使っているので試していない。

この記録の言葉:

- 代わりの物: Windows に初めから在る「アプリ実行エイリアス」の `python3.exe`・`python.exe`（`%LOCALAPPDATA%\Microsoft\WindowsApps` の中）。Python を入れていない人を Microsoft Store へ誘う物で、Python としては動かない。
- 初見読み・読み手: gates の、文脈を持たない別の claude（読み手）に、外へ出す文や書いた文書を読ませて詰まりを返させる仕組み。外部投稿ゲートは `gh` の投稿の前に読ませ、通らなければ投稿を止める。
- 探しのゲート（searchgate）: `/` やドライブのルートのような全体を起点にした探しを止める gates のフック。
- 待ちのゲート（waitgate）: 裏の処理の終わりを `pgrep -f` のループで待つ形を止める gates のフック（同じ文字列を持つ別の待ちに当たって終わらなくなるため）。
- 試しの会話: 下の「試しの環境」の `claude -p` の会話。頼みの文はその会話に渡した文。

## 結果のあらまし

- 4 件の直しが狙った所（Python を「起動できるか」で選ぶこと、1 つの OS でしか動かない物は訳を出して止まること、探しのゲートの起点の一覧）は、Linux と Windows のどちらでも動いた。下の詰まりの 2 と 3 は、4 件の直しが扱っていなかった所。
  - 試したフックは全部起き、終了の値は全部 0 だった（使用枠が尽きた時だけ起きる works-dispatch の StopFailure は試していない）。gates・graphloops・tiers・works-dispatch のフックを、SessionStart・UserPromptSubmit・PreToolUse・PostToolUse・Stop で見た。
  - Windows の PATH の先頭の `python3` は、Python を入れていない人向けの代わりの物（Microsoft Store へ誘う物。起動すると終了の値 49 か 9009 で終わる）だった。それでも、フックとスキルのコマンドは本物の Python 3.15 を選んで動いた。
  - 探しのゲートは、Windows の `C:/` を起点にした `grep -rn` を止めた。
- 新しく見つけた詰まりは 3 件。直しを受け持ちの担当に頼んだ（受付番号は各項に書いた）。
  1. ターミナルだけで入れると、convergence-loops と graphloops が読み込まれない。人だけなら止まる。
  2. 鍵を環境変数（`CLAUDE_CODE_OAUTH_TOKEN`）でだけ渡している人は、Linux と Windows で gates の初見読みの読み手が起動しない。その結果、gh の投稿を全部止め、ターンの終わりに書いた文書を読み手に読ませることもできない。
  3. gates の知らせの文が、手で読ませる手順として素の `python3 <パス> read` を打たせる。Windows ではこれが代わりの物に当たって動かない。
- 作った物は片付け、鍵の値がファイルに残っていないことを確かめた（下の「片付けと鍵」）。

## 確かめた物

### gates のフック

- 外部投稿ゲート（coldread-gate）:
  - 投稿の前に読み手を起動しようとした。下の「新しく見つけた詰まり」の 2 で起動に失敗し、「検査できていないので止めた」で止めた。
  - Linux でふつうのログインの鍵のファイルを置いた回は、読み手が読み、指摘を付けて止めた（deny）。
  - SKILL.md の手の検査の行（`bash run-python.sh coldread-gate.py read <ファイル>`）は、Linux では読み手の補いと疑問を返した。Windows では「読み手を起動できなかった」と出た（詰まりの 2）。
- 探しのゲート（searchgate）:
  - Linux の `grep -rn … /` と、Windows の `grep -rn … C:/` を止めた。Windows の知らせは「grep の起点 C: は / やホームの全体なので止めた」だった。
  - Claude Code 2.1.310 の会話には Grep・Glob のツールが無かった（「No such tool available」）。そのため、フックの Grep・Glob の口は Bash の grep でしか試せていない。
- 待ちのゲート（waitgate）: `until pgrep -f …; do sleep 1; done` を、どちらの OS でも止めた。
- 書いた文書の記録（PostToolUse）と、ターンの終わりの読み（Stop）:
  - 300 字未満の文書は読まずに通した。
  - 300 字を超える `guide.md` は、ターンの終わりに読みに回った。読み手が起動しなかった回は「読み手が読めなかった文書」と知らせた（詰まりの 2）。

## 新しく見つけた詰まり

### 1. ターミナルだけで入れると、convergence-loops と graphloops が読み込まれない（人だけなら止まる）

- どこで: ルートの README の Install の「From a terminal, these two lines do the same.」の 2 行。まだ対話の Claude Code を一度も起動していない機械で打った。
- どうなったか:
  - convergence-loops の依存の pr-review-toolkit は、Anthropic の公式の marketplace（claude-plugins-official）に在る。この marketplace がまだ登録されていないので、入れる時に「Warning: dependency "pr-review-toolkit@claude-plugins-official" was not installed (no marketplace you have added lists it)」と出た。
  - その後の `claude plugin list` では、convergence-loops が「failed to load」、それに依る graphloops も「Dependency "convergence-loops@raiki61" is disabled」で読み込まれなかった。
  - Linux: 対話の claude を一度起動すると公式の marketplace が登録された。その後に `claude plugin install pr-review-toolkit@claude-plugins-official` を打って直った。
  - Windows: 知らせの言うとおり打っても直らなかった。
    1. `claude plugin install pr-review-toolkit@claude-plugins-official` は「not found in marketplace … try `claude plugin marketplace update claude-plugins-official`」で失敗した。
    2. それに従った `marketplace update` は「Marketplace 'claude-plugins-official' not found」で失敗した。
    3. `claude plugin marketplace add anthropics/claude-plugins-official` を打つと、依存も一緒に入って直った。

    この VM は前の試しで marketplace を消したことがある。そのため、対話の起動で公式の marketplace が登録されるかは、この VM では確かめられていない。README の直しは、Claude Code の文書（下）が先に打つと書く 1 行を足すことなので、この点に依らない。
- 文書の足りない所:
  - Claude Code の文書（[Install from your shell](https://code.claude.com/docs/en/discover-plugins#install-from-your-shell)）は、まだ誰も対話の会話を開いていない機械では公式の marketplace が登録されていないと書く。だから、そこから入れる台本は `claude plugin marketplace add anthropics/claude-plugins-official` を先に打つ、とも書く。
  - ルートの README の Install は、この行を書かず、「Installing a plugin that depends on other plugins installs those too」と書いている。
  - convergence-loops の README の「Dependencies and how you obtain them」も「it is installed together when you install this plugin」と書いている。
- 頼んだ先:
  - ルートの README: 説明書（受付 20261026-112305-a0f9eb）。
  - convergence-loops の README: 見直し（受付 20261026-112324-bf6693）。

### 2. 鍵を環境変数でだけ渡している人は、Linux と Windows で gates の初見読みが動かない

- どこで: gates の外部投稿ゲート（PreToolUse）と、ターンの終わりの文書の読み（Stop）。Claude Code の鍵を `CLAUDE_CODE_OAUTH_TOKEN` だけで渡している（`claude setup-token` で作った鍵を環境変数に置く形。`~/.claude/.credentials.json` が無い）。
- どうなったか:
  - 読み手の子の claude が「Not logged in · Please run /login」で起動しなかった（ゲートの知らせには「認証: none」と添えてあった）。あわせて「Claude configuration file not found at: …/.claude/.claude.json」も出た。
  - 外部投稿ゲートは「検査できていないので止めた」で、`gh` の投稿を全部止めた。ターンの終わりは「読み手が読めなかった文書」を毎回知らせた。
  - フックのプロセスの環境変数には `CLAUDE_CODE_OAUTH_TOKEN` が無かった。gates の鍵の部品（`claude_auth.auth_env`）は、受け継いだ環境変数、macOS だけの keychain の順に探し、どちらも無ければ鍵を渡さない。その場合、子の claude は `~/.claude` の鍵のファイルだけを頼りにする。
  - Linux でふつうのログインの形（`~/.claude/.credentials.json`）を置いた回は、読み手が起動して読んだ。Windows でこの形は試していない（VM に鍵のファイルを書かないため）。
- 文書の足りない所: gates の README は、鍵を環境変数だけで渡す人は Linux と Windows で読み手が起動しないこと、その時にどうすればよいかを書いていない。止める時の知らせも、ログインの仕方を指さない。
- 頼んだ先: 点検（受付 20261026-112245-da9321。3 と一緒に頼んだ）。頼みでは README と知らせの文を求め、仕組みで救う直しにするかは点検に任せた。
