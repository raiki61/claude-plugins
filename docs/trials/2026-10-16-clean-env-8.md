# まっさらな環境で 8 回目の試し: 未納品のまま落ちた部署の戻し方（2026-10-17）

7 回目（[2026-10-16-clean-env-7.md](2026-10-16-clean-env-7.md)）で通らなかった形 B（未納品の頼みを持ったまま落ちた担当を、`--ask` が戻して納品を促す）を、割り振りの担当（works-dispatch と tiers を直す受け持ちの部署）が works-dispatch 0.19.6 で直した（本流 2f082ab）。今回は形 B だけを、3 つの OS の一時の環境で確かめた。直してはいない。試しは 2026-10-17 に回した（ファイル名の日付は 1〜7 回目と揃えた）。

この記録の言葉は 7 回目と同じ（窓口・部署〔担当と作業〕・納品・部署の窓・形 B・「人だけなら止まる」）。`w2:p1` のような印は herdr の作業場 2 のペイン 1。「頼み N・納品 M」は、その OS の試しの最初からの、窓口の受付箱の記録（`log.jsonl`）の頼みと納品の数（担当が自分で作業の部署に頼んだ分も含む）。

## 結果のあらまし

- macOS と Windows: 形 B は、手当て無しで通った。どちらも、部署の窓がシェルに戻っている（macOS）か、herdr ごと消えて窓が新しいシェルになっている（Windows）形で、0.19.5 からの「窓に会話が居なければ戻す」道と、0.19.6 で足した「入力欄に残った 1 行に Enter を足す」が働いた。`--ask` は会話を短い id の attach で戻し、促しの 1 行を送り、入力欄に残っていたので Enter を足し、新しい頼みは送らずに止まった。担当は続きを進めて納品した。7 回目の Windows の詰まり（促しが入力欄に残る）は直っていた。
- 0.19.6 で足したもう 1 つの道（会話の一覧が `stopped` で、前の attach が「Waking session …」のまま窓の前に残る形。残った attach を Ctrl-C で終わらせて打ち直す）は、3 つの OS のどれでも形を作れず、確かめていない。
- Linux: 形 B を 3 通りの落とし方で作ろうとしたが、上の道に入る形にならなかった（下の 1）。
  - 落とした担当は、どの回も、しばらくすると起き直って頼みを済ませ、納品した（1 回目は窓の attach が起こした。2・3 回目は何が起こしたか確かめていない）。結果として未納品のまま止まり続けはしなかった。
  - ペインを閉じてから止めた回だけは、`--ask` が戻せず、人が打つ命令（`claude attach <id>`）を出して止まった。作業場を開き直した後は「部署の窓で続きを頼む」と言ったが、その窓には会話が居なかった（下の 2）。説明書どおりに手を打っても戻せない形で、人だけなら止まる（担当が約 1 分後に自分で起き直したので、今回は止まり続けなかった）。
- SKILL.md の「部署の会話を止める」の「窓で Ctrl-C を押して attach を終わらせる」は、Linux では attach を終わらせなかった。macOS でも、Ctrl-C の直後の画面は attach のままだった（下の 3）。
- 作った物は全部片付け、鍵の値が残っていないことを確かめた（下の「片付けと鍵」）。

## 試しの環境

- macOS（Darwin 25.6.0・herdr 0.9.3）・Linux（`debian:trixie-slim`・herdr 0.9.5）・Windows（VM の Windows 11 ARM64・herdr 0.9.5）。Claude Code はどれも 2.1.301。works-dispatch 0.19.6・tiers 0.4.4（marketplace から入れた）。
- 隔離と鍵の渡し方は 7 回目と同じ。gh の鍵は使っていない。
- この試しを頼んだ窓口の指示に従い、macOS では `claude daemon stop` を打っていない（一時の HOME の中でも）。

## 3 つの OS の形 B

### macOS: 通った

- 落とし方: 担当に mean・twice_mul・README の節を頼み、頼みが届いた 3 秒後に、SKILL.md の手順どおり部署の窓で Ctrl-C を 2 回押し、`claude stop <短い id>` で止めた。部署の窓は「Session 391d874e has exited.」でシェルに戻った。未納品の頼みが残った（頼み 2・納品 1）。
- `--ask` の出力（終了の値 2）:
  - 「部署の窓に会話が居なかったので、ペイン w2:p1 で claude attach 391d874e を打って戻した」
  - 「戻した部署に、受付 … の納品を促した（sent。入力欄に残っていたので Enter を足した）」
  - 「止めた: … まだ納品していない。会話が落ちていたので戻して納品を促した。納品が届いてから頼み直す」
- 担当は mean と twice_mul を本流に入れ（dce3c9d）、納品した。

### Windows: 通った

- 落とし方: 担当に同じ頼みを出し、頼みが届いた 5 秒後に VM を再起動した（`Restart-Computer -Force`）。起き直した後も未納品の頼みが残っていた（頼み 2・納品 1）。herdr の server と窓口を起こし直し、`--desk` の後に `--ask` を打った。
- `--ask` は「ペイン w2:p1 で claude attach 18e0babb を打って戻した」「納品を促した（sent。入力欄に残っていたので Enter を足した）」と出して止まった。担当は納品した。窓口の AI は、納品が届いた後に同じ頼みを打ち直し、それも届いて納品された。

### 1. Linux: 0.19.6 の直した道に入る形を作れなかった（詰まりではない）

- 1 回目（窓の attach を開いたまま、コンテナの中で `claude daemon stop --any`）: 部署の窓の attach が会話を起こし直し、担当は頼みを済ませて納品した。その 4 秒後に打った `--ask` は、未納品が無いので、そのまま新しい頼みを送った（形 A と同じ動き。正しい）。
- 2 回目（窓で Ctrl-C を 2 回押した後に、同じく裏の処理を止めた）: 下の 3 のとおり attach は終わらず、「Starting background service… / Waking session 0d3d4727…」の後に「Reconnecting to 0d3d4727… / Session 0d3d4727 has exited.」でシェルに戻った。会話の一覧の状態は空（`stopped` ではない）。その約 1 分後、担当は頼みを済ませて納品した。何が起こし直したかは確かめていない。
- 3 回目（窓のペインを閉じて〔`herdr pane close`〕から `claude stop <短い id>`）: 下の 2。
- どの回も、未納品の頼みは最後に納品された。

### 2. Linux: ペインを閉じてから止めた部署は、`--ask` が戻せない

- ペインを閉じると、部署の作業場も herdr から閉じた。未納品の頼みが残った（頼み 6・納品 5）。
- `--ask` は「部署の会話を戻せなかった（部署の作業場が herdr に開いていない）。部署の作業場のペインで claude attach 0d3d4727 を打って戻す」「止めた: …の窓に会話が居ない」で止まった（終了の値 1）。
- 作業場を開き直した（`herdr worktree open --cwd <代表の clone> --path <部署の作業場>`。新しいペイン w3:p1 はシェル）後の `--ask` は、「まだ納品していない。…（部署の会話が止まって見えるなら、部署の窓 w3:p1 で続きを頼む）」で止まり、戻しも促しもしなかった。w3:p1 には会話が居ないので、勧めどおりに打っても会話には届かない。
- その約 1 分後に、担当は自分で起き直って頼みを済ませ、納品した。
- 文書の足りない所: SKILL.md の「部署の会話を止める」は「ペインを閉じる」も止め方に挙げるが、その後の戻し方（作業場を herdr で開き直し、そのペインで attach を打つ）は書いていない。

### 3. Linux: 部署の窓の Ctrl-C は attach を終わらせない

- 部署の窓で頼みの途中に Ctrl-C を 2 回押しても、attach の画面は残った（入力欄と「esc to interrupt」が出たまま）。その後に裏の処理を止めると、attach が起こし直しに入った（上の 1 の 2 回目）。
- macOS でも Ctrl-C を 2 回押した直後の画面は attach のままだった。終わったのは `claude stop` の後（「Session … has exited.」）。macOS で Ctrl-C が attach を終わらせたかは確かめていない。
- SKILL.md の「部署の会話を止める」は「先に部署の窓の attach を終わらせ（窓で Ctrl-C を押すか、ペインを閉じる）」と書く。Ctrl-C で終わる形は、今回は見ていない。

## 片付けと鍵

- macOS: 一時の環境の部署の会話を名指しで消し（`claude rm`）、窓口を閉じ、一時の herdr の server を止め、一時の場所を消した。`ps` で残りが無いことを確かめた。
- Linux: 部署の会話を消し、herdr の server を止め、試しのコンテナ（`clean-env-8-linux`）とイメージ（`clean-env-8-trial`）を名前で指して消した。
- Windows（VM は止めていない。試しの中で 1 回再起動した）: 部署の会話を消し、窓口を閉じ、裏の処理と herdr の server を止めた。部署の作業場・試しのリポジトリ・試しの会話の記録・herdr の作業場の控え・プラグインと marketplace を消し、控えた `settings.json` と `.claude.json` を戻した。Claude Code と herdr の処理が残っていないことを確かめた。
- 鍵: macOS の一時の HOME・Linux のコンテナの `/home/u` と `/tmp`・VM の `~\.claude`・`.claude.json`・`AppData\Roaming\herdr`・`%TEMP%` の全部のファイルを、Claude Code の鍵の値で探した。当たるファイルは 0 だった。値は画面にも出していない。GitHub には書いていない。
