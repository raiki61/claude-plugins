8 回目（[2026-10-16-clean-env-8.md](2026-10-16-clean-env-8.md)）の残りを、割り振りの担当（works-dispatch と tiers を直す受け持ちの部署）が works-dispatch 0.19.7 で直した（本流 1c24ed2）。次の 3 つだけを、3 つの OS の一時の環境で確かめた。直してはいない。試しは 2026-10-17 に回した（ファイル名の日付は 1〜8 回目と揃えた）。

- 手順 1: 未納品の頼みを持った担当のペインを閉じて（`herdr pane close`）から `claude stop <短い id>` で止め、`--ask` が作業場を開き直して戻し、納品を促すか。
- 手順 2: SKILL.md の「部署の会話を止める」の手（部署の窓で Ctrl+Z を押して attach を抜けてから `claude stop <短い id>`）が書いた通りに効くか。止めた後の `--ask` が戻して促すか。
- 手順 3: 8 回目に出た「開き直した後の新しいペインを、会話が居ると見て止まる」形が出たら、その時の会話の一覧の状態と herdr の印を残す。

この記録の言葉は 8 回目と同じ（窓口・部署〔担当と作業〕・納品・部署の窓・形 B・「人だけなら止まる」・「頼み N・納品 M」）。`w3:p1` のような印は herdr の作業場 3 のペイン 1。

## 結果のあらまし

- 手順 1: macOS と Linux は通った。Windows は、作業場を開き直して戻すところまでは通った。ただ、`--ask` が「納品を促した（sent）」と出したのに、促しの 1 行が会話に届いていなかった。担当は止まったままで、人だけなら止まる（下の 1）。
- 手順 2: Ctrl+Z は、3 つの OS とも attach の画面を抜けてシェルに戻した。その後の `claude stop` で、会話は止まった。止めた後の `--ask` の結果は分かれた。
  - Linux: 戻して促し（入力欄に残った 1 行に Enter を足した）、担当は納品した。
  - Windows: 戻して「入力欄に残っていたので Enter を足した」と出したが、促しの 1 行は入力欄に残ったまま、7 分以上進まなかった（下の 1）。部署の窓で Enter を押すと、担当は進んだ。
  - macOS: `--ask` を打つ前に、止めた会話が約 1 分で自分で起き直って納品を済ませていた。`--ask` は未納品が無いので、そのまま新しい頼みを送った（下の 2）。
- 手順 3 の形（開き直した後の新しいペインを、会話が居ると見て止まる）は、3 つの OS のどれでも出なかった。
- 作った物は全部片付け、鍵の値が残っていないことを確かめた（下の「片付けと鍵」）。

## 手順 1（ペインを閉じて止める）

- macOS: 頼み 4・納品 3 の所でペインを閉じて止めた。`--ask` は「部署の窓に会話が居なかったので、ペイン w3:p1 で claude attach f68b39e1 を打って戻した」「戻した部署に、受付 … の納品を促した（sent）」「止めた: … 納品が届いてから頼み直す」と出した（終了の値 2）。担当は 15 秒後に納品した。窓口の AI は、納品の後に同じ頼みを打ち直し、それも届いた。
- Linux: 同じ 3 行（促しは「sent。入力欄に残っていたので Enter を足した」）で止まり、担当は 14 秒後に納品した。
- Windows: 下の 1。
- macOS と Linux では、開き直した作業場のペイン（w3:p1）に部署の名前（`計算`）が付いていなかった（herdr のペインの一覧の `label` が空）。Windows は見ていない。

### 1. Windows: 戻した会話への促しの 1 行が、届かないか、入力欄に残る（人だけなら止まる）

- 手順 1（ペインを閉じて止めた後）:
  - `--ask` は「ペイン w3:p1 で claude attach c0585c32 を打って戻した」「戻した部署に、受付 20261016-181520-cfe83b の納品を促した（sent）」と出して止まった。
  - w3:p1 の会話の画面には、落とす前の頼み（sum3 と prod3）の後に「Ran 1 shell command」があるだけで、促しの 1 行は無く、入力欄も空だった。会話の一覧は `idle`。
  - 7 分以上待っても納品は来なかった（頼み 6・納品 5 のまま）。部署の窓に「止まる前の頼みを続けて、本流に入れてから納品して」と打つと、担当は納品した。
- 手順 2（Ctrl+Z で抜けて止めた後）:
  - `--ask` は「ペイン w2:p1 で claude attach c0585c32 を打って戻した」「戻した部署に、受付 20261016-180150-8a9a36 の納品を促した（sent。入力欄に残っていたので Enter を足した）」と出して止まった。
  - 部署の窓の入力欄には「❯ 再開の知らせです: この会話は落ちて戻った。…」が残ったままで、7 分 30 秒待っても納品は来なかった。部署の窓で Enter を押すと、担当は続きを進めた。
- 8 回目の Windows では、同じ「Enter を足した」で送信されていた。今回は、足した Enter が効かなかった回と、1 行そのものが届かなかった回があった。attach で戻した直後の会話の画面が、打った字を受けられるようになるまでの時間に左右されると見ている（確かめていない）。

## 手順 2（Ctrl+Z で抜けてから止める）

- 3 つの OS とも、頼みの途中で部署の窓に Ctrl+Z を送ると、attach の画面を抜けてシェル（macOS と Linux は bash、Windows は PowerShell）の入力待ちに戻った。続く `claude stop <短い id>` で会話は止まり、窓の attach が会話を起こし直すことは無かった。8 回目の Ctrl-C と違い、SKILL.md の書いたとおりに効いた。
- Linux: 止めた直後の `--ask` は戻して促し（「sent。入力欄に残っていたので Enter を足した」）、担当は 17 秒後に納品した。
- Windows: 上の 1。

### 2. macOS: 名指しで止めた会話が、約 1 分後に自分で起き直って頼みを済ませた

- 頼みが届いた 3 秒後に Ctrl+Z で抜け、`claude stop f68b39e1` で止めた。20 秒後に `claude agents --json --all` を打つと、会話の一覧の状態は空（`stopped` ではない）で、頼み 2・納品 1 のままだった。
- その約 30 秒後（止めてから約 1 分後）に、担当は頼みを済ませて納品した。何が起こし直したかは確かめていない。20 秒後に打った `claude agents` が裏の処理を起こし、止めた会話を続けさせた形に見える（8 回目の Linux と同じ形）。
- そのため、この回の `--ask` は戻しも促しもせず、未納品が無いので新しい頼みを送った（正しい動き）。手順 2 の `--ask` の側は、macOS では確かめていない（7・8 回目の macOS では、同じ形で戻して促すことを確かめている）。
- `claude stop` で止めた会話は、裏の処理が次に起きたときに続きから動き出すことがある。部署の会話を止めて置いておきたい人には、止めた後に `claude agents` などを打つと会話が動き出しうる、と知らせる値打ちがある（文書には無い）。

## 手順 3（開き直したペインを、会話が居ると見て止まる形）

- 3 つの OS の手順 1 のどれでも、`--ask` は開き直したペイン（w3:p1）に attach を打って戻した。8 回目の「部署の窓 w3:p1 で続きを頼む」で止まる形は出なかったので、残す記録は無い。
