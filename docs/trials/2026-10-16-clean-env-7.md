# まっさらな環境で 7 回目の試し: 落ちた部署の戻し方（2026-10-17）

6 回目（[2026-10-16-clean-env-6.md](2026-10-16-clean-env-6.md)）で働かなかった落ちた部署の戻し方を、割り振りの担当（works-dispatch と tiers を直す受け持ちの部署）が works-dispatch 0.19.5 で直した（本流 a2a8bcf）。今回は戻し方に絞り、3 つの OS の一時の環境で、担当の会話を落としてから `--ask` を打った。道の頭は macOS で通した。直してはいない。試しは 2026-10-17 に回した（ファイル名の日付は 1〜6 回目と揃えた）。

この記録の言葉は前の記録と同じ（窓口・部署〔担当と作業〕・会社と会社の形・納品・部署の窓〔部署の会話の画面を出した herdr のペイン〕）。「N 回目の M」は N 回目の記録の M 番目の項。`w2:p1` のような印は herdr の作業場 2 のペイン 1。

確かめた形は 2 つ。

- 形 A（未納品なし）: 担当が納品を済ませた後に会話を落とし、次の頼みを `--ask` で打つ。戻して頼みが届けばよい。
- 形 B（未納品あり）: 担当が頼みを受けて納品する前に会話を落とし、次の頼みを `--ask` で打つ。戻して「納品を促す 1 行」を打ち、止まればよい（0.19.5 の変更の記録のとおり）。

## 結果のあらまし

- 道の頭（入れる → 点検 → `--init-company` → 担当を立てる → 頼む → `--land` → 納品）は、macOS で詰まり 0 のまま通った。
- 形 A は、3 つの OS とも通った。会話を名指しで止め（`claude stop <短い id>`）、`--ask` を打つと「部署の窓に会話が居なかったので、ペイン w2:p1 で claude attach <短い id> を打って戻した」と出て、頼みが届き、担当は本流に入れて納品した。
- 形 B は、OS と落とし方で結果が分かれた。
  - macOS（窓の attach を終わらせてから名指しで止めた）: 通った。戻して促し、担当は納品した。
  - Windows（VM を再起動して herdr ごと消した）: 戻して促すところまでは通った。促しの 1 行は部署の入力欄に入ったまま送信されず、7 分待っても進まなかった。部署の窓で Enter を押すと、担当は続けて納品した（下の 1）。人だけなら、促しが届いていないと気づきにくい。
  - Linux（Claude Code の裏の処理を止めた）: 戻さずに「まだ納品していない」で止まった（下の 2）。言葉の勧めどおりに、部署の窓で手で attach して続きを頼むと、担当は納品した。
- 試しの作り方で気づいた物が 2 つある（下の 3・4）。部署の窓で attach の画面が開いていると、名指しで止めても会話が起き直る。attach の画面を強く終わらせると、窓の端末が崩れる。
- 作った物は全部片付け、鍵の値が残っていないことを確かめた（下の「片付けと鍵」）。

## 試しの環境

- macOS（Darwin 25.6.0・herdr 0.9.3）・Linux（`debian:trixie-slim`・herdr 0.9.5）・Windows（VM の Windows 11 ARM64・herdr 0.9.5）。Claude Code はどれも 2.1.301。works-dispatch 0.19.5・tiers 0.4.4（marketplace から入れた）。
- 隔離と鍵の渡し方は 6 回目と同じ。gh の鍵は使っていない。
- 頼みの守ることに従い、macOS では `claude daemon stop` を打っていない。会話は、一時の環境の物を名指しで止めた。

## 戻し方で見つけた詰まり

### 1. Windows: 促しの 1 行が部署の入力欄に入ったまま送信されない（人だけなら止まる）

- 何をして: 担当に mean と twice_mul と README の節を頼み、頼みが届いた 5 秒後に VM を再起動した（`Restart-Computer -Force`）。起き直した後、herdr の server と窓口を起こし直し、`--desk` の後に `--ask 計算` を打った。
- どうなったか:
  - `--ask` は次の 3 行を出して止まった（終了の値 2）。
    - 「部署の窓に会話が居なかったので、ペイン w2:p1 で claude attach 81cedbd6 を打って戻した」
    - 「戻した部署に、受付 … の納品を促した（sent）」
    - 「止めた: … まだ納品していない。会話が落ちていたので戻して納品を促した。納品が届いてから頼み直す」
  - 部署の窓には「❯ 再開の知らせです: この会話は落ちて戻った。受付 …（窓口から）の頼みをまだ納品していない。済んでいれば要約を納品の命令（--deliver）で返し、途中なら続けてから返す。」が入力欄に入ったまま残った。7 分待っても納品は来なかった。
  - 部署の窓で Enter を 1 回押すと、担当は続きを進めて納品した。
- macOS では、同じ促しは送信されて、担当は納品した。`docs/observed.md` は、herdr で送った文字が入っても送信されないことがあると書く（`/exit` の例）。Windows の会話を attach で戻した直後でも同じ形が出たと見ている（訳は確かめていない）。

### 2. Linux: 裏の処理を止めた形では、戻さずに「まだ納品していない」で止まる

- 何をして: 担当に頼みを出し、頼みが届いた 4 秒後に、コンテナの中で Claude Code の裏の処理を止めた（`claude daemon stop --any`。コンテナの中なので、持ち主の会話には触れない）。続けて窓口から `--ask 計算` を打った。
- どうなったか:
  - 部署の窓には、前の attach の終わり（「Session f59ee07a has exited.」）の後に、もう 1 つの `claude attach f59ee07a` と「Starting background service… / Waking session f59ee07a… / Session f59ee07a has exited.」が出ていた。会話は起きてすぐ終わった。この 2 つ目の attach を打ったのが dispatch か、前の attach の画面かは確かめていない。
  - `--ask` は「止めた: 宛先の部署 demo/計算 は受付 …（頼み元 窓口）をまだ納品していない。納品を待つか、別の部署に頼む（部署の会話が止まって見えるなら、部署の窓 w2:p1 で続きを頼む）」で止まった（終了の値 2）。「戻した」とも「促した」とも出なかった。
  - 部署の窓で `claude attach f59ee07a` を手で打つと会話が戻り（一覧で idle）、続きを頼むと担当は納品した。
  - 担当は、README の部分を作業の部署に頼んで並べて進めた（役の本文のとおり）。

## 試しの作り方で気づいた物

### 3. 部署の窓で attach の画面が開いていると、名指しで止めても会話が起き直る

- macOS で、担当が頼みを受けた数秒後に `claude stop <短い id>` で止めた。部署の窓の attach の画面は「Waking session 2f29d040…」と出して会話を起こし直し、担当はそのまま納品まで済ませた。形 B が作れなかった。
- 窓の attach の画面を先に終わらせてから止めると、未納品のまま止まった（下の 4）。
- 部署の窓が開いている間は、名指しの `claude stop` では会話を止め切れない。部署の会話を止めたい人には、窓を閉じてから止める、が要る（文書には無い）。

### 4. attach の画面を強く終わらせると、窓の端末が崩れ、dispatch の打った attach が届かない

- 上の 3 の後、macOS で部署の窓の attach の処理を pid を指して止め（SIGTERM）、それから会話を名指しで止めた。
- 次の `--ask` が窓に打った `claude attach 2f29d040` は、端末が貼り付けの印を残したままだったので「00~claude attach 2f29d04001~」と崩れて届き、「-bash: 00~claude: command not found」になった。`--ask` は「窓に会話が戻らない」として止まった。
- 窓で `reset` を打って端末を戻した後の `--ask` は、戻して促し、担当は納品した（形 B が通った）。
- 部署の会話が本当に落ちる（端末ごと落ちる）ときにも、同じ崩れが残るかは確かめていない。

## 片付けと鍵

- macOS: 一時の環境の部署の会話を名指しで消し（`claude rm`）、窓口を閉じ、一時の herdr の server を止め、一時の場所を消した。一時の環境の裏の処理は、会話が無くなって自分で止まった。`ps` で残りが無いことを確かめた。
- Linux: 部署の会話を消し、herdr の server を止め、試しのコンテナ（`clean-env-7-linux`）とイメージ（`clean-env-7-trial`）を名前で指して消した。
- Windows（VM は止めていない。試しの中で 1 回再起動した）: 部署の会話を消し、窓口を閉じ、裏の処理と herdr の server を止めた。部署の作業場・試しのリポジトリ・試しの会話の記録・herdr の作業場の控え・プラグインと marketplace を消し、控えた `settings.json` と `.claude.json` を戻した。Claude Code と herdr の処理が残っていないことを確かめた。
- 鍵: macOS の一時の HOME・Linux のコンテナの `/home/u` と `/tmp`・VM の `~\.claude`・`.claude.json`・`AppData\Roaming\herdr`・`%TEMP%` の全部のファイルを、Claude Code の鍵の値で探した。当たるファイルは 0 だった。値は画面にも出していない。GitHub には書いていない。
