# まっさらな環境での試し

持ち主以外の人が、説明書（README など）だけを頼りにプラグインを入れて使えるかを、まっさらな環境で試した記録と、試しに使う Windows の VM の手引き。試しでは直さない。詰まった所を記録し、直しはそのプラグインを受け持つ部署に頼んだ。

## 試しの記録

1 本が 1 回の試し。各回は前の回の詰まりの直しを確かめ、新しく見つけた物を次の回へ渡す鎖になっている。今の基準は 10 回目（3 つの OS で詰まり 0）。

- 試したのは、主に works-dispatch（Claude Code の会話を「部署」として立てて仕事を頼むプラグイン）。版は works-dispatch と tiers（要るツールの点検。works-dispatch の依存として入る）の物。Claude Code はどの回も 2.1.301。
- Linux は Colima の Docker の Debian 13（`debian:trixie-slim`）、Windows は下の手引きの VM（Windows 11 ARM64）。
- 日付: 1〜5 回目は 2026-10-16、6〜10 回目は 2026-10-17 に回した。ファイルの名前の日付は全部 2026-10-16 にそろえてある。名前は CHANGELOG や試験の docstring から指されているので変えない。

### 言葉

記録の言葉は works-dispatch の物。各記録の頭にも書いてある。

- 部署: 1 本の git のブランチの作業場（git worktree）と Claude Code の会話の組。部署ごとに役を 1 つ持ち、役は「担当」と「作業」の 2 つ。担当の部署は、決まった受け持ち（そのプラグインなど、部署が預かる範囲）の頼みを、常設のまま続けて受ける。作業の部署は、頼みごとに立って、済んだら片付ける。
- 窓口: 人と話し、部署に頼む Claude Code の会話。
- 納品: 部署が、決まった見出しの要約を窓口へ返すこと。
- 部署の窓: 部署の会話を出した herdr（端末の画面を分けて並べるツール）のペイン。attach は、裏で動く会話をその窓につなぐ Claude Code のコマンド。
- 道: 説明書どおりの一続きの使い方。入れる → 点検 → 会社の形（部署の役とメインブランチへの入れ方を書く設定）を作る → 窓口を名付ける → 担当を立てて頼む → メインブランチに入れる → 納品 → 作業を頼んで片付ける → 部署の名前を付け替える、まで。
- 落ちた部署の戻し方: PC や VM の再起動などで部署の会話が途中で止まった（落ちた）とき、その会話を部署の窓につなぎ直して（attach）続きから動かし、納品まで進める手順。「戻す」も、この意味で使う。
- 「人だけなら止まる」: 説明書と画面の言葉のとおりに手を打つだけでは先へ進まない詰まり。
- 「1 回目の 10」: 1 回目の記録の 10 番目の項。
- `--ask`・`--land` などは works-dispatch のコマンド（dispatch.py）のオプション。
