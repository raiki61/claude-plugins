# 0020. 変異テストは並べた run の中では撃たず、合流した版でまとめて撃つ

- 状態: 採用
- 日付: 2026-09-25
- 決めた人: 人（12:30「どうせ合流するんだから一緒に」）。記録の書き方は回す側（run を回す会話の AI）の答え（09-26 00:15）を人が 09:00 に今のままとした
- 実装: 0.21.0 に入った（3 つ目の印は未）

## 文脈

- 後で合流する run を何本も並べると、各 run が自分で変異テストを撃ち、負荷を食い合った（4 本で負荷 99）。合流した版でまた撃ち直すことにもなる。

## 決定

- 並べた run の中では変異テストを撃たない。合流した版（並べた run の枝を 1 つにマージした版）でまとめて撃つ。
- 選ぶのは `init --input gates=merge`（run は graphloops の engine の 1 回の実行。init で始まる）。選んだ run は、P1（素材集めの段）のゲートの検算（`p1.gate_efficacy`）・P3（修正の段）で修正と並べて背景で撃つ変異の検算（`p3.delta_gates`。修正と並行して背景で走る処理を「線」と呼ぶ）・P4（再採点の段）の最後の関門（`p4.final_gates`）を、理由つきの条件外（撃つ条件に当たらないとして理由を書いて閉じる）で閉じ、阻害（収束を妨げる指摘や未確認の検査）が残らなくなる周（採点・修正・再採点の 1 巡）でも、変異テストを撃っていないので収束（直し終えた）を名乗らず止まる。合流した版を gates=merge 無しの run で回し、そこで最後の関門を撃つ義務が残る。
- 補足（09-26 00:15、回す側の答え。人が回す側に任せた分かれ目への推し）: P1 のゲートの検算も撃たない範囲に入れる。記録は「当たらない（理由つき）」（not_applicable）に揃える。
- 補足（09-26 09:00、人）: 記録の言い方は今のまま。手順 3（どの文書の手順かは、この記録に残っていない）で状態の型（記録の各欄が取れる値の組）を整理するときに、記録の印の種類として「当たらない」（not_applicable）・「撃たなかった」（not_run）に続く 3 つ目の印（合流に回した）を足す。
- この決まりは run をまたいで効く人の方針でもある。人の方針としての正本は人が書く方針の文書（[review-graph の手順書の「人の方針」](../../graphloops/skills/review-graph/references/policy.md#人の方針)）で、この ADR は決まったときの文脈と理由の記録である。食い違えば方針の文書が勝つ。

## 比べた案

- 各 run の中で撃つ（捨てた案）: 負荷を食い合い、合流の後に撃ち直すことにもなる。
- 合流に回した検算を「理由つきの not_run」で書く: not_run は阻害に数えられ、run が合流待ちの止まり方に届かず周の上限まで回ってしまう。

## 理由

並べた run が各自撃つと負荷を食い合い、合流の後の撃ち直しと二重になる。

## 結果

- 楽になる: 並べた run が速く回る。
- 難しくなる: 「当たらない」と「撃たなかった」の区別が記録で崩れる（独立設計の目の異論）。3 つ目の印で解く予定。
