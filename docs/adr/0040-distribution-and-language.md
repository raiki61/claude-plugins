# 0040. 依存が要るときは即席の導入（uv 優先・無ければ pipx）にし、言語は Python のまま

- 状態: 採用
- 日付: 2026-09-25
- 決めた人: 人
- 実装: 変更なし（pip の依存を足していない）

## 文脈

- 実行の核に既製の基盤（LangGraph など）を使う検討で、pip の依存を利用者の開発機にどう入れるかが問いになった。配布の方針は「必須は git / python3 / bash だけ」だった。

## 決定

- 依存が要るときは即席の導入にする。uv を優先し、無ければ pipx。依存はスクリプト先頭の宣言（PEP 723）で版を固定する（`uv lock --script` で lock も持つ）。
- どちらも無いときは、回す側が導入の手順を示し、人の了承を取ってから入れる。導入の判定は決まった小さな起動スクリプトが行い、LLM の判断に任せない。
- 言語は Python のまま。

## 比べた案

作業メモに記載なし。

## 理由

- 黙って入れない理由: 道具を機械に入れるのは外に効く操作だから。
- Python のまま: 今の engine・rules・検証器・変異テストの道具がすべて Python で、周りの道具も厚い。

## 結果

- 実行の核は今の engine を続けた（[0027](0027-keep-own-engine.md)）ので、配布物に pip の依存は足していない。今の必須は README の「依存」の節（git・python 3.12 以降・bash）が正本。
- 初回だけ取得のためにネットワークが要る。プロキシの内側で失敗したときの案内を起動スクリプトが出す。
