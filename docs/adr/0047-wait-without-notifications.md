# 0047. 回す側の待ちは完了の知らせに頼らず、手番は人に聞く所か run の終わりまで終えない

- 状態: 採用
- 日付: 2026-09-25
- 決めた人: 人
- 実装: 0.21.0 に入った（手順書の案内）

## 文脈

- 回す側が役の完了の知らせだけを待ち、知らせが届かず 7 時間止まった（別セッション）。判定役は盤面で済んでいたのに、知らせを待った回す側が 25 分止まった。
- 回す側が launch を背景で走らせて手番を終えると、端末の管理の道具（herdr）には「1 shell still running」としか見えず、人の番に見えた。

## 決定

- 回す側は、完了の知らせに頼らず、前景で出力の置き場を見に行く。
- 手番を終えてよいのは、人に聞く所か run の終わりだけ。
- この決まりは run をまたいで効く人の方針でもある。人の方針としての正本は人が書く方針の文書（[review-graph の手順書の「人の方針」](../../graphloops/commands/review-graph.md#人の方針)）で、この ADR は決まったときの文脈と理由の記録である。食い違えば方針の文書が勝つ。

## 比べた案

作業メモに記載なし。

## 理由

知らせは入れ子や上限落ちで消えることがあり、背景で待って手番を終えると人の番に見える。

## 結果

- engine と役の間は、engine が子の終了を直接待つ形にした（[0063](0063-roles-as-child-processes.md)）。回す側と launch の間は手順書の案内で縛る。
- 回す側の LLM を無くす手順 H（[0028](0028-remove-orchestrator-llm.md)）で、この待ち自体を engine に移す。
