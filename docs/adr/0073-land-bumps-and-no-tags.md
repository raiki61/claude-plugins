# 0073. 版は --land が上げて手元の関門で main に入れ、tag は作らず、CI は入った後に回す

- 状態: 採用
- 日付: 2026-10-16
- 決めた人: 人（持ち主。2026-09-29「タグはつくりません」、2026-10-16 の会社の形の方針「CI は待たない」）。この ADR は、その 2 つの決めと今の仕組みを記録に起こした物（説明書の担当、2026-10-17）
- 実装: 入った（works-dispatch の `--land`。会社の形 `.claude/company.toml` の `[land]`）

## 文脈

- [0066](0066-release-tags-and-changelog.md) は、版ごとに plugin の tag を付け、tag を作って push するのは人と決めた。tag は 1 つも作っていない（2026-10-15 に `git ls-remote --tags origin` で 0 件）。持ち主は 2026-09-29 に tag を作らないと決めた。
- [0071](0071-test-sizes-and-where-they-run.md) の「回す場所」の 2 は、push と PR の CI（3 OS）の緑で取り込んでよいかを決めると書いた。今の CI（`.github/workflows/test.yml`）は main と release/* の枝への push でだけ走り（PR では走らない）、試験の job は ubuntu と windows の 2 つ（macOS は 2026-10-16 に外した）。
- 部署の枝を main に入れるのは works-dispatch の `--land` になった。`--land` は版を上げる commit を足し、手元の関門を通してから main を早送りする。持ち主の方針（2026-10-16）は「CI は待たない」。

## 決定

- 版は `--land` が上げる（`[land]` の `bump = "marketplace"`）。部署は版を上げずに枝を出す。上げ幅と手順は [docs/releasing.md](../releasing.md)。
- main に入れる前の関門は、`[land]` の `check` のコマンド（手元で回す。今は写しの一致と件数の柵）。関門が緑なら main を早送りして push する。
- CI は main に入った後に回り、入った後の赤を見つける。`--land` は CI を待たない。
- git の tag は作らない。依存の版の範囲は main の今の版で解決する（[docs/releasing.md](../releasing.md) の「tag を作らない理由と、依存の版の範囲」）。
- 0066 のうち、変更の記録（各 plugin の根の `CHANGELOG.md`。Keep a Changelog 1.1.0 の形）と、`tests/run.sh` が今の版の見出しの在ることを確かめる決まりは、この ADR でもそのまま残す。

## 比べた案

- 0066 と 0071 の本文を書き換える（捨てた案）: ADR の決まり（[README](README.md)）は、決定が覆ったら元の本文を書き換えずに新しい ADR を足す。

## 理由

- 持ち主の 2 つの決めが、どの ADR にも記録されていなかった。0066 は採用のまま tag を前提にし、0071 は CI の緑を取り込みの関門に置いたままで、今の仕組みと食い違っていた。

## 結果

- 楽になる: 部署が自分で main に入れられる。CI を待たないので、取り込みが CI の時間に縛られない。
- 難しくなる: 重い一式の赤は main に入った後にしか分からない。CI が赤を出したら、それを直すのは点検の担当（会社の形の受け持ち。CI と根の tests/）。
- 0071 のうち、試験の大きさの分け方と手元で回す物（回す場所の 1・3・4・6）は変わらない。変わったのは回す場所の 2（取り込みの関門）と 5 の「2 の緑」。

## 見直す条件

- main に入った後の赤が、直すより速く積もるようになったら、関門（`check`）に足す物を決め直す。

## 出どころ

- 持ち主の決め: 2026-09-29「タグはつくりません」（リポジトリの CLAUDE.md）、2026-10-16「CI は待たない」（`.claude/company.toml` の `[land]` のコメント）。
