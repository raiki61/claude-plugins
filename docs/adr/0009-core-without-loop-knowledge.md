# 0009. 実行の核（engine）はループ固有の知識を持たない

- 状態: 採用
- 日付: 2026-09-25
- 決めた人: 人（手順 F の承認 16:10 と、目標の作りの層）
- 実装: 一部（残る破れ 10 件は手順 3・H で直す）

## 文脈

- graphloops は review-loop と research-loop を載せており、ほかのループ（convergence-loops の doctor-loop・firstread-loop）も載る枠組みにしたい。
- 実測では、核がループを知っている所が 10 ある（例: `init --loop` の既定が research-loop・検証器の名付けの規則を核が持つ・next の案内が回す側を Claude Code の会話と決めている）。

## 決定

- 実行の核は、順番・並列・周回・再開・人待ちを持ち、レビューや調査の中身は持たない。ループ固有の判断は rules・graph・指示書・検証器に置く。
- 境界の破れは手順 3 と手順 H の中で直し（F2）、核とループを分けてから doctor-loop か firstread-loop を 1 つ載せて汎用さを確かめる（F3）。
- この決まりは run をまたいで効く人の方針でもある。人の方針としての正本は人が書く方針の文書（[review-graph の手順書の「人の方針」](../../graphloops/commands/review-graph.md#人の方針)）で、この ADR は決まったときの文脈と理由の記録である。食い違えば方針の文書が勝つ。
