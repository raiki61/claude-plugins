# 0003. 人の方針を 1 つの文書に置き、engine が全部の run に渡す

- 状態: 採用
- 日付: 2026-09-25
- 決めた人: 人（17:40 に方向、19:40 に run の結果）
- 実装: 0.21.0 に入った

## 文脈

- 人が決めた run をまたいで効く決まりを、依頼文に毎回書き写していた。走っている run の途中で届いた人の方針を盤面に記録する口が無く、開いた問いの run では「上位互換」の方針が記録に無いまま、独立設計の目（R2）が方針とぶつかる案を出した。

## 決定

- 人の方針を 1 つの文書に置き、engine が全部の run に渡す。既定の置き場は git の共通ディレクトリの下の `graphloops/policy.md`（`init --input policy_md=` でも可。置き場の決め方の正本は `graphloops/rules/policy_input.py`）。
- 役の節には本文を貼り、回す側の節には置き場だけを渡す。init の時点の版を記録に固定し、変われば関所で人に聞く。方針は人が書く。

## 比べた案

作業メモに記載なし。

## 理由

- 作業ツリーの外に置くと、採点する版・差分・作業ツリーの突合に入らず、run の途中の書き足しが P1 の撃ち直しにならない。同じリポジトリの worktree の run が全部同じ文書を読む（[手順書の「人の方針」](../../graphloops/commands/review-graph.md#人の方針)）。

## 結果

- 楽になる: 依頼文に方針を毎回写さなくてよい。途中の書き足しも後の節に届く。
- 難しくなる: 方針の文書は版管理の外にあり、人に見えるのは sha と写しの置き場だけ（方針の台帳の run の R2 が残した隙間）。
- 決定記録（この置き場）とは別物: 方針は run をまたいで効く人の決まり、決定記録は個々の論点の決着。
