# 0074. graphloops の直しは受け持ちの担当が当てて --land で入れ、review-graph の run は持ち主が頼んだときだけ回す

- 状態: 採用
- 日付: 2026-10-16
- 決めた人: 人（持ち主。2026-10-16 の会社の形の答え「検証が通れば機械で本流に入れる」と、同じ日の夕方の「受け持ちごとの常設の部」）。この ADR は、その決めと [0013](0013-all-edits-through-review-graph.md) の食い違いを記録に起こした物（説明書の担当、2026-10-17）
- 実装: 運用の決まり（仕組みの変更を伴わない）

## 文脈

- [0013](0013-all-edits-through-review-graph.md) は、graphloops の engine・graph・rules・テストの編集を、すべて review-graph の判定から入る run に通すと決めた。
- 2026-10-16 に、このリポジトリの直しは会社の形（`.claude/company.toml`）の部署が受ける形になった。graphloops は受け持ち「見直し」の担当が預かり、直した枝を works-dispatch の `--land`（部署の枝を main に入れる命令）で main に入れる。`--land` が main に入れる前に通すのは、`[land]` の `check` のコマンド（手元の関門）と、部署が手元で回す触ったプラグインの試験である（[0073](0073-land-bumps-and-no-tags.md)）。review-graph の run は、この道のどこにも無い。
- 重い工程（review-graph など）は、持ち主の指示のときだけ起動する（[0012](0012-heavy-processes-on-human-request.md)。人の方針の文書にも同じ行が在る）。0013 のとおりに全部の直しを run に通すと、担当は直すたびに持ち主の指示を待つことになる。

## 決定

- graphloops の直しは、受け持ち「見直し」の担当（か、担当が頼んだ作業の部署）が当て、`--land` で main に入れる。入れる前の確かめは [0073](0073-land-bumps-and-no-tags.md) の関門と、触ったプラグインの手元の試験。
- review-graph の run は、持ち主が頼んだときだけ回す（[0012](0012-heavy-processes-on-human-request.md)）。
- 0013 の「使い捨ての実験（spike）のコードは取り込まず、測った事実だけを材料にする」は、この ADR でもそのまま残す。

## 比べた案

- 0013 の本文を書き換える（捨てた案）: ADR の決まり（[README](README.md)）は、決定が覆ったら元の本文を書き換えずに新しい ADR を足す。

## 理由

- 持ち主の 2026-10-16 の決め（部署が受け持ちを直し、検証が通れば機械で main に入れる）が、どの ADR にも記録されていなかった。0013 は採用のまま、全部の直しを run に通す形を前提にしていて、今の会社の形と食い違っていた。

## 結果

- 楽になる: 担当が直してすぐ main に入れられる。持ち主の指示を待たない。
- 難しくなる: 判定役の反証・修正案の事前審査・修正差分の審査は、持ち主が run を頼んだときにしか当たらない。
- 0013 の結果の「回す側は P1 の最中に作業ツリーを触らない（触ると P1 全体の撃ち直しになる）」は、run を回すときにはそのまま効く。

## 見直す条件

- 手元の関門をすり抜けた壊れが main に積もるようになったら、graphloops の直しのどれを run に通すかを決め直す。

## 出どころ

- 持ち主の決め: [会社の形の設計](../specs/2026-10-16-company-shape-design.md) の 8（成果を本流に入れるとき）と 4.12（受け持ちごとの常設の部）。
- 受け持ち: `.claude/company.toml` の `[[skills]]` の「見直し」。
