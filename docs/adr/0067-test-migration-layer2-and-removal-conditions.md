## 決定

### 層 2 の筋書きの形

- 1 本の筋書きは、loop・入力と世界の種・役の表の名前・出来事の列・手で書いた期待を持つデータにする。
- 式で書けない期待には Python の述語の逃げ道を残す。読んでよいのは盤面と返事だけ。
- 前置きの結果はセッションの間控え、写しから始める。
- 台本の drive() の輪は、回し手の run_until 1 つになる。1 本の筋書きは 1 つの事柄だけを見る。
- テストは回し手（出来事を 1 つ受けて返事と盤面を返す物）越しに書く。回し手の口は inproc（loop.py の main を同じプロセスで呼ぶ）から始め、後で step・cli・gl に差し替える。

### 通しに残す 10 本

次の 10 本は今の形（子プロセスで loop.py を起こす台本）のまま残し、同じ筋書きを cli の回し手でも回して層 2 と突き合わせる相手にする: research の test_converges・review の test_converges・test_tdd_flow・test_spec_flow・test_human_gate の主経路・test_stop_midround・test_stop_signal_stops_test_runner_tree・test_relaunch・test_launch_delegate_fenced・test_isolated_real_launch。pytest の置き場に在る物（今は research の test_converges だけ）には印 layer6 を付ける（登録は graphloops/tests/py/glharness.py）。

- 通し（層 6）を回すのは最後の関門（p4.final_gates）と CI だけで、p0 と p4.ci は層 0〜5 を回す（依頼 2026-09-28 の人の答え Q1）。ただし engine が走らせる宣言（対象リポジトリの .review-checks.json の suite）の argv に `-m 'not layer6'` を足すのは、最後の関門が一式を走らせる口を持った後——それまでに足すと、台本の検査の件数と到達の柵（conftest.py の EXPECTED_SIM_CHECKS・EXPECTED_SIM_REACHED）が当たる所が CI の丸ごとの回だけになる（人の関所 2026-09-28 の round 1 の条件 2。親の推しで通した）。

### 台本を消す条件

台本 T を消してよいのは、必須の 2 つ（1 と 4）がそろったとき。2 と 3 は、変異の CI を撃った回にだけ使う任意の証拠。

1. **台帳**（必須）: T の check ごとに行き先を 1 行書く（空欄が 1 つでもあれば消さない）。
2. **手書きの腕**（任意）: tests が T を指す腕を新しい層だけで撃ち、全部 Killed のまま expect を付け替えられること。
3. **自動の腕**（任意）: 前の変異の結果から T が殺した腕の集合 K を引き、新しい層が K を全部殺すこと。
4. **被覆**（必須）: coverage.py のテストごとの文脈で、T が通った行が新しい層の和に含まれること。含まれない行は、層 5・6 が覆うか死んだ行かを 1 行ずつ書く。

- 必須と任意の分け方は人の決定（2026-09-28「変異CIはしなくていい」）: 台本を消す証明に変異の CI を待たない。この周に限らず、以後の削除にも効く。条件 2・3 は消さずに任意の証拠として残す（撃った回は消す前に読む）。人の関所 2026-09-28 の round 2 の条件 1（親の推しで通した）。
- 4 は消す前に取る。測るのは CI か重いテストの枠（testslot）の中で、消す関数を名指して 1 本ずつ。示せなかった関数は台本に残し、理由を台帳（graphloops/tests/py/MIGRATION.md）に書く。
- 4 を読むのは、関数ごとの帰属でなく集合の包含: 旧い側の関数の和が通った行のうち、新しい層の和に含まれない行が 0 なら、和はどの部分集合の行も含むので、どの関数を消してもその行は新しい層に残る。同じプロセスで 1 度だけ走る行（遅れて読む import・初回だけのキャッシュ）が後に回した関数の側に入らない測りの偏りは、どの関数がどの行を覆うかを動かすだけで、消す可否を動かさない（人の関所 2026-09-28 の round 3。親の推しで通した）。
- 4 が示すのは実行の包含だけで、移した期待の強さではない。強さは 2 と 3（変異）が示す（T2 の run の判定、2026-09-27 に足した）。2・3 を待たずに消した関数は、期待の強さを変異で確かめないまま消える——その分を消した周の MIGRATION.md の「外した台本」の行に書く。
- 消した関数の分だけ、人の方針「シェルの検査台本は第二の網として残す」から外れる（同じ人の決定の範囲）。外した関数は消した周の CHANGELOG と MIGRATION.md の「外した台本」に書く。
- 到達の柵（台本の VOCAB_REACHED・DELIVERY_SEEN）は下げない。消す関数だけが到達させていた語彙・渡し方の節があれば、層 2 に同じ到達を足すか、その関数を残す（同じ関所の条件 3）。

### 移す順

- T2 で移す順は、重い順・腕の少ない順にする: (1) 上限で止まる類 (2) 止める・人待ち (3) 判定から入る入口・修正案の審査 (4) 線・TDD・仕様。
- 通しに残す 10 本は、最後まで今の形で残す。

## 比べた案

- 台本の形（Run → drive → check）を保ち、呼び方（cli → inproc）と並べ方（xdist）だけを変える案（作業メモの PLAN.md）。確かめる単位が変わらないので、前置きの歩きと子の起動の費用が残る。
- 筋書きをデータで書く既製の道具（hypothesis.stateful・筋書きを小言語で書く pytest のプラグイン）。hypothesis.stateful は生成探索用で、手で書いた期待の列を持たない。小言語は正規表現の層が増える。出来事の列・1 手・期待の形は Axon Framework の test fixture（given・when・expect）に寄せる（この案は作業メモに無く、T2 の run の判定の先行例、2026-09-27）。

## 理由

- 時間の大半は、狙いの状態まで端から歩く前置きと子プロセスの起動に使われていた。確かめる単位を「端から歩いて 1 か所を見る」から「控えた盤面に出来事を当てる」に変える。
- 台本を消すのは上位互換の証明がそろった物からにする（[0002](0002-backward-compatibility.md)）。被覆は実行されたことしか示さないので、強さの証明は変異に任せる（[0019](0019-mutation-testing-google-style.md)）。

## 結果

- 移す間は同じ検査が台本と層 2 の両方に在り、片方を直したらもう片方も直す（二重の費用。台本を消す run まで）。
- 層 2 の回し手の inproc の口は loop.py だけを同じプロセスに回すので、engine が起こす子（git・検証器・走らせる語）は残る。small の大きさは、世界の口と偽の git（T3）の後。
