# 0041. 子を止める口は「数え上げ→送る→数え直し」にし、正常終了でも試行の終わりに片付け、段ごとに背景を残せる

- 状態: 採用
- 日付: 2026-09-26
- 決めた人: 人（18:30、2 周目の関所の問いに「おし」＝推し 1）
- 実装: 作業枝で済み（0.21.0 には未収録）

## 文脈

- 役の中のシェルが孫プロセスを別のまとまり（プロセスグループ）へ移すと、run を止めても孫が残った（写しで再現）。孫が出力の管を握ったまま後始末が進まず、止める口が「SIGKILL の後も残っている」と誤って報告した。
- macOS で、ゾンビの長と TERM を無視する孫が居ると最後の SIGKILL が送られない・信号 0 本で「止まった」を返しうる、が 4 つのレンズで再現した。
- それまでは、試行が正常に終わったときは子孫を残していた。

## 決定

- 子の木を止める口を「数え上げ→送る→数え直し」にする。セッション番号と親子の鎖で逃げた孫も拾い、その回に数えた生きた仲間だけに送る。番号の再利用は起こした時刻で見分ける。ゾンビだけのグループの EPERM は止まったと数える。
- 試行が正常に終わったときも、試行の終わりに残りを 1 回片付ける。
- ただし `.review-checks.json` の段ごとに「背景を残す」宣言の口（keep_background）を足し、背景のプロセスを残す使い方を減らさない。

## 比べた案

- 正常終了の子孫は残す（それまでの動き。人の関所で「失う物」として聞いた）。
- Jenkins 式の環境変数の印で子孫を見分ける: macOS は他プロセスの環境が読めないので使えないと実測した。

## 理由

- 正常終了でも片付ける理由は作業メモに記載なし（人の答え「おし」だけが残る）。
- keep_background の口を足す理由: 今ある能力を減らさない（[0002](0002-backward-compatibility.md)）。

## 結果

- 限界として宣言した物: 信号より前に親が消え、かつ setsid で抜けた子孫は拾えない。
- この決定を、修正後の関所が「修正前に人が通した同じ文」として聞き直した（engine の穴。この置き場を作ったきっかけの 1 つ）。
- 残り: 消す口の範囲の守り・置き場を指して止める日常の入口・Windows の taskkill の道（Windows では正常終了の片付けをまだしない）。
- 作業枝で 2 周目まで済み（0.21.0 には未収録。0.21.1 で重ねる予定）。
