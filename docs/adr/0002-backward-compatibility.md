# 0002. 上位互換: 今ある能力と使い方を減らさない

- 状態: 採用
- 日付: 2026-09-25
- 決めた人: 人（17:40）
- 実装: 0.21.0 に入った

## 文脈

- 読むだけの gh を役に戻す run が、代償として別の能力を落とした（Bash を持つ役を読むだけの許可にしたので、調べ役の子がテストやスクリプトを動かせず、手順トレースの実測が落ちた）。人が「なぜ破壊的なことを」と指摘し、改善を 3 点承認した。そのうちの 1 つ。

## 決定

- 今ある能力と使い方を減らさない。
- 能力を減らす・狭める修正案と、人の方針に反する修正案は、判定役・審査役が代償として決めず、人に聞く分かれ目（awaiting_human）として並べて人に上げる。
- 仕組みとして、修正案に「狭める物」（narrows）の欄、事前審査の語に後退（regression）と方針（policy）、見えていない範囲の目（R4）が BASE と比べて消えた能力を棚卸しし、修正の前と後の関所（p2.human_gate・r4.human_gate）で人に聞く。
- この決まりは run をまたいで効く人の方針でもある。人の方針としての正本は人が書く方針の文書（[review-graph の手順書の「人の方針」](../../graphloops/commands/review-graph.md#人の方針)）で、この ADR は決まったときの文脈と理由の記録である。食い違えば方針の文書が勝つ。

## 結果

- 楽になる: 版を上げても、利用者の今の使い方が壊れない。
- 難しくなる: 能力を狭める直しは人の答えまで進まない。無人の run は関所で止まる（[0006](0006-unattended-runs-stop-at-gates.md)）。
- 当てた例: CI を緑に戻す run で、Windows のリンク検査の直しが symlink のフォルダを通るリンクを新たに拒む（能力が 1 つ減る）と審査役が指摘し、「狭めずに直す」を選んだ（09-25 21:15）。仕様の流れの選び方で、字面どおりだと TDD を使わない仕様の run が消えるので、部品の形に改めた（[0050](0050-spec-flow-as-component.md)）。
- 外の土台を選ぶ物差しにもなった: Archon の今の版では、待ちの上限が外せない・任せ先の柵が既定で無しに反転する等で、この決まりを守れない（[0031](0031-no-full-archon-migration-yet.md)）。
