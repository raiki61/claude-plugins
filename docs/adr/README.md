# 決定の記録（ADR）

graphloops の設計で決まったこと（人が決めたこと・判定を経て決着した論点・人の委任で回す側が推しで決めたこと）を、1 決定 1 ファイルで残す置き場。ADR は Architecture Decision Record（設計の決定の記録）の略。

## 平易版（3 行）

- graphloops を作りながら決めたことを、なぜそう決めたか・ほかに何を比べたかと一緒に、1 件 1 ファイルで残している。
- 同じ論点をまた人に聞かないために、先行議論を洗う役（review-graph の p0.prior_decisions）がここを読む。
- 決定が覆ったら、元のファイルは書き換えずに新しいファイルを足し、元のファイルの状態を「置き換え」にする。

## なぜ置くか

経緯と理由は [0001](0001-record-decisions-as-adr.md) の文脈の節。

## 書き方

- ファイル名は `NNNN-<英小文字の短い名>.md`。番号は連番で、使い回さない。
- 頭の欄: 状態・日付（決めた日）・決めた人・実装。本文の節: 文脈（なぜ決める必要があったか）・決定・比べた案・理由・結果（何が楽に／難しくなるか）・見直す条件・出どころ。
- 状態の語は 4 つだけ: **提案**（まだ決めていない）・**採用**（決めた。仕組みに入ったかは実装の欄で見る）・**廃止**（やめた。代わりの決定は無い）・**置き換え**（別の ADR に置き換わった。どれに替わったかを状態の欄に書く）。
- 実装の欄は、決めたことが仕組みに入っているかを書く: 入った版（例: 0.21.0 に入った）・作業枝で済み（main の版には未収録）・一部（何が済み何が未か）・未・変更なし（今の形を残す決定）・運用の決まり（仕組みの変更を伴わない）・当たらない（置き換え済み）。「採用」で「未」の決定は、決まっているがまだ無い機能である——今のリポジトリで効いていると前提しない。「保留」は状態の語にしない——決めずに置いた論点は、その論点を扱う ADR の文脈か決定の節に書く。
- 決定が覆ったら、元の ADR の本文は書き換えない。新しい ADR を足し、元の ADR の状態だけを「置き換え（NNNN に）」に直す。
- 作業メモに理由・比べた案・見直す条件が書かれていない決定は、その節に「作業メモに記載なし」と書く。書かれていないことを補って作らない。
- 決めた人は、人・回す側の推し（人の「自明なものは推しで決めて」の委任による。覆せる）・判定役のように書き分ける。人が一度決めて後で改めた物は、改めた日と一緒に書く。
- 技術の決定だけを書く。技術と関係の無い人の事情・他の人物の話・個人の情報・外の会社の内部の推測は書かない。外の道具や OSS は製品名で書く。

## 正本はどれか

- **作業メモにしか無かった決定**は、この ADR が正本。出どころの節の「記録した時点の出どころ」は、ADR を書いたときに読んだリポジトリの外の作業メモの名前と節で、後から開けるとは限らない。
- **リポジトリの中の文書にも書かれている決定**（`docs/graphloops-rearchitecture.md`・`docs/graphloops-prior-art.md`・手順書・`README.md`）は、出どころの節にその文書の節へのリンクを置く。ADR は、その決定を 1 か所で洗えるようにした索引で、作業メモにだけあった経緯と理由を足している。両方を直すときは同じ commit で直す。
- **人の方針**（run をまたいで効く人の決まり。例: 今ある能力を減らさない・期限を足さない）の正本は、人が書く方針の文書である（置き場は [review-graph の手順書の「人の方針」](../../graphloops/commands/review-graph.md#人の方針)）。この置き場の ADR は、その決まりが決まったときの文脈と理由の記録で、方針の文書の写しではない。食い違えば方針の文書が勝つ。
- commit の id は、main に入った版の commit だけを書く。作業枝の commit は main に squash で入るので、枝が消えると辿れない。
- この一覧の状態と日付は、各 ADR の頭の欄の写しである。ADR の状態を変える commit で、この一覧も直す。

## 作業メモの名前（記録した時点の出どころ）

2026-09-26 に読んだ、リポジトリの外の一時置き場の作業メモ。後から開けるとは限らない。

- `REPLAN-0926.md`: 2026-09-26 の順番の見直しと、同じ日の追記（外の道具の調べ・乗り移る前提の方針）
- `plan/graphloops-rearchitecture.md`（計画版）: 2026-09-25 20 時の時点の計画と決定の一覧。リポジトリの `docs/graphloops-rearchitecture.md` より新しい版
- `MORNING.md`: 2026-09-25 夜〜09-26 の報告と、人の答え（09-26 09:00）
- `HANDOFF.md`・`HANDOFF-log-20260925.md`・`HANDOFF-log-20260926.md`: 引き継ぎのメモと、その時点の決定の記録
- `merge-request.md`: 合流の run の依頼と、各 run の残り・回す側が推しで決めた分かれ目
- `blocks/BLOCKS.md`: 手順 3（ブロック分割）の設計書
