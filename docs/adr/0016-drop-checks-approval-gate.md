# 0016. テストの宣言の人の承認（allow-checks）を外し、走らせる直前に宣言を読み直す

- 状態: 採用
- 日付: 2026-09-25
- 決めた人: 人（20:55「めんどくさい」→ 無くす方向の run）
- 実装: 0.21.0 に入った

## 文脈

- 手順 3b で、宣言のコマンドを engine が走らせる前に人が `loop.py allow-checks` で宣言の sha256 を承認する形（direnv 式。1 字変われば外れる）を入れた。打つまで、そのリポジトリの run は P0 で人待ちになった。

## 決定

- 承認の関門を外す。engine は走らせる直前にルートの宣言を読み直し、盤面に書かれた語と一致するときだけ走らせる。

## 比べた案

- direnv 式の承認を残す（打つのは 1 回で済む）。
- 自分のリポジトリでだけ承認を省く形。

## 理由

- 承認の手間（人の答え「めんどくさい」）。
- 判定役は「手間を要らなくすることと両立しない守りは無い」と判断し、人に上げなかった（GitHub Actions・VS Code の Workspace Trust と同じ考え方）。

## 結果

- 盤面を細工して宣言に無いコマンドを走らせる細工は、今までどおり止まる。
- 難しくなる: 他人のリポジトリ・他人の PR を回すと、そこに書かれたテストのコマンドが人が見る前に走る（Claude Code の許可の仕組みを通らない）。手順書と README に「他人の物を回すなら宣言と呼ぶスクリプトを先に読め」と書いただけで、機械の守りは無い。
- 仕様の承認の関門は別に決めた（[0017](0017-keep-spec-approval-gate.md)）。
