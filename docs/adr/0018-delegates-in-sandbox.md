# 0018. 任せ先は既定で OS の sandbox の中で起こし、外すのは人が run ごとに明示したときだけ

- 状態: 採用
- 日付: 2026-09-25
- 決めた人: 人（19:50、案 B）
- 実装: 0.20.2 に任せ先、0.21.0 に読むだけの役

## 文脈

- 配布中の 0.20.1 で、Bash を持つ任せ先が別のリポジトリの本物の作業ツリーで `git checkout <rev> -- .` と `git reset --hard HEAD` を打ち、回す側の未コミットの修正を消した。指示書には「作業ツリーを変えるな」が既に書いてあった。

## 決定

- 任せ先は engine が `claude -p` で、本物の作業ツリーの写しの上に、OS の sandbox の中で起こす。本物の作業ツリー・`.git`・ほかの作業ツリー・盤面への書き込みを拒む。
- 外すのは、人が run ごとに明示したとき（`init --unfenced-delegates <理由>`）だけで、外したことを盤面に残す。
- engine が起こす Bash を持つ読むだけの役も sandbox の中で起こす。sandbox の無い環境（Windows・名前空間を作れない Linux）では読むだけの形に落とす。
- この決まりは run をまたいで効く人の方針でもある。人の方針としての正本は人が書く方針の文書（[review-graph の手順書の「人の方針」](../../graphloops/commands/review-graph.md#人の方針)）で、この ADR は決まったときの文脈と理由の記録である。食い違えば方針の文書が勝つ。

## 比べた案

- Agent ツールの `isolation: worktree`: 作業ディレクトリが linked worktree に移るだけで権限は変わらず、絶対パスで本物に届く。公式の sandbox の文書は、linked worktree を作業ディレクトリにすると共有の `.git` への書き込みを許すと書いている。
- フック（PreToolUse）だけで Bash の文字列を検査する: `python -c`・`cd`・別名で迂回できる。
- コンテナ: Docker が前提になり、急ぎの直しとして配れる大きさを超える。
- 任せ先を無くし回す側が自分でやる: 回す側も同じ本物の作業ツリーで無制限の Bash を持つので柵にならず、任せ先の目的（回す側の文脈の節約）も失う。
- 指示書の規律を強めるだけ: 事故の時点で既に書いてあり、破られた。

## 理由

文字列の検査や規律でなく、構造で分ける OS の sandbox を採った。

## 結果

- 本物の claude で `git reset --hard`・`checkout`・`touch` が全部拒まれ、写しの上でテスト・CI の仕事は通ることを確かめた。
- docker を使う run など囲いが邪魔なときは、人が run ごとに外す。
- 残り: 書き込みの許可範囲が / のまま（名指ししていない所には書ける）・写しは .gitignore の対象を持たないので依存を入れ直す・comment-analyzer は今も Agent ツールで起こし柵が無い・回す側が sandbox の中のときの入れ子は未実測・Linux と WSL2 は未実測。
