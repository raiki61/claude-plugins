# 0001. 決定を ADR として docs/adr/ に残す

- 状態: 採用
- 日付: 2026-09-26
- 決めた人: 人（09-26 朝の順番の見直しで取り込みを計画し、この記録の run を依頼した）
- 実装: 作業枝（この記録の run。0.21.0 には未収録）

## 文脈

- graphloops の決定（人が決めたこと・判定を経て決着した論点）が、引き継ぎのメモ・朝の報告・計画の下書きに散っていた。どれもリポジトリの外の一時置き場にあり、会話の要約や片付けで消えうる。
- 先行議論を洗う役（review-graph の p0.prior_decisions）はリポジトリの中しか読めない。そのため決着済みの論点を知らずに判定し、関所が同じ論点を人に聞き直した。2026-09-26 の run では、同じ日に決めた「symlink を許しの一覧に入れない」（[0043](0043-no-symlink-in-windows-allowlist.md)）と「正常終了でも片付ける」（[0041](0041-child-process-control-layer.md)）を、別の関所が聞き直した。
- p0.prior_decisions の指示書は、決定記録を種類（ADR・意図的保留の台帳・issue / PR の棄却済み一覧・closed issue）で挙げるだけで、置き場を名指ししていなかった。

## 決定

- 技術の決定を `docs/adr/` に 1 決定 1 ファイル（`NNNN-<英小文字の短い名>.md`）で残す。欄と状態の語は [README](README.md) の「書き方」のとおり。
- 決定が覆ったら元の ADR を書き換えず、新しい ADR を足して元の状態を「置き換え」にする。番号は使い回さない。
- p0.prior_decisions の指示書（review-loop 版）に、対象リポジトリが宣言する決定記録の置き場か、一般の慣例の置き場（`docs/adr/`・`docs/decisions/`・`doc/adr/` など）を洗う範囲に入れる 1 行を足す。指示書には特定のリポジトリの道具名を書かない（[0014](0014-commands-from-repo-declaration.md)）。

## 比べた案

- 計画文書（`docs/graphloops-rearchitecture.md`）に決定を足して 1 か所にする: 計画文書は手順の進みと混ざり、決定ごとの状態を持てない（この記録の run の修正案で比べた）。
- 既にリポジトリの文書にある決定は ADR にせず、作業メモにしか無い決定だけを ADR にする: この記録の run の事前審査が挙げた別案。先行議論を洗う役が 1 か所で洗えるよう、リポジトリの文書にある決定も ADR にし、出どころの節でその文書の節を指す形を採った。二重になる面は下の結果に書く。

## 理由

- 決定を ADR の形にすれば、run をまたいだ記憶にそのまま載り、先行議論を洗う役が機械で見つけられる（09-26 の順番の見直しで、外の道具の手順書の型から取り込む物の 1 つ目に挙げた）。
- 型は、この記録の run の判定役が挙げた先行例（Nygard の ADR・MADR）に寄せた: リポジトリの中に連番で置く・番号を使い回さない・覆った決定は置き換えで残す。

## 結果

- 楽になる: 決定の理由と比べた案がリポジトリに残り、先行議論を洗う役が読める。
- 難しくなる: リポジトリの文書（計画文書・先行例の見立て・README）と ADR の両方に同じ決定が載る。どちらが正本かは [README](README.md) の「正本はどれか」に書いたが、両方を直す手間が残る（この記録の run の判定で先送りにした論点）。
- 閉じないこと: 決着済みの論点が届くのは判定役だけで、人に聞く行を作る役（修正案の事前審査・見えていない範囲の目）には届かない。ADR を置いても、この経路の聞き直しは残る（この記録の run の判定で、別の run に分ける論点とした）。
- 閉じないこと: 同じ手順の散文版（convergence-loops の /review-loop）の先行議論の手順は、置き場を名指ししないまま残る。
