# 0072. works の修正の後の局所レビューは、レンズを 1 本ずつ独立の節にしたブロック blk-lens に置く

- 状態: 採用
- 日付: 2026-10-01
- 決めた人: 人（works の持ち主が 2026-10-01 に設計の 4 つの問いへ推しの答えで通した。修正前の関所の一言「レンズの節に Agent を持たせない。節そのものがレンズで、定義の本文を節の指示として渡し、道具は Read・Grep・Glob だけ」）。ブロックの中の節の割り方・控えのファイル・止め方は、run 155h1 の判定・修正案・事前審査
- 実装: works の [Unreleased]（割り方の 1 本目「骨」。レンズは silent-failure-hunter の 1 本だけ）

## 文脈

- works のライン darkfactory には、修正が作った差分を見る局所レビューの目が無かった。局所レビューは判定の前の素材集め（blk-material の local-review）の中にしか無く、判定から入る run では起きない。修正が作った黙った失敗は、次の周の全体レビューまで見つからなかった。
- 素材集めの local-review は、1 つの会話が Skill・Agent でレンズを起こすまとめ役の形で、節ごとに model を決められない。
- レンズの節が落ちたとき、後ろの必須の差分の審査（reviewing）を黙って飛ばしてはいけない。依存を足すだけでは、集め役が落ちたときに reviewing が飛ばされ、手直しの境（h-refix）が h-review の成功だけで走り出す。

## 決定

- 修正の後の局所レビューは新しいブロック blk-lens に置き、ラインの h-review と reviewing の間に include する（h-review の go を引く。修正が差分を作った run だけ）。reviewing はその出口を待つ。
- ブロックの中は 4 つの節: 振り分け（AI なし。レンズごとの `<名>_go` と理由）→ レンズの節（`when:` で go を引く）→ 集め役（`trigger_rule: all_done`）→ 境（`all_done`）。
  - レンズの節は、利用者が入れた pr-review-toolkit の agent の定義の本文（前付けを剥がした物）を指示書に貼った節そのもの。子（Agent）を起こさない。道具は Read・Grep・Glob だけ。定義は写さず、役の隔離した設定（works/dev/toolset.py が入れる）から引く。引けないレンズは起こさず、理由を残す。
  - 集め役は、落ちたレンズ・起こさなかったレンズも名前と理由で記録して成功で終わる。境は、集め役が落ちた・成功でないときに盤面を止め（`state.stop.by` は `works:lens`）、後ろの境の節は止まった盤面を見て stop を返す。
- レンズの事実の置き場は盤面の今の周の `lens.json` 1 本で、読み書きは `works/.shared/core/lens.py` の口だけ。差分の審査の支度（`refix.cut`）が 1 回目の審査役の brief の `lens` に写し（graph の reads は写しなので足さない）、審査役が検算して穴にする。報告は「## 未確認のレンズ」に落ちた・起こさなかったレンズを出す。
- 判定の前の local-review（素材集め）には触れない。手直し（blk-refix）の差分にはレンズが当たらず、最後のテストで守ると報告に書く。
- レンズの節の model は段の `model:` で持つ。最初の 1 本は書かず、段の既定（Opus）のまま。下げるかは Opus と Sonnet の指摘を並べて測ってから決める。

## 比べた案

- 素材集めの local-review を reviewing の前で流用する: 判定の前の local-review は変えない（置き換えは 3 本目の run）という持ち主の答えとぶつかる。
- レンズを reviewing の依存の外に置く: 審査がレンズの指摘を待てず、指摘を穴として渡せない。
- 手直しの境（h-refix）に集め役の出口を渡して止める: 14 個の境の節の入力と境の検査を広げる。止めはブロックの中の境と、止まった盤面で境の節が stop を返す既存の手順で足りる。
- レンズの節に Agent を持たせて定義を読ませる: 子を起こす形はまとめ役に戻り、節ごとの model も効かない（持ち主の一言）。役の道具の柵を広げる変更でもある。

## 理由

- 任意の枝が落ちても必須の工程を巻き添えにしない合流は、ワークフローの実行器の定番（Apache Airflow の Trigger Rules の `all_done`）。ただしこのラインの境の節は `none_failed_min_one_success` で、合流だけでは止まらないので、境の節の明示の止めを足した。
- 選ばれなかった枝を成功と区別して残す形（Airflow の Branching の skipped）に倣い、起こさなかったレンズを `not_routed` として理由つきで残す。見なかったことを「指摘なし」と読ませない。

## 結果

- 修正が差分を作った run では、差分の審査の前にレンズが 1 本走り、1 周の時間と費用が増える。
- 振り分けか集め役が落ちた run は、差分の審査へ進まずに止まる（`stopped_by_line`）。
- 撤収は、darkfactory.yaml の include を外し、reviewing の依存を `[h-review]` に戻すだけ（試験 `works/tests/test_line.py` と `works/tests/test_line_a.py` が戻し方を縛る）。

## 見直す条件

- レンズを 2 本以上並べるとき（割り方の 2 本目）: キャッシュの前置きのそろえ方と、採られた件数・費用を数える口を決める。
- 判定の前の local-review を同じ節の定義に置き換えるとき（割り方の 3 本目）。
