## この型の正体（先に一度だけ）

このループは新発明ではない。**系統的レビュー（外部証拠の格付け突合）＋ファクトチェック（一次情報照合）＋敵対検証（反証を試みる独立の目）**の合成で、各部品は EBM/GRADE・報道の校閲・情報分析（ACH・悪魔の代弁人）・質的研究（理論的飽和）・科学哲学（Wimsatt robustness）で数十年運用されてきた。全体の二段構え ──「①外部の定石で自分の座標系を校正 → ②自ドメインの制約で最適化」── も外部視点→内部視点（reference class forecasting）・EBM の定義・守破離と同じ型である。ループ全体の骨格も枯れている ── 情報機関の**情報サイクル**（要求定義→収集→分析→配布→還流）と Peirce の**探究の循環**（仮説生成→検証）に同型で、主張1件の単位構造（claim・evidence・conditions・correction）は **Toulmin の論証モデル**（主張・根拠・限定・反駁）に一致する。新しいのはコスト構造だけ（LLM 並列で①が数時間になった）。由来の対応表は末尾。

## 厚みの三段（最初に決める ── 調査の厚みは決定の重さで決める）

全装備で走らせるかは問いの重さで決める（レビューの厚みを変更の厚みで決めるのと同じ原理。EBM にも rapid review／full systematic review という段の名前がある）。ただし**厚みは実行者の裁量ではない** ── 作業を減らして得する側が検査水準を自分で決められる構造は、それ自体が反パターン（graded approach の本体も「等級基準の事前定義」であって現場の裁量ではない）:

- **既定は標準**。**軽量への降格は依頼者が明示に指定した場合のみ**（実行者の自己判断による降格を禁ずる）。
- **昇格は自律で自由**（安全側への一方向ラチェット）。相違が結論の芯に刺さった・stuck が出た場合、昇格は**義務**。
- P0-1 に「どの段か・誰が決めたか（依頼者指定／既定）・客観基準（後戻りの高さ・影響範囲・参照される期間）に照らした根拠」を明記しろ。「時間がないから」「十分そうだから」は根拠ではない。
- **省略した機構は最終報告に明示しろ**（無言の省略の禁止は、段の選択にも適用される ── 依頼者指定の軽量でも飛ばした検査は見えるようにする）:

| 段 | 使う時 | 走らせるもの | 成果物 |
|---|---|---|---|
| **軽量（rapid）** | 可逆な選定・下調べ・単発の主張の真偽 | P0-1/2/3 ＋ P1 一巡（結論が乗る主張だけ・クラスタ≤3）。ゲートなし・1ラウンドで打ち切り | 判定の集計と結論・残件のみ |
| **標準** | 設計文書の論拠固め・技術選定 | P0 全部 ＋ P1〜P4（主張は結論が乗るもの＋数値/固有名詞）。ゲートは rederiver と cold-reader | 2層マップ・出典格付け・訂正の記録・残る決定 |
| **重厚（full）** | 戦略の芯に効く・後戻りが高価・長期に参照される | 全機構（P0-7 の手筋・cartographer・負荷確証の反証・木化まで） | 成果物の型の全部 |

段は途中で上げてよい（軽量で走らせて相違が芯に刺さったら標準へ）。下げるのは新ラウンドからのみ。効率の原理は一貫している ── **安い網を先に、高い針を後に**（漏斗）・**反証で早く刈る**（枝刈り）・**差分だけ再検証**・**情報の価値順**・**依存の無いものは同時に走らせる**（直列を許すのは依存があるときだけ。ゲート同士・内部突合・先行議論の突合は並走できる）。高価な機構は必ず安い機構の後ろにゲートする。

## 役割分担（最重要）

このループを回す session が **surveyor（調査者・統合者）**。surveyor はセッションのモデルをそのまま使え（主張の棚卸し・統合・ドメイン適応は判断作業＝上位モデルの仕事。コスト削減で sonnet に落とすな ── ここが濁ると全下流の判断が濁る）。surveyor は主張の棚卸し・訂正の統合・ドメイン適応という**判断作業だけ**を行い、**自分の主張を自分で検証しない**。検証は全て別 context の subagent が行う。モデル配分は**漏斗**で考える ── 広い所に安く、狭い所に高く:

- **checker（sonnet）**: 一次情報への突合。全主張に走る扇の広い部分＝コストの大半を占めるので sonnet。判定はするが、統合はしない。
- **refuter（opus）**: checker の「相違」判定そのものを疑う敵対検証 ── **悪魔の代弁人**の席（確認でなく反証を試みる。情報分析の **ACH＝競合仮説分析**と同じ流儀）。誤検出（読み違い・古い情報・版の混同・主張側に既にある留保の見落とし）を潰す。相違と【荷重】確証だけに走る狭い部分なので opus を払える ── 誤った相違が本文を書き換える損害の方が高い。
- **rederiver（opus・調査結果を遮断）**: 統合後の見立てを、前提だけから独立に再導出して突合する。収束ゲートでのみ走る（P3）。
- **cartographer（opus・文書を遮断）**: 領域と問いだけから「完全な地図に要る観点」を独立に列挙し、文書との差分＝白地図（盲点）を作る。収束ゲートでのみ走る（P3）。
- **cold-reader（sonnet・文脈を遮断）**: 経緯を知らない初見の読み手として成果物を通読し、導出の再現性を判定する。収束ゲートでのみ走る（P3）。

surveyor は refuter が確定した相違を反映するだけで、判定を自分で上げ下げできない。判定に異議があるなら自分で覆さず、別 context の refuter に再判定させろ。**一度確定した結論は社会的圧力でなく新証拠でのみ覆す。**

**判定を都合よく使うな**: 同一ラウンドで checker / refuter / ゲートを回し直して有利な判定を採るな（やり直しは次ラウンドのみ）。各判定者の生の verdict と理由は最終報告にそのまま転記しろ ── 要約で丸めるな。

## 目的関数の規律（このループの一撃）

①の目的は「**合ってるかの確認**」ではない。「**座標系の校正＋適用条件の抽出**」である。確認を求めて回すと一致する証拠ばかり集まり、見せかけのロバストネス（同じ系譜を複数回数える）に落ちる。だから:

- checker への指示に「主張を好意的に読み替えるな。書かれた文言がそのまま正しいかを判定しろ」を必ず入れろ。
- **確証にも必ず適用条件を添えさせろ**（「正しい。ただし成立するのは〜の条件下」）。適用条件を持ち帰らない確証は②で使えない。
- 一致の**数**を根拠にするな。一致を数える前に**系譜図を書け**（誰が誰から借りたか）。独立性を壊すのは思想の伝播（借用）だけで、共通の動機・共通の選択圧は反証にならない ── むしろメカニズム実在の証拠側に働く。独立でない一致を数えるのは Wimsatt の言う *illusory robustness*（見せかけのロバストネス）である。
- 証拠語（三角測量・consilience・構造的に正しい・最強・定石だから正しい）を結論に使うな。根拠はメカニズム（なぜその形が優位になるか）と適用条件で語れ。

## P0: 断面の固定（surveyor）

1. **問いと制約の棚卸し**: 何を決めるための調査か一文で書け。次に自ドメインの制約（規模・人数・配備・データ特性等）を番号付きで固定しろ ── これが P5 の入力になり、以降変更しない（変わったら新ラウンド。結果を見てから基準を動かすことを防ぐ**事前登録**の規律）。確度が低い制約は「出どころ不明・要確認」と正直に注記し、各前提には「**これが偽なら何が崩れるか**」を一行添えろ（鍵となる前提の点検 ── 荷重の大きい前提から検証・監視の優先度を付けるため）。
2. **主張の棚卸し**: 対象の文書・見立てから「外部に照合可能な主張」を全部抽出しろ。事実主張（製品仕様・標準の内容・歴史・数値・出典）と、判断（設計選択・好み）を分けろ ── 照合にかけるのは前者だけ。後者を事実のように書いている箇所は、それ自体を「要修正」として記録しろ。**複数の主体・出典を列挙する主張（「A も B も X と報告している」）は主体単位に分解してから棚卸ししろ** ── 束ねたままだと一部だけ正しい場合に単一の判定が付けられず、後段の判定ラベルが揺れる（実走で確認済み）。
3. **クラスタ化**: 主張を検証単位（同じ一次情報群で検証できる束）に割れ。1クラスタ3〜6主張が目安。**具体的な数値・固有名詞・年号を含む主張は必ず含めろ**（そこが一番折れやすい）。結論が乗る主張には**【荷重】印**を付けろ ── P1 のスクリプトが、確証への反証探索を相違の検証と同じ並列の扇の中で自動実行する。
4. **社内語の仮止め**: 社内でしか通じない語を列挙しろ。P1 で「業界の確立語か・最も近い標準語は何か」も検証対象に含める。
5. **問いと制約の出典の独立性**: 問い・制約は issue・ユーザー指示・既存文書など**調査と独立な出典**から取れ。surveyor の自書は最終手段 ── その場合は別 context の subagent にレビューさせろ（調べやすい方向に狭めていないか）。独立出典が全く取れないなら、P3 の rederiver は `unverifiable` として扱う。
6. **先行議論の突合**: 対象領域の issue・ADR・過去のクローズ済み議論を洗い、**決着済みの論点を「未決」として蒸し返さない**こと・既に走っている並行検討と重複しないことを確認しろ。決着済みに異議があるなら「再開の提案」として新証拠付きで別立てにしろ（この突合は検索作業なので subagent に切り出し、P0 の他項目と並走させてよい）。**洗えなかった場合（issue tracker に到達できない・履歴が浅い・ADR が無い）は「確認できなかった」と最終報告に明記しろ——未確認を「重複なし」と書くな。** 洗えないまま進むと、決着済みの論点を蒸し返す形で走り切ってから気づくことになる。
7. **断面の生成（重厚では初回に一度・それ以外は手詰まり時のみ）**: 切り口が凡庸・手詰まりのとき、次の生成ヒューリスティクスを順に当てろ。ひらめきは「確率的な探索＋強い濾過」であり（Peirce の abduction＝仮説生成は論理操作）、生成は安いので数を撃ち、検証（P1）で濾す:
   - **不在の逆算**（吠えなかった犬）: 「枯れているはずなのに、なぜここに完成品が無いのか」── 不在が成立するための制約を逆算すると地図の骨格が出る。
   - **違和感の棚卸し**（Kuhn の変則事例）: 期待と観測のずれを言語化しろ。違和感は発見の入口であって排除対象ではない。
   - **抽象度の上下**（Polya の一般化/特殊化・TRIZ の標準問題化）: 「どの抽象度まで上がると、この問題は自分たち固有でなくなるか」。標準問題になった瞬間、世界中の解が使える。
   - **直交化**（関心の分離・TRIZ の矛盾分離）: 「A が B に引きずられている」を見つけたら、空間・時間・条件のどれで分離できるかを機械的に試せ。
   - **隣の構造の転用**（構造写像）: 隣の領域で同じメタ問題を解いた成果物から、内容でなく**構造**を借りろ。
   - **逆転**（invert, always invert）: 結論を反転して「これが偽になる世界」を記述しろ。premortem はこの決定版。
   - **極端化（極論）**: パラメータを極端に振れ ── 文書数ゼロなら？無限なら？運用1人なら？設計が壊れる点＝適用条件の境界が出る。
   - **用語の二義展開（ダブルミーニング）**: 主張の中の多義語を列挙し、読みごとに枝を分けて**両方とも**検証しろ（例: 「閉域」→エアギャップ/限定接続、「作り直せる」→機能的等価/状態の再現）。二義が土台に埋まったまま進むと、結論が枝の片方にしか効かない。
   生成した断面・対抗仮説は本文に直接書くな ── P2-6 と同じく**主張化して P1 で濾せ**。

   **手筋は木にできる（機械の比較優位）**: 各手筋は1回ずつでなく再帰適用して木に展開できる。なぜなぜ分析が1本道の深掘りなのに対し、FTA（故障の木）・イシューツリー（MECE 分解）・形態分析（Zwicky の組み合わせ総当たり）・HAZOP（ずらし語×全要素の系統的すり替え）は**全部の枝を機械的に踏む**型 ── 人間には気が遠いが、並列エージェントには回せる。ただし総当たりは組み合わせ爆発するので、枯れた制御で刈れ: ① MECE に割って重複を消す ② 浅く広く展開してから **P1 の反証で早期に枝を刈る**（ゲーム木探索の刈り込みと同じ ── 反証が枝刈り演算子） ③ 生き残った有望枝にだけ予算を厚く割く。

## P1: 校正 ── 外部照合（checker → refuter。**系統的レビュー＋ファクトチェック**の段）

**武器の使い分け**: P1 は「閉じた主張の検証」専用。**開いた問い**（地図がまだ無い・選択肢の洗い出し・領域全体の調査）はここで解けない ── 既存の deep-research（多角検索→取得→敵対検証→統合）に委譲しろ。再実装するな。deep-research が持ち帰った事実主張を文書に採るときは、次ラウンドの P1 の検証対象に入れろ。

P0 で作ったクラスタを args に載せ、**下記スクリプト全文を Workflow の script に、{clusters: [{key, claims}]} を args に渡して起動しろ**。ワークフローが使えない状況なら、同じ構造（checker=sonnet → 相違と【荷重】確証に refuter=opus・同じ判定語彙と schema）を Agent の並列起動で再現しろ。

```js

  name: 'claim-audit',
  description: '主張クラスタを一次情報で監査し、相違の再検証と荷重確証への反証を敵対検証で行う（research-loop P1）',
  phases: [
    { title: 'Fact-check', detail: 'クラスタ並列・一次ソース突合（sonnet）' },
    { title: 'Verify', detail: '相違の再検証＋【荷重】確証への反証（opus）' },
  ],

  type: 'object',
  additionalProperties: false,
  required: ['cluster', 'findings'],
  properties: {
    cluster: { type: 'string' },

      type: 'array',
      items: {
        type: 'object',
        additionalProperties: false,
        required: ['claim', 'verdict', 'evidence', 'sources'],
        properties: {
          claim: { type: 'string', description: '検証対象の主張（要約可）' },
          verdict: { type: 'string', enum: ['確証', '相違', '留保', '検証不能'] },
          evidence: { type: 'string', description: '一次情報で確認した内容' },
          sources: { type: 'array', items: { type: 'string' }, description: '出典 URL' },
          conditions: { type: 'string', description: '確証の場合: この主張が成立する適用条件・限界（必須で書く）' },
          loadBearing: { type: 'boolean', description: '主張に【荷重】印が付いていた場合 true' },
          correction: { type: 'string', description: '相違/留保の場合: 文書に書くべき正しい記述' },
        },
      },
    },
  },
}

const VERDICT = {
  type: 'object',
  additionalProperties: false,
  required: ['isRealDiscrepancy', 'reasoning'],
  properties: {
    isRealDiscrepancy: { type: 'boolean' },
    reasoning: { type: 'string' },
    correctedStatement: { type: 'string', description: '真の相違の場合: 文書へ書くべき正しい記述の確定版' },
  },

const COMMON = [
  'あなたは設計文書のファクトチェッカー。ウェブ検索と取得で必ず一次情報（公式ドキュメント・標準文書・原典・公式リポジトリ）に当たり、以下の各主張を検証しろ。',
  '判定基準: 確証=一次情報が主張どおり（conditions に適用条件・限界を必ず書く。適用条件のない確証は不完全）／相違=一次情報と食い違う（correction に正しい記述を書く）／留保=概ね正しいが重要な限定・精密化が要る（correction に限定を書く）／検証不能=一次情報に到達できない。',
  '引用は文脈込みで当たれ: 切り出す一文の前後、その文書自身の問い・対象・条件・限定節（limitations）を確認し、主張への転用が原文の射程内かを判定しろ。都合のよい断片だけの切り出し（文脈剥ぎ取り引用）を禁ずる。evidence と conditions には原文の射程（誰が・何を対象に・どの条件で言っているか）を書け。',
  '重要: 主張を好意的に読み替えるな。書かれた文言がそのまま正しいかを判定しろ。二次ブログしか根拠が見つからないなら verdict を下げろ。数値・年号・固有名詞は特に厳密に。クラスタ内の全主張に1件ずつ必ず判定を返せ（検証不能も明示しろ・無言の省略を禁ずる）。主張に【荷重】印が付いていたら loadBearing=true を返せ。sources は URL。全て日本語で書け。',

phase('Fact-check')
const results = await pipeline(
  input.clusters,
  c => agent(COMMON + '\n\n【クラスタ: ' + c.key + '】\n' + c.claims, {

    model: 'sonnet',
    schema: FINDINGS,

    const loaded = res.findings.filter(f => f.verdict === '確証' && f.loadBearing)
    if (!disputed.length && !loaded.length) return res
    const refute = (f, mode) => () =>
      agent([
        mode === 'dispute'
          ? 'あなたは敵対的検証者。あるファクトチェッカーが次の主張を「相違（一次情報と食い違う）」と判定した。この判定自体が誤検出でないか、自分で一次情報をウェブ検索・取得して再検証しろ。'
          : 'あなたは敵対的検証者。次の主張はチェッカーが「確証」と判定したが、結論が乗る【荷重】主張なので反証を試みろ。一次情報を自分で検索・取得し、この確証を崩す証拠（反例・より新しい一次情報・原文の射程の限定）を本気で探せ。見つからなければ isRealDiscrepancy=false を返せ。',
        '誤検出・見落としの典型: 読み違い／古い情報／留保の見落とし／別エディション・別バージョンの混同／引用の文脈剥ぎ取り（原文の射程外への転用 ── チェッカー側と主張側の双方を疑え）。',
        '元の主張: ' + f.claim,
        'チェッカーの根拠: ' + f.evidence,
        'チェッカーの出典: ' + f.sources.join(' / '),
        'チェッカーの訂正案: ' + (f.correction || 'なし'),
        '実質的な問題が見つかったら isRealDiscrepancy=true とし、correctedStatement に文書へ書くべき正しい記述を書け。日本語で。',
      ].join('\n'), { label: 'verify:' + c.key, phase: 'Verify', model: 'opus', schema: VERDICT })
        .then(v => Object.assign({}, f, { verified: v }))
    return parallel([
      ...disputed.map(f => refute(f, 'dispute')),
      ...loaded.map(f => refute(f, 'confirm')),
    ]).then(vs => Object.assign({}, res, { verifiedFindings: vs.filter(Boolean) }))
  }
)
log('全クラスタ完了')
return results.filter(Boolean)
```

固定の判定語彙（変えるな・増やすな）:

- **確証** = 一次情報が主張どおり（＋適用条件を添える）
- **相違** = 一次情報と食い違う（正しい記述を添える）→ **refuter の敵対検証を経て初めて確定**
- **留保** = 概ね正しいが重要な限定・精密化が要る
- **検証不能** = 一次情報に到達できない（二次情報しか無い場合はここに落とすか格を下げる）

出典の格（**GRADE 流のエビデンス階層**・強い順）: 国際標準・法規 ＞ 査読論文 ＞ ベンダー/プロジェクト公式一次 ＞ コミュニティ標準 ＞ 実務二次（ブログ・ベンチ記事） ＞ 匿名・出典不明。**判定の根拠にできるのはベンダー公式一次まで**。実務二次は「複数が独立に一致」した場合のみ solid 扱い、匿名は参考止まり。

**件数突合（無言の省略を「なし」と誤認するな）**: 照合は実行記録の検証器が行う——記録のクラスタ欄に入れた主張数を書き、判定数との等式は `${CLAUDE_PLUGIN_ROOT}/scripts/research-record.py` が検査する。**記録は最終報告のためだけの物ではない——クラスタ欄と claims を書いた時点で検証器を回せ**（記録は途中で何度書き直してもよい）。欠けていたら当該クラスタだけ再実行してから P2 に入れ。

**再ラウンドの経済**: 2ラウンド目以降は「新規の主張」と「訂正の波及で前提が変わった主張」だけを P1 にかけろ。確定済みの確証・確定済みの相違を引き直すな ── 全量の引き直しは純粋な無駄で、精度も上がらない。

**検索予算の管理（実走で確認済み）**: WebSearch のセッション予算は Workflow の子エージェントも同じ枠を消費する。大規模スイープ（15体級）は予算をほぼ使い切り、**2ラウンド目以降の checker は WebSearch を呼べなくなる**。対策: ①1ラウンド目の全エージェントに「出典 URL 必須」を課す（URL があれば WebFetch だけで再検証できる）②2ラウンド目の checker には「WebSearch を使うな。この URL 群を WebFetch しろ」と明示する ③確認ラウンドの抜き取り検査が予算枯渇で回せない場合は、収束を宣言せず「新規相違ゼロ n ラウンド＋ゲート pass・抜き取りは未実施」と正直に報告しろ。

**高価な相違の増し掛け**: 反映すると結論の芯を書き換える相違は、refuter を独立3票（観点を変えて）に増やし 2/3 で確定させてよい。既定は1票 ── refuter の誤りは P3 と収束ラウンドが後段で捕まえるので、全件3票は過剰。

**負荷確証の反証探索**: refuter を相違だけに走らせるな ── **結論が乗っている確証**（これが崩れると本文の芯が崩れるもの）にも回せ。検証者の甘い確認（確証バイアス・出版バイアスの同族）は、相違より静かに生き残る。全確証に回すのは過剰、荷重で選べ ── 選定は P0-3 の**【荷重】印**で行い（スクリプトが同じ並列扇の中で自動実行・後追いの往復を作るな）、**どの主張に印を付けたか（0件ならその旨と理由）を最終報告に明示しろ**。選定ゼロで素通りする降格を禁ずる。

**生存者バイアスの点検**: 「業界に無い＝空白」と結論する前に、**死んだ試み**（廃止された製品・撤回された機能・クローズした議論）を探せ。空白が「誰もやっていない」でなく「やって死んだ」なら意味が逆転する ── 帰還した爆撃機の弾痕だけ見るな（Wald）。

**雪だるま式追跡**: 当たった一次情報の参考文献（後方）と被引用（前方）を1段だけ辿れ ── 主張単位の検索では届かない隣の一次情報が安く手に入る（系統的レビューの標準手技）。

## P2: 統合（surveyor）

1. **出自で束ねろ（1件ずつ潰す前に・根本原因分析）**: 複数の相違・留保が同じ誤った前提・同じ数え方から出ていないかを先に見ろ。同根なら症状を個別に直さず**前提側を直せ** ── 1つの根本訂正で複数の相違が連鎖して消えるのが最良の一撃。
2. **相違・留保を本文へ反映しろ**。反映は現在形で書け ── 本文に「以前は〜と書いたが」を撒くな。各相違・留保には**安定キー**（主張の対象＋一文要約）を付けろ ── ラウンド間の新規/残存（stuck）判定はこのキーの突合で行い、surveyor の印象で数えるな。
3. **訂正の記録（append-only）**: 何をなぜ訂正したかは、専用の節（「訂正の記録」）に番号付きで追記しろ。消すな。同じ誤りの再発を防ぐのが目的で、これは決算整理仕訳を仕訳帳に追記するのと同じ規律である（学術出版の正誤表と同型）。
4. **波及チェック**: 各訂正について「この事実に依存していた他の結論はどれか」を挙げ、連鎖して直せ。数値・固有名詞は文書全体を Grep して取り残しを潰せ。
5. **重心の点検**: 訂正後の論拠が「一致の数（権威）」に戻っていないか確認しろ。戻っていたらメカニズム＋適用条件に組み直せ。
6. **対抗仮説の主張化**: ループ中に生まれた新しい仮説（対抗説明・独立の傍証候補・別の実装筋）は、仮説のまま本文に書くな ── **主張の形にして次ラウンドの P1 の検証対象に入れろ**。

## P3: 収束ゲート（独立の目・新規相違ゼロのラウンド後にのみ回す）

走らせる体数は「厚みの三段」に従う ── **標準は 1（rederiver）と 3（cold-reader）の2体、重厚は3体**。各体は**入力の隔離がそれぞれ違う**（入力が違う目は違う層を拾う）。互いの出力に依存しないので、**同時に起動しろ**（直列に待つ理由がない ── 壁時計は最遅の1体分で済む）。各自 `verdict: pass | redesign-needed | unverifiable` と理由を返させろ。

1. **rederiver（`model: opus`・調査結果を遮断）**: 入力は P0（初回固定・不変）だけなので、**起動自体はループ序盤に先行してよい**（導出結果は変わらないため。統合見立てとの突合だけをゲート時に行う）。一人称の自己禁止を書け ──「お前はこの subagent。統合済み文書・調査結果を読むことを自らに禁じる。渡された問いと制約（P0 の棚卸し）だけから、あるべき結論を独立に導出しろ」。**ただし導出に入る前に、まず問いそのものの実在を疑え**: この調査が解く問いは実在するか・確立した既存の答えで自明に済んでいないか・要件が未確定のまま調べ始めていないか。問いが立っていないと判断したら導出に進まず `redesign-needed`（理由に「解くべき問いが立っていない」旨）を返せ。返ってきた独立導出は surveyor が統合済みの見立てと突合し、本質的な食い違いがあれば P2 に戻れ。表現の違いは食い違いではない ── 突合するのは**構造**（何を固定し何を派生と見るか・どこに継ぎ目を置くか・何を未決とするか）。
2. **cartographer（`model: opus`・文書を遮断）**: 統合済み文書を見せず、領域と問いだけを渡して「この領域の完全な地図に要る観点・構成要素・依存関係を列挙しろ」と指示しろ。返ってきた完全地図と文書の目次・白地図を surveyor が突合し、**文書に観点として立っていない項目＝新規の盲点**を数えろ。盲点は白地図に追記する（追記自体は pass を妨げない）。**結論に影響する盲点**なら `redesign-needed`。これが収束条件「新規の盲点ゼロ」の計測器である ── これ無しで盲点ゼロを名乗るな。
3. **cold-reader（`model: sonnet`・文脈を遮断）**: タスクの経緯を一切渡さず、成果物だけを通読させろ ──「お前は文脈を持たない初見の読み手。平易版→根拠→適用の導出が、書かれた本文だけから再現できるか。再現に要る前提が省かれていないか。経緯（以前は〜だった）が本文に混入していないか。仮説が断定調で書かれていないか。より少ない記述で同じ導出を運べる冗長はないか ── ただし削ってよいのは導出の再現性が落ちない分だけで、意図的な留保・適用条件・訂正の記録を『余分』と数えるな」。再現不能・混入・断定・（制約に反しない）冗長があれば `redesign-needed`。報道の校閲・初見読者の席である。

## P4: 収束判定

1ラウンド＝P1→P2 を1周。**P3（収束ゲート）は毎ラウンド回すな** ── 新規の相違がゼロだったラウンドの後にだけ回せ（P1 が荒れている間に回しても訂正で捨てられるだけで、opus の無駄撃ちになる）。

**収束（理論的飽和）で止めるのが正常終了**: 連続2ラウンドで新規の相違がゼロ、かつその段のゲート（標準=2体・重厚=3体）が全て pass（重厚では cartographer の新規盲点ゼロを含む）。

**確認ラウンドの抜き取り検査**: 再ラウンドの経済により2ラウンド目の検証対象が空集合になる場合、**空集合での自明成立を収束と認めるな**（それは実質1ラウンド収束）。確定済み主張から無作為に1〜2割を抜き取り、**新しい checker** で再検証しろ（品質管理の受入抜き取り検査と同型。この抜き取り分は再ラウンドの経済の例外）。判定が1件でも覆ったら飽和ではない ── 通常ラウンドに戻れ（覆りか否かの解釈に surveyor の裁量を持ち込むな ── ラベルの揺れによる見かけの覆りで余計に回るのは安全側の費用である）。束ねた主張はラベルが揺れて見かけの覆りを生みやすい ── 予防は P0-2 の主体単位の分解が担う（実走で確認済み）。

収束以外はカウントで黙って打ち切らずユーザーに諮れ:

- **stuck**: 同じ相違が反映後も残る → 主張側でなく前提側が間違っている可能性。P0 に戻すか人間判断。
- **thrash**: ラウンド毎に新規相違が出続ける → 主張の棚卸し（P0-2）が浅い。切り直せ。
- **ゼロベース乖離**: rederiver の `redesign-needed` が再ラウンド1回で解消しない → 機械では決められない設計の岐路。
- **独立検証不能**: 問いの独立出典が取れず rederiver が `unverifiable` → pass でも redesign でもないので、収束を宣言せずユーザーに諮れ。
- **先行議論を洗えていない**: P0-6 の突合が「確認できなかった」で終わった → 決着済みの論点を蒸し返している可能性が残る。**確認できないことを「重複なし」に丸めるな**——収束を宣言せずユーザーに諮れ。
- **暴走ガード**: 総ラウンドが **4** を超えたら「収束せず」として必ず停止し報告しろ。

**無人実行の読み替え（surveyor が subagent として無人で走る場合）**: 「ユーザーに諮れ」で停止して応答を待つな ── **待機は無人実行では失敗と同義**（諮る相手がいない）。読み替え規則: ①諮るべき事態（stuck・thrash・ゼロベース乖離・独立検証不能）に当たったら、**保守的な既定**（省略しない・降格しない・確定を主張しない・当該論点を未決に隔離する）を選んで続行しろ ②諮りたかった内容は最終報告の冒頭に「**要人間判断**」として列挙しろ ③人間の判断そのもの（P5-3）は無人でも代行するな ── 選択肢と帰結を並べて未決のまま返すのが正しい完了である ④子エージェントの扇形展開は**前景の並列呼び出し**で行え ── 背景起動して自分のターンを閉じて待つ形は、無人の入れ子実行では応答経路が壊れて結果が迷子になる（待機と同じ失敗）。

## P5: ドメイン適応（surveyor・②の入口）

**内部の突合**は P5 を待つな ── 関連する内部実態は P0 の問いの時点で特定できるので、**P1 と並走で背景起動してよい**（候補構成が固まったら差分だけ追加で当てる）。内容: `subagent_type: general-purpose` / `model: sonnet`（読み取り専用）に、候補の構成が前提にする**自社コードの実態** ── 既にある配線・既にある素材・スキーマ・削除/保持の実挙動 ── をファイルパス:行付きで確認させろ。**P0-1 の制約のうち機械的に確認できる事実（件数・ファイルの実在・設定値。対象リポジトリがある場合）も必須の突合対象に含めろ** ── surveyor が記憶で書いた前提は検証の網の外に置かれたまま全下流に流れる（実走で確認済み ── 3本と数えた自動化が実際は4本だった）。機械確認による事実の訂正は基準の変更に当たらない ── 訂正は P2-3（訂正の記録）に番号付きで残し、当ラウンドを続行しろ。制約そのものの追加・緩和・削除は従来どおり新ラウンドである。外部の定石が「うちでは既に半分できている」「うちの実態と矛盾する」ことは珍しくなく、これが決定の格を変える（実例: 重い新規機構が要ると見えていた案が、既存の永続化層に素材の半分が既にあると判明して、軽い設計選択に格下げされた）。

そのうえで、校正済みの地図に P0 の制約を掛けて最適構成を出す。**必ず次の3分類に仕分けろ**:

1. **今決められるもの**: 校正結果＋制約から論理的に決まる。根拠（どの適用条件×どの制約か）を添えて決め、**premortem**（死亡前検死: この選択が1年後に失敗していたとして、原因を先に列挙する）を一度かけてから、文脈→決定→帰結の形で根拠ごと残せ。決定には**トリップワイヤ**（何が観測されたらこの決定を見直すか）を1つ添えろ。
2. **実測でしか決まらないもの**: PoC 行き。何を測れば決まるか（測定量と閾値の考え方）まで書け。「要検証」とだけ書いて放置するな。順序は「**結果次第で決定が変わるもの**」から（情報の価値順 ── 何を測っても決定が変わらない PoC は後回しでなく削除候補）。
3. **人間にしか決められないもの**: 事業判断・リスク受容・契約条件。**勝手に決めるな**。「残る決定事項」として選択肢・各選択肢の帰結・推奨（あれば根拠付き）を並べて隔離しろ。

## 成果物の型（必須セクション ── 欠けたら未完成）

成果物は今日の答えであると同時に、**次のループの期待モデル（地図）への預金**である ── 違和感センサーの感度は校正済みの地図の濃さの関数なので、ここを省くと次回の発見力が下がる。重厚の統合文書には最低限これを備えろ（軽量・標準の減免は「厚みの三段」の表に従う）:

- **平易版**（冒頭に。専門語なしで何の話か・どう解いたか・なぜ正しいと言えるか）
- **役割・記法の凡例**（本文で使う役割語・番号参照・確定/仮説マークの定義を成果物の先頭で。文脈を持たない読み手が本文だけで読めるように ── cold-reader の形式往復をここで予防する）
- **前提の棚卸し**（P0-1。確度注記付き）
- **根拠**（メカニズム＋適用条件。出現例は傍証と明記）
- **2層マップ**（左＝業界の位置づけ・確度付き｜右＝我々の適用・仮説マーク付き。左右を混ぜるな）
- **白地図**（観点として立っていない盲点。「調べたが空白だった」も価値）
- **出典の格付け表**（各主張がどの格の出典に立つか辿れるように）
- **社内語→標準語 対応表**（社内造語と確定した語はその旨明記）
- **訂正の記録**（append-only・番号付き・理由付き）
- **残る決定事項**（P5-3）と **PoC 行き**（P5-2）

## 反パターン（見つけたらその場で直せ）

- **確認モードで回す**: 一致する証拠を集めて安心する。→ 反証を試みる指示に変えろ。
- **一致の数を看板にする**: 「N分野が一致」「Nソース確認」。作業量は証拠強度ではない。→ 出典の格で語れ。
- **系譜を数える**: 同根の流れ（借用・派生）を独立の脚として複数回数える。→ 先に系譜図。
- **自賛を根拠にする**: 「構造を正しく見た結果」等の反証不能な自己評価。→ 検証済みの反証・実測に置換。
- **経緯を本文に混ぜる**: 「以前は〜だったが」が本文に散在。→ 訂正の記録へ集約、本文は現在形。
- **断定調の仮説**: 物理選択・数値を確定のように書く。→ 仮説マーク＋「実測で確定」を明記。
- **「要検証」の放置**: 検証方法を添えない要検証はただの先送り。→ 測定量まで書け。
- **文脈剥ぎ取り引用（quote mining）**: 一次情報から都合のよい断片だけ切り出して根拠にする。原文には問い・対象・条件・限定があり、引用の効力はその**射程**の中だけ。→ 前後と限定節まで読み、原文の射程を conditions に書け。
- **さぼり降格**: 実行者が作業を減らすために自分で軽量を選ぶ。→ 降格は依頼者指定のみ・既定は標準・芯に刺さる相違では昇格が義務（「厚みの三段」）。

## 最終報告

**報告は利用者の言語で書け。** この手順書が日本語であることは、報告を日本語にする理由にならない——判断を下すのは人で、読めない言語の報告では下せない。

**記録が先、散文が後。** 最終報告を出す前に実行記録の JSON を書き、`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/research-record.py <記録.json>` が exit 0 になるまで直せ。**記録の欄の正本は script 側で、手順書は列挙を持たない**（二重管理を避けるため。実例は `templates/research-record.example.json`）。散文の最終報告は検証済みの記録を人が読める形に展開したものであり、数値・判定は記録が正本——散文に足したくなったら先に記録へ足せ（numbers 欄が数値と出所を対で要求する。報告時に遡って探すから漏れる）。同梱 script を実行できない環境では、script 本文（欄の正本）を Read して目視で照合し、その旨を報告に書け。**収束せずに停止した実行もそのまま出せる**——記録の convergence を stopped にして理由を書けば、ゲートの未 pass や覆りは「未収束の申告」であって阻害にならない（検証器が塞ぐのは、収束を名乗りながらゲートが通っていない記録だけ）。

散文の側にだけ残る義務: ①ゲート・refuter の**生の判定と理由の転記**（記録は verdict と件数しか持たない——要約で丸めるな）②段の選択で省略した機構の明示 ③平易版・凡例・2層マップ等の構成（「成果物の型」が正本）④P0-6 を洗えなかった場合の「確認できなかった」の明記 ⑤停止した実行・無人実行では、諮りたかった内容を冒頭に「要人間判断」として列挙 ⑥記録の process・convergence の展開は結論の節に混ぜず専用の節に隔離。

**執筆前の自己検査**: 記録の検証が緑であることに加え、散文側にしか現れないものを P3-3（cold-reader）の問いで自分に当てろ——仮説の断定調・経緯の混入・未定義語（用語の定義は記録の terms 欄に集約しろ。凡例を省いた段では報告冒頭で一言定義しろ）。

## 型への還流（ループの後に一度）

最終報告を出したら、型自体を短く振り返れ ── 今回のループで型が外した点・手で補った点・要らなかった段はどれか。あれば本 skill を更新しろ（AAR＝事後検証の規律。型は完成品でなく運用で育てる資産で、更新の理由は commit message に残す）。

## この型が保証しないもの（正直な限界）

- **特定のひらめきを期日までに保証できない**: 生成（P0-7）は確率的な探索で、手筋は当たり率を上げ、P1 が外れを濾すが、「この発見が今日出る」を予定に載せることはできない。型が変えるのは確率分布であって確実性ではない。
- **ドメインの暗黙知**: 現場でしか知られていない制約は、P0 の棚卸しに人間が入れない限りループのどこにも現れない。
